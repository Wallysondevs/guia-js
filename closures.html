JavaScript Closures

Na aula Escopo você viu que as variáveis de uma função somem quando ela termina. Quase sempre. Se a função criar outra função lá dentro e essa função sair (com return, por exemplo), as variáveis de que ela precisa continuam vivas, guardadas junto com ela. Essa dupla, "a função + as variáveis do lugar onde ela nasceu", se chama closure (em inglês, "fechamento"; a palavra costuma ficar em inglês). Parece detalhe técnico, mas é o que faz contadores, variáveis privadas e muitos callbacks funcionarem.

Você vai aprender
  • O que é uma closure, com o exemplo mais simples: uma função que lembra uma saudação.
  • O contador que não perde a conta, e por que dois contadores não se misturam.
  • Como esconder uma variável do resto do programa (o cofrinho com saldo privado).
  • Que a closure guarda a variável, não uma cópia do valor.
  • Fábricas de callbacks: precos.filter(acimaDe(10)).
  • O clássico do var no laço com setTimeout, e os enganos mais comuns.

A ideia: a mochila que a função leva

A Ana manda o filho à feira. Antes de ele sair, ela põe na mochila dele um bilhete: "compre 2 kg de tomate, no máximo R$ 10". A Ana pode ir trabalhar, sair de casa, esquecer o assunto: o bilhete está na mochila do filho, e ele consulta quando precisar.

Uma closure é isso. Quando uma função é criada dentro de outra, ela leva uma "mochila" com as variáveis de lá de dentro que ela usa. A função de fora pode terminar; a de dentro continua com a mochila, e consulta (e até muda) aquelas variáveis sempre que for chamada.

1. A primeira closure: uma função que lembra

function criarSaudacao(saudacao) {
  return (nome) => `${saudacao}, ${nome}!`;
}

const manha = criarSaudacao("Bom dia");
const noite = criarSaudacao("Boa noite");
console.log(manha("Ana"));
console.log(noite("Ana"));
console.log(manha("Bia"));
function criarSaudacao(saudacao)
Uma função "fábrica": recebe a saudação…
return (nome) => `${saudacao}, ${nome}!`;
…e devolve uma função nova, que usa duas variáveis: nome (o parâmetro dela) e saudacao (que é da função de fora). Essa saudacao vai na mochila.
const manha = criarSaudacao("Bom dia");
A fábrica roda, devolve a função e termina. Normalmente a saudacao sumiria aqui. Mas a função guardada em manha ainda precisa dela, então ela fica.
const noite = criarSaudacao("Boa noite");
Outra chamada, outra função, outra mochila: esta com "Boa noite".
$ node lembrar.js
Bom dia, Ana!
Boa noite, Ana!
Bom dia, Bia!

Na última linha, a criarSaudacao já tinha terminado havia muito tempo, e mesmo assim manha lembrou o "Bom dia". É a regra do escopo ("de dentro se enxerga para fora") funcionando mesmo depois que o "fora" terminou.

2. O contador que não perde a conta

A closure não só lê: ela pode mudar a variável da mochila, e a mudança fica guardada para a próxima chamada. A máquina de senhas da padaria:

function criarContador() {
  let total = 0;
  return () => {
    total = total + 1;
    return total;
  };
}

const senhaPadaria = criarContador();
console.log(senhaPadaria());
console.log(senhaPadaria());
console.log(senhaPadaria());

const senhaFarmacia = criarContador();
console.log(senhaFarmacia());
console.log(senhaPadaria());

$ node contador.js
1
2
3
1     « a farmácia tem o seu próprio total, começando do zero
4     « a padaria continuou de onde parou

Cada chamada de criarContador() cria variáveis novas (lembre: cada chamada de função tem o seu escopo). Por isso os contadores não se misturam.

Por que não uma variável global?

Daria para fazer o contador com uma variável global, como na aula Escopo. Veja o risco:

let total = 0;
function proximaSenha() {
  total = total + 1;
  return total;
}

console.log(proximaSenha());
console.log(proximaSenha());
total = 100;
console.log(proximaSenha());

$ node global.js
1
2
101     « alguém mexeu no total lá de fora

Com a global, qualquer linha do programa pode estragar a contagem, e só dá para ter um contador. Com a closure, o total só pode ser mudado pela função que está com ele.

3. Variáveis privadas: o cofrinho

Devolvendo um objeto com vários métodos, todos eles dividem a mesma mochila. A variável fica acessível a eles, e a mais ninguém:

function criarCofrinho(dono) {
  let saldo = 0;

  return {
    depositar(valor) {
      if (valor <= 0) {
        console.log("Depósito inválido.");
        return;
      }
      saldo = saldo + valor;
    },
    sacar(valor) {
      if (valor > saldo) {
        console.log(`${dono}, saldo insuficiente.`);
        return;
      }
      saldo = saldo - valor;
    },
    verSaldo() {
      return `Cofrinho de ${dono}: R$ ${saldo}`;
    },
  };
}

const cofreAna = criarCofrinho("Ana");
cofreAna.depositar(50);
cofreAna.depositar(-10);
cofreAna.sacar(80);
cofreAna.sacar(20);
console.log(cofreAna.verSaldo());
console.log(cofreAna.saldo);
cofreAna.saldo = 1000000;
console.log(cofreAna.verSaldo());

$ node cofrinho.js
Depósito inválido.
Ana, saldo insuficiente.
Cofrinho de Ana: R$ 30
undefined                    « o saldo não é uma propriedade do objeto
Cofrinho de Ana: R$ 30       « criar cofreAna.saldo não mexeu no saldo de verdade

O saldo de verdade está na mochila dos três métodos, não no objeto. A única forma de mudá-lo é pelos métodos, que conferem as regras (nada de depósito negativo, nada de sacar mais do que tem). A linha cofreAna.saldo = 1000000 só criou uma propriedade nova e inútil no objeto. Esconder dados assim se chama encapsular. (As classes têm outro jeito de fazer isso, os campos privados (#).)

4. A closure guarda a variável, não uma foto do valor

A mochila não leva uma cópia do valor do momento em que a função nasceu: leva a própria variável. Se ela mudar depois, a função vê o valor novo:

let taxa = 0.1;
const comTaxa = (preco) => preco + preco * taxa;
console.log(comTaxa(100));
taxa = 0.5;
console.log(comTaxa(100));

$ node viva.js
110
150     « a função leu a taxa nova

Por isso o contador da seção 2 funciona: cada chamada mexe no mesmo total, e a próxima vê o valor atualizado.

5. Fábricas de callbacks

Closures combinam muito com callbacks: uma fábrica cria, sob medida, a função que o filter (ou o map, o sort…) vai chamar:

function acimaDe(limite) {
  return (preco) => preco > limite;
}

const precos = [4.5, 12, 0.8, 25, 9];
console.log(precos.filter(acimaDe(5)));
console.log(precos.filter(acimaDe(10)));

$ node filtro.js
[ 12, 25, 9 ]
[ 12, 25 ]

Aqui o acimaDe(5) tem parênteses, e está certo: ele é chamado na hora e devolve a função que o filter recebe. Essa função lembra o limite enquanto o filter a chama para cada preço. Nas páginas web, o mesmo truque cria funções para botões e eventos que lembram "qual produto é este" (aula Eventos).

6. Closures em laços: let × var

Este é um clássico de entrevista de emprego. Os callbacks do setTimeout rodam depois que o laço terminou (veja setTimeout e setInterval). O que cada um lembra?

for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log("var:", i), 100);
}
for (let j = 1; j <= 3; j++) {
  setTimeout(() => console.log("let:", j), 200);
}

$ node lacovar.js
var: 4
var: 4
var: 4
let: 1
let: 2
let: 3
  • Com var, existe um i só para o laço inteiro (o var ignora blocos). As três funções guardam a mesma variável, e quando elas rodam o laço já terminou com i valendo 4.
  • Com let, cada volta do for ganha o seu próprio j. Cada função leva na mochila o j da sua volta.

Mais um motivo para usar let e esquecer o var (veja var: o Jeito Antigo).

Quando dá errado

Closures raramente geram mensagens de erro: os enganos aparecem como resultados estranhos. Os mais comuns:

Esqueceu de chamar a fábrica 
function criarContador() {
  let total = 0;
  return () => {
    total = total + 1;
    return total;
  };
}

const senha = criarContador;
console.log(senha());

$ node esqueceu.js
[Function (anonymous)]

Sem os parênteses em criarContador, senha virou outro nome para a fábrica. Então senha() roda a fábrica, que devolve o contador, e o console.log mostra essa função: [Function (anonymous)] ("função anônima", porque a arrow function devolvida não tem nome). Como consertar: const senha = criarContador();.

Criou um contador novo a cada vez 
function criarContador() {
  let total = 0;
  return () => {
    total = total + 1;
    return total;
  };
}

console.log(criarContador()());
console.log(criarContador()());
console.log(criarContador()());

$ node novo.js
1
1
1

criarContador()() cria um contador e o chama uma vez; a linha seguinte cria outro, que começa do zero. Como consertar: crie o contador uma vez, guarde numa variável e chame essa variável quantas vezes quiser.

Pôs a variável dentro da função errada 
function criarContador() {
  return () => {
    let total = 0;
    total = total + 1;
    return total;
  };
}

const senha = criarContador();
console.log(senha());
console.log(senha());

$ node dentro.js
1
1

Aqui o let total = 0 está na função de dentro, então ele é criado de novo, valendo 0, a cada chamada. Não há nada na mochila. Como consertar: a variável que deve durar entre as chamadas fica na função de fora (a fábrica); a de dentro só a usa.

var no laço

É o var: 4 três vezes da seção 6. Como consertar: troque var por let no for.

}

caixa.vender(50);

function criarCaixa(limite) {
  let total = 0;
  return {
    vender(valor) {
      if (total + valor > limite) {
        console.log(`Limite de R$ ${limite} atingido!`);
        return;
      }
      total = total + valor;
      console.log(`Venda de R$ ${valor} registrada. Total: R$ ${total}`);
    },
    fechar() {
      return `Total do dia: R$ ${total}`;
    },
  };
}

const caixa = criarCaixa(100);
caixa.vender(30);
caixa.vender(50);
caixa.vender(40);
console.log(caixa.fechar());

Resumo

  • Uma closure é uma função junto com as variáveis do escopo onde ela nasceu. Elas continuam vivas enquanto a função existir, mesmo depois que a função de fora terminou.
  • Cada chamada da fábrica cria variáveis novas: dois contadores não se misturam.
  • Devolvendo um objeto com métodos, a variável fica privada: só os métodos a leem e mudam.
  • A closure guarda a variável em si, não uma cópia: vê as mudanças.
  • Fábricas de callbacks (acimaDe(10)) e o let nos laços são usos do dia a dia.
  • Enganos comuns: esquecer de chamar a fábrica, criar uma nova a cada vez, pôr a variável na função de dentro, usar var no laço.
