JavaScript get e set

Na aula Classes, a comanda tinha um método total(), chamado com parênteses. Mas "o total da comanda" parece mais um dado do que uma ação: seria natural escrever comanda.total, como se lê comanda.cliente. E o preço de um produto parece um dado simples, mas ninguém deveria conseguir pôr -2 nele. O get e o set resolvem as duas coisas: são propriedades que, por baixo, rodam uma função. Funcionam igual no Node e no navegador.

Você vai aprender
  • O que é um getter (get): uma propriedade calculada na hora em que é lida.
  • O que é um setter (set): uma função que roda quando alguém dá um valor à propriedade.
  • Como usar os dois juntos para converter (Celsius e Fahrenheit) e para validar (preço negativo, nota acima de 10).
  • O "campo de apoio" (_preco), e por que o setter não pode gravar nele mesmo.
  • Getters e setters em objetos literais, e como o console.log os mostra.
  • Quando usar get e quando usar um método comum.
  • Os erros reais: parênteses no getter, getter sem parênteses quando era método, atribuir a um getter, e o setter que chama a si mesmo.

Todos os programas rodaram no Node.js v24.22.0 da máquina da Ana (usuária ana, computador notebook), na pasta /home/ana/getset.

A ideia: o balcão da padaria

O cliente não entra na cozinha. Ele fala com o atendente, no balcão:

  • "Quanto deu?" — o atendente não tem o número decorado: ele soma na hora o que está na comanda e responde. É o get ("pegar"): parece que você está lendo um valor, mas por trás alguém calculou.
  • "Põe o preço do sonho em -2." — o atendente confere antes de mudar a etiqueta, e recusa o que não faz sentido. É o set ("definir"): parece que você está guardando um valor, mas por trás alguém verificou.

Para quem usa o objeto, nada muda: lê-se comanda.total e escreve-se produto.preco = 4, como em qualquer propriedade. A diferença está dentro da classe.

1. get: a propriedade calculada

class Comanda {
  constructor(cliente) {
    this.cliente = cliente;
    this.itens = [];
  }

  adicionar(nome, preco) {
    this.itens.push({ nome, preco });
  }

  get total() {
    let soma = 0;
    for (const item of this.itens) {
      soma += item.preco;
    }
    return soma;
  }

  get quantidade() {
    return this.itens.length;
  }
}

const comanda = new Comanda("Bia");
console.log(comanda.total, comanda.quantidade);
comanda.adicionar("sonho", 3.5);
comanda.adicionar("café", 6);
console.log(comanda.total, comanda.quantidade);
console.log(`Total da ${comanda.cliente}: R$ ${comanda.total.toFixed(2)}`);
console.log(comanda);
get total() { … }
Parece um método, com a palavra get na frente. Não recebe parâmetros e precisa devolver (return) um valor: é ele que aparece quando alguém lê comanda.total.
comanda.total
Lido sem parênteses, como uma propriedade comum. Cada leitura roda a função de novo, então o valor está sempre atualizado.
get quantidade()
Um getter pode ser bem curto: aqui, só o tamanho da lista.
comanda.total.toFixed(2)
Como comanda.total já é um número, dá para emendar um método de número nele.
$ node comanda.js

9.5 2
Total da Bia: R$ 9.50
Comanda {
  cliente: 'Bia',
  itens: [ { nome: 'sonho', preco: 3.5 }, { nome: 'café', preco: 6 } ]

Com a comanda vazia, total e quantidade deram 0; depois de dois itens, 9.5 e 2, sem ninguém "atualizar" nada: o valor é calculado a cada leitura. E repare no último console.log: o total e a quantidade não aparecem no objeto. Eles não são dados guardados; são funções da classe (como os métodos), que só rodam quando alguém as lê.

Por que não guardar o total numa propriedade?

Daria para ter this.total = 0 e somar a cada adicionar. Mas aí são dois lugares para manter em dia: se alguém tirar um item da lista e esquecer de descontar do total, os dois discordam. Com o get, o total vem sempre da lista, e não há como discordar.

2. get e set juntos: o forno em Celsius e Fahrenheit

O forno da padaria guarda a temperatura em graus Celsius. Uma receita americana vem em Fahrenheit. Com um par get/set, o forno "fala" as duas unidades, mas guarda uma só:

class Forno {
  constructor() {
    this.celsius = 180;
  }

  get fahrenheit() {
    return this.celsius * 9 / 5 + 32;
  }

  set fahrenheit(valor) {
    this.celsius = (valor - 32) * 5 / 9;
  }
}

const forno = new Forno();
console.log(`${forno.celsius} °C = ${forno.fahrenheit} °F`);
forno.fahrenheit = 400;
console.log(`${forno.celsius.toFixed(1)} °C = ${forno.fahrenheit} °F`);
forno.celsius = 200;
console.log(`${forno.celsius} °C = ${forno.fahrenheit} °F`);
get fahrenheit()
Quando alguém lê forno.fahrenheit, converte o Celsius guardado.
set fahrenheit(valor)
Quando alguém escreve forno.fahrenheit = 400, essa função roda com valor = 400. Ela converte e guarda em celsius. Um setter recebe exatamente um parâmetro: o valor depois do =.
mesmo nome nos dois
O get e o set de fahrenheit formam uma propriedade só, que se lê e se escreve.
$ node forno.js
180 °C = 356 °F
204.4 °C = 400 °F
200 °C = 392 °F

Mudar o Fahrenheit mudou o Celsius, e mudar o Celsius mudou o Fahrenheit: as duas "propriedades" nunca discordam, porque só uma é guardada de verdade.

3. set para validar: o preço que não pode ser negativo

O uso mais comum do set é proteger um dado: conferir o valor antes de guardar e recusar o que não presta, com um erro (veja throw).

class Produto {
  constructor(nome, preco) {
    this.nome = nome;
    this.preco = preco;
  }

  get preco() {
    return this._preco;
  }

  set preco(valor) {
    if (typeof valor !== "number" || Number.isNaN(valor) || valor < 0) {
      throw new RangeError(`Preço inválido para ${this.nome}: ${valor}`);
    }
    this._preco = valor;
  }
}

const sonho = new Produto("sonho", 3.5);
console.log(sonho.preco);
sonho.preco = 4;
console.log(sonho.preco);
console.log(sonho);
try {
  sonho.preco = -2;
} catch (erro) {
  console.log(`${erro.name}: ${erro.message}`);
}
console.log(sonho.preco);
const broa = new Produto("broa", "barato");
this.preco = preco; (no constructor)
Esta linha já passa pelo setter! Toda atribuição a preco, inclusive a do construtor, é conferida. Assim, nem na criação entra um preço inválido.
set preco(valor) { … this._preco = valor; }
Confere: tem de ser número, não pode ser NaN nem negativo. Se passar, guarda em _preco, o campo de apoio.
_preco
Onde o valor mora de verdade. O sublinhado no começo é só um costume que quer dizer "isto é interno, não mexa". (Não pode ser this.preco, que chamaria o próprio setter de novo; veja Quando dá errado.)
get preco() { return this._preco; }
Quem lê sonho.preco recebe o valor do campo de apoio.
throw new RangeError(…)
Lança um erro do tipo RangeError ("fora da faixa"). Quem atribuiu um preço errado pode tratá-lo com try … catch.

O sublinhado não tranca nada

O _preco é só um aviso entre programadores: quem quiser ainda escreve sonho._preco = -2, e o setter não fica sabendo. Para trancar de verdade, o JavaScript tem os campos privados, com # (#preco), que de fora da classe nem podem ser lidos. É o assunto de Campos Privados (#), e o par get/set com # é o jeito moderno de proteger um dado.

4. Em objetos literais

get e set também funcionam num objeto escrito à mão, sem classe (veja Métodos e this):

const pedido = {
  itens: [3.5, 6, 2],
  taxa: 5,
  get total() {
    return this.itens.reduce((soma, preco) => soma + preco, 0) + this.taxa;
  },
  set adicionar(preco) {
    this.itens.push(preco);
  },
};

console.log(pedido.total);
pedido.adicionar = 4;
console.log(pedido.itens, pedido.total);
console.log(pedido);

$ node literal.js
16.5
[ 3.5, 6, 2, 4 ] 20.5
{
  itens: [ 3.5, 6, 2, 4 ],
  taxa: 5,
  total: [Getter],
  adicionar: [Setter]
}

No objeto literal, as partes se separam com vírgula (inclusive depois do getter e do setter), e o console.log mostra [Getter] e [Setter] no lugar dos valores (um par dos dois apareceria como [Getter/Setter]). Só para mostrar, este set adicionar funciona, mas é um mau uso: "adicionar" é uma ação, e pedido.adicionar = 4 engana quem lê. Para ações, use um método: pedido.adicionar(4).

Dentro do set preco, a linha this.preco = valor é… uma atribuição a preco, que chama o set preco de novo, que faz outra atribuição, que chama de novo… para sempre. Resumo

  • get nome() { return …; } cria uma propriedade calculada: lida sem parênteses (obj.nome), roda a função a cada leitura e está sempre atualizada.
  • set nome(valor) { … } roda quando alguém atribui (obj.nome = valor), inclusive no constructor. Serve para converter e, principalmente, para validar, lançando um erro quando o valor não presta.
  • O valor de verdade mora num campo de apoio com outro nome (_preco, ou o privado #preco). Gravar em this.preco dentro do set preco dá Maximum call stack size exceeded.
  • Getters e setters não aparecem no console.log de uma instância; num objeto literal, aparecem como [Getter]/[Setter].
  • get para valores calculados e rápidos; métodos para ações e para o que recebe parâmetros.
  • Erros comuns: is not a function (parênteses num getter), [Function: …] (faltaram parênteses num método), atribuir a um getter sem setter (ignorado no CommonJS, TypeError em módulos).
