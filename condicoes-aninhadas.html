JavaScript Condições Aninhadas

Dentro do bloco de um if pode ir qualquer código, inclusive outro if. Isso se chama aninhar (como uma boneca russa: uma dentro da outra). Serve para as decisões que só fazem sentido depois de outra: só adianta perguntar a senha se o usuário existe; só adianta perguntar a idade se a pessoa tem ingresso.

Você vai aprender
  • Como pôr um if dentro de outro, e um if dentro de um else.
  • Como a indentação mostra quem está dentro de quem.
  • Quando um aninhamento pode virar um && ou um else if, e quando não pode.
  • Por que uma "pirâmide" de if é difícil de ler, e como achatá-la.
  • As armadilhas reais: o else que vai para o if errado, a chave a mais e a variável que só existe dentro do bloco.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: a portaria do cinema

O porteiro do cinema do bairro segue duas regras, uma depois da outra:

  1. Primeiro, ele pergunta: você tem ingresso? Se não tem, nem adianta conversar: "vá até a bilheteria".
  2. Só se a pessoa tem ingresso, ele faz a segunda pergunta: tem 16 anos ou mais? Se tem, entra. Se não tem, precisa de um adulto junto.

A segunda pergunta está dentro do "sim" da primeira. Quem não tem ingresso nunca ouve a pergunta da idade. É isso que uma condição aninhada faz.

1. Um if dentro do outro

const temIngresso = true;
const idade = 14;

if (temIngresso) {
  if (idade >= 16) {
    console.log("Pode entrar. Bom filme!");
  } else {
    console.log("Só pode entrar com um adulto.");
  }
} else {
  console.log("Vá até a bilheteria comprar o ingresso.");
}
if (temIngresso) {
A pergunta de fora. temIngresso já é um booleano, então vai sozinho na condição.
if (idade >= 16) { … } else { … }
A pergunta de dentro: um if … else inteiro, morando no bloco do primeiro if. Ele tem 4 espaços a mais de recuo nas linhas de dentro: 2 por estar no if de fora, mais 2 por estar no de dentro.
} else {
Este else está no nível de fora (2 espaços a menos): ele é o "senão" do temIngresso, não da idade.
$ node cinema.js
Só pode entrar com um adulto.

O caminho que o Node fez: temIngresso é true, então entrou no bloco de fora. Lá dentro, 14 >= 16 é false, então rodou o else de dentro. O else de fora foi pulado.

2. Aninhar para evitar um erro

Às vezes o aninhamento não é só organização: ele protege a segunda pergunta. A Ana guarda o apelido do cliente, mas nem todo cliente tem um; para esses, a variável fica undefined (veja null e undefined). Ela quer saudar com o apelido, se ele for curto:

const apelido = undefined;

if (apelido !== undefined) {
  if (apelido.length <= 6) {
    console.log(`Oi, ${apelido}!`);
  } else {
    console.log("Oi! Que apelido comprido.");
  }
} else {
  console.log("Oi! Você ainda não tem apelido.");
}

$ node apelido.js
Oi! Você ainda não tem apelido.

A pergunta de dentro usa apelido.length (o tamanho do texto; veja Strings). Se ela fosse feita com apelido valendo undefined, o programa pararia com TypeError: Cannot read properties of undefined (reading 'length'). O if de fora garante que a de dentro só é feita quando o apelido existe.

3. Um if dentro de um else

O if de dentro também pode morar no bloco do else. A Ana confere o pagamento: se foi no Pix, está pago; senão, ela quer saber se foi no cartão ou em dinheiro:

const forma = "cartão";

if (forma === "pix") {
  console.log("Pago na hora.");
} else {
  if (forma === "cartão") {
    console.log("Aguardando a maquininha.");
  } else {
    console.log("Conferir o troco.");
  }
}

$ node pagamento.js
Aguardando a maquininha.

Funciona, mas olhe bem: um else cujo bloco tem só um if … else dentro é exatamente o que o else if da aula else e else if faz, com menos recuo e menos chaves:

const forma = "cartão";

if (forma === "pix") {
  console.log("Pago na hora.");
} else if (forma === "cartão") {
  console.log("Aguardando a maquininha.");
} else {
  console.log("Conferir o troco.");
}

$ node pagamento2.js
Aguardando a maquininha.

Mesma saída, mais fácil de ler. Na verdade, o else if é isso: um else cujo bloco é outro if, escrito sem as chaves do meio.

4. Quando o aninhamento vira um &&

Se o if de dentro não tem else, e o de fora também não, os dois podem virar um só, com o "e" (&&; veja Operadores Lógicos):

const total = 150;
const temCupom = true;

// aninhado
if (total >= 100) {
  if (temCupom) {
    console.log("Desconto de 20% (aninhado)");
  }
}

// com &&
if (total >= 100 && temCupom) {
  console.log("Desconto de 20% (com &&)");
}

$ node cupom.js
Desconto de 20% (aninhado)
Desconto de 20% (com &&)

Os dois dizem a mesma coisa: "se a compra passou de 100 e tem cupom". A versão com && é mais curta. E o && também protege como o aninhamento da seção 2: ele só olha o lado direito se o esquerdo for verdadeiro, então apelido !== undefined && apelido.length <= 6 nunca dá erro.

Quando NÃO dá para trocar

Se algum dos if tem else, cuidado. No cinema da seção 1, quem não tem ingresso ouve "vá à bilheteria" e quem tem ingresso mas é menor ouve "só com um adulto": são respostas diferentes para cada "não". Um único if (temIngresso && idade >= 16) … else … juntaria os dois "não" numa mensagem só.

Missão: junte os dois if num só, usando &&. A mensagem tem de continuar aparecendo uma vez.

const bairro = "Centro";
const total = 80;

if (bairro === "Centro") {
  if (total >= 50) {
    console.log("Entrega grátis!");
  }
}

const bairro = "Centro";
const total = 80;

if (bairro === "Centro" && total >= 50) {
  console.log("Entrega grátis!");
}

5. A pirâmide de if

Dá para aninhar quantos níveis quiser, mas cada nível empurra o código mais para a direita. Este é o cadastro de uma senha na lojinha:

const senha = "abacaxi2026";

if (senha.length >= 8) {
  if (senha !== "12345678") {
    if (senha.includes("2")) {
      console.log("Senha aceita.");
    } else {
      console.log("A senha precisa de um número 2.");
    }
  } else {
    console.log("Essa senha é fácil demais.");
  }
} else {
  console.log("A senha precisa de 8 caracteres ou mais.");
}

$ node piramide.js
Senha aceita.

Funciona, mas cada mensagem de erro fica longe da pergunta que a causou: o "8 caracteres" está lá embaixo, a 12 linhas do if dele. Esse formato tem até apelido: pirâmide (ou "código seta", pelo formato > que o recuo desenha). Dá para achatar invertendo as perguntas: teste primeiro o que está errado, com else if, e deixe o "deu tudo certo" para o else final:

const senha = "abacaxi2026";

if (senha.length < 8) {
  console.log("A senha precisa de 8 caracteres ou mais.");
} else if (senha === "12345678") {
  console.log("Essa senha é fácil demais.");
} else if (!senha.includes("2")) {
  console.log("A senha precisa de um número 2.");
} else {
  console.log("Senha aceita.");
}

$ node achatada.js
Senha aceita.

Cada problema fica ao lado da sua mensagem, e o código não entorta. O ! é o "não" (veja Operadores Lógicos) e o includes procura um pedaço no texto (veja Procurando em Strings). Quando você aprender funções, vai ver outro jeito de achatar: sair da função assim que encontrar um problema.

Quando dá errado

O else foi para o if errado

Sem chaves, um else sempre pertence ao if mais próximo, não importa como você indentou. A Ana quer a mensagem da bilheteria para quem não tem ingresso:

const temIngresso = false;
const idade = 20;

if (temIngresso)
  if (idade >= 16)
    console.log("Pode entrar.");
else
  console.log("Vá até a bilheteria.");

console.log("Próximo!");

$ node elseerrado.js
Próximo!

A mensagem da bilheteria não apareceu! Pela indentação, o else parece ser do temIngresso, mas o Node não olha os espaços: ele ligou o else ao if (idade >= 16), o mais próximo. Como temIngresso é false, o Node pulou o if de dentro com o seu else junto. Como consertar: use chaves sempre; com elas, fica explícito de quem é cada else.

Com várias chaves empilhadas, é fácil perder a conta. Como consertar: confira os pares: cada { tem a sua } na mesma coluna da linha que abriu o bloco. Aqui, apague a } da linha 8. A maioria dos editores de código destaca o par de uma chave quando você põe o cursor nela.

Resumo

  • Dentro do bloco de um if (ou de um else) pode ir outro if: a pergunta de dentro só é feita quando o caminho de fora é seguido.
  • Cada nível ganha 2 espaços de recuo; e use chaves sempre, porque sem elas o else vai para o if mais próximo, não importa a indentação.
  • Aninhar também protege: o if de fora pode garantir que a pergunta de dentro não dê erro.
  • Dois if aninhados sem else = um if com &&. Um else com só um if dentro = else if.
  • Pirâmides de três níveis ou mais ficam difíceis de ler: inverta as perguntas e use uma cadeia de else if.
  • Variáveis criadas dentro de um bloco não existem fora dele (ReferenceError): crie com let antes dos if.
