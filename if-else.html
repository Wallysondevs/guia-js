JavaScript else e else if

Na aula if, o programa decidia entre fazer uma coisa ou não fazer nada. Mas muitas decisões têm dois lados: aprovado ou reprovado, maior de idade ou menor, frete grátis ou frete pago. Para isso existe o else, que em inglês quer dizer "senão". E quando são mais de dois caminhos (nota A, B, C ou D), entra o else if: "senão, se".

Você vai aprender
  • Como o else dá ao if um caminho para quando a condição é falsa.
  • Que, num if … else, exatamente um dos dois blocos roda, nunca os dois e nunca nenhum.
  • Como escolher entre vários caminhos com else if, e por que a ordem das condições importa.
  • Quando o else final é útil, e quando ele pode faltar.
  • A diferença entre uma cadeia de else if e vários if soltos.
  • Os erros reais: else sem if, elseif junto e else com condição.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: a bifurcação na estrada

A Ana vai de bicicleta para a escola. No meio do caminho, a rua se divide em duas. Ela combinou consigo mesma: "Se estiver atrasada, pego o atalho pela avenida; senão, vou pela praça, que é mais bonita."

  • Ela sempre pega um dos dois caminhos. Nunca os dois ao mesmo tempo, e nunca fica parada na bifurcação.
  • Quem decide é uma pergunta só: estou atrasada? Sim → avenida. Não → praça.
  • Depois de qualquer um dos dois, ela chega ao mesmo lugar: a escola.

É exatamente o que o if … else faz com o seu programa.

Onde fica o else

O estilo mais comum em JavaScript é } else {, tudo na mesma linha: fecha o bloco do if e já abre o do else. Para o Node, tanto faz pôr o else na linha de baixo; mas, como quase todo mundo escreve assim, o seu código fica parecido com o que você vai ler por aí.

2. else if: mais de dois caminhos

A escola da Ana não dá só "aprovada" ou "reprovada": ela dá um conceito. De 9 a 10 é A, de 7 a 8,9 é B, de 5 a 6,9 é C, e abaixo de 5 é D. São quatro caminhos. Para isso, encaixe else if entre o if e o else:

const nota = 7.5;

if (nota >= 9) {
  console.log("Conceito A");
} else if (nota >= 7) {
  console.log("Conceito B");
} else if (nota >= 5) {
  console.log("Conceito C");
} else {
  console.log("Conceito D");
}

$ node conceito.js
Conceito B

O Node lê a cadeia de cima para baixo e para na primeira condição verdadeira:

PassoPerguntaCom nota 7.5O que acontece
1nota >= 9?falsePula o bloco do A e vai para o próximo teste
2nota >= 7?trueRoda o bloco do B e sai da cadeia inteira
3nota >= 5?nem é perguntado(seria true, mas a cadeia já terminou)
4elsenem é olhado

Repare num detalhe esperto: o segundo teste é só nota >= 7, e não nota >= 7 && nota < 9. Não precisa: se a nota fosse 9 ou mais, o primeiro teste já teria pegado. Quem chega ao segundo teste já sabe que a nota é menor que 9.

Testando várias notas de uma vez (o for … of que repete o teste para cada nota é assunto de Percorrendo com for … of; por enquanto, só olhe a saída):

for (const nota of [10, 9, 8.9, 7, 6.9, 5, 4.9, 0]) {
  if (nota >= 9) {
    console.log(`${nota} → A`);
  } else if (nota >= 7) {
    console.log(`${nota} → B`);
  } else if (nota >= 5) {
    console.log(`${nota} → C`);
  } else {
    console.log(`${nota} → D`);
  }
}

3. A ordem importa

Como a cadeia para na primeira condição verdadeira, a ordem dos testes muda o resultado. Veja o que acontece se a Ana testar do menor para o maior:

const nota = 9.5;

if (nota >= 5) {
  console.log("Conceito C");
} else if (nota >= 7) {
  console.log("Conceito B");
} else if (nota >= 9) {
  console.log("Conceito A");
} else {
  console.log("Conceito D");
}

$ node ordem.js
Conceito C

Um 9,5 virou C! O primeiro teste, 9.5 >= 5, já deu true, e a cadeia acabou ali. Os testes do B e do A nunca chegam a ser feitos: qualquer nota que passaria neles também passa no >= 5. Não há erro, nenhuma mensagem; o programa só fica errado.

Regra prática: com >=, comece pela condição mais difícil de cumprir (a maior nota) e desça. Com <, o contrário: comece pela menor.

4. O else final é opcional

A cadeia pode terminar num else if, sem o else. Aí, se nenhuma condição for verdadeira, nenhum bloco roda. A Ana quer um aviso só para estoques críticos:

const estoque = 20;

if (estoque === 0) {
  console.log("Produto esgotado!");
} else if (estoque < 5) {
  console.log("Estoque baixo.");
}

console.log(`Estoque: ${estoque}`);

$ node semelse.js
Estoque: 20

Com 20 unidades, nem o === 0 nem o < 5 são verdadeiros, e não há else: nada de aviso. Use o else final quando tem de acontecer alguma coisa em qualquer caso (todo aluno recebe um conceito); deixe sem quando "nenhum dos casos" for uma resposta normal.

Formas diferentes de fazer a mesma coisa

Cadeia de else if × vários if soltos

Parece a mesma coisa, mas não é. Compare a cadeia de conceitos com a mesma lógica escrita com if separados:

const nota = 9.5;

if (nota >= 9) {
  console.log("Conceito A");
}
if (nota >= 7) {
  console.log("Conceito B");
}
if (nota >= 5) {
  console.log("Conceito C");
}

$ node soltos.js
Conceito A
Conceito B
Conceito C

Três conceitos para a mesma aluna! Cada if solto é uma pergunta independente; todos são testados, e todos os verdadeiros rodam. Na cadeia de else if, só o primeiro verdadeiro roda. Use if soltos quando as coisas podem acontecer juntas (a compra pode ter frete grátis e brinde); use else if quando é uma coisa ou outra.

Dois caminhos numa linha: o ternário

Quando os dois caminhos só escolhem um valor, existe uma forma curta, o operador ternário (aula O Operador Ternário):

const nota = 8;
const situacao = nota >= 7 ? "Aprovada" : "Reprovada";
console.log(situacao);

$ node ternario.js
Aprovada

Muitos valores fixos: o switch

Quando cada caminho corresponde a um valor exato (o dia da semana é "sábado", "domingo"…), em vez de uma faixa, o switch pode ficar mais organizado. Ele tem aula própria: switch.

O else não tem condição: ele já quer dizer "em todos os outros casos". Com else (nota < 7), o Node entende que o bloco do else é a expressão (nota < 7) e não sabe o que fazer com a { seguinte. Como consertar: tire a condição (} else {) ou, se ela for mesmo necessária, escreva } else if (nota < 7) {.

Um buraco entre as faixas

Este não dá mensagem nenhuma. A Ana escreveu as faixas pensando em números inteiros:

const nota = 6.5;
if (nota >= 7) {
  console.log("Aprovada!");
} else if (nota <= 6) {
  console.log("Reprovada.");
}
console.log("Fim.");

$ node buraco.js
Fim.

A nota 6,5 não é >= 7 nem <= 6: caiu no "buraco" entre as faixas, e a aluna ficou sem resultado. Como consertar: use else para "todo o resto", em vez de tentar descrever cada faixa: } else {. Se as faixas forem necessárias, faça cada uma começar exatamente onde a anterior termina (>= 7 e depois < 7).

Resumo

  • else ("senão") dá ao if um segundo caminho, para quando a condição é falsa. O else não tem condição. Com if … else, roda exatamente um dos dois blocos.
  • else if ("senão, se") encadeia mais caminhos. O Node testa de cima para baixo e roda só o bloco da primeira condição verdadeira.
  • A ordem importa: com >=, comece pela condição mais difícil (a maior).
  • O else final é opcional; sem ele, pode ser que nenhum bloco rode.
  • if soltos são perguntas independentes (vários podem rodar); else if é "uma coisa ou outra".
  • Erros comuns: algo entre } e else (Unexpected token 'else'), elseif junto e condição no else (Unexpected token '{').
