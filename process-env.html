JavaScript process.env e process.exit

Um programa não vive sozinho: ele roda dentro de um computador, que tem um dono, uma língua, pastas, configurações. E, quando termina, ele avisa a quem o chamou se deu tudo certo. O objeto process do Node cuida das duas pontas: process.env traz as variáveis de ambiente, as configurações que chegam de fora do programa; process.exit encerra o programa com um código de saída, o "deu certo" ou "deu errado" que ele devolve. As duas coisas são só do Node.

Você vai aprender
  • O que são variáveis de ambiente e como lê-las com process.env.NOME.
  • Como definir uma variável só para um comando (DESCONTO=10 node loja.js) e com export.
  • Por que os valores chegam sempre como texto, e como usar um valor padrão com ??.
  • Como guardar as configurações num arquivo .env e carregá-lo com --env-file ou process.loadEnvFile().
  • Por que senhas vão em variáveis de ambiente, e não no código.
  • O que é o código de saída (echo $?) e como escolhê-lo com process.exit(n) e process.exitCode.
  • Como o terminal usa o código de saída com && e ||.

Tudo rodou no Node.js v24.22.0 da máquina da Ana (usuária ana, computador notebook), num terminal com o bash.

A ideia: o quadro de avisos e o sinal de "tudo certo"

Na parede da padaria há um quadro de avisos: "Loja: Padaria da Ana", "Desconto de hoje: 10%". O padeiro não precisa decorar nada; ele olha o quadro. Amanhã o desconto muda, e ninguém reescreve a receita: muda-se o quadro. As variáveis de ambiente são esse quadro: pares NOME=valor que o terminal entrega a todo programa que ele roda.

E, no fim do expediente, o padeiro avisa o gerente: um polegar para cima ("tudo certo") ou um número que diz qual foi o problema ("faltou farinha", "o forno quebrou"). Esse é o código de saída: 0 quer dizer "terminei bem"; qualquer outro número quer dizer "deu algum problema".

1. Lendo variáveis de ambiente: process.env

O terminal já vem com várias variáveis. Duas delas, vistas pelo próprio terminal com o echo e o $:

$ echo $HOME
/home/ana
$ echo $USER
ana

HOME é a pasta pessoal; USER, o nome da usuária. No Node, as mesmas variáveis estão no objeto process.env (de environment, "ambiente"):

console.log(process.env.HOME);
console.log(process.env.USER);
console.log(process.env.LANG);
console.log(process.env.NOME_DA_LOJA);
console.log(typeof process.env);

$ node quem.js
/home/ana
ana
pt_BR.UTF-8
undefined
object
process.env
Um objeto (o typeof confirma) com uma propriedade para cada variável de ambiente. Lê-se como qualquer objeto (veja Propriedades).
process.env.HOME, .USER
A pasta e o nome da Ana.
process.env.LANG
A língua do sistema: pt_BR.UTF-8 (português do Brasil).
process.env.NOME_DA_LOJA
Uma variável que não existe: dá undefined, como qualquer propriedade que falta.

Por tradição, nomes de variáveis de ambiente são em MAIÚSCULAS, com _ separando as palavras: NOME_DA_LOJA, DESCONTO. Num computador de verdade há dezenas delas; os valores dependem da máquina e de quem está usando.

2. Definindo uma variável para o seu programa

O programa da loja lê duas configurações do ambiente e usa um valor padrão com o ?? (veja ?. e ??) quando elas não existem:

const loja = process.env.LOJA ?? "Padaria da Ana";
const desconto = Number(process.env.DESCONTO ?? "0");
console.log(`Bem-vindo à ${loja}!`);
console.log(`Desconto de hoje: ${desconto}%`);

Para dar valor a uma variável só para um comando, escreva NOME=valor antes dele, na mesma linha (sem espaços em volta do =; aspas se o valor tiver espaço):

$ node loja.js
Bem-vindo à Padaria da Ana!
Desconto de hoje: 0%
$ LOJA="Padaria Pão Quente" node loja.js
Bem-vindo à Padaria Pão Quente!
Desconto de hoje: 0%
$ DESCONTO=10 LOJA="Padaria Pão Quente" node loja.js
Bem-vindo à Padaria Pão Quente!
Desconto de hoje: 10%
$ node loja.js
Bem-vindo à Padaria da Ana!
Desconto de hoje: 0%

Repare na última execução: as variáveis valeram só para aquele comando e sumiram. Para que valham para todos os comandos seguintes naquele terminal, use export ("exportar"); para apagar, unset ("desdefinir"):

$ export DESCONTO=15
$ node loja.js
Bem-vindo à Padaria da Ana!
Desconto de hoje: 15%
$ echo $DESCONTO
15
$ unset DESCONTO
$ node loja.js
Bem-vindo à Padaria da Ana!
Desconto de hoje: 0%

O export dura até você fechar o terminal. Esse jeito (NOME=valor comando e export) é do bash, o terminal do Linux e do macOS; no PowerShell do Windows se escreve $env:DESCONTO = "10".

Por que não usar process.argv?

Os argumentos são o pedido de cada vez ("cumprimente a Ana"); as variáveis de ambiente são a configuração do lugar onde o programa roda ("a loja se chama tal", "a senha do banco de dados é tal"). Um programa costuma usar os dois.

Experimente: rode o programa da loja no editor. Depois mude o valor padrão do ?? para o nome da padaria do seu bairro e rode de novo.

const loja = process.env.LOJA ?? "Padaria da Ana";
const desconto = Number(process.env.DESCONTO ?? "0");
console.log(`Bem-vindo à ${loja}!`);
console.log(`Desconto de hoje: ${desconto}%`);

3. Os valores são sempre texto

Como nos argumentos da linha de comando, tudo em process.env é string:

console.log(process.env.DESCONTO, typeof process.env.DESCONTO);
console.log(process.env.DESCONTO + 5);

$ DESCONTO=10 node tipo.js
10 string
105

"10" + 5 deu 105, a junção dos textos. Por isso o loja.js usa Number(…). Até o que o próprio programa grava vira texto:

process.env.LOJA = "Mudei aqui dentro";
process.env.NUMERO = 42;
console.log(process.env.LOJA);
console.log(process.env.NUMERO, typeof process.env.NUMERO);

$ node muda.js
Mudei aqui dentro
42 string
$ echo "LOJA=$LOJA"
LOJA=

O número 42 foi guardado como "42". E a mudança ficou dentro do programa: o terminal, depois, continua sem a variável LOJA. Um programa não muda o ambiente de quem o chamou.

4. O arquivo .env

Quando as configurações são muitas, digitar todas antes do comando cansa. O costume é guardá-las num arquivo chamado .env (com ponto no começo, o que o deixa escondido no ls), uma por linha:

# configurações da padaria
LOJA="Padaria Pão Quente"
DESCONTO=20
SENHA_DO_CAIXA=troque-esta-senha

As linhas com # são comentários. O Node 24 lê esse arquivo sozinho com a opção --env-file:

$ node --env-file=.env loja.js
Bem-vindo à Padaria Pão Quente!
Desconto de hoje: 20%
$ node loja.js
Bem-vindo à Padaria da Ana!
Desconto de hoje: 0%
node --env-file=.env loja.js
"Antes de rodar o loja.js, ponha no process.env as variáveis do arquivo .env". A opção vem antes do nome do programa (depois dele, seria um argumento do programa).
node loja.js
Sem a opção, o arquivo é ignorado.

Também dá para carregar de dentro do programa, com process.loadEnvFile() ("carregar o arquivo de ambiente"), que procura um .env na pasta atual:

process.loadEnvFile();
console.log(process.env.LOJA);

Se o arquivo não existir, as duas formas dão erro (veja Quando dá errado). Para quando o .env é opcional existe --env-file-if-exists, que só avisa:

$ node --env-file-if-exists=.env loja.js
.env not found. Continuing without it.
Bem-vindo à Padaria da Ana!
Desconto de hoje: 0%

".env não encontrado. Continuando sem ele." (Antes de o Node ganhar o --env-file, na versão 20.6, isso exigia um pacote, o dotenv; você ainda vai vê-lo em muitos projetos.)

Senhas ficam fora do código

Senhas, chaves de acesso e afins nunca se escrevem no .js: o código é copiado, mandado para colegas, publicado no GitHub, e a senha iria junto. Elas vão em variáveis de ambiente (ou no .env), e o programa as lê com process.env.SENHA_DO_CAIXA. O próprio .env também não se compartilha: ele entra no .gitignore, como a node_modules (veja npm). Costuma-se deixar no projeto um .env.exemplo com os nomes e valores de mentira, para quem chegar saber o que preencher.

5. O código de saída: echo $?

Todo programa, ao terminar, devolve um número ao terminal. Logo depois, o terminal o mostra com echo $?:

$ node quem.js > /dev/null
$ echo $?
0
$ node erro.js > /dev/null 2>&1
$ echo $?
1

(O > /dev/null só joga fora o que o programa escreveu, para a tela ficar limpa; o 2>&1 joga fora também a mensagem de erro.) O quem.js terminou normalmente: código 0. O erro.js (que tem um null.nome, um erro não tratado; veja Lendo uma Mensagem de Erro) terminou com 1, que é o que o Node devolve quando o programa morre com erro.

CódigoQuer dizer
0Terminou bem. É o que o Node devolve quando o programa chega ao fim sozinho.
1Deu errado (erro geral). É o que o Node devolve num erro não tratado.
2, 3…Você escolhe o significado, para diferenciar os problemas.

6. Encerrando com process.exit(n)

process.exit ("sair") encerra o programa na hora, com o código que você passar. O que vem depois não roda:

console.log("Abrindo o caixa...");
process.exit(0);
console.log("Esta linha nunca aparece.");

$ node fim.js
Abrindo o caixa...
$ echo $?
0

O uso mais comum é parar quando algo impede o programa de continuar, com um código diferente para cada problema:

const paes = Number(process.argv[2]);

if (Number.isNaN(paes)) {
  console.error("Erro: informe a quantidade de pães, em número.");
  process.exit(2);
}
if (paes === 0) {
  console.error("Acabou o pão!");
  process.exit(1);
}
console.log(`Temos ${paes} pães.`);

$ node estoque.js 30
Temos 30 pães.
$ echo $?
0
$ node estoque.js 0
Acabou o pão!
$ echo $?
1
$ node estoque.js muitos
Erro: informe a quantidade de pães, em número.
$ echo $?
2
process.argv[2]
A quantidade vem como argumento (veja process.argv).
console.error(…)
As mensagens de problema vão para a saída de erros (veja console.error).
process.exit(2)
Para o programa com código 2: "a entrada estava errada".
process.exit(1)
Para com código 1: "acabou o pão". O console.log do fim não chega a rodar.

Missão: a caixa roda node main.js 0. O programa avisa que acabou o pão, mas segue em frente e ainda diz Temos 0 pães., terminando com código 0. Faça-o parar logo depois do aviso, com o código de saída 1.

const paes = Number(process.argv[2]);

if (paes === 0) {
  console.error("Acabou o pão!");
}
console.log(`Temos ${paes} pães.`);

const paes = Number(process.argv[2]);

if (paes === 0) {
  console.error("Acabou o pão!");
  process.exit(1);
}
console.log(`Temos ${paes} pães.`);

Para que serve o código? && e || no terminal

Quem lê o código de saída é quem chamou o programa: o terminal, um script, o npm, um servidor que testa o seu código. No terminal, && roda o segundo comando só se o primeiro deu 0; ||, só se ele não deu 0:

$ node estoque.js 30 && echo "Pode abrir a padaria."
Temos 30 pães.
Pode abrir a padaria.
$ node estoque.js 0 && echo "Pode abrir a padaria."
Acabou o pão!
$ node estoque.js 0 || echo "Chame o padeiro!"
Acabou o pão!
Chame o padeiro!

É a mesma ideia do && e do || do JavaScript (veja Operadores Lógicos), aplicada a comandos. Foi assim que o npm test da aula O package.json "falhou": o script terminava com exit 1.

7. process.exitCode: avisar sem cortar

O process.exit corta o programa no meio, mesmo que ainda haja coisa para fazer. Aqui, um setTimeout (veja setTimeout e setInterval) ia mostrar uma mensagem depois de 1 segundo:

setTimeout(() => {
  console.log("O pão ficou pronto!");
}, 1000);
console.log("Pão no forno...");
process.exit(0);

$ node corta.js
Pão no forno...

O pão nunca ficou pronto: o process.exit encerrou tudo antes. Quando você só quer marcar que houve um problema e deixar o programa terminar o trabalho, troque por process.exitCode = n ("código de saída"): o programa segue, e o código vale quando ele acabar sozinho.

const precos = { sonho: 3.5, broa: -2, rosca: 6, bolo: "caro" };

for (const [item, preco] of Object.entries(precos)) {
  if (typeof preco !== "number" || preco < 0) {
    console.error(`Preço inválido: ${item}`);
    process.exitCode = 1;
  }
}
console.log("Conferência terminada.");

$ node conferir.js
Preço inválido: broa
Preço inválido: bolo
Conferência terminada.
$ echo $?
1

Os dois preços errados foram listados, a conferência chegou ao fim, e o código foi 1. Com process.exit(1) no lugar, o programa teria parado na broa, sem conferir o resto.

A Ana apagou o .env e rodou com --env-file:

4. Espaço em volta do =

Com espaços, o bash não define variável nenhuma: ele acha que DESCONTO é o nome de um comando (com os argumentos =, 10, node…) e reclama que esse comando não existe. O Node nem chegou a rodar. Escreva colado: DESCONTO=10.

6. A segunda metade do trabalho sumiu

Um process.exit no meio do programa corta tudo o que falta, inclusive o que estava agendado (o pão que nunca ficou pronto, na seção 7). Se o programa parece "parar cedo demais", procure um process.exit e veja se não era caso de process.exitCode.

Missão: o programa confere as notas da turma (de 0 a 10), mas para no primeiro erro: mostra só a Bia e nunca chega ao fim. Faça-o listar todas as notas inválidas, mostrar Conferência terminada. e, mesmo assim, terminar com código de saída 1. Dica: troque o process.exit(1) por process.exitCode = 1.

const notas = { Ana: 9, Bia: 11, Davi: 7, Caio: -1 };

for (const [aluno, nota] of Object.entries(notas)) {
  if (nota < 0 || nota > 10) {
    console.error(`Nota inválida: ${aluno}`);
    process.exit(1);
  }
}
console.log("Conferência terminada.");

const notas = { Ana: 9, Bia: 11, Davi: 7, Caio: -1 };

for (const [aluno, nota] of Object.entries(notas)) {
  if (nota < 0 || nota > 10) {
    console.error(`Nota inválida: ${aluno}`);
    process.exitCode = 1;
  }
}
console.log("Conferência terminada.");

Resumo

  • process.env é um objeto com as variáveis de ambiente: configurações que chegam de fora do programa. Variável que não existe vale undefined; use ?? para um padrão.
  • No bash: NOME=valor node app.js vale para um comando; export NOME=valor, para o terminal. Os valores são sempre texto: converta com Number().
  • Configurações em quantidade vão num .env, carregado com node --env-file=.env ou process.loadEnvFile(). Senhas ficam no ambiente, nunca no código, e o .env não vai para o Git.
  • Todo programa devolve um código de saída (echo $?): 0 = tudo certo; outro número = problema. Erro não tratado dá 1.
  • process.exit(n) encerra na hora; process.exitCode = n marca o código e deixa o programa terminar.
  • O terminal usa o código com && (se deu certo) e || (se deu errado).
