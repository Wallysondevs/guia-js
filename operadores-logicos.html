JavaScript Operadores Lógicos

Na aula Comparação, você fez perguntas de uma parte só: "a idade é maior ou igual a 18?", "o preço é menor que 50?". A vida real quase sempre pergunta duas coisas ao mesmo tempo: "tem ingresso e tem idade?", "paga com dinheiro ou com cartão?", "não está chovendo?". Para juntar perguntas existem os operadores lógicos: && (E), || (OU) e ! (NÃO).

Você vai aprender
  • O && ("E"): verdadeiro só quando as duas partes são verdadeiras.
  • O || ("OU"): verdadeiro quando pelo menos uma parte é verdadeira.
  • O ! ("NÃO"): inverte, true vira false e vice-versa.
  • Como juntar comparações: "a nota está entre 0 e 10" e "a nota é inválida".
  • O curto-circuito: quando o JavaScript nem olha a segunda parte.
  • Que && e || devolvem um dos valores, e não só true/false (nome || "visitante"), e a pegadinha do 0.
  • Os erros reais: and/or escritos por extenso, o & sozinho, e o cor === "azul" || "verde".

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: as regras da portaria do cinema

O cinema do bairro tem um cartaz na porta da sala do filme de terror:

  1. "Para entrar, é preciso ter ingresso E ter 14 anos ou mais." Quem tem ingresso mas tem 12 anos fica de fora. Quem tem 20 anos mas não comprou ingresso também. As duas condições precisam ser verdade.
  2. Na bilheteria: "Aceitamos dinheiro OU cartão." Basta uma das duas. Quem tem as duas também paga, claro.
  3. Na pipoca: "Promoção válida se o cliente NÃO for funcionário." O "não" vira a resposta ao contrário.

Cada pergunta do cartaz tem resposta true (verdadeiro) ou false (falso), os booleanos. Os operadores lógicos pegam essas respostas e montam uma resposta nova:

OU||"ou" (duas barras verticais grudadas; no teclado ABNT, Shift + a tecla ao lado do Z)
NÃO!"não" (o ponto de exclamação, sempre antes do valor)

1. && (E): as duas partes têm de ser verdade

const idade = 16;
const temIngresso = true;

console.log(idade >= 14 && temIngresso);
console.log(idade >= 18 && temIngresso);
idade >= 14
A primeira pergunta: "a idade é 14 ou mais?". Com idade valendo 16, a resposta é true.
&&
O "E". Junta a pergunta da esquerda com a da direita.
temIngresso
A segunda pergunta. Aqui ela já é um booleano pronto (true), então não precisa de comparação: temIngresso === true seria o mesmo que temIngresso, só mais comprido.
idade >= 18 && temIngresso
Agora a primeira parte é false (16 não é 18 ou mais). Como o "E" exige as duas, o resultado é false, mesmo com o ingresso.

true
false

Todas as combinações possíveis cabem numa tabelinha, a tabela-verdade do &&. Ela saiu deste programa:

console.log("true  && true  →", true && true);
console.log("true  && false →", true && false);
console.log("false && true  →", false && true);
console.log("false && false →", false && false);

Resumindo: basta um false para o "E" dar false. Só dá true quando tudo é true.

2. || (OU): basta uma parte ser verdade

const temDinheiro = false;
const temCartao = true;

console.log(temDinheiro || temCartao);
console.log(temDinheiro || false);

$ node pagamento.js

false

Na primeira linha, a Ana não tem dinheiro, mas tem cartão: uma das duas basta, true. Na segunda, as duas partes são false, então o "OU" também dá false. A tabela-verdade do ||:

console.log("true  || true  →", true || true);
console.log("true  || false →", true || false);
console.log("false || true  →", false || true);
console.log("false || false →", false || false);

$ node tabela-ou.js
true  || true  → true
true  || false → true
false || true  → true
false || false → false

O espelho do "E": basta um true para o "OU" dar true. Só dá false quando tudo é false.

O "ou" do JavaScript não é o "ou um ou outro"

Em português, "café ou chá?" costuma querer dizer "escolha só um". O || não é assim: true || true dá true. Quem tem dinheiro e cartão também pode pagar.

3. ! (NÃO): inverte a resposta

const ehFuncionario = false;
const ganhaPromocao = !ehFuncionario;

console.log("Funcionário?", ehFuncionario);
console.log("Ganha a promoção?", ganhaPromocao);
console.log(!true, !false);

$ node nao.js
Funcionário? false
Ganha a promoção? true
false true

O ! vem colado antes do valor (!ehFuncionario) e só trabalha com um valor, enquanto o && e o || ficam entre dois. Ele lê "não é funcionário?": como ehFuncionario é false, a resposta invertida é true.

Para inverter uma expressão inteira, use parênteses: !(idade >= 18) quer dizer "a idade não é 18 ou mais" (o mesmo que idade < 18). Sem os parênteses, o ! pegaria só o idade, e o resultado seria outro (veja Quando dá errado).

Missão: a lojinha da Ana dá frete grátis para compras de R$ 100 ou mais OU para clientes VIP. O programa abaixo usa o operador errado e nega o frete para uma cliente VIP que comprou R$ 80. Troque o operador para aparecer Frete grátis? true.

const totalCompra = 80;
const clienteVip = true;
const freteGratis = totalCompra >= 100 && clienteVip;

const totalCompra = 80;

4. Juntando comparações: a nota entre 0 e 10

A professora da Ana quer saber se uma nota é válida, isto é, se está entre 0 e 10. Em matemática se escreve 0 ≤ nota ≤ 10, mas no JavaScript são duas perguntas ligadas por um "E": a nota é maior ou igual a 0 e menor ou igual a 10.

const nota = 7.5;
const notaValida = nota >= 0 && nota <= 10;
const notaInvalida = nota < 0 || nota > 10;

console.log("Nota:", nota);
console.log("Válida?", notaValida);
console.log("Inválida?", notaInvalida);

$ node nota.js
Nota: 7.5
Válida? true
Inválida? false

Repare que as duas perguntas são o avesso uma da outra: "válida" usa && (dentro da faixa: as duas pontas valem), e "inválida" usa || (fora da faixa: basta escapar por um lado). Trocando a nota para 15, as respostas se invertem:

$ node nota15.js
Nota: 15
Válida? false
Inválida? true

Três partes ou mais

Dá para encadear quantas partes quiser: a && b && c só é true se as três forem; a || b || c é true se qualquer uma for. Quando misturar && com ||, use parênteses para deixar claro o que vai junto. No parque de diversões, a montanha-russa exige 1,40 m de altura e (12 anos ou um adulto junto):

const altura = 1.45;
const idade = 10;
const comAdulto = true;

const podeEntrar = altura >= 1.4 && (idade >= 12 || comAdulto);
console.log("Pode entrar?", podeEntrar);

$ node parque.js
Pode entrar? true

O JavaScript resolve primeiro os parênteses (false || true → true) e depois o "E" (true && true → true). Sem parênteses, o && seria feito antes do ||, porque ele tem prioridade maior (como a multiplicação antes da soma). A aula Precedência dos Operadores mostra a ordem completa; por enquanto, a regra prática é: misturou && e ||, ponha parênteses.

5. O curto-circuito: quando a segunda parte nem é olhada

O JavaScript lê da esquerda para a direita e é preguiçoso de um jeito esperto:

  • no a && b, se a já é falso, o resultado vai ser falso, então ele nem olha o b;
  • no a || b, se a já é verdadeiro, o resultado vai ser verdadeiro, então ele nem olha o b.

Isso se chama curto-circuito. Dá para ver acontecendo pondo um console.log na segunda parte:

console.log("Começo");
false && console.log("1. isto não aparece");
true && console.log("2. isto aparece");
true || console.log("3. isto não aparece");
false || console.log("4. isto aparece");
console.log("Fim");

$ node curto.js
Começo
2. isto aparece
4. isto aparece
Fim

As linhas 1 e 3 nunca rodaram: o JavaScript já sabia a resposta pela primeira parte. Isso não é só curiosidade, é uma proteção muito usada. Imagine que o nome do cliente pode não ter sido preenchido (null, veja null e undefined):

const nome = null;
const temNome = nome !== null && nome.length > 0;
console.log("Tem nome?", temNome);

$ node protecao.js
Tem nome? false

Como nome !== null deu false, o nome.length (o tamanho do texto) nunca foi calculado. E ainda bem: pedir o .length de null é um erro que derruba o programa (veja Quando dá errado).

6. && e || devolvem um dos valores

Até aqui, tudo deu true ou false. Mas a regra exata é outra: o && e o || devolvem um dos dois valores, exatamente o que fez o JavaScript decidir. Com booleanos não dá para notar a diferença; com textos e números, dá:

console.log("Ana" || "visitante");
console.log("" || "visitante");
console.log(null || "visitante");
console.log("Ana" && "Bia");
console.log(null && "Bia");
console.log(0 || 10);

$ node valores.js
Ana
visitante
visitante
Bia
null
10

Para entender, você precisa de uma ideia da aula Truthy e Falsy: alguns valores contam como falso numa pergunta (false, 0, "" o texto vazio, null, undefined e NaN), e todos os outros contam como verdadeiro. Com isso:

OperadorO que devolveExemplo
a || bO a, se ele contar como verdadeiro; senão, o b"" || "visitante" → visitante
a && bO a, se ele contar como falso; senão, o bnull && "Bia" → null
!aSempre um booleano: true se a conta como falso!"" → true

O uso mais comum disso é o valor padrão: "use o nome, e, se ele estiver vazio, use visitante":

const nomeDigitado = "";
const nome = nomeDigitado || "visitante";
console.log(`Olá, ${nome}!`);

$ node padrao.js
Olá, visitante!

(O `Olá, ${nome}!` com crases é um template string, que encaixa o valor da variável no texto.)

A pegadinha do 0

O 0 também conta como falso. Se a quantidade em estoque pode ser zero, quantidade || 10 troca o zero por 10, e o programa diz que tem 10 pães quando não tem nenhum (a última linha de valores.js mostrou: 0 || 10 deu 10). Para "use o padrão só quando o valor faltar (null ou undefined)", o JavaScript tem o ??: 0 ?? 10 dá 0. Ele tem aula própria: ?. e ??.

E o !! (dois "não" seguidos)? Ele inverte duas vezes, e o que sobra é o booleano que o valor "conta como": !!"Ana" dá true, !!"" dá false. Você vai encontrá-lo em código dos outros; o jeito mais claro de escrever a mesma coisa é Boolean("Ana") (veja Conversão).

console.log(!!"Ana", !!"", !!0, !!42);
console.log(Boolean("Ana"), Boolean(""));

$ node duplo.js
true false false true
true false

Formas diferentes de fazer a mesma coisa

A mesma pergunta pode ser escrita de mais de um jeito. As duas linhas de cada par abaixo dão sempre o mesmo resultado:

const nota = 15;

// "a nota é inválida?"
console.log(nota < 0 || nota > 10);
console.log(!(nota >= 0 && nota <= 10));

// "não tem dinheiro E não tem cartão?"
const temDinheiro = false;
const temCartao = false;
console.log(!temDinheiro && !temCartao);
console.log(!(temDinheiro || temCartao));

$ node formas.js
true
true
true
true

Esse "troca-troca" tem nome: leis de De Morgan. Para negar uma pergunta com "E", negue cada parte e troque o "E" por "OU" (e vice-versa): "não (A e B)" é o mesmo que "não A ou não B". Na prática, escolha a forma que se lê melhor em voz alta: nota < 0 || nota > 10 ("menor que zero ou maior que dez") é mais fácil de entender que a versão com !( … ).

SituaçãoQual usar
Todas as condições precisam valer (faixa de valores, "tem isso e aquilo")a && b
Basta uma condição (várias formas de pagamento, várias exceções)a || b
Inverter um booleano!a (para uma expressão inteira: !( … ))
Valor padrão quando o texto vem vaziovalor || "padrão"
Valor padrão só quando falta (null/undefined), e 0 ou "" são respostas válidasvalor ?? padrão (aula ?. e ??)
Transformar qualquer valor em booleanoBoolean(valor) (ou !!valor, em código antigo)

Nas próximas aulas, os operadores lógicos vão aparecer o tempo todo dentro do if ("se"), que decide se um trecho do programa roda ou não: if (nota >= 0 && nota <= 10) { … } (veja if).

Nenhuma mensagem de erro, e por isso é traiçoeiro: o & e o | sozinhos existem, mas são outros operadores (os "bit a bit", que fazem contas com os zeros e uns dentro dos números). Eles transformam true em 1 e false em 0 e devolvem um número, não um booleano, e não fazem curto-circuito. Como consertar: são sempre dois: && e ||.

cor === "azul" || "verde": o "ou" que sempre dá certo 
const cor = "vermelho";
const corFria = cor === "azul" || "verde";
console.log("É cor fria?", corFria);

$ node cor.js
É cor fria? verde

A Ana quis perguntar "a cor é azul ou verde?". Mas o JavaScript leu duas partes separadas: cor === "azul" (que dá false) ou "verde" (um texto que não está vazio, que conta como verdadeiro). Pela regra da seção 6, o || devolveu o "verde", e qualquer pergunta com esse resultado vai achar que "sim". Como consertar: repita a comparação em cada parte: cor === "azul" || cor === "verde".

0 < nota < 10: a faixa escrita como em matemática 
const nota = 15;
console.log(0 < nota < 10);
console.log(0 < nota && nota < 10);

$ node faixa.js
true
false

A primeira linha diz que 15 está entre 0 e 10! O JavaScript faz uma comparação de cada vez: 0 < 15 dá true, e depois true < 10, em que o true vira o número 1 (veja Conversão Automática), e 1 < 10 dá true. Nenhum erro, resposta errada. Como consertar: duas comparações ligadas por &&, como na segunda linha.

Resumo

  • && (E) dá true só quando todas as partes são verdadeiras; || (OU) dá true quando pelo menos uma é; ! (NÃO) inverte.
  • Faixa de valores: x >= 0 && x <= 10. Fora da faixa: x < 0 || x > 10. Nunca 0 < x < 10.
  • Misturou && e ||? Use parênteses.
  • Curto-circuito: no &&, se a primeira parte é falsa, a segunda nem roda; no ||, se a primeira é verdadeira, idem. Serve de proteção: nome !== null && nome.length > 0.
  • && e || devolvem um dos valores: nome || "visitante" é um valor padrão (mas o 0 e o "" também contam como falso; para eles, ??).
  • Erros comuns: and/or por extenso (SyntaxError), &/| sozinhos (dão números) e x === "a" || "b" (sempre "verdadeiro").
