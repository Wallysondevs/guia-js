JavaScript Arrow Functions (=>)

Uma arrow function ("função flecha", por causa do =>, que parece uma setinha) é um jeito mais curto de escrever uma função. Ela chegou ao JavaScript em 2015 (no ES6, veja Versões) e hoje está em todo lugar: quando você ler código JavaScript moderno, vai ver => o tempo todo. Nesta aula, você vai aprender a ler e a escrever arrows, partindo das funções que já conhece.

Você vai aprender
  • Como transformar uma function numa arrow, passo a passo.
  • Como escrever arrows com zero, um ou vários parâmetros.
  • O return implícito: a arrow de uma linha devolve o valor sozinha.
  • Quando usar chaves { } no corpo, e a pegadinha que elas trazem.
  • Onde as arrows brilham: funções curtas passadas para outras funções.
  • Os erros reais mais comuns ao escrever uma arrow.

Todos os programas desta aula rodaram no Node.js 24 (v24.22.0) da máquina da Ana, com node arquivo.js. Você pode rodar cada um no editor do guia. Antes, convém conhecer Funções, Parâmetros e return.

A ideia: a abreviação

Na lista de compras, a Ana escreve "1 kg" em vez de "um quilograma", e "pão fr." em vez de "pão francês". Quem lê entende igual; só ocupa menos espaço. A arrow function é a abreviação da função: faz a mesma coisa (recebe parâmetros, roda um corpo, devolve um valor) com menos palavras. Como toda abreviação, é preciso aprender a ler, e existem algumas regras do que pode e do que não pode abreviar.

1. De function para arrow, passo a passo

As cinco funções abaixo fazem exatamente a mesma coisa: devolvem o dobro do número. Cada uma tira um pedaço da anterior.

function dobro1(n) {
  return n * 2;
}

const dobro2 = function (n) {
  return n * 2;
};

const dobro3 = (n) => {
  return n * 2;
};

const dobro4 = (n) => n * 2;

const dobro5 = n => n * 2;

console.log(dobro1(21), dobro2(21), dobro3(21), dobro4(21), dobro5(21));

$ node passos.js
42 42 42 42 42
  1. dobro1: a declaração que você já conhece.
  2. dobro2: a mesma função, sem nome, guardada numa constante (a "expressão de função" da aula Funções).
  3. dobro3: tira a palavra function e põe a seta => depois dos parênteses. Já é uma arrow.
  4. dobro4: o corpo é só um return? Então tira as chaves e o return: o que vem depois da seta é devolvido sozinho.
  5. dobro5: com um parâmetro só, até os parênteses podem sair.

A forma mais usada é a 4: (n) => n * 2. Lê-se "n vai para n * 2", ou "recebe n e devolve n * 2".

Com um parâmetro, n => n * 2 funciona, mas neste guia escrevemos (n) => n * 2: fica igual aos outros casos e, se um dia a função ganhar um segundo parâmetro, é só acrescentar. O Prettier, a ferramenta de formatação mais usada no JavaScript, faz o mesmo (veja Estilo de Código).

3. Corpo com chaves: quando a função tem mais de uma linha

Se a função precisa de mais de uma instrução (criar uma variável, um if, um console.log), o corpo vai entre chaves, como numa função comum. E aí o return volta a ser obrigatório, se a função tiver de devolver algo:

const mostrarPedido = (produto, quantidade) => {
  const linha = `${quantidade} x ${produto}`;
  console.log(`Pedido: ${linha}`);
};

const calcularTroco = (pago, total) => {
  const troco = pago - total;
  return troco;
};

mostrarPedido("pão francês", 10);
console.log(`Troco: R$ ${calcularTroco(20, 12.5)}`);

$ node corpo.js
Pedido: 10 x pão francês
Troco: R$ 7.5
CorpoExemploDevolve
Sem chaves (uma expressão)(n) => n * 2O valor da expressão, sozinho
Com chaves (bloco)(n) => { return n * 2; }Só o que tiver return; sem ele, undefined

A pegadinha das chaves

Misturar as duas formas é o erro mais comum com arrows: pôr chaves e esquecer o return.

const triplo = (n) => { n * 3 };
console.log(triplo(10));

$ node chaves.js
undefined

Com chaves, o corpo é um bloco comum, e um bloco sem return devolve undefined. A conta n * 3 é feita e jogada fora. Sem erro nenhum.

Missão: o programa mostra undefined. Conserte a arrow para mostrar 30. Há dois jeitos: tirar as chaves, ou pôr um return dentro delas.

const triplo = (n) => { n * 3 };
console.log(triplo(10));

const triplo = (n) => n * 3;
console.log(triplo(10));

A mesma pegadinha com objetos

Mais adiante, em Objetos, você vai escrever valores entre chaves, como { nome: "café" }. Uma arrow que devolve um objeto direto confunde o JavaScript, que acha que as chaves são o bloco da função:

const criarItem1 = (nome) => { nome: nome };
const criarItem2 = (nome) => ({ nome: nome });

console.log(criarItem1("café"));
console.log(criarItem2("café"));

$ node objeto.js
undefined
{ nome: 'café' }

A solução é envolver o objeto em parênteses: ({ … }). Guarde só isto por enquanto; você vai voltar aqui quando estudar objetos.

4. Onde as arrows brilham

As arrows foram feitas para funções curtas, principalmente as que se passam como argumento para outra função. Um exemplo do que vem no Nível 2: o map passa por uma lista e aplica uma função a cada item (aula map):

const precos = [0.8, 4.5, 18];
const dobrados = precos.map((preco) => preco * 2);
console.log(dobrados);

$ node map.js
[ 1.6, 9, 36 ]

A arrow (preco) => preco * 2 foi escrita direto dentro dos parênteses do map, sem nem ganhar nome. Com function, a mesma linha seria precos.map(function (preco) { return preco * 2; }): funciona, mas é bem mais comprida. Funções passadas para outras funções têm aula própria: Funções como Valores (Callbacks).

Outras diferenças, para mais tarde

Além de ser mais curta, a arrow tem diferenças técnicas em relação à function: ela não tem o seu próprio this (aula this), não pode ser usada com new (aula Classes) e não pode ser chamada antes da linha que a cria (veja em Quando dá errado). Para as funções desta parte do guia, nada disso faz diferença.

Formas diferentes de fazer a mesma coisa

Você já conhece as três formas de criar uma função. Elas convivem no mesmo programa, e cada equipe tem as suas preferências. Uma divisão comum:

Quando dá errado

Chaves sem return

É o undefined do triplo (seção 3), sem erro nenhum. Como consertar: tire as chaves ((n) => n * 3) ou ponha o return ((n) => { return n * 3; }).

A seta na linha de baixo

  => n * 2;
console.log(dobro(5));

Linha por linha: o erro está na linha 2; o ^^ marca a seta; e SyntaxError: Unexpected token '=>' quer dizer "erro de sintaxe: símbolo => inesperado". A seta tem de ficar na mesma linha dos parênteses dos parâmetros; depois dela, pode quebrar a linha à vontade. Como consertar: const dobro = (n) => n * 2;.

"Símbolo > inesperado". Com o espaço, = e > viram dois sinais separados, e o JavaScript não sabe o que fazer com o >. Como consertar: a seta é =>, grudada.

Dois parâmetros sem parênteses

"Falta o valor inicial numa declaração const". A mensagem engana: o JavaScript leu a vírgula como "agora vem outra constante", const somar = a, b, e uma constante b sem = não pode. Como consertar: com dois ou mais parâmetros, os parênteses são obrigatórios: const somar = (a, b) => a + b;.

"Não é possível acessar dobro antes da inicialização". A arrow fica numa const, e uma const só existe a partir da linha que a cria (com function dobro(n), funcionaria; veja Hoisting). Como consertar: crie as arrows no alto do arquivo, antes de usar.

Resumo

  • Arrow function é o jeito curto de escrever uma função: const dobro = (n) => n * 2;.
  • Sem chaves, o valor depois da seta é devolvido sozinho (return implícito).
  • Com chaves, o corpo é um bloco comum, e só devolve o que tiver return.
  • Parênteses: obrigatórios com zero ou vários parâmetros; opcionais com um (neste guia, sempre usamos).
  • A seta => é grudada e fica na mesma linha dos parâmetros.
  • A arrow fica numa const: crie antes de chamar. Ela brilha em funções curtas passadas para outras, como no map.
