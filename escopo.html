JavaScript Escopo (Onde a Variável Existe)

Uma variável não existe no programa inteiro: ela existe só num pedaço dele. Esse pedaço se chama escopo (em inglês, scope, "alcance"). Saber onde cada variável existe explica um dos erros mais comuns de quem começa, o ReferenceError: total is not defined logo depois de você ter criado o total, e é a base para entender a aula seguinte, Closures.

Você vai aprender
  • Os três escopos: global (o arquivo todo), de função e de bloco (as chaves { } de um if, de um for…).
  • A regra de ouro: de dentro se enxerga para fora; de fora não se enxerga para dentro.
  • O que acontece quando duas variáveis têm o mesmo nome (a de dentro faz "sombra").
  • Por que o var escapa do bloco e o let não.
  • A variável global criada sem querer, e como o modo estrito evita isso.
  • Os erros reais: is not defined, Cannot access … before initialization e has already been declared.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js.

A ideia: os cômodos de uma casa com janelas espelhadas

Imagine a casa da Ana com uma regra estranha: de dentro de cada cômodo dá para ver tudo o que está nos cômodos de fora (as janelas são de vidro espelhado, que só deixa ver de dentro para fora).

  • O quintal é o escopo global: o que está nele, qualquer cômodo vê.
  • A casa é uma função: de dentro dela se vê o quintal, mas quem está no quintal não vê o que está dentro da casa.
  • O armário dentro da casa é um bloco (as chaves de um if ou for): de dentro dele se vê a casa e o quintal; de fora, ninguém vê o que tem no armário.

Quando o JavaScript procura uma variável, ele olha primeiro no cômodo onde está; se não achar, olha no de fora, e no de fora desse, até o quintal. Se não achar em lugar nenhum, dá erro.

1. Escopo global: o arquivo todo

Uma variável criada fora de qualquer função ou bloco é global para aquele arquivo: todo mundo ali enxerga.

const loja = "Padaria da Ana";

function mostrarLoja() {
  console.log("Dentro da função:", loja);
}

mostrarLoja();
console.log("Fora da função:", loja);

$ node global.js
Dentro da função: Padaria da Ana
Fora da função: Padaria da Ana

A função não tem nenhuma variável loja; ela "olhou pela janela" e achou a do escopo global.

Para levar um valor de dentro da função para fora, a função devolve o valor com return, e quem chamou o guarda numa variável própria: const total = calcularTotal();. Esse é o jeito certo de "tirar coisas de dentro" de uma função.

Cada chamada da função ganha variáveis novas, e os parâmetros também moram no escopo da função: são variáveis locais que já chegam com valor.

3. Escopo de bloco: let e const ficam presos às chaves

Qualquer par de chaves { } de um if, else, for, while… forma um bloco. Uma variável criada com let ou const lá dentro só existe até o }:

const idade = 20;
if (idade >= 18) {
  const mensagem = "Pode votar.";
  console.log(mensagem);
}
console.log(mensagem);

$ node bloco.js
Pode votar.
/home/ana/bloco.js:6
console.log(mensagem);
            ^

ReferenceError: mensagem is not defined
    at Object.<anonymous> (/home/ana/bloco.js:6:13)    « (mais 7 linhas node:internal cortadas)

Node.js v24.22.0

O mesmo vale para a variável do for: o i de for (let i = 1; …) só existe dentro do laço. Depois dele, console.log(i) deu ReferenceError: i is not defined no lab.

Como usar o valor depois do bloco

Crie a variável antes do bloco, do lado de fora, e só dê o valor lá dentro:

let resultado;
const idade = 20;
if (idade >= 18) {
  resultado = "Pode votar.";
}
console.log(resultado);

$ node fora.js
Pode votar.

Repare: dentro do if não há let nem const. Sem eles, a linha não cria variável nova; ela procura a resultado que já existe (lá fora) e muda o valor dela.

Missão: o programa quebra na última linha com situacao is not defined. Crie a variável antes do if (let situacao;) e, dentro do if e do else, só dê o valor (tire o const).

const nota = 8;
if (nota >= 7) {
  const situacao = "aprovada";
} else {
  const situacao = "em recuperação";
}
console.log(`Situação: ${situacao}`);

const nota = 8;
let situacao;
if (nota >= 7) {
  situacao = "aprovada";
} else {
  situacao = "em recuperação";
}
console.log(`Situação: ${situacao}`);

4. Funções dentro de funções: olhando para fora, nível por nível

const cidade = "Recife";

function padaria() {
  const nome = "Doce Pão";

  function balcao() {
    const atendente = "Bia";
    console.log(`${atendente} atende na ${nome}, em ${cidade}.`);
  }

  balcao();
  console.log(typeof atendente);
}

padaria();

$ node aninhado.js
Bia atende na Doce Pão, em Recife.
undefined
EscopoCriaEnxerga

padarianomenome, cidade
balcao (dentro de padaria)atendenteatendente, nome, cidade

Para achar nome, o balcao não achou em si mesmo e subiu um nível (a padaria); para achar cidade, subiu dois. Já a padaria não vê o atendente: o typeof respondeu undefined (o typeof é o único jeito de perguntar por um nome que não existe sem dar erro; veja typeof). Essa "escada" de escopos, que o JavaScript sobe procurando o nome, se chama cadeia de escopos.

5. O mesmo nome dentro e fora: a sombra

Se você cria, lá dentro, uma variável com o mesmo nome de uma de fora, são duas variáveis diferentes. A de dentro "faz sombra" na de fora (em inglês, shadowing): enquanto você estiver dentro, só vê a de dentro.

const nome = "Ana";

function saudar() {
  const nome = "Bia";
  console.log("Dentro:", nome);
}

saudar();
console.log("Fora:", nome);

$ node sombra.js
Dentro: Bia
Fora: Ana

A nome de fora nunca mudou. O mesmo acontece com blocos: let total = 0; fora e let total = 10; dentro de um if deram, no lab, Dentro: 10 e Fora: 0. Funciona, mas confunde quem lê; prefira nomes diferentes.

Mudar × criar

Compare com uma função que muda a variável de fora, sem criar outra (sem let/const):

let vendas = 0;

function vender() {
  vendas = vendas + 1;
}

vender();
vender();
vender();
console.log("Vendas:", vendas);

$ node mudar.js
Vendas: 3
Dentro da função/blocoO que acontece
let vendas = 1; / const vendas = 1;Cria uma variável nova, só de lá de dentro (sombra, se o nome já existir fora)
vendas = 1;Procura vendas subindo os escopos e muda a que achar
Variáveis globais que mudam: com cuidado

Funções que mudam variáveis globais funcionam, mas, num programa grande, fica difícil saber quem mudou o valor. Prefira receber por parâmetro e devolver com return. Na aula Closures você vai ver um jeito de ter uma variável que só certas funções conseguem mudar.

6. O var escapa do bloco

O var, o jeito antigo de criar variáveis (veja var: o Jeito Antigo), não respeita blocos: só respeita funções.

if (true) {
  var antigo = "eu escapo do bloco";
  let novo = "eu fico no bloco";
}
console.log(antigo);
console.log(typeof novo);

$ node var.js
eu escapo do bloco     « o var "vazou" do if
undefined              « o let ficou preso nas chaves

Esse vazamento causava muitos defeitos (uma variável de um for aparecendo no resto da função, por exemplo). Foi um dos motivos para o let e o const serem criados. Por isso o guia usa só os dois.

7. A variável global criada sem querer

Se você atribui a um nome que não existe em nenhum escopo, sem let/const, um arquivo comum do Node não reclama: ele cria uma variável global, em silêncio.

function contar() {
  contador = 10;
}

contar();
console.log(contador);

$ node semdeclarar.js
10

Parece prático, mas um erro de digitação (contdor = 10) vira uma variável nova em vez de um aviso. No modo estrito (o arquivo começa com "use strict";) e nos módulos, isso vira erro, como deveria:

"use strict";

function contar() {
  contador = 10;
}

contar();
console.log(contador);

$ node estrito.js
/home/ana/estrito.js:4
  contador = 10;
           ^

ReferenceError: contador is not defined
    at contar (/home/ana/estrito.js:4:12)
    at Object.<anonymous> (/home/ana/estrito.js:7:1)
    at Module._compile (node:internal/modules/cjs/loader:1929:14)    « (mais 6 linhas node:internal cortadas)

Node.js v24.22.0

As duas linhas at de cima contam o caminho: a linha 7 chamou contar, e o erro aconteceu dentro dela, na linha 4. Regra: sempre crie as variáveis com const ou let.

Boas práticas: qual escopo usar

SituaçãoFaça
Valor usado só dentro de um if/forCrie dentro do bloco
Valor calculado no bloco e usado depoislet antes do bloco, atribuição dentro
Valor calculado numa função e usado forareturn na função, const x = f(); fora
Valor que a função precisa receberParâmetro, em vez de ler uma global
Constantes do programa todo (nome da loja, taxa)const global, no topo do arquivo

A regra geral: crie cada variável no menor escopo possível. Quanto menos lugares a enxergam, menos lugares podem estragá-la, e mais fácil é entender o programa.

Quando dá errado

Usou fora uma variável criada dentro

É o ReferenceError: … is not defined das seções 2 e 3: a variável existe, mas em outro escopo. Como consertar: crie-a no escopo de fora (seção 3) ou devolva o valor com return (seção 2). Se o nome não existe em lugar nenhum, confira a grafia: o JavaScript diferencia maiúsculas (Total ≠ total).

Usou a variável antes da linha que a cria 
const preco = 10;

function aplicarDesconto() {
  console.log(preco);
  const preco = 8;
}

aplicarDesconto();

$ node tdz.js
/home/ana/tdz.js:4
  console.log(preco);
              ^

    at aplicarDesconto (/home/ana/tdz.js:4:15)
    at Object.<anonymous> (/home/ana/tdz.js:8:1)    « (mais 7 linhas node:internal cortadas)

Node.js v24.22.0

"Não é possível acessar preco antes da inicialização". Surpresa: a Ana esperava ver o 10 de fora. Mas a função tem a sua própria preco (linha 5), e ela faz sombra na função inteira, desde a primeira linha. Só que ela só ganha valor na linha 5; antes disso, usá-la é proibido. (Esse trecho proibido tem até nome, "zona morta temporal", e é assunto da aula Hoisting.) Como consertar: use nomes diferentes (const precoComDesconto = 8;) ou mova a criação para antes do uso.

Criou duas vezes a mesma variável no mesmo escopo 
let total = 0;
let total = 10;

$ node duplicada.js
/home/ana/duplicada.js:2

    ^

    at wrapSafe (node:internal/modules/cjs/loader:1861:18)    « (mais 7 linhas node:internal cortadas)

"O identificador (nome) total já foi declarado". No mesmo escopo, cada nome só pode ser criado uma vez. Por ser erro de sintaxe, o programa nem começa. (Em escopos diferentes pode, como na seção 5.) Como consertar: na segunda vez, só atribua: total = 10;.

Resumo

  • Escopo é o pedaço do programa onde uma variável existe.
  • Global (fora de tudo), de função (dentro de uma função) e de bloco (let/const dentro de { }).
  • De dentro se enxerga para fora; de fora não se enxerga para dentro. O JavaScript sobe a cadeia de escopos procurando o nome.
  • let/const dentro cria uma variável nova (sombra, se o nome existir fora); sem eles, a linha muda a variável que já existe.
  • O var escapa dos blocos; atribuir a um nome que não existe cria uma global sem querer (erro no modo estrito).
  • Crie cada variável no menor escopo possível; para tirar um valor de uma função, use return.
