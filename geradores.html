JavaScript Geradores

Uma função comum roda do começo ao fim de uma vez só, e devolve um resultado. Um gerador é uma função que sabe pausar: entrega um valor, para, espera alguém pedir o próximo, continua de onde parou, entrega outro… Na aula Iteradores, você escreveu um next() na mão, com { value, done } e uma variável para lembrar onde parou. Com um gerador, o JavaScript faz esse trabalho todo por você.

Você vai aprender
  • Como se escreve um gerador: function* (com estrela) e yield ("entregar").
  • Por que chamar um gerador não roda nada, e como o next() faz ele andar até o próximo yield.
  • Como usar geradores no for … of e no ...: um intervalo de números em 3 linhas.
  • Sequências infinitas (uma máquina de senhas que nunca acaba) e como pegar só um pedaço delas.
  • O gerador como [Symbol.iterator] de um objeto seu, o yield* e o return do gerador.
  • Os erros reais: o yield sem a estrela, o yield dentro do forEach, a arrow function com estrela e o gerador que nunca roda.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana, com node arquivo.js. Leia antes a aula Iteradores: geradores são o jeito fácil de fazer iteradores.

A ideia: o marcador de página

A Ana está lendo uma receita comprida em voz alta para a filha, que cozinha. Ela lê um passo e para: põe o dedo na linha, espera a filha terminar aquele passo e dizer "próximo!". Aí continua exatamente de onde o dedo estava, lê o passo seguinte e para de novo. Quando a receita acaba, ela avisa: "acabou".

  • A receita é a função geradora.
  • Cada "leia este passo e pare" é um yield.
  • O dedo na linha é o que o gerador guarda sozinho: onde parou e o valor de todas as variáveis.
  • O "próximo!" da filha é o next().

1. O primeiro gerador: function* e yield

function* cardapio() {
  yield "Pão de queijo";
  yield "Café";
  yield "Bolo de fubá";
}

const garcom = cardapio();
console.log(garcom);
console.log(garcom.next());
console.log(garcom.next());
console.log(garcom.next());
console.log(garcom.next());

$ node primeiro.js
Object [Generator] {}
{ value: 'Pão de queijo', done: false }
{ value: 'Café', done: false }
{ value: 'Bolo de fubá', done: false }
{ value: undefined, done: true }
function*
A estrela depois de function transforma a função numa função geradora. (Também se escreve function *cardapio ou function * cardapio: os espaços não importam, a estrela sim.)
yield "Pão de queijo"
yield quer dizer "entregar", "render". Entrega esse valor para quem pediu e pausa a função ali, naquela linha.
const garcom = cardapio()
Chamar uma função geradora não roda o corpo dela. Devolve um objeto gerador, que o Node mostra como Object [Generator] {}. É a receita com o dedo posicionado antes da primeira linha.
garcom.next()
"Próximo!": o gerador roda até o próximo yield e devolve { value: o que foi entregue, done: false }. É o mesmo formato dos iteradores, porque o objeto gerador é um iterador.
{ value: undefined, done: true }
Na quarta chamada, a função chegou ao fim (o }) sem achar outro yield: acabou.

Compare com o iterador escrito na mão da aula anterior: aqui não há { value, done } montado por você, nem variável para lembrar a posição. O yield e a estrela cuidam disso.

2. A função que pausa de verdade

O yield não é só um "return repetido". Entre um next() e outro, a função fica congelada, e o resto do programa segue a vida. Este gerador escreve mensagens entre os passos, para você ver quando cada pedaço roda:

function* receita() {
  console.log("  (separando os ingredientes)");
  yield "1. Misture a farinha e o ovo";
  console.log("  (lavando a tigela)");
  yield "2. Leve ao forno";
  console.log("  (desligando o forno)");
}

const passos = receita();
console.log("Gerador criado. Nada rodou ainda.");
console.log(passos.next().value);
console.log("A cozinheira foi atender o telefone...");
console.log(passos.next().value);
console.log(passos.next());

$ node pausa.js
Gerador criado. Nada rodou ainda.
  (separando os ingredientes)
1. Misture a farinha e o ovo
A cozinheira foi atender o telefone...
  (lavando a tigela)
2. Leve ao forno
  (desligando o forno)
{ value: undefined, done: true }

Siga a ordem:

  1. receita() criou o gerador, mas o (separando os ingredientes) não apareceu: o corpo ainda não rodou.
  2. O primeiro next() rodou o corpo até o primeiro yield: mostrou (separando…) e entregou o passo 1.
  3. O programa principal fez outra coisa (A cozinheira foi atender o telefone...). O gerador ficou parado esperando.
  4. O segundo next() continuou da linha seguinte ao primeiro yield: (lavando a tigela) e o passo 2.
  5. O terceiro next() rodou o resto ((desligando o forno)), chegou ao fim da função e respondeu done: true.

Isso é algo que nenhuma função comum consegue: parar no meio, devolver o controle, e depois continuar com todas as variáveis do jeito que estavam.

3. Geradores no for … of

Como o objeto gerador é um iterador (e também é iterável), ele funciona direto no for … of, no ... e no Array.from. Lembra do intervalo de 1 a 5 da aula de iteradores, com 15 linhas? Com um gerador:

function* intervalo(de, ate) {
  for (let n = de; n <= ate; n++) {
    yield n;
  }
}

for (const n of intervalo(1, 5)) {
  console.log(n);
}
console.log([...intervalo(10, 13)]);

$ node intervalo.js
1
2
3
4
5
[ 10, 11, 12, 13 ]

O yield pode ficar dentro de laços, ifs, o que for. A cada volta do for interno, o gerador entrega um número e pausa; o for … of de fora pede o próximo; e assim por diante, até o laço interno terminar. Um gerador também pode receber parâmetros, como qualquer função: aqui, de e ate.

Missão: escreva o gerador pares(ate), que entrega os números pares de 2 até ate. Dica: um for que começa em 2 e anda de 2 em 2 (n += 2), com um yield n dentro.

function* pares(ate) {
  // escreva aqui
}

for (const n of pares(10)) {
  console.log(n);
}

function* pares(ate) {
  for (let n = 2; n <= ate; n += 2) {
    yield n;
  }
}

for (const n of pares(10)) {
  console.log(n);
}

4. Sequências infinitas

Como o gerador só calcula o próximo valor quando alguém pede, ele pode representar uma sequência que nunca acaba, sem travar o computador. A máquina de senhas do açougue, agora sem fim de rolo:

function* senhas() {
  let numero = 1;
  while (true) {
    yield `A${String(numero).padStart(3, "0")}`;
    numero++;
  }
}

const maquina = senhas();
console.log(maquina.next().value);
console.log(maquina.next().value);
console.log(maquina.next().value);

console.log(senhas().take(5).toArray());

for (const s of senhas()) {
  if (s === "A004") break;
  console.log(`Chamando ${s}`);
}

$ node senhas.js
A001
A002
A003
[ 'A001', 'A002', 'A003', 'A004', 'A005' ]
Chamando A001
Chamando A002
Chamando A003
while (true)
Um laço sem fim de propósito. Numa função comum, isso travaria o programa. No gerador, o yield pausa a cada volta, então ele só anda quando alguém pede.
String(numero).padStart(3, "0")
Completa o número com zeros à esquerda até ter 3 dígitos: 1 vira "001" (veja Métodos de String).
senhas().take(5).toArray()
Cada senhas() cria uma máquina nova, começando do A001. O take(5) ("pegar 5") é um dos ajudantes de iterador ES2025: pega só os 5 primeiros, e o toArray() junta num array.
if (s === "A004") break
No for … of, o break é a saída. Quando o laço termina com break, o gerador é encerrado, e a máquina para de verdade.
Nunca espalhe um gerador infinito

[...senhas()] ou Array.from(senhas()) tentam pegar todos os valores, e "todos" não termina nunca. O programa fica travado, comendo memória. A Ana testou com um limite de 5 segundos (o comando timeout 5):

$ timeout 5 node infinito.js; echo "código de saída: $?"
código de saída: 124

Nenhuma saída: o timeout teve de matar o programa depois de 5 segundos (o código 124 é o jeito do timeout dizer "eu interrompi"). Com sequências infinitas, use sempre break, take ou chamadas de next() contadas.

5. O gerador como [Symbol.iterator]

O uso mais prático dos geradores é tornar um objeto seu iterável. Basta escrever o método [Symbol.iterator] como gerador, com uma estrela na frente do nome:

const turma = {
  nome: "5º ano B",
  alunos: ["Ana", "Bia", "Caio"],
  *[Symbol.iterator]() {
    for (const aluno of this.alunos) {
      yield aluno;
    }
  },
};
console.log([...turma]);

$ node turma.js
[ 'Ana', 'Bia', 'Caio' ]

O *[Symbol.iterator]() { … } é um método gerador dentro de um objeto (a estrela vem antes do nome). Em classes, é igual: *[Symbol.iterator]() { … } dentro da classe. Ao contrário de devolver o iterador do array (como na missão de Iteradores), aqui você controla o que sai: pode filtrar, transformar, juntar listas.

Entregando outro iterável inteiro: yield*

O yield* (com estrela) entrega, um por um, todos os itens de outro iterável, como se você escrevesse um for … of com yield dentro:

function* tudo() {
  yield "começo";
  yield* ["a", "b"];
  yield* "xy";
  yield "fim";
}
console.log([...tudo()]);

$ node tudo.js
[ 'começo', 'a', 'b', 'x', 'y', 'fim' ]

Por isso o método da turma também poderia ser só *[Symbol.iterator]() { yield* this.alunos; }.

E o return num gerador?

Um return termina o gerador. O valor dele aparece no next() que encerrou, junto com done: true, mas o for … of e o ... ignoram esse valor:

function* curto() {
  yield 1;
  return "acabou";
}
const g = curto();
console.log(g.next());
console.log(g.next());
console.log(g.next());
console.log([...curto()]);

$ node retorno.js
{ value: 1, done: false }
{ value: 'acabou', done: true }
{ value: undefined, done: true }
[ 1 ]

O 'acabou' só aparece para quem chama next() na mão; o array ficou só com o 1. Na prática, use return sem valor (return;) para encerrar um gerador mais cedo, e yield para tudo o que deve sair.

Formas diferentes de fazer a mesma coisa

Para produzir a sequência 1, 2, 3, 4, 5, há pelo menos três caminhos:

// 1. um array pronto: todos os valores existem na memória de uma vez
const lista = [1, 2, 3, 4, 5];

// 2. um iterador escrito na mão (aula Iteradores): next() e { value, done }
// 3. um gerador: os valores são calculados um por vez, quando pedidos
function* umAteCinco() {
  for (let n = 1; n <= 5; n++) yield n;
}
SituaçãoQual usar
Poucos valores, já conhecidosUm array
Uma sequência calculada (intervalo, pares, datas de um mês)Um gerador function*
Uma sequência infinita ou muito grandeUm gerador, com break ou take
Tornar um objeto seu iterável*[Symbol.iterator]() { … } com yield
Controle total do protocolo (raro)Um iterador na mão, com next()
Geradores e o código assíncrono

Antes do async/await existir, geradores eram usados para escrever código que espera (a função pausa no yield e continua quando a resposta chega). Hoje, para isso, use async e await. Existem também os geradores assíncronos (async function*, percorridos com for await … of), usados para ler dados que chegam aos poucos, como um arquivo grande ou uma resposta da internet.

Missão final: só os aprovados

Missão: a professora quer percorrer a turma e ver só quem passou (nota 6 ou mais). Dê à turma um método gerador *[Symbol.iterator]() que percorra this.alunos e entregue (yield) só o nome de quem tem nota >= 6. A saída tem de ser Ana e Caio.

const turma = {
  alunos: [
    { nome: "Ana", nota: 8.5 },
    { nome: "Bia", nota: 5 },
    { nome: "Caio", nota: 7 },
  ],
};

for (const nome of turma) {
  console.log(nome);
}

const turma = {
  alunos: [
    { nome: "Ana", nota: 8.5 },
    { nome: "Bia", nota: 5 },
    { nome: "Caio", nota: 7 },
  ],
  *[Symbol.iterator]() {
    for (const aluno of this.alunos) {
      if (aluno.nota >= 6) {
        yield aluno.nome;
      }
    }
  },
};

for (const nome of turma) {
  console.log(nome);
}

Antes de consertar, a caixa mostra o mesmo TypeError: turma is not iterable da aula Iteradores. Depois, experimente console.log([...turma].length): o número de aprovados, sem precisar de filter.

Resumo

  • Uma função geradora se escreve com estrela, function*, e entrega valores com yield, pausando a cada um.
  • Chamar a função geradora não roda o corpo: devolve um objeto gerador. Cada next() roda até o próximo yield e devolve { value, done }.
  • O objeto gerador é um iterador e um iterável: funciona no for … of, no ... e no Array.from.
  • Geradores podem ser infinitos: pegue só um pedaço com break ou take(n), nunca com [...].
  • *[Symbol.iterator]() { … } torna um objeto seu iterável; yield* entrega todos os itens de outro iterável.
  • O yield só vale dentro da própria function*: nem em arrow functions, nem em callbacks como o do forEach.
