JavaScript Protótipos

Desde as primeiras aulas de arrays você escreve lista.push("café"). Mas, se você olhar o que tem dentro da lista, só encontra os itens: nenhum push. Então de onde ele vem? A resposta é o mecanismo que está por baixo de todos os objetos do JavaScript, inclusive das classes que você aprendeu nas últimas aulas: o protótipo. Entender protótipos não muda o jeito de escrever o dia a dia, mas explica muitas mensagens de erro e muita coisa que parecia mágica.

Você vai aprender
  • O que é o protótipo de um objeto e como o JavaScript procura uma propriedade.
  • A diferença entre propriedade própria e herdada (Object.hasOwn).
  • Como criar um objeto com um protótipo escolhido por você: Object.create.
  • A cadeia de protótipos, que termina em null, e de onde vem o toString.
  • O que uma class faz por baixo dos panos (Produto.prototype).
  • O antigo __proto__ e os erros reais do Node.js.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Você pode rodar cada um no editor do guia.

A ideia: "se não sabe, pergunte para quem te ensinou"

Na padaria do bairro, o aprendiz novo tem um caderninho com o que ele já sabe. Quando alguém pergunta uma coisa que não está no caderno dele ("quanto tempo o pão de queijo fica no forno?"), ele não responde "não sei": vai perguntar para o padeiro que o ensina. Se o padeiro também não souber, ele pergunta para a dona da padaria. Se nem a dona souber, aí sim a resposta é "ninguém aqui sabe".

Todo objeto do JavaScript funciona assim:

  • o objeto tem as suas próprias propriedades (o caderninho do aprendiz);
  • e tem um elo escondido para outro objeto, o seu protótipo (o padeiro);
  • quando você pede uma propriedade que o objeto não tem, o JavaScript vai perguntar ao protótipo, e ao protótipo do protótipo, e assim por diante: é a cadeia de protótipos;
  • se ninguém na cadeia tiver, a resposta é undefined.

Protótipo quer dizer "o primeiro modelo, o molde de onde os outros saem".

1. O mistério do push

const lista = ["pão", "leite"];
lista.push("café");
console.log(lista);
console.log(Object.keys(lista));
console.log(Object.hasOwn(lista, "push"));
console.log(Object.getPrototypeOf(lista) === Array.prototype);
console.log(Object.hasOwn(Array.prototype, "push"));

As propriedades próprias da lista são só as posições dos itens. Nada de push.
Object.hasOwn(lista, "push") → false
Object.hasOwn(obj, "nome") ("tem como próprio") pergunta: esta propriedade está no próprio objeto? Para o push, não está.
Object.getPrototypeOf(lista) === Array.prototype → true
Object.getPrototypeOf(obj) ("pegar o protótipo de") devolve o elo escondido. O protótipo de todo array é um objeto chamado Array.prototype.
Object.hasOwn(Array.prototype, "push") → true
Achamos: o push mora no Array.prototype. Quando você escreve lista.push, o JavaScript não acha na lista, sobe para o protótipo e acha lá.

É por isso que todos os arrays do seu programa têm push, map, filter… sem que cada um carregue uma cópia: existe um Array.prototype, e todos os arrays apontam para ele. Com textos é igual: o toUpperCase mora em String.prototype.

2. Escolhendo o protótipo: Object.create

Você pode criar um objeto e dizer qual vai ser o protótipo dele, com Object.create(protótipo). A Ana faz um objeto "modelo" com o método descrever, e cria o leite a partir dele:

const produtoBase = {
  descrever() {
    return `${this.nome}: R$ ${this.preco.toFixed(2)}`;
  },
};

const leite = Object.create(produtoBase);
leite.nome = "Leite 1 L";
leite.preco = 5.49;

console.log(leite.descrever());
console.log(leite);
console.log(Object.hasOwn(leite, "descrever"));
console.log(Object.getPrototypeOf(leite) === produtoBase);

3. Próprio ganha de herdado; herdado é compartilhado

Duas regras completam o mecanismo:

  1. Se o objeto tem a propriedade, o JavaScript nem olha o protótipo: a própria esconde (faz sombra sobre) a herdada.
  2. Uma propriedade do protótipo é uma só, vista por todos os objetos que apontam para ele. Mudou lá, mudou para todos que não têm a sua própria.
const produtoBase = {
  loja: "Lojinha da Ana",
  descrever() {
    return `${this.nome}: R$ ${this.preco.toFixed(2)}`;
  },
};

const leite = Object.create(produtoBase);
leite.nome = "Leite 1 L";
leite.preco = 5.49;

const caneta = Object.create(produtoBase);
caneta.nome = "Caneta";
caneta.descrever = function () {
  return `${this.nome}: grátis!`;
};

console.log(leite.descrever());
console.log(caneta.descrever());
console.log(leite.loja, "|", caneta.loja);

produtoBase.loja = "Mercadinho da Ana";
console.log(leite.loja, "|", caneta.loja);

leite.loja = "Outra loja";
console.log(leite.loja, "|", caneta.loja, "|", produtoBase.loja);

$ node sombra.js
Leite 1 L: R$ 5.49
Caneta: grátis!
Lojinha da Ana | Lojinha da Ana
Mercadinho da Ana | Mercadinho da Ana
Outra loja | Mercadinho da Ana | Mercadinho da Ana
  • Linha 2: a caneta tem o descrever próprio, e ele ganhou do protótipo. É o mesmo "sobrescrever" da aula Herança.
  • Linha 4: a Ana mudou o loja no protótipo, e os dois objetos passaram a ver o nome novo: nenhum deles tinha uma cópia.
  • Linha 5: leite.loja = "Outra loja" não mudou o protótipo: criou uma propriedade própria no leite, que agora esconde a herdada. A caneta e o protótipo continuam com Mercadinho da Ana. Ler sobe pela cadeia; escrever sempre grava no próprio objeto.

4. O que uma class faz por baixo

As classes das aulas anteriores são, por dentro, exatamente este mecanismo. Os métodos que você escreve numa class vão parar num objeto chamado NomeDaClasse.prototype, e todo objeto criado com new recebe esse objeto como protótipo:

class Produto {
  constructor(nome, preco) {
    this.nome = nome;
    this.preco = preco;
  }

  descrever() {
    return `${this.nome}: R$ ${this.preco.toFixed(2)}`;
  }
}

const arroz = new Produto("Arroz 5 kg", 27.9);
const leite = new Produto("Leite 1 L", 5.49);

console.log(typeof Produto);
console.log(Object.getPrototypeOf(leite) === Produto.prototype);
console.log(Object.hasOwn(leite, "descrever"));
console.log(Object.hasOwn(Produto.prototype, "descrever"));
console.log(leite.descrever === arroz.descrever);
console.log(Object.getOwnPropertyNames(Produto.prototype));

$ node classe.js

true
[ 'constructor', 'descrever' ]
typeof Produto → function
Surpresa: para o JavaScript, uma classe é um tipo especial de função (a que roda no new). Toda função dessas tem uma propriedade prototype.
getPrototypeOf(leite) === Produto.prototype → true
O new Produto(…) criou o leite com o elo apontando para Produto.prototype.
hasOwn(leite, "descrever") → false
O leite não tem o método: ele só tem nome e preco, que o construtor gravou com this.
leite.descrever === arroz.descrever → true
Os dois usam a mesma função, guardada uma vez só no protótipo. Com mil produtos, continua existindo um descrever só.
[ 'constructor', 'descrever' ]
O que mora no Produto.prototype: os métodos da classe e o constructor (que aponta de volta para a própria classe; é daí que vem o leite.constructor.name).
Atenção: Produto.prototype não é o protótipo do Produto

O nome confunde. Produto.prototype é o objeto que vai ser o protótipo dos objetos criados por new Produto. O protótipo do leite é Object.getPrototypeOf(leite), que é igual a Produto.prototype.

5. A cadeia até o fim: Object.prototype e null

Com herança, a cadeia fica mais longa. O extends faz o Perecivel.prototype apontar para o Produto.prototype. E no topo de quase tudo está o Object.prototype, cujo protótipo é null ("nada"): ali a cadeia acaba.

class Produto {
  constructor(nome, preco) {
    this.nome = nome;
    this.preco = preco;
  }
}

class Perecivel extends Produto {
  constructor(nome, preco, validade) {
    super(nome, preco);
    this.validade = validade;
  }
}

const leite = new Perecivel("Leite 1 L", 5.49, "25/10");

let elo = Object.getPrototypeOf(leite);
while (elo !== null) {
  console.log(elo.constructor.name);
  elo = Object.getPrototypeOf(elo);
}
console.log(elo);
console.log(leite.toString());
console.log(Object.hasOwn(Object.prototype, "toString"));

$ node cadeia.js
Perecivel
Produto
Object
null
[object Object]
true

O while (aula while) andou elo por elo: Perecivel.prototype → Produto.prototype → Object.prototype → null. Em forma de desenho:

leite { nome, preco, validade }
  └─► Perecivel.prototype { constructor }
        └─► Produto.prototype { constructor }
              └─► Object.prototype { toString, hasOwnProperty, … }
                    └─► null

Ninguém escreveu um toString no Produto, mas leite.toString() funcionou e devolveu [object Object]: ele mora no Object.prototype, o "dono da padaria" de quase todos os objetos. É por isso que um texto com ${objeto} às vezes sai como [object Object].

6. Mexendo no protótipo depois

Como o protótipo é um objeto comum, dá para acrescentar um método nele depois que os objetos já existem, e todos passam a ter:

class Produto {
  constructor(nome, preco) {
    this.nome = nome;
    this.preco = preco;
  }
}

const leite = new Produto("Leite 1 L", 5.49);

Produto.prototype.comDesconto = function (porcento) {
  return this.preco * (1 - porcento / 100);
};

console.log(leite.comDesconto(10).toFixed(2));

$ node acrescentar.js
4.94

O leite foi criado antes do método existir, e mesmo assim o tem: o JavaScript procura no protótipo na hora da chamada, não na hora do new. Era assim que se escreviam os métodos antes das classes (veja o jeito antigo na aula de herança).

Não mexa nos protótipos prontos do JavaScript

Daria para fazer Array.prototype.ultimo = function () { … } e todos os arrays ganhariam um ultimo(). Não faça: se uma versão futura do JavaScript criar um método com o mesmo nome, o seu passa por cima e o comportamento muda; e as bibliotecas que você usar podem se confundir. Isso já aconteceu na história do JavaScript (alguns métodos de array tiveram de ganhar nomes estranhos porque o nome óbvio já estava "ocupado" por bibliotecas antigas). Para o último item, use lista.at(-1); para métodos seus, use classes ou funções.

Formas diferentes de fazer a mesma coisa

Há várias formas de ler o protótipo e de criar objetos com protótipo. Algumas são antigas e só aparecem em código velho:

console.log(leite.__proto__ === Object.prototype);
console.log(Object.getPrototypeOf(leite) === Object.prototype);
const semNada = Object.create(null);
console.log(semNada.toString);
console.log(Object.getPrototypeOf(semNada));

  • obj.__proto__ (com dois sublinhados de cada lado) é o jeito antigo de chegar ao protótipo. Ainda funciona no Node e nos navegadores, mas é considerado ultrapassado: prefira Object.getPrototypeOf.

Resumo

  • Todo objeto tem um elo escondido para outro objeto, o seu protótipo. Ao ler uma propriedade que o objeto não tem, o JavaScript procura no protótipo, e no protótipo dele, até chegar a null: é a cadeia de protótipos.
  • Os métodos dos arrays moram em Array.prototype; os das suas classes, em SuaClasse.prototype. Cada método existe uma vez só, compartilhado por todos os objetos.
  • Object.getPrototypeOf(obj) mostra o protótipo; Object.create(base) cria um objeto com o protótipo que você quiser; Object.hasOwn(obj, "x") diz se a propriedade é própria.
  • Propriedade própria esconde a herdada. Ler sobe pela cadeia; escrever grava sempre no próprio objeto.
  • class e extends são um jeito mais limpo de montar essa cadeia. No topo de quase tudo está o Object.prototype, de onde vem o toString.
  • Não acrescente métodos aos protótipos prontos (Array.prototype, String.prototype), e prefira getPrototypeOf ao antigo __proto__.
