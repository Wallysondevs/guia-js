JavaScript localStorage

Tudo o que o seu JavaScript faz numa página some quando ela é recarregada: o item que você acrescentou na lista, o placar, o nome que a pessoa digitou. Recarregou, voltou tudo ao começo. Para a página lembrar de coisas de uma visita para a outra, o navegador oferece uma gaveta: o localStorage ("armazenamento local"). É ele que faz o site lembrar que você prefere o tema escuro, ou manter a lista de tarefas depois que você fecha a aba.

Você vai aprender
  • Como guardar, ler e apagar um dado: setItem, getItem, removeItem e clear.
  • Um contador de visitas que sobrevive ao F5.
  • Por que o localStorage só guarda texto, e o que acontece com números, arrays e objetos.
  • Como guardar arrays e objetos com JSON.stringify e recuperá-los com JSON.parse.
  • Onde ver a gaveta pelo F12, o que é o sessionStorage e o que não guardar ali.
  • Os erros reais: o null da chave que não existe, o texto que não é JSON, a gaveta cheia e o localStorage no Node.js.

O localStorage é do navegador. As respostas do Console foram colhidas no Chromium da máquina da Ana, com a página aberta como arquivo (file:///home/ana/…), do jeito que ela abre com dois cliques. Antes desta aula, ajuda ter visto JSON e Formulários.

A ideia: a gaveta com etiquetas

Pense numa gaveta da cozinha da Ana onde cada coisa fica num potinho com uma etiqueta: "açúcar", "café", "chave do portão". Para guardar, ela escreve a etiqueta e põe o conteúdo. Para pegar, procura pela etiqueta. Se procurar uma etiqueta que não existe, a mão volta vazia. E a gaveta continua lá no dia seguinte.

  • Cada site tem a sua gaveta. O site da padaria não abre a gaveta do site do banco.
  • A etiqueta se chama chave (key); o conteúdo, valor (value).
  • Os potinhos só aceitam papel escrito: tudo o que entra vira texto. (É a pegadinha da seção 3.)
  • A gaveta fica neste navegador, neste computador. No celular da Ana, o mesmo site tem outra gaveta, vazia.

1. Guardar, ler e apagar

Quatro métodos fazem quase tudo. A Ana testou no Console:

> localStorage.setItem("nome", "Ana")
undefined
> localStorage.getItem("nome")
'Ana'
> localStorage.getItem("idade")
null
> localStorage.removeItem("nome")
undefined
> localStorage.getItem("nome")
null
localStorage.setItem("nome", "Ana")
"Definir item": guarda o valor "Ana" com a etiqueta "nome". Se a etiqueta já existia, o valor antigo é trocado. Não devolve nada (o undefined).
localStorage.getItem("nome")
"Pegar item": devolve o valor guardado com essa etiqueta: 'Ana'.
getItem("idade") → null
Etiqueta que não existe devolve null ("nada"; veja null e undefined). Não é erro: é a mão voltando vazia.
localStorage.removeItem("nome")
"Remover item": tira o potinho da gaveta. Depois disso, o getItem devolve null.

E mais três para conhecer: localStorage.clear() esvazia a gaveta inteira (deste site); localStorage.length diz quantos itens há; localStorage.key(0) devolve a etiqueta do item número 0 (a ordem não é garantida, então use só para percorrer tudo). Digitando só localStorage no Console, aparece a gaveta inteira. Aqui a Ana estava na página do contador de visitas da seção 2 (por isso o visitas) e tinha guardado de novo o nome e a idade:

> localStorage
Storage {nome: 'Ana', visitas: '1', idade: '30', length: 3}
> localStorage.clear()
undefined
> localStorage.length
0

2. O dado que sobrevive ao F5

O exemplo clássico: um contador de visitas. Cada vez que a página abre, ele lê o número guardado, soma 1 e guarda de novo.

<p id="saida"></p>
<script src="script.js"></script>

const visitas = Number(localStorage.getItem("visitas")) + 1;
localStorage.setItem("visitas", visitas);
document.querySelector("#saida").textContent = `Esta é a sua visita número ${visitas}.`;
localStorage.getItem("visitas")
Na primeira visita, a etiqueta não existe: vem null. Nas próximas, vem o número guardado, como texto ("1", "2"…).
Number(…) + 1
Converte para número antes de somar (veja Conversão). O Number(null) dá 0, então a primeira visita vira 0 + 1 = 1 sem precisar de if. Sem o Number, "1" + 1 daria "11".
localStorage.setItem("visitas", visitas)
Guarda o número novo para a próxima vez.

A Ana abriu a página e recarregou duas vezes (F5). O parágrafo mostrou Esta é a sua visita número 1., depois Esta é a sua visita número 2. e depois Esta é a sua visita número 3.

Uma variável comum (let visitas = 0) voltaria a 0 a cada recarga, porque o script inteiro roda de novo do zero. O localStorage não: a gaveta fica guardada no navegador, até alguém apagar. Ela sobrevive a fechar a aba, fechar o navegador e desligar o computador.

Salve os dois arquivos numa pasta, abra o index.html no navegador e aperte F5 algumas vezes. Depois feche o navegador, abra de novo, e veja o número continuar de onde parou.

3. A pegadinha: tudo vira texto

O localStorage só guarda strings. Se você entregar outra coisa, ela é convertida em texto antes de entrar, do jeito que o JavaScript converte (o mesmo do String(valor)). Para números e booleanos, o estrago é pequeno:

> localStorage.setItem("idade", 30)
undefined
> localStorage.getItem("idade")
'30'
> typeof localStorage.getItem("idade")
'string'
> localStorage.setItem("tema", true)
undefined
> localStorage.getItem("tema") === true
false
> localStorage.getItem("tema") === "true"
true

O 30 voltou como '30' (com aspas: texto), e o true voltou como "true". Por isso o Number(…) no contador de visitas, e por isso o === true deu false. Para arrays e objetos, o estrago é grande:

> const compras = ["Pão", "Leite", "Café"]
undefined
> localStorage.setItem("compras", compras)
undefined
> localStorage.getItem("compras")
'Pão,Leite,Café'
> const ana = { nome: "Ana", idade: 30 }
undefined
> localStorage.setItem("perfil", ana)
undefined
> localStorage.getItem("perfil")
'[object Object]'

O array virou um texto com vírgulas (já não é uma lista: é uma frase). E o objeto virou '[object Object]', que é o jeito do JavaScript dizer "um objeto" quando o transforma em texto. O nome e a idade da Ana se perderam, sem nenhum aviso.

4. Guardando arrays e objetos: JSON

A solução é transformar o array ou o objeto num texto que dê para desfazer: o JSON (veja JSON). Na ida, JSON.stringify ("transformar em string"); na volta, JSON.parse ("analisar", ler o texto e montar o valor de novo):

> localStorage.setItem("compras", JSON.stringify(compras))
undefined
> localStorage.getItem("compras")
'["Pão","Leite","Café"]'
> JSON.parse(localStorage.getItem("compras"))
(3) ['Pão', 'Leite', 'Café']
> localStorage.setItem("perfil", JSON.stringify(ana))
undefined
> JSON.parse(localStorage.getItem("perfil")).nome
'Ana'

Guardado como JSON, o texto tem colchetes e aspas: ele "lembra" que era um array. O JSON.parse monta o array de volta, com 3 itens, e o objeto de volta, com o .nome funcionando.

O padrão "carregar, mudar, salvar"

Quase todo programa com localStorage tem duas funções pequenas, uma para ler e outra para gravar, e usa as duas assim:

function carregar() {
  return JSON.parse(localStorage.getItem("compras")) ?? [];
}

function salvar(lista) {
  localStorage.setItem("compras", JSON.stringify(lista));
}

const compras = carregar();   // 1. carregar
compras.push("Manteiga");     // 2. mudar
salvar(compras);              // 3. salvar
console.log(compras);
JSON.parse(localStorage.getItem("compras"))
Lê o texto da gaveta e monta o array.
?? []
Na primeira vez, a etiqueta não existe: o getItem dá null, e JSON.parse(null) também dá null. O ?? ("se for nulo, use isto"; veja ?. e ??) troca esse null por um array vazio, para o push funcionar.
salvar(compras)
Mudar o array na memória não muda a gaveta. É preciso gravar de novo depois de cada mudança.

A Ana abriu a página com a gaveta vazia e recarregou duas vezes. O Console mostrou:

(1) ['Manteiga']
(2) ['Manteiga', 'Manteiga']
(3) ['Manteiga', 'Manteiga', 'Manteiga']

A cada recarga o script roda de novo, carrega o que estava guardado, acrescenta mais uma Manteiga e grava. (Numa lista de verdade, o push fica dentro de um ouvinte de clique, como na missão final.) E o ?? [] conferido no Console, com a etiqueta "tarefas", que não existe:

> JSON.parse(localStorage.getItem("tarefas"))
null
> JSON.parse(localStorage.getItem("tarefas")) ?? []
(0) []

5. sessionStorage: a gaveta que some com a aba

Existe uma irmã, o sessionStorage ("armazenamento da sessão"), com os mesmos métodos: setItem, getItem, removeItem, clear. A diferença é quanto tempo dura:

localStoragesessionStorage
Sobrevive ao F5SimSim
Sobrevive a fechar a abaSimNão: some junto com a aba
Outra aba do mesmo site enxergaSimNão: cada aba tem a sua
Bom paraPreferências, listas, rascunhos que devem ficarUm passo a passo em andamento, dados de uma visita só
O que não guardar no localStorage
  • Senhas, números de cartão, documentos. Qualquer código que rodar na página (até o de um anúncio, ou um ataque como o XSS de Criando Elementos) consegue ler a gaveta inteira, e qualquer pessoa com o computador nas mãos também, pelo F12.
  • Coisas que não podem se perder. A pessoa pode limpar os dados do navegador a qualquer momento, e a navegação anônima apaga tudo ao fechar. Para dados importantes, o lugar é um servidor.
  • Muita coisa. Cada site tem só alguns megabytes (em geral, cerca de 5 MB). Veja o erro de gaveta cheia abaixo.

Formas diferentes de fazer a mesma coisa

Além dos métodos, dá para usar a gaveta como um objeto comum, com ponto:

> localStorage.nome = "Bia"
'Bia'
> localStorage.getItem("nome")
'Bia'

Funciona, mas evite: uma etiqueta com o nome de um método (como "length", "key" ou "clear") não dá para ler assim, e quem lê o código não percebe que aquilo é a gaveta do navegador. Os métodos setItem/getItem deixam isso claro.

SituaçãoQual usar
Um texto simples (nome, tema)setItem("tema", "escuro") / getItem("tema")
Um númerosetItem("visitas", n) / Number(getItem("visitas"))
Um array ou objetosetItem("x", JSON.stringify(valor)) / JSON.parse(getItem("x")) ?? padrão
Deve sumir quando a aba fecharsessionStorage
Senha, dado sensível, dado importanteNenhum dos dois: um servidor

Quando dá errado

Usou o valor de uma etiqueta que não existe 
> localStorage.getItem("nada").length
Uncaught TypeError: Cannot read properties of null (reading 'length')
    at <anonymous>:1:29

"Não dá para ler propriedades de null (lendo length)". O getItem("nada") devolveu null, e o null não tem length. É o que acontece na primeira visita de qualquer pessoa, quando a gaveta ainda está vazia: o programa funciona no seu computador (onde você já tinha salvo algo) e quebra no de quem abre pela primeira vez. (O <anonymous>:1:29 quer dizer: código digitado no Console, linha 1, coluna 29.) Como consertar: dê um valor padrão: localStorage.getItem("nome") ?? "", ou JSON.parse(…) ?? []. Para testar a primeira visita, apague a gaveta pelo F12 (aba Application) ou com localStorage.clear().

Tentou JSON.parse num texto que não é JSON 
> localStorage.setItem("lista", "Pão, Leite")
undefined
> JSON.parse(localStorage.getItem("lista"))
Uncaught SyntaxError: Unexpected token 'P', "Pão, Leite" is not valid JSON
    at JSON.parse (<anonymous>)
    at <anonymous>:1:6

"Símbolo inesperado 'P': "Pão, Leite" não é um JSON válido". Alguém (uma versão antiga do seu código, ou você mesmo pelo F12) guardou um texto comum nessa etiqueta, e o JSON.parse não sabe ler. É o caso também de quem guardou o array sem JSON.stringify (seção 3). Como consertar: guarde sempre com JSON.stringify; para se proteger de um valor estragado, use try … catch em volta do JSON.parse e, no catch, comece com o valor padrão.

O objeto voltou como [object Object]

Sem erro nenhum, o getItem devolveu '[object Object]', e o .nome dele dá undefined. O objeto foi guardado direto, sem JSON.stringify, e virou esse texto (seção 3). O dado original se perdeu. Como consertar: setItem("perfil", JSON.stringify(ana)), e na volta JSON.parse.

A gaveta encheu 
> localStorage.setItem("enorme", "x".repeat(6 * 1024 * 1024))
Uncaught QuotaExceededError: Failed to execute 'setItem' on 'Storage': Setting the value of 'enorme' exceeded the quota.
    at <anonymous>:1:14

"Cota excedida: guardar o valor de 'enorme' passou do limite". A Ana tentou guardar um texto de 6 milhões de letras (o repeat repete o "x"), e o Chromium recusou: o limite de cada site é de alguns megabytes. Na prática, isso acontece com quem tenta guardar fotos ou listas gigantes. Como consertar: guarde só o necessário; fotos e arquivos grandes vão para um servidor.

Resumo

  • O localStorage é uma gaveta do navegador, uma por site, que guarda dados entre visitas: sobrevive ao F5 e a fechar o navegador.
  • setItem(chave, valor) guarda, getItem(chave) lê (ou null), removeItem apaga um, clear apaga todos.
  • Tudo vira texto: números voltam como "30" (use Number), arrays como "Pão,Leite", objetos como "[object Object]".
  • Arrays e objetos: JSON.stringify na ida, JSON.parse na volta, com ?? [] para a primeira visita.
  • Mudou o dado? Grave de novo. A gaveta não acompanha a variável sozinha.
  • sessionStorage tem os mesmos métodos e some com a aba. Nenhum dos dois serve para senhas ou dados importantes.
