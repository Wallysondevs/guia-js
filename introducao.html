JavaScript Introdução

Bem-vindo ao Guia JavaScript! O JavaScript é a linguagem de programação que faz as páginas da internet se mexerem: o botão que curte uma foto, o carrinho de compras que soma sozinho, o mapa que você arrasta com o dedo. E, com o Node.js, ele também roda fora do navegador, no terminal do seu computador. Esta aula conta o que é programar, o que o JavaScript tem de especial e de onde ele veio. Você não precisa saber nada antes: começamos do zero.

  • O que é o JavaScript e os dois lugares onde ele roda: o navegador e o Node.js.
  • O que quer dizer "linguagem interpretada" e o que o motor (V8) faz com o seu código.
  • Um pouco de história: de 1995 até o ECMAScript 2025, a versão que este guia ensina.
  • Por que JavaScript não é Java, apesar do nome.

Todos os programas desta aula foram rodados com o Node.js 24 LTS na máquina fictícia da Ana (usuária ana, computador notebook), na pasta pessoal dela, com o comando node arquivo.js. Cada caixa "Experimente" roda o JavaScript de verdade do seu navegador (aula O Editor do Guia).

Primeiro: o que é programar?

Pense numa receita de bolo. Ela é uma lista de passos, na ordem certa, escrita de um jeito que qualquer pessoa consegue seguir: "ligue o forno", "misture os ingredientes", "asse por 40 minutos". Quem segue a receita não precisa inventar nada: só faz o que está escrito, um passo depois do outro.

Programar é escrever uma receita para o computador. A diferença é que o computador é um cozinheiro muito obediente e muito literal: ele faz exatamente o que está escrito, nem mais, nem menos. Se você esquecer um passo, ele não completa sozinho; se escrever uma palavra errada, ele para e reclama.

E como o computador não entende português, a receita precisa ser escrita numa língua que ele entenda: uma linguagem de programação. O JavaScript é uma delas. Veja uma receita de verdade, em JavaScript:

console.log("1. Ligue o forno");
console.log("2. Misture os ingredientes");
console.log("3. Asse por 40 minutos");

Cada linha é um passo. O console.log (em inglês, "registrar no console") é o jeito de o programa mostrar alguma coisa na tela; ele tem uma aula inteira só para ele: console.log(). Na máquina da Ana, o programa rodou assim:

$ node receita.js
1. Ligue o forno
2. Misture os ingredientes
3. Asse por 40 minutos
$ node receita.js
O comando que a Ana digitou no terminal: "Node.js, rode o arquivo receita.js". O $ não se digita: é o terminal avisando que está pronto. A aula Rodando um Programa mostra isso passo a passo.
As três linhas de baixo
A saída do programa: o que ele mostrou. Uma linha para cada console.log, na ordem em que estão no arquivo, de cima para baixo, como uma receita.

Missão: a receita esqueceu um passo. Acrescente uma quarta linha, igual às outras, que mostre 4. Espere esfriar. Depois clique em Rodar.

A linguagem da Web

Toda página da internet é feita de três camadas, cada uma com a sua linguagem. Pense numa casa:

LinguagemNa casaNa página
HTMLAs paredes e os cômodosO conteúdo: títulos, textos, imagens, botões
CSSA pintura e a decoraçãoA aparência: cores, tamanhos, posições
JavaScriptA parte elétrica: o interruptor que acende a luz, a campainha que tocaO comportamento: o que acontece quando você clica, digita, rola a página

HTML e CSS descrevem a página; o JavaScript a faz agir. Ele é a única linguagem de programação que todos os navegadores (Chrome, Edge, Firefox, Safari) entendem sozinhos, sem instalar nada. Por isso, quem quer trabalhar com sites acaba aprendendo JavaScript.

No grupo "A Página Web" deste guia você vai escrever JavaScript dentro de páginas, com botões e caixas de texto de verdade. Antes disso, nos níveis 1 e 2, você aprende a linguagem em si, do jeito mais simples: no terminal, com o Node.js.

Fora do navegador: o Node.js

Durante muitos anos, JavaScript só rodava dentro do navegador. Em 2009, o programador Ryan Dahl pegou o "motor" de JavaScript do Google Chrome e o colocou num programa que roda direto no computador, sem navegador: o Node.js. Com ele, JavaScript passou a servir também para programas de terminal, servidores de sites, ferramentas e automações.

É com o Node.js que você vai rodar os programas deste guia: você escreve um arquivo .js, digita node arquivo.js e vê a saída no terminal. A comparação completa entre os dois lugares está na próxima aula, Onde o JavaScript Roda, e a instalação, em Instalar o Node.js.

Uma linguagem, vários "donos da casa"

A linguagem é a mesma nos dois lugares: console.log, as contas, os textos, as decisões, as repetições. O que muda são os "extras" que cada lugar oferece. O navegador tem a página (document) e as janelinhas (alert); o Node.js tem os arquivos do computador (fs) e o terminal (process). O guia sempre avisa quando algo é só do Node ou só do navegador.

O JavaScript é uma linguagem interpretada

O computador, lá no fundo, só entende números: instruções de máquina, zeros e uns. Ninguém escreve programas assim. Você escreve em JavaScript, que é quase inglês (console.log, if, for), e alguém precisa traduzir.

Em algumas linguagens (como C), você traduz o programa inteiro antes, com um compilador, e ganha um arquivo executável. No JavaScript não tem esse passo: você entrega o arquivo .js do jeito que escreveu e o motor de JavaScript lê, traduz e executa na hora. Por isso se diz que o JavaScript é uma linguagem interpretada.

MotorOnde está
V8Google Chrome, Microsoft Edge, Opera… e o Node.js
SpiderMonkeyMozilla Firefox
JavaScriptCoreSafari (Apple)

Por dentro: a tradução esperta (JIT)

Os motores modernos são mais espertos que um simples "lê uma linha, faz uma linha". O V8 primeiro confere se o arquivo inteiro está escrito corretamente; depois começa a executar; e, quando percebe que um trecho roda muitas vezes (uma conta repetida mil vezes, por exemplo), ele compila esse trecho para instruções de máquina, enquanto o programa roda. Isso se chama compilação JIT (do inglês just in time, "bem na hora") e é o motivo de o JavaScript de hoje ser rápido. Para você, nada muda: escreve o .js e roda.

Uma consequência que você vai sentir já nas primeiras aulas: como o motor confere a escrita do arquivo inteiro antes de rodar, um erro de escrita numa linha impede o programa todo de começar, até as linhas certas. Você vai ver isso acontecer em Quando dá errado.

O lado bom e o lado ruim

  • Bom: escreveu, rodou. Não há passo de compilação para lembrar, e o mesmo arquivo roda em qualquer computador que tenha Node.js, e em qualquer navegador.
  • Bom: o JavaScript é dinâmico: uma variável pode guardar um número agora e um texto depois, sem você declarar o tipo. É menos coisa para escrever no começo.
  • Ruim: muitos erros só aparecem quando a linha com problema é executada. Um nome escrito errado numa parte do programa que raramente roda pode ficar escondido por meses.
  • Ruim: o lado dinâmico tem pegadinhas: "2" + 2 dá "22", e não 4. O guia mostra todas, com calma, em Conversão Automática.

Um pouco de história

Em 1995, a empresa Netscape fazia o navegador mais usado do mundo, o Netscape Navigator, e queria uma linguagem simples para deixar as páginas menos paradas. O programador Brendan Eich criou o primeiro protótipo em poucos dias. A linguagem se chamou primeiro Mocha, depois LiveScript e, por fim, JavaScript, e apareceu pela primeira vez no Navigator 2.0.

O nome "JavaScript" foi uma jogada de marketing: a linguagem Java, de outra empresa, estava na moda, e a Netscape aproveitou a fama. As duas linguagens não têm parentesco (veja a seção seguinte).

A Microsoft fez a sua própria versão para o Internet Explorer 3.0, chamada JScript. Para que o mesmo código funcionasse em todos os navegadores, a linguagem foi entregue a uma organização de padrões, a Ecma International, que escreveu a "lei" oficial da linguagem: a especificação ECMA-262, cuja linguagem se chama ECMAScript. A primeira edição saiu em junho de 1997.

AnoO que aconteceu
1995Brendan Eich cria o JavaScript na Netscape; ele aparece no Navigator 2.0
1997Sai a 1ª edição do padrão ECMAScript (ECMA-262)
2009ECMAScript 5 (5ª edição) e o nascimento do Node.js
2015ECMAScript 2015 (a 6ª edição, também chamada ES6): a grande reforma, com let, const, arrow functions, classes, módulos, promises
2016 em dianteUma edição nova por ano, sempre em junho, com o ano no nome: ES2016, ES2017…
2025ECMAScript 2025 (16ª edição): a versão que este guia ensina
2026ECMAScript 2026 (17ª edição, junho de 2026)

Por isso você vai ouvir dois nomes: ECMAScript é o nome do padrão, a "lei"; JavaScript é o nome que todo mundo usa no dia a dia. Quando alguém fala "ES6" ou "ES2025", está falando de uma edição do padrão. As datas desta tabela estão na própria especificação e na página da ECMA-262 no site da Ecma International.

Um JavaScript "antigo" e um "moderno"

Como a linguagem mudou muito em 2015, você vai encontrar na internet dois estilos: o antigo, com var e function para tudo, e o moderno, com let, const e =>. Este guia ensina o moderno, e mostra o antigo só para você reconhecê-lo em código dos outros (por exemplo, em var: o Jeito Antigo). Recursos novos aparecem marcados assim: ES2025.

JavaScript não é Java

É a confusão mais comum de quem está começando. Os nomes são parecidos e a escrita lembra um pouco (as chaves { }, o ponto e vírgula), mas são linguagens diferentes, de empresas diferentes, com usos diferentes. Como diz a piada, "Java está para JavaScript assim como carro está para carpete".

JavaScriptJava
Como rodaO motor lê o .js e executa (com JIT)Compila o .java para bytecode e roda numa máquina virtual (JVM)
TiposDinâmicos: não se declara o tipo da variávelEstáticos: cada variável tem um tipo declarado (int, String…)
Onde rodaEm todo navegador, e no computador com o Node.jsNo computador e em servidores; nos navegadores, não
Mostrar "Olá"console.log("Olá");System.out.println("Olá");

Um código de Java não funciona no Node.js. Você vai ver a mensagem real em Quando dá errado.

Onde o JavaScript está hoje

  • Em praticamente todo site: menus, formulários, carrinhos de compras, mapas, jogos no navegador.
  • Em servidores, com o Node.js: o programa que recebe o seu pedido quando você abre um site pode ser JavaScript.
  • Em programas de computador: vários aplicativos de desktop são feitos com tecnologias da web (HTML, CSS e JavaScript) por baixo; o editor de código VS Code é um exemplo.
  • Em aplicativos de celular, com ferramentas que transformam código JavaScript em apps.
  • Em ferramentas: o próprio Node.js vem com o npm, a maior coleção de bibliotecas prontas do mundo (aula npm).

Para mostrar onde você vai chegar, este é um programa que a Ana vai saber escrever (e entender linha por linha) depois de algumas aulas. Ele soma a lista de compras:

const itens = ["pão", "leite", "café"];
const precos = [7.5, 5.2, 18.9];
let total = 0;

for (let i = 0; i < itens.length; i++) {
  console.log(`${itens[i]}: R$ ${precos[i]}`);
  total = total + precos[i];
}

console.log(`Total: R$ ${total.toFixed(2)}`);

$ node compras.js
pão: R$ 7.5
leite: R$ 5.2
café: R$ 18.9
Total: R$ 31.60

Não se preocupe em entender agora. Os colchetes [ ] são arrays (listas), o for é uma repetição, o texto com crase e ${ } é uma template string, e o toFixed(2) mostra duas casas decimais. Cada coisa tem a sua aula.

Experimente: rode o programa da lista de compras. Depois troque um preço (por exemplo, o do café) e rode de novo para ver o total mudar. Não há missão: mexa à vontade.

O LTS (do inglês Long Term Support, "suporte de longo prazo") é a versão do Node.js recomendada para o dia a dia: recebe correções por anos. Na máquina da Ana, o Node.js se apresenta assim:

console.log("Node.js", process.version);

$ node versao.js

O process.version é só do Node (no navegador não existe process). O número do meio e o do fim mudam a cada atualização (24.22.0, 24.23.0…); o que importa é o 24 do começo. A aula Instalar o Node.js mostra como ter o seu.

Quando dá errado

O computador é literal: qualquer letra fora do lugar e ele para. As mensagens de erro do Node.js saem em inglês; aqui elas aparecem como saíram na máquina da Ana e explicadas em português. A aula Lendo uma Mensagem de Erro aprofunda o assunto.

Console com C maiúsculo 
Console.log("Olá, mundo!");

$ node maiuscula.js
/home/ana/maiuscula.js:1
Console.log("Olá, mundo!");
^

ReferenceError: Console is not defined
    at Object.<anonymous> (/home/ana/maiuscula.js:1:1)
    at Module._compile (node:internal/modules/cjs/loader:1929:14)
    «  mais 6 linhas "at … (node:internal/…)" cortadas: são do próprio Node

Node.js v24.22.0
$ echo $?
1

É a primeira mensagem de erro do guia, então vamos ler parte por parte:

/home/ana/maiuscula.js:1
O arquivo (com a pasta inteira) e a linha do problema: linha 1. É a informação mais útil da mensagem: abra o arquivo e vá direto nessa linha.
Console.log("Olá, mundo!");
A própria linha com problema, copiada do seu arquivo.
^
O "chapeuzinho" aponta a coluna onde o problema começa: bem embaixo do C de Console.
ReferenceError: Console is not defined
O tipo do erro e a mensagem. ReferenceError é "erro de referência": você citou um nome que não existe. "Console is not defined" quer dizer "Console não está definido". O nome certo é console, tudo minúsculo.
at Object.<anonymous> (/home/ana/maiuscula.js:1:1)
O caminho que o programa fez até o erro, começando pelo seu arquivo: linha 1, coluna 1. As linhas at … (node:internal/…) que vêm depois são do próprio Node.js; pode ignorar.
Node.js v24.22.0
A versão do Node.js que rodou o programa. Ela aparece no fim de todo erro que derruba o programa.
echo $? → 1
O código de saída (o $? do terminal guarda o do último comando): 1 quer dizer "terminou com erro"; um programa que deu certo termina com 0.

O JavaScript diferencia maiúsculas de minúsculas: console, Console e CONSOLE são três nomes diferentes, e só o primeiro existe. Como consertar: escreva console.log, tudo minúsculo.

Texto sem aspas 
console.log(Olá, mundo!);

$ node aspas.js
/home/ana/aspas.js:1
console.log(Olá, mundo!);
                 ^^^^^

SyntaxError: missing ) after argument list
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)
    «  mais 7 linhas "at … (node:internal/…)" cortadas

Node.js v24.22.0

SyntaxError é um erro de sintaxe: o código não está escrito do jeito que o JavaScript entende. "missing ) after argument list" quer dizer "faltou um ) depois da lista de argumentos". Sem aspas, Olá não é um texto, é um nome; o JavaScript leu Olá, mundo como dois nomes separados por vírgula e, quando chegou no !, esperava o parêntese fechar ali. Os ^^^^^ marcam onde ele se perdeu. Repare que desta vez não há at Object.<anonymous> com o seu arquivo: o erro de sintaxe é achado antes de o programa começar a rodar. Como consertar: todo texto vai entre aspas: console.log("Olá, mundo!");.

Escrevendo Java em vez de JavaScript 
System.out.println("Olá, mundo!");

$ node java.js
/home/ana/java.js:1
System.out.println("Olá, mundo!");
^

ReferenceError: System is not defined
    at Object.<anonymous> (/home/ana/java.js:1:1)
    «  mais 7 linhas "at … (node:internal/…)" cortadas

Node.js v24.22.0

A Ana copiou um "Olá, mundo" de um site de Java. Para o JavaScript, System é um nome desconhecido: o mesmo ReferenceError do primeiro cenário. Isso acontece muito ao procurar exemplos na internet: confira se a página é de JavaScript. Como consertar: console.log("Olá, mundo!");.

Resumo

  • Programar é escrever uma receita de passos para o computador, numa linguagem de programação. O computador faz exatamente o que está escrito.
  • O JavaScript é a linguagem que dá comportamento às páginas da Web (junto com o HTML e o CSS) e, com o Node.js, roda também no terminal.
  • Ele é interpretado: o motor (V8 no Chrome e no Node.js) lê o .js e executa, compilando na hora (JIT) os trechos que rodam muito.
  • Nasceu em 1995, na Netscape, criado por Brendan Eich. O padrão oficial se chama ECMAScript; desde 2015 sai uma edição por ano. Este guia ensina o ECMAScript 2025 com o Node.js 24 LTS.
  • JavaScript não é Java: são linguagens diferentes.
  • Os primeiros erros: um nome que não existe dá ReferenceError: … is not defined; um erro de escrita dá SyntaxError e impede o programa inteiro de rodar. A mensagem sempre diz o arquivo e a linha.
