Uma Olhada no TypeScript

Em vagas de emprego e em projetos grandes, você vai esbarrar num nome parecido: TypeScript. Não é outra linguagem do zero: é o JavaScript com tipos. Você escreve o mesmo JavaScript que aprendeu neste guia e acrescenta, aqui e ali, etiquetas dizendo "isto aqui é um número", "isto é um texto". Um programa chamado tsc lê essas etiquetas e avisa, antes de você rodar, quando algo não combina. Esta aula é só uma olhada: o suficiente para você reconhecer TypeScript quando vir e saber por onde começar.

Você vai aprender
  • Que problema o TypeScript resolve, com um defeito real do JavaScript.
  • Como se lê uma anotação de tipo (preco: number) e uma interface.
  • Que o Node.js 24 roda arquivos .ts direto, apagando os tipos, mas sem conferi-los.
  • Como conferir os tipos de verdade com o tsc (npx tsc --noEmit) e ler o erro dele.
  • O que o Node não aceita (enum) e o que acontece com tipos num arquivo .js.

Os comandos desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), numa pasta ts, com o TypeScript instalado pelo npm. O editor do guia roda JavaScript, e não TypeScript: as caixas "Experimente" desta aula são em JavaScript.

A ideia: a etiqueta na tomada

Na casa da Ana, algumas tomadas têm uma etiqueta "220 V". Ninguém precisa colar essa etiqueta; a tomada funciona sem ela. Mas, com a etiqueta, você percebe antes de ligar a cafeteira de 110 V que ela vai queimar. Os tipos do TypeScript são essas etiquetas: o programa roda sem elas, mas com elas um "fiscal" (o tsc) pega a combinação errada antes de ela virar defeito.

1. O problema: o JavaScript aceita tudo

Esta função deveria somar dois números. Mas o JavaScript não reclama se alguém passar um texto:

function somar(a, b) {
  return a + b;
}

console.log(somar(2, 3));
console.log(somar("2", 3));

Com 2, sai 5. Com "2" (um texto, que veio de um formulário ou do teclado), o + junta em vez de somar, e sai 23 (veja Conversão Automática). Nenhum erro, nenhum aviso: o defeito só aparece quando alguém percebe o 23 na tela. Num programa de 50 mil linhas, isso pode levar meses.

Missão: a entrada veio do teclado, como texto, e a soma sai 23. Converta a entrada para número antes de somar (com Number(entrada); veja Conversão) para o programa mostrar 5.

function somar(a, b) {
  return a + b;
}

const entrada = "2";
console.log(somar(entrada, 3));

function somar(a, b) {
  return a + b;
}

const entrada = "2";
console.log(somar(Number(entrada), 3));

2. A mesma função em TypeScript

Em TypeScript, o arquivo termina em .ts, e você pode dizer o tipo de cada parâmetro e do que a função devolve:

function somar(a: number, b: number): number {
  return a + b;
}

console.log(somar(2, 3));
console.log(somar("2", 3));
a: number
Uma anotação de tipo: "o parâmetro a é um número". Os dois-pontos depois do nome são a etiqueta.
b: number
O mesmo para o b.
): number {
Depois dos parênteses: "esta função devolve um número".
o resto
É JavaScript comum, igualzinho. Tirando as etiquetas, sobra o soma.js da seção 1.

3. O Node 24 roda .ts direto, sem conferir

Até pouco tempo atrás, para rodar TypeScript era obrigatório "traduzir" o .ts para .js primeiro. O Node.js 24 roda o arquivo .ts direto:

$ node soma.ts
5
23

Rodou, e sem nenhum aviso. Mas repare: o 23 continua lá! O Node faz o que a documentação dele chama de remoção de tipos (em inglês, type stripping): ele apaga as anotações (troca por espaços) e roda o JavaScript que sobra. Ele não confere se os tipos combinam. Nas palavras da documentação do Node 24: "nenhuma conferência de tipos é feita".

Em que versão isso entrou

Pela documentação oficial do Node: a remoção de tipos chegou no Node 22.6 (atrás de uma opção), passou a vir ligada no Node 23.6, deixou de mostrar o aviso de "experimental" no 24.3 e foi declarada estável no 24.12. No Node 24 que a Ana usa (24.22), node arquivo.ts simplesmente roda, como você viu acima. Em versões mais antigas do Node, o mesmo comando dá erro.

O arquivo, a linha 6 e a coluna 19: bem no "2" do somar("2", 3).

Um erro, com o número dele no catálogo do TypeScript (dá para pesquisar "TS2345" na internet).

Esse é o ganho do TypeScript: o defeito do 23 foi apontado sem rodar o programa, na linha e coluna exatas. Nos editores de código como o VS Code, isso acontece enquanto você digita: o "2" fica sublinhado em vermelho na hora.

O jeito comum de trabalhar

Você escreve .ts, o editor de código mostra os erros de tipo enquanto você digita, e o tsc confere o projeto todo antes de publicar. Projetos de verdade têm um arquivo de configuração do tsc, o tsconfig.json, criado com npx tsc --init (o Node ignora esse arquivo; ele é só para o tsc). Com ele na pasta, o comando fica sem nome de arquivo, e o tsc confere todos os .ts de uma vez:

$ npx tsc --init

Created a new tsconfig.json

You can learn more at https://aka.ms/tsconfig
$ npx tsc --noEmit
produto.ts(8,41): error TS2322: Type 'string' is not assignable to type 'number'.
soma.ts(6,19): error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.

(O produto.ts é o exemplo da próxima seção.) Para rodar, continua sendo node arquivo.ts.

5. interface: o formato de um objeto

O TypeScript brilha com objetos. Uma interface descreve quais propriedades um objeto tem e de que tipo:

interface Produto {
  nome: string;
  preco: number;
  emEstoque: boolean;
}

const pao: Produto = { nome: "Pão francês", preco: 0.75, emEstoque: true };
const sonho: Produto = { nome: "Sonho", preco: "4,50", emEstoque: true };

function etiqueta(p: Produto): string {
  return `${p.nome}: R$ ${p.preco.toFixed(2)}`;
}

console.log(etiqueta(pao));
console.log(etiqueta(sonho));
interface Produto { … }
"Um Produto é um objeto com nome (texto), preco (número) e emEstoque (booleano)". A interface não vira código: é só a descrição, e o Node a apaga.
const pao: Produto = { … }
"O pao é um Produto": o tsc confere se o objeto tem o formato combinado.
preco: "4,50"
O erro de propósito: alguém digitou o preço como texto, com vírgula.
function etiqueta(p: Produto): string
Recebe um Produto e devolve um texto.

Rodando direto no Node, o problema só aparece quando o programa chega no sonho:

$ node produto.ts
Pão francês: R$ 0.75
file:///home/ana/ts/produto.ts:11
  return `${p.nome}: R$ ${p.preco.toFixed(2)}`;
                                  ^

TypeError: p.preco.toFixed is not a function
    at etiqueta (file:///home/ana/ts/produto.ts:11:35)
    at Object.<anonymous> (file:///home/ana/ts/produto.ts:15:13)
    at Module._compile (node:internal/modules/cjs/loader:1929:14)  « linhas internas do Node cortadas
    …

Node.js v24.22.0

"p.preco.toFixed não é uma função": um texto não tem o método toFixed dos números. O erro aponta a linha 11, dentro da etiqueta, mas a culpa está na linha 8, onde o preço foi escrito como texto. O tsc aponta direto o lugar certo, sem rodar nada:

$ npx tsc --noEmit produto.ts
produto.ts(8,41): error TS2322: Type 'string' is not assignable to type 'number'.

"O tipo texto não pode ser atribuído ao tipo número", na linha 8, coluna 41: o "4,50".

Quando dá errado

Tipos num arquivo .js

A Ana copiou o soma.ts para soma.js e rodou:

$ node soma.js
/home/ana/ts/soma.js:1
function somar(a: number, b: number): number {
                ^

SyntaxError: Unexpected token ':'
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)  « linhas internas do Node cortadas
    …

Node.js v24.22.0

"Símbolo inesperado :". As anotações de tipo não são JavaScript: o Node só as apaga em arquivos .ts. Num .js, a primeira anotação (o : number do a, apontado pelo ^) é um erro de sintaxe. O mesmo acontece no navegador e no editor do guia. Como consertar: renomeie para .ts (no Node) ou tire as anotações.

enum: o Node recusa 
enum Cor {
  Vermelho,
  Verde,
}
console.log(Cor.Verde);

$ node enum.ts
file:///home/ana/ts/enum.ts:1
  > enum Cor {
      Vermelho,
      Verde,
  > }
    console.log(Cor.Verde);

SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript enum is not supported in strip-only mode
    at parseTypeScript (node:internal/modules/typescript:68:40)  « linhas internas do Node cortadas
    …
  code: 'ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX'
}

Node.js v24.22.0

"enum do TypeScript não é suportado no modo só-remoção". O enum (uma lista de constantes com nome) é um recurso do TypeScript que gera código JavaScript; o Node só sabe apagar tipos, não gerar código. As linhas com > marcam o trecho problemático. A documentação do Node lista outros casos assim: namespace com código, parameter properties nas classes. Como consertar: use um objeto congelado no lugar (const Cor = Object.freeze({ Vermelho: 0, Verde: 1 });, veja Imutabilidade), ou rode pelo tsc, que traduz o enum.

TS5112: o tsc com nome de arquivo e tsconfig.json na pasta 
$ npx tsc --noEmit soma.ts
error TS5112: tsconfig.json is present but will not be loaded if files are specified on commandline. Use '--ignoreConfig' to skip this error.

"O tsconfig.json existe, mas não seria lido, porque você deu nomes de arquivo na linha de comando. Use --ignoreConfig para pular este erro." Depois do npx tsc --init, o tsc quer que você use a configuração. Como consertar: rode sem o nome do arquivo (npx tsc --noEmit), ou, se quer mesmo conferir um arquivo solto, acrescente --ignoreConfig.

"Rodou no Node, então os tipos estão certos"

Não estão necessariamente: o Node não confere tipos (seção 3). O soma.ts rodou e mostrou 23. Como evitar: confira com npx tsc --noEmit (ou no editor de código) antes de confiar.

Missão final: de TypeScript para JavaScript

Missão: este código é TypeScript, e o editor roda JavaScript: ele para com SyntaxError. Transforme em JavaScript: apague a interface inteira e as anotações (: Produto, : Produto[], : string). O resto fica igual.

interface Produto {
  nome: string;
  preco: number;
}

const produtos: Produto[] = [
  { nome: "Pão francês", preco: 0.75 },
  { nome: "Sonho", preco: 4.5 },
];

function etiqueta(p: Produto): string {
  return `${p.nome}: R$ ${p.preco.toFixed(2)}`;
}

for (const p of produtos) {
  console.log(etiqueta(p));
}

const produtos = [
  { nome: "Pão francês", preco: 0.75 },
  { nome: "Sonho", preco: 4.5 },
];

function etiqueta(p) {
  return `${p.nome}: R$ ${p.preco.toFixed(2)}`;
}

for (const p of produtos) {
  console.log(etiqueta(p));
}

É exatamente o que o Node faz com um .ts: apaga os tipos e roda o que sobra. No lab, o código original salvo como main.ts rodou com node main.ts e mostrou as mesmas duas etiquetas da solução.

Resumo

  • TypeScript é JavaScript com anotações de tipo (preco: number) e interface para o formato dos objetos. Os arquivos terminam em .ts.
  • O Node.js 24 roda node arquivo.ts direto (remoção de tipos, estável desde o 24.12), mas não confere os tipos, e recusa recursos que geram código, como enum.
  • Quem confere é o tsc: npm install --save-dev typescript e npx tsc --noEmit arquivo.ts. Os erros vêm com arquivo, linha, coluna e código (TS2345, TS2322).
  • Num arquivo .js, no navegador e no editor do guia, anotações de tipo são SyntaxError.
  • Tudo o que você aprendeu de JavaScript vale no TypeScript: ele é o mesmo JavaScript, com etiquetas.
