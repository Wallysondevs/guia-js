Projeto: Jogo de Adivinhação

Hora de juntar tudo num programa de verdade: um jogo. O computador pensa num número de 1 a 100, e você tenta adivinhar. A cada palpite errado, ele dá uma dica: "é maior" ou "é menor". Parece simples, e é justamente por isso que é o primeiro projeto de tanta gente: ele usa números aleatórios, leitura do teclado, laço, decisões e validação, tudo junto. Vamos construir o jogo em quatro versões, cada uma um pouco melhor que a anterior, do jeito que os programadores trabalham de verdade.

Você vai usar
  • Math.random para sortear o número secreto.
  • readline (await rl.question) para ler os palpites, e Number para convertê-los.
  • while, break e continue para repetir até acertar.
  • if/else e o ternário para as dicas.
  • process.argv para um "modo de teste" com o número escolhido por você.

Todas as versões rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), num terminal de verdade, com a Ana digitando os palpites, numa pasta chamada jogo. Nas caixas "Experimente", quem digita é você, no terminal da própria caixa.

O plano

Antes de escrever código, a Ana escreveu as regras do jogo em português, como uma receita:

  1. O computador sorteia um número inteiro de 1 a 100 e guarda segredo.
  2. Pergunta: "Seu palpite:".
  3. Se o palpite for o número, mostra "Acertou!" e quantas tentativas foram.
  4. Se não for, diz se o número secreto é maior ou menor, e volta ao passo 2.
  5. Palpites que não são números de 1 a 100 não valem (e não contam).
  6. Depois de 7 tentativas sem acertar, o jogo acaba e revela o número.

Ninguém escreve tudo isso de uma vez. O caminho é fazer a menor versão que roda, testar, e acrescentar uma regra por vez:

VersãoO que acrescentaRegras do plano
1Sorteia e aceita um palpite só1, 2, 3
2Repete até acertar, com dicas e contagem; modo de teste4
3Recusa palpites inválidos5
4Limite de 7 tentativas6

Versão 2: repetir até acertar, com dicas

Agora o jogo de verdade: um while que repete enquanto o palpite for diferente do segredo, dizendo a cada volta se o número é maior ou menor, e contando as tentativas. E um truque que vai ajudar muito a testar: o modo de teste. Se você escrever um número depois do nome do programa (node adivinha2.js 42), ele usa esse número em vez de sortear. Assim dá para conferir o jogo sabendo a resposta.

import { createInterface } from "node:readline/promises";

const rl = createInterface({ input: process.stdin, output: process.stdout });

// modo de teste: "node adivinha2.js 42" usa o 42 em vez de sortear
const segredo = process.argv[2]
  ? Number(process.argv[2])
  : Math.floor(Math.random() * 100) + 1;
console.log("Pensei num número de 1 a 100.");

let tentativas = 0;
let palpite = 0;

while (palpite !== segredo) {
  palpite = Number(await rl.question("Seu palpite: "));
  tentativas++;

  if (palpite < segredo) {
    console.log("É maior!");
  } else if (palpite > segredo) {
    console.log("É menor!");
  }
}

console.log(`Acertou! Era ${segredo}. Você precisou de ${tentativas} tentativas.`);
rl.close();

Versão 3: recusar palpites inválidos

O que acontece na versão 2 se a pessoa digitar cinquenta? O Number("cinquenta") dá NaN ("não é um número"; veja NaN): nenhuma dica aparece (NaN não é maior nem menor que nada) e a tentativa é contada assim mesmo. A versão 3 confere o palpite antes de usar:

import { createInterface } from "node:readline/promises";

const MIN = 1;
const MAX = 100;

const rl = createInterface({ input: process.stdin, output: process.stdout });

const segredo = process.argv[2]
  ? Number(process.argv[2])
  : Math.floor(Math.random() * MAX) + MIN;
console.log(`Pensei num número de ${MIN} a ${MAX}.`);

let tentativas = 0;

while (true) {
  const resposta = await rl.question("Seu palpite: ");
  const palpite = Number(resposta);

  if (!Number.isInteger(palpite) || palpite < MIN || palpite > MAX) {
    console.log(`"${resposta}" não vale: digite um número inteiro de ${MIN} a ${MAX}.`);
    continue;

    break;
  }

console.log(`Acertou! Era ${segredo}. Você precisou de ${tentativas} ${palavra}.`);

Versão 4: no máximo 7 tentativas

Sem limite, qualquer um acaba acertando chutando 1, 2, 3… A última regra do plano: 7 tentativas. Por que 7? Porque, com a estratégia certa (veja a dica abaixo), 7 palpites sempre bastam para achar um número de 1 a 100. Quem perde, perdeu por estratégia, não por azar.

import { createInterface } from "node:readline/promises";

const MIN = 1;
const MAX = 100;
const MAX_TENTATIVAS = 7;

const rl = createInterface({ input: process.stdin, output: process.stdout });

const segredo = process.argv[2]
  ? Number(process.argv[2])
  : Math.floor(Math.random() * MAX) + MIN;
console.log(`Pensei num número de ${MIN} a ${MAX}. Você tem ${MAX_TENTATIVAS} tentativas.`);

let tentativas = 0;
let acertou = false;

while (tentativas < MAX_TENTATIVAS) {
  const resposta = await rl.question("Seu palpite: ");
  const palpite = Number(resposta);

  if (!Number.isInteger(palpite) || palpite < MIN || palpite > MAX) {
    console.log(`"${resposta}" não vale: digite um número inteiro de ${MIN} a ${MAX}.`);
    continue;
  }

  tentativas++;
  if (palpite === segredo) {
    acertou = true;
    break;
  }
  const dica = palpite < segredo ? "É maior!" : "É menor!";
  console.log(`${dica} Restam ${MAX_TENTATIVAS - tentativas}.`);
}

if (acertou) {
  const palavra = tentativas === 1 ? "tentativa" : "tentativas";
  console.log(`Acertou! Era ${segredo}. Você precisou de ${tentativas} ${palavra}.`);
} else {
  console.log(`Suas tentativas acabaram! O número era ${segredo}.`);
}
rl.close();
const MAX_TENTATIVAS = 7;

let acertou = false;
Uma "bandeira" (em inglês, flag): começa false e vira true se a pessoa acertar. Depois do laço, é ela que diz qual mensagem mostrar.
while (tentativas < MAX_TENTATIVAS)
Agora o laço tem duas saídas: o break (acertou) ou a condição ficar falsa (acabaram as tentativas).
Restam ${MAX_TENTATIVAS - tentativas}
Quantas sobram, junto com a dica.
if (acertou) … else …
A mensagem final certa para cada uma das duas saídas.

A estratégia: chute sempre o meio

Comece com 50. Se for "maior", o número está entre 51 e 100: chute o meio, 75. Cada palpite corta pela metade os números que sobram: 100 → 50 → 25 → 13 → 7 → 4 → 2 → 1. Em 7 palpites sobra um número só, o certo. Os programadores chamam isso de busca binária, e ela é usada de verdade para procurar em listas ordenadas enormes: num milhão de itens, bastam 20 passos.

Ela digitou 42, o número certo, duas vezes, e o jogo continuou perguntando, sem dica nenhuma. O motivo: o rl.question devolve o texto "42", e "42" !== 42 é true (com ===/!==, texto nunca é igual a número). O laço não termina nunca. A Ana apertou Ctrl+C no terceiro "Seu palpite:", e o Node encerrou com o AbortError ("abortado com Ctrl+C") que você já viu em Lendo o Teclado. Como consertar: Number(await rl.question(…)).

O sorteio nunca acerta (ou o 100 nunca sai)

Sem o Math.floor, o segredo tem casas decimais (como 41.83…), e nenhum palpite inteiro acerta. Sem o + 1, o sorteio vai de 0 a 99, e o 100 nunca sai. Com Math.round no lugar do Math.floor, o 1 e o 100 saem com metade da chance dos outros (veja Números Aleatórios). Como conferir: rode no modo de teste para testar o jogo, e confira o sorteio separado, com um console.log(segredo) provisório.

O programa não termina depois do "Acertou!"

Faltou o rl.close() no fim: o leitor continua esperando o teclado, e o $ não volta (veja Lendo o Teclado no Node). Como consertar: rl.close(); como última linha.

A tentativa inválida contou

O tentativas++ ficou antes da validação. A ordem importa: primeiro confira, e só depois que o palpite for válido conte a tentativa (na versão 3, o continue vem antes do tentativas++).

Ideias para continuar

  • Níveis de dificuldade: pergunte no começo "fácil (1 a 10), médio (1 a 100) ou difícil (1 a 1000)?" e ajuste o MAX e o MAX_TENTATIVAS.
  • Jogar de novo: no fim, pergunte "Jogar de novo? (s/n)" e envolva o jogo inteiro num laço.
  • Recorde: guarde o menor número de tentativas num arquivo com fs e avise quando alguém bater o recorde.
  • Versão para a página: troque o readline pelo prompt(), ou por um campo de texto e um botão (veja Formulários).
  • Testes: separe a parte das dicas numa função (dica(palpite, segredo)) e escreva testes para ela (veja Testes).

  const palpite = Number(resposta);

  if (!Number.isInteger(palpite) || palpite < MIN || palpite > MAX) {
    console.log(`"${resposta}" não vale: digite um número inteiro de ${MIN} a ${MAX}.`);
    continue;
  }

  tentativas++;
  if (palpite === segredo) {
    acertou = true;
    break;
  }
  const dica = palpite < segredo ? "É maior!" : "É menor!";
  console.log(`${dica} Restam ${MAX_TENTATIVAS - tentativas}.`);
}

if (acertou) {
  const palavra = tentativas === 1 ? "tentativa" : "tentativas";
  console.log(`Acertou! Era ${segredo}. Você precisou de ${tentativas} ${palavra}.`);
} else {
  console.log(`Suas tentativas acabaram! O número era ${segredo}.`);
}
rl.close();

No lab, a solução mostrou as dicas até É maior! Restam 0. e, por fim, Suas tentativas acabaram! O número era 42.. Depois, rode sem o modo de teste e jogue de verdade, usando a estratégia do meio.

Resumo

  • Um projeto se constrói em versões: a menor que roda, e depois uma regra nova por vez, testando a cada passo.
  • Sorteio de 1 a 100: Math.floor(Math.random() * 100) + 1. Palpite: Number(await rl.question(…)), porque o teclado entrega texto.
  • O laço do jogo: while até acertar, com dicas por if/ternário; continue para recusar palpite inválido sem contar, break para sair quando acerta.
  • Validação com Number.isInteger e os limites; uma bandeira (acertou) para saber por qual saída o laço terminou.
  • O modo de teste com process.argv fixa o número secreto, para testar um programa que depende do acaso.
