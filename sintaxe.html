JavaScript Instruções, Ponto e Vírgula e Blocos

Toda língua tem regras de escrita: em português, a frase termina com ponto, os parágrafos agrupam frases, e a letra maiúscula muda o sentido de algumas palavras. O JavaScript também tem as suas, e elas formam a sintaxe da linguagem. Esta aula mostra as três primeiras: a instrução (a "frase" do programa), o ponto e vírgula que a termina e o bloco com chaves { } que agrupa instruções. E mostra, com as mensagens reais, o que acontece quando elas são quebradas.

Você vai aprender
  • O que é uma instrução e que o programa as executa uma de cada vez, de cima para baixo.
  • Para que serve o ponto e vírgula e por que este guia sempre o escreve.
  • O que o JavaScript faz quando o ; falta, e as duas armadilhas disso (linhas que começam com ( ou [).
  • Que espaços e quebras de linha, na maior parte dos lugares, não importam; e que maiúsculas importam sempre.
  • O que é um bloco { }, a indentação de 2 espaços, e que o que nasce dentro de um bloco fica nele.
  • Os erros reais: Unexpected identifier, Unexpected end of input, Unexpected token '}', is not a function.

Os programas foram rodados com o Node.js 24 LTS na máquina fictícia da Ana, na pasta /home/ana/js.

A ideia: frases, pontos e parágrafos

Pense numa receita escrita no caderno. Cada frase é uma ordem: "ligue o forno." O ponto final mostra onde uma ordem termina e a próxima começa. E um parágrafo agrupa as frases que andam juntas: "Para a cobertura: derreta o chocolate. Junte o creme."

1. Instruções

Uma instrução (em inglês, statement) é uma ordem completa para o computador: "mostre isto", "guarde aquilo", "se tal coisa, faça aquilo outro". Um programa é uma sequência de instruções, executadas uma de cada vez, de cima para baixo:

console.log("Bom dia!");
console.log("A padaria abriu.");
console.log("Pão saindo às 7h.");

$ node instrucoes.js
Bom dia!
A padaria abriu.
Pão saindo às 7h.

Três instruções, três linhas na saída, na ordem do arquivo. O normal, e o que este guia faz, é escrever uma instrução por linha: fica fácil de ler, e a mensagem de erro aponta a linha exata do problema.

2. O ponto e vírgula

O ; marca o fim de uma instrução. Com ele, o JavaScript sabe onde uma termina e a outra começa, mesmo que estejam na mesma linha:

console.log("Um"); console.log("Dois"); console.log("Três");

$ node mesma-linha.js
Um
Dois
Três

Funciona, mas é mais difícil de ler; use só em casos raros. Agora, o que acontece se o ; falta?

Sem ponto e vírgula, em linhas separadas: funciona

console.log("Bom dia!")
console.log("A padaria abriu.")

$ node sem-ponto.js
Bom dia!
A padaria abriu.

Rodou normalmente. O JavaScript tem uma regra chamada inserção automática de ponto e vírgula (em inglês, ASI, de Automatic Semicolon Insertion): quando uma linha termina e a próxima não faz sentido como continuação, ele age como se houvesse um ; ali. Por isso você vai encontrar muito código JavaScript sem ; nenhum.

Sem ponto e vírgula, na mesma linha: erro

console.log("Um") console.log("Dois")

$ node sem-ponto-mesma.js
/home/ana/js/sem-ponto-mesma.js:1
console.log("Um") console.log("Dois")
                  ^^^^^^^

SyntaxError: Unexpected identifier 'console'
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)

Node.js v24.22.0

Aqui não há quebra de linha para o JavaScript "adivinhar". Depois de console.log("Um") ele esperava o fim da instrução e encontrou outra palavra: "identificador inesperado console" (um identificador é um nome, como console, nome ou preco). Os ^^^^^^^ marcam o segundo console. É um SyntaxError, então nem o "Um" apareceu.

Missão: conserte a linha para mostrar Um e Dois. Dá para resolver de dois jeitos: com um ; entre as instruções, ou passando a segunda para a linha de baixo (melhor ainda: os dois).

console.log("Um") console.log("Dois")

console.log("Um");
console.log("Dois");

As duas armadilhas do ponto e vírgula esquecido

A inserção automática só põe o ; quando a linha de baixo não pode continuar a de cima. E algumas linhas podem. As duas armadilhas clássicas são linhas que começam com ( ou com [.

Uma linha que começa com (:

console.log("Olá")
(2 + 3)

$ node parenteses.js
Olá
/home/ana/js/parenteses.js:2
(2 + 3)
^

TypeError: console.log(...) is not a function
    at Object.<anonymous> (/home/ana/js/parenteses.js:2:1)
    «  mais 7 linhas "at … (node:internal/…)" cortadas

Node.js v24.22.0

Para o JavaScript, um ( logo depois de alguma coisa quer dizer "chame isso como função". Então ele juntou as duas linhas numa só: console.log("Olá")(2 + 3). Ele rodou o console.log("Olá") (o "Olá" apareceu) e tentou chamar o resultado com (2 + 3). Mas o console.log não devolve uma função, e veio o TypeError ("erro de tipo"): "console.log(...) não é uma função".

Uma linha que começa com [:

const nome = "Ana"
[1, 2, 3].forEach(n => console.log(n))

$ node colchetes.js
/home/ana/js/colchetes.js:2
[1, 2, 3].forEach(n => console.log(n))
          ^

TypeError: Cannot read properties of undefined (reading 'forEach')
    at Object.<anonymous> (/home/ana/js/colchetes.js:2:11)
    «  mais 7 linhas "at … (node:internal/…)" cortadas

Node.js v24.22.0

Não precisa entender a linha 2 agora (ela mostra os números de uma lista; aula forEach). O que importa: o [ no começo da linha também pode continuar a anterior (é o jeito de pegar uma posição: "Ana"[1] é a letra n). O JavaScript leu "Ana"[1, 2, 3].forEach(...), uma bagunça que deu undefined ("indefinido"), e quebrou: "não dá para ler propriedades de undefined (lendo forEach)". O erro aponta a linha 2, mas a causa é o ; que faltou na linha 1.

A regra deste guia: sempre ; no fim das instruções

Com o ;, essas armadilhas não existem: o JavaScript não tenta juntar linhas que você separou. Há programadores (e projetos inteiros) que preferem não usar ;, e também funciona, desde que conheçam essas regras. Para quem está começando, colocar sempre é mais seguro. Exceção: depois de um bloco } de if, for e function, não vai ; (você vai ver abaixo).

Missão: o programa deveria mostrar Olá e o resultado de 2 + 3, mas cai na armadilha do (. Conserte: termine a linha 1 com ; e transforme a linha 2 numa instrução que mostre o resultado.

console.log("Olá")
(2 + 3)

console.log("Olá");
console.log(2 + 3);

3. Espaços, quebras de linha e maiúsculas

Entre as partes de uma instrução, o JavaScript ignora espaços e quebras de linha a mais. Estas três instruções são iguais para ele:

console.log("Pães:",12);
console.log( "Pães:" , 12 ) ;
console.log(
  "Pães:",
  12
);

$ node espacos.js
Pães: 12
Pães: 12
Pães: 12

A terceira forma, quebrada em várias linhas, é útil quando a instrução fica comprida demais. Mas os espaços dentro das aspas contam: "Pães:" e " Pães: " são textos diferentes. E não dá para quebrar um nome ao meio (con sole.log) nem continuar um texto de aspas duplas ou simples na linha de baixo.

Já as maiúsculas e minúsculas importam sempre: console, Console e CONSOLE são três nomes diferentes, e só o primeiro existe (você viu o Console is not defined na Introdução). Em inglês se diz que o JavaScript é case-sensitive, "sensível à caixa" (caixa alta = maiúscula, caixa baixa = minúscula).

O estilo deste guia

Um espaço depois da vírgula ("Pães:", 12), espaço em volta das contas (2 + 3), nenhum espaço logo depois do ( nem antes do ), e uma instrução por linha. Não é obrigatório, mas deixa o código fácil de ler, e é o estilo mais comum no JavaScript.

4. Blocos { }

Um bloco é um grupo de instruções entre chaves { }, tratado como uma coisa só. Ele quase sempre aparece junto com uma palavra que diz quando ou quantas vezes o grupo roda. Aqui, com o if ("se"), que você vai estudar em if:

const paes = 12;

if (paes > 10) {
  console.log("Muitos pães hoje!");
  console.log("Pode vender à vontade.");
}

console.log("Fim do dia.");

$ node bloco.js
Muitos pães hoje!
Pode vender à vontade.
Fim do dia.
const paes = 12;
Uma instrução que guarda o número 12 com o nome paes (aula Constantes).
if (paes > 10)
"Se paes for maior que 10". O que vem a seguir só roda se isso for verdade.
{
Abre o bloco: daqui até o }, tudo faz parte do "então".
As duas linhas de dentro
As instruções do bloco, cada uma com o seu ;. Elas rodam juntas, uma depois da outra.
}
Fecha o bloco. Depois dele não vai ;: o } já marca o fim.
console.log("Fim do dia.");
Fora do bloco: roda sempre, seja qual for o número de pães.

Você vai usar blocos com o if, o else, o for, o while, as funções… Eles são os "parágrafos" do JavaScript.

A indentação: 2 espaços

Repare que as linhas de dentro do bloco começam com 2 espaços. Esse recuo se chama indentação. Para o JavaScript ela não muda nada (o que vale são as chaves), mas para quem lê ela muda tudo: dá para ver, de longe, o que está dentro e o que está fora. Este guia usa 2 espaços por nível, o padrão mais comum no JavaScript. Os editores de código (como o VS Code) fazem isso sozinhos quando você aperta Enter depois de um {.

O que nasce no bloco fica no bloco

Um nome criado com const (ou let) dentro de um bloco só existe ali dentro. Aqui o bloco está sozinho, sem if, só para mostrar isso:

{
  const recado = "Pão quentinho!";
  console.log("Dentro:", recado);
}
console.log("Fora:", recado);

$ node bloco-let.js
Dentro: Pão quentinho!

Dentro do bloco, recado funcionou. Fora, "recado não está definido": ao fechar o }, o nome deixou de existir. É como um recado preso dentro de uma gaveta: quem está fora não vê. Essa regra se chama escopo de bloco e tem aula própria: Escopo.

Instruções coladas na mesma linha

Já visto acima: console.log("Um") console.log("Dois") dá SyntaxError: Unexpected identifier 'console'. Como consertar: ; entre elas, ou uma por linha.

Resumo

  • Um programa é uma sequência de instruções, executadas uma de cada vez, de cima para baixo. Escreva uma por linha.
  • O ; termina a instrução. Sem ele, o JavaScript tenta adivinhar (inserção automática), e erra quando a linha seguinte começa com ( ou [. Neste guia: sempre ;, menos depois do } de um bloco.
  • Espaços e quebras de linha extras não importam (fora das aspas); maiúsculas e minúsculas importam sempre.
  • Um bloco { } agrupa instruções; dentro dele, 2 espaços de indentação. O que é criado com const/let dentro do bloco só existe ali.
  • Erros: Unexpected identifier (instruções coladas), Unexpected end of input (chave sem fechar), Unexpected token '}' (chave sobrando).
