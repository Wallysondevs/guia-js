JavaScript process.argv

Até agora, para o programa usar outro nome ou outro número, você mudava o código. Mas os programas de verdade recebem informações na hora de rodar: em npm install lodash, o lodash é uma informação que o npm recebeu; em node vitrine.js, o vitrine.js é uma informação que o node recebeu. Essas palavras que vêm depois do comando são os argumentos da linha de comando, e no Node o seu programa as encontra em process.argv. É um recurso só do Node: no navegador não existe linha de comando.

Você vai aprender
  • O que é process.argv e o que há em cada posição dele.
  • Como pegar o primeiro argumento (process.argv[2]) e todos de uma vez (process.argv.slice(2)).
  • Por que os números chegam como texto ("2" + "3" dá "23") e como converter.
  • Como lidar com o argumento que falta: valor padrão com ?? ou mensagem de uso com process.exit(1).
  • Aspas para textos com espaço e o cuidado com o $.
  • Opções do tipo --maiusculas, à mão e com o parseArgs do Node.
  • Como passar argumentos pelo npm start --.

Todos os programas rodaram no Node.js v24.22.0 da máquina da Ana (usuária ana, computador notebook), salvos na pasta dela e executados com node arquivo.js seguido dos argumentos.

A ideia: o bilhete junto com o pedido

Na padaria, o forno não muda: o que muda é o pedido. A Ana não reescreve a receita a cada cliente; ela recebe um bilhete, "3 pães de queijo para a Bia", e a mesma receita atende a todos. Com o programa é igual: o código fica igual, e o bilhete vai junto no comando.

$ node saudacao.js Ana   « "Ana" é o bilhete
Bom dia, Ana!

O terminal separa o que você digitou nos espaços e entrega as palavras ao Node, que as guarda num array: o process.argv (argument vector, "lista de argumentos"). O process é um objeto que o Node cria sozinho, com informações sobre o programa que está rodando (você vai ver outras partes dele em process.env e process.exit).

1. O que tem dentro do process.argv

O jeito mais fácil de entender é mostrar o array inteiro:

console.log(process.argv);

$ node argumentos.js
[ '/usr/local/bin/node', '/home/ana/argumentos.js' ]
$ node argumentos.js Ana 30 padaria
[
  '/usr/local/bin/node',
  '/home/ana/argumentos.js',
  'Ana',
  '30',
  'padaria'
]
PosiçãoValorO que é
process.argv[0]'/usr/local/bin/node'Onde está o programa node no computador
process.argv[1]'/home/ana/argumentos.js'O caminho completo do seu arquivo
process.argv[2]'Ana'O primeiro argumento seu
process.argv[3]'30'O segundo
process.argv[4]'padaria'O terceiro

Três coisas para guardar:

  • As posições 0 e 1 estão sempre ocupadas, pelo node e pelo arquivo. Os seus argumentos começam na posição 2. (Os caminhos das posições 0 e 1 mudam de um computador para outro; ninguém escreve programa que dependa deles.)
  • Todos os valores são strings, até o '30' (repare nas aspas).
  • Sem argumentos, o array tem só os dois primeiros itens.

Espaços e aspas

Como o terminal separa nos espaços, "pão de queijo" vira três argumentos. Para mandar um texto com espaços como um argumento, ponha-o entre aspas:

$ node argumentos.js pão de queijo
[
  '/usr/local/bin/node',
  '/home/ana/argumentos.js',
  'pão',
  'de',
  'queijo'
]
$ node argumentos.js "pão de queijo"
[ '/usr/local/bin/node', '/home/ana/argumentos.js', 'pão de queijo' ]

As aspas não chegam ao programa: o terminal as usa para saber onde o argumento começa e termina, e as tira.

2. Pegando um argumento: process.argv[2]

const nome = process.argv[2];
console.log(`Bom dia, ${nome}!`);
process.argv[2]
O item na posição 2 do array, ou seja, o primeiro argumento depois do nome do arquivo (veja Acessando e Alterando Itens).
const nome = …
Guarda o argumento numa variável com um nome que diz o que ele é. process.argv[2] espalhado pelo código fica difícil de ler; nome, não.
$ node saudacao.js Ana
Bom dia, Ana!
$ node saudacao.js Bia
Bom dia, Bia!
$ node saudacao.js
Bom dia, undefined!

O mesmo programa, sem mudar uma letra, cumprimentou a Ana e a Bia. Na terceira vez, sem argumento, a posição 2 não existia, e um item que não existe vale undefined (veja null e undefined). Não deu erro, mas a mensagem ficou estranha. A seção 5 resolve isso.

Experimente: no editor, o atributo da caixa faz o papel do terminal e manda Ana como argumento. Rode, depois troque o texto do console.log para mostrar também process.argv.length (quantos itens há no array: os dois fixos mais o seu).

const nome = process.argv[2];
console.log(`Bom dia, ${nome}!`);

3. Os números chegam como texto

A Ana quer somar dois números passados no comando:

const a = process.argv[2];
const b = process.argv[3];
console.log(a + b);
console.log(typeof a);

$ node soma.js 2 3
23
string

Deu 23, não 5. O typeof mostra por quê: a é uma string, "2", e o + entre duas strings junta os textos (veja Conversão Automática). Tudo o que vem do terminal é texto. Para fazer conta, converta com Number() (veja Conversão):

const a = Number(process.argv[2]);
const b = Number(process.argv[3]);
console.log(`${a} + ${b} = ${a + b}`);

$ node soma2.js 2 3
2 + 3 = 5
$ node soma2.js 2 três
2 + NaN = NaN

Com 2 três, o Number("três") não sabe converter e devolve NaN ("não é um número"; veja NaN, Infinity e a Precisão). Na seção Quando dá errado você vê como avisar a pessoa.

Missão: a caixa roda o programa como node main.js 2 3. Hoje ele mostra 2 + 3 = 23. Converta os argumentos para número, para aparecer 2 + 3 = 5.

const a = process.argv[2];
const b = process.argv[3];
console.log(`${a} + ${b} = ${a + b}`);

const b = Number(process.argv[3]);
console.log(`${a} + ${b} = ${a + b}`);

4. Todos os argumentos: process.argv.slice(2)

Quando não se sabe quantos argumentos virão (a lista de compras pode ter 2 itens ou 20), corte fora as duas primeiras posições com o slice(2) ("fatiar a partir da posição 2"; veja splice e slice). Sobra um array só com os seus argumentos:

const itens = process.argv.slice(2);
console.log(`A Ana vai comprar ${itens.length} itens:`);
for (const item of itens) {
  console.log(`- ${item}`);
}

$ node todos.js leite pão café
A Ana vai comprar 3 itens:
- leite
- pão
- café
$ node todos.js
A Ana vai comprar 0 itens:

Sem argumentos, o slice(2) devolve um array vazio, [], e o for … of não dá nenhuma volta.

Dando nome a cada posição: desestruturação

Quando os argumentos têm papéis fixos (o primeiro é o preço, o segundo é o valor pago), a desestruturação dá um nome a cada um numa linha só:

const [precoTexto, pagoTexto] = process.argv.slice(2);

É o mesmo que const precoTexto = process.argv[2]; e const pagoTexto = process.argv[3];. O programa completo está logo abaixo.

5. E se o argumento faltar?

Jeito 1: um valor padrão com ??

Se dá para seguir com um valor qualquer, use o ?? (veja ?. e ??): "use o argumento; se ele for undefined, use este outro".

const nome = process.argv[2] ?? "freguês";
console.log(`Bom dia, ${nome}!`);

$ node padrao.js
Bom dia, freguês!
$ node padrao.js Ana
Bom dia, Ana!

Jeito 2: explicar o uso e sair com erro

Se o argumento é indispensável, o programa deve parar e explicar como se usa. É o que os programas de terminal fazem: mostram uma linha "Uso: …" e terminam com código de saída 1 ("deu errado").

const [precoTexto, pagoTexto] = process.argv.slice(2);

if (precoTexto === undefined || pagoTexto === undefined) {
  console.error("Uso: node troco.js PREÇO VALOR_PAGO");
  console.error("Exemplo: node troco.js 7.50 10");
  process.exit(1);
}

const preco = Number(precoTexto);
const pago = Number(pagoTexto);
console.log(`Troco: R$ ${(pago - preco).toFixed(2)}`);
if (precoTexto === undefined || pagoTexto === undefined)
"Se faltou o preço ou faltou o valor pago…"
console.error(…)
Escreve a mensagem na saída de erros (veja console.error, warn e table). No terminal aparece igual ao console.log.
process.exit(1)
Encerra o programa ali mesmo, com o código de saída 1. As linhas de baixo não rodam. Os detalhes estão em process.env e process.exit.
(pago - preco).toFixed(2)
A conta, com duas casas decimais (veja Formatando Números). O - já converte texto em número sozinho, mas o Number() deixa a intenção clara.
$ node troco.js 7.50 10
Troco: R$ 2.50
$ node troco.js 7.50
Uso: node troco.js PREÇO VALOR_PAGO
Exemplo: node troco.js 7.50 10
$ echo $?
1

O echo $? mostra o código de saída do último comando: 1, porque faltou o valor pago.

6. Opções: --maiusculas

Muitos comandos aceitam opções que começam com -- (ou - e uma letra), como o --save-dev do npm. São argumentos como os outros; o programa é que decide o que fazer com eles.

À mão, com includes e filter

const args = process.argv.slice(2);
const maiusculas = args.includes("--maiusculas");
const itens = args.filter((a) => !a.startsWith("--"));
for (const item of itens) {
  console.log(maiusculas ? item.toUpperCase() : item);
}
args.includes("--maiusculas")
true se a opção apareceu em qualquer posição (veja Procurando).
args.filter((a) => !a.startsWith("--"))
Fica com os argumentos que não começam com --: os itens da lista (veja filter).
maiusculas ? item.toUpperCase() : item
Com a opção, o item em maiúsculas; sem ela, como veio (veja O Operador Ternário).
$ node lista.js leite pão
leite
pão
$ node lista.js leite --maiusculas pão
LEITE
PÃO

Com o parseArgs do Node

Quando as opções aumentam (opção com valor, letra curta, valor padrão), fazer tudo à mão cansa. O Node traz pronto o parseArgs ("analisar os argumentos"), no módulo node:util:

const { parseArgs } = require("node:util");

const { values, positionals } = parseArgs({
  options: {
    maiusculas: { type: "boolean", short: "m" },
    vezes: { type: "string", short: "v", default: "1" },
  },
  allowPositionals: true,
});

console.log(values);
console.log(positionals);
options
As opções que o programa aceita. maiusculas é do tipo "boolean" (liga/desliga: --maiusculas ou -m). vezes é do tipo "string": espera um valor depois (--vezes 3), e vale "1" se não vier.
allowPositionals: true
"Permitir argumentos soltos": os que não são opção (leite, pão).
values / positionals
O resultado: um objeto com as opções e um array com os argumentos soltos.
$ node opcoes.js leite pão
[Object: null prototype] { vezes: '1' }
[ 'leite', 'pão' ]
$ node opcoes.js leite -m --vezes 3 pão
[Object: null prototype] { maiusculas: true, vezes: '3' }
[ 'leite', 'pão' ]

O [Object: null prototype] é um detalhe técnico do objeto que o parseArgs cria; para você, ele funciona como um objeto comum: values.vezes, values.maiusculas. Repare que o 3 chegou como '3', texto, como todo argumento.

7. Argumentos pelo npm start

Num projeto com "start": "node index.js" no package.json (veja O package.json), os argumentos vão depois de --, que diz ao npm "daqui em diante, não é para você, é para o programa":

$ npm start

> saudar@1.0.0 start
> node index.js

Bom dia, freguês!
$ npm start -- Ana

> saudar@1.0.0 start
> node index.js Ana

Bom dia, Ana!

A segunda linha com > mostra o comando que o npm montou: node index.js Ana. No npm 11 da Ana, npm start Bia (sem o --) também chegou ao programa (> node index.js Bia). Com uma opção, não: sem o --, o npm acha que ela é para ele.

$ npm start --maiusculas
npm warn Unknown cli config "--maiusculas". This will stop working in the next major version of npm.

> saudar@1.0.0 start
> node index.js

Bom dia, freguês!
$ npm start -- --maiusculas

> saudar@1.0.0 start
> node index.js --maiusculas

Bom dia, --maiusculas!

No primeiro, o npm avisou "configuração desconhecida: --maiusculas" e não a passou adiante (o comando montado é só node index.js). No segundo, com o --, ela chegou ao programa. Por isso, use sempre o --.

2. NaN: o argumento não era número

Brasileiro escreve 7,50 com vírgula, mas o Number() só entende ponto:

$ node troco.js 7,50 10
Troco: R$ NaN

Não houve erro: o programa rodou e mostrou um resultado sem sentido. Conserto: confira com Number.isNaN(preco) e explique o uso (como na seção 5), ou troque a vírgula por ponto antes de converter: Number(precoTexto.replace(",", ".")) (veja replace).

3. O $ sumiu do argumento

console.log(process.argv.slice(2));

$ node preco.js R$5 "R$ 5" 'R$ 5'
[ 'R', 'R$ 5', 'R$ 5' ]

No primeiro, sem aspas, o terminal entendeu $5 como uma variável dele (que estava vazia) e entregou só R. O programa nem ficou sabendo. Com aspas, o $ seguido de espaço passou. Regra prática: argumento com $, &, *, ! ou espaço vai entre aspas simples ('R$5'), que o terminal não mexe em nada.

Resumo

  • Argumentos da linha de comando são as palavras depois de node arquivo.js. No Node, chegam no array process.argv (só no Node; o navegador não tem).
  • As posições 0 e 1 são o node e o arquivo; os seus argumentos começam em process.argv[2]. process.argv.slice(2) dá todos eles.
  • Todo argumento é string: converta com Number() antes de fazer conta, e cuide do NaN.
  • O terminal separa nos espaços: texto com espaço (ou com $) vai entre aspas, de preferência simples.
  • Argumento que falta vale undefined: use um padrão com ?? ou explique o uso e saia com process.exit(1).
  • Opções (--maiusculas) se tratam com includes/filter ou com o parseArgs do node:util. Pelo npm: npm start -- argumentos.
