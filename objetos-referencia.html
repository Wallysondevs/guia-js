JavaScript Objetos são Referências

Você escreve const outra = ana;, muda a idade em outra… e a idade de ana muda junto. Não é defeito: é a regra mais importante sobre objetos e arrays no JavaScript. Uma variável não guarda o objeto; ela guarda o caminho até ele, uma referência. Esta aula mostra o que isso muda no dia a dia e como fazer uma cópia de verdade quando você precisa de uma.

Você vai aprender
  • A diferença entre copiar um número (o valor vai junto) e "copiar" um objeto (só o endereço vai junto).
  • Por que { nome: "Ana" } === { nome: "Ana" } dá false.
  • O que acontece com um objeto que você passa para uma função.
  • Por que const não impede de mudar o objeto, e o que é o Object.freeze.
  • Como copiar de verdade: a cópia rasa ({ ...obj }) e a cópia profunda (structuredClone).
  • Os erros reais: Assignment to constant variable e could not be cloned.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa).

A ideia: o papel com o endereço da casa

Pense numa casa e num papelzinho com o endereço dela.

  • Se a Ana tira xerox do papel e dá para a Bia, agora existem dois papéis, mas continua existindo uma casa só. Se a Bia for lá e pintar a porta de azul, quando a Ana chegar a porta estará azul.
  • Já um número é como um bilhete com "10" escrito. Tirar xerox dá outro bilhete com "10"; riscar e escrever "20" na cópia não muda o original.

No JavaScript é assim:

Tipo de valorO que a variável guardaO que b = a faz
Primitivos: número, texto, booleano, null, undefined, bigint (veja Os Tipos de Dados)O próprio valorCopia o valor: são dois valores independentes
Objetos (inclui arrays e funções)Uma referência: o "endereço" do objeto na memóriaCopia o endereço: as duas variáveis apontam para o mesmo objeto

1. Números são copiados

let a = 10;
let b = a;
b = 20;
console.log("a:", a);
console.log("b:", b);

$ node numeros.js
a: 10
b: 20

Na linha 2, b recebeu uma cópia do 10. Na linha 3, só o b mudou. Nada surpreendente, e é assim que você espera que tudo funcione. Agora veja um objeto.

2. Objetos são compartilhados

const ana = { nome: "Ana", idade: 30 };
const outra = ana;
outra.idade = 31;
console.log(ana);
console.log(outra);
const ana = { nome: "Ana", idade: 30 };
As chaves { } criam um objeto novo na memória. A variável ana recebe o endereço dele.
const outra = ana;
Não cria objeto nenhum (não há { } aqui). Só copia o endereço: agora ana e outra são dois nomes para o mesmo objeto.
outra.idade = 31;
Vai até o objeto pelo endereço guardado em outra e troca a idade lá dentro. Como o objeto é um só…
console.log(ana);
…lendo pelo outro nome, a idade também é 31.
$ node referencia.js
{ nome: 'Ana', idade: 31 }
{ nome: 'Ana', idade: 31 }
Regra prática

Conte as chaves { } (ou colchetes [ ]). Cada { … } escrito no código cria um objeto. Neste programa há um par de chaves só, então há um objeto só, por mais variáveis que apontem para ele.

Missão: a Ana quer que outra seja um objeto separado, para mudar a idade sem mexer no original. Troque const outra = ana; por const outra = { ...ana }; (os três pontinhos copiam as propriedades para um objeto novo; a seção 6 explica) e rode: a primeira linha deve continuar com idade: 30.

const ana = { nome: "Ana", idade: 30 };
const outra = ana;
outra.idade = 31;
console.log(ana);
console.log(outra);

const ana = { nome: "Ana", idade: 30 };
const outra = { ...ana };
outra.idade = 31;
console.log(ana);
console.log(outra);

3. Comparar objetos com ===

O === (veja Comparação) compara o que a variável guarda. Para objetos, ele guarda o endereço, então === pergunta: "é o mesmo objeto?", e não "têm o mesmo conteúdo?".

const a = { nome: "Ana" };
const b = { nome: "Ana" };
const c = a;
console.log(a === b);
console.log(a === c);
console.log(a.nome === b.nome);

$ node comparar.js
false     « dois pares de chaves: dois objetos, mesmo com o mesmo conteúdo
true      « c é só outro nome para o objeto de a
true      « aqui se comparam dois textos (primitivos): "Ana" === "Ana"

São duas casas iguaizinhas, mas em endereços diferentes. Para saber se dois objetos têm o mesmo conteúdo, compare as propriedades que importam (a.nome === b.nome) ou, para objetos simples, compare a versão em texto deles, com JSON.stringify (veja JSON e a seção Quando dá errado).

4. Objetos passados para funções

Quando você chama uma função com um objeto, o parâmetro recebe o endereço (veja Parâmetros e Argumentos). Por isso a função consegue mudar o objeto original:

function fazerAniversario(pessoa) {
  pessoa.idade = pessoa.idade + 1;
}

const ana = { nome: "Ana", idade: 30 };
fazerAniversario(ana);
console.log(ana);

$ node aniversario.js
{ nome: 'Ana', idade: 31 }

pessoa e ana apontam para o mesmo objeto; mudar pessoa.idade é mudar ana.idade. Mas atenção à diferença entre mexer dentro do objeto e trocar o endereço do parâmetro:

function trocarPessoa(pessoa) {
  pessoa = { nome: "Bia", idade: 25 };
  console.log("dentro:", pessoa);
}

const ana = { nome: "Ana", idade: 30 };
trocarPessoa(ana);
console.log("fora:", ana);

$ node trocar.js
dentro: { nome: 'Bia', idade: 25 }
fora: { nome: 'Ana', idade: 30 }

pessoa = { … } escreve um endereço novo no papel pessoa, que é só da função. O papel ana, lá fora, continua com o endereço antigo. Resumindo:

Dentro da funçãoAfeta o objeto de quem chamou?
pessoa.idade = 31, lista.push("café"), delete pessoa.nomeSim: mexe dentro do objeto compartilhado
pessoa = { … }, lista = []Não: só troca o endereço guardado no parâmetro
Função que muda o que recebeu

Uma função que altera o objeto recebido pode surpreender quem a chamou ("eu só queria calcular, por que a minha lista mudou?"). Quando a função só precisa calcular algo, prefira não mexer no objeto: crie e devolva um novo (veja return). Métodos como map, filter e toSorted seguem essa ideia.

5. Arrays também são referências

Array é um tipo de objeto, então vale tudo o que você viu:

const compras = ["arroz", "feijão"];
const lista = compras;
lista.push("café");
console.log(compras);
console.log(compras === lista);

$ node lista.js
[ 'arroz', 'feijão', 'café' ]
true

O push (veja push, pop, shift e unshift) foi feito em lista, mas compras ganhou o café, porque é o mesmo array. Os jeitos de copiar um array estão em Copiando Arrays.

produto.preco = 0.9;

Se quiser proibir mudanças: Object.freeze

Object.freeze(obj) ("congelar") trava as propriedades do objeto. Num arquivo comum, a tentativa de mudar é ignorada em silêncio:

const config = Object.freeze({ moeda: "R$", taxa: 0.05 });
config.taxa = 0.5;
console.log(config.taxa);
console.log(Object.isFrozen(config));

$ node congelar2.js
0.05
true

Nos módulos e em arquivos que começam com "use strict"; (o "modo estrito"), a mesma linha vira erro: TypeError: Cannot assign to read only property 'taxa' of object '#<Object>' ("não é possível atribuir à propriedade somente-leitura taxa"). O congelamento vale só para o primeiro nível: um objeto dentro de config continuaria mudável.

7. Copiando de verdade

Cópia rasa: { ...obj }

Os três pontinhos dentro de { } (o spread, "espalhar"; aula Spread e Rest) criam um objeto novo e copiam para ele cada propriedade do original:

const ana = { nome: "Ana", idade: 30 };
const copia = { ...ana };
copia.idade = 31;
console.log(ana);
console.log(copia);
console.log(ana === copia);

$ node copia.js
{ nome: 'Ana', idade: 30 }
{ nome: 'Ana', idade: 31 }
false

Agora há dois pares de chaves, então dois objetos: o original ficou com 30. O jeito mais antigo de fazer a mesma cópia é Object.assign({}, ana), que você vai encontrar em código antigo (no lab, console.log(ana.idade, copia.idade) mostrou 30 31, igual).

Por que "rasa"? Porque ela copia só o primeiro nível. Se uma propriedade guarda outro objeto, o que é copiado é o endereço desse objeto de dentro:

const ana = { nome: "Ana", endereco: { cidade: "Recife" } };
const copia = { ...ana };
copia.endereco.cidade = "Natal";
console.log(ana.endereco.cidade);
console.log(ana.endereco === copia.endereco);

$ node rasa.js
Natal     « o endereço da Ana mudou também!
true      « as duas cópias dividem o mesmo objeto endereco

Cópia profunda: structuredClone

structuredClone(obj) ("clone estruturado") copia o objeto e tudo o que está dentro dele, em todos os níveis. Funciona no Node e nos navegadores atuais:

const ana = { nome: "Ana", endereco: { cidade: "Recife" } };
const copia = structuredClone(ana);
copia.endereco.cidade = "Natal";
console.log(ana.endereco.cidade);
console.log(copia.endereco.cidade);
console.log(ana.endereco === copia.endereco);

$ node profunda.js
Recife
Natal
false

Quando dá errado

Comparou dois objetos com === esperando true 
const pedido1 = { produto: "Pão", quantidade: 10 };
const pedido2 = { produto: "Pão", quantidade: 10 };
if (pedido1 === pedido2) {
  console.log("Pedidos iguais");
} else {
  console.log("Pedidos diferentes");
}
console.log(JSON.stringify(pedido1) === JSON.stringify(pedido2));

$ node igual.js
Pedidos diferentes
true

Não há mensagem de erro, e é isso que torna o engano perigoso: o programa só dá a resposta errada. São dois objetos (dois pares de chaves), então === dá false. Como consertar: compare as propriedades (pedido1.produto === pedido2.produto && pedido1.quantidade === pedido2.quantidade) ou, para objetos simples com as propriedades na mesma ordem, os textos do JSON.stringify (última linha: true).

Mudou a "cópia" e estragou o original

É o programa da seção 2: const outra = ana; não copia nada. Também acontece com a cópia rasa quando há objetos dentro de objetos (seção 7). Como consertar: { ...ana } para um nível; structuredClone(ana) quando há objetos dentro.

Reatribuiu uma variável const

É o TypeError: Assignment to constant variable. da seção 6. Como consertar: se você só quer mudar uma propriedade, mude a propriedade (produto.preco = 15); se precisa mesmo trocar o objeto inteiro, declare com let.

A mensagem DataCloneError: saudar() { … } could not be cloned quer dizer "erro de clonagem: saudar não pôde ser clonado": structuredClone copia dados (números, textos, arrays, objetos, datas…), mas não funções (os métodos, veja Métodos e this). Missão final: o estoque da filial

Missão: a lojinha da Ana abriu uma filial e quer começar com o mesmo estoque da matriz, mas cada uma vendendo o seu. O programa abaixo estraga o estoque da matriz. Conserte a linha da cópia para sair Matriz: 20 e Filial: 5. (Dica: o estoque é um objeto dentro de outro.)

filial.nome = "Filial";
filial.estoque.pao = 5;
console.log(`${matriz.nome}: ${matriz.estoque.pao}`);
console.log(`${filial.nome}: ${filial.estoque.pao}`);

const matriz = { nome: "Matriz", estoque: { pao: 20 } };
const filial = structuredClone(matriz);
filial.nome = "Filial";
filial.estoque.pao = 5;
console.log(`${matriz.nome}: ${matriz.estoque.pao}`);
console.log(`${filial.nome}: ${filial.estoque.pao}`);

Resumo

  • Primitivos (números, textos, booleanos…) são copiados; objetos e arrays são acessados por referência: b = a copia só o endereço.
  • Cada { } ou [ ] escrito cria um objeto novo; conte-os para saber quantos objetos existem.
  • === entre objetos pergunta "é o mesmo objeto?", não "têm o mesmo conteúdo?".
  • Uma função que recebe um objeto pode mudá-lo; trocar o parâmetro inteiro (p = { … }) não afeta quem chamou.
  • const impede trocar o endereço, não o conteúdo. Para travar o conteúdo, Object.freeze.
  • Cópia rasa: { ...obj }. Cópia profunda: structuredClone(obj) (sem funções).
