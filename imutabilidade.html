JavaScript Object.freeze e Imutabilidade

Na padaria do bairro, a tabela de preços fica pregada na parede, atrás de um vidro. Qualquer funcionário pode ler os preços, mas ninguém consegue mudar um número com a caneta. No JavaScript, um objeto comum é como uma folha solta no balcão: qualquer parte do programa pode riscar e reescrever. Às vezes é isso mesmo que você quer; outras vezes, um valor mudado "sem querer" vira um defeito difícil de achar. Esta aula mostra como pôr o objeto atrás do vidro: imutável quer dizer "que não pode ser mudado".

Você vai aprender
  • Por que o const não impede que um objeto mude por dentro.
  • Como congelar um objeto com Object.freeze e conferir com Object.isFrozen.
  • O que acontece quando alguém tenta mudar um objeto congelado: o silêncio do modo normal e o TypeError do modo estrito.
  • Que o congelamento é raso (os objetos de dentro continuam mudando) e como congelar tudo.
  • Os primos do freeze: Object.seal e Object.preventExtensions.
  • O jeito moderno de "mudar" sem estragar o original: criar uma cópia nova com ..., toSorted e with.

A ideia: a etiqueta e a caixa

Lembre da aula Objetos são Referências: a variável não guarda o objeto, guarda o caminho até ele, como uma etiqueta presa numa caixa. Isso explica tudo nesta aula:

  • O const cola a etiqueta na caixa para sempre: a variável não pode apontar para outra caixa. Mas a caixa continua aberta: dá para tirar e pôr coisas dentro dela.
  • O Object.freeze ("congelar") lacra a caixa: ninguém tira, põe ou troca o que está dentro, por mais etiquetas que apontem para ela.

São duas proteções diferentes, e muita gente confunde. Vamos ver cada uma.

1. O const não congela o objeto

const produto = { nome: "Pão francês", preco: 0.75 };
produto.preco = 0.9;

console.log(produto);

O silêncio e o modo estrito

Ignorar em silêncio é perigoso: você acha que mudou o preço, o programa segue em frente e o defeito só aparece lá na frente. Isso acontece porque um arquivo .js comum roda, por padrão, no modo "relaxado" do JavaScript. No modo estrito ("use strict"), a mesma tentativa vira um erro de verdade:

Onde o modo estrito já vem ligado

Você não precisa escrever "use strict" dentro de classes nem em módulos (arquivos com import/export, ou .mjs): lá o modo estrito é automático. Em código moderno, então, mexer num objeto congelado quase sempre dá erro, e isso é bom: o defeito aparece na hora, na linha certa.

3. Arrays congelados

Um array também é um objeto, então também pode ser congelado. A lista de compras da Ana, depois de fechada, não deveria mudar:

lista[0] = "bolo";
console.log(lista);

lista.push("açúcar");

4. O congelamento é raso

O Object.freeze lacra só a caixa de fora. Se dentro dela houver outra caixa (um objeto ou um array), essa de dentro continua aberta. Os programadores dizem que o congelamento é raso (em inglês, shallow):

const pedido = Object.freeze({
  cliente: "Ana",
  itens: ["pão", "leite"],
});

pedido.cliente = "Bia";
pedido.itens.push("café");

console.log(pedido);
console.log(Object.isFrozen(pedido));
console.log(Object.isFrozen(pedido.itens));

$ node raso.js
{ cliente: 'Ana', itens: [ 'pão', 'leite', 'café' ] }
true
false

O cliente não mudou (é uma propriedade da caixa de fora, que está lacrada). Mas o café entrou na lista! A propriedade itens continua apontando para o mesmo array (isso o freeze garante), só que o array em si não foi congelado: Object.isFrozen(pedido.itens) deu false.

Congelando tudo, camada por camada

O JavaScript não tem um "congelar fundo" pronto. A solução é uma função que congela cada objeto de dentro antes de congelar o de fora, usando recursão (a função chamando a si mesma):

function congelarTudo(objeto) {
  for (const valor of Object.values(objeto)) {
    if (typeof valor === "object" && valor !== null) {
      congelarTudo(valor);
    }
  }
  return Object.freeze(objeto);
}

const pedido = congelarTudo({
  cliente: "Ana",
  itens: ["pão", "leite"],
  entrega: { rua: "Rua das Flores", numero: 12 },
});

pedido.itens[0] = "bolo";
pedido.entrega.numero = 99;

console.log(pedido);
console.log(Object.isFrozen(pedido.itens), Object.isFrozen(pedido.entrega));

"Esse valor é uma caixa?". O teste do null é necessário porque typeof null também dá "object" (uma esquisitice antiga da linguagem; veja typeof).

Se for uma caixa, congela tudo o que tem dentro dela primeiro.

5. Os primos do freeze: seal e preventExtensions

Existem dois "lacres" mais fracos. O Object.seal ("selar") deixa mudar os valores que já existem, mas proíbe criar e apagar propriedades. É útil quando o formato do objeto é fixo mas os valores mudam, como o placar de um jogo:

const placar = Object.seal({ casa: 0, visitante: 0 });

placar.casa = 2;
placar.prorrogacao = true;
delete placar.visitante;

console.log(placar);
console.log(Object.isSealed(placar), Object.isFrozen(placar));

$ node selar.js
{ casa: 2, visitante: 0 }
true false

O casa mudou para 2; a prorrogacao não entrou e o visitante não saiu (de novo em silêncio, porque não há "use strict"). E o Object.preventExtensions ("impedir extensões") é o mais fraco dos três: só proíbe criar propriedades novas.

LacreMudar valorCriar propriedadeApagar propriedadePara conferir
Object.preventExtensions(obj)PodeNãoPodeObject.isExtensible(obj) (dá false)
Object.seal(obj)PodeNãoNãoObject.isSealed(obj)
Object.freeze(obj)NãoNãoNãoObject.isFrozen(obj)

Os três são para sempre: não existe "descongelar". Para ter de novo um objeto que muda, você faz uma cópia, que é o assunto da próxima seção.

6. Mudar sem estragar: criar um objeto novo

Se o preço do pão subiu, como atualizar um objeto congelado? Você não muda o objeto: cria um novo, com o valor novo, e deixa o antigo como estava. Essa é a ideia de imutabilidade que você vai encontrar em muito código moderno (e em bibliotecas como o React). O spread (...) faz isso numa linha:

const precoAntigo = Object.freeze({ nome: "Pão francês", preco: 0.75 });
const precoNovo = { ...precoAntigo, preco: 0.9 };

console.log(precoAntigo);
console.log(precoNovo);
console.log(Object.isFrozen(precoNovo));

$ node copia-nova.js
{ nome: 'Pão francês', preco: 0.75 }
{ nome: 'Pão francês', preco: 0.9 }
false

O { ...precoAntigo, preco: 0.9 } quer dizer: "um objeto novo com tudo o que o precoAntigo tem, e o preco trocado por 0.9". A cópia nasce descongelada (o freeze não é copiado). E o original fica intacto: dá para comparar o antes e o depois, desfazer, guardar um histórico.

Arrays: os métodos que devolvem uma cópia ES2023

Para arrays, o JavaScript ganhou em 2023 versões "que não estragam" dos métodos que mudam o array:

console.log(notas.toSorted((a, b) => a - b));
console.log(notas.toReversed());

Quando dá errado

"Usei const, mas o objeto mudou!"

Não é erro do JavaScript: o const protege a variável, não o conteúdo (seção 1). Se o conteúdo não pode mudar, acrescente Object.freeze.

Com delete produto.nome no lugar, sai TypeError: Cannot delete property 'nome' of #<Object> ("não é possível apagar a propriedade nome"). Como consertar: se o objeto precisa mesmo mudar, não o congele, ou crie uma cópia nova (seção 6).

Mudou um objeto congelado sem "use strict": nada acontece

O pior caso, porque não há mensagem nenhuma: o valor simplesmente não muda (seção 2). Se um valor "teima" em não mudar, confira com console.log(Object.isFrozen(obj)). Melhor ainda: use o modo estrito (ou módulos e classes, onde ele é automático), para o erro aparecer na linha certa.

push num array congelado

TypeError: Cannot add property 3, object is not extensible, mesmo sem "use strict" (seção 3). Com pop sai Cannot delete property '2' of [object Array], e com sort, Cannot assign to read only property '0' of object '[object Array]'. Como consertar: use a versão que devolve uma cópia: [...lista, x], lista.slice(0, -1), lista.toSorted().

"Congelei, mas a lista de dentro mudou!"

O congelamento é raso (seção 4). Use a função congelarTudo, ou congele também o objeto de dentro: Object.freeze(pedido.itens).

Achou que o freeze fazia uma cópia 
const original = { nome: "Sonho", preco: 4.5 };

Resumo

  • O const impede trocar a variável inteira, mas não impede mudar o objeto por dentro.
  • Object.freeze(obj) lacra o objeto: não muda, não ganha e não perde propriedades. Ele devolve o mesmo objeto, e não tem volta.
  • Fora do modo estrito, as tentativas de mudar um objeto congelado são ignoradas em silêncio; no modo estrito (e em módulos e classes) viram TypeError. Métodos como push dão erro sempre.
  • O congelamento é raso: objetos e arrays de dentro continuam mudando, a não ser que você congele cada um (função congelarTudo).
  • Object.seal deixa mudar os valores, mas não criar nem apagar; Object.preventExtensions só proíbe criar.
  • Para "mudar" um valor imutável, crie um novo: { ...obj, campo: novo }, [...lista, x], toSorted, toReversed, with.
