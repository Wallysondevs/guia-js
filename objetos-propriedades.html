JavaScript: Propriedades (ler, mudar, apagar)

Na aula Objetos você criou fichas com { chave: valor } e leu valores com o ponto. Um objeto, porém, não é uma ficha impressa: é uma ficha a lápis. Durante o programa, os valores mudam (o preço subiu, o estoque baixou), propriedades novas aparecem (a cor do produto) e outras somem (a promoção acabou). Esta aula mostra as quatro operações com propriedades, ler, mudar, acrescentar e apagar, e como perguntar se uma propriedade existe.

Você vai aprender
  • Os dois jeitos de ler: o ponto (produto.preco) e os colchetes (produto["preco"]).
  • Como ler uma propriedade cujo nome está numa variável: produto[campo].
  • Como mudar um valor e acrescentar uma propriedade nova com =.
  • Como apagar uma propriedade com delete, e a diferença para "pôr undefined".
  • Como perguntar se uma propriedade existe: in e Object.hasOwn.
  • Como dar um valor padrão para o que falta (??) e como criar uma chave calculada ({ [campo]: valor }).
  • Os erros reais: ler ou escrever em undefined, trocar o objeto de um const, o hífen sem colchetes.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js. Você pode rodar cada um no editor do guia.

A ideia: a ficha do produto, a lápis

Na papelaria da Ana, cada produto tem uma ficha na gaveta. Ao longo do dia, ela:

  1. Lê a ficha: "quanto custa o caderno?"
  2. Muda um valor: apaga o preço antigo e escreve o novo.
  3. Acrescenta uma linha que não existia: "cor: azul".
  4. Apaga uma linha inteira: a promoção acabou.
  5. Confere se uma linha existe antes de usá-la.

Cada operação dessas tem um jeito de escrever no JavaScript.

1. Ler: o ponto e os colchetes

const produto = { nome: "caderno", preco: 18, "em estoque": 40 };
console.log(produto.nome);
console.log(produto["nome"]);
console.log(produto["em estoque"]);

$ node ler.js
caderno
caderno
40
produto.nome
O ponto: o jeito mais comum e mais curto. Depois do ponto vem o nome da chave, escrito como um nome de variável.
produto["nome"]
Os colchetes, com a chave como texto (entre aspas). Faz o mesmo que o ponto.
produto["em estoque"]
Para chaves com espaço, hífen ou outros caracteres especiais, só os colchetes funcionam: produto.em estoque seria um erro de sintaxe.

A chave numa variável

A grande vantagem dos colchetes: dentro deles pode ir qualquer expressão, inclusive uma variável com o nome da chave. É assim que um programa lê uma propriedade que só vai saber qual é na hora de rodar (a coluna que o usuário escolheu, o campo de um formulário):

const produto = { nome: "caderno", preco: 18, estoque: 40 };
const campo = "preco";
console.log(produto[campo]);
console.log(produto.campo);
const campos = ["nome", "preco", "estoque"];
for (const c of campos) {
  console.log(`${c} = ${produto[c]}`);
}

$ node dinamica.js
18
undefined
nome = caderno
preco = 18
estoque = 40
produto[campo]
Sem aspas: o JavaScript primeiro olha o valor da variável campo ("preco") e depois lê produto["preco"]. Resultado: 18.
produto.campo → undefined
Com o ponto, campo é o nome literal da chave: o JavaScript procura uma propriedade chamada campo, que não existe. O ponto nunca olha variáveis.
produto[c] no laço
A cada volta, c vale uma chave diferente. Um laço só lê as três propriedades.
EscritaProcura a chave chamada…
produto.campo"campo", literalmente
produto["campo"]"campo", literalmente (mesma coisa)
produto[campo]O que estiver dentro da variável campo

Missão: o programa deveria mostrar o campo escolhido, mas mostra preco: undefined. Conserte a leitura para usar o valor da variável campo, para aparecer preco: 18. Depois, troque o campo para "estoque".

const produto = { nome: "caderno", preco: 18, estoque: 40 };
const campo = "preco";
console.log(`${campo}: ${produto.campo}`);

const produto = { nome: "caderno", preco: 18, estoque: 40 };
const campo = "preco";
console.log(`${campo}: ${produto[campo]}`);

2. Mudar e acrescentar

Para mudar uma propriedade, ponha a leitura do lado esquerdo de um =, como numa variável. Se a propriedade ainda não existir, ela é criada; não há um comando separado para acrescentar:

const produto = { nome: "caderno", preco: 18, estoque: 40 };
produto.preco = 20;
produto.estoque -= 3;
produto["nome"] = "caderno universitário";
produto.cor = "azul";
console.log(produto);

$ node mudar.js
{ nome: 'caderno universitário', preco: 20, estoque: 37, cor: 'azul' }
produto.preco = 20
A propriedade preco existia (18) e passou a valer 20.
produto.estoque -= 3
Os atalhos +=, -=, ++… funcionam em propriedades como em variáveis (aula Atribuição): vendeu 3, o estoque foi de 40 para 37.
produto["nome"] = …
Os colchetes também servem para escrever.
produto.cor = "azul"
Não existia cor: a propriedade foi criada, no fim do objeto.
E o const?

O produto é const, e mesmo assim tudo mudou. O const protege a variável (ela vai apontar sempre para este objeto), não o conteúdo do objeto. Trocar o objeto inteiro, esse sim, dá erro (veja Quando dá errado). Para um objeto que não pode mudar de jeito nenhum, existe o Object.freeze (aula Object.freeze e Imutabilidade).

3. Apagar: delete

const produto = { nome: "caderno", preco: 18, promocao: true };
console.log(delete produto.promocao);
console.log(produto);
console.log(produto.promocao);
console.log(delete produto.naoExiste);

$ node apagar.js
true
{ nome: 'caderno', preco: 18 }
undefined
true
delete produto.promocao
O operador delete ("apagar") tira a propriedade inteira do objeto: a chave e o valor. Ele devolve true quando deu certo.
{ nome: 'caderno', preco: 18 }
A promoção sumiu da ficha.
produto.promocao → undefined
Ler uma propriedade apagada é como ler uma que nunca existiu.
delete produto.naoExiste → true
Apagar o que não existe não dá erro: o delete devolve true do mesmo jeito.

delete × pôr undefined

Parece a mesma coisa, mas não é:

const a = { nome: "caderno", promocao: true };
const b = { nome: "caderno", promocao: true };
a.promocao = undefined;
delete b.promocao;
console.log(a);
console.log(b);
console.log("promocao" in a, "promocao" in b);

$ node undef.js
{ nome: 'caderno', promocao: undefined }
{ nome: 'caderno' }
true false

Em a, a linha da promoção continua na ficha, só que em branco; em b, a linha foi arrancada. A diferença aparece quando você percorre as chaves do objeto (aula Percorrendo Objetos) ou o transforma em JSON. Para tirar uma propriedade, use delete.

4. A propriedade existe?

A borracha está com estoque zero. Repare no que acontece com cada jeito de perguntar:

const produto = { nome: "borracha", preco: 2, estoque: 0 };
console.log("estoque" in produto);
console.log("cor" in produto);
console.log(Object.hasOwn(produto, "estoque"));
console.log(Object.hasOwn(produto, "cor"));
if (produto.estoque) {
  console.log("Tem estoque");
} else {
  console.log("Sem estoque (ou sem o campo?)");
}
console.log(produto.estoque !== undefined);

$ node existe.js
true
false
true
false
Sem estoque (ou sem o campo?)
true
"estoque" in produto
O operador in ("em"): "existe a chave estoque em produto?". Responde true/false e não liga para o valor: o estoque é 0, mas a chave existe.
Object.hasOwn(produto, "estoque")
"O objeto tem a própria propriedade estoque?" ES2022. Quase sempre dá o mesmo que o in; a diferença aparece com propriedades herdadas (aula Protótipos). É o jeito mais seguro e mais recomendado hoje.
if (produto.estoque)
A armadilha: o if testa o valor, e 0 é falsy (aula Truthy e Falsy). O programa não sabe se o campo está zerado ou se não existe. O mesmo acontece com "", false e null.
produto.estoque !== undefined
Funciona na maioria dos casos, mas erra se alguém guardou undefined de propósito (como o objeto a da seção 3).

Regra prática: para perguntar "o campo existe?", use Object.hasOwn(obj, "chave") (ou "chave" in obj). Para perguntar "o valor serve?", teste o valor.

Um valor padrão para o que falta: ??

const produto = { nome: "borracha", preco: 2, estoque: 0 };
console.log(produto.cor ?? "sem cor");
console.log(produto.estoque ?? "não informado");
console.log(produto.estoque || "não informado");

$ node padrao.js
sem cor
0
não informado

O ?? ("se faltar, use…") troca o valor só quando ele é undefined ou null: a cor que não existe virou "sem cor", e o estoque 0 continuou 0. O ||, mais antigo, troca qualquer valor falsy, e escondeu o zero. Os detalhes estão na aula ?. e ??.

5. Chave calculada na criação: { [campo]: valor }

Os colchetes também funcionam dentro do literal, para a chave sair de uma variável:

const campo = "telefone";
const valor = "(81) 90000-0000";
const contato = { nome: "Bia", [campo]: valor };
console.log(contato);

$ node computada.js
{ nome: 'Bia', telefone: '(81) 90000-0000' }

[campo]: valor quer dizer "uma propriedade cuja chave é o valor de campo". Sem os colchetes, a chave se chamaria campo, literalmente. O nome técnico é propriedade computada (calculada).

Missão final: registrando a venda

Missão: a Ana vendeu 3 cadernos e a promoção acabou. Antes do console.log, escreva três linhas: diminua 3 do estoque, crie a propriedade vendidos com 3 e apague a propriedade promocao. O objeto deve terminar com estoque: 37, vendidos: 3 e sem promocao.

const produto = { nome: "caderno", estoque: 40, promocao: true };
// escreva as três linhas aqui
console.log(produto);

const produto = { nome: "caderno", estoque: 40, promocao: true };
produto.estoque -= 3;
produto.vendidos = 3;
delete produto.promocao;
console.log(produto);

No lab, a solução mostrou { nome: 'caderno', estoque: 37, vendidos: 3 }.

Resumo

  • Leia com o ponto (obj.chave) ou com colchetes (obj["chave"]). Para chaves com espaço/hífen ou guardadas numa variável, só colchetes: obj[campo].
  • obj.chave = valor muda a propriedade, ou a cria se ela não existia. Funciona mesmo com const; o que o const proíbe é trocar o objeto inteiro.
  • delete obj.chave apaga a propriedade inteira; pôr undefined deixa a chave lá, vazia.
  • Para saber se existe: Object.hasOwn(obj, "chave") ou "chave" in obj. Não use if (obj.chave), que confunde 0 e "" com "não existe".
  • obj.chave ?? padrao dá um valor padrão só quando falta (undefined/null).
  • Ler ou escrever propriedades de undefined quebra o programa (Cannot read/set properties of undefined): o culpado é o que vem antes do ponto.
