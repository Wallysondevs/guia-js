JavaScript Recursão

Uma função pode chamar outras funções: você já fez isso muitas vezes, chamando o console.log de dentro das suas. Ela também pode chamar a si mesma. Isso se chama recursão (do latim recurrere, "voltar a correr"), e a função que faz isso é uma função recursiva. Parece truque de mágica, mas é só um jeito de resolver um problema grande resolvendo um pedaço dele e deixando o resto para "uma cópia de si mesma". É o jeito natural de lidar com coisas que têm coisas iguais dentro: pastas dentro de pastas, comentários com respostas dentro de respostas, categorias com subcategorias.

Você vai aprender
  • O que é uma função recursiva e as duas peças que ela sempre tem: o caso base e o passo recursivo.
  • Como fazer uma contagem regressiva e um fatorial com recursão.
  • O que é a pilha de chamadas e como o JavaScript "volta" de cada chamada.
  • Como somar uma lista e percorrer pastas dentro de pastas, onde a recursão brilha.
  • Quando usar recursão e quando um laço (for) é melhor.
  • Os erros reais: RangeError: Maximum call stack size exceeded (sem caso base, ou fundo demais) e o return esquecido.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa). Você pode rodar cada um no editor do guia. Antes desta aula, é bom conhecer Funções, Parâmetros e return.

A ideia: "quantas pessoas tem na sua frente?"

A Ana está numa fila enorme da padaria e quer saber em que posição está. Ela não enxerga o começo da fila. Então ela cutuca a pessoa da frente e pergunta: "Em que posição você está?". Essa pessoa também não sabe, então faz a mesma pergunta para quem está na frente dela. E assim por diante:

  1. A pergunta vai passando para a frente, cada pessoa fazendo a mesma pergunta à próxima.
  2. Até chegar na primeira pessoa da fila. Ela não precisa perguntar a ninguém: ela sabe que é a 1ª. Esse é o caso base: a resposta que sai direto, sem perguntar de novo.
  3. A resposta volta para trás: "sou a 1ª", então a de trás diz "sou a 2ª", a outra "sou a 3ª"… cada uma soma 1 à resposta que recebeu.
  4. Até a resposta chegar de volta na Ana.

Toda recursão funciona assim, e tem sempre duas peças:

  • o caso base: a situação tão simples que a resposta sai direto, sem chamar a função de novo (a primeira pessoa da fila). Sem ele, a pergunta passaria para a frente para sempre;
  • o passo recursivo: a função chama a si mesma com um problema um pouco menor (uma pessoa mais perto do começo), e usa a resposta para montar a sua.

2. Recursão que devolve um valor: o fatorial

O fatorial de um número (escrito 5! na matemática) é a multiplicação dele por todos os inteiros menores até 1: 5! = 5 × 4 × 3 × 2 × 1 = 120. É o número de jeitos de enfileirar 5 pessoas. Repare numa coisa: 5! = 5 × 4!. O fatorial de 5 é 5 vezes o fatorial de 4; o de 4 é 4 vezes o de 3… e o de 1 é 1. Isso é uma recursão pronta:

function fatorial(n) {
  if (n <= 1) {
    return 1;
  }
  return n * fatorial(n - 1);
}

console.log(fatorial(5));
console.log(fatorial(1));
console.log(fatorial(10));
if (n <= 1) { return 1; }
O caso base: o fatorial de 1 é 1 (e o de 0 também, pela regra da matemática). Aqui a função devolve a resposta direto.
return n * fatorial(n - 1);
O passo recursivo: "o fatorial de n é n vezes o fatorial de n - 1". Para calcular a multiplicação, o JavaScript precisa primeiro do valor de fatorial(n - 1), então ele espera essa chamada terminar.
$ node fatorial.js

1
3628800

A conta de fatorial(5) se desdobra assim, descendo até o caso base e depois voltando com os resultados:

fatorial(5) = 5 * fatorial(4)
            = 5 * (4 * fatorial(3))
            = 5 * (4 * (3 * fatorial(2)))
            = 5 * (4 * (3 * (2 * fatorial(1))))
            = 5 * (4 * (3 * (2 * 1)))       // caso base: fatorial(1) devolve 1
            = 5 * (4 * (3 * 2))
            = 5 * (4 * 6)
            = 5 * 24
            = 120

3. A pilha de chamadas: descer e voltar

Quando uma função chama outra, o JavaScript anota "onde eu estava" e vai cuidar da nova chamada. Quando ela termina, ele volta para a anotação e continua de onde parou. Essas anotações ficam empilhadas, uma em cima da outra, como uma pilha de pratos: a última que entrou é a primeira que sai. Essa pilha se chama pilha de chamadas (em inglês, call stack).

Para ver a pilha funcionando, a Ana colocou mensagens no fatorial, com um recuo (recuo) que aumenta 2 espaços a cada chamada mais funda:

function fatorial(n, recuo = "") {
  console.log(`${recuo}entrou em fatorial(${n})`);
  if (n <= 1) {
    console.log(`${recuo}caso base: devolve 1`);
    return 1;
  }
  const resultado = n * fatorial(n - 1, recuo + "  ");
  console.log(`${recuo}fatorial(${n}) devolve ${resultado}`);
  return resultado;
}

fatorial(4);

$ node pilha.js

  entrou em fatorial(3)

      entrou em fatorial(1)
      caso base: devolve 1

  fatorial(3) devolve 6
fatorial(4) devolve 24

Leia a saída como uma escada:

  • Descendo (as linhas "entrou em"): cada chamada para no meio da conta n * fatorial(n - 1) e espera. Nenhuma multiplicação foi feita ainda. A pilha tem 4 chamadas esperando.
  • O fundo: fatorial(1) é o caso base e devolve 1 sem chamar ninguém.
  • Subindo (as linhas "devolve"): cada chamada recebe a resposta da de baixo, termina a sua multiplicação e devolve para a de cima. A última a entrar foi a primeira a sair.

O parâmetro recuo = "" tem um valor padrão (veja Parâmetros Padrão): quem chama de fora não precisa passar nada, e cada chamada recursiva passa o recuo com mais 2 espaços.

A pilha tem tamanho limitado

Cada chamada que espera ocupa um pouco de memória na pilha. Se a recursão descer fundo demais (ou nunca parar), a pilha enche e o programa quebra com RangeError: Maximum call stack size exceeded ("tamanho máximo da pilha de chamadas excedido"). Você vai ver esse erro em Quando dá errado.

4. Recursão numa lista: somar as compras

Uma lista também pode ser pensada de forma recursiva: "a soma da lista é o primeiro item mais a soma do resto". E a soma de uma lista vazia é 0 (o caso base):

function somar(precos) {
  if (precos.length === 0) {
    return 0;
  }
  const [primeiro, ...resto] = precos;
  return primeiro + somar(resto);
}

console.log(somar([4.5, 12, 3.5]));
console.log(somar([]));
if (precos.length === 0) { return 0; }
O caso base: lista vazia, soma zero.
const [primeiro, ...resto] = precos;
Separa a lista em duas partes: o primeiro item e um array novo com o resto (veja Desestruturação e Spread e Rest). Para [4.5, 12, 3.5], primeiro é 4.5 e resto é [12, 3.5].
return primeiro + somar(resto);
O passo recursivo: o resto é uma lista um item menor, então cada chamada se aproxima da lista vazia.
$ node soma-lista.js
20
0

Funciona, mas sejamos honestos: para somar uma lista simples, um for … of ou o reduce são mais curtos e mais rápidos. Este exemplo serve para treinar o jeito recursivo de pensar. O próximo mostra onde a recursão é a ferramenta certa.

5. Onde a recursão brilha: pastas dentro de pastas

A pasta Documentos da Ana tem arquivos e outras pastas; essas pastas também têm arquivos e outras pastas, e assim por diante, sem um limite fixo. Num programa, isso vira um objeto com uma lista de subpastas, e cada subpasta tem o mesmo formato da pasta de cima:

const documentos = {
  nome: "Documentos",
  arquivos: ["curriculo.pdf", "rg.jpg"],
  pastas: [
    {
      nome: "Escola",
      arquivos: ["notas.txt"],
      pastas: [
        { nome: "2025", arquivos: ["boletim.pdf", "foto.png"], pastas: [] },
        { nome: "2026", arquivos: ["matricula.pdf"], pastas: [] }
      ]
    },
    { nome: "Receitas", arquivos: ["bolo.txt", "pao.txt"], pastas: [] }
  ]
};

function contarArquivos(pasta) {
  let total = pasta.arquivos.length;
  for (const subpasta of pasta.pastas) {
    total = total + contarArquivos(subpasta);
  }
  return total;
}

console.log(`Arquivos em ${documentos.nome}: ${contarArquivos(documentos)}`);

Onde está o caso base?
Ele está escondido: uma pasta com pastas: [] (sem subpastas) não entra no for, então não chama ninguém e devolve só os seus arquivos. É ali que a recursão para.

Com um laço comum, você teria de escrever um for dentro de um for dentro de um for… e um nível a mais na pasta quebraria o programa. A recursão desce quantos níveis houver. O mesmo jeito serve para mostrar a árvore de pastas, com um recuo a cada nível:

function mostrar(pasta, recuo = "") {
  console.log(`${recuo}${pasta.nome}/`);
  for (const arquivo of pasta.arquivos) {
    console.log(`${recuo}  ${arquivo}`);
  }
  for (const subpasta of pasta.pastas) {
    mostrar(subpasta, recuo + "  ");
  }
}

Formas diferentes de fazer a mesma coisa

Quase tudo que a recursão faz, um laço também faz. O fatorial com for (veja for):

function fatorial(n) {
  let resultado = 1;
  for (let i = 2; i <= n; i++) {
    resultado = resultado * i;
  }
  return resultado;
}

console.log(fatorial(5));

$ node fatorial-for.js
120

E a recursão também pode ser escrita como arrow function guardada numa const, com o caso base no ternário. A função consegue chamar a si mesma pelo nome da constante porque, quando ela roda, a constante já existe:

const fatorial = (n) => (n <= 1 ? 1 : n * fatorial(n - 1));

console.log(fatorial(5));
console.log(fatorial(20));
console.log(fatorial(25));

Missão final: a potência

Missão: 2 elevado a 10 é 2 multiplicado por ele mesmo 10 vezes. Pense recursivamente: "base elevado a expoente é base vezes base elevado a expoente - 1", e qualquer número elevado a 0 é 1. Escreva a função potencia com um caso base (expoente === 0) e um passo recursivo.

function potencia(base, expoente) {
  // caso base: se o expoente for 0, devolva 1
  // passo recursivo: devolva base vezes potencia(base, expoente - 1)
}

console.log(`2 elevado a 10 = ${potencia(2, 10)}`);

function potencia(base, expoente) {
  if (expoente === 0) {
    return 1;
  }
  return base * potencia(base, expoente - 1);
}

console.log(`2 elevado a 10 = ${potencia(2, 10)}`);

No lab, a solução mostrou 2 elevado a 10 = 1024. (No dia a dia, a potência já vem pronta: 2 ** 10 ou Math.pow(2, 10), veja Math.)

Resumo

  • Uma função recursiva chama a si mesma. Ela sempre tem um caso base (a resposta sai direto) e um passo recursivo (chama a si mesma com um problema menor).
  • Cada chamada tem as suas próprias variáveis. As chamadas que esperam ficam na pilha de chamadas: a recursão desce até o caso base e depois volta, da última chamada para a primeira.
  • No passo recursivo que calcula algo, não esqueça o return: sem ele, sai undefined.
  • Sem caso base (ou com um caso base que nunca é alcançado), a pilha enche: RangeError: Maximum call stack size exceeded. O mesmo erro aparece quando a recursão é funda demais (dezenas de milhares de níveis).
  • A recursão brilha em estruturas com coisas iguais dentro (pastas, menus, comentários). Para repetir muitas vezes ou somar listas, prefira um laço ou os métodos de array.
