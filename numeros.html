JavaScript Números

Preço do pão, quantidade de itens, nota da prova, temperatura de hoje: números aparecem em quase todo programa. No JavaScript eles são do tipo number (em inglês, "número"), e um tipo só serve para todos: inteiros, decimais, negativos. Nesta aula você vai ver como escrever números, como o Node os mostra, e as pegadinhas que pegam quem está acostumado a escrever números "à brasileira".

Você vai aprender
  • Que inteiros e decimais são o mesmo tipo, e que a casa decimal usa ponto.
  • As quatro contas, e por que 7 / 2 dá 3.5.
  • Como escrever números grandes de forma legível: 1_000_000 e 1e6.
  • As outras bases: 0xff, 0b1010.
  • O maior inteiro seguro e o que acontece depois dele.
  • As pegadinhas reais: a vírgula decimal, o 1.500 que vira 1,5 e o CEP que começa com zero.

Todos os programas desta aula rodaram no Node.js v24.22.0 da máquina da Ana (ana@notebook), com node arquivo.js.

A ideia: a calculadora da padaria

A calculadora do caixa da padaria não tem um botão para "inteiro" e outro para "decimal": você digita 6 ou 0.75 do mesmo jeito, e ela faz a conta. E ela usa ponto na tecla das casas decimais, como as calculadoras do mundo inteiro. O number do JavaScript é essa calculadora: um tipo só para todo número, com ponto decimal.

console.log(typeof paes, typeof preco, typeof temperatura);

6.0 e 6 são o mesmo número (a comparação 6 === 6.0 deu true), e o Node mostra 6. O zero final de 6.50 some; .5 vira 0.5. Ou seja: o número não "lembra" como foi escrito. Se você precisa mostrar 6.50 com duas casas (um preço, por exemplo), isso é formatação, e se faz na hora de mostrar (aula Formatando Números). Para saber se um número é inteiro, existe o Number.isInteger(n) ("é inteiro?").

Missão: a Ana ganha mil e quinhentos reais por mês e quer saber quanto ganha por ano. Mas o programa mostra Por ano: 18. O número foi escrito "à brasileira". Conserte para aparecer Por ano: 18000.

const salario = 1.500;
const meses = 12;
console.log("Por ano:", salario * meses);

const salario = 1500;

No português, o ponto separa os milhares (1.500 = mil e quinhentos). No JavaScript, o ponto é a vírgula decimal: 1.500 é "um vírgula cinco zero zero", ou seja, 1,5. Sem erro nenhum, o programa calculou 1,5 × 12 = 18. Para escrever o milhar de forma legível, existe outro jeito, que vem agora.

3. Números grandes: 1_000_000 e 1e6

O separador _

Para não se perder nos zeros, você pode separar os grupos de algarismos com um sublinhado. O JavaScript ignora os _; eles servem só para você ler:

const premio = 1_000_000;
const populacao = 214_000_000;
console.log(premio);
console.log(populacao);
console.log(premio === 1000000);

$ node separador.js
1000000
214000000
true

1_000_000 e 1000000 são o mesmo número. Na hora de mostrar, o Node escreve sem os separadores. O _ só pode ficar entre dois algarismos: dois seguidos (1__000) ou no fim (1000_) dão erro (veja Quando dá errado). Esse separador chegou na versão ES2021 da linguagem.

4. Outras bases: hexadecimal, binário e octal

Você conta na base 10 (algarismos de 0 a 9). Os computadores também usam outras bases, e o JavaScript aceita números escritos nelas com um prefixo:

console.log(0b1010);
console.log(0o17);

5. O maior inteiro seguro

O number guarda inteiros com exatidão até um limite: 9.007.199.254.740.991 (mais de 9 quatrilhões). O JavaScript tem esse número pronto, com o nome Number.MAX_SAFE_INTEGER ("o maior inteiro seguro"):

console.log(Number.MAX_SAFE_INTEGER);
console.log(9007199254740991 + 1);
console.log(9007199254740991 + 2);
console.log(9007199254740993);
console.log(Number.MAX_VALUE);
console.log(Number.MIN_VALUE);

$ node limite.js

Ainda certo.

Errado: devia dar …993. Passou do limite, o number não consegue mais guardar todos os inteiros, e "arredonda" para o vizinho mais próximo que ele consegue.
9007199254740993 → 9007199254740992
Nem escrevendo direto: o número digitado já é guardado arredondado.
Number.MAX_VALUE e Number.MIN_VALUE
O maior número que o number guarda (cerca de 1,8 × 10308, mas sem exatidão nos algarismos) e o menor número positivo (5 × 10-324, um zero vírgula com 323 zeros antes do 5).

Para o dia a dia (preços, notas, quantidades, datas), o limite está tão longe que você nunca vai encostar nele. Mas números como o CPF de 11 dígitos, um código de barras ou o identificador de um tweet podem passar do limite ou não ser "números de fazer conta". Para inteiros gigantes existe o bigint (aula BigInt); para códigos, use texto (seção 6).

Quando dá errado

Vírgula no lugar do ponto 
const preco = 0,75;

$ node virgula.js

                ^^

Linha por linha: o erro está na linha 1 de virgula.js; as setinhas marcam o 75; e a mensagem diz "número inesperado". Para o JavaScript, a vírgula separa coisas (lembra do let a = 1, b = 2?). Ele leu const preco = 0, uma vírgula, e depois esperava o nome de outra variável, mas encontrou o número 75.

Dentro do console.log, a vírgula é ainda mais traiçoeira, porque não dá erro:

console.log(0,75);
console.log(0.75);

$ node virgula2.js
0 75
0.75

console.log(0,75) mostrou dois números, 0 e 75, separados por espaço (como em console.log("A", "B")). Como consertar: ponto decimal sempre: 0.75.

Ponto de milhar: 1.500 
const salario = 1.500;
console.log(salario);
console.log(salario * 12);

$ node milhar.js
1.5
18

Nenhum erro, e a conta saiu completamente errada: 1.500 é 1,5. Esse é o defeito mais perigoso, porque o programa roda. Como consertar: 1500, ou 1_500 se quiser marcar o milhar. Com 1.500.000 (dois pontos), aí sim, é erro de sintaxe.

Número começando com zero: o CEP 
const cep = 01310;
console.log(cep);

$ node cep.js
712

O CEP 01310 virou 712! Por uma regra antiga do JavaScript, um número que começa com 0 e só tem algarismos de 0 a 7 é lido como octal (base 8, seção 4): 1310 na base 8 é 712 na base 10. Com um 8 ou 9 no meio (01390), a regra não vale e sai 1390, perdendo o zero. No modo estrito, a regra antiga é proibida:

$ node cep2.js
/home/ana/cep2.js:2

            ^^^^^

("Números octais não são permitidos no modo estrito".) Como consertar: CEP, telefone, CPF, número de cartão… não são números "de fazer conta", e o zero da frente importa. Guarde como texto: const cep = "01310-100";.

Resumo

  • No JavaScript, todo número (inteiro, decimal, negativo) é do tipo number.
  • A casa decimal usa ponto: 0.75. A vírgula separa coisas (0,75 dá erro ou vira dois números) e o ponto de milhar engana (1.500 é 1,5).
  • O Node mostra o número do jeito mais curto: 6.0 vira 6, 6.50 vira 6.5. Casas fixas são formatação.
  • A divisão / dá decimais: 7 / 2 é 3.5.
  • Para ler números grandes: 1_000_000 (separador) ou 1e6 (notação científica). Números enormes ou minúsculos aparecem como 1e+21, 1e-7.
  • Inteiros são exatos até Number.MAX_SAFE_INTEGER (9007199254740991). Depois disso, use bigint.
  • CEP, telefone e códigos com zero na frente são texto, não número.
