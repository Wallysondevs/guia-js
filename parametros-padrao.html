JavaScript Parâmetros Padrão

No JavaScript, você pode chamar uma função com menos argumentos do que ela tem parâmetros, e ele não reclama: o parâmetro que ficou sem valor vale undefined. Isso costuma estragar contas e textos sem dar erro nenhum. Um parâmetro padrão (em inglês, default parameter) diz qual valor usar quando o argumento não vier: function precoTotal(preco, quantidade = 1).

Você vai aprender
  • O que acontece com um parâmetro sem argumento (o undefined, o NaN).
  • Como dar um valor padrão: nome = "visitante".
  • Que o padrão só entra no lugar de undefined, nunca de null, 0 ou "".
  • Como pular um parâmetro do meio, e por que os opcionais vão no fim.
  • Padrões que usam outro parâmetro, que chamam uma função, e o padrão com desestruturação.
  • Os jeitos antigos (if e ||) e a armadilha do 0.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Para relembrar o que são parâmetros e argumentos, veja Parâmetros e Argumentos.

A ideia: "se não disser o tamanho, é médio"

Na padaria, quem pede "um café" sem dizer o tamanho recebe o médio. Ninguém precisa perguntar; já está combinado. O cliente que diz "um café grande" recebe o grande. O parâmetro padrão é esse combinado: um valor que a função usa quando quem chamou não disse nada.

1. O problema: o argumento que faltou

function saudar(nome) {
  console.log(`Olá, ${nome}!`);
}

function precoTotal(preco, quantidade) {
  return preco * quantidade;
}

saudar();
console.log(precoTotal(0.8));

$ node problema.js
Olá, undefined!
NaN

Nenhum erro, mas dois resultados ruins. Sem argumento, nome e quantidade valem undefined. No texto, o undefined aparece escrito; na conta, 0.8 * undefined dá NaN ("não é um número"; veja NaN, Infinity e a Precisão), que estraga qualquer conta seguinte.

2. O parâmetro padrão

function saudar(nome = "visitante") {
  console.log(`Olá, ${nome}!`);
}

saudar("Ana");
saudar();
nome
O parâmetro, como sempre.
= "visitante"
O valor padrão. Lê-se: "se não vier nada para nome, ele vale "visitante"". Qualquer expressão serve: um número, um texto, um array, uma conta.
saudar("Ana")
Veio argumento: o padrão é ignorado.
saudar()
Não veio: o padrão entra.
$ node padrao.js

Com dois parâmetros, só o que pode faltar ganha padrão:

function precoTotal(preco, quantidade = 1) {
  return preco * quantidade;
}

console.log(precoTotal(0.8, 10));
console.log(precoTotal(0.8));
console.log(precoTotal(0.8, 0));

$ node dois.js

0.8      « quantidade não veio: usou 1
0        « quantidade veio, e é 0: o padrão não entrou

3. O padrão só entra no lugar de undefined

A regra exata: o padrão é usado quando o argumento não vem ou vem undefined. Qualquer outro valor, mesmo "vazio", é respeitado:

function cafe(tamanho = "médio") {
  console.log(`Um café ${tamanho}.`);
}

cafe("grande");
cafe();
cafe(undefined);
cafe(null);
cafe("");

$ node soundefined.js
Um café grande.
Um café médio.     « sem argumento
Um café médio.     « undefined explícito: mesmo efeito
Um café null.      « null é um valor: o padrão não entra
Um café .          « texto vazio também é um valor

É a mesma regra do ??, só que mais estrita: o ?? troca null e undefined; o padrão troca só undefined. Se a função pode receber null e você quer tratar como "faltou", use dentro dela tamanho = tamanho ?? "médio"; (veja ?. e ??).

4. Pular um parâmetro do meio

Os argumentos são entregues pela ordem. Para usar o padrão de um parâmetro do meio e ainda passar o seguinte, mande undefined no lugar dele:

function pedido(item, quantidade = 1, embalagem = "saco de papel") {
  console.log(`${quantidade}x ${item} em ${embalagem}`);
}

pedido("pão");
pedido("pão", 10);
pedido("bolo", undefined, "caixa");

$ node meio.js
1x pão em saco de papel
10x pão em saco de papel
1x bolo em caixa

Funciona, mas pedido("bolo", undefined, "caixa") é feio e fácil de errar. Duas boas práticas:

  • Ponha os parâmetros obrigatórios primeiro e os que têm padrão no fim, do mais usado para o menos usado.
  • Quando forem muitos opcionais, receba um objeto e use desestruturação (seção 6): cada valor vai com o nome dele, em qualquer ordem.

5. Padrões mais espertos

Um padrão pode usar os parâmetros anteriores

function parcelar(total, parcelas = 1, valorParcela = total / parcelas) {
  console.log(`${parcelas}x de R$ ${valorParcela.toFixed(2)}`);
}

parcelar(120);
parcelar(120, 3);
parcelar(120, 3, 50);

$ node anterior.js
1x de R$ 120.00
3x de R$ 40.00
3x de R$ 50.00

Os parâmetros são preparados da esquerda para a direita; quando chega a vez de valorParcela, total e parcelas já têm valor. O contrário (usar um parâmetro que vem depois) dá erro: veja Quando dá errado. O toFixed(2) formata com duas casas (aula Formatando Números).

O padrão é calculado a cada chamada

A expressão do padrão roda de novo em toda chamada que precisa dela. Por isso, um array padrão é novo a cada vez:

function adicionar(item, lista = []) {
  lista.push(item);
  return lista;
}

console.log(adicionar("pão"));
console.log(adicionar("leite"));
const minha = ["café"];
console.log(adicionar("açúcar", minha));

$ node cadavez.js
[ 'pão' ]
[ 'leite' ]           « outro array vazio, novinho: o pão não está aqui
[ 'café', 'açúcar' ]

E o padrão pode chamar uma função, que só roda quando o padrão é necessário:

function hoje() {
  console.log("(calculando o padrão...)");
  return "19/10/2026";
}

function registrar(venda, data = hoje()) {
  console.log(`${venda} em ${data}`);
}

registrar("Bolo", "18/10/2026");
registrar("Pão");

$ node funcaopadrao.js
Bolo em 18/10/2026          « veio a data: hoje() nem foi chamada
(calculando o padrão...)
Pão em 19/10/2026

(Num programa de verdade, hoje() usaria new Date(), da aula Datas; aqui a data está fixa para o exemplo dar sempre a mesma saída.)

Em arrow functions

Igualzinho, dentro dos parênteses (veja Arrow Functions):

const desconto = (preco, porcentagem = 10) => preco - (preco * porcentagem) / 100;
console.log(desconto(50));
console.log(desconto(50, 20));

$ node arrow.js

6. Padrão com desestruturação: opções com nome

Juntando com a desestruturação, a função recebe um objeto de opções, e cada opção tem o seu padrão:

function criarPedido({ item, quantidade = 1, viagem = false } = {}) {
  console.log({ item, quantidade, viagem });
}

criarPedido({ item: "café", viagem: true });
criarPedido({ item: "pão", quantidade: 6 });
criarPedido();
{ item, quantidade = 1, viagem = false }
Desmonta o objeto recebido; quantidade e viagem têm padrões próprios.
= {}
O padrão do parâmetro inteiro: se a função for chamada sem nada, desestrutura um objeto vazio (sem isso, criarPedido() daria Cannot destructure property).
console.log({ item, quantidade, viagem })
Monta um objeto só para mostrar os três valores de uma vez.
$ node objeto.js
{ item: 'café', quantidade: 1, viagem: true }
{ item: 'pão', quantidade: 6, viagem: false }
{ item: undefined, quantidade: 1, viagem: false }

Repare que a chamada { item: "café", viagem: true } pulou a quantidade sem precisar de undefined: é a vantagem das opções com nome.

Formas diferentes de fazer a mesma coisa

Antes de existir o parâmetro padrão (até o ES5), o valor padrão era feito dentro da função. Você vai encontrar os dois jeitos em código antigo:

function precoTotalIf(preco, quantidade) {
  if (quantidade === undefined) {
    quantidade = 1;
  }
  return preco * quantidade;
}

function precoTotalOu(preco, quantidade) {
  quantidade = quantidade || 1;
  return preco * quantidade;
}

console.log(precoTotalIf(0.8), precoTotalIf(0.8, 0));
console.log(precoTotalOu(0.8), precoTotalOu(0.8, 0));

$ node antigo.js
0.8 0
0.8 0.8      « o || trocou a quantidade 0 por 1!

O || 1 troca qualquer valor falsy (veja Truthy e Falsy), então a quantidade 0, que é válida, virou 1. Esse defeito era comum e é um dos motivos de o parâmetro padrão existir.

Quando dá errado

Esqueceu o padrão: undefined e NaN

É o problema da seção 1: nenhuma mensagem de erro, só Olá, undefined! e NaN. Quando vir esses dois na saída, desconfie de um argumento que faltou. Como consertar: passe o argumento, ou dê um padrão ao parâmetro.

Mandou null esperando o padrão

Na seção 3, cafe(null) deu Um café null.. É comum quando o valor vem de um formulário ou de um JSON (onde "sem valor" costuma ser null). Como consertar: mande undefined (ou não mande nada), ou trate o null dentro da função com ??.

Parâmetro obrigatório que ninguém passou

Às vezes o certo não é um padrão, e sim reclamar. Um truque conhecido: um padrão que chama uma função que lança um erro (veja throw), e só roda se o argumento faltar.

function faltou(nome) {
  throw new Error(`O parâmetro "${nome}" é obrigatório.`);
}

function cadastrar(nome = faltou("nome"), cidade = "Recife") {
  console.log(`${nome}, de ${cidade}`);
}

cadastrar("Ana");
cadastrar();

Missão final: a etiqueta de preço

Missão: a função quebra quando não recebe a unidade nem a moeda (sai undefined), e quando não recebe o preco o toFixed dá erro. Dê padrões: preco = 0, unidade = "unidade" e moeda = "R$". Deve sair Pão: R$ 0.80 (unidade), Bolo: R$ 25.00 (unidade) e Café: R$ 32.00 (kg), e a última chamada também não pode dar erro.

function etiqueta(nome, preco, unidade, moeda) {
  console.log(`${nome}: ${moeda} ${preco.toFixed(2)} (${unidade})`);
}

etiqueta("Pão", 0.8);
etiqueta("Bolo", 25);
etiqueta("Café", 32, "kg");
etiqueta("Brinde");

function etiqueta(nome, preco = 0, unidade = "unidade", moeda = "R$") {
  console.log(`${nome}: ${moeda} ${preco.toFixed(2)} (${unidade})`);
}

etiqueta("Pão", 0.8);
etiqueta("Bolo", 25);
etiqueta("Café", 32, "kg");
etiqueta("Brinde");

Resumo

  • Parâmetro sem argumento vale undefined, o que gera undefined em textos e NaN em contas, sem erro.
  • function f(x = valor) usa o valor quando o argumento não vem ou é undefined. null, 0 e "" são respeitados.
  • Opcionais no fim; para pular um do meio, undefined, ou, melhor, um objeto de opções com { a = 1 } = {}.
  • O padrão é calculado a cada chamada, pode usar parâmetros anteriores e chamar funções.
  • Prefira o padrão ao velho x = x || 1, que estraga o 0.
