JavaScript console.error, warn e table

Na aula console.log() você aprendeu a mostrar qualquer coisa na tela. Mas o console (em inglês, "painel de controle"; aqui, o lugar onde o programa escreve as suas mensagens) tem outras ferramentas além do log. Duas delas servem para avisar que algo deu errado (console.error e console.warn) e uma serve para mostrar dados em forma de tabela (console.table), do jeito que a Ana confere o estoque da padaria num caderno quadriculado.

Você vai aprender
  • Para que serve o console.error ("erro") e por que a mensagem dele vai para um "canal" separado: a saída de erro.
  • Como separar as mensagens normais das de erro no terminal, com > e 2>.
  • O console.warn ("aviso"), o console.info ("informação") e o console.debug ("depuração").
  • Como mostrar uma lista, um objeto ou uma lista de objetos como tabela, com console.table, e como escolher as colunas.
  • Três ajudantes: console.count (contar), console.group (agrupar) e console.time (cronometrar).
  • Os erros reais mais comuns: o nome do método escrito errado, o Console com C maiúsculo e as aspas que não fecham.

Todos os programas desta aula rodaram no Node.js v24.22.0 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa).

A ideia: o recado normal e o bilhete vermelho

Na padaria do bairro, o funcionário do caixa anota tudo num caderno: "abri o caixa", "vendi 6 pães", "fechei o caixa". Quando acontece um problema (a máquina de cartão não liga, o pão acabou), ele não escreve no meio do caderno: ele cola um bilhete vermelho na geladeira, para o dono ver logo.

Um programa faz a mesma coisa. Ele tem dois canais de saída:

CanalNome técnicoQuem escreve neleNa padaria
A saída padrãostdout ("standard output")console.log, console.info, console.debug, console.tableO caderno do dia a dia
A saída de errostderr ("standard error")console.error, console.warnO bilhete vermelho na geladeira

No terminal, os dois canais aparecem misturados na mesma tela, e à primeira vista não há diferença nenhuma. A diferença aparece quando você quer separar um do outro, como você vai ver na seção 2.

1. console.error(): avisar que algo deu errado

console.log("Abrindo o caixa da padaria...");
console.error("Erro: o preço do pão está vazio!");
console.log("Caixa aberto.");
console
O mesmo objeto do console.log: a "caixa de ferramentas" para escrever mensagens.
.error
O ponto quer dizer "de dentro do console, use a ferramenta…". error é "erro" em inglês.
("Erro: o preço do pão está vazio!")
O que vai ser escrito, entre parênteses, igual ao console.log. Pode ser um texto, um número, uma variável, ou vários valores separados por vírgula.
;
O ponto e vírgula fecha a instrução (veja Instruções, Ponto e Vírgula e Blocos).
$ node caixa.js
Abrindo o caixa da padaria...
Erro: o preço do pão está vazio!
Caixa aberto.
$ echo $?
0

Repare em três coisas:

  • As três linhas apareceram na ordem em que o programa as escreveu. No terminal da Ana, a linha do console.error tem a mesma cara das outras.
  • O programa continuou depois do console.error: o Caixa aberto. apareceu. O console.error só escreve uma mensagem; ele não para o programa nem cria um erro de verdade. (Erros de verdade, que param o programa, são o assunto de Erros e throw.)
  • O código de saída (o echo $?, que mostra como o último programa terminou) foi 0, que quer dizer "terminou bem". Para o Node, escrever no canal de erro não é falhar.
E no navegador?

No Console do navegador (o F12, veja O Console do Navegador), as mensagens do console.error aparecem com fundo vermelho e as do console.warn, com fundo amarelo. Lá a diferença salta aos olhos. No terminal do Node, o que muda é o canal.

2. Separando os dois canais no terminal: > e 2>

O terminal deixa você mandar a saída de um programa para um arquivo, em vez da tela. O sinal > manda só a saída padrão para o arquivo. O que sobra na tela é a saída de erro:

$ node caixa.js > saida.txt
Erro: o preço do pão está vazio!
$ cat saida.txt
Abrindo o caixa da padaria...
Caixa aberto.

As duas linhas do console.log foram para o arquivo saida.txt (o cat mostra o conteúdo de um arquivo). A linha do console.error não foi: ela continuou na tela. É o bilhete vermelho que não vai para o caderno. Isso é útil de verdade: um programa que gera um relatório pode mandar o relatório para um arquivo e, mesmo assim, avisar você na tela se alguma coisa der errado.

O contrário também funciona. 2> manda só a saída de erro para o arquivo (o 2 é o número que o sistema dá para o canal de erro; o 1, que fica escondido no > sozinho, é a saída padrão):

$ node caixa.js 2> erros.txt
Abrindo o caixa da padaria...
Caixa aberto.
$ cat erros.txt
Erro: o preço do pão está vazio!
No terminalO que vai para o arquivoO que fica na tela
node caixa.jsnadatudo
node caixa.js > saida.txtconsole.log (saída padrão)console.error (saída de erro)
node caixa.js 2> erros.txtconsole.error (saída de erro)console.log (saída padrão)
Atenção: > apaga o que havia no arquivo

Se o saida.txt já existir, o > joga fora o conteúdo antigo e escreve o novo. Para acrescentar no fim, sem apagar, use >> (ou 2>> para os erros).

Missão: a terceira mensagem é um problema, não um recado normal. Troque o console.log dela por console.error e rode.

console.log("Conferindo a geladeira...");
console.log("Manteiga: ok");
console.log("Erro: acabou o leite!");
console.log("Conferência terminada.");

3. console.warn(), console.info() e console.debug()

Nem todo problema é um erro. "Só restam 3 pães" não é um desastre, mas merece atenção: é um aviso, e para isso existe o console.warn (warn = "avisar"). Do outro lado existem dois parentes do console.log: o console.info (para informações) e o console.debug (para detalhes que só interessam a quem está programando; "depurar" é caçar defeitos no programa, veja Depuração).

const paes = 3;
console.log("Pães no cesto:", paes);
console.warn("Atenção: só restam", paes, "pães!");
console.info("Informação: o padeiro chega às 5h.");
console.debug("Detalhe para o programador: paes =", paes);

$ node aviso.js
Pães no cesto: 3
Atenção: só restam 3 pães!
Informação: o padeiro chega às 5h.
Detalhe para o programador: paes = 3

Igual ao console.log, todos aceitam vários valores separados por vírgula e põem um espaço entre eles (só restam 3 pães!). Agora, a Ana joga a saída de erro fora (2> /dev/null: o /dev/null é a "lixeira" do sistema, onde tudo some):

$ node aviso.js 2> /dev/null
Pães no cesto: 3
Informação: o padeiro chega às 5h.
Detalhe para o programador: paes = 3

Só o aviso sumiu. Isso mostra para que canal cada um escreve no Node:

MétodoPara que serveCanal no Node
console.log()Mensagem comumsaída padrão
console.info()Informaçãosaída padrão (no Node, é o mesmo que console.log)
console.debug()Detalhe para quem programasaída padrão (no Node, é o mesmo que console.log)
console.warn()Aviso: atenção, mas não é desastresaída de erro (no Node, é o mesmo que console.error)
console.error()Erro: algo deu erradosaída de erro

Então por que existem cinco, se no Node eles se resumem a dois? Porque eles dizem a intenção de quem escreveu. Quem lê console.warn(…) no seu código sabe na hora que aquilo é um aviso. E no Console do navegador eles são diferentes: o warn vem em amarelo, o error em vermelho, e dá para filtrar por nível ("só erros", "só avisos"). O console.debug nem aparece, a não ser que você ligue o nível "Detalhado" (Verbose) no Console do Chrome.

4. console.table(): dados em forma de tabela

Quando os dados são uma lista ou um "cadastro", o console.log mostra tudo numa linha só, e fica difícil de ler. O console.table (table = "tabela") desenha uma tabela com linhas e colunas.

4.1 Uma lista

Uma lista entre colchetes [ ] é um array (você vai estudá-los em Arrays). Veja a mesma lista com log e com table:

const compras = ["pão", "leite", "café"];
console.log(compras);
console.table(compras);

$ node lista.js
[ 'pão', 'leite', 'café' ]
┌─────────┬─────────┐
│ (index) │ Values  │
├─────────┼─────────┤
│ 0       │ 'pão'   │
│ 1       │ 'leite' │
│ 2       │ 'café'  │
└─────────┴─────────┘
(index)
"Índice": a posição de cada item na lista. O JavaScript começa a contar do 0, então o primeiro item ('pão') é o de índice 0. Isso vai aparecer muito no curso.
Values
"Valores": o que está guardado em cada posição. Os textos aparecem entre aspas simples, como no console.log, para você saber que são textos.
┌ ─ ┬ │ └
As bordas da tabela, desenhadas com caracteres especiais. O Node ajusta a largura de cada coluna ao maior valor dela.

4.2 Um objeto

Um objeto, entre chaves { }, guarda pares "nome: valor" (o assunto de Objetos). É o caderno de estoque da padaria:

const estoque = { pao: 40, leite: 12, cafe: 8 };
console.table(estoque);

$ node estoque.js
┌─────────┬────────┐
│ (index) │ Values │
├─────────┼────────┤
│ pao     │ 40     │
│ leite   │ 12     │
│ cafe    │ 8      │
└─────────┴────────┘

Agora a coluna (index) mostra os nomes (pao, leite, cafe) em vez de números. Os números aparecem sem aspas: são números, não textos.

4.3 Uma lista de objetos: onde o table brilha

O caso mais útil é uma lista em que cada item é um objeto com os mesmos campos, como as linhas de um pedido. Cada objeto vira uma linha e cada campo vira uma coluna:

const pedido = [
  { item: "pão francês", quantidade: 6, preco: 0.75 },
  { item: "leite", quantidade: 2, preco: 5.49 },
  { item: "café", quantidade: 1, preco: 18.9 },
];
console.table(pedido);
console.table(pedido, ["item", "preco"]);

4.4 E quando não é uma tabela?

Se você passar um valor simples, como um texto ou um número, não há linhas nem colunas para desenhar. O console.table então faz o mesmo que o console.log:

console.table("Bom dia!");
console.table(42);

$ node texto.js
Bom dia!
42

5. Três ajudantes: contar, agrupar e cronometrar

console.count(): quantas vezes isto aconteceu?

Cada vez que o console.count("nome") roda, ele escreve o nome e quantas vezes já foi chamado com aquele nome. É a "catraca" da porta da padaria:

console.count("cliente");
console.count("cliente");
console.count("entrega");
console.count("cliente");
console.count();

$ node contar.js
cliente: 1
cliente: 2
entrega: 1
cliente: 3
default: 1

Cada nome tem a sua própria contagem: entrega começou do 1 sem atrapalhar cliente. Sem nome nenhum, o Node usa o nome default ("padrão"). Ele vai ser útil dentro dos laços, para saber quantas voltas um trecho deu (veja while).

console.group(): mensagens com recuo

Entre o console.group("título") e o console.groupEnd() ("fim do grupo"), as mensagens ganham recuo (2 espaços na frente), como os itens de uma comanda:

console.log("Pedido da mesa 3");
console.group("Bebidas");
console.log("café com leite");
console.log("suco de laranja");
console.groupEnd();
console.group("Comidas");
console.log("pão na chapa");
console.groupEnd();
console.log("Fim do pedido");

$ node grupo.js
Pedido da mesa 3
Bebidas
  café com leite
  suco de laranja
Comidas
  pão na chapa
Fim do pedido

Se você esquecer o console.groupEnd(), tudo o que vier depois continua com recuo.

console.time() e console.timeEnd(): quanto tempo levou?

O console.time("nome") liga um cronômetro; o console.timeEnd("nome"), com o mesmo nome, para o cronômetro e escreve quanto tempo passou. Aqui a Ana mede quanto o computador leva para somar os números de 0 a 999.999 (o for, que repete uma conta muitas vezes, é o assunto da aula for):

console.time("contar");
let soma = 0;
for (let i = 0; i < 1000000; i++) {
  soma = soma + i;
}
console.timeEnd("contar");

$ node tempo.js
contar: 4.024ms                          « muda a cada execução

Pouco mais de 4 milissegundos (milésimos de segundo) para um milhão de somas. Esse número muda a cada vez que você roda, e de um computador para outro: o seu vai mostrar outro valor.

Formas diferentes de mostrar a mesma coisa

O mesmo problema ("acabou o pão") pode ser escrito de vários jeitos. Todos mostram o texto; o que muda é a intenção e o canal:

console.log("Acabou o pão!");    // recado comum, saída padrão
console.warn("Acabou o pão!");   // aviso, saída de erro
console.error("Acabou o pão!");  // erro, saída de erro

$ node formas.js
Acabou o pão!
Acabou o pão!
Acabou o pão!
$ node formas.js 2> /dev/null
Acabou o pão!                          « só a do console.log sobrou

Resumo

  • Um programa tem dois canais de saída: a saída padrão (console.log, info, debug, table) e a saída de erro (console.error, warn). No terminal os dois aparecem juntos; > separa a saída padrão e 2>, a de erro.
  • console.error e console.warn só escrevem: o programa continua, e o código de saída segue 0.
  • Use o método que diz a intenção: log para o resultado, warn para avisos, error para problemas. No navegador, o warn aparece em amarelo e o error em vermelho.
  • console.table mostra listas e objetos como tabela; numa lista de objetos, cada objeto é uma linha e cada campo, uma coluna. console.table(lista, ["a", "b"]) escolhe as colunas.
  • console.count conta chamadas, console.group/groupEnd dão recuo e console.time/timeEnd medem o tempo.
  • Os nomes são exatos e em minúsculas: console.tabel dá TypeError … is not a function, e Console dá ReferenceError … is not defined.
