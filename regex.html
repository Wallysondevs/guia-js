JavaScript Expressões Regulares

Com o includes você pergunta se um texto contém uma palavra exata: "tem pão na lista?". Mas e se a pergunta for "tem algum número nesse texto?", "isso tem cara de CEP?", "a pessoa respondeu sim, s ou Sim?"? Para perguntas assim, sobre o formato de um texto, existem as expressões regulares (em inglês, regular expressions, ou regex, como todo mundo fala). Uma regex é um padrão: uma descrição curta de como um texto deve ser. Parece um idioma estranho no começo (/^\d{5}-?\d{3}$/), mas ele tem poucas peças, e esta aula apresenta uma por vez.

Você vai aprender
  • O que é uma regex, como se escreve (/padrão/) e como testar com .test().
  • As classes: [abc], [0-9], [^0-9] e os atalhos \d, \w, \s e o ponto ..
  • Os quantificadores: +, *, ? e {n,m}, para dizer "quantas vezes".
  • As âncoras ^ e $, que fazem o padrão valer para o texto inteiro.
  • A flag i (ignorar maiúsculas), os grupos ( ) e as alternativas |.
  • Como escapar os caracteres especiais (\., \$) e criar uma regex a partir de um texto com new RegExp.
  • Como validar CEP, placa de carro, e-mail e celular, e os erros reais do Node 24.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. As regex são da linguagem: funcionam igual no navegador. Esta aula usa quase só o .test(), que responde true ou false; buscar, extrair e substituir com regex é o assunto da próxima aula, Regex na Prática.

A ideia: o molde de um documento

Quando a Ana preenche um formulário, a moça do caixa olha o CEP e já sabe se está certo, sem conhecer a rua: "cinco números, um tracinho, três números". Ela não está procurando um CEP específico; está conferindo o formato. Uma regex é esse molde, escrito com símbolos:

Em portuguêsEm regex
um número qualquer\d
cinco números\d{5}
um tracinho-
três números\d{3}
e nada mais antes nem depois^ no começo, $ no fim
Tudo junto/^\d{5}-\d{3}$/

Até o fim da aula, você vai saber ler e escrever essa linha.

2. Classes: "um destes caracteres"

Colchetes [ ] querem dizer "um caractere, qualquer um destes". Com um tracinho dentro, vira uma faixa: [0-9] é qualquer dígito, [a-z] qualquer letra minúscula sem acento. E um ^ logo depois do [ inverte: [^0-9] é "qualquer caractere que não seja dígito".

const vogal = /[aeiou]/;
const digito = /[0-9]/;
const naoDigito = /[^0-9]/;

console.log(vogal.test("psiu"));
console.log(vogal.test("psst"));
console.log(digito.test("Apartamento 42"));
console.log(digito.test("sem número"));
console.log(naoDigito.test("12345"));
console.log(naoDigito.test("123a5"));

3. Quantificadores: "quantas vezes"

Um quantificador vem depois de uma peça e diz quantas vezes ela pode se repetir. Para ver o que cada padrão encontrou, a Ana fez uma função mostrar, que usa o match ("casar"), um método que você vai conhecer direito na próxima aula. Por enquanto, basta saber que ele devolve o pedaço do texto que casou com o padrão:

function mostrar(regex, texto) {
  const achado = texto.match(regex);
  console.log(`${regex} em "${texto}" → ${achado ? `"${achado[0]}"` : "nada"}`);
}

mostrar(/\d+/, "Mesa 127, fila B");
mostrar(/\d*/, "Mesa 127");
mostrar(/\d{2}/, "Mesa 127");
mostrar(/\d{2,4}/, "Ano 2026");
mostrar(/colou?r/, "a color e a colour");
mostrar(/bo+m/, "booooom!");
mostrar(/bo+m/, "bm");

$ node mostrar.js

/\d{2}/ em "Mesa 127" → "12"
/\d{2,4}/ em "Ano 2026" → "2026"
/colou?r/ em "a color e a colour" → "color"

O quantificador vale só para a peça imediatamente antes dele: em bo+m, o + repete só o o. Para repetir mais de um caractere, use um grupo (seção 6).

4. Âncoras: ^ e $, "o texto inteiro"

Sem âncoras, o test procura o padrão em qualquer lugar do texto. Para validar (conferir se o texto inteiro tem o formato), isso é um problema:

const cep = /\d{5}-\d{3}/;
const cepInteiro = /^\d{5}-\d{3}$/;

console.log(cep.test("01310-100"));
console.log(cep.test("CEP: 01310-100, São Paulo"));
console.log(cepInteiro.test("01310-100"));
console.log(cepInteiro.test("CEP: 01310-100, São Paulo"));
console.log(cepInteiro.test("01310-1000"));

$ node ancoras.js
true
true
true
false
false
^ (no começo do padrão)
"Aqui é o começo do texto". Nada pode vir antes.
$ (no fim do padrão)
"Aqui é o fim do texto". Nada pode vir depois.
01310-1000 → false
Sem o $, esse CEP com um dígito a mais passaria: os 8 primeiros caracteres têm o formato certo. Com o $, depois dos 3 dígitos o texto tem de acabar.

Regra prática: para validar um campo, use ^ e $. Para procurar algo dentro de um texto maior, não use. (Cuidado para não confundir: o ^ dentro dos colchetes, [^0-9], quer dizer "não"; fora deles, quer dizer "começo".)

5. Flags: a letra depois da barra

Depois da segunda barra podem vir letras que mudam o jeito de a regex funcionar: as flags ("bandeirinhas"). A mais simples é o i, de ignore case ("ignorar maiúsculas e minúsculas"):

console.log(/pão/.test("PÃO de queijo"));
console.log(/pão/i.test("PÃO de queijo"));
console.log(/^sim$/i.test("SIM"));
console.log(/^sim$/i.test("Sim"));

6. Grupos e alternativas: ( ) e |

A barra vertical | quer dizer "ou". Os parênteses agrupam um pedaço do padrão, para o | ou um quantificador valerem para o pedaço inteiro. O programa da Ana aceita várias formas de dizer "sim":

const resposta = /^(sim|s|claro)$/i;

for (const texto of ["sim", "S", "Claro", "não", "simmm"]) {
  console.log(`${texto}: ${resposta.test(texto)}`);
}
console.log(/^(ha)+!$/.test("hahaha!"));

$ node grupos.js

Claro: true
não: false
simmm: false
true

"sim ou s ou claro". Os parênteses delimitam as alternativas: sem eles, ^sim|s|claro$ seria "começa com sim, ou tem um s em qualquer lugar, ou termina com claro", algo bem diferente.
^ … $ e o i
O texto inteiro tem de ser uma das alternativas (simmm não passa), sem ligar para maiúsculas.
(ha)+
O + depois do grupo repete o grupo inteiro: ha, haha, hahaha…

Os grupos também servem para capturar pedaços do texto (separar o DDD do número, o dia do mês…). Isso fica para a próxima aula.

7. Escapando os caracteres especiais

Você já viu que ., +, *, ?, (, ), [, ], {, }, ^, $, |, \ e / têm significados especiais. E quando você quer o caractere de verdade, como o ponto de 3.14 ou o cifrão de R$? Ponha uma barra invertida antes: isso se chama escapar o caractere.

console.log(/3.14/.test("3x14"));
console.log(/3\.14/.test("3x14"));
console.log(/3\.14/.test("3.14"));
console.log(/R\$ \d+/.test("Preço: R$ 20"));

$ node escapar.js
true
false
true
true

A primeira linha é um erro silencioso clássico: sem a barra, o ponto quer dizer "qualquer caractere", e 3x14 passou. \. é "um ponto mesmo"; \$ é "um cifrão mesmo"; \( é "um parêntese mesmo".

Uma regex feita de um texto: new RegExp

Quando o padrão vem de uma variável (o que a pessoa digitou na busca, por exemplo), use new RegExp(texto, flags):

const palavra = "pão";
const busca = new RegExp(palavra, "i");

console.log(busca);
console.log(busca.test("Pão de queijo"));

const errado = new RegExp("^\d{3}$");
const certo = new RegExp("^\\d{3}$");
console.log(errado, errado.test("123"));
console.log(certo, certo.test("123"));

$ node regexp.js
/pão/i
true
/^d{3}$/ false
/^\d{3}$/ true

Cuidado com a barra invertida: dentro de aspas, "\d" já é um caractere especial de texto (veja Caracteres Especiais), e a barra some antes de a regex nascer. O resultado, /^d{3}$/, procura três letras d! Dentro de aspas, escreva a barra dobrada: "\\d". Por isso, quando o padrão é fixo, prefira as barras /…/.

8. Validando formatos do dia a dia

CEP, com ou sem tracinho

const cep = /^\d{5}-?\d{3}$/;

const testes = ["01310-100", "01310100", "1310-100", "01310-10a", " 01310-100"];
for (const texto of testes) {
  console.log(`"${texto}": ${cep.test(texto) ? "válido" : "inválido"}`);
}

$ node cep.js

O -? deixa o tracinho opcional. O último falhou por causa do espaço no começo: textos digitados por pessoas costumam ter espaços sobrando, então passe um .trim() antes de testar (veja Métodos de String).

Missão: esta regex só aceita o CEP com tracinho. Mude o padrão para o tracinho ser opcional: 01310100 deve ficar válido, e 1310-100 (com 4 dígitos no começo) deve continuar inválido.

const cep = /^\d{5}-\d{3}$/;

for (const texto of ["01310-100", "01310100", "1310-100"]) {
  console.log(`${texto}: ${cep.test(texto) ? "válido" : "inválido"}`);
}

const cep = /^\d{5}-?\d{3}$/;

for (const texto of ["01310-100", "01310100", "1310-100"]) {
  console.log(`${texto}: ${cep.test(texto) ? "válido" : "inválido"}`);

const email = /^[\w.+-]+@[\w-]+(\.[\w-]+)+$/;

Depois: um nome, e um ou mais grupos "ponto + nome" (.com, .edu.br). Uma regex nunca garante que o e-mail existe; ela só confere se tem cara de e-mail.

Diferente dos anteriores, este erro acontece com o programa rodando (veja o at new RegExp e a linha 2 do seu programa), porque a regex só nasce quando a linha 2 roda. Se o texto vier de uma pessoa, qualquer parêntese ou ponto que ela digitar vira símbolo especial. Como consertar: quando você quer procurar o texto exatamente como veio, use includes em vez de regex.

Erros que não dão mensagem
  • Esqueceu ^ e $ numa validação: /\d{5}-\d{3}/ aceitou "CEP: 01310-100, São Paulo" e aceitaria 01310-1000 (seção 4).
  • Ponto sem escape: /3.14/ aceitou 3x14 (seção 7).
  • \w com acentos: /^\w+$/ recusou pão (seção 2).
  • "\d" entre aspas no new RegExp: virou d (seção 7).

Por isso, sempre teste a regex com exemplos que devem passar e com exemplos que devem falhar, como os programas desta aula fazem.

Os dois primeiros testes devem dar true, e os outros três, false. (Lembre: parêntese de verdade se escreve \(, e não esqueça o ^ e o $.)

const celular = /troque-por-sua-regex/;

const testes = ["(11) 91234-5678", "(21) 98765-4321", "11912345678", "(11) 1234-5678", "(11) 91234-56789"];
for (const texto of testes) {
  console.log(`${texto}: ${celular.test(texto)}`);
}

const celular = /^\(\d{2}\) 9\d{4}-\d{4}$/;

const testes = ["(11) 91234-5678", "(21) 98765-4321", "11912345678", "(11) 1234-5678", "(11) 91234-56789"];
for (const texto of testes) {
  console.log(`${texto}: ${celular.test(texto)}`);
}

No lab, a solução mostrou:

$ node celular.js
(11) 91234-5678: true
(21) 98765-4321: true
11912345678: false
(11) 1234-5678: false
(11) 91234-56789: false

Resumo

  • Uma regex é um padrão de texto, escrito entre barras: /padrão/flags. regex.test(texto) responde se o padrão aparece no texto.
  • Classes dizem "qual caractere": [abc], [0-9], [^0-9], \d, \w (sem acentos!), \s e o ponto (qualquer um).
  • Quantificadores dizem "quantas vezes" a peça anterior aparece: +, *, ?, {n}, {n,m}.
  • Âncoras ^ e $ fazem o padrão valer para o texto inteiro: use sempre para validar.
  • ( ) agrupa, | é "ou", a flag i ignora maiúsculas. Caracteres especiais de verdade se escapam com \.
  • new RegExp(texto, flags) cria uma regex de um texto: dobre as barras invertidas. Teste sempre com exemplos que devem passar e que devem falhar.
