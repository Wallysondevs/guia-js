JavaScript Herança (extends e super)

Na aula Classes, a Ana criou a classe Produto para a lojinha dela: todo produto tem nome, preço e sabe se descrever. Mas alguns produtos são especiais: o leite e o queijo têm data de validade; o sorvete, além disso, precisa de temperatura. Escrever uma classe nova do zero para cada um repetiria o nome, o preço e o descrever() em todas. A herança resolve isso: uma classe nova pode herdar tudo de uma classe que já existe e só acrescentar o que é diferente.

Você vai aprender
  • O que é herança e como se escreve: class Perecivel extends Produto ("estende").
  • Para que serve o super(…) no construtor, e por que ele é obrigatório antes do this.
  • Como sobrescrever um método e como reaproveitar o método da classe mãe com super.metodo().
  • Como perguntar "este objeto é um produto?" com instanceof.
  • Herança em vários níveis, e herdar de uma classe pronta do JavaScript (Error).
  • O jeito antigo (com prototype), a alternativa sem herança, e os erros reais do Node.js.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: "é um produto, só que com validade"

Pense na ficha de cadastro da lojinha. Todo produto tem uma ficha com nome e preço. Para os perecíveis, a Ana não inventa uma ficha nova do zero: ela pega a ficha normal e grampeia nela uma folhinha a mais com a validade. O leite continua sendo um produto (tem nome e preço, aparece na prateleira, entra na conta), só que com uma informação extra.

Na programação é igual:

  • a classe que já existe (Produto) é a classe mãe (também chamada de superclasse ou classe base);
  • a classe nova (Perecivel) é a classe filha (ou subclasse): ela herda tudo da mãe e acrescenta o que é dela;
  • a frase que deve fazer sentido é "todo perecível é um produto". Se a frase "todo X é um Y" soar estranha, herança provavelmente não é a ferramenta certa (veja Formas diferentes).

1. A primeira herança: extends e super()

class Produto {
  constructor(nome, preco) {
    this.nome = nome;
    this.preco = preco;
  }

  descrever() {
    return `${this.nome}: R$ ${this.preco.toFixed(2)}`;
  }
}

class Perecivel extends Produto {
  constructor(nome, preco, validade) {
    super(nome, preco);
    this.validade = validade;
  }
}

const arroz = new Produto("Arroz 5 kg", 27.9);
const leite = new Perecivel("Leite 1 L", 5.49, "25/10");

console.log(arroz.descrever());
console.log(leite.descrever());
console.log(leite.validade);
console.log(leite);
class Produto { … }
A classe mãe, igual à da aula Classes: o constructor guarda nome e preço; o método descrever() devolve um texto com o preço em 2 casas (o toFixed(2), de Formatando Números).
class Perecivel extends Produto
"A classe Perecivel estende a classe Produto". O extends (em inglês, "estende") é a palavra que liga a filha à mãe. Só com isso, a filha já ganha o descrever() da mãe.
constructor(nome, preco, validade)
O construtor da filha recebe três valores: os dois que a mãe sabe guardar e o que é novo.
super(nome, preco);
Chama o construtor da mãe, passando o nome e o preço. É o super(…) que roda o this.nome = nome; this.preco = preco; lá do Produto. Em inglês, super quer dizer "acima": a classe de cima.
this.validade = validade;
Depois que a mãe fez a parte dela, a filha guarda o que é só dela. A ordem importa: o this só pode ser usado depois do super(…) (a seção Quando dá errado mostra o erro).
leite.descrever()
A classe Perecivel não tem nenhum descrever() escrito nela. O JavaScript procura na filha, não acha, e sobe para a mãe: é o método do Produto que roda.
$ node perecivel.js
Arroz 5 kg: R$ 27.90
Leite 1 L: R$ 5.49
25/10
Perecivel { nome: 'Leite 1 L', preco: 5.49, validade: '25/10' }

Repare na última linha: o console.log do objeto mostra o nome da classe (Perecivel) e as três propriedades juntas, como se fossem uma ficha só. As duas primeiras foram guardadas pelo construtor da mãe; a terceira, pelo da filha.

2. A filha pode não ter construtor nenhum

Se a filha não precisa guardar nada novo, ela nem precisa escrever um constructor. Nesse caso, o JavaScript usa o construtor da mãe sozinho. A lojinha dá canetas de brinde: um brinde é um produto, só que se descreve de outro jeito:

class Produto {
  constructor(nome, preco) {
    this.nome = nome;
    this.preco = preco;
  }

  descrever() {
    return `${this.nome}: R$ ${this.preco.toFixed(2)}`;
  }
}

class Brinde extends Produto {
  descrever() {
    return `${this.nome}: grátis!`;
  }
}

const caneta = new Brinde("Caneta da loja", 0);
console.log(caneta.descrever());
console.log(caneta.preco);

$ node substituir.js
Caneta da loja: grátis!
0

Duas coisas aconteceram aqui:

  • O new Brinde("Caneta da loja", 0) usou o construtor do Produto: por isso caneta.preco vale 0. Sem construtor próprio, a filha funciona como se tivesse escrito constructor(...args) { super(...args); } (repassa tudo para a mãe; o ... é o rest e spread).
  • O Brinde escreveu o seu próprio descrever(). Quando a filha tem um método com o mesmo nome do da mãe, o da filha ganha: o JavaScript procura primeiro na filha e, achando, nem olha a mãe. Isso se chama sobrescrever o método (em inglês, override).

3. Sobrescrever, mas aproveitando a mãe: super.metodo()

O brinde trocou o descrever() inteiro. Para o leite, a Ana quer outra coisa: o texto da mãe (Leite 1 L: R$ 5.49) mais a validade. Copiar o código da mãe para a filha funcionaria, mas aí a mesma conta ficaria escrita em dois lugares. O jeito certo é chamar o método da mãe com super.descrever():

class Produto {
  constructor(nome, preco) {
    this.nome = nome;
    this.preco = preco;
  }

  descrever() {
    return `${this.nome}: R$ ${this.preco.toFixed(2)}`;
  }
}

class Perecivel extends Produto {
  constructor(nome, preco, validade) {
    super(nome, preco);
    this.validade = validade;
  }

  descrever() {
    return `${super.descrever()} (vence em ${this.validade})`;
  }
}

const arroz = new Produto("Arroz 5 kg", 27.9);
const leite = new Perecivel("Leite 1 L", 5.49, "25/10");

console.log(arroz.descrever());
console.log(leite.descrever());

$ node sobrescrever.js
Arroz 5 kg: R$ 27.90
Leite 1 L: R$ 5.49 (vence em 25/10)
EscritaOnde apareceO que faz
super(nome, preco)Só dentro do constructor da filhaRoda o construtor da mãe
super.descrever()Em qualquer método da filhaRoda o método descrever da mãe (mesmo que a filha tenha um com o mesmo nome)

Se um dia a Ana mudar o descrever() do Produto (por exemplo, para mostrar o preço com vírgula), o leite muda junto, sem ela mexer na classe Perecivel. É a grande vantagem do super.metodo().

4. Uma prateleira com tipos misturados, e o instanceof

Como todo perecível e todo brinde são produtos, eles podem ficar juntos no mesmo array. O laço chama descrever() em cada um, sem se preocupar com o tipo: cada objeto responde do seu jeito.

// (as classes Produto, Perecivel e Brinde das seções 2 e 3 vêm aqui em cima)

const prateleira = [
  new Produto("Arroz 5 kg", 27.9),
  new Perecivel("Leite 1 L", 5.49, "25/10"),
  new Brinde("Caneta da loja", 0),
];

for (const item of prateleira) {
  console.log(item.descrever());
}

const leite = prateleira[1];
console.log(leite instanceof Perecivel);
console.log(leite instanceof Produto);
console.log(prateleira[0] instanceof Perecivel);
console.log(leite.constructor.name);

$ node prateleira.js

Leite 1 L: R$ 5.49 (vence em 25/10)
Caneta da loja: grátis!

true
false
Perecivel

A mesma linha de código produziu três textos diferentes. Esse "cada um responde do seu jeito à mesma pergunta" tem um nome chique: polimorfismo ("muitas formas"). O for … of é o da aula Percorrendo com for … of.
leite instanceof Perecivel → true
instanceof ("é instância de") pergunta: "este objeto foi criado por esta classe, ou por uma filha dela?". O leite foi criado com new Perecivel: true.
leite instanceof Produto → true
O leite também é um Produto, porque Perecivel é filha de Produto. É a frase "todo perecível é um produto" virando código.
prateleira[0] instanceof Perecivel → false
O arroz é um produto comum. Nem todo produto é perecível: a herança vale de baixo para cima, nunca de cima para baixo.
leite.constructor.name → Perecivel
O nome da classe que criou o objeto, como texto. Útil para mostrar em mensagens.

5. Herança em vários níveis

A filha também pode ter filhas. O sorvete é um perecível (tem validade) que precisa de freezer. A classe Congelado estende Perecivel, que estende Produto:

// (Produto e Perecivel da seção 3 vêm aqui em cima)

class Congelado extends Perecivel {
  constructor(nome, preco, validade, temperatura) {
    super(nome, preco, validade);
    this.temperatura = temperatura;
  }

  descrever() {
    return `${super.descrever()} [guardar a ${this.temperatura} °C]`;
  }
}

const sorvete = new Congelado("Sorvete 2 L", 24.9, "10/03", -18);
console.log(sorvete.descrever());
console.log(sorvete instanceof Congelado, sorvete instanceof Perecivel, sorvete instanceof Produto);
console.log(sorvete);

$ node congelado.js
Sorvete 2 L: R$ 24.90 (vence em 10/03) [guardar a -18 °C]
true true true
Congelado {
  nome: 'Sorvete 2 L',
  preco: 24.9,
  validade: '10/03',
  temperatura: -18
}

Siga o caminho do sorvete.descrever():

  1. O descrever() do Congelado chama super.descrever(), que é o do Perecivel (a mãe imediata).
  2. O do Perecivel chama o seu super.descrever(), que é o do Produto: devolve Sorvete 2 L: R$ 24.90.
  3. O Perecivel acrescenta (vence em 10/03) e devolve.
  4. O Congelado acrescenta [guardar a -18 °C] e devolve o texto inteiro.

Com o construtor é igual: o super(nome, preco, validade) do Congelado chama o construtor do Perecivel, que chama o do Produto. (O objeto agora tem 4 propriedades e o Node passou a mostrar uma por linha: ele faz isso quando a linha ficaria comprida demais.)

Até quantos níveis?

O JavaScript não tem limite, mas cadeias longas ficam difíceis de seguir: para entender o Congelado você precisa abrir três classes. Na prática, 2 ou 3 níveis já é bastante.

6. Herdando de uma classe pronta: o seu próprio tipo de erro

Dá para estender as classes que já vêm com o JavaScript. A mais útil para começar é Error (aula Lançando Erros): a Ana cria um erro só da lojinha, que carrega o nome do produto que acabou.

class ErroDeEstoque extends Error {
  constructor(produto) {
    super(`acabou o estoque de ${produto}`);
    this.name = "ErroDeEstoque";
    this.produto = produto;
  }
}

try {
  throw new ErroDeEstoque("Leite 1 L");
} catch (erro) {
  console.log(erro.name);
  console.log(erro.message);
  console.log(erro.produto);
  console.log(erro instanceof ErroDeEstoque, erro instanceof Error);
}

throw new ErroDeEstoque("Pão de queijo");

Formas diferentes de fazer a mesma coisa

O jeito antigo: função construtora e prototype

As classes chegaram ao JavaScript em 2015 (o ES6). Antes disso, a herança era montada à mão. Você ainda vai encontrar este estilo em código antigo e em respostas velhas da internet:

function Produto(nome, preco) {
  this.nome = nome;
  this.preco = preco;
}
Produto.prototype.descrever = function () {
  return this.nome + ": R$ " + this.preco.toFixed(2);
};

function Perecivel(nome, preco, validade) {
  Produto.call(this, nome, preco);
  this.validade = validade;
}
Perecivel.prototype = Object.create(Produto.prototype);
Perecivel.prototype.constructor = Perecivel;

const leite = new Perecivel("Leite 1 L", 5.49, "25/10");
console.log(leite.descrever());
console.log(leite instanceof Produto);

$ node antigo.js
Leite 1 L: R$ 5.49
true

O resultado é o mesmo, mas veja quanta coisa: o Produto.call(this, …) faz o papel do super(…), e as duas linhas com prototype fazem o papel do extends. O class … extends faz exatamente isso por baixo dos panos, de um jeito mais curto e com menos chance de erro. O que é esse tal de prototype é o assunto da aula Protótipos, e o call aparece em this, call, apply e bind. Em código novo, use class e extends.

Sem herança: um objeto dentro do outro (composição)

Nem toda relação é "é um". Um item do carrinho não é um produto: ele tem um produto e uma quantidade. Para "tem um", em vez de extends, guarde o outro objeto numa propriedade:

// (Produto da seção 1 vem aqui em cima)

class ItemDoCarrinho {
  constructor(produto, quantidade) {
    this.produto = produto;
    this.quantidade = quantidade;
  }

  total() {
    return this.produto.preco * this.quantidade;
  }
}

const item = new ItemDoCarrinho(new Produto("Leite 1 L", 5.49), 3);
console.log(item.produto.descrever());
console.log(`Total: R$ ${item.total().toFixed(2)}`);

$ node composicao.js
Leite 1 L: R$ 5.49
Total: R$ 16.47

Os programadores costumam dizer "prefira composição à herança": junte objetos pequenos em vez de criar árvores grandes de classes. Herança é ótima quando a frase "todo X é um Y" é verdadeira de fato.

SituaçãoQual usar
"Todo X é um Y, com algo a mais" (perecível é um produto; gerente é um funcionário)class X extends Y
"X tem um Y" (item do carrinho tem um produto; turma tem alunos)Composição: guardar o Y numa propriedade do X
Um tipo de erro só seu, reconhecível no catchclass MeuErro extends Error
Ler código antigo (antes de 2015)Reconhecer Mae.call(this, …) e Filha.prototype = Object.create(Mae.prototype); não escrever assim

class Funcionario {

Resumo

  • class Filha extends Mae cria uma classe que herda tudo da mãe. Use quando a frase "todo X é um Y" for verdadeira.
  • No construtor da filha, super(…) roda o construtor da mãe e tem de vir antes de qualquer this. Se a filha não tem nada novo para guardar, ela nem precisa de construtor.
  • Um método da filha com o mesmo nome sobrescreve o da mãe; super.metodo() chama o da mãe para aproveitar o que ela já faz.
  • instanceof responde se um objeto é de uma classe ou de uma filha dela.
  • Dá para estender classes prontas, como Error, para ter erros com nome próprio.
  • O extends faz por baixo o que o código antigo fazia com prototype e Mae.call(this) (aula Protótipos). Para "tem um", prefira composição.
