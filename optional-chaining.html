JavaScript ?. e ?? (Valores que Podem Faltar)

Dados do mundo real vêm incompletos: o cliente que não informou o endereço, o produto sem foto, a configuração que a pessoa nunca mexeu. Tentar ler uma propriedade de algo que não existe derruba o programa com o erro mais comum do JavaScript: Cannot read properties of undefined. Dois operadores modernos resolvem isso: o ?. ("se existir", chamado optional chaining, encadeamento opcional) e o ?? ("senão, use este", chamado nullish coalescing). Os dois existem desde o ES2020.

Você vai aprender
  • Por que bia.endereco.cidade dá erro quando a Bia não tem endereço.
  • O ?. com propriedades, com colchetes (?.[0]) e com métodos (?.()).
  • O ?? para dar um valor reserva, e por que ele é diferente do || com 0 e "".
  • Os dois juntos, e os atalhos ??= e ||=.
  • Os erros reais: os que o ?. não evita e o ?? misturado com ||.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js.

A ideia: "se tiver, me passa; se não tiver, use este"

A Ana pede ao filho: "vê na gaveta se tem a chave do portão, e se tiver, me traz". Se a gaveta estiver vazia, ele volta de mãos vazias, e tudo bem. Isso é o ?.: "se o que está antes existir, continue; se não, pare e responda undefined, sem erro".

Ela completa: "se não tiver, traz a chave reserva do prego". Isso é o ??: "se o valor da esquerda estiver faltando (null ou undefined), use o da direita".

2. O ?.: "se existir, continue"

const ana = { nome: "Ana", endereco: { cidade: "Recife" } };
const bia = { nome: "Bia" };
console.log(ana.endereco?.cidade);
console.log(bia.endereco?.cidade);
console.log("O programa continua.");
ana.endereco
O JavaScript lê o endereço normalmente.
?.
Olha o que veio antes. Se for null ou undefined, para tudo e a expressão inteira vale undefined. Se for qualquer outra coisa, funciona como um ponto comum.
cidade
Só é lida se o endereço existir.
$ node interrogacao.js
Recife
undefined
O programa continua.

Antes do ?., isso se escrevia com && (veja Operadores Lógicos): bia.endereco && bia.endereco.cidade, que no lab também deu undefined. Funciona, mas repete o caminho, e fica enorme com vários níveis.

Vários níveis

Ponha um ?. em cada passo que pode faltar:

const pedidos = {
  ana: { entrega: { endereco: { rua: "Rua das Flores" } } },
};
console.log(pedidos.ana?.entrega?.endereco?.rua);
console.log(pedidos.bia?.entrega?.endereco?.rua);

$ node cadeia.js
Rua das Flores
undefined

No segundo, pedidos.bia é undefined; o primeiro ?. já para tudo, e o resto da linha nem é avaliado.

Com colchetes: ?.[ ]

Para posições de array e nomes guardados em variáveis, o ponto de interrogação vem antes dos colchetes, com o ponto: ?.[.

const turmas = { manha: ["Ana", "Bia"] };
console.log(turmas.manha?.[0]);
console.log(turmas.noite?.[0]);
const campo = "manha";
console.log(turmas?.[campo]?.length);

3. O ??: "se estiver faltando, use este"

a ?? b devolve a, a não ser que a seja null ou undefined; aí devolve b. Só esses dois valores contam como "faltando" (em inglês, nullish, "nulos").

const config = { tema: null, fonte: 0, nome: "" };
console.log(config.tema ?? "claro");
console.log(config.cor ?? "azul");
console.log(config.fonte ?? 16);
console.log(config.nome ?? "Visitante");

$ node nullish.js
claro      « tema era null: usou a reserva
azul       « cor não existe (undefined): usou a reserva
0          « fonte é 0, um valor de verdade: ficou com ele
           « nome é "" (texto vazio): também ficou (por isso a linha em branco)

?? × ||

Em código mais antigo, o valor reserva se escreve com || ("ou"). A diferença: o || troca qualquer valor falsy (veja Truthy e Falsy): 0, "", false, NaN, null, undefined. O mesmo objeto, com ||:

const config = { tema: null, fonte: 0, nome: "" };
console.log(config.tema || "claro");
console.log(config.fonte || 16);
console.log(config.nome || "Visitante");

$ node ou.js
claro
16          « a fonte 0 virou 16!
Visitante
Valor da esquerdavalor ?? "reserva"valor || "reserva"
undefined"reserva""reserva"
null"reserva""reserva"
00"reserva"
"""""reserva"
falsefalse"reserva"
"Ana", 42o próprio valoro próprio valor

Qual usar? Quando 0, "" ou false são respostas válidas (quantidade zero, desconto zero, "não quero som"), use ??. Quando você quer trocar também o texto vazio (um nome que a pessoa deixou em branco vira "Visitante"), o || é o certo.

4. Os dois juntos

A combinação mais comum do JavaScript moderno: ?. para chegar ao valor sem erro, ?? para trocar o undefined por algo que faça sentido.

const clientes = [
  { nome: "Ana", endereco: { cidade: "Recife" } },
  { nome: "Bia" },
  { nome: "Caio", endereco: { cidade: null } },
];
for (const cliente of clientes) {
  const cidade = cliente.endereco?.cidade ?? "cidade não informada";
  console.log(`${cliente.nome}: ${cidade}`);
}

$ node juntos.js
Ana: Recife
Bia: cidade não informada       « sem endereço: o ?. deu undefined
Caio: cidade não informada      « com endereço, mas cidade null

Atalhos de atribuição: ??= e ||= ES2021

x ??= valor quer dizer "se x estiver faltando, dê a ele este valor" (é o mesmo que x = x ?? valor). O ||= faz o mesmo com a regra do ||.

const config = { tema: "escuro", fonte: 0 };
config.tema ??= "claro";
config.som ??= true;
config.fonte ||= 16;
console.log(config);

$ node atribuir.js
{ tema: 'escuro', fonte: 16, som: true }

O tema já tinha valor e ficou; o som não existia e ganhou true; a fonte era 0, que para o ||= conta como falso, e virou 16.

Formas diferentes de fazer a mesma coisa

ObjetivoModernoAntigo
Ler a.b.c sem quebrar se a.b faltara.b?.ca.b && a.b.c ou um if
Valor reserva só para null/undefinedx ?? "padrão"x !== null && x !== undefined ? x : "padrão"
Valor reserva para qualquer falsyx || "padrão"(o mesmo)
Preencher só se faltarx ??= "padrão"if (x === undefined || x === null) x = "padrão";
Valor reserva num parâmetrofunction f(x = "padrão")Aula Parâmetros Padrão
Não espalhe ?. por tudo

Use ?. só onde faltar é normal (o endereço é opcional no cadastro). Se um valor tem de existir, um ?. ali só esconde o problema: o programa segue com undefined e quebra mais adiante, longe da causa. Um erro na hora certa é mais fácil de achar.

Quando dá errado

Usou ?. numa variável que nem foi criada 
console.log(cliente?.nome);

$ node naodeclarada.js
/home/ana/naodeclarada.js:1
console.log(cliente?.nome);
            ^

    at Object.<anonymous> (/home/ana/naodeclarada.js:1:13)    « (mais 7 linhas node:internal cortadas)

Node.js v24.22.0

"cliente não está definida". O ?. protege contra um valor undefined, não contra uma variável que não existe (não foi criada com const/let). É outro tipo de erro, ReferenceError, e quase sempre é um nome digitado errado. Como consertar: crie a variável, ou confira a grafia.

Misturou ?? com || sem parênteses 
const apelido = null;
const nome = "";
const exibir = apelido ?? nome || "Visitante";
console.log(exibir);

$ node misturar3.js
/home/ana/misturar3.js:3

                               ^^

SyntaxError: Unexpected token '||'
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)    « (mais 7 linhas node:internal cortadas)

Node.js v24.22.0

"Símbolo || inesperado". A linguagem proíbe juntar ?? com || ou && sem parênteses, para ninguém ter de adivinhar qual vem primeiro. Se a mesma mistura estiver dentro de um console.log(…), a mensagem engana: no lab saiu SyntaxError: missing ) after argument list ("falta ) depois da lista de argumentos"). Como consertar: diga a ordem com parênteses: (apelido ?? nome) || "Visitante" (no lab, Visitante).

Usou ?. do lado esquerdo do = 
const cliente = {};
cliente.endereco?.cidade = "Recife";

$ node esquerda.js
/home/ana/esquerda.js:2

^^^^^^^^^^^^^^^^^^^^^^^^

SyntaxError: Invalid left-hand side in assignment
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)    « (mais 7 linhas node:internal cortadas)

Node.js v24.22.0

"Lado esquerdo inválido na atribuição". O ?. serve para ler; não dá para guardar algo "se existir". Como consertar: crie o objeto que falta antes: cliente.endereco ??= {}; e depois cliente.endereco.cidade = "Recife";.

?.() em algo que existe, mas não é função 
const loja = { nome: "Lojinha", saudar: "Olá" };
console.log(loja.saudar?.());

$ node naofuncao.js

                         ^

    at Object.<anonymous> (/home/ana/naofuncao.js:2:26)    « (mais 7 linhas node:internal cortadas)

O ?.() só pula a chamada quando o valor é null/undefined. Aqui saudar existe, só que é um texto, e um texto não pode ser chamado. Como consertar: confira o tipo com typeof loja.saudar === "function" (veja typeof), ou corrija o objeto.

Missão final: o carrinho da lojinha

Missão: o programa quebra no Café (que não tem promo) e mostra a quantidade errada no Leite (o 0 virou 1). Use ?. e troque o || certo por ?? para sair: Pão: 10 un. (sem desconto), Leite: 0 un. (desconto de 5%) e Café: 1 un. (sem desconto).

const carrinho = [
  { nome: "Pão", quantidade: 10, promo: { desconto: null } },
  { nome: "Leite", quantidade: 0, promo: { desconto: 5 } },
  { nome: "Café" },
];
for (const item of carrinho) {
  const quantidade = item.quantidade || 1;
  const desconto = item.promo.desconto;
  const texto = desconto ? `desconto de ${desconto}%` : "sem desconto";
  console.log(`${item.nome}: ${quantidade} un. (${texto})`);
}

const carrinho = [
  { nome: "Pão", quantidade: 10, promo: { desconto: null } },
  { nome: "Leite", quantidade: 0, promo: { desconto: 5 } },
  { nome: "Café" },
];
for (const item of carrinho) {
  const quantidade = item.quantidade ?? 1;
  const desconto = item.promo?.desconto;
  const texto = desconto ? `desconto de ${desconto}%` : "sem desconto";
  console.log(`${item.nome}: ${quantidade} un. (${texto})`);
}

Resumo

  • Ler uma propriedade de undefined ou null dá TypeError: Cannot read properties of undefined.
  • a?.b lê b só se a existir; senão, a expressão inteira vale undefined. Também há ?.[i] e ?.().
  • a ?? b usa b só quando a é null ou undefined; a || b usa b para qualquer falsy, inclusive 0 e "".
  • valor?.caminho ?? "reserva" é a dupla do dia a dia. ??= preenche só o que falta.
  • ?. não salva de variável inexistente, não serve antes de =, e ?? com || exige parênteses.
