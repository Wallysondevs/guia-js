JavaScript Versões (ECMAScript, ES6, Node)

Em tutoriais e vagas de emprego aparecem siglas como "ES6", "ES2015", "ES2025", "Node 24 LTS". Parecem coisas diferentes, mas contam uma história só: a linguagem JavaScript ganha uma edição nova por ano, e cada programa que roda JavaScript (o Chrome, o Firefox, o Node…) vai aprendendo as novidades no seu próprio ritmo. Esta aula explica essas versões, para você saber o que pode usar, onde, e o que fazer quando um recurso "não existe" no computador de alguém.

Você vai aprender
  • A diferença entre JavaScript e ECMAScript, e quem decide o que entra na linguagem.
  • A linha do tempo: ES3, ES5, o grande ES6 (ES2015) e as edições anuais até o ES2026.
  • O que é um motor de JavaScript (V8, SpiderMonkey, JavaScriptCore).
  • Como funcionam as versões do Node.js: Current, LTS, fim de vida, e onde estão o Node 24 e o Node 26.
  • Como ver a sua versão e como o programa pode conferir se um recurso existe antes de usar.

Os comandos desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook). As datas vêm das páginas oficiais: a da Ecma International (o padrão ECMA-262), a do TC39 e a do Node.js (nodejs.org/about/previous-releases e o calendário do repositório nodejs/Release), conferidas em outubro de 2026.

A ideia: a gramática e quem fala a língua

O português tem as regras dele, escritas em gramáticas e atualizadas de tempos em tempos (o último acordo ortográfico, por exemplo). Cada pessoa aprende as regras novas no seu ritmo: uns já escrevem "ideia" sem acento, outros ainda não. Com o JavaScript é igual:

  • ECMAScript é a "gramática": o documento oficial com as regras da linguagem, chamado ECMA-262, publicado pela Ecma International (uma organização de padrões, como a ABNT).
  • JavaScript é o nome do dia a dia da linguagem que segue essas regras.
  • Os motores são "quem fala a língua": os programas dentro do navegador e do Node que leem e rodam o seu código. Cada um aprende as regras novas no seu próprio ritmo.

Na prática, "JavaScript" e "ECMAScript" são usados como sinônimos. "ES" é a abreviação de ECMAScript: ES2025 quer dizer "a edição de 2025 das regras".

1. Quem decide: o TC39

As novidades da linguagem são decididas por um comitê chamado TC39 (Technical Committee 39), com gente das empresas que fazem navegadores, de empresas que usam muito JavaScript e da comunidade. Toda ideia nova vira uma proposta e passa por etapas (stages), de 0 a 4:

EtapaO que quer dizer
Stage 0 e 1Uma ideia, e depois uma proposta com um problema bem descrito
Stage 2O comitê escolheu uma solução e está detalhando
Stage 2.7Texto aprovado, faltam os testes
Stage 3Pronta: os motores começam a implementar
Stage 4Terminada: funciona em pelo menos dois motores e entra na próxima edição anual

Por isso, muitas vezes um recurso já funciona no Chrome ou no Node antes de "sair" oficialmente na edição do ano: os motores implementam no stage 3, e a edição só "carimba" o que chegou ao stage 4. A lista de propostas terminadas, com o ano de cada uma, fica em github.com/tc39/proposals.

Repare na mudança de nome: até o ES6, as edições tinham número; a partir dele, passaram a ter o ano, uma por ano, publicadas todo mês de junho. "ES6" e "ES2015" são a mesma coisa; o nome "ES6" pegou porque a mudança foi enorme, e até hoje se fala em "JavaScript moderno (ES6+)" para dizer "com let, const, arrow functions e companhia". Os destaques de cada ano mais recente estão em Novidades Recentes.

Nada é removido

Uma regra de ouro do JavaScript: não quebrar a web. Código de 1999 ainda roda num navegador de hoje. Por isso o var e o == continuam existindo, mesmo com coisas melhores no lugar. As edições novas só acrescentam.

3. Os motores

O motor (em inglês, engine) é a parte do programa que lê e roda o JavaScript. Os principais:

MotorQuem fazOnde está
V8GoogleChrome, Edge, Opera, Node.js, Deno
SpiderMonkeyMozillaFirefox
JavaScriptCoreAppleSafari (e todos os navegadores do iPhone), Bun

O Node.js é, por dentro, o motor V8 com os módulos do Node em volta (fs, process…). Então o que o Node sabe da linguagem depende da versão do V8 que veio com ele:

$ node -v
v24.22.0
$ node -p process.versions.v8
13.6.233.17-node.57

O node -p ("imprimir") roda um pedaço de JavaScript e mostra o resultado. O Node 24.22 da Ana traz o V8 13.6. O Chrome que você usa pode ter um V8 mais novo e, por isso, conhecer recursos que o Node 24 ainda não conhece (e vice-versa).

4. As versões do Node.js

Uma versão do Node tem três números, como 24.22.0:

24
A versão principal (major). Muda uma ou duas vezes por ano e pode trazer mudanças que quebram programas antigos.
22
A versão secundária (minor): recursos novos que não quebram nada.
0
A correção (patch): só conserta defeitos.

Esse jeito de numerar se chama versionamento semântico (semver), e é o mesmo dos pacotes do npm.

Current, LTS e fim de vida

Cada versão principal passa por fases:

FaseO que quer dizer
Current ("atual")Os primeiros 6 meses: recebe novidades o tempo todo. Bom para experimentar.
Active LTSLong-Term Support, "suporte de longo prazo": estável, recomendada para programas de verdade. Ganha um apelido (o do Node 24 é Krypton).
Maintenance LTS"Manutenção": só correções importantes e de segurança.
EOL (end of life)"Fim de vida": não recebe mais nem correção de segurança. Hora de atualizar.

Até o Node 26, a regra era: duas versões principais por ano; as pares (20, 22, 24, 26) viram LTS, e as ímpares (21, 23, 25) duram só 6 meses. O LTS garante correções por cerca de 30 meses no total. As datas das versões em uso hoje, segundo o calendário oficial:

O que isso quer dizer para você, em outubro de 2026:

  • O Node 24, usado neste guia, é LTS e entra em manutenção em 20 de outubro de 2026: continua recebendo correções de segurança até abril de 2028. É uma escolha segura.
  • O Node 26 está na fase Current e vira LTS em 28 de outubro de 2026. A partir daí, ele passa a ser a LTS mais nova, recomendada para projetos novos. Tudo o que este guia ensina funciona nele também.
  • O Node 20 e o Node 25 já chegaram ao fim de vida: se você encontrar um computador com eles, atualize.
A mudança a partir do Node 27

A página oficial do Node anuncia um calendário novo: a partir do Node 27, sai uma versão principal por ano, e todas viram LTS, depois de 6 meses de fase Alpha (testes) e 6 meses de Current. Pelo calendário, o Node 27 começa em fase Alpha em 28/10/2026 e é lançado em abril de 2027. Ou seja: a regra "par é LTS, ímpar não" termina no Node 26.

O node -v ("versão") é o jeito rápido. O process.release mostra o apelido da LTS (lts: 'Krypton'); numa versão Current, esse campo não aparece. O npm tem a versão dele, separada (o npm 11 vem junto com o Node 24). Dentro de um programa, a versão está em process.version ('v24.22.0') e em process.versions.node ('24.22.0', sem o v):

$ node -p "process.versions.node.split('.')"
[ '24', '22', '0' ]

5. "Esse recurso existe aqui?"

Como cada motor aprende no seu ritmo, um recurso novo pode faltar no computador de alguém. O Math.sumPrecise (soma sem os errinhos de arredondamento do 0.1 + 0.2) entrou no ES2026, mas o V8 do Node 24 ainda não o tem:

const valores = [0.1, 0.2, 0.3];
console.log(Math.sumPrecise(valores));

$ node soma-precisa.js
/home/ana/soma-precisa.js:2
console.log(Math.sumPrecise(valores));
                 ^

TypeError: Math.sumPrecise is not a function
    at Object.<anonymous> (/home/ana/soma-precisa.js:2:18)
    at Module._compile (node:internal/modules/cjs/loader:1929:14)  « linhas internas do Node cortadas
    …

Node.js v24.22.0

"Math.sumPrecise não é uma função": no Node 24, Math.sumPrecise é undefined, e chamar undefined(…) dá esse erro. É o sintoma típico de usar um recurso mais novo que o motor. Três jeitos de lidar:

  1. Conferir antes de usar, com typeof: if (typeof Math.sumPrecise === "function") { … } else { … }. Isso se chama detecção de recurso.
  2. Consultar a tabela de compatibilidade: no fim de cada página da MDN (developer.mozilla.org) há uma tabela dizendo em que versão de cada navegador e do Node o recurso chegou.
  3. Avisar a versão mínima no package.json, com o campo "engines" (veja Quando dá errado).

Missão: este programa quebra onde o Math.sumPrecise não existe (como no Node 24). Use a detecção de recurso: se typeof Math.sumPrecise === "function", use ele; senão, some com o reduce (já escrito no comentário). O programa tem de mostrar Total: 42.5 em qualquer motor.

const valores = [10, 20, 12.5];

// plano B: valores.reduce((soma, v) => soma + v, 0)
const total = Math.sumPrecise(valores);

console.log(`Total: ${total}`);

const valores = [10, 20, 12.5];

let total;
if (typeof Math.sumPrecise === "function") {
  total = Math.sumPrecise(valores);
} else {
  total = valores.reduce((soma, v) => soma + v, 0);
}

console.log(`Total: ${total}`);

(O editor do guia usa o motor do seu navegador: dependendo dele, o Math.sumPrecise pode existir ou não aí. A detecção funciona nos dois casos; por isso a missão usa números que dão o mesmo total nos dois caminhos.)

Qual versão usar?

SituaçãoO que escolher
Aprender, ou um projeto novoA LTS mais recente (Node 24; Node 26 a partir de 28/10/2026)
Um servidor ou programa em produçãoUma LTS (Active ou Maintenance); nunca uma versão em fim de vida
Experimentar o que vem por aíA versão Current

Quando dá errado

… is not a function num método que "existe" na documentação

Como o Math.sumPrecise acima: o recurso é novo demais para o motor. Isso também acontece ao contrário: um tutorial recente usa toSorted (ES2023), e um Node 18 antigo responde TypeError: lista.toSorted is not a function (ilustrativo; o lab tem o Node 24, onde ele existe). Como consertar: confira a tabela de compatibilidade da MDN, atualize o Node, ou use detecção de recurso.

O projeto pede uma versão do Node mais nova que a sua

A Ana criou um projeto que exige o Node 26 (npm pkg set engines.node=">=26", que grava "engines": { "node": ">=26" } no package.json) e rodou o npm install no Node 24:

$ npm install
npm warn EBADENGINE Unsupported engine {
npm warn EBADENGINE   package: 'motor@1.0.0',

Um aviso (warn): "motor não suportado: o pacote motor@1.0.0 exige Node >=26; o atual é o v24.22.0". Por padrão o npm só avisa e segue em frente. Com npm install --engine-strict ("motor estrito"), vira erro de verdade: npm error code EBADENGINE e Not compatible with your version of node/npm: motor@1.0.0, e nada é instalado. Como consertar: instale a versão pedida (veja Instalar o Node.js) ou, se o projeto é seu, ajuste o "engines".

"Funciona no meu computador!"

Duas pessoas com versões diferentes do Node podem ver resultados diferentes no mesmo código. Antes de pedir ajuda num fórum, mande o node -v junto. Em equipe, combine a versão (o "engines" no package.json, ou um arquivo .nvmrc com o número, lido por ferramentas como o nvm).

Missão final: lendo um número de versão

Missão: complete a função principal para devolver a versão principal (o primeiro número) de um texto como "v24.22.0", como número. Dica: tire o v com slice(1), separe nos pontos com split("."), pegue o primeiro pedaço e converta com Number.

function principal(versao) {
  // complete aqui
}

for (const v of ["v24.22.0", "v26.0.0", "v18.20.8"]) {
  console.log(`${v}: versão principal ${principal(v)}`);
}

function principal(versao) {
  return Number(versao.slice(1).split(".")[0]);
}

for (const v of ["v24.22.0", "v26.0.0", "v18.20.8"]) {
  console.log(`${v}: versão principal ${principal(v)}`);
}

No lab, a solução mostrou v24.22.0: versão principal 24, v26.0.0: versão principal 26 e v18.20.8: versão principal 18. Num programa de verdade, passe process.version para a função e você tem a versão principal do Node que está rodando.

Resumo

  • ECMAScript (ECMA-262) é o padrão oficial; JavaScript é o nome do dia a dia. O TC39 decide as novidades, que passam pelos stages 0 a 4.
  • ES5 (2009) trouxe o modo estrito e o JSON; o ES6 = ES2015 trouxe o JavaScript moderno; desde então, uma edição por ano, até o ES2026 (junho de 2026). Nada é removido.
  • Os motores (V8, SpiderMonkey, JavaScriptCore) aprendem as novidades no seu ritmo; o Node 24 usa o V8 13.6.
  • Versões do Node: principal.secundária.correção; fases Current → LTS → Manutenção → fim de vida. Node 24 (Krypton) é LTS até abril de 2028; o Node 26 vira LTS em 28/10/2026; a partir do Node 27, uma versão por ano, todas LTS.
  • node -v, npm -v, process.version. Recurso que não existe dá … is not a function: use detecção de recurso (typeof) e a tabela de compatibilidade da MDN.
