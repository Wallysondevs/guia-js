JavaScript Onde Roda

Na Introdução você viu que o JavaScript roda em dois lugares: dentro do navegador (Chrome, Edge, Firefox, Safari) e no terminal, com o Node.js. Esta aula mostra o que é igual nos dois, o que só existe num deles, e o que acontece quando você usa uma coisa do navegador no Node (ou o contrário). Saber isso evita muita confusão quando você copiar exemplos da internet.

Você vai aprender
  • Que a linguagem é a mesma no navegador e no Node.js, e o que muda é o ambiente em volta dela.
  • O que é só do navegador: a página (document), as janelinhas (alert), a janela (window).
  • O que é só do Node.js: os arquivos (node:fs), o programa em execução (process).
  • Como descobrir onde o código está rodando, com typeof e globalThis.
  • Os erros reais: alert is not defined, document is not defined, process is not defined.
  • Onde este guia usa cada um.

As saídas de terminal desta aula foram colhidas com o Node.js 24 LTS na máquina fictícia da Ana (ana@notebook). As caixas "Experimente" de página (com o quadro Resultado) rodam no seu próprio navegador.

A ideia: a mesma língua, cômodos diferentes

A Ana fala português na cozinha e no escritório. A língua é a mesma nos dois lugares: as mesmas palavras, a mesma gramática. O que muda são as coisas à mão: na cozinha tem fogão e geladeira; no escritório tem impressora e arquivo de papéis. Se ela pedir "liga o fogão" no escritório, ninguém sabe do que ela está falando.

Com o JavaScript é igual. A linguagem (as contas, os textos, o if, o for, as funções) é a mesma em todo lugar: é o padrão ECMAScript. Mas cada lugar onde ela roda, chamado de ambiente (em inglês, runtime ou host, "anfitrião"), oferece as suas próprias ferramentas:

Na casa da AnaNo JavaScript
A língua portuguesaA linguagem JavaScript (ECMAScript): igual em todo lugar
A cozinha, com fogãoO navegador, com a página (document) e as janelinhas (alert)
O escritório, com o arquivo de papéisO Node.js, com os arquivos do computador (fs) e o terminal (process)

1. A mesma linguagem nos dois lugares

Este programa só usa a linguagem e o console.log, que os dois ambientes têm:

console.log(2 + 3);

3. O que é só do Node.js

No Node.js não há página nem janelinha, mas há o computador: os arquivos, as pastas, o terminal. Este programa cria um arquivo de verdade na pasta da Ana, lê de volta o que escreveu e diz em que sistema está rodando:

import fs from "node:fs";

fs.writeFileSync("recado.txt", "Comprar pão");
console.log("Arquivo criado!");
console.log(fs.readFileSync("recado.txt", "utf8"));
console.log(process.platform);

$ node so-node.js
Arquivo criado!
Comprar pão
linux
$ cat recado.txt; echo
Comprar pão
import fs from "node:fs";
Traz para o programa o módulo fs (de file system, "sistema de arquivos"), que vem com o Node.js. O node: na frente deixa claro que é um módulo do próprio Node. Módulos têm aula própria: Módulos.
fs.writeFileSync("recado.txt", "Comprar pão");
Escreve o texto Comprar pão num arquivo chamado recado.txt, na pasta onde o programa rodou (a pasta da Ana). Se o arquivo não existe, ele é criado.
fs.readFileSync("recado.txt", "utf8")
Lê o arquivo e devolve o conteúdo como texto (o "utf8" diz como as letras estão gravadas). O console.log mostra esse texto.
process.platform
O process é o programa que está rodando agora; platform diz o sistema operacional: linux na máquina da Ana (no Windows sairia win32; no macOS, darwin).
$ cat recado.txt; echo
Prova de que o arquivo existe de verdade: o comando cat do terminal mostrou o conteúdo dele. (O echo só pula a linha, porque o recado não terminava com uma quebra de linha.)

Um site não pode fazer isso: imagine se qualquer página que você visita pudesse ler e apagar os arquivos do seu computador! Por segurança, o navegador não deixa. O Node.js deixa porque é um programa que você rodou, de propósito, no seu computador. Os arquivos têm aulas próprias, no nível 3 (Lendo Arquivos).

Missão: o programa grava pão no arquivo lista.txt. Mude o texto para que a lista tenha também leite (por exemplo, "pão e leite") e rode.

import fs from "node:fs";

fs.writeFileSync("lista.txt", "pão");
console.log(fs.readFileSync("lista.txt", "utf8"));

Na caixa "Experimente", o arquivo é criado numa pasta de mentira, só da caixa: o editor do guia imita o Node.js, e o seu computador não é tocado.

5. Descobrindo onde o código está rodando

O operador typeof ("tipo de") diz o tipo de um valor. Para um nome que não existe, em vez de erro, ele responde "undefined" ("indefinido"). Isso permite perguntar, sem quebrar o programa, se o ambiente tem uma coisa:

console.log(typeof window);
console.log(typeof document);
console.log(typeof process);

$ node onde.js
undefined
undefined
object

No Node.js, window e document não existem (undefined), e o process existe (object, um "objeto"). No navegador, a resposta se inverte. Rode na caixa abaixo e compare o Console:

Experimente: as mesmas três linhas, agora no navegador.

<p>Veja o Console.</p>
<script src="script.js"></script>

console.log(typeof window);
console.log(typeof document);
console.log(typeof process);

O nome que vale nos dois: globalThis

Cada ambiente tem o seu "objeto global", a caixa onde ficam os nomes que existem em todo o programa: no navegador ele se chama window; no Node.js, global. Para não precisar saber qual é, o ECMAScript 2020 criou um nome que funciona nos dois: globalThis ES2020.

console.log(typeof globalThis);
console.log(globalThis === global);

$ node global.js
object
true

O true ("verdadeiro") confirma: no Node.js, globalThis e global são a mesma coisa. Você vai usar isso pouco no começo; o importante é reconhecer o nome.

Quando dá errado

Quase todos os erros desta aula têm a mesma causa: uma coisa de um ambiente usada no outro. A mensagem é sempre um ReferenceError ("erro de referência": um nome que não existe ali).

alert no Node.js 
console.log("Antes do alert");
alert("Bom dia, Ana!");
console.log("Depois do alert");

$ node alerta.js
Antes do alert

^

ReferenceError: alert is not defined
    at Object.<anonymous> (/home/ana/alerta.js:2:1)

Node.js v24.22.0

"alert não está definido": o Node.js não tem janelinhas.

E a linha 3 nunca rodou: o erro derrubou o programa, e "Depois do alert" não apareceu. Como consertar: no Node.js, para mostrar um recado, use console.log; para perguntar alguma coisa, veja Lendo o Teclado no Node.

A Ana copiou de um tutorial uma linha que muda o título da página. No Node.js não há página, então não há document. Como consertar: código com document vai numa página, carregado por um <script> (ou numa caixa "Experimente" com o quadro Resultado, aqui no guia), nunca no node arquivo.js.

process no navegador

O contrário também acontece: o process é só do Node.js. Na página, ele não existe, e o erro aparece em vermelho no Console. A mensagem é a mesma do Node: process is not defined.

Missão: clique em Rodar e veja o erro no Console. Depois apague a linha que só funciona no Node.js e rode de novo, até o Console mostrar só Padaria aberta, sem erro.

<script src="script.js"></script>

console.log("Padaria aberta");
console.log(process.platform);

console.log("Padaria aberta");
Um exemplo da internet que não diz onde roda

Muitos tutoriais mostram código sem avisar se é para o navegador ou para o Node.js. Uma pista rápida: se aparece document, window, alert ou addEventListener, é de navegador; se aparece require, process, node:fs ou npm, é de Node.js. Se o código só tem contas, textos e console.log, roda nos dois.

Resumo

  • A linguagem JavaScript é a mesma em todo lugar; o ambiente (navegador ou Node.js) é que oferece ferramentas próprias.
  • Só do navegador: document, window, alert/prompt/confirm, localStorage. Só do Node.js: node:fs, process, require, npm.
  • O console.log existe nos dois: no Node.js escreve no terminal; no navegador, no Console (F12).
  • typeof nome diz "undefined" para um nome que não existe, sem erro; globalThis é o objeto global nos dois ambientes.
  • Usar uma coisa no ambiente errado dá ReferenceError: … is not defined e derruba o programa na linha do erro.
  • Neste guia: níveis 1 e 2 no Node.js (node arquivo.js); o grupo "A Página Web", no navegador.
