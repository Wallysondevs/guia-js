JavaScript O Editor do Guia

Em toda aula deste guia aparecem caixas Experimente: você escreve um programa em JavaScript, clica em Rodar e vê, logo embaixo, o que o programa fez. Quem roda o seu código é o JavaScript do seu próprio navegador (o Chrome, o Edge, o Firefox…), o mesmo que roda em qualquer site. Não precisa instalar nada. Nesta página você conhece os dois tipos de caixa, aprende a responder quando o programa pergunta alguma coisa, a parar um programa que não termina, e vê o que muda quando você roda o mesmo programa no Node.js, no terminal.

Você vai aprender
  • As partes da caixa de programa: o código, Rodar, o terminal da caixa, Restaurar, Ver solução e os atalhos do teclado.
  • Por que cada Rodar começa do zero.
  • Como responder quando o programa pergunta (o readline), as abas com vários arquivos e o modo interativo.
  • A caixa de página: o quadro Resultado e o Console.
  • Como aparecem os erros e como parar um programa que não termina.
  • Como funcionam as missões e o que muda no Node.js do terminal.

A ideia: uma bancada de treino dentro da página

Pense numa escola de culinária. O professor explica a receita no quadro, mas a aula só vale a pena quando cada aluno vai para a sua bancada e faz o bolo com as próprias mãos. Se o bolo desanda, tudo bem: a bancada é de treino, e no dia seguinte ela está limpa de novo.

O editor do guia é essa bancada. Ele tem dois tipos de caixa, porque o JavaScript vive em dois lugares:

CaixaImitaVocê vêUsada em
Programao comando node main.js no terminal da Anao terminal da caixa, com o que o programa escreveua linguagem (níveis 1 e 2) e o que é do Node (fs, process)
Páginauma página aberta no navegadoro quadro Resultado e o Console"A Página Web": DOM, eventos, localStorage, prompt

Tudo acontece no seu computador, dentro do navegador: o seu código não é enviado para lugar nenhum. E o programa roda separado da página (num Web Worker), então, mesmo que ele trave, a página do guia continua funcionando.

A caixa de programa

Esta é uma caixa livre, sem missão. Clique em ▶ Rodar:

const nome = "Ana";
console.log(`Olá, ${nome}!`);
console.log("Bem-vinda ao JavaScript.");

Aparece o terminal da caixa. Repare nas partes:

ana@notebook:~$ node main.js
O comando que o editor "digitou" por você: rodar o arquivo main.js com o Node.js, na pasta da Ana (~ = /home/ana). A Ana é a usuária das aulas, e o notebook é o computador dela.
Olá, Ana!
O que o programa escreveu com o console.log, uma linha por chamada.
[código de saída: 0]
Como o programa terminou: 0 quer dizer "terminou bem"; 1, que terminou com um erro. É o número que o terminal guarda depois de cada programa.

No computador da Ana, com o Node.js instalado, o mesmo programa dá a mesma resposta:

$ node main.js
Olá, Ana!
Bem-vinda ao JavaScript.

O console.log mostra objetos e listas do jeito do Node.js: textos dentro de um objeto aparecem com aspas simples, e há espaços dentro das chaves e dos colchetes. Rode:

const produto = { nome: "Pão de queijo", preco: 4.5, tags: ["salgado", "quente"] };
console.log(produto);

$ node main.js
{ nome: 'Pão de queijo', preco: 4.5, tags: [ 'salgado', 'quente' ] }

Cada Rodar começa do zero

Cada clique em Rodar é um node main.js novo, numa pasta /home/ana nova, só com os arquivos das abas da caixa. Uma variável do Rodar anterior não existe mais, e um arquivo que o programa gravou com o fs some quando você roda de novo. É a bancada limpa: nada do que você fez numa caixa atrapalha outra caixa, nem a próxima vez.

Quando o programa pergunta

Um programa pode pedir uma resposta com o módulo readline (aula Entrada pelo teclado). No editor, quando o programa pergunta, aparece um campo dentro do terminal da caixa: digite a resposta e tecle Enter. Experimente:

import * as readline from "node:readline/promises";
import { stdin as input, stdout as output } from "node:process";

const rl = readline.createInterface({ input, output });
const nome = await rl.question("Qual é o seu nome? ");
console.log(`Olá, ${nome}!`);
rl.close();
No campo do terminalO que acontece
Entermanda a linha para o programa (o que você digitou fica no terminal, em cinza)
Ctrl+D"fim da entrada": não há mais nada para ler (como no terminal de verdade)
Ctrl+C ou ■ Pararinterrompe o programa

Em algumas caixas há um campo Entrada embaixo do código: o que estiver nele vai para o programa de uma vez, como se viesse de um arquivo (node main.js < entrada.txt). E o campo Argumentos, quando aparece, é o que vem depois do nome do arquivo no comando: chega no programa em process.argv[2], process.argv[3]…

Vários arquivos: as abas

Quando a caixa tem mais de um arquivo, eles aparecem como abas em cima do código. A primeira (main.js) é a que roda; as outras ficam na mesma pasta, e o programa pode importá-las ou lê-las:

import { soma } from "./contas.js";

console.log("2 + 3 =", soma(2, 3));

export function soma(a, b) {
  return a + b;
}

O modo interativo

Algumas caixas têm o botão ▶ Abrir o node: é o modo interativo do Node.js (o REPL), que você abre no terminal digitando só node. Ele mostra o sinal > e espera uma linha de JavaScript; tecle Enter e ele mostra o resultado. Uma linha que ficou "aberta" (um { sem o }) continua na próxima, com o sinal | . Para sair: .exit ou Ctrl+D.

$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> 2 + 3
5
> const nome = "Ana"
undefined
> nome.toUpperCase()
'ANA'
> .exit

A caixa de página

Nas aulas sobre páginas web, a caixa tem as abas index.html (a página), script.js e às vezes style.css. Rodar abre a página no quadro Resultado, e embaixo dele aparece o Console: o que o console.log escreveu e os erros. Clique em Rodar e depois no botão do Resultado:

<h1>Padaria da Ana</h1>
<button id="botao">Quantos pães?</button>
<p id="saida"></p>
<script src="script.js"></script>

const botao = document.querySelector("#botao");
let paes = 0;

botao.addEventListener("click", () => {
  paes = paes + 12;
  document.querySelector("#saida").textContent = `Pães no forno: ${paes}`;
  console.log("Mais uma fornada:", { paes });
});

O Console do editor mostra o mesmo que o Console do navegador (a tecla F12, aula O Console do Navegador), no jeito do Chrome: {paes: 12}, sem os espaços que o Node.js põe. Erros aparecem em vermelho, com o arquivo e a linha (script.js:3:7). Na caixa de página não existe nada do Node: lá não há process, require nem fs, como num site de verdade. Já o prompt, o alert e o localStorage funcionam.

Quando dá errado

Erros fazem parte. Quando o programa tem um erro que ninguém tratou, o editor mostra a mensagem do jeito que o Node.js mostra, em vermelho, e o código de saída vira 1. Rode:

const preco = 4.5;
const quantidade = 3;
console.log("Total:", preco * quantidade);
console.log(totl);

O que o Node.js responde (no terminal da Ana, igual ao editor):

O que aconteceu, em inglês: "erro de referência: totl não está definido". Faltou uma letra: o certo é total… e a variável nem existe! As mensagens do Node.js saem sempre em inglês; as aulas traduzem cada uma.

O caminho até o erro: a primeira linha at é o seu código (main.js:4:13 = linha 4, coluna 13); as outras, com node:internal, são o Node.js por dentro e podem ser ignoradas.

Repare que o Total: 13.5 saiu: o programa rodou até a linha 4 e parou ali.

Num navegador que não é o Chrome ou o Edge (Firefox, Safari), o programa roda igual, mas o texto das mensagens de erro pode sair com outras palavras, porque esses navegadores têm outro motor de JavaScript. O Node.js usa o motor do Chrome (o V8). Nesses navegadores, a caixa avisa embaixo do código.

Um programa que não termina

Um laço sem fim (aula while) não trava a página: clique em ■ Parar. Se você não clicar, o editor para o programa sozinho depois de 10 segundos rodando (o tempo em que o programa espera você digitar não conta). Experimente e clique em Parar:

let voltas = 0;
while (true) {
  voltas++;
}

O que o editor não faz

  • Módulos do Node que precisam do computador de verdade: servidor web (node:http), rodar outros programas (child_process), rede (net). O editor avisa: O editor do guia não tem o módulo node:http. As aulas mostram esses com a saída do terminal.
  • npm install e pacotes de fora (require("lodash") dá Cannot find module 'lodash', como num computador sem o pacote).
  • Guardar arquivos: o fs funciona, mas numa pasta de mentira, que some no próximo Rodar.
  • O relógio da Ana: new Date() mostra a hora do seu computador. Os números e datas saem no jeito brasileiro (1.234,5, 31/12/2026), como no computador da Ana.

As missões

Muitas caixas têm uma Missão: um pedido, como "mude o programa para mostrar Olá, Ana!". Quando você roda, o editor confere o resultado e escreve, embaixo da caixa, ✔ Missão cumprida! ou uma dica do que ainda falta. Na caixa de página, a missão é conferida de novo a cada clique e tecla no Resultado. Experimente:

Missão: troque "mundo" por "Ana" e clique em Rodar.

console.log("Olá, mundo!");

console.log("Olá, Ana!");

Travou? Ver solução mostra uma resposta (há sempre mais de um jeito certo). Antes de olhar, releia a mensagem de erro: ela quase sempre diz a linha do problema.

O mesmo programa no terminal

Quando você instalar o Node.js (aula Instalando o Node.js), o mesmo programa roda no terminal: salve o código num arquivo main.js e digite node main.js. A saída é a mesma do editor, inclusive as mensagens de erro. O que muda:

AssuntoNo editorNo terminal
Arquivos gravados com fssomem no próximo Rodarficam na pasta, de verdade
Math.random(), new Date()mudam a cada Rodarmudam a cada vez também
Mensagens de erroiguais (no Chrome/Edge)as do Node.js

O fim do programaparado em 10 s se não terminarroda até você apertar Ctrl+C

Resumo

  • As caixas Experimente rodam o JavaScript do seu navegador; o seu código não sai do seu computador.
  • A caixa de programa imita o node main.js do Node.js v24.22.0: o terminal da caixa mostra o comando, a saída, os erros em vermelho (iguais aos do Node) e o código de saída. Cada Rodar começa do zero.
  • Restaurar volta ao código original; Ver solução (nas missões) pergunta antes de trocar o seu código. Ctrl+Enter roda.
  • Quando o programa pergunta, digite no campo do terminal e tecle Enter (Ctrl+D = fim da entrada). As abas são vários arquivos; Abrir o node é o modo interativo.
  • A caixa de página abre o index.html no quadro Resultado e mostra o Console do jeito do Chrome. Lá não existe nada do Node.
  • Um laço sem fim para com ■ Parar ou sozinho, em 10 segundos.
  • As missões conferem o resultado: ✔ Missão cumprida! quando dá certo.
