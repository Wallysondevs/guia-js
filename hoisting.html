JavaScript Hoisting

Você já deve ter percebido que o JavaScript roda o programa de cima para baixo, uma linha depois da outra. Então como este programa funciona, se ele chama saudar antes de a função aparecer? A resposta é o hoisting (em inglês, "içamento", o ato de levantar algo com uma corda, como uma bandeira). Antes de rodar a primeira linha, o JavaScript dá uma olhada no código inteiro e "levanta" as declarações para o topo do seu bloco. Mas cada tipo de declaração é levantado de um jeito, e é isso que esta aula explica.

Você vai aprender
  • Por que uma function declarada pode ser chamada antes de aparecer no código.
  • Por que um var usado antes da declaração vale undefined, sem erro.
  • O que é a zona morta temporal do let e do const, e a mensagem Cannot access 'x' before initialization.
  • O que acontece com arrow functions, funções guardadas em variáveis e classes usadas cedo demais.
  • A diferença entre "não pode acessar antes de inicializar" e "não está definida".
  • Como organizar o arquivo para nunca depender do hoisting por acidente.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. É bom já conhecer let, const, var, Funções e Escopo.

A ideia: a lista de chamada antes da aula

No primeiro dia de aula, a professora da Ana recebe a lista de chamada antes de entrar na sala. Ela ainda não conhece ninguém, mas já sabe os nomes de todos os alunos que existem na turma. O JavaScript faz parecido: antes de rodar a primeira linha, ele lê o arquivo inteiro e monta a "lista" de tudo que foi declarado (cada function, var, let, const e class).

A diferença está no que a lista diz sobre cada nome:

  • function: o nome já vem com a função pronta. Dá para usar desde a primeira linha.
  • var: o nome já existe, mas vale undefined até a linha da atribuição rodar.
  • let, const e class: o nome está na lista, mas "ainda não chegou". Tocar nele antes da linha da declaração é erro.

Nada é movido de verdade no seu arquivo: "levantar para o topo" é só um jeito de explicar o efeito.

1. function: pode chamar antes

saudar("Ana");

function saudar(nome) {
  console.log(`Olá, ${nome}!`);
}

$ node antes.js
Olá, Ana!

Funcionou. Uma declaração de função (a palavra function no começo da linha, com um nome) é levantada inteira: o nome e o corpo. Quando a linha 1 roda, o JavaScript já sabe o que saudar faz. É como se o arquivo fosse este:

function saudar(nome) {
  console.log(`Olá, ${nome}!`);
}

saudar("Ana");

Esse é o hoisting útil. Ele permite escrever o programa principal no topo e deixar os detalhes (as funções auxiliares) mais para baixo:

function main() {
  const total = somar(4.5, 12);
  mostrar(total);
}

function somar(a, b) {
  return a + b;
}

function mostrar(valor) {
  console.log(`Total: R$ ${valor}`);
}

main();

$ node organizado.js
Total: R$ 16.5

Repare que main usa somar e mostrar, que aparecem depois dela. Mesmo sem hoisting, isso funcionaria aqui: o que importa é que, quando main() roda (na última linha), as outras já existem.

2. var: existe, mas vale undefined

O var é o jeito antigo de criar variáveis (veja var: o Jeito Antigo). Ele também é levantado, mas só o nome. O valor só chega quando a linha da atribuição roda:

console.log(preco);
var preco = 4.5;
console.log(preco);

$ node var-antes.js
undefined
4.5

Nenhum erro, e a primeira linha mostrou undefined. Para o JavaScript, o programa era assim:

var preco;            // levantado: o nome existe, valendo undefined
console.log(preco);   // undefined
preco = 4.5;          // a atribuição fica onde estava
console.log(preco);   // 4.5

Isso parece gentil, mas é uma armadilha: o programa segue rodando com um valor errado, sem avisar ninguém. Um undefined numa conta vira NaN, e você só descobre bem longe dali. É um dos motivos para nunca usar var em código novo.

4. Funções guardadas em variáveis: valem as regras da variável

Só a declaração function nome() {} é levantada inteira. Uma arrow function (ou qualquer função) guardada numa const segue as regras da const:

  console.log(`Olá, ${nome}!`);

O caso que engana: a função roda antes da hora

Uma função pode usar uma const que aparece depois dela, desde que seja chamada depois que essa const foi criada. O que importa é o momento em que a linha roda:

const calcularTotal = (itens) => {
  return itens.reduce((soma, item) => soma + aplicarDesconto(item), 0);
};

const aplicarDesconto = (preco) => preco * 0.9;

console.log(calcularTotal([10, 20]));

$ node ordem-ok.js
27

Funcionou: quando calcularTotal rodou (na última linha), aplicarDesconto já existia. (O reduce soma os itens da lista, cada um com 10% de desconto; veja reduce.) Agora a mesma coisa com o console.log no meio:

const calcularTotal = (itens) => {

5. A zona morta também vale dentro de um bloco

O hoisting acontece em cada bloco (cada par de { }). Aqui a Ana esperava ver Ana, a variável de fora:

let nome = "Ana";

if (true) {
  console.log(nome);
  let nome = "Bia";
}

$ node bloco.js
/home/ana/bloco.js:4
  console.log(nome);
              ^

ReferenceError: Cannot access 'nome' before initialization
    at Object.<anonymous> (/home/ana/bloco.js:4:15)
                                    « (mais 7 linhas at … do node:internal cortadas)

Node.js v24.22.0

O let nome da linha 5 foi levantado para o topo do bloco do if. Dentro do bloco, nome já é a variável nova (a "Bia"), que ainda está na zona morta, e não a "Ana" de fora. Como consertar: use outro nome para a variável de dentro (let outroNome = "Bia";). Ter duas variáveis com o mesmo nome, uma dentro da outra, confunde: evite.

6. Classes: como o let

As classes (o molde para criar objetos, assunto do nível 3) também ficam na zona morta até a linha da declaração:

class Conta {
  constructor(dono) {
    this.dono = dono;
  }
}

Como consertar: declare a classe antes de usar o new.

Resumo das regras e qual usar

DeclaraçãoUsar antes da linha dela…Exemplo de resultado
function nome() {}Funciona: levantada inteiraOlá, Ana!

Duas formas de organizar um arquivo, as duas boas:

EstiloComo ficaQuando escolher
Tudo antes de usarConstantes e funções no topo; o código que chama, embaixoSempre funciona, com function, const ou arrow. É o mais seguro.
Principal primeiroUma function main() no topo, as function auxiliares embaixo e main(); na última linhaQuando você quer ler o "resumo" do programa primeiro. Funciona por causa do hoisting das declarações function.
A regra prática

Não precisa decorar as regras de hoisting para programar bem. Basta: declare antes de usar, use const e let (nunca var), e chame o código principal no fim do arquivo. Se aparecer Cannot access '…' before initialization, olhe a ordem das linhas.

Quando dá errado

Os erros desta aula, juntos, para consulta rápida:

Chamou uma arrow function antes da const

ReferenceError: Cannot access 'saudar' before initialization (seção 4). Como consertar: mova a chamada para depois da const saudar = …, ou troque por uma declaração function saudar(nome) { … }, que pode ser chamada antes.

Código antigo com var: o valor sai undefined ou "não é uma função"

Um var usado cedo demais vale undefined (seção 2), e chamar uma função guardada num var cedo demais dá TypeError: saudar is not a function (seção 4). Como consertar: troque var por const/let (o erro passa a dizer claramente que é um problema de ordem) e acerte a ordem.

O erro aponta uma linha, mas o culpado é outra

Quando uma função roda cedo demais e usa algo que ainda está na zona morta (seção 4, ordem-ruim.js), o ^ aponta para dentro da função. Leia as linhas at … de baixo para cima até achar a linha do seu programa principal (Object.<anonymous>, linha 5): é ali que está a chamada fora de hora.

A variável de dentro do bloco "esconde" a de fora

Cannot access 'nome' before initialization numa variável que existe lá fora (seção 5). Como consertar: não reaproveite o nome dentro do bloco.

Resumo

  • Antes de rodar um bloco, o JavaScript registra todas as declarações dele: isso é o hoisting (içamento).
  • function nome() {} é levantada inteira: dá para chamar antes da linha dela.
  • var é levantado valendo undefined: sem erro, mas com valor errado. Mais um motivo para não usar var.
  • let, const e class ficam na zona morta temporal até a linha da declaração: usar antes dá ReferenceError: Cannot access '…' before initialization.
  • Funções guardadas em variáveis (arrow functions, const f = function …) seguem as regras da variável.
  • O que importa é o momento em que a linha roda: declare antes de usar e chame o código principal no fim.
