JavaScript Rodando um Programa (node arquivo.js)

Com o Node.js instalado (aula Instalar o Node.js), chegou a hora de rodar o seu primeiro arquivo. O caminho é sempre o mesmo: escrever o programa num arquivo .js, salvar e, no terminal, digitar node seguido do nome do arquivo. Esta aula mostra cada passo, o que acontece por dentro quando o Node.js roda o arquivo, e o que fazer quando ele não acha o arquivo ou para no meio.

Você vai aprender
  • A criar uma pasta para os seus programas e um arquivo .js dentro dela.
  • A rodar com node arquivo.js, e por que a pasta atual importa.
  • Que o Node.js primeiro confere a escrita do arquivo inteiro e só depois executa, de cima para baixo.
  • A diferença entre um erro de escrita (nada roda) e um erro durante a execução (roda até a linha do erro).
  • O código de saída (echo $?) e o node --check.
  • Outras formas de rodar: o arquivo como comando (#!/usr/bin/env node), node -e, node -p e o "cano".
  • Os erros reais: Cannot find module, comando não encontrado, Permissão negada, e o node arquivo.js digitado no lugar errado.

Todas as transcrições foram feitas com o Node.js 24 LTS na máquina fictícia da Ana (usuária ana, computador notebook, Ubuntu). No Windows e no macOS, os comandos node são os mesmos; mudam só os comandos de pasta.

A ideia: a receita e o cozinheiro

Você escreve a receita num papel (o arquivo .js), guarda o papel numa gaveta (a pasta) e chama o cozinheiro (o Node.js) dizendo qual papel ele deve seguir. Se você disser o nome de um papel que não está naquela gaveta, ele não acha. E, antes de começar a cozinhar, ele lê a receita inteira: se uma frase estiver ilegível, ele nem liga o fogão.

O papel com a receitaO arquivo ola.js
A gaveta onde o papel estáA pasta, por exemplo /home/ana/js
"Cozinheiro, siga a receita ola!"node ola.js
O prato prontoA saída que aparece no terminal

1. Uma pasta para os seus programas

Para não espalhar arquivos pelo computador, a Ana criou uma pasta só para os programas do guia, chamada js, e entrou nela:

$ mkdir js
$ cd js
$ pwd
/home/ana/js
mkdir js
make directory, "criar pasta": cria a pasta js dentro da pasta onde você está (a pasta pessoal da Ana, /home/ana).
cd js
change directory, "mudar de pasta": entra na pasta js. A partir daqui, ela é a pasta atual.
pwd
print working directory, "mostrar a pasta de trabalho": confirma onde você está.

No Windows (PowerShell), os comandos mkdir, cd e pwd também existem (e o caminho da pasta atual aparece no próprio prompt). Se você não conhece o terminal, os guias de Bash e de Ubuntu começam do zero.

2. Escrevendo o arquivo

Abra um editor de código (o VS Code, ou o nano, que já vem no Ubuntu; veja Instalar o Node.js) e crie o arquivo ola.js dentro da pasta js. Com o nano, pelo terminal:

nano ola.js

O nano abre uma tela de edição. Digite as duas linhas abaixo e salve: Ctrl+O (de output, "gravar"), Enter para confirmar o nome, e Ctrl+X para sair.

console.log("Olá, mundo!");
console.log("Meu nome é Ana.");

De volta ao terminal, a Ana conferiu que o arquivo existe (ls, "listar") e o que tem dentro dele (cat, que mostra um arquivo de texto):

$ ls
ola.js
$ cat ola.js
console.log("Olá, mundo!");
console.log("Meu nome é Ana.");
O nome do arquivo

Termine sempre com .js. Prefira letras minúsculas, sem espaços e sem acentos: ola.js, lista-compras.js. No Linux, ola.js e Ola.js são arquivos diferentes.

Você pode rodar o mesmo arquivo quantas vezes quiser: mude o texto no editor, salve e rode node ola.js de novo. (Se a saída não mudou, quase sempre você esqueceu de salvar.)

O Node.js até aceita o nome sem o .js: se não acha um arquivo chamado exatamente ola, ele tenta ola.js. Mas escreva sempre o nome completo; é mais claro e é o que você vai ver em todo lugar.

$ node ola

4. A pasta atual e os caminhos

O node ola.js procura o ola.js na pasta atual. Se você estiver em outra pasta, precisa dizer o caminho até o arquivo. Aqui a Ana voltou para a pasta pessoal (cd ~; o ~ é um atalho para /home/ana):

$ cd ~
$ node js/ola.js
Olá, mundo!
Meu nome é Ana.
$ node ./js/ola.js
Olá, mundo!
Meu nome é Ana.

js/ola.js quer dizer "dentro da pasta js, o arquivo ola.js". O ./ na frente significa "a partir daqui" e não muda nada, mas você vai vê-lo bastante. E se ela tivesse digitado só node ola.js na pasta pessoal? O Node.js não acha o arquivo; a mensagem está em Quando dá errado.

5. Primeiro ele confere, depois executa de cima para baixo

Quando você roda node arquivo.js, o Node.js faz duas coisas, nesta ordem:

  1. Lê o arquivo inteiro e confere a escrita (a sintaxe): parênteses que abrem e fecham, aspas que fecham, palavras no lugar certo. Se algo estiver mal escrito, ele para aqui, com um SyntaxError, e nenhuma linha roda.
  2. Executa as instruções, de cima para baixo, uma de cada vez. Se uma delas der problema (um nome que não existe, por exemplo), ele para nessa linha: as de cima já rodaram, as de baixo não rodam mais.

O código de saída

Todo programa, ao terminar, entrega ao terminal um número: o código de saída. O terminal guarda o do último comando em $?, e o echo $? mostra:

$ node ola.js
Olá, mundo!
Meu nome é Ana.
$ echo $?
0

0 quer dizer "terminou bem". Quando um erro derruba o programa, o Node.js termina com 1 (você viu acima, depois do consol). Isso é útil para ferramentas que rodam programas automaticamente: elas olham esse número para saber se deu certo. Mais adiante no guia, você vai aprender a escolher esse número com process.exit().

Só conferir, sem rodar: node --check

O node --check (ou node -c) faz só o passo 1: confere a escrita e não executa nada. Se estiver tudo certo, não mostra nada:

$ node --check lista2.js
/home/ana/js/lista2.js:3
console.log("2. leite";
            ^^^^^^^^^^

SyntaxError: missing ) after argument list
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)
    at checkSyntax (node:internal/main/check_syntax:88:3)

Node.js v24.22.0
$ node --check ola.js
$ echo $?
0

Repare que o --check não pega o consol do lista.js: escrever um nome errado não é erro de escrita. Esse tipo de erro só aparece rodando.

6. Rodando o arquivo como um comando

No Linux e no macOS, dá para rodar um arquivo .js sem digitar node na frente, como se fosse um comando. São duas coisas. Primeiro, a linha #!/usr/bin/env node no topo do arquivo:

#!/usr/bin/env node
console.log("Padaria aberta!");
#!
O shebang (de hash + bang, os nomes em inglês do # e do !): diz ao sistema qual programa deve ler este arquivo. Só vale na primeira linha.
/usr/bin/env node
"Procure o node onde ele estiver instalado e use-o". Assim funciona tanto com o Node.js do nvm quanto com o oficial.

Depois, dê ao arquivo a permissão de ser executado, com chmod +x (change mode, "mudar permissões"; +x = "pode executar"), e chame com ./ na frente:

$ chmod +x padaria.js
$ ./padaria.js
Padaria aberta!
$ node padaria.js
Padaria aberta!

O node padaria.js continua funcionando: o Node.js ignora a linha do shebang. É assim que são feitas muitas ferramentas de terminal em JavaScript. No Windows, o shebang não tem efeito; lá, use sempre node arquivo.js.

7. Outras formas de rodar

node -e: uma linha, sem arquivo

O -e (de eval, "avaliar") roda o código que vem entre aspas, sem criar arquivo nenhum:

$ node -e 'console.log("Bom dia, Ana!")'
Bom dia, Ana!

Repare nas aspas: as simples de fora são para o terminal (marcam onde o código começa e termina); as duplas de dentro são do JavaScript.

node -p: calcula e mostra

O -p (de print, "mostrar") faz o mesmo que o -e e ainda mostra o resultado, sem precisar de console.log. Vira uma calculadora de bolso:

$ node -p '2 + 3'
5
$ node -p '"pão".toUpperCase()'
PÃO

O programa vem pelo "cano"

Se você não der nome de arquivo, o node lê o programa da entrada. Com a barra | (o "cano"), a saída de um comando vira a entrada do outro:

$ echo 'console.log("veio pelo cano")' | node
veio pelo cano

Cuidado: o node sozinho, digitado no terminal, sem cano, abre o modo interativo, com o prompt >. Esse é o assunto da próxima aula: O Modo Interativo do Node.

A Ana voltou para a pasta pessoal e esqueceu que o ola.js está dentro de js. Vamos ler:

node:internal/modules/cjs/loader:1568, throw err; e o ^
Desta vez, o arquivo e a linha do topo não são seus: são do próprio Node.js, do pedaço que carrega os arquivos. É um sinal de que o problema aconteceu antes de o seu programa começar.
Error: Cannot find module '/home/ana/ola.js'
"Não foi possível encontrar o módulo /home/ana/ola.js". Para o Node.js, cada arquivo .js é um módulo. O caminho mostra onde ele procurou: na pasta pessoal, e não em /home/ana/js.
code: 'MODULE_NOT_FOUND'
O código do erro, "módulo não encontrado": um nome fixo, em inglês, bom para pesquisar na internet. O requireStack: [] pode ignorar.

Como consertar: entre na pasta certa (cd js) ou diga o caminho (node js/ola.js). Na dúvida, pwd mostra onde você está e ls mostra os arquivos daí.

A Ana digitou só node, apertou Enter e caiu no modo interativo (o >). Ali, tudo o que se digita é JavaScript, e node ola.js não é JavaScript: é um comando do terminal. Resumo

  • O caminho de sempre: escreva o arquivo .js, salve, e rode com node arquivo.js no terminal.
  • O node procura o arquivo na pasta atual; de outra pasta, diga o caminho (node js/ola.js). pwd e ls ajudam a se achar.
  • O Node.js primeiro confere a escrita do arquivo inteiro: com um SyntaxError, nada roda. Depois executa de cima para baixo e, num erro como o ReferenceError, para na linha do erro.
  • O código de saída (echo $?) é 0 quando dá certo e 1 quando um erro derruba o programa. node --check só confere a escrita.
  • Com #!/usr/bin/env node na primeira linha e chmod +x, o arquivo roda como comando: ./arquivo.js.
  • node -e roda uma linha; node -p roda e mostra o resultado; node sozinho abre o modo interativo.
  • Cannot find module = pasta ou nome errado (ou .js.txt).
