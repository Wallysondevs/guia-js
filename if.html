JavaScript if

Até agora, os seus programas rodaram todas as linhas, de cima para baixo, sempre do mesmo jeito. Mas um programa de verdade precisa decidir: mostrar o aviso só se o estoque estiver baixo, dar o desconto só se a compra passar de um valor, liberar a entrada só se a senha estiver certa. Para isso existe o if, que em inglês quer dizer "se". Ele roda um pedaço do programa só quando uma condição é verdadeira.

Você vai aprender
  • Como se escreve um if: a condição entre parênteses ( ) e o bloco entre chaves { }.
  • O que acontece quando a condição é verdadeira e quando é falsa.
  • Como pôr várias linhas dentro do if, e por que indentar com 2 espaços.
  • Que tipo de coisa pode ir na condição: comparações (===, >…), && e ||, e variáveis booleanas.
  • Como o if aparece no modo interativo do Node.
  • As armadilhas e os erros reais: parênteses esquecidos, a chave que falta, = no lugar de ===, o ponto e vírgula depois do if e o if sem chaves.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: "se chover, leve o guarda-chuva"

Antes de sair de casa, a mãe da Ana sempre diz: "Se estiver chovendo, leve o guarda-chuva." Repare como essa frase funciona:

  1. Tem uma pergunta de sim ou não: está chovendo?
  2. Tem uma ação: levar o guarda-chuva.
  3. A ação só acontece se a resposta for sim. Se for não, a Ana simplesmente segue o caminho, sem guarda-chuva.

Em JavaScript, a pergunta se chama condição, e a resposta é sempre um booleano: true (verdadeiro, "sim") ou false (falso, "não"), como você viu em Booleanos. A ação é um bloco de código, uma ou mais linhas entre chaves.

1. O primeiro if

A Ana cuida do estoque da lojinha. Quando sobram menos de 5 unidades de um produto, o programa deve avisar:

const estoque = 3;

if (estoque < 5) {
  console.log("Atenção: estoque baixo!");
}

console.log("Fim da conferência.");
if
A palavra-chave: "se". Sempre em minúsculas (If ou IF não funcionam).
( … )
Os parênteses em volta da condição. No JavaScript eles são obrigatórios.
estoque < 5
A condição: "o estoque é menor que 5?". Ela vira true ou false (veja Comparação).
{
Abre o bloco: as linhas que só rodam se a condição for verdadeira.
console.log("Atenção: estoque baixo!");
O corpo do if. Os 2 espaços na frente mostram, para quem lê, que essa linha está dentro do bloco.
}
Fecha o bloco. Repare: não vai ponto e vírgula depois da chave.
console.log("Fim da conferência.");
Fora do bloco: roda sempre, com a condição verdadeira ou falsa.
$ node estoque.js
Atenção: estoque baixo!
Fim da conferência.

Como 3 < 5 é true, o Node entrou no bloco e mostrou o aviso. Depois, seguiu para a linha de baixo.

2. Várias linhas dentro do bloco

O bloco pode ter quantas linhas você quiser. Todas elas rodam juntas, se a condição for verdadeira, ou são todas puladas. Na padaria do bairro, compras de R$ 50 ou mais ganham 10% de desconto:

let total = 64;

if (total >= 50) {
  const desconto = total * 0.1;
  total = total - desconto;
  console.log(`Você ganhou R$ ${desconto} de desconto!`);
}

console.log(`Total a pagar: R$ ${total}`);

$ node desconto.js
Você ganhou R$ 6.4 de desconto!
Total a pagar: R$ 57.6

As três linhas do bloco rodaram, porque 64 >= 50 é true. Repare que o total foi criado com let: ele muda dentro do if. Com uma compra de R$ 30, o bloco inteiro seria pulado, e a saída seria só Total a pagar: R$ 30.

Indentação: 2 espaços

Para o JavaScript, os espaços no começo da linha não fazem diferença: quem marca o começo e o fim do bloco são as chaves. Mas para as pessoas que leem o código, fazem toda a diferença: com as linhas do bloco 2 espaços mais para a direita, dá para ver de relance o que está dentro do if. Use sempre (a maioria dos editores faz isso sozinha quando você aperta Enter depois do {).

A const desconto só existe dentro do bloco

Uma variável criada com const ou let dentro das chaves só existe ali dentro. Tentar usar desconto depois do } dá ReferenceError: desconto is not defined. Por isso o total foi criado antes do if: ele é usado dentro e fora. A aula Escopo explica isso em detalhe.

3. O que pode ir na condição

Qualquer coisa que dê true ou false. As mais comuns:

const idade = 17;
const nome = "Bia";
const temCupom = true;
const nota = 8;

if (idade >= 18) {
  console.log("Pode tirar a carteira de motorista.");
}
if (nome === "Bia") {
  console.log("Oi, Bia!");
}
if (temCupom) {
  console.log("Cupom aplicado.");
}
if (nota >= 7 && nota <= 10) {
  console.log("Aprovada.");
}

$ node condicoes.js
Oi, Bia!
Cupom aplicado.
Aprovada.
idade >= 18
Comparação de números: 17 >= 18 é false, por isso a frase da carteira não apareceu.
nome === "Bia"
Comparação de textos com o igual estrito === (três sinais de igual). Use sempre o ===, nunca o ==: a aula Comparação mostra por quê.
temCupom
Uma variável que já é booleana pode ir sozinha na condição. Não precisa escrever temCupom === true: o resultado seria o mesmo true.
nota >= 7 && nota <= 10
Duas perguntas juntas com o "e" (&&): as duas precisam ser verdadeiras. Também existe o "ou" (||) e o "não" (!); veja Operadores Lógicos.

Repare também que cada if é independente: o Node testa um, depois o outro, depois o outro. Nenhum deles depende do resultado do anterior. Para escolher entre caminhos ("se for assim, faça isto; senão, faça aquilo"), existe o else, assunto da próxima aula: else e else if.

E se a condição não for um booleano?

O JavaScript aceita qualquer valor na condição: um número, um texto… Ele transforma o valor em true ou false por conta própria. Por exemplo, if (0) não entra no bloco, e if ("Ana") entra. Essa regra tem nome e aula própria: Truthy e Falsy.

4. O if no modo interativo

Dá para escrever um if direto no > do Node (veja O Modo Interativo do Node). Depois da linha com o {, o > dá lugar a uma barrinha, |: o Node está esperando o resto do bloco. Ele só roda quando recebe o }:

$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> const estoque = 3;
undefined
> if (estoque < 5) {
| console.log("Estoque baixo!");
| }
Estoque baixo!
undefined
> .exit

Os undefined não são erro: no modo interativo, o Node mostra o "valor" de cada coisa que você digita, e nem o const nem o if têm valor para mostrar. (Em versões mais antigas do Node, a linha de continuação aparecia como ... em vez de |.)

Formas diferentes de fazer a mesma coisa

O aviso de estoque baixo pode ser escrito de mais de um jeito. Todos estes mostram a mesma coisa:

const estoque = 3;

// 1. O jeito recomendado: com chaves, em várias linhas
if (estoque < 5) {
  console.log("Estoque baixo (1)");
}

// 2. Com chaves, numa linha só
if (estoque < 5) { console.log("Estoque baixo (2)"); }

// 3. Sem chaves (só vale para UMA linha)
if (estoque < 5) console.log("Estoque baixo (3)");

// 4. Com && (um atalho que você vai ver em código dos outros)
estoque < 5 && console.log("Estoque baixo (4)");

$ node formas.js
Estoque baixo (1)
Estoque baixo (2)
Estoque baixo (3)
Estoque baixo (4)
Forma 2
Igual à 1, só que apertada numa linha. Serve para blocos bem curtos.
Forma 3
Sem chaves, o if controla só a próxima instrução. Funciona, mas é uma armadilha: veja em Quando dá errado o que acontece quando alguém acrescenta uma segunda linha.
Forma 4
O && só olha o lado direito se o esquerdo for verdadeiro (veja Operadores Lógicos). Programadores experientes usam isso como um "if curto", mas é bem mais difícil de ler.
SituaçãoQual usar
Quase sempreif (condição) { … }, com chaves e o bloco em linhas próprias
Uma ação curtinha, numa linha sóif (condição) { … } na mesma linha (com chaves)
Sem chavesEvite: funciona, mas engana quem acrescenta linhas depois
condição && açãoSaiba ler; prefira o if para escrever

É mais um motivo para usar const sempre que der.

Ponto e vírgula depois do if 
const estoque = 12;
if (estoque < 5); {
  console.log("Atenção: estoque baixo!");
}

$ node pontoevirgula.js
Atenção: estoque baixo!

O estoque é 12, e o aviso apareceu mesmo assim, sem erro nenhum. O ; logo depois do ) termina o if ali mesmo, com uma instrução vazia: "se o estoque for menor que 5, não faça nada". O bloco { … } da linha de baixo virou um bloco solto, que roda sempre. Como consertar: nunca ponha ; entre o ) e o {. O ponto e vírgula vai no fim das instruções de dentro do bloco, não no if.

O JavaScript diferencia maiúsculas de minúsculas: If não é a palavra-chave if. O Node achou que If(…) era uma chamada de função e, como o { logo depois não faz sentido nesse lugar, reclamou dele. Como consertar: if, tudo minúsculo.

Resumo

  • if (condição) { … } ("se") roda o bloco só se a condição for verdadeira. Se for falsa, o bloco é pulado, sem erro, e o programa segue depois do }.
  • Os parênteses da condição são obrigatórios; as chaves marcam o bloco. Indente o bloco com 2 espaços e não ponha ; depois do ) nem do }.
  • Na condição vão comparações (===, !==, <, >=…), combinações com &&, || e !, e variáveis booleanas sozinhas.
  • = guarda, === compara. Um = na condição dá TypeError com const e, com let, faz o bloco rodar sem erro.
  • Sem chaves, o if controla só a próxima instrução: use chaves sempre.
  • Para escolher entre dois caminhos, a próxima aula: else e else if.
