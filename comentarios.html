JavaScript Comentários (// e /* */)

Nem tudo o que se escreve num programa é para o computador. Às vezes você quer deixar um recado para quem vai ler o código depois (um colega, ou você mesmo daqui a um mês): "este preço é do quilo", "falta conferir o desconto". Para isso existem os comentários: trechos que o JavaScript ignora por completo. Eles são escritos para pessoas.

Você vai aprender
  • O comentário de uma linha, //, sozinho ou no fim de uma linha de código.
  • O comentário de várias linhas, /* … */.
  • A "desligar" uma linha ou um trecho de código para testar, sem apagar.
  • Que // e /* dentro de aspas são só texto.
  • O /** … */ dos comentários de documentação.
  • O que é um bom comentário, e o que não vale a pena comentar.
  • Os erros reais: comentário que não fecha, comentário dentro de comentário, # no lugar de //, uma barra só.

Os programas foram rodados com o Node.js 24 LTS na máquina fictícia da Ana, na pasta /home/ana/js.

A ideia: o post-it na receita

A Ana tem um caderno de receitas cheio de post-its colados: "dobrar a receita no Natal", "a vó usava manteiga, não margarina", "testar com menos açúcar". Quem faz o bolo lê os post-its, mas eles não são passos da receita: ninguém vai "dobrar a receita no Natal" numa terça-feira de março.

Os comentários são os post-its do código. O JavaScript passa por eles sem fazer nada, como se não existissem; quem lê o arquivo, vê.

1. O comentário de uma linha: //

Duas barras // começam um comentário que vai até o fim da linha. Ele pode ocupar a linha inteira, ou vir no fim de uma linha de código:

// Recibo da Padaria do Bairro
// Autora: Ana

console.log("Padaria do Bairro");
console.log("10 pães:", 10 * 0.8); // R$ 0,80 cada
console.log("2 cafés:", 2 * 3.5);  // R$ 3,50 cada

$ node recibo.js
Padaria do Bairro
10 pães: 8
2 cafés: 7
// Recibo da Padaria do Bairro
Um comentário de linha inteira. Aqui, um título: o que o arquivo faz.
// Autora: Ana
Outro. Cada linha de comentário precisa do seu //.
console.log(…); // R$ 0,80 cada
Um comentário no fim da linha: o código antes do // roda normalmente; do // em diante, é ignorado. Bom para explicar um número.

Na saída, nenhum comentário aparece: só as três linhas dos console.log. Repare também que, dentro do comentário, a vírgula decimal (0,80) e o R$ não causam problema nenhum: ali vale qualquer coisa, porque o JavaScript nem lê.

Por costume, coloca-se um espaço depois do // (// Autora, e não //Autora), e pelo menos um espaço antes de um // no fim da linha.

No modo interativo também

$ node

> 2 + 3 // a soma

Uma linha que só tem comentário não tem nada para calcular: o modo interativo responde undefined, como em qualquer linha sem valor.

Missão: ponha na primeira linha um comentário com // dizendo o que o programa faz (por exemplo, // Estoque da padaria), e troque o número de pães de queijo para 8.

console.log("Pão de queijo:", 5);

// Estoque da padaria
console.log("Pão de queijo:", 8);

2. Comentários de várias linhas: /* … */

Para um recado comprido, em vez de pôr // em cada linha, abra o comentário com /* e feche com */. Tudo o que estiver entre os dois é ignorado, quantas linhas forem:

/*
  Programa: quadro de avisos
  Mostra os recados do dia na padaria.
  Última mudança: horário do pão.
*/
console.log("Pão saindo às 7h");
console.log(/* número de fornadas: */ 3, "fornadas hoje");

$ node longo.js
Pão saindo às 7h
3 fornadas hoje
/*
Abre o comentário (barra e asterisco, nessa ordem).
As linhas do meio
O recado. A indentação de 2 espaços é só para ficar bonito.
*/
Fecha o comentário (asterisco e barra, na ordem contrária).
console.log(/* … */ 3, …)
Como tem começo e fim marcados, o /* */ pode ficar até no meio de uma linha de código. Funciona, mas atrapalha a leitura; use raramente.

3. "Desligando" código para testar

Um uso muito comum: você quer que uma linha não rode por enquanto, mas não quer apagá-la (vai precisar dela depois). Ponha // na frente e ela vira comentário. Os programadores chamam isso de comentar a linha:

console.log("Padaria do Bairro");
// console.log("Promoção: leve 2 sonhos, pague 1");
console.log("Obrigado!");

$ node desligar.js
Padaria do Bairro
Obrigado!

A promoção acabou, e a linha ficou guardada para a próxima. Para "religar", é só apagar o //. Para várias linhas de uma vez, o /* */:

console.log("Padaria do Bairro");
/*
console.log("Promoção: leve 2 sonhos, pague 1");
console.log("Só hoje!");
*/
console.log("Obrigado!");

$ node desligar2.js
Padaria do Bairro
Obrigado!
O atalho do editor

No VS Code (e na maioria dos editores de código), selecione as linhas e aperte Ctrl+/ (no macOS, Cmd+/): o editor põe // na frente de cada uma. O mesmo atalho tira.

Missão: a promoção voltou! "Religue" a linha da promoção (tire o comentário) e rode.

console.log("Padaria do Bairro");
// console.log("Promoção: leve 2 sonhos, pague 1");
console.log("Obrigado!");

console.log("Padaria do Bairro");
console.log("Promoção: leve 2 sonhos, pague 1");
console.log("Obrigado!");

4. // dentro de aspas não é comentário

Dentro de um texto entre aspas, // e /* são letras como quaisquer outras. Isso é bom: os endereços de sites têm //.

console.log("Site: https://padaria.exemplo // não é comentário");
console.log("/* nem isto */");

$ node aspas.js
Site: https://padaria.exemplo // não é comentário
/* nem isto */

O JavaScript lê da esquerda para a direita: quando encontra a aspa, sabe que está dentro de um texto até a aspa que fecha, e lá dentro nada é comentário.

5. O /** … */ de documentação

Você vai encontrar, em código dos outros, comentários que começam com dois asteriscos, logo acima de uma função:

/**
 * Calcula o preço total de uma compra.
 * @param {number} quantidade - Quantos itens.
 * @param {number} preco - O preço de cada item.
 * @returns {number} O total.
 */
function total(quantidade, preco) {
  return quantidade * preco;
}

Para o JavaScript, é um /* */ comum (o segundo * é só mais uma letra dentro do comentário). A diferença é para as ferramentas: esse formato, chamado JSDoc, é lido por editores como o VS Code, que mostram a explicação quando você passa o mouse sobre total. As linhas com @param descrevem os parâmetros, e @returns, o que a função devolve (aula Funções). Você não precisa escrever assim agora; só reconhecer.

6. O que é um bom comentário

Comentário bom explica o porquê, que o código não consegue dizer sozinho. Comentário ruim repete o quê, que o código já diz.

Ruim (repete o código)Bom (explica o porquê)
console.log(10 * 0.8); // multiplica 10 por 0.8console.log(10 * 0.8); // pão francês: R$ 0,80 a unidade
// mostra Obrigado// a dona pediu para sempre agradecer no fim do recibo
Um comentário em cada linhaUm comentário no topo dizendo o que o programa faz, e alguns onde algo não é óbvio

Dois costumes que você vai ver muito:

  • // TODO: … (em inglês, "a fazer"): algo que ainda falta. Muitos editores listam todos os TODO do projeto.
  • // FIXME: … ("conserte-me"): algo que está errado e precisa de conserto.
Comentário desatualizado é pior que nenhum

Se o preço mudou para R$ 0,90 e o comentário ainda diz "R$ 0,80", ele engana quem lê. Quando mudar o código, confira os comentários de perto. E não deixe código "desligado" para sempre: se não vai mais usar, apague.

O /* da linha 2 abriu um comentário, e o JavaScript procurou o */ até o fim do arquivo, sem achar. "Símbolo inválido ou inesperado", na linha 2, onde o comentário começou (desta vez sem o ^). É um SyntaxError, então nem a linha 1 rodou. Como consertar: feche com */ no lugar certo. Dica: nos editores de código, o comentário aparece numa cor diferente; se o resto do arquivo inteiro ficou dessa cor, falta fechar.

A Ana quis desligar um trecho com /* */, mas dentro dele já havia um /* o nome */. O /* */ não se aninha: o primeiro */ que aparece (o da linha 2) fecha o comentário, não importa quantos /* abriram. Assim, a linha 3 voltou a ser código, e o */ da linha 4 ficou sobrando: "símbolo inesperado *". Como consertar: para desligar trechos que já têm comentários, use // em cada linha (o atalho Ctrl+/ do editor faz isso).

Cerquilha # no lugar de // 
# Recibo da padaria
console.log("Padaria do Bairro");

$ node cerquilha.js
/home/ana/js/cerquilha.js:1
# Recibo da padaria
^

SyntaxError: Invalid or unexpected token
    «  8 linhas "at …" cortadas

Node.js v24.22.0

Em Python, no Bash e em outras linguagens, o comentário é com #. No JavaScript, não: o # no começo da linha é um "símbolo inválido". (A única exceção é o #! do shebang, e só na primeira linha.) Como consertar: // Recibo da padaria.

Uma barra só 
/ Recibo da padaria
console.log("Padaria do Bairro");

$ node barra.js
/home/ana/js/barra.js:1
/ Recibo da padaria
^

SyntaxError: Invalid regular expression: missing /
    «  8 linhas "at …" cortadas

Node.js v24.22.0

Faltou uma barra. A mensagem parece de outro mundo: "expressão regular inválida: falta /". É que, no JavaScript, um texto entre barras (/assim/) é uma expressão regular, um "molde" para procurar palavras (aula Expressões Regulares). Uma barra sozinha no começo da linha fez o JavaScript achar que um molde estava começando, e ele procurou a barra que fecharia. Como consertar: duas barras: // Recibo da padaria.

O comentário que "não funciona"

Se você pôs // numa linha e ela continua aparecendo na saída, confira se você salvou o arquivo, e se o // não está dentro de aspas (console.log("// promoção") mostra // promoção, como na seção 4).

Resumo

  • Comentários são recados para pessoas: o JavaScript os ignora.
  • // comenta até o fim da linha (sozinho ou depois do código); /* … */ comenta um trecho, de uma ou várias linhas.
  • Pôr // na frente de uma linha a "desliga" sem apagar (Ctrl+/ no editor).
  • Dentro de aspas, // e /* são texto.
  • /** … */ é o formato de documentação (JSDoc), lido pelos editores.
  • Bom comentário explica o porquê; não repita o que o código já diz, e mantenha os comentários atualizados.
  • Erros: /* sem */, /* */ dentro de outro, # ou / no lugar de //.
