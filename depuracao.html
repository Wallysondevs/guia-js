JavaScript: Depurando

Os erros mais fáceis são os que dão mensagem: o Node diz o tipo, a linha e até aponta com ^ (veja Lendo uma Mensagem de Erro). Os difíceis são os silenciosos: o programa roda até o fim, sem reclamar, e mostra NaN, undefined ou um número que não faz sentido. Para esses, você precisa olhar dentro do programa enquanto ele roda. Isso se chama depurar (em inglês, debug, "tirar os insetos": os defeitos de um programa são chamados de bugs, "insetos").

Você vai aprender
  • A técnica mais usada do mundo: console.log estratégico, com rótulos, com { } e dentro dos laços.
  • Os ajudantes do console para depurar: console.table, console.dir, console.trace, console.count e console.assert.
  • O depurador do terminal, node inspect: parar o programa numa linha, andar uma linha por vez e espiar as variáveis.
  • A palavra debugger, que marca um ponto de parada no próprio código.
  • O node --inspect com o Chrome DevTools, o depurador com janelas e botões.
  • Um método para caçar qualquer bug, e os tropeços comuns.

Todas as saídas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), inclusive as sessões do depurador. Só a parte do Chrome DevTools (seção 6) é descrita sem ter sido colhida: ela está marcada como ilustrativa.

A ideia: o detetive e as pegadas

Quando a torta some da janela, o detetive não fica olhando para o prato vazio. Ele segue as pegadas: às 10h a torta estava lá; às 11h, não. Então ele vai olhando o que aconteceu entre 10h e 11h, cada vez mais perto, até achar o culpado.

Depurar é igual. O resultado final está errado (o prato vazio). Você coloca "câmeras" no meio do caminho para ver os valores em cada ponto, e vai estreitando: aqui ainda estava certo, ali já estava errado. O bug está entre os dois.

  • O console.log é uma câmera que você instala no código e que fotografa o valor naquele instante.
  • O depurador é poder parar o tempo numa linha, olhar tudo em volta e andar uma linha por vez.

1. O bug silencioso

A professora da Ana quer a média de quatro notas:

const notas = [7, 8, 10, 9];
let total = 0;
for (let i = 0; i <= notas.length; i++) {
  total += notas[i];
}
const media = total / notas.length;
console.log(`Média: ${media}`);

$ node media.js
Média: NaN

Nenhum erro, nenhum ^, nenhuma linha. Só um NaN ("não é um número") onde devia estar 8.5. Para o Node, está tudo certo: ele fez exatamente o que foi escrito. Onde o número se estragou?

2. console.log estratégico

A pergunta é "o que está acontecendo dentro do laço?". Então a câmera vai dentro do laço, mostrando tudo o que importa em cada volta, com rótulos para não confundir:

const notas = [7, 8, 10, 9];
let total = 0;
for (let i = 0; i <= notas.length; i++) {
  console.log("volta", i, "nota:", notas[i], "total antes:", total);
  total += notas[i];
}
const media = total / notas.length;
console.log(`Média: ${media}`);

$ node media-log.js
volta 0 nota: 7 total antes: 0
volta 1 nota: 8 total antes: 7
volta 2 nota: 10 total antes: 15
volta 3 nota: 9 total antes: 25
volta 4 nota: undefined total antes: 34
Média: NaN

Pronto, a pegada apareceu: são 4 notas, mas o laço deu 5 voltas. Na volta 4, notas[4] não existe (as posições vão de 0 a 3) e vale undefined; e 34 + undefined dá NaN. O culpado é o <= da condição: com i <= notas.length, o i chega a 4. O certo é i < notas.length. Esse erro de "uma volta a mais" é tão comum que tem nome: erro "por um" (em inglês, off-by-one).

Missão: rode o programa com o console.log de depuração, veja em que volta o problema aparece, conserte a condição do for e, no fim, apague a linha do console.log de depuração. O resultado certo é Média: 8.5.

const notas = [7, 8, 10, 9];
let total = 0;
for (let i = 0; i <= notas.length; i++) {
  console.log("volta", i, "nota:", notas[i], "total antes:", total);
  total += notas[i];
}
const media = total / notas.length;
console.log(`Média: ${media}`);

  total += notas[i];
}
const media = total / notas.length;
console.log(`Média: ${media}`);

Dicas para um bom console.log de depuração

Outro bug: a lojinha calcula o total com frete, e o resultado sai esquisito.

const preco = 4.5;
const quantidade = "3";
const total = preco * quantidade;
const frete = "10";
console.log(total + frete);
console.log(preco, quantidade, frete);
console.log({ preco, quantidade, frete });
console.log(typeof quantidade, typeof frete);

$ node rotulo.js
13.510
4.5 3 10
{ preco: 4.5, quantidade: '3', frete: '10' }
string string
13.510
O sintoma: deveria ser 23.5. Parece que o 13.5 e o 10 foram "grudados".
console.log(preco, quantidade, frete)
Vários valores separados por vírgula saem numa linha. Mas repare: 4.5 3 10 esconde o problema. Não dá para ver que o 3 e o 10 são textos.
console.log({ preco, quantidade, frete })
O truque das chaves: cria na hora um objeto com o nome e o valor de cada variável (veja Objetos). E o Node mostra os textos entre aspas: quantidade: '3', frete: '10'. Achado! O + entre um número e um texto junta os dois como texto (veja Conversão Automática).
typeof
Quando desconfiar do tipo, pergunte: typeof frete respondeu string (veja typeof).

A multiplicação 4.5 * "3" deu certo porque o * converte o texto em número; o + não converte, ele junta. A correção é converter: Number(frete) (veja Conversão).

Missão: use o console.log({ … }) que já está aí para ver os tipos e conserte a conta do total, para aparecer Total com frete: 23.5.

const preco = 4.5;
const quantidade = "3";
const frete = "10";
console.log({ preco, quantidade, frete });
const total = preco * quantidade + frete;
console.log(`Total com frete: ${total}`);

const preco = 4.5;
const quantidade = "3";
const frete = "10";
const total = preco * quantidade + Number(frete);
console.log(`Total com frete: ${total}`);
Regras de ouro do console.log de depuração
  • Sempre com rótulo: console.log("total:", total) ou console.log({ total }). Com cinco console.log(total) espalhados, você não sabe qual linha é de qual.
  • Antes e depois da linha suspeita: se antes está certo e depois está errado, achou.
  • Dentro dos laços, mostre o contador junto (i).
  • Apague quando terminar. console.log de depuração esquecido polui a saída do programa.

  console.count(produto);
}

$ node contar.js

leite: 1

O console.count ("contar") conta quantas vezes passou por ali com cada rótulo. Bom para responder "essa função está sendo chamada quantas vezes?".

const estoque = -2;
console.assert(estoque >= 0, "Estoque negativo!", estoque);
console.assert(10 >= 0, "isto não aparece");
console.log("Fim");

$ node assert.js
Assertion failed: Estoque negativo! -2
Fim

O console.assert ("afirmar") só escreve quando a condição é falsa: "eu afirmo que o estoque é maior ou igual a zero; se não for, me avise". Quando a condição é verdadeira, fica quieto. Ele não para o programa (o Fim apareceu).

5. A palavra debugger

Em vez de marcar o ponto de parada com sb(4), você pode escrevê-lo no código: a linha debugger;. Quando há um depurador ligado (o node inspect, o Chrome DevTools…), o programa pausa ali, como você viu na segunda sessão: o primeiro c já parou na linha 4, a do debugger.

E quando não há depurador nenhum? A linha é simplesmente ignorada:

$ node comdebugger.js
Média: 8.5

Experimente: rode este programa na caixa. Ele tem um debugger; dentro do laço, mas como nenhum depurador está ligado, roda direto até o fim. O console.table mostra as notas.

const notas = [7, 8, 10, 9];
let total = 0;
for (let i = 0; i < notas.length; i++) {
  debugger;
  total += notas[i];
}
console.log(`Média: ${total / notas.length}`);
console.table(notas);
Não esqueça o debugger no código

Sem depurador, ele não faz mal; mas, no dia em que alguém abrir o DevTools do navegador numa página com um debugger esquecido, a página vai pausar ali sem ninguém entender por quê. Terminou de depurar, apague.

6. O depurador com janelas: node --inspect e o Chrome DevTools

O node inspect é todo em texto. O mesmo depurador pode ser usado com janelas e botões: as ferramentas de desenvolvedor do Chrome (o DevTools, aquele do F12, veja O Console do Navegador). Para isso, rode o programa com --inspect-brk ("inspecionar e pausar no começo"):

$ node --inspect-brk media.js
Debugger listening on ws://127.0.0.1:9229/a751f70e-bd70-4fcc-bdbc-af70ad3eee40
For help, see: https://nodejs.org/learn/getting-started/debugging

O programa fica parado, esperando um depurador se conectar (o terminal não volta para o $). Com --inspect, sem o -brk, o Node abre a porta mas não espera: o programa roda direto, e só pausa num debugger ou num ponto de parada se o DevTools já estiver conectado. No lab, sem ninguém conectado, ele foi até o fim:

$ node --inspect media.js
Debugger listening on ws://127.0.0.1:9229/d6a5f11e-ecce-4330-a496-9ec821f77ef6
For help, see: https://nodejs.org/learn/getting-started/debugging
Média: NaN

Daqui em diante, a parte do Chrome é ilustrativa (não foi colhida no lab). Com o programa parado pelo --inspect-brk:

  1. Abra o Chrome (ou o Edge) e digite na barra de endereços: chrome://inspect (no Edge, edge://inspect).
  2. Na seção Remote Target ("alvo remoto") aparece o seu programa, com o caminho do arquivo. Clique em inspect. (Outro jeito: o link Open dedicated DevTools for Node.)
  3. Abre uma janela do DevTools, na aba Sources ("fontes"), com o seu código e a primeira linha destacada: o programa está pausado ali.
  4. Clique no número de uma linha para marcar um ponto de parada (aparece uma marquinha azul). Clique de novo para tirar.
  5. Use os botões do painel da direita (ou as teclas): F8 continuar (o c), F10 próxima linha (o n), F11 entrar na função (o s).
  6. No painel Scope ("escopo") aparecem todas as variáveis e seus valores, sem precisar de watch. Passar o mouse sobre uma variável no código também mostra o valor.
  7. A aba Console, enquanto o programa está pausado, calcula expressões com as variáveis daquele momento (o exec).

É o mesmo depurador do navegador. Numa página web (as aulas de DOM), você nem precisa do --inspect: aperte F12, vá à aba Sources, abra o seu script.js e marque os pontos de parada; um debugger; no script também pausa a página quando o DevTools está aberto. Editores como o VS Code têm o mesmo depurador embutido (menu Run and Debug, "executar e depurar").

Um método para caçar qualquer bug

  1. Reproduza. Ache um jeito de fazer o erro acontecer sempre (os mesmos dados, os mesmos passos).
  2. Diga o que esperava e o que aconteceu. "Esperava 8.5, veio NaN."
  3. Divida ao meio. Ponha um console.log (ou um ponto de parada) no meio do caminho. O valor está certo ali? Então o bug está depois; senão, antes. Repita na metade que sobrou.
  4. Desconfie das certezas. "Essa variável com certeza é número": confira com typeof.
  5. Mude uma coisa por vez e rode de novo.
  6. Explique em voz alta. Contar o programa linha por linha para alguém (ou para um patinho de borracha na mesa, o famoso "método do patinho") faz você perceber o que pulou.

Quando dá errado

O console.log sem rótulo que confunde

Com console.log(total) em três lugares, a saída é uma coluna de números sem nome, e você acaba olhando o número errado. Pior: o console.log(a, b, c) esconde os tipos (4.5 3 10, na seção 2). Use rótulo ou { }.

O objeto aparece "cortado", com [Object]

Não é que a informação sumiu: o console.log do Node só mostra dois níveis de profundidade (seção 3). Use console.dir(obj, { depth: null }). Com arrays, algo parecido: o Node mostra só os 100 primeiros itens e termina com um aviso como ... 50 more items ("mais 50 itens").

debug> não reconhece o nome da variável

No debug>, só os comandos do depurador funcionam direto. Para calcular uma expressão, use exec na frente (exec total) ou entre no repl. E só existem as variáveis que já foram criadas até a linha onde o programa está parado: no Break on start, nenhuma linha rodou ainda.

O programa "travou" depois do --inspect-brk

Ele não travou: está esperando o depurador (é o que o -brk pede). Conecte o Chrome em chrome://inspect, ou aperte Ctrl+C e rode sem a opção.

Os console.log de depuração ficaram no programa

Linhas como volta 0 nota: 7 total antes: 0 no meio da saída de um programa "pronto" confundem quem usa. Antes de dar o trabalho por terminado, procure e apague os console.log de depuração e os debugger. (Se o aviso é útil de verdade, ele vira um console.error com uma mensagem clara.)

Missão final: o desconto que não desconta

Missão: a compra de R$ 30 + R$ 50 + R$ 20, com 10% de desconto, deveria dar Total: R$ 90, mas o programa mostra Total: R$ 18, sem erro nenhum. Ponha um console.log({ preco, total }) dentro do laço, veja o que acontece com o total a cada volta e conserte a linha que soma.

const precos = [30, 50, 20];
let total = 0;
for (const preco of precos) {
  total = preco;
}
const comDesconto = total * 0.9;
console.log(`Total: R$ ${comDesconto}`);

const precos = [30, 50, 20];
let total = 0;
for (const preco of precos) {
  total += preco;
}
const comDesconto = total * 0.9;
console.log(`Total: R$ ${comDesconto}`);

No lab, o programa original mostrou Total: R$ 18 (só o último preço, 20, com desconto) e o consertado, Total: R$ 90. O total = preco trocava o total a cada volta, em vez de somar (total += preco).

Resumo

  • Depurar é achar erros silenciosos (de lógica): o programa roda, mas o resultado está errado.
  • console.log estratégico: com rótulo ou { }, dentro dos laços, antes e depois da linha suspeita; apague no fim.
  • console.table, console.dir(…, { depth: null }), console.trace, console.count e console.assert ajudam em casos específicos.
  • node inspect arquivo.js abre o depurador do terminal: sb(linha), c, n, s, watch('x'), exec x, .exit.
  • debugger; é um ponto de parada no código; sem depurador, é ignorado.
  • node --inspect-brk + chrome://inspect dá o mesmo depurador com janelas, como o F12 do navegador.
  • Método: reproduzir, comparar o esperado com o obtido, dividir ao meio, conferir os tipos, mudar uma coisa por vez.
