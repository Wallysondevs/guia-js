JavaScript JavaScript na Página (<script>)

Na aula O que é o DOM, a Ana mexeu na página digitando no Console. Mas o que se digita no Console some quando a página recarrega. Para o JavaScript rodar toda vez que alguém abre a página, ele precisa estar ligado ao HTML. Quem faz essa ligação é a tag <script> ("roteiro"). Parece simples, e é, mas onde você põe essa tag muda tudo.

Você vai aprender
  • Os dois jeitos de usar a tag <script>: com o código dentro e com um arquivo script.js separado (src).
  • Por que um script no <head> quebra com Cannot set properties of null, e três formas de resolver: no fim do <body>, defer e DOMContentLoaded.
  • O type="module", e por que ele não funciona quando a página é aberta com dois cliques.
  • Como vários scripts na mesma página se enxergam, e por que a ordem deles importa.
  • O onclick escrito no HTML, que você vai ver em código antigo.
  • Os erros reais do Console: arquivo não encontrado, erro de sintaxe, CORS.

As páginas desta aula foram abertas no Chromium da máquina da Ana, e as mensagens do Console mostradas aqui foram colhidas lá. Em quase todas, a página foi aberta com dois cliques no arquivo index.html (o endereço fica file:///home/ana/…); quando foi aberta por um servidor, a aula avisa.

A ideia: o roteiro do teatro

Pense numa peça de teatro. O cenário (o HTML) é montado no palco, peça por peça, de cima para baixo. O roteiro (o JavaScript) diz o que os atores fazem com o cenário: "acenda a luz do abajur", "troque a placa da porta".

O problema: se o ator ler a frase "troque a placa da porta" antes de a porta ser montada, ele não tem o que trocar. No navegador acontece exatamente isso. Ele lê o HTML de cima para baixo, construindo o DOM aos poucos, e quando encontra um <script>, para tudo e roda o script na hora. O script só enxerga o que já foi construído até ali.

1. O código dentro da tag

O jeito mais direto: escrever o JavaScript entre <script> e </script>, dentro do HTML.

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Padaria da Ana</title>
</head>
<body>
  <h1>Padaria da Ana</h1>
  <p id="aviso">Carregando...</p>
  <script>
    console.log("Olá do JavaScript!");
    document.querySelector("#aviso").textContent = "Aberto das 6h às 20h";
  </script>
</body>
</html>

Ao abrir a página, o parágrafo mostra Aberto das 6h às 20h (o Carregando... do HTML foi trocado tão rápido que nem aparece), e o Console mostra:

Olá do JavaScript!

À direita da mensagem, o DevTools mostra de onde ela veio: index.html:11, a linha 11 do arquivo HTML, onde está o console.log.

<script> … </script>
Tudo o que fica entre as duas tags é JavaScript, não HTML. O navegador roda esse código quando chega nele.
No fim do <body>
A tag está depois do <p id="aviso">. Quando o script roda, o parágrafo já existe no DOM e o querySelector("#aviso") o encontra (o # procura pelo id; veja Selecionando Elementos).

Funciona, mas tem desvantagens: o HTML e o JavaScript ficam misturados no mesmo arquivo, e o mesmo código não pode ser usado em outras páginas. Por isso, o jeito mais comum é o próximo.

2. O arquivo separado: <script src="…">

A Ana criou uma pasta meu-site com dois arquivos lado a lado:

meu-site/
├── index.html
└── script.js

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Padaria da Ana</title>
</head>
<body>
  <h1>Padaria da Ana</h1>
  <p id="aviso">Carregando...</p>
  <script src="script.js"></script>
</body>
</html>

console.log("Olá do script.js!");
document.querySelector("#aviso").textContent = "Aberto das 6h às 20h";

Olá do script.js!

O resultado na tela é o mesmo, e agora o link à direita da mensagem diz script.js:1: o arquivo e a linha do console.log.

src="script.js"
src vem de source, "fonte": o endereço do arquivo com o código. Um nome sozinho, como script.js, quer dizer "na mesma pasta do index.html". Numa subpasta, seria src="js/script.js".
</script>
A tag de fechar é obrigatória, mesmo sem nada dentro. E, com src, o que você escrever entre as duas tags é ignorado.
O arquivo script.js
Só JavaScript, sem nenhuma tag <script> dentro. É o mesmo tipo de arquivo que você roda no Node com node arquivo.js; a diferença é quem roda (o navegador) e o que existe lá (o document).
Por que separar?

Cada arquivo cuida de uma coisa: o HTML da estrutura, o CSS da aparência, o JavaScript do comportamento. O editor de código colore e confere cada um direito, o mesmo script.js pode servir a várias páginas, e o navegador guarda o arquivo na memória (o cache) para abrir as próximas páginas mais rápido.

Experimente: as caixas de página do guia já trabalham assim: a aba index.html tem a tag <script src="script.js">, e o código fica na aba script.js. Mude o horário no script.js e rode de novo.

<h1>Padaria da Ana</h1>
<p id="aviso">Carregando...</p>
<script src="script.js"></script>

console.log("Olá do script.js!");
document.querySelector("#aviso").textContent = "Aberto das 6h às 20h";

3. A posição importa: o script no <head>

Muita gente põe o <script> no <head>, junto com o <title>. Com o mesmo script.js:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Padaria da Ana</title>
  <script src="script.js"></script>
</head>
<body>
  <h1>Padaria da Ana</h1>
  <p id="aviso">Carregando...</p>
</body>
</html>

Olá do script.js!
Uncaught TypeError: Cannot set properties of null (setting 'textContent')
    at script.js:2:46

A primeira linha do script rodou (a mensagem apareceu), mas a segunda quebrou, e o parágrafo continuou dizendo Carregando.... O que aconteceu:

  1. O navegador começou a ler o HTML e chegou ao <script> no <head>. Parou e rodou o script.js.
  2. Nesse momento, o <body> ainda não tinha sido lido: o <p id="aviso"> não existia no DOM.
  3. document.querySelector("#aviso") não achou nada e devolveu null ("nada").
  4. null.textContent = …: não dá para mudar uma propriedade de nada. Erro.

Lendo a mensagem:

Uncaught
"Não capturado": ninguém tratou o erro com try … catch.
TypeError: Cannot set properties of null (setting 'textContent')
"Erro de tipo: não é possível definir propriedades de null (definindo textContent)." O valor à esquerda do ponto era null.
at script.js:2:46
No arquivo script.js, linha 2, coluna 46: bem no .textContent.

Há três jeitos de consertar. Todos fazem o script rodar depois que o elemento existe.

Conserto 1: a tag no fim do <body>

É o que as seções 1 e 2 fizeram: a tag <script> logo antes do </body>. Quando o navegador chega nela, todo o conteúdo da página já foi lido. É o jeito tradicional, e é o que as caixas deste guia usam.

Conserto 2: defer

Deixe a tag no <head> e acrescente o atributo defer ("adiar"):

  <script src="script.js" defer></script>

Olá do script.js!

Sem erro, e o parágrafo mostrou Aberto das 6h às 20h. Com defer, o navegador baixa o arquivo enquanto continua lendo o HTML, e só roda o script quando terminou de ler a página inteira. É o jeito mais usado hoje: a tag fica arrumada no <head>, e o script não precisa esperar sua vez para ser baixado. (O defer só vale para scripts com src; num <script> com o código dentro, ele é ignorado.)

Conserto 3: esperar o evento DOMContentLoaded

Também dá para deixar o script no <head>, sem defer, e pedir ao navegador: "me avise quando terminar de construir o DOM". Esse aviso é o evento DOMContentLoaded ("conteúdo do DOM carregado"):

document.addEventListener("DOMContentLoaded", () => {
  console.log("A página foi lida até o fim!");
  document.querySelector("#aviso").textContent = "Aberto das 6h às 20h";
});

A página foi lida até o fim!

O addEventListener ("adicionar ouvinte de evento") guarda a função e só a chama quando o evento acontece; a aula Eventos explica em detalhes. Você vai ver muito esse jeito em código mais antigo, de antes de o defer ser comum.

Missão: o script está no <head> e quebra com Cannot set properties of null (veja o Console da caixa). Conserte de um dos três jeitos: mova a tag para o fim do <body>, ou acrescente defer na tag.

<html lang="pt-BR">

  <script src="script.js"></script>

4. type="module": o script como módulo

Na aula Módulos, você viu o import e o export. No navegador, para um script poder usar import, a tag precisa de type="module":

  <script type="module" src="script.js"></script>

Um script módulo já se comporta como defer (espera a página ser lida), roda no modo estrito e pode usar await no topo do arquivo. Só que, abrindo o index.html com dois cliques, a Ana teve uma surpresa:

Access to script at 'file:///home/ana/meu-site/script.js' from origin 'null' has been blocked by CORS policy: Cross origin requests are only supported for protocol schemes: chrome, chrome-experimental-site-token-provider, chrome-extension, chrome-untrusted, data, http, https, isolated-app.
Failed to load resource: net::ERR_FAILED

O script nem rodou. "O acesso ao script em file:///… a partir da origem null foi bloqueado pela política de CORS: pedidos entre origens só são permitidos para os protocolos chrome, data, http, https…". Traduzindo: por segurança, o Chrome não carrega módulos de uma página aberta direto do disco (file://). A segunda linha confirma que o arquivo não foi carregado.

Como consertar: abra a página por um servidor, mesmo que seja no seu computador. O mais fácil é a extensão Live Server do VS Code (botão "Go Live"). Pelo endereço http://127.0.0.1:5500/index.html, a mesma página funcionou:

Olá do script.js!
> location.href
'http://127.0.0.1:5500/index.html'

Os scripts comuns (sem type="module") funcionam com dois cliques, sem servidor. Por isso as aulas deste grupo usam scripts comuns.

5. Vários scripts na mesma página

Uma página pode ter várias tags <script>. Os scripts comuns rodam na ordem em que aparecem e compartilham as variáveis do nível de cima: uma const criada num arquivo pode ser usada no seguinte. A Ana guardou os preços num arquivo à parte:

const precoPao = 0.8;

console.log(`Pão francês: R$ ${precoPao.toFixed(2)}`);

  <script src="precos.js"></script>
  <script src="script.js"></script>

Pão francês: R$ 0.80

Agora com as duas tags trocadas de lugar (primeiro o script.js):

Uncaught ReferenceError: precoPao is not defined
    at script.js:1:32

O script.js rodou primeiro, quando o precos.js ainda não tinha criado a precoPao. "Erro de referência: precoPao não está definido", na linha 1, coluna 32 do script.js. A ordem das tags é a ordem de execução: quem fornece vem antes de quem usa. (Com type="module" é diferente: cada módulo tem as suas variáveis, e um usa o do outro com import.)

6. No código antigo: onclick no HTML

Você ainda vai encontrar JavaScript escrito dentro de um atributo do HTML:

<button onclick="console.log(&quot;Clicou!&quot;)">Clique</button>

Ao clicar no botão, o Console mostrou Clicou!. Funciona, mas mistura de novo HTML e JavaScript, complica as aspas (repare no &quot;, o jeito de escrever aspas dentro de um atributo) e só permite uma ação por evento. Hoje, o jeito recomendado é o addEventListener num arquivo .js, como na aula Eventos. Reconheça o onclick="…" quando o vir, mas não escreva código novo assim.

Quando dá errado

O nome do arquivo está errado

A Ana escreveu <script src="scripts.js"> (com um s a mais), mas o arquivo se chama script.js:

Failed to load resource: net::ERR_FILE_NOT_FOUND

"Falha ao carregar o recurso: arquivo não encontrado." O link à direita diz scripts.js, o nome que o navegador procurou. A página aparece normal, só que nada do JavaScript acontece (o parágrafo ficou em Carregando...). Aberta por um servidor, a mesma página mostra Failed to load resource: the server responded with a status of 404 (Not Found) ("o servidor respondeu com o código 404, não encontrado"). Como consertar: confira o nome, a pasta e as maiúsculas/minúsculas (Script.js e script.js são arquivos diferentes no Linux e nos servidores).

Um erro de sintaxe derruba o arquivo inteiro 
console.log("Olá do script.js!");
document.querySelector("#aviso").textContent = "Aberto das 6h às 20h;

Uncaught SyntaxError: Invalid or unexpected token

Faltou fechar as aspas na linha 2 (o link à direita diz script.js:2). "Erro de sintaxe: símbolo inválido ou inesperado." Repare que nem a linha 1 rodou: o Olá do script.js! não apareceu. Antes de rodar um script, o navegador lê o arquivo inteiro; com um erro de sintaxe em qualquer lugar, ele não roda nada daquele arquivo. Um erro em um arquivo não impede os outros scripts da página de rodar. Como consertar: feche as aspas: "Aberto das 6h às 20h";.

Cannot set properties of null

O elemento ainda não existia quando o script rodou (seção 3), ou o seletor está errado ("aviso" sem o #, um id com outro nome). Para saber qual dos dois, digite o seletor no Console depois que a página abrir: document.querySelector("#aviso"). Se aparecer o elemento, o problema era a hora; se aparecer null, o seletor está errado (veja Selecionando Elementos).

type="module" aberto com dois cliques

O erro has been blocked by CORS policy da seção 4. Como consertar: use um servidor (Live Server), ou tire o type="module" se o código não usa import.

Escreveu <script src="…" /> sem a tag de fechar

Em HTML, <script> sempre precisa do </script>. A barra no fim (/>) é ignorada, e o navegador passa a tratar todo o HTML seguinte como se fosse o conteúdo do script, até achar um </script>. No Chromium da Ana, com <script src="script.js" /> logo no começo do <body>, a página ficou em branco (no Console, document.querySelectorAll("h1").length deu 0: o título virou texto do script) e o próprio script.js nem rodou. Como consertar: <script src="script.js"></script>.

Resumo

  • A tag <script> liga o JavaScript à página: com o código dentro, ou, melhor, com src="script.js" apontando para um arquivo separado (e sempre com </script>).
  • O navegador lê o HTML de cima para baixo e roda cada script quando chega nele; o script só enxerga o que já foi construído.
  • Script no <head> sem cuidado dá Cannot set properties of null. Soluções: tag no fim do <body>, defer, ou DOMContentLoaded.
  • type="module" permite import e já é adiado, mas precisa de um servidor (com file://, o Chrome bloqueia por CORS).
  • Vários scripts comuns rodam na ordem das tags e compartilham as variáveis: quem fornece vem antes de quem usa.
  • Um erro de sintaxe impede o arquivo inteiro de rodar; um src errado dá ERR_FILE_NOT_FOUND.
