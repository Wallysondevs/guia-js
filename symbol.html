JavaScript Symbol

Na aula Iteradores apareceu um nome estranho entre colchetes: [Symbol.iterator]. Ele é um símbolo, um tipo de valor que você ainda não tinha visto. Um símbolo é um valor único: não existe outro igual a ele, nunca. Isso serve para uma coisa bem específica: criar nomes de propriedade que não se misturam com nenhum outro nome. Você vai usar símbolos poucas vezes, mas vai encontrá-los em código de bibliotecas e no próprio JavaScript.

Você vai aprender
  • O que é o tipo symbol e como criar um com Symbol("descrição").
  • Por que dois símbolos com a mesma descrição não são iguais.
  • Como usar um símbolo como chave de objeto, e por que essa chave fica "escondida" do Object.keys, do for … in e do JSON.stringify.
  • Para que isso serve: evitar choque de nomes, e criar constantes de estado.
  • O Symbol.for (o símbolo compartilhado) e os símbolos que o próprio JavaScript usa: Symbol.iterator, Symbol.toPrimitive, Symbol.toStringTag.
  • Os erros reais: new Symbol e o símbolo juntado num texto.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana, com node arquivo.js. Símbolos funcionam igual no navegador.

A ideia: a chave com número de série

Na portaria do prédio da Ana, cada morador tem uma etiqueta com o nome no claviculário: "Ana", "Bia", "Caio". Um dia chega outra Ana, nova moradora. Duas etiquetas "Ana": confusão na certa. O síndico resolve trocando as etiquetas de nome por chaves com número de série gravado de fábrica. Duas chaves podem até ter o mesmo chaveirinho escrito "Ana", mas o número de série é único: uma nunca abre a porta da outra.

  • Os nomes de propriedade comuns ("nome", "id") são as etiquetas: dois textos iguais são o mesmo nome.
  • Um símbolo é a chave com número de série. O chaveirinho (a descrição) é só para humanos lerem; quem decide a identidade é o número de série, que nunca se repete.

1. Criando um símbolo

const a = Symbol("id");
const b = Symbol("id");

console.log(a);
console.log(typeof a);
console.log(a.description);
console.log(a === b);
console.log(a === a);
console.log(String(a));

$ node primeiro.js
Symbol(id)
symbol
id
false
true
Symbol(id)
Symbol("id")
Cria um símbolo novo. O texto entre parênteses é a descrição, o chaveirinho: serve para você reconhecer o símbolo ao mostrá-lo. É opcional (Symbol() também funciona). Repare: sem new (veja Quando dá errado).
Symbol(id)
É como o Node mostra o símbolo: a palavra Symbol e a descrição.
typeof a → symbol
Um tipo próprio, o sétimo tipo primitivo do JavaScript, ao lado de string, number, bigint, boolean, undefined e null (veja Os Tipos de Dados).
a.description → id
Lê a descrição, como texto.
a === b → false
O ponto central: a e b têm a mesma descrição, mas são dois símbolos diferentes. Cada chamada de Symbol() fabrica um valor que nunca existiu antes.
a === a → true
Um símbolo só é igual a ele mesmo. Para usar o "mesmo" símbolo em vários lugares, guarde-o numa variável e passe a variável adiante.
String(a) → Symbol(id)
Para transformar em texto, é preciso pedir com todas as letras: String(a) ou a.toString(). Juntar com + dá erro (veja Quando dá errado).

2. Símbolo como chave de objeto

O uso principal dos símbolos é servir de nome de propriedade. Para isso, use colchetes, tanto ao criar quanto ao ler:

const ID = Symbol("id");

const cliente = {
  nome: "Ana",
  cidade: "Recife",
  [ID]: 4521,
};

console.log(cliente);
console.log(cliente[ID]);
console.log(Object.keys(cliente));
console.log(JSON.stringify(cliente));
for (const chave in cliente) {
  console.log(`for…in: ${chave}`);
}
console.log(Object.getOwnPropertySymbols(cliente));
console.log(cliente.ID);
console.log(cliente["id"]);

$ node chave.js
{ nome: 'Ana', cidade: 'Recife', Symbol(id): 4521 }
4521
[ 'nome', 'cidade' ]
{"nome":"Ana","cidade":"Recife"}
for…in: nome
for…in: cidade
[ Symbol(id) ]
undefined
undefined
[ID]: 4521
Os colchetes dizem: "o nome desta propriedade é o valor da variável ID", ou seja, o símbolo (é a mesma escrita do [Symbol.iterator]). Sem colchetes, ID: 4521 criaria uma propriedade comum chamada "ID".
{ … Symbol(id): 4521 }
O console.log do Node mostra a propriedade de símbolo, com o nome Symbol(id).
cliente[ID] → 4521
Para ler, colchetes com a mesma variável.
Object.keys, JSON.stringify, for … in
Os três ignoram as chaves de símbolo: só aparecem nome e cidade. A propriedade existe, mas não atrapalha quem percorre o objeto nem vai junto quando ele é transformado em JSON.
Object.getOwnPropertySymbols(cliente)
"Pegar os símbolos próprios do objeto": o jeito de listar justamente essas chaves. Elas não são secretas, só ficam fora do caminho.
cliente.ID e cliente["id"] → undefined
Com ponto, o nome é o texto "ID"; com ["id"], o texto "id". Nenhum dos dois é o símbolo.
Escondido não é secreto

Uma chave de símbolo não aparece no Object.keys, mas qualquer código pode achá-la com Object.getOwnPropertySymbols, e o console.log mostra. Não use símbolos para esconder senhas. Para dados realmente privados numa classe, existem os campos privados (#).

Missão: o código interno do cliente não deve ir junto quando o cliente é transformado em JSON (para mandar ao site de entregas). Troque a propriedade codigo por uma chave de símbolo: crie const CODIGO = Symbol("codigo");, use [CODIGO]: 4521 no objeto e cliente[CODIGO] na última linha.

const cliente = {
  nome: "Ana",
  cidade: "Recife",
  codigo: 4521,
};

console.log(JSON.stringify(cliente));
console.log(`Código interno: ${cliente.codigo}`);

const CODIGO = Symbol("codigo");

const cliente = {
  nome: "Ana",
  cidade: "Recife",
  [CODIGO]: 4521,
};

console.log(JSON.stringify(cliente));
console.log(`Código interno: ${cliente[CODIGO]}`);

3. Para que serve: nomes que não se chocam

Imagine que o objeto do pedido de pizza é usado por dois pedaços de código, escritos por pessoas diferentes: o seu, que usa pedido.id para o número do pedido, e uma biblioteca de entregas, que quer pendurar no pedido o código da entrega dela. Se a biblioteca escrevesse pedido.id = "ENT-2091", apagaria o seu número sem ninguém perceber. Com um símbolo, não há como os nomes se chocarem:

const pedido = { id: 7, sabor: "calabresa" };

// uma "biblioteca" de entregas quer marcar o pedido sem estragar o id dele
const ID_ENTREGA = Symbol("idEntrega");
pedido[ID_ENTREGA] = "ENT-2091";

// se ela tivesse usado o nome "id", teria apagado o número do pedido
console.log(pedido.id);
console.log(pedido[ID_ENTREGA]);
console.log(pedido);

$ node colisao.js
7
ENT-2091
{ id: 7, sabor: 'calabresa', Symbol(idEntrega): 'ENT-2091' }

O id continua 7. A propriedade da biblioteca só pode ser lida por quem tem a variável ID_ENTREGA, e não aparece no Object.keys nem no JSON do pedido. É exatamente por isso que o próprio JavaScript usa símbolos quando acrescenta recursos novos à linguagem: um nome como Symbol.iterator nunca vai bater com uma propriedade "iterator" que alguém já tenha criado num objeto antigo.

Constantes de estado

Outro uso: valores que só precisam ser diferentes uns dos outros, como os estados de um pedido:

const Status = Object.freeze({
  ABERTO: Symbol("aberto"),
  NO_FORNO: Symbol("no forno"),
  ENTREGUE: Symbol("entregue"),
});

let pedido = Status.NO_FORNO;

if (pedido === Status.NO_FORNO) {
  console.log("A pizza está assando.");
}
console.log(pedido === Symbol("no forno"));
console.log(pedido.description);
console.log(Status.ENTREGUE.toString());

$ node status.js
A pizza está assando.
false
no forno
Symbol(entregue)

Com textos ("no forno"), qualquer texto igual escrito em outro lugar passaria por um estado válido, e um erro de digitação ("no-forno") passaria em silêncio. Com símbolos, só vale quem usa Status.NO_FORNO: até um Symbol("no forno") novo é diferente (o false da segunda linha). O Object.freeze impede que alguém troque as constantes depois (veja Imutabilidade). Na prática, muita gente usa textos mesmo, porque eles aparecem bem no JSON; os símbolos ficam para quando a garantia de "só este valor" importa.

4. O símbolo compartilhado: Symbol.for

Às vezes você quer o mesmo símbolo em dois arquivos que não se conhecem. Para isso existe um "cartório" global de símbolos: Symbol.for("nome") procura no cartório um símbolo com esse nome; se não achar, cria e registra. Na segunda vez, devolve o mesmo:

const x = Symbol.for("loja.cliente");
const y = Symbol.for("loja.cliente");
console.log(x === y);
console.log(Symbol.keyFor(x));
console.log(Symbol.keyFor(Symbol("solto")));

$ node global.js
true
loja.cliente
undefined

Agora x === y dá true. O Symbol.keyFor devolve o nome com que o símbolo foi registrado; para um símbolo comum, que não passou pelo cartório, devolve undefined. Como o nome do cartório vale para o programa inteiro, use nomes compridos e específicos ("loja.cliente", e não "id"), senão volta o problema do choque de nomes.

5. Os símbolos do próprio JavaScript

O JavaScript guarda alguns símbolos prontos como propriedades do Symbol. Eles são "ganchos": quando você dá a um objeto seu um método com um desses nomes, a linguagem passa a usar esse método em situações especiais.

SímboloO JavaScript usa quando…
Symbol.iteratoro objeto vai num for … of ou num ... (aulas Iteradores e Geradores)
Symbol.toPrimitiveo objeto precisa virar número ou texto (numa conta, num template)
Symbol.toStringTago objeto é descrito como [object Nome]
Symbol.asyncIteratoro objeto vai num for await … of
console.log(typeof Symbol.iterator);
console.log(Symbol.iterator);

const preco = {
  valor: 7.5,
  [Symbol.toPrimitive](tipo) {
    if (tipo === "number") return this.valor;
    return `R$ ${this.valor.toFixed(2)}`;
  },
};
console.log(preco * 2);
console.log(`Total: ${preco}`);
console.log(+preco);

class Carrinho {
  get [Symbol.toStringTag]() {
    return "Carrinho";
  }
}
console.log(String(new Carrinho()));
console.log(Object.prototype.toString.call([]));

$ node conhecidos.js
symbol
Symbol(Symbol.iterator)
15
Total: R$ 7.50
7.5
[object Carrinho]
[object Array]
Symbol(Symbol.iterator)
O Symbol.iterator é um símbolo comum, com a descrição "Symbol.iterator".
[Symbol.toPrimitive](tipo)
"Para primitivo". O JavaScript chama este método quando precisa transformar o objeto num valor simples, e avisa no parâmetro o que prefere: "number" (numa conta como preco * 2 ou +preco), "string" (num template `${preco}`) ou "default" (no + com texto, no ==).
15 e 7.5
Na conta, o método devolveu o número 7.5.
Total: R$ 7.50
No template, devolveu o texto formatado (veja Formatando Números). Sem esse método, apareceria [object Object].
get [Symbol.toStringTag]()
Um getter com o nome do símbolo. Muda o "Object" do [object Object] para Carrinho. É o mesmo mecanismo que faz os arrays serem descritos como [object Array].

Formas diferentes de fazer a mesma coisa

Para dar a um objeto uma propriedade "extra", que não atrapalhe ninguém, há três caminhos:

  • Um nome comum com um prefixo combinado (_interno, __codigo): simples, aparece em tudo (Object.keys, JSON) e pode chocar com outro nome igual.
  • Um símbolo ([CODIGO]): não choca, fica fora do Object.keys e do JSON, mas qualquer um acha com getOwnPropertySymbols.
  • Um campo privado de classe (#codigo): realmente inacessível de fora (aula Campos Privados). Só existe dentro de classes.
SituaçãoQual usar
Propriedade comum, que deve aparecer e ir para o JSONNome de texto
Pendurar algo num objeto que não é seu, sem risco de choqueSymbol("descrição")
Mesmo símbolo em arquivos diferentesSymbol.for("nome.bem.especifico")
Dado realmente privado, dentro de uma classeCampo privado #nome
Objeto no for … of, ou com conversão própriaSymbol.iterator, Symbol.toPrimitive
Estados que só precisam ser diferentes entre siSímbolos num objeto congelado (ou textos, se precisarem ir para o JSON)

"Não dá para converter um valor Symbol em string". Números e booleanos viram texto sozinhos no +; símbolos, não, de propósito: para ninguém transformar uma chave única num texto comum sem perceber. O template string dá o mesmo erro: `A chave é ${id}` sai com a mesma mensagem, apontando a coluna do ${id}. Como consertar: converta você mesmo: String(id) (dá Symbol(id)) ou id.description (dá id).

Leu a propriedade com ponto

Criou [ID]: 4521 e leu cliente.ID: veio undefined, sem erro (seção 2). Com ponto, o nome é sempre o texto escrito depois dele. Como consertar: cliente[ID], com colchetes e a mesma variável usada na criação.

Criou o símbolo de novo para ler

cliente[Symbol("id")] também dá undefined: o Symbol("id") novo é outro símbolo, com o mesmo chaveirinho. Como consertar: crie o símbolo uma vez, numa constante, e use a constante em todo lugar (ou exporte-a de um módulo; ou, se precisar mesmo de um símbolo por nome, Symbol.for).

Missão: este programa quer mostrar Status: no forno, mas para com um erro. Rode, leia a mensagem e conserte usando a descrição do símbolo.

const NO_FORNO = Symbol("no forno");
const pedido = NO_FORNO;

console.log(`Status: ${pedido}`);

const NO_FORNO = Symbol("no forno");
const pedido = NO_FORNO;

console.log(`Status: ${pedido.description}`);

Missão final: o preço que sabe se mostrar

Missão: o objeto preco sai como [object Object] no texto e como NaN na conta. Dê a ele um método [Symbol.toPrimitive](tipo) que devolva this.valor quando o tipo for "number" e, nos outros casos, o texto `R$ ${this.valor.toFixed(2)}`.

  valor: 7.5,
};

console.log(`Total: ${preco}`);
console.log(`Três: ${preco * 3}`);

const preco = {
  valor: 7.5,
  [Symbol.toPrimitive](tipo) {
    if (tipo === "number") return this.valor;
    return `R$ ${this.valor.toFixed(2)}`;
  },
};

console.log(`Total: ${preco}`);
console.log(`Três: ${preco * 3}`);

Resumo

  • symbol é um tipo primitivo: Symbol("descrição") cria um valor único, que só é igual a ele mesmo. A descrição é só um rótulo (.description).
  • Símbolos servem de chave de objeto, sempre com colchetes: { [ID]: 1 } e obj[ID].
  • Chaves de símbolo ficam fora do Object.keys, do for … in e do JSON.stringify, mas não são secretas (getOwnPropertySymbols).
  • Usos: pendurar dados num objeto sem choque de nomes, e constantes que só precisam ser diferentes entre si.
  • Symbol.for("nome") dá o mesmo símbolo em qualquer lugar do programa.
  • Symbol.iterator, Symbol.toPrimitive e Symbol.toStringTag são ganchos para o seu objeto funcionar no for … of, nas conversões e na descrição.
  • Sem new, e sem + com texto: use String(s) ou s.description.
