JavaScript var: o Jeito Antigo

Nas duas últimas aulas você criou variáveis com let e const. Mas, se abrir um tutorial antigo, um livro de 2010 ou o código de um site que existe há anos, vai encontrar outra palavra em todo lugar: var (de variable, "variável"). Durante os primeiros vinte anos do JavaScript, ela era a única forma de criar variáveis. Esta aula mostra como ela funciona, para você reconhecer o var quando o encontrar, e os problemas que fizeram os programadores pararem de usá-lo.

Você vai aprender
  • Como se escreve um var e por que ele parece igual ao let.
  • Problema 1: o var deixa criar a mesma variável duas vezes, sem aviso.
  • Problema 2: dá para usar a variável antes do var, e ela vale undefined em vez de dar erro.
  • Problema 3: o var "vaza" para fora do bloco { } e do laço for.
  • Como trocar var por const ou let num código antigo.
Regra deste guia: nunca use var em código novo

Use const por padrão e let quando o valor muda. O var aparece aqui só para você entender código antigo. Todos os programas da aula rodaram no Node.js v24.22.0 da máquina da Ana (ana@notebook).

Um pouco de história

O JavaScript nasceu em 1995, com o var. Em 2015, a versão da linguagem chamada ES2015 (também conhecida como ES6) trouxe o let e o const, criados justamente para consertar os problemas do var. O var não foi removido: se fosse, milhões de sites antigos parariam de funcionar. Ele continua lá, funcionando do mesmo jeito estranho de sempre.

É como uma tomada antiga de dois pinos numa casa reformada: ainda funciona, você vai encontrá-la por aí, mas ninguém instala uma nova.

1. Como se escreve

À primeira vista, o var é igualzinho ao let:

var cliente = "Ana";
var pontos = 10;
pontos = pontos + 5;
console.log(cliente, "tem", pontos, "pontos.");

$ node antigo.js
Ana tem 15 pontos.
var
Cria a variável, no mesmo lugar onde iria o let ou o const.
cliente = "Ana"
Nome e valor, como sempre.
pontos = pontos + 5;
Como no let, o valor pode mudar. Não existe "var constante".

Num programa curto assim, não há diferença nenhuma. Os problemas aparecem em programas maiores, em três situações.

2. Problema 1: criar duas vezes, sem aviso

Num programa de 300 linhas, a Ana criou um total lá em cima. Duzentas linhas depois, esqueceu e criou outro total, para outra coisa:

var total = 50;
console.log("Total da compra:", total);
var total = 0;
console.log("Total da compra:", total);

$ node duas.js
Total da compra: 50
Total da compra: 0

Nenhum erro: o segundo var total simplesmente passou por cima do primeiro, e o valor da compra se perdeu. Num programa grande, esse defeito pode levar horas para ser encontrado. Agora o mesmo programa com let:

let total = 50;
console.log("Total da compra:", total);
let total = 0;
console.log("Total da compra:", total);

$ node duaslet.js
/home/ana/duaslet.js:3

O let reclama: "o identificador total já foi declarado", apontando a linha 3. Ele nem deixa o programa começar. Um erro que aparece na hora, com o número da linha, é muito melhor que um defeito silencioso.

3. Problema 2: usar antes de criar dá undefined

console.log("Pães:", paes);
var paes = 6;
console.log("Pães:", paes);

$ node antes.js
Pães: undefined
Pães: 6

A linha 1 usa paes antes de o var criá-la, e mesmo assim não deu erro: mostrou undefined. Isso acontece porque, antes de rodar o programa, o JavaScript "puxa para o topo" a criação de todas as variáveis var (sem o valor). É como se o programa fosse:

var paes;                     // a criação "subiu" para o topo, vazia
console.log("Pães:", paes);   // undefined
paes = 6;                     // o valor fica onde estava
console.log("Pães:", paes);   // 6

Esse "puxar para o topo" tem nome: hoisting ("içamento", como içar uma bandeira); a aula Hoisting conta tudo. O problema é que um undefined silencioso no lugar de um número pode virar um defeito bem longe dali. Com let, o mesmo programa para na linha 1:

4. Problema 3: o var escapa do bloco

Na aula Variáveis (let) você viu que uma variável let criada dentro de um bloco { } só existe lá dentro. O var ignora os blocos:

var mensagem = "Bom dia";
{
  var mensagem = "Promoção!";
  console.log("Dentro:", mensagem);
}
console.log("Fora:", mensagem);

$ node bloco.js
Dentro: Promoção!
Fora: Promoção!

A intenção era ter uma mensagem só para dentro do bloco. Mas, para o var, o bloco não é uma "sala separada": o var mensagem de dentro é a mesma variável de fora, e o "Bom dia" foi perdido. Com let, cada bloco tem as suas:

let mensagem = "Bom dia";
{
  let mensagem = "Promoção!";
  console.log("Dentro:", mensagem);
}
console.log("Fora:", mensagem);

$ node blocolet.js
Dentro: Promoção!
Fora: Bom dia

O caso mais comum: o contador do for

Isso aparece muito com o laço for, que repete um trecho contando as voltas (ele tem aula própria: for; aqui basta saber que o i é o contador). Com var, o contador continua existindo depois do laço:

for (var i = 1; i <= 3; i++) {
  console.log("Volta", i);
}
console.log("Depois do laço, i vale", i);

$ node laco.js
Volta 1
Volta 2
Volta 3
Depois do laço, i vale 4

Com let, o i pertence ao laço e some quando ele termina:

O erro aqui é bom: ele mostra que o i não sobrou "solto" no programa, onde poderia ser usado por engano.

A única "sala" que o var respeita: a função

O var ignora blocos { }, if e for, mas respeita as funções (trechos de código com nome, assunto de Funções). Um var criado dentro de uma função não existe fora dela:

function calcular() {
  var desconto = 10;
  console.log("Dentro da função:", desconto);
}
calcular();
console.log("Fora da função:", desconto);

$ node funcao.js
Dentro da função: 10
/home/ana/funcao.js:6
console.log("Fora da função:", desconto);
                               ^

    at Object.<anonymous> (/home/ana/funcao.js:6:32)
    «  … mais 7 linhas "at" de dentro do Node (cortadas aqui)

Por isso se diz que o var tem escopo de função, e o let/const têm escopo de bloco (veja Escopo).

Missão: por causa do var, a mensagem de fora foi estragada pelo bloco. Troque os dois var por let e rode: tem de aparecer Dentro: Promoção! e Fora: Bom dia.

var mensagem = "Bom dia";
{
  var mensagem = "Promoção!";
  console.log("Dentro:", mensagem);
}
console.log("Fora:", mensagem);

let mensagem = "Bom dia";
{
  let mensagem = "Promoção!";
  console.log("Dentro:", mensagem);
}
console.log("Fora:", mensagem);

Trocando var por const ou let

Quando você encontrar var num código que vai mexer, a troca é simples. Para cada var, pergunte: "esse valor muda depois?"

  1. Não muda → troque por const.
  2. Muda (recebe outro valor mais adiante, ou é contador de laço) → troque por let.
  3. Rode o programa. Se aparecer has already been declared ou is not defined, ótimo: você achou um dos problemas que o var escondia. Conserte (renomeie a segunda variável, ou crie a variável fora do bloco).

O programa da seção 1, modernizado:

const cliente = "Ana";
let pontos = 10;
pontos = pontos + 5;
console.log(cliente, "tem", pontos, "pontos.");

$ node mudado.js
Ana tem 15 pontos.

A saída é a mesma; o código agora diz que o cliente não muda e que os pontos mudam.

E no navegador?

No navegador, um var criado fora de qualquer função, num <script> comum, vira também uma propriedade do objeto window (a janela), visível para todos os scripts da página: mais um jeito de dois scripts estragarem as variáveis um do outro. O let e o const não fazem isso. O window aparece na aula O que é o DOM.

Quando dá errado

A maior parte dos problemas do var não dá erro: é exatamente esse o perigo. Os cenários abaixo resumem os sintomas.

Um valor "sumiu" e foi trocado por outro

Sintoma: a variável tem um valor que você não pôs ali. Causa provável: dois var com o mesmo nome (seção 2), ou um var dentro de um bloco que passou por cima do de fora (seção 4). Como consertar: troque por let/const; o Node vai apontar a linha repetida com SyntaxError: Identifier '…' has already been declared.

Apareceu undefined onde devia ter um número

Sintoma: Pães: undefined. Causa provável: a variável foi usada numa linha acima do var dela (seção 3). Como consertar: crie a variável antes de usar; com let/const, esse engano vira ReferenceError: Cannot access '…' before initialization, que aponta a linha.

Misturou let e var com o mesmo nome 
let nome = "Ana";
var nome = "Bia";

$ node mistura.js
/home/ana/mistura.js:2
var nome = "Bia";
    ^

SyntaxError: Identifier 'nome' has already been declared
    «  … linhas "at" de dentro do Node (cortadas aqui)

Node.js v24.22.0

Quando um dos dois é let (ou const), a repetição vira erro, mesmo que o outro seja var. Isso costuma acontecer quando se moderniza um código pela metade. Como consertar: termine a troca: nenhum var, e um nome para cada coisa.

Trocou var por const numa variável que muda

Sintoma: depois da troca, TypeError: Assignment to constant variable. Causa: aquele valor recebe outro mais adiante (veja Constantes). Como consertar: use let nela.

Missão: modernize este programa antigo. Troque cada var por const (o que não muda) ou let (o que muda). O PRECO não muda; o itens e o total mudam. A saída tem de continuar a mesma.

var PRECO = 3.5;
var itens = 0;
var total = 0;
itens = itens + 3;
total = itens * PRECO;
console.log("Itens:", itens);
console.log("Total:", total);

const PRECO = 3.5;
let itens = 0;
let total = 0;
itens = itens + 3;
total = itens * PRECO;
console.log("Itens:", itens);
console.log("Total:", total);

Resumo

  • var é a forma antiga (1995) de criar variáveis. O let e o const chegaram no ES2015 para consertar os problemas dele.
  • Com var, criar a mesma variável duas vezes não dá erro: a segunda passa por cima.
  • Com var, usar a variável antes de criá-la dá undefined (o hoisting), em vez de erro.
  • O var ignora os blocos { }, o if e o for: só respeita as funções.
  • Os três problemas não dão erro; viram defeitos silenciosos. O let e o const transformam cada um num erro com o número da linha.
  • Em código novo: nunca var. Em código antigo: troque por const (não muda) ou let (muda).
