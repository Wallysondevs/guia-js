JavaScript Várias Promises

Na aula async e await, cada await esperava a tarefa anterior terminar para começar a próxima. Às vezes é isso mesmo que você quer (só dá para passar o café depois de ferver a água). Mas quando as tarefas não dependem umas das outras, esperar uma por uma é perder tempo. O objeto Promise tem quatro funções para lidar com várias Promises de uma vez: Promise.all, Promise.allSettled, Promise.race e Promise.any.

Você vai aprender
  • A diferença de tempo entre esperar as tarefas uma por uma e todas juntas.
  • Promise.all: espera todas e entrega os resultados num array, na ordem; com desestruturação e com map.
  • O que acontece com o Promise.all quando uma das tarefas falha.
  • Promise.allSettled: o relatório de todas, deu certo ou não.
  • Promise.race: a primeira que terminar (e como usá-la para pôr um limite de tempo).
  • Promise.any: a primeira que der certo, e o AggregateError quando todas falham.
  • Os erros reais: esquecer os colchetes, esquecer o await e passar a função sem chamá-la.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook) com node arquivo.js. Eles usam o await no topo do arquivo, que o Node 24 aceita direto (veja async e await).

A ideia: as encomendas da festa

A Ana está organizando o aniversário da sobrinha e precisa de três coisas: o bolo (a confeitaria leva 3 horas), os salgados (2 horas) e o suco (1 hora). Ela tem dois jeitos de encomendar:

  1. Uma por uma: liga para a confeitaria, espera o bolo chegar, só então liga para os salgados, espera, e depois liga para o suco. Total: 3 + 2 + 1 = 6 horas.
  2. Todas juntas: liga para as três lojas logo de manhã e espera tudo chegar. As três trabalham ao mesmo tempo, e o tempo total é o da mais demorada: 3 horas.

O segundo jeito é o Promise.all. Ele não deixa as lojas mais rápidas; só faz você não esperar uma para começar a outra.

1. Uma por uma × todas juntas

Nos programas, as horas viraram segundos. A função encomendar(item, segundos) devolve uma Promise que se resolve depois de tantos segundos. O console.time e o console.timeEnd medem quanto tempo passou entre os dois (veja console.error, warn e table).

Primeiro, uma por uma, com três await seguidos:

function encomendar(item, segundos) {
  return new Promise((resolve) => {
    setTimeout(() => resolve(`${item} chegou`), segundos * 1000);
  });
}

console.time("tempo total");
const bolo = await encomendar("bolo", 3);
const salgados = await encomendar("salgados", 2);
const suco = await encomendar("suco", 1);

2. Promise.all com map: uma Promise para cada item

Quando a lista vem de um array, você não escreve as Promises uma a uma: o map transforma cada item numa Promise, e o Promise.all espera todas. A Ana consulta o preço de cada produto da lista de compras (cada consulta leva meio segundo):

function consultarPreco(produto) {
  const precos = { arroz: 6.5, feijao: 8.9, cafe: 19.9 };
  return new Promise((resolve) => {
    setTimeout(() => resolve(precos[produto]), 500);
  });
}

const lista = ["arroz", "feijao", "cafe"];
const precos = await Promise.all(lista.map((produto) => consultarPreco(produto)));
console.log(precos);
const total = precos.reduce((soma, preco) => soma + preco, 0);
console.log(`Total: R$ ${total.toFixed(2)}`);

$ node all-map.js
[ 6.5, 8.9, 19.9 ]
Total: R$ 35.30
lista.map((produto) => consultarPreco(produto))
Para cada produto, chama consultarPreco. O resultado é um array de Promises (três "senhas"), todas começando ao mesmo tempo.
await Promise.all(…)
Espera as três. Tudo leva meio segundo, e não um segundo e meio.
precos.reduce(…)
Com os números na mão, soma tudo com o reduce.

É o par mais comum do dia a dia: await Promise.all(lista.map(…)). Funciona igual com 3 ou com 300 itens.

Valores que não são Promises

O array pode misturar Promises e valores comuns: os valores comuns passam direto. No lab, await Promise.all([1, "dois", Promise.resolve(3)]) deu [ 1, 'dois', 3 ], e await Promise.all([]), com o array vazio, deu [] na hora.

3. Quando uma falha, o Promise.all inteiro falha

O Promise.all é "tudo ou nada". Se uma das Promises for rejeitada, a Promise do all é rejeitada na mesma hora, com o erro dessa, e os outros resultados se perdem. Agora a função encomendar tem um terceiro parâmetro, deuCerto (com valor padrão true; veja Parâmetros Padrão), e a loja dos salgados fechou:

function encomendar(item, segundos, deuCerto = true) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (deuCerto) {
        resolve(`${item} chegou`);
      } else {
        reject(new Error(`a loja do ${item} fechou`));
      }
    }, segundos * 1000);
  });
}

try {
  const itens = await Promise.all([
    encomendar("bolo", 3),
    encomendar("salgados", 2, false),
    encomendar("suco", 1),
  ]);
  console.log(itens);
} catch (erro) {
  console.log(`A festa atrasou: ${erro.message}`);
}

$ node all-falha.js
A festa atrasou: a loja do salgados fechou      « depois de 2 segundos, não de 3

O suco chegou (em 1 segundo) e o bolo também ia chegar, mas o catch só recebe o erro dos salgados. O Promise.all desistiu no segundo 2, sem esperar o bolo. (O bolo continuou "assando": o Promise.all não cancela as outras tarefas, só para de esperar por elas.)

Use o Promise.all quando precisa de todos os resultados e qualquer falha estraga o conjunto: sem um dos preços, o total da compra não serve. Quando cada resultado vale por si, use o próximo.

4. Promise.allSettled: o relatório de todas ES2020

Settled quer dizer "resolvida", no sentido de "decidida": deu certo ou deu errado, mas acabou. O Promise.allSettled espera todas acabarem, nunca é rejeitado, e entrega um relatório com um objeto para cada Promise:

const relatorio = await Promise.allSettled([
  encomendar("bolo", 3),
  encomendar("salgados", 2, false),
  encomendar("suco", 1),
]);
console.log(relatorio);

5. Promise.race: a primeira que terminar

Race é "corrida". O Promise.race se decide pela primeira Promise que terminar, dando certo ou errado; as outras são ignoradas. Três entregadores saíram com a mesma encomenda:

function entregador(nome, segundos) {
  return new Promise((resolve) => {
    setTimeout(() => resolve(`${nome} chegou primeiro`), segundos * 1000);
  });
}

const vencedor = await Promise.race([
  entregador("Bia, de bicicleta", 2),
  entregador("Caio, de moto", 1),
  entregador("Davi, a pé", 3),
]);
console.log(vencedor);

$ node race.js
Caio, de moto chegou primeiro

O uso clássico: um limite de tempo

O race brilha para dizer "espero no máximo tanto tempo". Ponha na corrida a tarefa de verdade e uma Promise que é rejeitada depois do limite. Quem chegar primeiro decide:

function esperar(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

function limiteDeTempo(ms) {
  return new Promise((resolve, reject) => {
    setTimeout(() => reject(new Error(`passou de ${ms} ms`)), ms);
  });
}

async function buscarCardapio() {
  await esperar(3000);
  return "cardápio do dia";
}

try {
  const cardapio = await Promise.race([buscarCardapio(), limiteDeTempo(1000)]);
  console.log(cardapio);
} catch (erro) {
  console.log(`Desisti: ${erro.message}`);
}

$ node race-tempo.js
Desisti: passou de 1000 ms

O cardápio levaria 3 segundos; o limite, 1. O limite "ganhou a corrida" com uma rejeição, e o catch a pegou. Troque o 3000 por 500 e o cardápio é que vence.

6. Promise.any: a primeira que der certo ES2021

O Promise.any ("qualquer uma") parece o race, mas ignora as falhas: ele fica com a primeira Promise que der certo. A Ana liga para três lojas perguntando quem tem bolo de chocolate:

function perguntar(loja, segundos, temBolo) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (temBolo) {
        resolve(`${loja} tem bolo`);
      } else {
        reject(new Error(`${loja} não tem bolo`));
      }
    }, segundos * 1000);
  });
}

const resposta = await Promise.any([
  perguntar("Padaria Sol", 1, false),
  perguntar("Doce Lar", 2, true),
  perguntar("Confeitaria Lua", 3, true),
]);
console.log(resposta);

$ node any.js
Doce Lar tem bolo

A Padaria Sol respondeu primeiro, mas com um "não" (rejeição): o any ignorou e esperou a próxima. Com o race, esse "não" teria decidido a corrida.

Se todas falharem, o any é rejeitado com um erro especial, o AggregateError ("erro agregado", que junta vários). A lista dos erros fica na propriedade errors:

try {
  await Promise.any([
    perguntar("Padaria Sol", 1, false),
    perguntar("Doce Lar", 2, false),
  ]);
} catch (erro) {
  console.log(erro.message);
  for (const e of erro.errors) {
    console.log(`- ${e.message}`);
  }
}

$ node any-catch.js
All promises were rejected
- Padaria Sol não tem bolo
- Doce Lar não tem bolo

All promises were rejected quer dizer "todas as Promises foram rejeitadas". Sem o try … catch, o programa cai mostrando o AggregateError inteiro (veja em Quando dá errado).

}
console.log(`Total: R$ ${total.toFixed(2)}`);

function consultarPreco(produto) {
  const precos = { arroz: 6.5, feijao: 8.9, cafe: 19.9 };
  return new Promise((resolve) => {
    setTimeout(() => resolve(precos[produto]), 500);
  });
}

const lista = ["arroz", "feijao", "cafe"];
const precos = await Promise.all(lista.map((produto) => consultarPreco(produto)));
const total = precos.reduce((soma, preco) => soma + preco, 0);
console.log(`Total: R$ ${total.toFixed(2)}`);

Repare que o código inicial ainda tem um defeito: ele nunca soma nada no total, e mostra Total: R$ 0.00. Na solução, o reduce resolve isso.

Resumo

  • Tarefas que não dependem umas das outras podem andar juntas: o tempo total vira o da mais demorada, e não a soma.
  • await Promise.all([…]) espera todas e dá os valores num array, na ordem do array de entrada. Combina com desestruturação e com lista.map(…).
  • No Promise.all, uma falha derruba tudo: use try … catch.
  • Promise.allSettled nunca falha: entrega um relatório com status ('fulfilled'/'rejected'), value ou reason.
  • Promise.race fica com a primeira que terminar (bom para limite de tempo); Promise.any, com a primeira que der certo (ou AggregateError).
  • As Promises vão dentro de [ ], as funções são chamadas com (), e o resultado precisa de await.
