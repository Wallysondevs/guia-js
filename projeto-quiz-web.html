Projeto Quiz na Página

A Ana quer testar o que aprendeu de JavaScript com um quiz: uma pergunta por vez, quatro opções em botões, a resposta na hora ("Certo!" ou "Errado! A resposta é…"), o placar no fim e o recorde guardado. É um projeto pequeno que junta quase tudo de "A Página Web": dados num array, elementos criados pelo JavaScript, eventos e localStorage. E as perguntas do quiz são sobre pegadinhas que você já viu neste guia.

Você vai praticar
  • Guardar as perguntas num array de objetos.
  • Criar um botão para cada opção com createElement e forEach.
  • Saber em qual botão a pessoa clicou, com uma arrow function que "lembra" da posição (closure).
  • Avançar de pergunta com uma variável de estado e mostrar o placar.
  • Desabilitar botões e colorir com classList.
  • Guardar o recorde com localStorage.

O que vamos construir

A página mostra "Pergunta 1 de 5", a pergunta e um botão para cada opção. Ao clicar, as opções travam, a certa fica verde (e a escolhida, se errada, vermelha), aparece o resultado e o botão Próxima. No fim: "Você acertou 4 de 5. Novo recorde!", o recorde guardado e o botão Jogar de novo. A Ana jogou duas vezes no Chromium do computador dela (errou a primeira pergunta na primeira vez e acertou tudo na segunda); o texto dos parágrafos, lido em cada momento:

> localStorage.getItem("quiz-recorde")
null
  • ao abrir: Seu recorde: 0 de 5;
  • no fim da primeira partida: Você acertou 4 de 5. Novo recorde! e Seu recorde: 4 de 5;
  • depois de Jogar de novo: Pergunta 1 de 5;
  • no fim da segunda: Você acertou 5 de 5. Novo recorde! e Seu recorde: 5 de 5.

Vamos chegar lá em quatro versões:

  1. Uma pergunta (objeto, botões criados, clique).
  2. Várias perguntas e o placar (array, atual, acertos, Próxima).
  3. Uma resposta só, com cores (disabled, classList).
  4. Recorde e Jogar de novo (localStorage).

Antes de começar

Crie a pasta quiz com o index.html, o style.css e o script.js, e abra o index.html no navegador (veja JavaScript na Página). Nas caixas Experimente, responda as perguntas clicando no quadro Resultado.

Versão 1 · Uma pergunta

Uma pergunta de múltipla escolha tem três partes: o texto, as opções e qual delas é a certa. Um objeto guarda as três. A certa é guardada pela posição no array de opções (0 é a primeira), e não pelo texto: assim, mudar a forma de escrever uma opção não estraga a correção.

Um for com var: todos os botões dizem "Errado"

A Ana trocou o forEach por um for com o var que viu num tutorial antigo:

for (var i = 0; i < pergunta.opcoes.length; i++) {
  const botao = document.createElement("button");
  botao.textContent = pergunta.opcoes[i];
  botao.addEventListener("click", () => {
    if (i === pergunta.certa) {
      elResultado.textContent = "Certo!";

Ela clicou na opção certa, "105", e a página respondeu Errado! A resposta é "105". No Console:

> i
4

O var cria uma variável i para o laço inteiro (e ela até existe fora dele, na página toda). Os quatro botões lembram da mesma variável, e quando alguém clica, o laço já terminou: i vale 4 para todos, e 4 nunca é a certa. Com let, cada volta do laço tem o seu próprio i, e tudo funciona. É um dos motivos para nunca usar var (veja var: o Jeito Antigo). Nenhum erro aparece: só a resposta errada.

Versão 2 · Várias perguntas e o placar

Agora as perguntas viram um array, e a página precisa lembrar de duas coisas enquanto a Ana joga: em qual pergunta está (atual) e quantas acertou (acertos). Três funções fazem o trabalho: mostrarPergunta desenha a pergunta atual, responder confere o clique, e mostrarFim mostra o placar. O botão Próxima começa escondido.

const elProgresso = document.querySelector("#progresso");
const elPergunta = document.querySelector("#pergunta");
const elOpcoes = document.querySelector("#opcoes");
const elResultado = document.querySelector("#resultado");
const botaoProxima = document.querySelector("#proxima");

let atual = 0;    // a posição da pergunta na tela
let acertos = 0;

function mostrarPergunta() {
  const p = perguntas[atual];
  elProgresso.textContent = `Pergunta ${atual + 1} de ${perguntas.length}`;
  elPergunta.textContent = p.texto;
  elResultado.textContent = "";
  botaoProxima.hidden = true;
  elOpcoes.replaceChildren();
  p.opcoes.forEach((opcao, i) => {
    const botao = document.createElement("button");
    botao.textContent = opcao;
    botao.addEventListener("click", () => responder(i));
    elOpcoes.append(botao);
  });
}

function responder(escolha) {
  const p = perguntas[atual];
  if (escolha === p.certa) {
    acertos++;
    elResultado.textContent = "Certo!";
  } else {
    elResultado.textContent = `Errado! A resposta é ${p.opcoes[p.certa]}.`;
  }
  botaoProxima.hidden = false;
}

function mostrarFim() {
  elProgresso.textContent = "";
  elPergunta.textContent = "Fim do quiz!";
  elOpcoes.replaceChildren();
  elResultado.textContent = `Você acertou ${acertos} de ${perguntas.length}.`;
  botaoProxima.hidden = true;
}

botaoProxima.addEventListener("click", () => {
  atual++;
  if (atual < perguntas.length) {
    mostrarPergunta();
  } else {
    mostrarFim();
  }
});

Chamar a função no addEventListener: o quiz responde sozinho

Na pressa, a Ana escreveu botao.addEventListener("click", responder(i));, sem o () =>. A página abriu já mostrando Errado! A resposta é "105"., sem ninguém clicar, e com o botão Próxima à mostra. No Console:

> acertos
1
> botaoProxima.hidden
false

Clicar nos botões não mudou mais nada. O que aconteceu: responder(i), com parênteses, chama a função na hora, durante a criação dos botões. As quatro opções foram "respondidas" uma atrás da outra (a segunda contou um acerto, a última deixou a mensagem de erro), e o addEventListener recebeu o que responder devolveu: undefined. É o mesmo erro do setInterval(atualizar(), 1000) do projeto do relógio: para entregar uma função que deve rodar depois, ou você passa o nome dela sem parênteses, ou embrulha a chamada numa arrow function, () => responder(i).

Clicar várias vezes: "Você acertou 7 de 5."

A Ana clicou três vezes na opção certa da primeira pergunta e, na segunda, clicou primeiro na errada e depois na certa. No fim, a página mostrou Você acertou 7 de 5. Cada clique na opção certa soma um acerto, e nada impede de clicar de novo. A versão 3 trava as opções depois da primeira resposta.

Versão 3 · Uma resposta só, com cores

Duas melhorias no responder: depois do clique, todos os botões da pergunta ficam desabilitados (nada de clicar de novo), a opção certa fica verde e, se a Ana errou, a escolhida fica vermelha. No CSS, duas classes:

#opcoes button.certo {
  background: #c8f7c5;
}

#opcoes button.errado {
  background: #f7c5c5;
}

E o responder novo (o resto do script.js fica igual):

function responder(escolha) {
  const p = perguntas[atual];
  const botoes = elOpcoes.querySelectorAll("button");
  for (const botao of botoes) {
    botao.disabled = true;
  }
  botoes[p.certa].classList.add("certo");
  if (escolha === p.certa) {
    acertos++;
    elResultado.textContent = "Certo!";
  } else {
    botoes[escolha].classList.add("errado");
    elResultado.textContent = `Errado! A resposta é ${p.opcoes[p.certa]}.`;
  }
  botaoProxima.hidden = false;
}
elOpcoes.querySelectorAll("button")
Todos os botões dentro de #opcoes, na ordem em que aparecem: a mesma ordem das opções. Por isso botoes[p.certa] é o botão da opção certa.
botao.disabled = true;
Um botão desabilitado fica cinza e não dispara mais o click.
classList.add("certo")
Acrescenta a classe; o CSS pinta de verde (veja classList).

A Ana clicou em "15" (errado) e, em seguida, tentou clicar em "105". O resultado continuou Errado! A resposta é "105"., e o placar não mudou. No Console:

> [...document.querySelectorAll("#opcoes button")].map((b) => `${b.textContent} ${b.className} ${b.disabled}`)
(4) ['15 errado true', '"105" certo true', 'NaN  true', 'Dá erro  true']
> acertos
0

As quatro opções desabilitadas (true), a escolhida com a classe errado, a certa com certo, e nenhum acerto contado pelo segundo clique.

Desafio extra: embaralhar as perguntas

Jogando de novo, a Ana já sabe a ordem das perguntas de cor. A solução é embaralhar o array antes de cada partida. O jeito certo de embaralhar é o algoritmo de Fisher-Yates: do fim para o começo, troca cada item com um item sorteado entre ele e os anteriores (veja Math.random):

// Embaralha a lista no lugar (algoritmo de Fisher-Yates)
function embaralhar(lista) {
  for (let i = lista.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [lista[i], lista[j]] = [lista[j], lista[i]];
  }
}

O [lista[i], lista[j]] = [lista[j], lista[i]] troca dois itens de lugar numa linha, com desestruturação. Chame embaralhar(perguntas) antes da primeira mostrarPergunta() e no Jogar de novo. Como a ordem muda a cada vez, a Ana conferiu no Console, abrindo a página três vezes, a posição certa de cada pergunta na ordem sorteada:

> perguntas.map((p) => p.certa).join(",")
'1,1,1,0,2'
> perguntas.map((p) => p.certa).join(",")
'0,1,2,1,1'
> perguntas.map((p) => p.certa).join(",")
'1,1,0,2,1'

Três ordens diferentes. (Você vai achar na internet o atalho perguntas.sort(() => Math.random() - 0.5): ele embaralha, mas não de forma justa; algumas ordens saem mais que outras. Prefira o Fisher-Yates.)

// Embaralha a lista no lugar (algoritmo de Fisher-Yates)
function embaralhar(lista) {
  for (let i = lista.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [lista[i], lista[j]] = [lista[j], lista[i]];
  }
}

Resumo

  • Dados primeiro: as perguntas num array de objetos, com a resposta certa pela posição.
  • Os botões nascem do array (forEach + createElement), e cada um lembra da sua posição pela closure. Com var no laço, todos lembrariam da mesma.
  • No addEventListener, entregue uma função (() => responder(i)), nunca a chamada (responder(i)).
  • O estado do jogo (atual, acertos) fica em variáveis let; cada tela é desenhada a partir dele.
  • Desabilite o que não pode ser clicado de novo; hidden esconde e mostra.
  • O localStorage guarda texto: converta com Number ao ler.
