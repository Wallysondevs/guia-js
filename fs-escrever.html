JavaScript Escrevendo Arquivos (fs)

Na aula Lendo Arquivos, os programas leram o que já estava guardado. Agora eles vão guardar: anotar as vendas do dia, salvar a lista de compras, atualizar o estoque. É assim que um programa "lembra" das coisas de uma execução para a outra. Quem escreve é o mesmo módulo node:fs, e o recurso continua sendo só do Node (no navegador, o jeito de guardar dados é outro: localStorage).

Você vai aprender
  • Como criar um arquivo, ou trocar todo o conteúdo dele, com writeFileSync.
  • Como acrescentar no fim, sem apagar o que havia, com appendFileSync.
  • Como salvar uma lista (com join) e um objeto (com JSON.stringify).
  • O ciclo "ler → mudar → gravar", que dá memória ao programa.
  • Como criar pastas (mkdirSync), não apagar um arquivo que já existe (flag "wx") e apagar um arquivo (unlinkSync).
  • A versão que não trava: writeFile com await.
  • Os erros reais: escrever um número, um objeto, numa pasta que não existe, num arquivo protegido.

Todos os programas rodaram no Node.js v24.22.0 da máquina da Ana (usuária ana, computador notebook), na pasta /home/ana/escrever.

A ideia: o quadro branco e o caderno de vendas

Na padaria há dois jeitos de anotar:

  • O quadro branco da cozinha: para escrever o aviso de hoje, a Ana apaga o de ontem e escreve o novo. Ali só cabe uma coisa por vez.
  • O caderno de vendas do caixa: cada venda vai numa linha nova, embaixo das outras. Nada se apaga.

O fs tem uma função para cada um: writeFileSync é o quadro branco (substitui tudo); appendFileSync é o caderno (acrescenta no fim). Escolher a errada é o erro mais comum desta aula: usar o quadro branco quando se queria o caderno apaga o histórico.

1. Criando um arquivo: writeFileSync

const fs = require("node:fs");

fs.writeFileSync("bilhete.txt", "Comprar farinha e fermento.\n");
console.log("Bilhete escrito!");
fs.writeFileSync(…)
"Escrever o arquivo, esperando terminar". Se o arquivo não existe, ele é criado; se existe, o conteúdo antigo é apagado e trocado pelo novo.
"bilhete.txt"
O nome do arquivo. Como na leitura, sem pasta na frente, ele vai para a pasta atual do terminal (veja Caminhos de Arquivo).
"Comprar farinha e fermento.\n"
O conteúdo: tem de ser uma string. O \n no fim é a quebra de linha (veja Caracteres Especiais): arquivos de texto costumam terminar com uma, e o cat fica mais bonito assim.

Não precisa passar o "utf8": para escrever texto, ele já é o padrão.

$ ls
$ node bilhete.js
Bilhete escrito!
$ ls
bilhete.js
bilhete.txt
$ cat bilhete.txt
Comprar farinha e fermento.

A pasta só tinha o programa; depois de rodar, apareceu o bilhete.txt, com o texto dentro.

Escrever de novo apaga o que havia

const fs = require("node:fs");

fs.writeFileSync("bilhete.txt", "Ligar para o fornecedor.\n");

$ node bilhete2.js
$ cat bilhete.txt
Ligar para o fornecedor.

O recado da farinha sumiu, sem aviso e sem lixeira. É o quadro branco. Antes de usar writeFileSync, pergunte: "posso perder o que está nesse arquivo?"

Missão: o programa só mostra o recado na tela. Faça-o gravar o recado no arquivo recado.txt, com fs.writeFileSync. Para conferir, acrescente no fim um console.log(fs.readFileSync("recado.txt", "utf8"));.

const fs = require("node:fs");

const recado = "Bom dia, Bia! A encomenda fica pronta às 10h.\n";
console.log(recado);

const fs = require("node:fs");

const recado = "Bom dia, Bia! A encomenda fica pronta às 10h.\n";
fs.writeFileSync("recado.txt", recado);
console.log("Recado gravado.");
No editor do guia

Os arquivos que o programa grava ficam numa pasta de mentira, na memória da caixa: valem até o programa terminar, e cada Rodar começa de novo só com as abas. Por isso, na caixa, o arquivo não "lembra" de uma execução para a outra (o vender.js da seção 3 diria sempre Restam 11.). Para ver o que foi gravado, leia o arquivo no fim do próprio programa, como a missão sugere. Na sua máquina, com node, os arquivos ficam no disco de verdade.

2. Acrescentando no fim: appendFileSync

Para o caderno de vendas, cada execução deve acrescentar uma linha. O programa recebe a venda pelos argumentos:

const fs = require("node:fs");

const venda = process.argv.slice(2).join(" ");
fs.appendFileSync("vendas.txt", venda + "\n");
console.log(`Anotado: ${venda}`);
process.argv.slice(2).join(" ")
Junta todos os argumentos numa frase: 3 sonhos.
fs.appendFileSync("vendas.txt", …)
"Acrescentar ao arquivo": escreve no fim, sem apagar nada. Se o arquivo não existe, ele é criado.
venda + "\n"
A quebra de linha no fim de cada venda. Sem ela, as vendas ficariam todas grudadas numa linha só: 3 sonhos2 broas.
$ node diario.js 3 sonhos
Anotado: 3 sonhos
$ node diario.js 2 broas
Anotado: 2 broas
$ node diario.js 1 bolo de fubá
Anotado: 1 bolo de fubá
$ cat vendas.txt
3 sonhos
2 broas
1 bolo de fubá

Três execuções, três linhas: o caderno guardou o histórico.

3. Salvando uma lista e um objeto

Uma lista: uma linha por item

O writeFileSync só aceita texto. Para gravar um array, transforme-o em texto com o join (veja split e join), que é o caminho inverso do split da leitura:

const fs = require("node:fs");

const compras = ["leite", "pão francês", "café"];
fs.writeFileSync("compras.txt", compras.join("\n") + "\n");
console.log(fs.readFileSync("compras.txt", "utf8"));

$ node lista.js
leite
pão francês
café

(A linha em branco no fim é a quebra de linha do arquivo mais a do console.log, como na aula de leitura.)

Um objeto: JSON.stringify

Para guardar dados com estrutura (objetos dentro de arrays, números, textos), o formato é o JSON. O JSON.stringify transforma o objeto em texto; o terceiro argumento, 2, pede 2 espaços de recuo, para o arquivo ficar legível:

const fs = require("node:fs");

const estoque = {
  loja: "Padaria da Ana",
  produtos: [
    { nome: "sonho", qtd: 12 },
    { nome: "broa", qtd: 7 },
  ],
};

fs.writeFileSync("estoque.json", JSON.stringify(estoque, null, 2) + "\n");
console.log("Estoque salvo.");

$ node salvar.js
Estoque salvo.
$ cat estoque.json
{
  "loja": "Padaria da Ana",
  "produtos": [
    {
      "nome": "sonho",
      "qtd": 12
    },
    {
      "nome": "broa",
      "qtd": 7
    }
  ]
}

Ler, mudar, gravar: a memória do programa

Juntando a leitura e a escrita, o programa passa a lembrar. A cada venda, ele lê o estoque, tira um sonho e grava de volta:

const fs = require("node:fs");

const estoque = JSON.parse(fs.readFileSync("estoque.json", "utf8"));
const sonho = estoque.produtos.find((p) => p.nome === "sonho");
sonho.qtd -= 1;
fs.writeFileSync("estoque.json", JSON.stringify(estoque, null, 2) + "\n");
console.log(`Vendi um sonho. Restam ${sonho.qtd}.`);
  1. Ler: readFileSync + JSON.parse trazem o estoque do arquivo para um objeto.
  2. Mudar: o find acha o sonho (veja Procurando) e o -= 1 tira uma unidade.
  3. Gravar: JSON.stringify + writeFileSync levam o objeto inteiro de volta para o arquivo, substituindo a versão antiga. Aqui o "quadro branco" é o certo: o arquivo tem de ter o estoque atual.
$ node vender.js
Vendi um sonho. Restam 11.
$ node vender.js
Vendi um sonho. Restam 10.
$ grep -A1 sonho estoque.json
      "nome": "sonho",
      "qtd": 10

Cada execução partiu do que a anterior deixou: 12, 11, 10. O grep confirma que o arquivo guardou o 10. É exatamente o que o Projeto: Lista de Tarefas faz.

4. Pastas, arquivos novos e apagar

Criar a pasta antes: mkdirSync

O writeFileSync cria o arquivo, mas não cria pastas. Escrever em relatorios/outubro.txt sem a pasta relatorios dá ENOENT (veja Quando dá errado). Crie a pasta antes com mkdirSync ("criar pasta"):

const fs = require("node:fs");
fs.mkdirSync("relatorios", { recursive: true });
fs.writeFileSync("relatorios/outubro.txt", "Vendas de outubro\n");
console.log(fs.readdirSync("relatorios"));

$ node pasta2.js
[ 'outubro.txt' ]
$ node pasta2.js
[ 'outubro.txt' ]

O { recursive: true } faz duas coisas: cria também as pastas do meio, se precisar ("a/b/c"), e não reclama se a pasta já existir. Por isso a segunda execução funcionou igual. O readdirSync ("ler a pasta") lista o que há dentro dela.

Só criar se ainda não existir: a flag "wx"

Para não apagar sem querer um arquivo importante, passe a opção flag: "wx" ("escrever, exclusivo"): se o arquivo já existir, em vez de substituí-lo, o Node dá o erro EEXIST ("já existe"), que você trata:

const fs = require("node:fs");
try {
  fs.writeFileSync("cadastro.txt", "Ana\n", { flag: "wx" });
  console.log("Cadastro criado.");
} catch (erro) {
  if (erro.code === "EEXIST") {
    console.log("O cadastro já existe; não vou apagar.");
  } else {
    throw erro;
  }
}

$ node novo.js
Cadastro criado.
$ node novo.js
O cadastro já existe; não vou apagar.

Apagar um arquivo: unlinkSync

const fs = require("node:fs");
fs.unlinkSync("bilhete.txt");
console.log(fs.existsSync("bilhete.txt"));

$ node apagar.js
false

unlinkSync ("desvincular") apaga o arquivo de vez: não vai para a lixeira. O existsSync confirmou: false. Rodar de novo dá ENOENT, porque não há mais o que apagar.

5. Sem travar: writeFile e appendFile com await

Como na leitura, o node:fs/promises tem as versões que não travam o programa enquanto o disco trabalha (veja async e await). Num arquivo .mjs:

import { writeFile, appendFile } from "node:fs/promises";

await writeFile("caixa.txt", "Abertura: R$ 100.00\n");
await appendFile("caixa.txt", "Venda: R$ 7.50\n");
console.log("Caixa anotado.");

$ node assinc.mjs
Caixa anotado.
$ cat caixa.txt
Abertura: R$ 100.00
Venda: R$ 7.50

O await em cada linha garante a ordem: primeiro o arquivo é criado, depois a venda é acrescentada. Sem o await, as duas operações poderiam correr ao mesmo tempo, e a ordem no arquivo não seria garantida.

Missão final: o caderno de vendas

3 sonhos

console.log(`Anotado: ${venda}`);

No lab, com o diario.js da seção 2 (que usa appendFileSync) e um vendas.txt que tinha só 3 sonhos:

Anotado: 2 broas
$ cat vendas.txt
3 sonhos
2 broas

Resumo

  • fs.writeFileSync(nome, texto) cria o arquivo ou substitui todo o conteúdo (o quadro branco). fs.appendFileSync(nome, texto) acrescenta no fim (o caderno).
  • O conteúdo tem de ser texto: String(n) para números, lista.join("\n") para listas, JSON.stringify(obj, null, 2) para objetos. Lembre o "\n" no fim das linhas.
  • Ler → mudar → gravar dá memória ao programa entre uma execução e outra.
  • mkdirSync(pasta, { recursive: true }) cria pastas; a flag "wx" evita sobrescrever; unlinkSync apaga de vez.
  • writeFile e appendFile de node:fs/promises, com await, escrevem sem travar o programa.
  • Erros comuns: ERR_INVALID_ARG_TYPE (não era texto), [object Object] (faltou o JSON.stringify), ENOENT (a pasta não existe), EACCES (sem permissão).
