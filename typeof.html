JavaScript typeof

Na aula Os Tipos de Dados você viu que "6" e 6 parecem iguais, mas um é texto e o outro é número, e que isso muda o resultado das contas. Como saber, com certeza, o tipo de um valor? Perguntando ao próprio JavaScript, com o typeof (de type of, "tipo de"). Você escreve typeof antes de um valor, e o JavaScript responde com o nome do tipo.

Você vai aprender
  • Como se usa o typeof e o que ele responde para cada tipo.
  • Que a resposta do typeof é um texto ("number"), e como comparar com ela.
  • As duas pegadinhas famosas: typeof null e typeof [] dão "object", e o Array.isArray.
  • Por que typeof 1 + 2 dá number2.
  • Os erros reais: typeOf com O maiúsculo, o tipo sem aspas e o tipo com maiúscula.

Todos os programas desta aula rodaram no Node.js v24.22.0 da máquina da Ana (ana@notebook), com node arquivo.js.

A ideia: perguntar "isto é o quê?"

A Ana recebe uma caixa sem etiqueta na padaria. Antes de usar, ela abre e olha: é farinha? É açúcar? É sal? Errar aqui estraga o bolo. O typeof faz isso com um valor: olha o que tem dentro e responde "é um número", "é um texto", "é um sim/não". Ele não muda nada; só responde.

1. O primeiro typeof

const nome = "Ana";
const idade = 30;
const temCadastro = true;
let apelido;
console.log(typeof nome);
console.log(typeof idade);
console.log(typeof temCadastro);
console.log(typeof apelido);

3. A resposta é um texto

O typeof devolve o nome do tipo como uma string. Dá para guardar numa variável, mostrar e comparar:

const tipo = typeof 42;
console.log(tipo);
console.log(typeof tipo);
console.log([tipo]);

$ node texto.js
number
string
[ 'number' ]

A variável tipo guardou o texto "number". O tipo desse texto é, claro, string. E, dentro da lista, ele aparece com aspas, como todo texto.

Comparando com ===

O uso mais comum do typeof é conferir se um valor é do tipo esperado. Para isso, compare a resposta com o nome do tipo, entre aspas, usando o === ("é exatamente igual a?", assunto de Comparação). A resposta é true ou false:

const preco = "4.50";
console.log(typeof preco === "number");
console.log(typeof preco === "string");

$ node conferir.js
false
true

"O tipo de preco é number?" Não (false): o preço veio como texto. Com o if, você vai poder usar essa resposta para decidir o que fazer: avisar o usuário, converter o valor… Esse é o jeito de se proteger do "6" + 1 = "61" da aula anterior.

4. As duas pegadinhas: null e arrays

typeof null é "object"

const telefone = null;
console.log(typeof telefone);
console.log(telefone === null);

$ node nulo.js
object
true

O null não é um objeto: é o vazio. Essa resposta é um erro que existe desde a primeira versão do JavaScript, em 1995. Ele nunca foi consertado porque muitos programas antigos dependem dele, e consertar os quebraria. Moral: para saber se um valor é null, não use typeof; compare direto: telefone === null (deu true).

typeof [] também é "object"

const compras = ["pão", "leite"];
const cliente = { nome: "Ana" };
console.log(typeof compras, typeof cliente);
console.log(Array.isArray(compras), Array.isArray(cliente));

$ node lista.js
object object
true false

Aqui não é erro: um array é um objeto (um objeto especial, com os itens numerados). Mas isso quer dizer que o typeof não distingue uma lista de um objeto comum. Para perguntar "isto é uma lista?", existe o Array.isArray(valor) ("é um array?"), que respondeu true para as compras e false para o cliente. Mais em Arrays.

E o NaN?

Uma conta impossível, como "abc" * 2, dá NaN ("não é um número", em inglês). E o typeof dele é… number:

const resultado = "abc" * 2;
console.log(resultado);
console.log(typeof resultado);

$ node nan.js
NaN
number

Parece piada, mas faz sentido: NaN é o valor especial que o tipo number usa para "resultado inválido". Ele é explicado em NaN, Infinity e a Precisão.

5. Parênteses e precedência: typeof 1 + 2

Você pode escrever typeof(preco), com parênteses, como se fosse uma função. Dá no mesmo:

const preco = 0.75;
console.log(typeof preco);
console.log(typeof(preco));
console.log(typeof (preco));

$ node parenteses.js
number
number
number

Mas atenção: o typeof pega só o valor logo depois dele. Numa conta, ele age antes do +:

console.log(typeof 1 + 2);
console.log(typeof (1 + 2));

$ node soma.js
number2
number
typeof 1 + 2 → number2
O JavaScript fez primeiro typeof 1, que dá o texto "number", e depois "number" + 2: texto mais número junta, e saiu "number2".
typeof (1 + 2) → number
Com parênteses em volta da conta, ela é feita primeiro (3), e o typeof pergunta o tipo do resultado.

Quem age primeiro numa expressão é o assunto de Precedência dos Operadores. Por enquanto: se for perguntar o tipo de uma conta, ponha a conta entre parênteses.

"number não está definido". Sem aspas, number é um nome de variável, e ela não existe. A resposta do typeof é um texto, então compare com um texto. Como consertar: typeof preco === "number".

Comparou com o tipo em maiúscula 
const preco = 0.75;
console.log(typeof preco);
console.log(typeof preco === "Number");

$ node maiusc2.js

Sem erro nenhum, e por isso é traiçoeiro: o typeof responde em minúsculas ("number"), e "number" não é igual a "Number". A comparação dá sempre false. Como consertar: escreva o tipo exatamente como na tabela da seção 2, em minúsculas.

Usou typeof para achar null ou uma lista

Sintoma: o programa trata um null ou uma lista como se fosse um objeto comum. Causa: typeof null e typeof [] dão "object" (seção 4). Como consertar: valor === null e Array.isArray(valor).

Missão: o programa deveria mostrar true (a idade é um número), mas não roda. São dois enganos na mesma linha. Conserte.

const idade = 30;
console.log(typeOf idade === Number);

const idade = 30;
console.log(typeof idade === "number");

Resumo

  • typeof valor responde o tipo do valor, como texto e em minúsculas: "string", "number", "boolean", "undefined", "bigint", "symbol", "object" ou "function".
  • Para conferir um tipo, compare com o nome entre aspas: typeof preco === "number".
  • Pegadinhas: typeof null e typeof [] dão "object". Use valor === null e Array.isArray(valor). E typeof NaN é "number".
  • O typeof pega só o valor logo depois dele: typeof 1 + 2 dá "number2"; para uma conta, use parênteses.
  • typeof de uma variável que não existe dá "undefined", sem erro (mas não antes do let/const dela).
