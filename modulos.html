JavaScript Módulos (import e export)

Até aqui, cada programa coube num arquivo só. Mas programas de verdade crescem: o sistema da lojinha da Ana tem contas, estoque, clientes, relatórios… Tudo num arquivo de 2 000 linhas vira uma gaveta bagunçada. A solução é dividir o programa em vários arquivos, cada um com um assunto, e deixar um arquivo usar o que o outro oferece. Cada um desses arquivos é um módulo. As palavras que ligam um ao outro são export ("exportar", oferecer para fora) e import ("importar", trazer para dentro).

Você vai aprender
  • O que é um módulo, e como exportar (export) e importar (import { … } from "./arquivo.js").
  • O export default, o import * as e como renomear com as.
  • Como o Node sabe que um arquivo é um módulo: a extensão .mjs, o "type": "module" no package.json e a detecção automática do Node 24.
  • Como importar os módulos que já vêm com o Node (node:fs, node:path…).
  • O que muda dentro de um módulo: cada um tem o seu escopo, roda uma vez só, está sempre em modo estrito e aceita await fora de função.
  • Os erros reais: o módulo que não é encontrado, o nome que não foi exportado, o require num módulo.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), numa pasta loja dentro da pasta pessoal dela. Os módulos que você vê aqui são os módulos ES (ESM, de ECMAScript Modules), o padrão oficial da linguagem desde o ES2015, que funciona igual no Node e no navegador. O Node também tem um sistema mais antigo, o CommonJS (require), que é o assunto da próxima aula.

A ideia: a cozinha do restaurante

Num restaurante, a cozinha tem várias bancadas. A bancada dos molhos prepara o molho de tomate e o molho branco e os coloca no balcão de saída. A bancada das massas pega no balcão o molho de que precisa, sem saber nem se importar com como ele foi feito.

  • Cada bancada é um módulo (um arquivo).
  • Pôr no balcão é export: "isto aqui, os outros podem usar".
  • Pegar no balcão é import: "eu vou usar o molho de tomate da bancada de molhos".
  • O que não vai para o balcão (o caderno de receitas da bancada, o tempero secreto) fica privado: ninguém de fora enxerga.

1. O primeiro módulo: export e import

A pasta loja tem três arquivos. O primeiro é o package.json, um arquivo de configuração do projeto (ele tem aula própria: O package.json). Por enquanto, ele só tem uma linha que importa: "os arquivos .js desta pasta são módulos".

{
  "type": "module"
}

O módulo das contas, que oferece funções:

export function somar(a, b) {
  return a + b;
}

export function aplicarDesconto(preco, porcento) {
  return preco - (preco * porcento) / 100;
}

export const TAXA_ENTREGA = 7.5;

function arredondar(valor) {
  return Math.round(valor * 100) / 100;
}

E o programa principal, que usa o que o contas.js oferece:

import { somar, aplicarDesconto, TAXA_ENTREGA } from "./contas.js";

const subtotal = somar(30, 20);
const comDesconto = aplicarDesconto(subtotal, 10);
console.log(`Subtotal: R$ ${subtotal}`);
console.log(`Com desconto: R$ ${comDesconto}`);
console.log(`Com entrega: R$ ${comDesconto + TAXA_ENTREGA}`);

$ cd loja
$ node main.js
Subtotal: R$ 50
Com desconto: R$ 45
Com entrega: R$ 52.5
export function somar…
O export na frente de uma função, de uma const ou de uma let a coloca "no balcão": outros arquivos podem importá-la. Isto se chama exportação nomeada (cada coisa sai com o seu nome).
function arredondar… (sem export)
Fica privada do contas.js: ele pode usar à vontade, mas ninguém de fora enxerga (veja Quando dá errado).
import { somar, aplicarDesconto, TAXA_ENTREGA }
Os nomes que você quer trazer, entre chaves, separados por vírgula. Têm de ser exatamente os nomes exportados.
from "./contas.js"
"De onde": o caminho do arquivo. O ./ quer dizer "nesta mesma pasta". No Node, com módulos ES, a extensão .js é obrigatória.
a linha do import no topo
Os import ficam no começo do arquivo, antes de tudo. O Node lê todos eles e carrega os outros módulos antes de rodar a primeira linha do main.js.

Repare que você roda só o main.js: o Node descobre sozinho, pelos import, que precisa do contas.js.

Missão: a caixa tem duas abas, main.js e contas.js. Na aba contas.js, crie e exporte uma função subtrair(a, b). Na aba main.js, importe-a junto com o somar. O programa deve mostrar Troco: R$ 8.

import { somar } from "./contas.js";

const total = somar(30, 12);
const troco = subtrair(50, total);
console.log(`Troco: R$ ${troco}`);

export function somar(a, b) {
  return a + b;
}

import { somar, subtrair } from "./contas.js";

const total = somar(30, 12);
const troco = subtrair(50, total);
console.log(`Troco: R$ ${troco}`);

export function somar(a, b) {
  return a + b;
}

export function subtrair(a, b) {
  return a - b;
}

2. Outras formas de exportar e importar

Importar tudo de uma vez: import * as

import * as contas from "./contas.js";
console.log(contas);
console.log(contas.somar(2, 3));

$ node tudo.js
[Module: null prototype] {
  TAXA_ENTREGA: 7.5,
  aplicarDesconto: [Function: aplicarDesconto],
  somar: [Function: somar]
}
5

O * as contas ("tudo, com o nome contas") junta todas as exportações num objeto só, e você usa com ponto: contas.somar. O Node mostra esse objeto como [Module: null prototype], "um módulo". Repare: o arredondar não está lá, porque não foi exportado. Essa forma é boa quando você usa muitas coisas do módulo, e deixa claro de onde cada uma vem.

Renomear: as

import { somar as mais, TAXA_ENTREGA as frete } from "./contas.js";
console.log(mais(1, 2), frete);

$ node renomear.js
3 7.5

O as ("como") dá outro nome ao que chega. Útil quando dois módulos exportam o mesmo nome, ou quando o nome original é comprido. Também dá para renomear na saída: export { somar as adicionar };.

A exportação padrão: export default

Quando um módulo tem uma coisa principal, ele pode exportá-la como padrão (default):

export default function saudar(nome) {
  return `Olá, ${nome}!`;
}

import saudar from "./saudacao.js";
import cumprimentar from "./saudacao.js";
console.log(saudar("Ana"));
console.log(cumprimentar("Bia"));

$ node usa-default.js
Olá, Ana!
Olá, Bia!

Duas diferenças em relação à exportação nomeada: no import, sem chaves; e quem importa escolhe o nome (saudar, cumprimentar, tanto faz: é a mesma função). Cada módulo pode ter um export default só.

No móduloQuem importa escreve
export function somar() {}import { somar } from "./contas.js";
export const TAXA = 7.5;import { TAXA } from "./contas.js";
export { somar, TAXA }; (no fim do arquivo)import { somar, TAXA } from "./contas.js";
export default function saudar() {}import saudar from "./saudacao.js"; (qualquer nome)
Qualquer um dos de cimaimport * as tudo from "./arquivo.js";
Nomeada ou padrão?

Na dúvida, prefira as exportações nomeadas. Com elas, o nome é o mesmo em todo o projeto (fica fácil procurar), e um nome errado no import dá erro na hora. O default é comum em bibliotecas que oferecem uma coisa principal.

3. Como o Node sabe que é um módulo?

Por razões históricas, o Node tem dois sistemas de módulos: o ESM desta aula e o CommonJS (o antigo, com require). Ele precisa decidir qual usar para cada arquivo. As regras do Node 24:

ArquivoO Node trata como
arquivo.mjsMódulo ES, sempre
arquivo.cjsCommonJS, sempre
arquivo.js com "type": "module" no package.json da pastaMódulo ES
arquivo.js com "type": "commonjs"CommonJS
arquivo.js sem "type"CommonJS, a não ser que o arquivo tenha import/export: aí o Node detecta e trata como módulo ES

Com .mjs

A extensão .mjs ("module JS") resolve sem nenhuma configuração:

import { somar } from "./contas.mjs";
console.log(somar(2, 3));

$ node main.mjs
5

Sem nada: a detecção automática

Numa pasta sem package.json, com os mesmos arquivos em .js, o Node 24 percebe o import e trata o arquivo como módulo, sem reclamar:

$ cd ~/semtipo
$ node main.js
5

Essa detecção é recente: ela vem ligada de fábrica desde o Node 22.7 (antes, era preciso uma opção especial). Se a pasta tiver um package.json sem o "type", o Node também detecta, mas avisa que teve trabalho dobrado:

$ cd ~/semtipo2
$ node main.js
(node:141) [MODULE_TYPELESS_PACKAGE_JSON] Warning: Module type of file:///home/ana/semtipo2/main.js is not specified and it doesn't parse as CommonJS.
Reparsing as ES module because module syntax was detected. This incurs a performance overhead.
To eliminate this warning, add "type": "module" to /home/ana/semtipo2/package.json.
(Use `node --trace-warnings ...` to show where the warning was created)
5

Traduzindo: "o tipo do módulo não foi informado e ele não é CommonJS; vou ler de novo como módulo ES, porque achei a sintaxe de módulo. Isso custa desempenho. Para tirar este aviso, acrescente "type": "module" ao package.json". O (node:141) é o número do processo, que muda a cada execução. O programa rodou (o 5 no fim); é só um aviso.

Cuidado com o npm init

O npm init -y do npm 11 (o que vem com o Node 24) cria o package.json com "type": "commonjs". Num projeto assim, um import no .js dá erro (veja Quando dá errado). Se você vai usar import, troque para "type": "module". A aula npm mostra o npm init.

A recomendação para os seus projetos: ponha "type": "module" no package.json e use .js normalmente. Assim fica claro para o Node e para quem lê.

4. Os módulos que já vêm com o Node

O Node traz vários módulos prontos: fs (arquivos), path (caminhos), readline (teclado)… Eles se importam pelo nome, com o prefixo node::

import { readFileSync } from "node:fs";
import path from "node:path";
console.log(path.basename(import.meta.filename));
console.log(import.meta.dirname);
console.log(readFileSync("package.json", "utf8"));

$ node nativo.js
nativo.js
/home/ana/loja
{
  "type": "module"
}
import { readFileSync } from "node:fs"
Uma função do módulo de arquivos, que lê um arquivo inteiro (aula Lendo Arquivos). Sem ./: o nome sem caminho quer dizer "um módulo do Node ou um pacote instalado", e não "um arquivo da pasta".
import path from "node:path"
O módulo de caminhos, importado pelo default (aula Caminhos de Arquivo).
import.meta.filename · import.meta.dirname
Dentro de um módulo, o import.meta traz informações sobre o próprio arquivo: o caminho completo dele e o da pasta em que ele está. (No CommonJS, isso se chama __filename e __dirname.)

O prefixo node: é opcional para os módulos do Node ("fs" também funciona), mas deixa claro que é um módulo embutido, e não um pacote baixado. Pacotes instalados com o npm se importam do mesmo jeito, pelo nome: import pc from "picocolors";.

5. O que é diferente dentro de um módulo

Cada módulo tem o seu escopo

Variáveis e funções de um módulo não vazam para os outros. Só passa o que é exportado, e só para quem importa:

import "./contas.js";
console.log(typeof somar);

$ node escopo.js
undefined

O import "./contas.js", sem chaves, roda o módulo mas não traz nada. O somar continua sendo só de lá. Isso evita que dois arquivos briguem pelo mesmo nome.

Um módulo roda uma vez só

console.log("contador.js rodou");
export let visitas = 0;
export function visitar() {
  visitas++;
}

import { visitas, visitar } from "./contador.js";
import { visitar as outraVez } from "./contador.js";
visitar();
outraVez();
console.log(`Visitas: ${visitas}`);

$ node ummavez.js
contador.js rodou
Visitas: 2

O contador.js foi importado duas vezes, mas a mensagem contador.js rodou apareceu uma vez: o Node carrega cada módulo uma única vez e entrega o mesmo para todos que o importam. Por isso visitar e outraVez mexeram no mesmo visitas, que chegou a 2. E repare que o visitas importado acompanhou a mudança: o import é uma "janela" para a variável do módulo, não uma cópia.

await fora de função

import { setTimeout as esperar } from "node:timers/promises";
console.log("Esperando...");
await esperar(500);
console.log("Pronto!");

$ node topo.js
Esperando...
Pronto!

Num módulo, dá para usar await direto no "topo" do arquivo, fora de qualquer função (o top-level await, ES2022). Aqui o programa esperou meio segundo entre as duas mensagens. O await é o assunto de async e await.

E no navegador?

Os mesmos import e export funcionam numa página web, com <script type="module" src="main.js"></script>. No navegador, o caminho também precisa do ./ e da extensão. Veja JavaScript na Página.

Missão final: o estoque num módulo

Missão: a Ana separou o estoque num módulo, mas esqueceu os export. Na aba estoque.js, exporte a lista produtos e a função totalItens. Não precisa mexer no main.js. O resultado deve ser Itens em estoque: 52.

import { produtos, totalItens } from "./estoque.js";

console.log(`Produtos: ${produtos.length}`);
console.log(`Itens em estoque: ${totalItens()}`);

const produtos = [
  { nome: "caneta", qtd: 40 },
  { nome: "caderno", qtd: 12 },
];

function totalItens() {
  return produtos.reduce((soma, p) => soma + p.qtd, 0);
}

export const produtos = [
  { nome: "caneta", qtd: 40 },
  { nome: "caderno", qtd: 12 },
];

export function totalItens() {
  return produtos.reduce((soma, p) => soma + p.qtd, 0);
}

Resumo

  • Um módulo é um arquivo que oferece coisas (export) e usa coisas de outros (import). O que não é exportado fica privado.
  • export function f + import { f } from "./arquivo.js": nomes exatos, ./ e extensão obrigatórios.
  • export default + import qualquerNome from …; import * as m; as para renomear.
  • O Node trata como módulo ES: .mjs; .js com "type": "module"; ou .js sem "type" que tenha import/export (detecção do Node 24, com aviso se houver package.json).
  • Módulos do Node: import fs from "node:fs". Caminho do próprio arquivo: import.meta.filename e import.meta.dirname.
  • Dentro de um módulo: escopo próprio, roda uma vez só, modo estrito sempre, await no topo, importações só de leitura.
  • require não existe em módulo ES, e import não existe em CommonJS: veja require e module.exports.
