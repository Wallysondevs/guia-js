JavaScript throw

Nas aulas anteriores, os erros vinham do JavaScript ou do Node: você lia (ReferenceError, TypeError…) e tratava com try … catch. Mas às vezes é o seu programa que precisa dizer "isso está errado, não vou continuar": um saque maior que o saldo, uma nota 15 numa prova que vai até 10, uma idade negativa. O JavaScript não acha nada disso errado. Quem sabe é você. Para avisar, você lança um erro com o throw (em inglês, "lançar", "atirar").

Você vai aprender
  • Como lançar um erro com throw new Error("mensagem"), e o que o Node mostra quando ninguém o pega.
  • Para que serve: validar os dados que chegam numa função.
  • Como pegar o seu próprio erro com try … catch.
  • Quando usar TypeError e RangeError em vez do Error genérico.
  • Como guardar a causa de um erro ({ cause: erro }) e como criar um tipo de erro seu.
  • Por que não lançar um texto puro (throw "erro"), e os erros reais de quem está começando.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Você pode rodar cada um no editor do guia.

A ideia: o caixa eletrônico

A Ana vai ao caixa eletrônico com R$ 100 na conta e pede R$ 500. O caixa não entrega R$ 100 e "deixa para lá", nem entrega R$ 500 e fica com o saldo negativo. Ele para a operação e mostra uma mensagem clara: "Saldo insuficiente". Quem decide o que fazer depois é a Ana (pedir menos, desistir).

O throw é esse "parar e avisar":

  • a função que encontra o problema lança o erro (o caixa mostra a mensagem);
  • quem chamou a função decide: pega o erro com try … catch e trata (a Ana pede outro valor), ou deixa o erro subir e o programa para.

Por que lançar um erro, e não só um console.log?

Se a função só escrevesse "Saldo insuficiente" e seguisse, ela teria de devolver alguma coisa, e o programa continuaria com um saldo errado. O throw garante que nada de errado continue: ou alguém trata o problema, ou tudo para com uma mensagem clara, apontando a linha.

Missão: a função aceita um saque negativo, e o saldo aumenta de R$ 100 para R$ 120! Acrescente uma validação no começo da sacar: se valor <= 0, lance new Error(`Valor inválido: ${valor}`). Rode e leia a mensagem.

function sacar(saldo, valor) {
  if (valor > saldo) {
    throw new Error("Saldo insuficiente");
  }
  return saldo - valor;
}
console.log(sacar(100, -20));

function sacar(saldo, valor) {
  if (valor <= 0) {
    throw new Error(`Valor inválido: ${valor}`);
  }
  if (valor > saldo) {
    throw new Error("Saldo insuficiente");
  }
  return saldo - valor;
}
console.log(sacar(100, -20));

2. Pegando o seu próprio erro

Um erro lançado com throw é pego pelo try … catch igualzinho aos erros do JavaScript. A Ana faz três saques seguidos; o do meio é grande demais:

function sacar(saldo, valor) {
  if (valor > saldo) {
    throw new Error(`Saldo insuficiente: você tem R$ ${saldo} e pediu R$ ${valor}`);
  }
  return saldo - valor;
}
const pedidos = [30, 500, 50];
let saldo = 100;
for (const valor of pedidos) {
  try {
    saldo = sacar(saldo, valor);
    console.log(`Sacou R$ ${valor}. Saldo: R$ ${saldo}`);
  } catch (erro) {
    console.log(`Não deu: ${erro.message}`);
  }
}

$ node sacar2.js
Sacou R$ 30. Saldo: R$ 70
Não deu: Saldo insuficiente: você tem R$ 70 e pediu R$ 500
Sacou R$ 50. Saldo: R$ 20

Repare na divisão de tarefas: a sacar só detecta o problema e lança; quem chama decide como tratar (aqui, avisar e seguir para o próximo pedido). E o saldo ficou certo: como o throw interrompeu a sacar, a linha saldo = sacar(…) não mudou o saldo no saque que falhou.

Uma boa mensagem de erro

Diga o que está errado e, se der, com quais valores: "Saldo insuficiente: você tem R$ 70 e pediu R$ 500" ajuda muito mais do que "Erro!" ou "Valor inválido". Quem vai ler pode ser você mesmo, daqui a seis meses.

3. Escolhendo o tipo do erro

Você pode lançar qualquer um dos tipos de Os Tipos de Erro. Os mais usados para validar dados:

  • TypeError: o valor é do tipo errado (veio texto onde devia vir número);
  • RangeError: o tipo está certo, mas o valor está fora da faixa (idade −5);
  • Error: qualquer outro problema (saldo insuficiente, produto esgotado).
function definirIdade(idade) {
  if (typeof idade !== "number") {
    throw new TypeError(`A idade tem de ser um número, e veio ${typeof idade}`);
  }
  if (idade < 0 || idade > 130) {
    throw new RangeError(`Idade fora da faixa (0 a 130): ${idade}`);
  }
  return idade;
}
for (const valor of [30, "30", -5]) {
  try {
    console.log("OK:", definirIdade(valor));
  } catch (erro) {
    if (erro instanceof RangeError) {
      console.log("Faixa errada ->", erro.message);
    } else {
      console.log(`${erro.name} ->`, erro.message);
    }
  }
}

$ node tipos.js
OK: 30
TypeError -> A idade tem de ser um número, e veio string
Faixa errada -> Idade fora da faixa (0 a 130): -5

O tipo certo ajuda quem pega o erro: com instanceof RangeError, o catch consegue tratar cada caso de um jeito. O typeof (veja typeof) descobriu que "30", entre aspas, é string.

4. Guardando a causa: { cause: erro } ES2022

Às vezes você pega um erro "técnico" e quer lançar outro, mais claro para quem vai ler, sem perder o original. O segundo parâmetro do Error aceita a causa:

function lerConfig(texto) {
  try {
    return JSON.parse(texto);
  } catch (erro) {
    throw new Error("Configuração inválida", { cause: erro });
  }
}
try {
  lerConfig("{tema: escuro}");
} catch (erro) {
  console.log(erro.message);
  console.log("Causa:", erro.cause.message);
}

$ node causa2.js
Configuração inválida
Causa: Expected property name or '}' in JSON at position 1 (line 1 column 2)

Quem chama a lerConfig vê a mensagem simples ("Configuração inválida"), e o detalhe do JSON.parse continua guardado em erro.cause. Se ninguém pegar, o Node mostra os dois: o seu erro e, embaixo, a causa, marcada com [cause]:

5. Um tipo de erro só seu

Em programas maiores, vale criar um tipo de erro com nome próprio. Isso usa classes e herança, que você vai estudar no Nível 3; por enquanto, veja como fica e o que muda na mensagem:

class SaldoInsuficienteError extends Error {
  constructor(saldo, valor) {
    super(`Você tem R$ ${saldo} e pediu R$ ${valor}`);
    this.name = "SaldoInsuficienteError";
    this.falta = valor - saldo;
  }
}
try {
  throw new SaldoInsuficienteError(100, 500);
} catch (erro) {
  console.log(erro.name);
  console.log(erro.message);
  console.log(`Faltam R$ ${erro.falta}`);
  console.log(erro instanceof SaldoInsuficienteError, erro instanceof Error);
}
throw new SaldoInsuficienteError(20, 50);

Formas diferentes de avisar que algo deu errado

O throw não é o único jeito de uma função dizer "não deu". Outra forma comum é devolver um valor especial (null, undefined, -1), como faz o indexOf do array quando não acha o item.

Quando dá errado

Lançou um texto em vez de um Error

O JavaScript deixa lançar qualquer valor, até um texto. Mas veja o que se perde:

  if (valor > saldo) {
    throw "Saldo insuficiente";
  }
  return saldo - valor;
}

Código depois do throw que nunca roda 
function dividir(a, b) {
  if (b === 0) {
    throw new Error("Divisão por zero");
    console.log("Isto nunca aparece");
  }
  return a / b;
}
try {
  dividir(10, 0);
} catch (erro) {
  console.log("Peguei:", erro.message);
}

$ node depois.js
Peguei: Divisão por zero

O throw sai da função na hora, como um return. Qualquer linha depois dele, no mesmo bloco, é inútil. Se você precisa avisar algo, faça antes do throw (ou no catch de quem chamou).

Esqueceu o new (e funcionou) 
const e1 = new Error("com new");
const e2 = Error("sem new");
console.log(e1.message, e2.message, e2 instanceof Error);

$ node semnew.js
com new sem new true

Diferente do Set e do Map, o Error funciona sem new: o resultado é o mesmo. Mesmo assim, escreva new Error(…): é o jeito que todo mundo usa, e uma classe de erro sua (seção 5) exige o new.

Missão final: as notas da turma

Missão: a função notaValida lança um RangeError para notas fora de 0 a 10. Rode: a nota 15 derruba o programa. Sem mexer na função, ponha um try … catch dentro do for que mostre Nota ignorada: … (com o erro.message) e continue. No fim deve aparecer Notas válidas: 2.

function notaValida(nota) {

    throw new RangeError(`Nota fora da faixa: ${nota}`);
  }
  return nota;
}
const notas = [8, 15, 9.5];
const validas = [];
for (const nota of notas) {
  validas.push(notaValida(nota));
}
console.log(`Notas válidas: ${validas.length}`);

Resumo

  • throw new Error("mensagem") lança um erro: a função para na hora, e o erro sobe para quem a chamou.
  • Se ninguém pegar, o programa para com a mensagem normal do Node (com a sua mensagem e a linha do throw).
  • Use para validar: quando continuar levaria a um resultado errado.
  • Quem chama decide: pega com try … catch e trata, ou deixa subir.
  • TypeError para tipo errado, RangeError para fora da faixa, Error para o resto; mensagens com os valores ajudam muito.
  • { cause: erro } guarda o erro original; uma classe que estende Error cria um tipo próprio.
  • Lance sempre um Error, nunca um texto puro; e o que é lançado começa na mesma linha do throw.
