JavaScript O que é o DOM

Até agora, o JavaScript deste guia rodou quase sempre no terminal, com o Node. A partir desta aula, ele volta para a sua casa de origem: o navegador. Lá, a grande função do JavaScript é mexer na página: trocar um texto, mostrar uma mensagem, esconder um menu, acrescentar um item a uma lista. Para isso, o navegador entrega ao JavaScript uma versão da página feita de objetos, que ele pode ler e alterar. Essa versão se chama DOM.

Você vai aprender
  • O que é o DOM, com a comparação da planta e da casa.
  • Por que o DOM é uma árvore, e o que são nós, pais, filhos e irmãos.
  • O objeto document, a porta de entrada para a página.
  • Como explorar o DOM no Console do navegador: document.title, querySelector, children, textContent.
  • Os tipos de nó (elemento e texto) e por que childNodes tem mais itens que children.
  • Por que mudar o DOM não muda o arquivo .html.
  • O erro real ReferenceError: document is not defined, quando se tenta usar o DOM no Node.

As respostas do Console mostradas nesta aula foram colhidas no Chromium (a versão livre do Chrome) da máquina da Ana; as do terminal, no Node.js 24 dela. Para abrir o Console no seu navegador, aperte F12 e escolha a aba Console (veja O Console do Navegador).

A ideia: a planta e a casa

Um arquivo HTML é como a planta de uma casa: um papel que descreve onde fica cada cômodo. Ninguém mora na planta. Quando o navegador abre o arquivo, ele lê a planta e constrói a casa: cria, na memória, um objeto para cada parte da página. Essa casa construída é o DOM, sigla de Document Object Model ("modelo de objetos do documento").

  • O que você vê na tela é desenhado a partir do DOM, e não direto do arquivo.
  • O JavaScript mexe no DOM: muda a cor de uma parede, troca um móvel de lugar, constrói um quarto novo. A tela acompanha na hora.
  • A planta (o arquivo .html) continua igual. Se você recarregar a página, o navegador constrói a casa de novo, a partir da planta original.

1. A página vira uma árvore

Esta é a página da padaria da Ana, salva como padaria/index.html:

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Padaria da Ana</title>
</head>
<body>
  <h1>Padaria da Ana</h1>
  <p>Pão quentinho todo dia!</p>
  <ul>
    <li>Pão francês</li>
    <li>Pão de queijo</li>
  </ul>
</body>
</html>

Repare que as tags ficam umas dentro das outras: o <li> está dentro do <ul>, que está dentro do <body>, que está dentro do <html>. O navegador transforma esse "dentro de" numa árvore, como uma árvore genealógica de cabeça para baixo:

document
└── html
    ├── head
    │   ├── meta
    │   └── title
    │       └── "Padaria da Ana"
    └── body
        ├── h1
        │   └── "Padaria da Ana"
        ├── p
        │   └── "Pão quentinho todo dia!"
        └── ul
            ├── li
            │   └── "Pão francês"
            └── li
                └── "Pão de queijo"

Cada caixinha da árvore se chama nó (em inglês, node). E os nós têm "parentes", com os nomes da família:

NomeQuer dizerExemplo nesta página
RaizO nó do topo, de onde tudo saidocument
Pai (parent)O nó logo acimaO pai do h1 é o body
Filhos (children)Os nós logo abaixoOs filhos do ul são os dois li
Irmãos (siblings)Nós com o mesmo paih1, p e ul são irmãos

Os textos ("Padaria da Ana", "Pão francês") também são nós: são os nós de texto, sempre nas pontas da árvore. Os nós das tags (h1, ul, li) se chamam elementos.

2. O document: a porta de entrada

No navegador, o JavaScript recebe pronto um objeto chamado document ("documento"). Ele é a raiz da árvore: tudo na página se alcança a partir dele. A Ana abriu a página da padaria no Chromium, apertou F12 e digitou no Console:

> document.title
'Padaria da Ana'
> document.querySelector("h1")
<h1>Padaria da Ana</h1>
> document.querySelector("h1").textContent
'Padaria da Ana'
> document.documentElement.nodeName
'HTML'
> document.querySelector("h1").parentElement.nodeName
'BODY'
document.title
O título da página, o texto do <title> (aparece na aba do navegador).
document.querySelector("h1")
"Seletor de consulta": procura na árvore o primeiro elemento que combina com "h1" e o devolve. O Console mostra o elemento como HTML (no Chrome de verdade, dá para clicar nele e abrir a árvore). A aula Selecionando Elementos é toda sobre isso.
.textContent
"Conteúdo de texto": o texto que está dentro do elemento.
document.documentElement
O elemento <html>, o primeiro filho elemento do document. O nodeName é o nome do nó, em maiúsculas para os elementos.
.parentElement
O pai de um elemento: o pai do h1 é o BODY.

Repare nas aspas simples em 'Padaria da Ana': no Console, o resultado de uma expressão que é texto aparece entre aspas, para você saber que é uma string.

Os filhos de um elemento

> document.body.children
(3) [h1, p, ul]
> document.body.children.length
3
> document.querySelector("ul").children[1].textContent
'Pão de queijo'

O children ("filhos") é uma lista dos elementos filhos, que se usa quase como um array: tem length e posições contadas a partir do 0. O (3) na frente é o jeito do Console dizer "3 itens". O children[1] do ul é o segundo li.

Mudando a casa pelo Console

Agora o mais divertido: dar um valor novo ao textContent.

> document.querySelector("h1").textContent = "Padaria e Confeitaria da Ana"
'Padaria e Confeitaria da Ana'

Na mesma hora, o título grande da página mudou na tela para Padaria e Confeitaria da Ana. Você acabou de mudar o DOM. (A linha de resposta é só o valor que foi atribuído; quem mudou foi a página.) A aula Mudando Textos e Atributos mostra isso em detalhes.

3. Elementos e nós de texto

Cada nó tem um nodeType ("tipo de nó"), um número que diz o que ele é:

> document.querySelector("p").nodeType
1
> document.querySelector("p").firstChild
"Pão quentinho todo dia!"
> document.querySelector("p").firstChild.nodeType
3
nodeTypeTipo de nóExemplo
1Elemento (uma tag)<p>, <h1>, <li>
3Texto"Pão quentinho todo dia!"
8Comentário<!-- assim -->
9O documentodocument

O firstChild ("primeiro filho") do <p> é um nó de texto: o Console o mostra entre aspas duplas, sem tag nenhuma.

A pegadinha dos espaços: children × childNodes

> document.body.children.length
3
> document.body.childNodes.length
7

Por que 7? O children conta só os elementos (h1, p, ul). O childNodes ("nós filhos") conta todos os nós, inclusive os de texto. E as quebras de linha e os espaços que a Ana usou para deixar o HTML arrumado também viram nós de texto, invisíveis na tela: um antes do h1, um entre o h1 e o p, um entre o p e o ul, e um depois do ul. São 3 elementos + 4 textos de espaço = 7.

Por isso, no dia a dia, prefira children, firstElementChild e parentElement, que só enxergam elementos.

4. O DOM muda; o arquivo, não

Depois de mudar o título pelo Console, a Ana fez duas coisas:

  1. Clicou com o botão direito na página e escolheu Inspecionar. A aba Elementos (Elements) do DevTools mostra o DOM de agora: lá estava <h1>Padaria e Confeitaria da Ana</h1>.
  2. Apertou Ctrl+U (Exibir código-fonte). Essa tela mostra o arquivo que o navegador recebeu: lá continuava <h1>Padaria da Ana</h1>.

Quando ela recarregou a página (F5), o título voltou a ser Padaria da Ana: o navegador construiu a casa de novo a partir da planta. (O que aparece em cada tela foi descrito em texto: o lab da Ana roda o Chromium sem janela, então não há foto dessas telas.)

5. O DOM é do navegador, não do JavaScript

Um detalhe importante: o document não faz parte da linguagem JavaScript. Ele é uma ferramenta que o navegador oferece ao JavaScript. O Node não tem página nenhuma para mostrar, então não tem document (nem window, a janela):

console.log(typeof document);
console.log(typeof window);
console.log(typeof console);

$ node tipo.js
undefined
undefined
object

No Node, document e window não existem (typeof dá "undefined", veja typeof), mas o console existe nos dois. No Console do Chromium, typeof document deu 'object'. A tabela da aula Onde o JavaScript Roda resume o que existe em cada lugar.

O elemento não existe (ainda)

Se o querySelector não acha nada, ele devolve null, e a linha seguinte quebra com TypeError: Cannot set properties of null (ou Cannot read properties of null). Os dois motivos mais comuns são um seletor escrito errado e um <script> que roda antes de o elemento ser construído. Eles são o assunto das próximas aulas: JavaScript na Página e Selecionando Elementos.

Resumo

  • O arquivo HTML é a planta; o DOM é a casa que o navegador constrói a partir dela, feita de objetos que o JavaScript pode ler e mudar.
  • O DOM é uma árvore de nós: elementos (as tags) e textos, com pai, filhos e irmãos.
  • O document é a raiz e a porta de entrada: document.title, document.body, document.querySelector(…).
  • children só tem elementos; childNodes tem também os nós de texto, inclusive os espaços entre as tags.
  • Mudar o DOM muda a tela na hora, mas não o arquivo: recarregando, tudo volta.
  • O DOM é do navegador: no Node, document não existe (ReferenceError: document is not defined).
