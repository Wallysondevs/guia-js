JavaScript fetch

Até aqui, todos os dados dos seus programas estavam dentro do próprio programa (ou num arquivo do computador). Mas muita informação útil está em outros computadores: o endereço de um CEP, a previsão do tempo, a cotação do dólar. Para pedir esses dados pela internet, o JavaScript tem a função fetch (em inglês, "buscar", "ir pegar"). Ela devolve uma Promise, então tudo o que você aprendeu sobre async e await vale aqui.

Você vai aprender
  • O que é uma API, um pedido e uma resposta, e como o fetch faz o pedido.
  • Como buscar o endereço de um CEP na API pública ViaCEP, com os dois await (o do fetch e o do .json()).
  • O que tem dentro da resposta: status, ok, headers; e a diferença entre .text() e .json().
  • Como conferir se o pedido deu certo (resposta.ok) e como tratar a internet fora do ar (try … catch).
  • Como enviar dados (POST), como fazer várias buscas juntas e como treinar sem internet com uma URL data:.
  • Os erros reais mais comuns: o await esquecido, o JSON que era HTML, a resposta lida duas vezes e o endereço incompleto.

Os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com internet, buscando dados de verdade. O fetch existe no Node sem precisar instalar nada (segundo a documentação do Node, ele é parte do Node desde a versão 18 e é estável desde a 21) e existe também em todos os navegadores modernos, com o mesmo jeito de usar.

A ideia: o pedido no balcão

A Ana quer saber o endereço do CEP 01001-000. Ela não tem essa informação, mas sabe quem tem: um serviço na internet que responde perguntas sobre CEPs. É como pedir no balcão de uma loja:

  1. Ela faz o pedido (em inglês, request) para um endereço certo: "quero os dados do CEP 01001000".
  2. Espera. A resposta pode demorar um pouco (a internet é lenta perto do computador): por isso o fetch devolve uma Promise.
  3. Recebe a resposta (response): um código dizendo se deu certo (200 = "tudo bem") e um pacote com o conteúdo.
  4. Abre o pacote. O conteúdo vem como texto no formato JSON, e é preciso transformá-lo num objeto do JavaScript.

Um serviço feito para programas conversarem assim se chama API (do inglês Application Programming Interface, "interface de programação"). Nesta aula, a Ana usa a ViaCEP (viacep.com.br), uma API brasileira gratuita, que não pede cadastro nem senha (as APIs que pedem dão uma "chave" de acesso; esta não precisa).

const dados = await resposta.json();

fetch("https://viacep.com.br/ws/01001000/json/")
Faz o pedido para esse endereço (a URL) e devolve na hora uma Promise. O programa não trava esperando a internet.
const resposta = await …
Primeiro await: espera chegar a resposta. A resposta é um objeto Response com o código de situação e os cabeçalhos; o conteúdo ainda está "fechado".
resposta.json()
Lê o conteúdo inteiro e o transforma de texto JSON em objeto do JavaScript, como o JSON.parse. O conteúdo pode chegar aos poucos, então o .json() também devolve uma Promise.
const dados = await …
Segundo await: espera o conteúdo terminar de chegar e ser convertido. Agora dados é um objeto comum.
dados.localidade, dados.uf…
As propriedades do objeto, como em qualquer objeto. Os nomes (logradouro, localidade, uf) foram escolhidos pela ViaCEP; cada API tem os seus, explicados na documentação dela.
Os dois await

Quase todo fetch tem dois await: um para a resposta chegar (await fetch(…)) e um para o conteúdo ser lido (await resposta.json()). Esquecer qualquer um dos dois é o erro mais comum desta aula (veja Quando dá errado).

Experimente (precisa de internet): esta caixa faz um pedido de verdade à ViaCEP. Troque o CEP pelo da sua rua (só os 8 números) e rode. Se estiver sem internet, a caixa mostra um erro; a seção 4 explica qual.

const resposta = await fetch("https://viacep.com.br/ws/01001000/json/");
const dados = await resposta.json();
console.log(`${dados.logradouro}, ${dados.bairro} - ${dados.localidade}/${dados.uf}`);

3. Conferindo se deu certo: resposta.ok

Uma surpresa para quem começa: o fetch não dá erro quando o servidor responde 400 ou 404. Para ele, o pedido foi e a resposta voltou: missão cumprida. Quem tem de olhar o código é você. Um CEP com o formato errado, só 3 números:

const resposta = await fetch("https://viacep.com.br/ws/123/json/");
console.log(resposta.status, resposta.ok);

$ node cep-invalido.js
400 false

Nenhum erro, só o 400 e o ok falso. E cada API tem seu jeito de dizer "não achei". A ViaCEP, para um CEP com 8 números que não existe, responde 200 com um objeto que avisa o erro:

const resposta = await fetch("https://viacep.com.br/ws/99999999/json/");
console.log(resposta.status, resposta.ok);
console.log(await resposta.json());

$ node cep-inexistente.js
200 true
{ erro: 'true' }

Por isso, um programa cuidadoso confere as duas coisas. A Ana escreveu uma função buscarCep que lança um erro (com throw) em cada caso, e testou três CEPs:

async function buscarCep(cep) {
  const resposta = await fetch(`https://viacep.com.br/ws/${cep}/json/`);
  if (!resposta.ok) {
    throw new Error(`O servidor respondeu ${resposta.status}`);
  }
  const dados = await resposta.json();
  if (dados.erro) {
    throw new Error(`CEP ${cep} não existe`);
  }
  return dados;
}

for (const cep of ["01001000", "123", "99999999"]) {
  try {
    const endereco = await buscarCep(cep);
    console.log(`${cep}: ${endereco.localidade}/${endereco.uf}`);
  } catch (erro) {
    console.log(`${cep}: ${erro.message}`);
  }
}

$ node buscar-cep.js
01001000: São Paulo/SP
123: O servidor respondeu 400
99999999: CEP 99999999 não existe
if (!resposta.ok) { throw … }
"Se a resposta não deu certo, lance um erro." Assim, um 400 ou um 404 vira um erro de verdade, que o catch pega.
if (dados.erro) { throw … }
O jeito da ViaCEP de dizer "CEP não encontrado". Esta parte é só desta API; outra API diria de outro jeito.
return dados;
Se passou pelas duas conferências, devolve o endereço.
try { … } catch (erro) { … }
Quem chama trata os erros num lugar só, como em async e await.

4. Quando a internet não ajuda: try … catch

Às vezes o pedido nem chega ao servidor: o Wi-Fi caiu, o endereço está errado, o servidor saiu do ar. Aí, sim, a Promise do fetch é rejeitada. A Ana rodou o programa abaixo com o computador desconectado da internet:

try {
  const resposta = await fetch("https://viacep.com.br/ws/01001000/json/");
  console.log(await resposta.json());
} catch (erro) {
  console.log(`Não deu para buscar: ${erro.message}`);
  console.log(erro.cause);
}

"O fetch falhou." É a mensagem do erro (um TypeError) no Node, sempre a mesma, seja qual for o motivo.
erro.cause
A causa: o erro de baixo nível que provocou a falha. Aqui, getaddrinfo EAI_AGAIN viacep.com.br.

A função do sistema que traduz o nome viacep.com.br para o endereço numérico do servidor (o "DNS"). Sem internet, ela não conseguiu.

"Tente de novo mais tarde": o código do sistema para "não consegui consultar o DNS agora". Com internet, mas com um nome de site que não existe, o código é outro: no lab, fetch("https://padaria-da-ana-nao-existe.com.br/") deu fetch failed com a causa ENOTFOUND ("não encontrado").

No editor do guia, que usa o fetch do navegador, a mensagem também é fetch failed, mas a causa sai TypeError: Failed to fetch: o navegador não conta ao programa o motivo (sem internet, nome errado, CORS).

Repare na diferença com a seção 3: um 400 ou um 404 não rejeita a Promise (o servidor respondeu); sem resposta nenhuma, ela é rejeitada. Um programa que busca dados na internet precisa tratar os dois casos.

No navegador, a mensagem é outra

No Chrome, o mesmo erro aparece como TypeError: Failed to fetch ("falhou ao buscar"), e o motivo vai para uma linha separada do Console, como net::ERR_INTERNET_DISCONNECTED (ilustrativo; cada navegador escreve do seu jeito). Por isso, não compare o texto da mensagem: só trate o erro no catch.

5. Enviando dados: POST

Até aqui, o fetch só pediu dados (um pedido do tipo GET, "pegar", que é o padrão). Para mandar dados para um servidor (cadastrar uma receita, enviar um formulário), passe um segundo argumento com as opções do pedido. A Ana testou no JSONPlaceholder, uma API pública de mentirinha, feita para treinar: ela responde como se tivesse guardado o dado, mas não guarda nada.

const novoPost = {
  title: "Bolo de cenoura",
  body: "Receita da vó da Ana",
  userId: 1,
};

const resposta = await fetch("https://jsonplaceholder.typicode.com/posts", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(novoPost),
});
console.log(resposta.status, resposta.statusText);
console.log(await resposta.json());

6. Várias buscas ao mesmo tempo

Buscar três CEPs, um depois do outro, soma o tempo das três esperas. Como as buscas não dependem umas das outras, dá para fazê-las juntas com Promise.all (aula Várias Promises):

const ceps = ["01001000", "20040002", "70040010"];
const respostas = await Promise.all(
  ceps.map((cep) => fetch(`https://viacep.com.br/ws/${cep}/json/`)),
);
const enderecos = await Promise.all(respostas.map((r) => r.json()));
for (const e of enderecos) {
  console.log(`${e.cep}: ${e.localidade}/${e.uf}`);
}

$ node dois-ceps.js
01001-000: São Paulo/SP
20040-002: Rio de Janeiro/RJ
70040-010: Brasília/DF

Os dois await continuam lá, cada um com o seu Promise.all: um espera as três respostas chegarem; o outro, os três conteúdos serem lidos.

Não exagere

APIs gratuitas, como a ViaCEP, limitam quantos pedidos cada pessoa pode fazer. Três juntos não incomodam ninguém; trezentos de uma vez podem fazer o servidor bloquear você por um tempo. Busque só o que precisa.

7. Treinando sem internet: a URL data:

Uma URL que começa com data: traz o conteúdo dentro dela mesma: o fetch não precisa sair do computador. É ótima para treinar e para testar um programa sem depender de um servidor. Depois de data: vem o tipo (application/json), uma vírgula e o conteúdo:

const url = 'data:application/json,{"produto":"pão de queijo","preco":4.5}';
const resposta = await fetch(url);
console.log(resposta.status, resposta.ok);
const dados = await resposta.json();
console.log(dados);

$ node dataurl.js
200 true
{ produto: 'pão de queijo', preco: 4.5 }

O resto do programa é igual ao de um fetch pela internet: await, status, ok, .json(). (O texto da URL usa aspas simples por fora porque o JSON de dentro tem aspas duplas.) As missões desta aula usam URLs data: para funcionar mesmo sem internet.

Missão: o programa mostra undefined no lugar do produto. Falta um await: descubra onde, conserte e faça aparecer coxinha: R$ 6.5.

const dados = resposta.json();
console.log(`${dados.produto}: R$ ${dados.preco}`);

8. fetch no navegador

O fetch nasceu no navegador e funciona lá do mesmo jeito. A diferença é o que você faz com os dados: em vez de console.log, você os coloca na página (o assunto do grupo A Página Web). No Chromium da Ana, uma página com este script.js mostrou no Console:

async function mostrarCep() {
  const resposta = await fetch("https://viacep.com.br/ws/01001000/json/");
  const dados = await resposta.json();
  console.log(dados);
  document.querySelector("#saida").textContent = `${dados.localidade}/${dados.uf}`;
}
mostrarCep();

CORS: quando o navegador não deixa

No navegador existe uma proteção que o Node não tem: uma página só consegue ler a resposta de outro site se esse site permitir (a regra se chama CORS). A ViaCEP permite, por isso o exemplo funciona. Com uma API que não permite, o Console mostra um erro com blocked by CORS policy e o fetch falha com TypeError: Failed to fetch. O mesmo acontece ao abrir a página com dois cliques no arquivo e tentar buscar um arquivo da própria pasta (fetch("dados.json")): o navegador bloqueia, e é preciso abrir a página por um servidor (como o Live Server do VS Code).

Formas diferentes de fazer a mesma coisa

O fetch também pode ser usado com .then(), como era comum antes do await:

fetch("https://viacep.com.br/ws/01001000/json/")
  .then((resposta) => resposta.json())
  .then((dados) => console.log(`${dados.localidade}/${dados.uf}`))
  .catch((erro) => console.log(`Erro: ${erro.message}`));

Resumo

  • fetch(url) faz um pedido pela internet e devolve uma Promise da resposta. Funciona no Node (sem instalar nada) e no navegador.
  • São dois await: const resposta = await fetch(url) e const dados = await resposta.json() (ou .text()).
  • A resposta traz status (200, 404, 500…), ok (true de 200 a 299) e headers. Um 404 não é erro para o fetch: confira resposta.ok.
  • Sem internet, a Promise é rejeitada (TypeError: fetch failed no Node): use try … catch.
  • Para enviar dados: method: "POST", o cabeçalho Content-Type e body: JSON.stringify(obj).
  • Várias buscas independentes andam juntas com Promise.all; para treinar sem internet, use uma URL data:.
