JavaScript filter: Filtrando

A professora quer a lista só dos alunos que passaram. A padaria quer saber quais produtos custam mais de R$ 10. A Ana quer tirar da lista de compras tudo o que já comprou. Nos três casos, a ideia é a mesma: passar o array por um filtro e ficar só com os itens que obedecem a uma regra. O método que faz isso se chama, justamente, filter (em inglês, "filtrar").

Você vai aprender
  • Como o filter cria um array novo só com os itens para os quais a sua função responde true.
  • Que o original não muda, e que o resultado pode ter menos itens, ou nenhum.
  • A contar quantos obedecem com filter(…).length.
  • A tirar um item pelo valor, e a tirar itens repetidos.
  • A emendar filter e map: primeiro escolher, depois transformar.
  • Quando usar filter e quando usar find.
  • Os erros reais mais comuns: o = no lugar do ===, as chaves sem return e o filter numa string.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Você pode rodar cada um no editor do guia.

A ideia: a peneira

A Ana está fazendo um bolo e passa a farinha pela peneira. O que é fino passa e cai na tigela; os grumos ficam presos. No fim, a tigela tem só a farinha que passou, e nada foi transformado: cada grão que caiu é o mesmo que entrou.

  • A farinha antes de peneirar é o array original.
  • A peneira é a função que você escreve: para cada item, ela responde "passa" (true) ou "não passa" (false).
  • A tigela é o array novo que o filter devolve.

Compare com o map, da aula anterior: o map é a máquina de suco (todo item entra e sai transformado; mesmo tamanho). O filter é a peneira (os itens saem iguais, mas nem todos saem).

1. O primeiro filter

const notas = [7.5, 5, 9, 4, 6, 10];
const aprovadas = notas.filter((nota) => nota >= 6);
console.log(aprovadas);
console.log(notas);
notas.filter( … )
"Filtre notas": para cada item, pergunte à função se ele fica.
(nota) => nota >= 6
A "peneira": uma arrow function que recebe uma nota e devolve true ou false. Aqui, "a nota é maior ou igual a 6?". É a mesma forma de função que você usou no find.
const aprovadas = …
O filter devolve um array novo com os itens que receberam true, na mesma ordem em que estavam.

Quando ninguém passa, ou todos passam

Se nenhum item passa, o resultado é um array vazio ([]), nunca undefined: dá para usar length, for … of e tudo mais nele, sem erro. Se todos passam, sai uma cópia com todos.

2. Regras com textos

A regra pode ser qualquer pergunta de sim ou não. Com textos, os métodos de string (aulas Procurando em Strings e Métodos de String) e o && e || ajudam a montar a pergunta:

const alunos = ["Ana", "Bia", "Caio", "Carla", "Duda", "Cecília"];

console.log(alunos.filter((nome) => nome.startsWith("C")));
console.log(alunos.filter((nome) => nome.length <= 3));
console.log(alunos.filter((nome) => nome.includes("a") && nome.length > 4));

$ node textos.js
[ 'Caio', 'Carla', 'Cecília' ]
[ 'Ana', 'Bia' ]
[ 'Carla', 'Cecília' ]

Os nomes que começam com C.
nome.length <= 3
Os nomes com até 3 letras.
nome.includes("a") && nome.length > 4

3. Contar quantos obedecem

Como o filter devolve um array, o length dele diz quantos passaram. É um jeito curto de contar, sem laço nem contador:

const notas = [7.5, 5, 9, 4, 6, 10];
const quantos = notas.filter((nota) => nota >= 6).length;
console.log(`${quantos} de ${notas.length} alunos passaram.`);

const vendas = [120, 98, 143, 110, 87, 156, 160];
console.log(`Dias com mais de 140 pães: ${vendas.filter((v) => v > 140).length}`);

$ node contar.js
4 de 6 alunos passaram.
Dias com mais de 140 pães: 3

Na aula for … of, a mesma contagem precisou de uma variável let, um laço e um if. Aqui coube numa linha.

4. Tirar um item pelo valor

Na aula Procurando, para tirar o feijão da lista você precisou achar a posição com indexOf, conferir o -1 e usar o splice. Com o filter, a ideia é outra: em vez de tirar, você monta uma lista nova com todos, menos o feijão:

const compras = ["arroz", "feijão", "café", "feijão", "leite"];
const semFeijao = compras.filter((item) => item !== "feijão");
console.log(semFeijao);

const comprados = ["café", "leite"];
const falta = compras.filter((item) => !comprados.includes(item));
console.log(falta);

$ node tirar.js
[ 'arroz', 'café', 'leite' ]
[ 'arroz', 'feijão', 'feijão' ]
item !== "feijão"
"O item é diferente de feijão?" Todos os que não são feijão passam. Repare que saíram os dois feijões (o indexOf + splice tiraria só o primeiro). E, se não houvesse feijão nenhum, nada de errado aconteceria: não existe o perigo do -1.
!comprados.includes(item)
"O item não está na lista do que já foi comprado?" Fica só o que ainda falta comprar.

Missão: a Bia mudou de escola. Use o filter para criar turmaNova, com todos menos a "Bia".

const turma = ["Ana", "Bia", "Caio", "Duda"];
const turmaNova = turma;
console.log(turmaNova);

5. A posição: tirar os repetidos

Como no map e no forEach, a função recebe a posição como segundo parâmetro. Um truque clássico usa isso para tirar itens repetidos: um item fica só se a posição dele for a primeira em que ele aparece.

const pedidos = ["pão", "café", "pão", "leite", "café", "pão"];
const semRepetir = pedidos.filter((item, i) => pedidos.indexOf(item) === i);
console.log(semRepetir);

$ node repetidos.js
[ 'pão', 'café', 'leite' ]

O primeiro "pão" está na posição 0, e indexOf("pão") também dá 0: fica. O segundo "pão" está na posição 2, mas indexOf("pão") continua dando 0: sai. Funciona, mas existe um jeito mais direto de tirar repetidos, o Set: [...new Set(pedidos)] (aula Set).

6. Escolher e depois transformar: filter + map

Como o filter devolve um array, dá para emendar um map logo depois (e vice-versa). A professora quer os nomes dos aprovados em maiúsculas para o mural:

const alunos = ["Ana", "Bia", "Caio", "Duda"];
const notas = [7.5, 5, 9, 4];

const mural = alunos
  .filter((nome, i) => notas[i] >= 6)
  .map((nome) => nome.toUpperCase());

console.log(mural);

$ node encadear.js
[ 'ANA', 'CAIO' ]
alunos.filter((nome, i) => notas[i] >= 6)
Fica só quem tem nota boa. A nota de cada aluno está no outro array, na mesma posição, por isso a regra usa o i: [ 'Ana', 'Caio' ].
.map((nome) => nome.toUpperCase())
O map trabalha sobre o resultado do filter, não sobre alunos.
uma por linha
Quando a corrente fica comprida, o costume é pôr cada método numa linha, começando com o ponto. O JavaScript lê tudo como uma instrução só, até o ;.

A ordem importa: filtrar primeiro e transformar depois faz o map trabalhar menos, e a regra do filter continua vendo os valores originais.

Formas diferentes de fazer a mesma coisa

Antes do filter, a peneira se fazia à mão, com um laço, um if e push:

const notas = [7.5, 5, 9, 4];

// 1. filter
const a = notas.filter((nota) => nota >= 6);

// 2. for … of + if + push
const b = [];
for (const nota of notas) {
  if (nota >= 6) {
    b.push(nota);
  }
}

console.log(a);
console.log(b);

Quando dá errado

Escreveu = no lugar de === 
const compras = ["arroz", "café", "leite"];
const cafes = compras.filter((item) => item = "café");
console.log(cafes);

$ node igual.js
[ 'arroz', 'café', 'leite' ]

A ideia era ficar só com o café, mas passaram todos, e sem nenhuma mensagem de erro. Um = sozinho não compara: ele guarda "café" dentro de item (veja Atribuição), e a função devolve esse texto. Um texto que não está vazio conta como "verdadeiro" (veja Truthy e Falsy), então todo item passou. Como consertar: para comparar, ===: (item) => item === "café".

Chaves sem return: o array vazio 
const notas = [7.5, 5, 9, 4];
const aprovadas = notas.filter((nota) => {
  nota >= 6;
});
console.log(aprovadas);

$ node sem_return.js
[]

Nenhum erro, e nenhuma nota passou. Com chaves, a função sem return devolve undefined para todos os itens, e undefined conta como "falso": ninguém passa na peneira. (No map, o mesmo engano dava um array cheio de undefined; no filter, dá um array vazio.) Como consertar: return nota >= 6;, ou a forma curta sem chaves.

Achou que o filter tirava do original 
const compras = ["arroz", "feijão", "café"];
compras.filter((item) => item !== "feijão");
console.log(compras);

$ node original.js
[ 'arroz', 'feijão', 'café' ]

O feijão continua lá. O filter montou um array novo sem ele e o devolveu, mas ninguém guardou. Como consertar: const semFeijao = compras.filter(…); ou, com let, ponha o novo no lugar: compras = compras.filter(…).

Missão final: o relatório da padaria

Missão: a meta da padaria é vender mais de 140 pães por dia. (1) Com filter e length, conte quantos dias passaram da meta. (2) Monte destaques: primeiro, com map, transforme cada dia num texto como qua: 143 (a venda do dia está em vendas[i]); depois, com filter, fique só com os textos dos dias em que vendas[i] passou de 140.

const dias = ["seg", "ter", "qua", "qui", "sex", "sáb", "dom"];
const vendas = [120, 98, 143, 110, 87, 156, 160];

const acima = 0;
const destaques = dias;

console.log(`Dias acima da meta: ${acima}`);
console.log(destaques);

const dias = ["seg", "ter", "qua", "qui", "sex", "sáb", "dom"];
const vendas = [120, 98, 143, 110, 87, 156, 160];

const acima = vendas.filter((venda) => venda > 140).length;
const destaques = dias
  .map((dia, i) => `${dia}: ${vendas[i]}`)
  .filter((texto, i) => vendas[i] > 140);

console.log(`Dias acima da meta: ${acima}`);
console.log(destaques);

No lab, a solução mostrou Dias acima da meta: 3 e [ 'qua: 143', 'sáb: 156', 'dom: 160' ]. Repare que aqui a ordem foi a contrária da seção 6: map primeiro. O map não muda as posições (o texto da quarta continua na posição 2), então o filter ainda pode olhar vendas[i]. Se o filter viesse antes, as posições mudariam e o vendas[i] do map pegaria a venda errada. Quando dados que andam juntos (o dia e a venda) ficam em arrays separados, esse tipo de malabarismo aparece. A solução elegante é guardá-los juntos num objeto, o assunto do próximo grupo de aulas (Objetos).

Resumo

  • lista.filter(regra) devolve um array novo só com os itens para os quais a regra devolveu true, na ordem original.
  • O original não muda; o resultado pode ter menos itens, ou ser [].
  • filter(…).length conta; filter((x) => x !== valor) tira um valor; filter((x, i) => lista.indexOf(x) === i) tira repetidos.
  • filter e map se encadeiam: escolha primeiro, transforme depois.
  • find devolve o primeiro que passa; filter, todos (sempre um array).
  • Na regra, compare com === (um = deixa passar tudo) e, com chaves, não esqueça o return (sem ele, ninguém passa).
