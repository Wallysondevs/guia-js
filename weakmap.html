JavaScript WeakMap e WeakSet

Você já conhece o Map (um dicionário: chave → valor) e o Set (um conjunto sem repetição). Eles têm dois primos com um nome curioso: WeakMap e WeakSet. Weak quer dizer "fraco": eles seguram os objetos sem força, de um jeito que não impede o JavaScript de jogá-los fora quando ninguém mais precisa deles. Parece um detalhe, mas é o que permite "pendurar" informações num objeto sem mexer nele e sem desperdiçar memória.

Você vai aprender
  • O que é o coletor de lixo do JavaScript e por que um Map pode atrapalhar o trabalho dele.
  • Como usar um WeakMap: set, get, has e delete, com objetos como chave.
  • Por que o WeakMap não tem size, nem for … of, nem forEach.
  • Dois usos de verdade: guardar dados extras sobre um objeto (até um congelado) e lembrar um resultado já calculado.
  • Como usar um WeakSet para marcar objetos ("este pedido já foi impresso").
  • Os erros reais: chave que não é objeto, is not iterable e o objeto "igual" que não é o mesmo.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Esta é uma aula do nível avançado: se Map, Set e referências ainda estão confusos, revise essas aulas primeiro.

A ideia: o guarda-volumes e o post-it

Pense no guarda-volumes do supermercado. Você deixa a mochila, recebe uma ficha, e a mochila fica lá até alguém buscar. Se o dono for embora e esquecer, a mochila continua ocupando o armário para sempre, porque o guarda-volumes "segura" as coisas com força. Assim é o Map: o que entra nele fica guardado até alguém tirar.

Agora pense num post-it colado numa caixa: "frágil", "conferido", "é da Ana". O post-it fala da caixa, mas não segura a caixa. Quando a caixa vai para o lixo, o post-it vai junto. Assim é o WeakMap: ele guarda uma informação sobre um objeto, mas, quando o resto do programa não usa mais esse objeto, o objeto e a informação somem juntos.

O coletor de lixo

O JavaScript cuida da memória sozinho. De tempos em tempos, um ajudante chamado coletor de lixo (em inglês, garbage collector) procura objetos que nenhuma variável alcança mais e libera o espaço deles. Você nunca chama esse ajudante: ele trabalha quando quer. A regra dele é simples: enquanto alguém segura o objeto, ele fica. Um Map conta como "alguém segurando"; um WeakMap, não.

1. O problema do Map

A lojinha da Ana guarda, para cada cliente (um objeto), a data do último atendimento. Com um Map:

const ultimaVisita = new Map();

let cliente = { nome: "Bia" };
ultimaVisita.set(cliente, "18/10");

cliente = null; // a Bia saiu do sistema
console.log(ultimaVisita.size);
console.log(ultimaVisita);

$ node map-segura.js
1
Map(1) { { nome: 'Bia' } => '18/10' }

O programa jogou fora a variável cliente, mas o objeto da Bia continua vivo dentro do Map. Num programa que roda o dia inteiro (um servidor, uma página aberta por horas), isso vai acumulando: é o que os programadores chamam de vazamento de memória. Às vezes é exatamente o que você quer (um cadastro tem de guardar tudo). Mas, quando a informação só faz sentido enquanto o objeto existe, quem resolve é o WeakMap.

2. O primeiro WeakMap

const ultimaVisita = new WeakMap();

const ana = { nome: "Ana" };
const bia = { nome: "Bia" };

ultimaVisita.set(ana, "17/10");
ultimaVisita.set(bia, "18/10");

console.log(ultimaVisita.get(ana));
console.log(ultimaVisita.has(bia));
ultimaVisita.delete(bia);
console.log(ultimaVisita.has(bia));
console.log(ultimaVisita.get(bia));
console.log(ultimaVisita);
new WeakMap()
Cria um WeakMap vazio. (Também aceita uma lista de pares, como o Map: new WeakMap([[ana, "17/10"]]).)
.set(chave, valor)
Guarda o valor ligado à chave. A chave tem de ser um objeto (ou um array, uma função…); o valor pode ser qualquer coisa.
.get(chave)
Devolve o valor ligado à chave, ou undefined se não houver.
.has(chave)
"Tem essa chave?": true ou false.
.delete(chave)
Apaga a chave e o valor dela.
$ node weakmap.js
17/10
true
false
undefined
WeakMap { <items unknown> }

Os quatro métodos funcionam igual aos do Map. A última linha é a novidade: o Node não mostra o conteúdo. <items unknown> quer dizer "itens desconhecidos". Não é preguiça: o coletor de lixo pode tirar um item a qualquer momento, então o JavaScript não deixa ninguém listar o que tem dentro. Por isso o WeakMap só tem esses quatro métodos:

  • não tem size (dá undefined);
  • não tem for … of, forEach, keys(), values() nem entries();
  • não tem clear().

Para pegar um valor, você precisa ter o objeto na mão e perguntar por ele.

Vendo o coletor trabalhar

Normalmente não dá para ver o coletor de lixo. Mas o Node tem uma opção para testes, --expose-gc ("expor o coletor"), que deixa o programa chamar o coletor na hora com globalThis.gc(). E o FinalizationRegistry ("registro de finalização") avisa quando um objeto é recolhido. Com os dois, a Ana fez a experiência da seção 1 com um WeakMap:

const avisos = new FinalizationRegistry((nome) => {
  console.log(`${nome} foi recolhido pelo coletor de lixo.`);
});

const fichas = new WeakMap();
let cliente = { nome: "Ana" };
fichas.set(cliente, "cliente desde 2024");
avisos.register(cliente, "O objeto da Ana");

cliente = null;
globalThis.gc();
setTimeout(() => console.log("Fim do programa."), 100);

$ node --expose-gc coletor-weakmap.js
O objeto da Ana foi recolhido pelo coletor de lixo.
Fim do programa.
$ sed 's/new WeakMap()/new Map()/' coletor-weakmap.js > coletor-map.js
$ node --expose-gc coletor-map.js
Fim do programa.

Com o WeakMap, depois do cliente = null ninguém mais segurava o objeto, e o coletor o recolheu (a ficha foi junto). Com o Map (o comando sed trocou uma palavra pela outra numa cópia do arquivo), o objeto continuou preso e o aviso nunca veio. Isso é só uma experiência para enxergar o que acontece por dentro: em programas normais, não use --expose-gc nem conte com o momento exato em que o coletor passa (sem a opção, globalThis.gc nem existe: TypeError: globalThis.gc is not a function).

3. Uso 1: informações extras sobre um objeto

O uso mais comum do WeakMap é guardar dados sobre um objeto que não é seu, ou que você não quer (ou não pode) mudar. Lembra da aula Object.freeze? Um objeto congelado não aceita propriedade nova. Mas um WeakMap pode "colar o post-it" nele mesmo assim:

const visitas = new WeakMap();

function registrarVisita(cliente) {
  const anteriores = visitas.get(cliente) ?? 0;
  visitas.set(cliente, anteriores + 1);
}

const ana = Object.freeze({ nome: "Ana" });
registrarVisita(ana);
registrarVisita(ana);
registrarVisita(ana);

console.log(`${ana.nome} visitou ${visitas.get(ana)} vezes`);
console.log(ana);
visitas.get(cliente) ?? 0
Na primeira visita, o get devolve undefined, e o ?? troca por 0.
visitas.set(cliente, anteriores + 1)
Guarda o novo total, ligado ao objeto.
Object.freeze({ nome: "Ana" })
O objeto da Ana está congelado: ana.visitas = 1 seria ignorado. O WeakMap não mexe no objeto, então funciona.
$ node visitas.js
Ana visitou 3 vezes
{ nome: 'Ana' }

O objeto continua limpo, só com nome: a contagem ficou "do lado de fora", no WeakMap. E se um dia o objeto da Ana sumir do programa, a contagem some junto, sem você precisar apagar nada.

Missão: o programa tenta guardar as visitas dentro do objeto, mas os clientes estão congelados e a contagem não funciona. Troque para um WeakMap chamado visitas, como no exemplo acima. A Bia veio duas vezes, a Ana três.

function registrarVisita(cliente) {
  cliente.visitas = (cliente.visitas ?? 0) + 1;
}

const ana = Object.freeze({ nome: "Ana" });
const bia = Object.freeze({ nome: "Bia" });
registrarVisita(bia);
registrarVisita(ana);
registrarVisita(bia);
registrarVisita(ana);
registrarVisita(ana);

console.log(`${bia.nome} visitou ${bia.visitas} vezes`);
console.log(`${ana.nome} visitou ${ana.visitas} vezes`);

const visitas = new WeakMap();

function registrarVisita(cliente) {
  visitas.set(cliente, (visitas.get(cliente) ?? 0) + 1);
}

const ana = Object.freeze({ nome: "Ana" });
const bia = Object.freeze({ nome: "Bia" });
registrarVisita(bia);
registrarVisita(ana);
registrarVisita(bia);
registrarVisita(ana);
registrarVisita(ana);

console.log(`${bia.nome} visitou ${visitas.get(bia)} vezes`);
console.log(`${ana.nome} visitou ${visitas.get(ana)} vezes`);

4. Uso 2: lembrar um resultado já calculado

Somar um pedido grande dá trabalho. Se o mesmo pedido é somado várias vezes, dá para guardar o resultado na primeira vez e reaproveitar depois. Guardar resultados assim se chama cache (pronuncia-se "quéch"; quer dizer "esconderijo"):

const totais = new WeakMap();

function totalDoPedido(pedido) {
  if (totais.has(pedido)) {
    console.log("(do cache)");
    return totais.get(pedido);
  }
  console.log("(calculando...)");
  const total = pedido.itens.reduce((soma, item) => soma + item.preco, 0);
  totais.set(pedido, total);
  return total;
}

const pedido = { itens: [{ preco: 4.5 }, { preco: 12 }, { preco: 3.25 }] };
console.log(totalDoPedido(pedido));
console.log(totalDoPedido(pedido));

$ node cache.js
(calculando...)
19.75
(do cache)
19.75

Na primeira chamada, a soma foi feita (com o reduce) e guardada; na segunda, veio pronta. Com um Map, cada pedido somado ficaria preso no cache para sempre; com o WeakMap, quando o pedido não é mais usado, o total guardado vai embora junto.

Cuidado com o cache de objeto que muda

Se alguém fizer pedido.itens.push(…) depois, o cache continua devolvendo o total antigo. Um cache assim combina com objetos que não mudam, como os congelados da aula Imutabilidade.

5. WeakSet: marcando objetos

O WeakSet é o Set "fraco": guarda objetos, sem repetição, sem segurá-los com força. Ele só responde uma pergunta: "este objeto está marcado?". Na padaria, a impressora da cozinha não pode imprimir o mesmo pedido duas vezes:

const impressos = new WeakSet();

function imprimir(pedido) {
  if (impressos.has(pedido)) {
    console.log(`Pedido ${pedido.numero} já foi impresso.`);
    return;
  }
  console.log(`Imprimindo pedido ${pedido.numero}: ${pedido.item}`);
  impressos.add(pedido);
}

const p1 = { numero: 1, item: "3 pães" };
const p2 = { numero: 2, item: "1 sonho" };
imprimir(p1);
imprimir(p2);
imprimir(p1);
console.log(impressos);
new WeakSet()
Cria um conjunto fraco vazio.
.add(objeto)
Marca o objeto. Marcar duas vezes não faz nada de diferente.
.has(objeto)
"Está marcado?".
.delete(objeto)
Tira a marca.
$ node weakset.js
Imprimindo pedido 1: 3 pães
Imprimindo pedido 2: 1 sonho
Pedido 1 já foi impresso.
WeakSet { <items unknown> }

Como no WeakMap, não dá para listar nem contar: só add, has e delete.

Um objeto "igual" não é o mesmo objeto 
const visitas = new WeakMap();
visitas.set({ nome: "Ana" }, 3);
console.log(visitas.get({ nome: "Ana" }));

Cada { nome: "Ana" } escrito no código cria um objeto novo. Os dois têm o mesmo conteúdo, mas são caixas diferentes (veja Objetos são Referências), e o WeakMap compara pela caixa. Pior: como ninguém guardou o primeiro objeto numa variável, ele já está pronto para o coletor levar, junto com o 3. Como consertar: guarde o objeto numa variável e use sempre ela: const ana = { nome: "Ana" };.

Missão final: o caixa que não cobra duas vezes

Missão: o caixa da lojinha está cobrando a Ana duas vezes. Crie um WeakSet chamado pagos e, na função cobrar: se a compra já estiver em pagos, mostre Ana já pagou. (com o nome do cliente) e saia com return; senão, cobre e marque a compra com add.

function cobrar(compra) {
  console.log(`Cobrando ${compra.cliente}: R$ ${compra.total}`);
}

const compraAna = { cliente: "Ana", total: 20 };
const compraBia = { cliente: "Bia", total: 7.5 };
cobrar(compraAna);
cobrar(compraBia);
cobrar(compraAna);

const pagos = new WeakSet();

function cobrar(compra) {
  if (pagos.has(compra)) {
    console.log(`${compra.cliente} já pagou.`);
    return;
  }
  console.log(`Cobrando ${compra.cliente}: R$ ${compra.total}`);
  pagos.add(compra);
}

const compraAna = { cliente: "Ana", total: 20 };
const compraBia = { cliente: "Bia", total: 7.5 };
cobrar(compraAna);
cobrar(compraBia);
cobrar(compraAna);

No lab, a solução mostrou Cobrando Ana: R$ 20, Cobrando Bia: R$ 7.5 e Ana já pagou..

Resumo

  • O coletor de lixo libera os objetos que ninguém mais alcança. Um Map/Set segura seus itens; um WeakMap/WeakSet, não.
  • WeakMap: chave é um objeto; métodos set, get, has, delete. WeakSet: guarda objetos; métodos add, has, delete.
  • Eles não têm size, for … of, forEach nem clear, e o console.log mostra <items unknown>: para consultar, é preciso ter o objeto na mão.
  • Usos típicos: guardar dados extras sobre um objeto sem mexer nele (até congelado), cache de resultados e marcar objetos ("já impresso").
  • Chave de texto ou número dá TypeError: Invalid value used as weak map key; para isso existe o Map.
