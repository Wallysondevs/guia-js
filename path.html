JavaScript path: Caminhos de Arquivo

Nas aulas de leitura e escrita de arquivos, um programa que funcionava numa pasta deu ENOENT quando foi rodado de outra. O problema não era o arquivo: era o caminho até ele. Um caminho é o "endereço" de um arquivo, como /home/ana/caminhos/dados/compras.txt. O módulo node:path monta, desmonta e conserta esses endereços sem que você precise lidar com barras à mão. Ele vem com o Node e é só do Node.

Você vai aprender
  • O que é um caminho absoluto e um relativo, e de onde o relativo parte.
  • Como desmontar um caminho: basename, extname, dirname e parse.
  • Como montar um caminho com path.join e transformá-lo em absoluto com path.resolve.
  • A diferença entre process.cwd() (a pasta do terminal) e __dirname (a pasta do programa).
  • Como achar um arquivo "ao lado do programa", de qualquer pasta, com path.join(__dirname, …) ou import.meta.dirname.
  • As barras do Linux (/) e do Windows (\), e os erros reais.

Tudo rodou no Node.js v24.22.0 da máquina da Ana (usuária ana, computador notebook), num projeto em /home/ana/caminhos, que tem uma subpasta dados com o arquivo compras.txt.

A ideia: endereço completo × "na rua de trás"

Há dois jeitos de explicar onde fica a padaria:

  • O endereço completo: "Rua das Flores, 120, Centro, São Paulo". Serve para qualquer pessoa, de qualquer lugar.
  • Um endereço a partir de onde você está: "na rua de trás, segunda porta". Só funciona se a pessoa estiver no lugar certo; dito em outro bairro, leva a outra porta.

Os caminhos de arquivo são iguais:

TipoExemploParte de…
Absoluto/home/ana/caminhos/dados/compras.txtA raiz do disco, a / do começo. Vale de qualquer lugar.
Relativodados/compras.txtA pasta atual do terminal. Muda conforme onde você está.

Dentro de um caminho, cada pasta é separada por uma barra (/ no Linux e no macOS). Dois nomes especiais: . é "esta pasta" e .. é "a pasta de cima".

console.log(path.dirname(arquivo));
console.log(path.parse(arquivo));

Carrega o módulo (com import: import path from "node:path";).
path.basename(arquivo)
"Nome base": a última parte, o nome do arquivo com a extensão.
path.basename(arquivo, ".txt")
O mesmo, sem a extensão que você passou.
path.extname(arquivo)
"Nome da extensão": do último ponto em diante, com o ponto.
path.dirname(arquivo)
"Nome da pasta": tudo menos a última parte.
path.parse(arquivo)
Tudo de uma vez, num objeto: a raiz (root), a pasta (dir), o nome completo (base), a extensão (ext) e o nome sem extensão (name).

Essas funções só olham o texto: não conferem se o arquivo existe. path.extname("qualquer/coisa.xyz") dá ".xyz" mesmo que não haja nada no disco.

A extensão em casos diferentes

const path = require("node:path");

const fotos = ["bolo.JPG", "pao.png", "recibo.pdf", "LEIA-ME", "foto.antiga.jpeg"];
for (const f of fotos) {
  console.log(f, "→", JSON.stringify(path.extname(f)));

$ node ext.js

recibo.pdf → ".pdf"
LEIA-ME → ""

(O JSON.stringify só serve para mostrar as aspas, e assim enxergar a string vazia.) Três detalhes: a extensão mantém maiúsculas (.JPG); sem ponto, ela é ""; com vários pontos, vale só o último.

console.log(partes);

const path = require("node:path");

const foto = "/home/ana/fotos/bolo.jpg";
const { dir, name, ext } = path.parse(foto);
console.log(path.join(dir, `${name}-pequeno${ext}`));

2. Montando um caminho: path.join

Juntar pedaços de caminho com + é pedir para errar uma barra. O path.join ("juntar") põe as barras certas, tira as repetidas e resolve os ..:

const path = require("node:path");

console.log(path.join("dados", "compras.txt"));
console.log(path.join("dados/", "/compras.txt"));
console.log(path.join("dados", "..", "fotos", "bolo.jpg"));
console.log(path.join("/home/ana", "caminhos", "dados"));
console.log("dados" + "compras.txt");

$ node juntar.js
dados/compras.txt
dados/compras.txt
fotos/bolo.jpg
/home/ana/caminhos/dados
dadoscompras.txt
path.join("dados", "compras.txt")
Pôs a barra no meio.
path.join("dados/", "/compras.txt")
Barras sobrando: o resultado é o mesmo, com uma só.
path.join("dados", "..", "fotos", "bolo.jpg")
Entrou em dados, subiu (..) e entrou em fotos: sobrou fotos/bolo.jpg.
"dados" + "compras.txt"
Com +, a barra faltou, e o resultado aponta para um arquivo que não existe, dadoscompras.txt (o erro está em Quando dá errado).

O path.join devolve um caminho relativo se o primeiro pedaço for relativo, e absoluto se ele começar com /.

process.cwd()
"Current working directory", a pasta atual do terminal: a mesma que o pwd mostra. É dela que partem os caminhos relativos.
path.resolve("dados/compras.txt")
"Resolver": transforma em caminho absoluto, colando a pasta atual na frente.

Se algum pedaço já é absoluto, ele vira o ponto de partida.
path.isAbsolute(…)
true se o caminho começa da raiz.
path.relative(de, para)
O caminho relativo que leva de uma pasta a outra.
path.normalize(…)
Arruma um caminho bagunçado: tira o ., resolve o .. e as barras dobradas.

4. A pasta do programa: __dirname

Para achar um arquivo que mora ao lado do programa, o ponto de partida não pode ser a pasta do terminal: tem de ser a pasta onde o .js está. Em arquivos CommonJS (com require), o Node oferece duas variáveis prontas:

console.log("__filename:", __filename);
console.log("__dirname: ", __dirname);
console.log("cwd:       ", process.cwd());

$ node onde.js
__filename: /home/ana/caminhos/onde.js
__dirname:  /home/ana/caminhos
cwd:        /home/ana/caminhos
$ cd /home/ana
$ node caminhos/onde.js
__filename: /home/ana/caminhos/onde.js
__dirname:  /home/ana/caminhos
cwd:        /home/ana
NomeO que éMuda quando você roda de outra pasta?
__filenameO caminho absoluto do próprio arquivo .jsNão
__dirnameA pasta onde o .js estáNão
process.cwd()A pasta atual do terminalSim

(São dois sublinhados no começo: __dirname.) Juntando com o path.join, o programa acha o arquivo de qualquer lugar:

const fs = require("node:fs");
const path = require("node:path");

const arquivo = path.join(__dirname, "dados", "compras.txt");
const itens = fs.readFileSync(arquivo, "utf8").trim().split("\n");
console.log(`Li ${itens.length} itens de ${arquivo}`);

$ node ler.js
Li 3 itens de /home/ana/caminhos/dados/compras.txt
$ cd /
$ node /home/ana/caminhos/ler.js
Li 3 itens de /home/ana/caminhos/dados/compras.txt

Da pasta do projeto ou da raiz do disco (cd /), o resultado foi o mesmo. Esse é o conserto do ENOENT da aula Lendo Arquivos. Repare também no path.join(__dirname, "dados", "compras.txt"): cada pasta é um pedaço separado, e o join cuida das barras.

Em módulos ES: import.meta.dirname

Em arquivos com import (.mjs ou "type": "module"; veja Módulos), __dirname e __filename não existem. O equivalente fica em import.meta:

import path from "node:path";

console.log(import.meta.filename);
console.log(import.meta.dirname);
console.log(path.join(import.meta.dirname, "dados", "compras.txt"));

$ node onde.mjs
/home/ana/caminhos/onde.mjs
/home/ana/caminhos
/home/ana/caminhos/dados/compras.txt

import.meta.dirname e import.meta.filename chegaram no Node 20.11. Em código mais antigo, você vai ver uma receita mais comprida para o mesmo fim: path.dirname(fileURLToPath(import.meta.url)).

5. Linux × Windows: as barras

No Linux e no macOS, as pastas se separam com /; no Windows, com \ (e o caminho começa com a letra do disco: C:\). O path usa automaticamente o jeito do sistema em que o programa roda: num Windows, path.join("dados", "compras.txt") dá dados\compras.txt. É mais um motivo para nunca montar caminhos com + e "/". Para ver ou tratar caminhos do outro sistema, há path.win32 e path.posix:

const path = require("node:path");

console.log(path.sep);
console.log(path.win32.sep);
console.log(path.win32.join("C:\\Users\\Ana", "Documentos", "compras.txt"));
console.log(path.win32.basename("C:\\Users\\Ana\\Documentos\\compras.txt"));
console.log(path.posix.join("dados", "compras.txt"));

$ node windows.js
/
\
C:\Users\Ana\Documentos\compras.txt
compras.txt
dados/compras.txt

path.sep ("separador") é a barra do sistema atual: no Linux da Ana, /. Repare no "C:\\Users\\Ana": dentro de uma string do JavaScript, a barra invertida se escreve dobrada (veja Caracteres Especiais).

4. O caminho do Windows no código

Um caminho como "C:\Users\Ana\novo.txt" escrito assim, com barras simples, se estraga dentro da string:

console.log(JSON.stringify("C:\Users\Ana\novo.txt"));

$ node win.js
"C:UsersAna\novo.txt"

O \U e o \A perderam a barra, e o \n virou uma quebra de linha (o JSON.stringify a mostra como \n; veja Caracteres Especiais). Conserto: dobre as barras ("C:\\Users\\Ana\\novo.txt") ou, melhor, monte com path.join e deixe o Node escolher a barra.

Missão final: separando as fotos

Missão: da lista de arquivos, mostre só as fotos .jpg, uma por linha, aceitando também .JPG em maiúsculas. Use path.extname e toLowerCase(). Devem aparecer bolo.JPG e sonho.jpg, nessa ordem, e mais nada.

const path = require("node:path");

const arquivos = ["bolo.JPG", "pao.png", "recibo.pdf", "LEIA-ME", "sonho.jpg", "jpg.txt"];

// mostre só os .jpg


const path = require("node:path");

const arquivos = ["bolo.JPG", "pao.png", "recibo.pdf", "LEIA-ME", "sonho.jpg", "jpg.txt"];

for (const nome of arquivos) {
  if (path.extname(nome).toLowerCase() === ".jpg") {
    console.log(nome);
  }
}

Repare na pegadinha jpg.txt: quem procura "jpg" com includes o leva junto; o extname não se engana, porque olha só a extensão de verdade. No lab, a solução mostrou bolo.JPG e sonho.jpg.

Resumo

  • Caminho absoluto começa na raiz (/home/ana/…) e vale de qualquer lugar; relativo (dados/x.txt) parte da pasta atual do terminal, process.cwd().
  • basename, extname, dirname e parse desmontam um caminho; join monta (com as barras certas) e resolve transforma em absoluto. Elas só mexem no texto, sem olhar o disco.
  • __dirname (CommonJS) e import.meta.dirname (módulos ES) são a pasta do próprio programa: path.join(__dirname, "dados", "x.txt") acha o arquivo de qualquer pasta.
  • O path usa a barra do sistema (/ no Linux e no macOS, \ no Windows): nunca monte caminhos com +.
  • Num ENOENT, leia o caminho que o Node tentou abrir: ele mostra o que o programa montou.
