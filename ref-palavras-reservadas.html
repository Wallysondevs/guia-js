JavaScript Palavras Reservadas

Algumas palavras são da própria linguagem: if, for, function, class… São as palavras reservadas. Elas não podem ser usadas como nome de variável, função, classe ou parâmetro, porque o JavaScript não saberia se você está dando um nome ou usando o comando. Esta página reúne todas, separadas em grupos, com o que cada uma faz e onde ela é ensinada no guia.

Nesta página
  • As palavras reservadas sempre (36 palavras).
  • As reservadas só no modo estrito, nos módulos ou em certos lugares.
  • Palavras com sentido especial que ainda podem ser nomes.
  • As antigas, que foram liberadas.
  • As mensagens de erro reais e a exceção das propriedades.

A lista segue a especificação da linguagem, o ECMAScript 2025 (conferida na documentação da MDN), e as mensagens de erro foram colhidas no Node.js v24.22.0 do computador da Ana. Para regras de nomes em geral (letras, camelCase, sem acento), veja Nomes de Variáveis.

Reservadas só em certos lugares

Estas palavras viraram parte da linguagem depois que muito código antigo já as usava como nome. Para não quebrar esse código, elas só são proibidas no modo estrito ("use strict", que vale sozinho dentro de classes e de módulos com import/export) ou em lugares específicos:

PalavraProibida como nome…Para que serve
letno modo estrito, e sempre num let/const/classCria uma variável (Variáveis)
staticno modo estritoMembro da própria classe (static)
yieldno modo estrito e dentro de geradoresEntrega um valor num gerador (Geradores)
awaitem módulos e dentro de funções asyncEspera uma Promise (async e await)
implements, interface, package, private, protected, publicno modo estritoNenhum: reservadas para o futuro (o TypeScript usa várias)
arguments, evalno modo estrito (não são reservadas, mas não podem ser declaradas)O arguments das funções antigas; o eval, que roda texto como código (evite)

Na prática: trate todas como reservadas. Um nome que funciona hoje num arquivo comum quebra no dia em que o arquivo virar módulo ou ganhar um "use strict".

Palavras especiais que ainda podem ser nomes

Algumas palavras têm sentido especial só numa posição da sintaxe e, fora dela, são nomes comuns. São chamadas de palavras contextuais:

PalavraOnde tem sentido especial
asyncantes de function ou de uma arrow function (async)
ofno for (const x of lista) (for … of)
get, setem objetos e classes (get e set)
from, asno import … from "…" e no import * as … (Módulos)
target, metasó em new.target e import.meta

E três nomes que parecem palavras da linguagem, mas são só variáveis globais que já vêm prontas: undefined, NaN e Infinity. Dentro de uma função ou de um bloco, dá para criar uma variável com esses nomes, que "esconde" a original. Não faça isso: veja o cenário abaixo.

Experimente: palavras reservadas podem ser nomes de propriedade, e as contextuais podem ser nomes de variável. Rode e depois tente trocar const async por const class.

const aluno = { nome: "Bia", class: "3º ano B", new: true, default: 10 };
console.log(aluno.class);
console.log(aluno.new, aluno.default);

const async = "ainda é um nome";
const of = 1;
const get = 2;
const int = 3;
console.log(async, of, get, int);

$ node propriedades.js
3º ano B
true 10
ainda é um nome 1 2 3

Depois de um ponto (aluno.class) ou como chave de objeto ({ class: … }), não há confusão possível: ali só pode vir um nome de propriedade. Por isso o JavaScript permite. É comum ver isso no DOM, por exemplo: elemento.className é o nome "seguro", mas propriedades como default e new aparecem em bibliotecas.

As antigas, que foram liberadas

As primeiras versões da linguagem (ECMAScript 1 a 3, de 1997 a 1999) reservavam várias palavras do Java, para um futuro que nunca chegou. Desde o ECMAScript 5 (2009), elas são nomes comuns:

abstract, boolean, byte, char, double, final, float, goto, int, long, native, short, synchronized, throws, transient, volatile.

O const int = 3 do exemplo acima funcionou por isso. Em sites e livros antigos, elas ainda aparecem na lista de proibidas.

Sem modo estrito e fora de módulo, public e await passam. Bastou mudar a extensão para .mjs e o mesmo código quebrou. É o motivo da recomendação de tratar todas como reservadas. O mesmo vale para o let, o yield e o static: com var let = 1; var yield = 2; var static = 3;, um arquivo comum roda e mostra 1 2 3; com "use strict" na primeira linha, o var yield dá Unexpected strict mode reserved word.

Esconder o undefined: nenhum erro, só confusão 
const undefined = "surpresa";
console.log(undefined);
let x;
console.log(x === undefined);

$ node indefinido.js
surpresa
false

O undefined não é reservado: num arquivo do Node (que roda dentro de uma função, por baixo dos panos), dá para criar uma constante com esse nome. Daí em diante, undefined vale "surpresa", e a variável x, que não recebeu valor (e, portanto, é o undefined de verdade), deixa de ser igual a ele. Nenhuma mensagem avisa. O mesmo vale para NaN e Infinity: nunca os use como nome.

Missão: o programa da Ana não roda: ele usa duas palavras reservadas como nome. Rode para ver o erro e troque os nomes (por exemplo, turma e notaMinima) em todos os lugares, para sair Turma 3º ano B, nota mínima 7.

const class = "3º ano B";
const default = 7;
console.log(`Turma ${class}, nota mínima ${default}`);

const turma = "3º ano B";
const notaMinima = 7;
console.log(`Turma ${turma}, nota mínima ${notaMinima}`);

Resumo

  • Palavras reservadas são da linguagem e não podem ser nome de variável, função, classe ou parâmetro: o erro é de sintaxe (Unexpected token ou Unexpected reserved word) e nada do programa roda.
  • 36 são sempre reservadas, inclusive true, false, null e a sem uso enum.
  • let, static, yield, await, public, private e outras são reservadas no modo estrito, nos módulos ou em certos lugares: trate-as como sempre reservadas.
  • async, of, get, set, from e as têm sentido especial só em certas posições; fora delas, são nomes comuns.
  • Como nome de propriedade (aluno.class), qualquer palavra serve.
  • undefined, NaN e Infinity não são reservadas, mas nunca as use como nome.
