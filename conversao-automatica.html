JavaScript Conversão Automática

Na aula Conversão, você transformou valores de um tipo em outro de propósito, com Number() e String(). Mas o JavaScript também converte sozinho, sem pedir licença, quando você mistura tipos numa conta ou numa comparação. Isso se chama conversão automática (os programadores dizem coerção). Às vezes ela ajuda; muitas vezes ela produz resultados que parecem piada, como "5" + 2 dar "52". Esta aula mostra as pegadinhas mais comuns, a regra por trás de cada uma, e como fugir delas.

Você vai aprender
  • Por que o + com um texto junta, e os outros sinais de conta (-, *, /) convertem para número.
  • Por que 1 + 2 + "3" e "1" + 2 + 3 dão resultados diferentes.
  • O que o == converte, e por que o guia usa sempre o ===.
  • Por que "10" < "9" é verdadeiro.
  • O que acontece quando um objeto, um array, null ou undefined vira texto.
  • Como se proteger: converter antes, com as próprias mãos.

A ideia: o atendente que "adivinha"

Imagine um atendente de lanchonete muito prestativo, que nunca diz "não entendi". Você pede "um suco e 2", e ele não pergunta "2 o quê?": ele adivinha. Às vezes acerta (dois sucos), às vezes traz um suco e dois guardanapos. Ele nunca reclama, e por isso você só descobre o engano quando a bandeja chega.

O JavaScript é esse atendente. Quando você mistura um texto e um número, ele não dá erro: escolhe sozinho para que tipo converter e segue em frente. O segredo é conhecer as regras que ele usa para adivinhar. Elas são poucas.

1. A regra do +: se tiver texto, ele junta

O sinal + tem dois trabalhos: somar números e juntar textos (veja Strings). Quando um dos lados é texto, o JavaScript escolhe juntar, e converte o outro lado em texto:

console.log("5" + 2);
console.log(5 + "2");
console.log("Idade: " + 30);
console.log(typeof ("5" + 2));

$ node mais.js
52
52
Idade: 30
string
"5" + 2 → 52
O lado esquerdo é texto. O 2 virou o texto "2" e foi colado: "52". O typeof da última linha confirma que o resultado é string, um texto.
5 + "2" → 52
Não importa de que lado está o texto: basta um.
"Idade: " + 30
Aqui a conversão é bem-vinda: é exatamente o que queríamos, juntar o número na frase. É por isso que ela existe.

2. Os outros sinais de conta convertem para número

O -, o *, o / e o % só têm um trabalho: fazer conta. Então, com eles, o JavaScript converte o texto para número:

console.log("5" - 2);
console.log("5" * "2");
console.log("10" / "4");
console.log("7" % 2);
console.log("abc" * 2);
console.log(typeof ("5" - 2));

$ node outros.js
3
10
2.5
1
NaN
number

Todos viraram números (o resultado é number), e as contas deram certo, até a de dois textos, "5" * "2". Quando o texto não é um número, como "abc", a conversão dá NaN (veja NaN, Infinity e a Precisão).

Juntando as duas regras, aparece a pegadinha clássica:

const idadeTexto = "30";
console.log(`Daqui a 5 anos: ${idadeTexto + 5}`);
console.log(`Há 5 anos: ${idadeTexto - 5}`);

$ node idade.js
Daqui a 5 anos: 305
Há 5 anos: 25

A subtração deu certo (25) e a soma deu 305. Mesmo valor, mesmo número 5, resultados de tipos diferentes. É o atendente que adivinhou certo uma vez e errado na outra.

Missão: conserte a conta da primeira linha do console.log para mostrar Daqui a 5 anos: 35. Dica: converta o texto com Number() antes de somar (aula Conversão).

const idadeTexto = "30";
console.log(`Daqui a 5 anos: ${idadeTexto + 5}`);

const idadeTexto = "30";
console.log(`Daqui a 5 anos: ${Number(idadeTexto) + 5}`);

3. A ordem importa: da esquerda para a direita

Numa conta com vários +, o JavaScript resolve um de cada vez, da esquerda para a direita. A regra do texto vale a cada passo:

console.log(1 + 2 + "3");
console.log("1" + 2 + 3);
console.log("1" + (2 + 3));

$ node ordem.js
33
123
15
Expressão1º passo2º passoResultado
1 + 2 + "3"1 + 2 = 3 (dois números: soma)3 + "3" = "33" (tem texto: junta)"33"
"1" + 2 + 3"1" + 2 = "12" (tem texto: junta)"12" + 3 = "123" (tem texto: junta)"123"
"1" + (2 + 3)(2 + 3) = 5 (os parênteses vêm primeiro)"1" + 5 = "15""15"

Depois que o resultado vira texto, ele continua texto até o fim. Os parênteses mudam a ordem, como na matemática (mais em Precedência dos Operadores). Na prática, isso aparece numa frase como "Total: " + preco + taxa, que junta os dois valores em vez de somar; o certo é "Total: " + (preco + taxa), ou melhor ainda, uma template string: `Total: ${preco + taxa}`.

4. O == converte antes de comparar

O JavaScript tem duas igualdades. O === (três sinais) compara o valor e o tipo, sem converter nada. O == (dois sinais) primeiro converte os dois lados para um tipo comum, e só depois compara. E as conversões do == produzem resultados estranhos:

console.log("1" == 1);
console.log("1" === 1);
console.log(0 == "");
console.log(0 == "0");
console.log("" == "0");
console.log(false == "0");
console.log(null == 0);
console.log(null == undefined);

$ node igual.js
true
false
true
true
false
true
false
true
"1" == 1 → true / "1" === 1 → false
O == converteu o texto para número e achou igual. O === viu que um é texto e o outro é número: diferentes.
0 == "" → true e 0 == "0" → true
O texto vazio vira 0, e o texto "0" também. Os dois "são iguais" a zero.
"" == "0" → false
Mas entre si, não! Aqui os dois lados são textos, então não há conversão: são textos diferentes. Ou seja: 0 é igual a "", 0 é igual a "0", mas "" não é igual a "0". Essa falta de lógica é o motivo de o == ter má fama.
false == "0" → true
O false vira 0, o "0" vira 0: "iguais".
null == 0 → false / null == undefined → true
O null tem regra própria: com ==, ele só é igual ao undefined (veja null e undefined).
A regra do guia: sempre ===

Com o === você nunca precisa decorar essa tabela: tipos diferentes são sempre diferentes. Se os tipos podem ser diferentes (um texto que veio do teclado e um número), converta antes, com Number(), e compare com ===. A comparação completa está na aula Comparação (== × ===).

5. "10" < "9": comparando textos

Quando os dois lados de um < ou > são textos, o JavaScript não converte nada: ele compara os textos como num dicionário, letra por letra, da esquerda para a direita.

console.log(10 < 9);
console.log("10" < "9");
console.log("10" < 9);
console.log("banana" < "maçã");
console.log("Zebra" < "abelha");

$ node menor.js
false
true
false
true
true
10 < 9 → false
Dois números: 10 não é menor que 9. Certo.
"10" < "9" → true
Dois textos: o JavaScript compara o primeiro caractere de cada um, "1" com "9". Como "1" vem antes de "9", ele decide que "10" vem antes, e para por aí. É como no dicionário, onde "casa" vem antes de "dado" mesmo sendo mais comprida.
"10" < 9 → false
Basta um lado ser número para o outro ser convertido: aí a comparação é numérica.
"banana" < "maçã" → true
Para textos de verdade, a comparação de dicionário faz sentido: b vem antes de m.
"Zebra" < "abelha" → true
Outra surpresa: para o computador, todas as maiúsculas vêm antes de todas as minúsculas. Por isso "Zebra" vem antes de "abelha". Ordenar nomes do jeito certo é assunto de Ordenando.

Isso morde quem compara números que chegaram como texto, como preços lidos de um arquivo: "100" > "25" dá false (no lab, deu false), e Number("100") > Number("25") dá true.

6. Quando objetos, arrays e o "nada" viram texto

Quando um valor que não é texto entra numa frase, o JavaScript converte também. Com números e booleanos o resultado é o esperado; com o resto, nem tanto:

const aluna = { nome: "Ana" };
const notas = [7, 8, 10];
console.log("Aluna: " + aluna);
console.log(`Notas: ${notas}`);
console.log([] + []);
console.log("Total: " + null);

$ node objetos.js
Aluna: [object Object]
Notas: 7,8,10

Total: null
"Aluna: " + aluna → Aluna: [object Object]
Um objeto (aula Objetos) vira o texto [object Object], que não diz nada. Se aparecer isso na tela, você colocou o objeto inteiro onde queria uma propriedade dele: era para ser aluna.nome.
`Notas: ${notas}` → Notas: 7,8,10
Um array (aula Arrays) vira os itens separados por vírgula, sem espaço.
[] + [] → (linha vazia)
Dois arrays vazios viram dois textos vazios, e juntá-los dá um texto vazio: a linha em branco da saída. O + não sabe "somar" arrays.
"Total: " + null → Total: null
null e undefined viram as palavras "null" e "undefined". Na tela do usuário, isso indica um valor que faltou.
E o console.log com vírgula?

console.log("Aluna:", aluna), com vírgula em vez de +, não converte nada: o Node mostra o objeto inteiro, Aluna: { nome: 'Ana' }. Para olhar o que tem dentro de um objeto, use a vírgula (veja console.log()).

7. Numa condição, tudo vira booleano

O if espera um true ou false (veja Booleanos). Se receber outra coisa, ele converte. E aqui há mais uma pegadinha com o "0":

const digitado = "0";
if (digitado) {
  console.log("O texto \"0\" conta como verdadeiro!");
}
if (0) {
  console.log("Não aparece.");
}
console.log(Boolean("0"), Boolean(0), Boolean(" "), Boolean(""));

$ node condicao.js
O texto "0" conta como verdadeiro!
true false true false

O número 0 conta como falso, mas o texto "0" conta como verdadeiro, porque não está vazio (até um texto com um espaço só, " ", é verdadeiro). A lista completa do que conta como falso está em Truthy e Falsy.

Quando dá errado

O traço comum de todos os erros desta aula: o JavaScript não avisa. Não há mensagem de erro; só um resultado estranho. Por isso cada cenário mostra o sintoma e de onde ele vem.

O caixa que "soma" grudando

Os preços chegaram como texto, e a Ana somou um por um num total que começa em 0:

const precos = ["4.50", "12.90", "3.25"];
let total = 0;
total = total + precos[0];
total = total + precos[1];
total = total + precos[2];
console.log(`Total: ${total}`);

$ node caixa.js
Total: 04.5012.903.25

O primeiro + juntou o 0 com "4.50" e virou o texto "04.50"; daí para frente, tudo foi colado. Sintoma: um número enorme ou cheio de pontos onde devia estar uma soma. Como consertar: converta cada preço: total = total + Number(precos[0]);. No lab, a versão consertada mostrou Total: 20.65.

[object Object] na tela

Sintoma: a frase mostra Aluna: [object Object]. Causa: você juntou um objeto inteiro num texto. Como consertar: use a propriedade que você quer mostrar (aluna.nome), ou, para investigar, console.log("Aluna:", aluna) com vírgula.

O maior preço que não é o maior

Sintoma: "100" > "25" dá false. Causa: os dois são textos, e a comparação foi letra por letra ("1" vem antes de "2"). Como consertar: Number("100") > Number("25").

O "zero" que passa no if

Sintoma: a pessoa digitou 0, mas o if (digitado) entrou como se ela tivesse digitado alguma coisa. Causa: o que vem do teclado é o texto "0", e texto não vazio é verdadeiro. Como consertar: converta e compare: if (Number(digitado) !== 0).

Quando o JavaScript se recusa: BigInt

Existe um tipo que não entra na adivinhação: o BigInt. 10n + 5 para o programa com TypeError: Cannot mix BigInt and other types, use explicit conversions ("não dá para misturar BigInt com outros tipos; use conversões explícitas"). É o atendente que, pelo menos dessa vez, pergunta antes. Veja BigInt.

Missão: conserte o caixa da Ana. O programa mostra Total: 04.5012.903.25; faça ele mostrar Total: 20.65, convertendo cada preço antes de somar.

Missão: a compra deu 20 reais e a entrega custa 5. Os dois são números, mas a frase mostra Total com entrega: 205. Descubra por quê (seção 3) e conserte só a linha do console.log, sem mudar as variáveis, para mostrar Total com entrega: 25.

Os parênteses fazem a soma acontecer primeiro, entre dois números. Outra solução, ainda mais clara: console.log(`Total com entrega: ${compra + entrega}`);.

Resumo

  • Quando você mistura tipos, o JavaScript converte sozinho e não avisa. Isso se chama conversão automática (coerção).
  • + com algum texto junta ("5" + 2 é "52"); -, *, / e % convertem para número ("5" - 2 é 3). Vários + vão da esquerda para a direita.
  • O == converte antes de comparar e dá resultados sem lógica (0 == "" é true). Use sempre ===.
  • Entre dois textos, < e > comparam letra por letra: "10" < "9" é true.
  • Objetos viram [object Object], arrays viram itens com vírgula, e o texto "0" é verdadeiro. A defesa é uma só: converta você mesmo, com Number() e String(), antes de usar.
