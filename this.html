JavaScript this, call, apply e bind

Na aula Métodos e this, você viu que, dentro de um método, this ("este") é o objeto dono do método. Isso é verdade quase sempre, e esse "quase" é uma das maiores fontes de confusão do JavaScript. Nesta aula você vai entender a regra de verdade: o this não é decidido quando a função é escrita, e sim quando ela é chamada. E vai aprender as três ferramentas para escolher o this na mão: call, apply e bind.

Você vai aprender
  • A regra principal: o this é quem está antes do ponto na hora da chamada.
  • Por que o this se perde quando você guarda um método numa variável ou o passa para o forEach.
  • Por que as arrow functions resolvem o forEach, mas estragam um método.
  • call e apply: chamar uma função escolhendo o this.
  • bind: criar uma cópia da função com o this "colado".
  • O this fora de qualquer função, e o erro que você mais vai ver: Cannot read properties of undefined (reading 'nome').

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Você pode rodar cada um no editor do guia.

A ideia: a palavra "eu"

A palavra "eu" não tem dono fixo. Quando a Ana diz "eu moro aqui", "eu" é a Ana; quando o Caio lê exatamente a mesma frase em voz alta, "eu" passa a ser o Caio. A frase é a mesma; quem é o "eu" depende de quem está falando agora.

O this é o "eu" de uma função. A mesma função, chamada por objetos diferentes, tem this diferentes. E se ninguém estiver "falando" (a função é chamada sozinha, sem objeto), o this fica sem dono: undefined.

1. A regra: quem está antes do ponto

const leite = {
  nome: "Leite 1 L",
  apresentar() {
    return `Eu sou o ${this.nome}`;
  },
};

const pao = {
  nome: "Pão francês",
  apresentar: leite.apresentar,
};

console.log(leite.apresentar());
console.log(pao.apresentar());
console.log(leite.apresentar === pao.apresentar);

$ node quem.js
Eu sou o Leite 1 L
Eu sou o Pão francês
true
apresentar: leite.apresentar
O pão não ganhou um método novo: ganhou a mesma função do leite (o true da última linha confirma). Funções são valores e podem ser guardadas em qualquer lugar (aula Funções como Valores).
leite.apresentar()
Antes do ponto está o leite: nesta chamada, this é o leite.
pao.apresentar()
A mesma função, mas agora antes do ponto está o pao: this é o pão, e o texto muda.

Essa é a regra que resolve a maioria dos casos: olhe a linha da chamada, não a linha onde a função foi escrita. objeto.metodo() → this é o objeto.

3. O caso mais comum: uma function dentro do forEach

O this se perde sem você guardar nada numa variável. A professora da Ana tem uma classe Turma e quer fazer a chamada: o nome da turma na frente de cada aluno.

class Turma {
  constructor(nome, alunos) {
    this.nome = nome;
    this.alunos = alunos;
  }

  chamada() {
    this.alunos.forEach(function (aluno) {
      console.log(`${this.nome}: ${aluno}`);
    });
  }
}

const turma = new Turma("5º ano B", ["Bia", "Caio", "Davi"]);
turma.chamada();

A pilha at, lida de baixo para cima, conta a história: a linha 15 chamou Turma.chamada; a chamada (linha 8) chamou o Array.forEach; e o forEach chamou a função sem nome da linha 9 (por isso ela aparece só como at /home/ana/foreach.js:9:27).

O this.alunos da linha 8 funcionou: ali o this é a turma. Mas a function (aluno) { … } é uma função nova, com o seu próprio this, e quem a chama é o forEach, assim: funcao(aluno), sem nada antes do ponto. Resultado: this é undefined lá dentro.

A solução: arrow function

Uma arrow function (=>) não tem this próprio: ela usa o this do lugar onde foi escrita. Escrita dentro do método chamada, ela usa o this da chamada, que é a turma:

  chamada() {
    this.alunos.forEach((aluno) => {
      console.log(`${this.nome}: ${aluno}`);
    });
  }

$ node foreach-arrow.js
5º ano B: Bia
5º ano B: Caio
5º ano B: Davi

É por isso que, desde que as arrow functions chegaram (2015), elas são o jeito preferido de escrever callbacks dentro de métodos: o forEach, o map, o filter, o setTimeout (aula setTimeout e setInterval) e os eventos.

4. O outro lado: arrow function como método

Se a arrow pega o this de fora, ela é uma péssima escolha para um método de objeto:

const padaria = {
  nome: "Padaria do Bairro",
  saudar: () => {
    return `Bem-vindo à ${this.nome}!`;
  },
  saudarCerto() {
    return `Bem-vindo à ${this.nome}!`;
  },
};

console.log(padaria.saudar());
console.log(padaria.saudarCerto());

$ node arrow-metodo.js
Bem-vindo à undefined!
Bem-vindo à Padaria do Bairro!

Mesmo com padaria. antes do ponto, o saudar não enxergou a padaria: a arrow ignorou a regra do ponto e usou o this de fora do objeto (o topo do arquivo, seção 6), que não tem nome. Sem erro, só um undefined no texto. O saudarCerto, escrito como método normal, funcionou.

5. Escolhendo o this na mão: call, apply e bind

Toda função do JavaScript tem três métodos para controlar o this.

call e apply: chamar agora, com o this que eu disser

function descrever(moeda) {
  return `${this.nome}: ${moeda} ${this.preco.toFixed(2)}`;
}

const leite = { nome: "Leite 1 L", preco: 5.49 };
const cafe = { nome: "Café 500 g", preco: 19.9 };

console.log(descrever.call(leite, "R$"));
console.log(descrever.call(cafe, "US$"));
console.log(descrever.apply(leite, ["€"]));

$ node call.js
Leite 1 L: R$ 5.49
Café 500 g: US$ 19.90
Leite 1 L: € 5.49
descrever.call(leite, "R$")
call ("chamar") roda a função agora. O primeiro argumento vira o this; os outros vão para os parâmetros, um por um (moeda recebe "R$").
descrever.apply(leite, ["€"])
apply ("aplicar") é igual, só que os argumentos vão dentro de um array. Para lembrar: apply, array.

Uma função solta (fora de objeto) que usa this é rara em código novo; o call aparece mais em código antigo, como no Produto.call(this, nome, preco) do jeito antigo de fazer herança. O apply também tinha um uso clássico, que hoje o spread faz melhor:

const precos = [27.9, 5.49, 19.9];

console.log(Math.max.apply(null, precos));
console.log(Math.max(...precos));

$ node apply.js
27.9
27.9

O Math.max não usa this, por isso o primeiro argumento do apply é null ("tanto faz"). O ...precos "espalha" o array e é bem mais fácil de ler: prefira-o.

bind: uma cópia com o this colado

O bind ("amarrar") não chama a função. Ele devolve uma função nova, igual à original, mas com o this preso para sempre. É a solução para o this perdido da seção 2:

// (a classe Produto da seção 2 vem aqui em cima)

const leite = new Produto("Leite 1 L", 5.49);

const anunciar = leite.descrever.bind(leite);
console.log(anunciar());
console.log(anunciar);

const outro = { nome: "Outro", preco: 1 };
outro.anunciar = anunciar;
console.log(outro.anunciar());

$ node bind.js
Leite 1 L: R$ 5.49
[Function: bound descrever]
Leite 1 L: R$ 5.49
  • anunciar(), chamada sozinha, funcionou: o this estava amarrado ao leite.
  • console.log(anunciar) mostra [Function: bound descrever]: "função amarrada (bound) de descrever".
  • Nem pondo a função em outro objeto (outro.anunciar()) o this muda: o bind ganha da regra do ponto.

6. O this fora de qualquer método

E no topo do arquivo, ou numa função comum chamada sozinha? Aqui a resposta depende de onde o código roda, e é bom saber disso só para não estranhar:

console.log(this);

function solta() {
  return this === globalThis;
}
console.log(solta());

function soltaEstrita() {
  "use strict";
  return this;
}
console.log(soltaEstrita());

$ node topo.js
{}
true
undefined
  • No topo de um arquivo do Node (o formato tradicional, CommonJS), this é um objeto vazio: {} (é o module.exports da aula require e module.exports). Num arquivo com import/export (aula Módulos), é undefined. No navegador, num <script> comum, é o window.
  • Numa função comum chamada sozinha, fora do modo estrito, o JavaScript antigo dá a ela o objeto global (globalThis) como this: o true da segunda linha. Isso escondia erros: o código "funcionava" lendo coisas do lugar errado.
  • No modo estrito ("use strict", que vale sozinho dentro de classes e de módulos import/export), a mesma função recebe undefined, e o erro aparece logo, como na seção 2. É melhor assim.

Resumindo: não use this fora de métodos. Fora deles, o valor muda de um ambiente para outro e quase nunca é o que você quer. (No navegador, dentro de um evento escrito com function, o this é o elemento que recebeu o evento; isso aparece na aula Eventos.)

Formas diferentes de fazer a mesma coisa

Para não perder o this ao passar um método adiante (para um forEach, um timer, um evento), há quatro saídas:

// 1. arrow function em volta da chamada: o ponto continua lá
botao.addEventListener("click", () => visitas.somar());

// 2. bind: uma cópia com o this colado
botao.addEventListener("click", visitas.somar.bind(visitas));

// 3. arrow function DENTRO do método (o caso do forEach, seção 3)
this.alunos.forEach((aluno) => { … this.nome … });

// 4. o método já nasce como campo com arrow, dentro da classe (abaixo)

(Esse trecho é ilustrativo: botao e visitas são de uma página web e não rodam sozinhos.) A forma 4 cria o método como um campo da classe que guarda uma arrow function. Como a arrow é criada dentro do objeto, o this dela é sempre o próprio objeto:

class Contador {
  total = 0;

  somar = () => {
    this.total = this.total + 1;
  };
}

const visitas = new Contador();
const botaoClicado = visitas.somar;
botaoClicado();
botaoClicado();
[1, 2, 3].forEach(visitas.somar);
console.log(visitas.total);

$ node campo-arrow.js
5

Duas chamadas soltas mais três pelo forEach: 5, sem nenhum this perdido. O custo: cada objeto ganha a sua própria cópia da função (ela não fica no protótipo, aula Protótipos). Para poucos objetos, tudo bem.

Quando dá errado

Cannot read properties of undefined (reading '…') dentro de um método

É o erro das seções 2 e 3. Quando ele aparecer apontando um this.algo, a pergunta é sempre a mesma: como este método foi chamado?

  • Foi guardado numa variável e chamado sozinho (const f = obj.metodo; f())? Use bind ou chame pelo objeto.
  • Foi passado para outra função (lista.forEach(obj.metodo), setTimeout(obj.metodo, 1000))? Use uma arrow em volta: lista.forEach((x) => obj.metodo(x)).
  • Está dentro de uma function de callback, dentro do método? Troque a function por uma arrow.

A pilha at ajuda: se a função do erro aparece sem o nome da classe (at descrever em vez de at Produto.descrever) ou sem nome nenhum (at /home/ana/foreach.js:9:27), ela foi chamada sem objeto.

undefined no meio do texto, sem erro

O caso da seção 4: um método escrito como arrow (saudar: () => …), que mostrou Bem-vindo à undefined!. Também acontece com uma função comum chamada sozinha fora do modo estrito: o this é o objeto global, que não tem a propriedade, e sai undefined em vez de um erro. Como consertar: escreva o método como saudar() { … }.

Esqueceu que o bind não chama

Resumo

  • O this é decidido na hora da chamada: em obj.metodo(), é o obj, quem está antes do ponto.
  • Guardar um método numa variável, ou passá-lo para outra função, separa a função do objeto: chamada sozinha, ela recebe this undefined (em classes, módulos e modo estrito), e aparece Cannot read properties of undefined.
  • Arrow functions não têm this próprio: usam o de onde foram escritas. Ótimas para callbacks dentro de métodos; ruins como métodos.
  • f.call(obj, a, b) e f.apply(obj, [a, b]) chamam agora com o this escolhido; f.bind(obj) devolve uma função nova com o this preso para sempre.
  • Fora de métodos, o this muda de ambiente para ambiente ({} no topo de um arquivo do Node, window no navegador): não conte com ele.
