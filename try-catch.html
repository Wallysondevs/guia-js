JavaScript try … catch … finally

Até agora, todo erro que acontecia parava o programa na hora, com aquela mensagem que você aprendeu a ler em Lendo uma Mensagem de Erro. Mas nem todo problema precisa derrubar tudo. Se a pessoa digitou uma idade inválida, o programa pode pedir de novo; se o arquivo de notas ainda não existe, ele pode começar com uma lista vazia. Para pegar um erro e decidir o que fazer com ele, o JavaScript tem o try … catch: "tente … e, se der errado, pegue o erro".

Você vai aprender
  • Como funciona o try { } catch (erro) { }, e que o programa continua depois dele.
  • O que vem dentro do erro: name, message e a pilha.
  • O finally ("finalmente"), que roda sempre, com erro ou sem erro, até depois de um return.
  • O catch sem parâmetro.
  • Dois usos do dia a dia: ler um texto JSON que pode estar errado e ler um arquivo que pode não existir.
  • O que o try não pega: erros de sintaxe e erros que acontecem "mais tarde" (num setTimeout).
  • O maior perigo: o catch vazio que "engole" o erro.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Você pode rodar cada um no editor do guia.

A ideia: o trapezista e a rede

No circo, o trapezista faz o número lá no alto. Embaixo dele tem uma rede de proteção. Se ele escorregar, cai na rede, levanta, acena para o público, e o espetáculo continua. Sem a rede, uma queda acabaria com o show.

  • O try é o número no trapézio: o código que pode dar errado.
  • O catch é a rede: só entra em ação se alguém cair (se acontecer um erro).
  • O finally é o agradecimento ao público: acontece no fim, tenha o número dado certo ou não.

1. O primeiro try … catch

console.log("Antes");
try {
  const cliente = null;
  console.log(cliente.nome);
  console.log("Esta linha não roda");
} catch (erro) {
  console.log("Deu um problema:", erro.message);
}
console.log("Depois: o programa continuou!");
try { … }
"Tente". Entre as chaves vai o código que pode dar errado. Ele roda normalmente, linha por linha.
console.log(cliente.nome)
Aqui acontece um TypeError (ler .nome de null, veja Os Tipos de Erro). No mesmo instante, o JavaScript abandona o resto do bloco try e pula para o catch.
"Esta linha não roda"
Como o erro aconteceu na linha de cima, esta é pulada.
catch (erro) { … }
"Pegue". Só roda se algum erro aconteceu no try. O erro entre parênteses é uma variável que recebe o erro pego (pode ter qualquer nome; erro, e e err são os mais usados).
erro.message
A mensagem do erro, o mesmo texto que apareceria depois de TypeError:.
console.log("Depois…")
Depois do catch, o programa segue normalmente. Sem o try, ele teria parado na linha 4.
$ node primeiro.js
Antes
Deu um problema: Cannot read properties of null (reading 'nome')
Depois: o programa continuou!

Nada de caminho do arquivo, de ^, de linhas at: o erro foi tratado, então o Node não precisou avisar nada. O que apareceu foi só o que o seu catch escreveu. E o programa terminou bem (código de saída 0).

Quando não dá erro

Se tudo no try der certo, o catch é simplesmente pulado:

try {

} catch (erro) {
  console.log("Nunca chega aqui");

console.log("Fim");

2. O que vem dentro do erro

O erro pego é um objeto (veja Os Tipos de Erro). As duas propriedades que você mais vai usar são o name e o message. E, se você mostrar o erro inteiro com console.log, o Node mostra também a pilha:

try {
  null.nome;
} catch (erro) {
  console.log(erro.name);
  console.log(erro.message);
  console.log(erro);
}

Mostre o erro na saída de erros

Para avisar de um problema, prefira console.error a console.log: ele escreve na saída de erros, que o terminal consegue separar da saída normal (veja console.error, warn e table).

3. Um uso de verdade: ler um texto que pode estar errado

O JSON.parse lança um SyntaxError quando o texto não é um JSON válido. Se o texto vem de fora (de um arquivo, da internet, do teclado), você não controla se ele está certo. É o lugar perfeito para um try:

const textos = ['{"nome": "Ana", "idade": 30}', "{nome: 'Bia'}", ""];
for (const texto of textos) {
  try {
    const pessoa = JSON.parse(texto);
    console.log(`Li: ${pessoa.nome}`);
  } catch (erro) {
    console.log(`Texto inválido (${erro.name}): ${erro.message}`);
  }
}

$ node json.js
Li: Ana
Texto inválido (SyntaxError): Expected property name or '}' in JSON at position 1 (line 1 column 2)
Texto inválido (SyntaxError): Unexpected end of JSON input

O primeiro texto era um JSON correto. O segundo usa aspas simples e nomes sem aspas (não vale em JSON). O terceiro está vazio ("fim inesperado do JSON"). Repare que o try está dentro do for: um texto ruim não impede o laço de ir para o próximo.

4. finally: o que roda sempre

Às vezes, há uma tarefa que precisa acontecer com erro ou sem erro: fechar o caixa, fechar um arquivo, desligar a luz de "carregando…". Para isso existe o finally ("finalmente"):

function vender(produto, estoque) {
  console.log(`Abrindo o caixa para vender ${produto}`);
  try {
    estoque[produto].quantidade -= 1;
    console.log(`Vendido! Restam ${estoque[produto].quantidade}`);
  } catch (erro) {
    console.log(`Não deu para vender ${produto}: ${erro.message}`);
  } finally {
    console.log("Fechando o caixa");
  }
}
const estoque = { pão: { quantidade: 10 } };
vender("pão", estoque);
vender("bolo", estoque);

$ node finally.js

Vendido! Restam 9
Fechando o caixa
Abrindo o caixa para vender bolo
Não deu para vender bolo: Cannot read properties of undefined (reading 'quantidade')
Fechando o caixa

O finally roda até depois de um return

function teste() {
  try {
    console.log("No try");
    return "valor do try";
  } finally {
    console.log("No finally (mesmo depois do return)");
  }
}
console.log(teste());

$ node finallyreturn.js
No try
No finally (mesmo depois do return)
valor do try

O return manda a função sair, mas antes de sair de verdade, o JavaScript passa pelo finally. Só depois o valor chega ao console.log de fora.

try … finally sem catch

Dá para usar o finally sem o catch. Aí o erro não é tratado: o finally roda e, em seguida, o erro continua e para o programa.

try {
  console.log("Trabalhando...");
  semNome;
} finally {
  console.log("Arrumando a mesa");
}
console.log("Depois");

5. O catch sem parâmetro

Se você não vai usar o erro para nada, pode tirar o (erro) e escrever só catch { … }. Aqui, qualquer texto que não seja número vira 0:

function lerNumero(texto) {
  try {
    return JSON.parse(texto);
  } catch {
    return 0;
  }
}
console.log(lerNumero("42"));
console.log(lerNumero("quarenta"));

$ node semparam.js
42
0

Essa forma existe desde o ES2019. Use-a quando o motivo do erro realmente não importa; se importa, deixe o (erro) e olhe o que veio nele.

6. Tratar só o erro que você espera

Um catch pega qualquer erro do try, inclusive os que você não imaginou. O jeito cuidadoso é olhar o erro e tratar só o caso esperado. A Ana guarda as notas num arquivo; na primeira vez que o programa roda, o arquivo ainda não existe (o erro ENOENT, de Os Tipos de Erro):

const fs = require("node:fs");
let notas;
try {
  notas = fs.readFileSync("notas.txt", "utf8");
} catch (erro) {
  if (erro.code === "ENOENT") {
    console.log("Arquivo notas.txt não existe; começando vazio.");
    notas = "";
  } else {
    throw erro;
  }
}
console.log(`Tamanho das notas: ${notas.length}`);

$ node arquivo.js
Arquivo notas.txt não existe; começando vazio.
Tamanho das notas: 0
let notas; antes do try
A variável é criada fora do try, para continuar existindo depois dele (veja Quando dá errado).
erro.code === "ENOENT"
"O erro é 'arquivo não encontrado'?" Esse é o caso esperado: começa vazio.
throw erro
Qualquer outro erro (sem permissão, disco com defeito) é "jogado de novo" para cima, e o programa para com a mensagem normal. Assim você não esconde problemas que não sabe resolver. O throw ("lançar") é o assunto da próxima aula.

A leitura de arquivos com fs tem aula própria: Lendo Arquivos. Para não errar o tipo, você também pode testar com instanceof: if (erro instanceof SyntaxError).

Formas diferentes: try ou testar antes?

Muitos erros dá para evitar com um if ou com o ?., sem precisar de try. Compare duas formas de mostrar o nome de um cliente que pode ser null:

const cliente = null;

// com try … catch
try {
  console.log(cliente.nome);
} catch {
  console.log("visitante");
}

// testando antes (mais simples)
console.log(cliente?.nome ?? "visitante");

$ node duas-formas.js
visitante
visitante

O resultado é o mesmo, mas a segunda forma é uma linha só e não esconde outros erros que poderiam acontecer ali.

SituaçãoQual usar
Dá para saber antes se vai dar certo (valor null, número negativo, lista vazia)Teste com if, ?. ou ?? (?. e ??)
Só dá para saber tentando (o texto é JSON válido? o arquivo existe? a internet respondeu?)try … catch
Algo precisa acontecer com erro ou sem erro (fechar, limpar, avisar que terminou)finally
Um erro que você não sabe resolverDeixe passar (ou throw erro de novo): é melhor o programa parar com a mensagem certa do que seguir errado

  try {
    let total = 0;
    for (const nota of notas) total += nota;
    return total / notas.lenght;
  } catch {
  }
}

Dois problemas, nenhuma mensagem. O primeiro NaN vem do lenght escrito errado (não é erro, é undefined, e a divisão dá NaN). O undefined vem de media() sem as notas: o for … of deu TypeError, o catch vazio engoliu o erro, e a função terminou sem devolver nada. Sem o try, o Node teria mostrado o erro e a linha. Missão final: somar só o que é número

Missão: o programa soma os números digitados, mas cai quando encontra "abc" (rode para ver o SyntaxError do JSON.parse). Ponha um try … catch dentro do for, para pular o texto inválido (mostrando Ignorando "abc") e continuar somando. A soma certa é 16.5.

const entradas = ["12", "abc", "7.5", "-3"];
let soma = 0;
for (const texto of entradas) {
  const n = JSON.parse(texto);
  soma += n;
}
console.log(`Soma: ${soma}`);

const entradas = ["12", "abc", "7.5", "-3"];
let soma = 0;
for (const texto of entradas) {
  try {
    const n = JSON.parse(texto);
    soma += n;
  } catch {
    console.log(`Ignorando "${texto}"`);
  }
}
console.log(`Soma: ${soma}`);

No lab, o programa original parou com SyntaxError: Unexpected token 'a', "abc" is not valid JSON; a solução mostrou Ignorando "abc" e Soma: 16.5.

Resumo

  • try { } catch (erro) { }: tenta; se der erro, pula para o catch; depois o programa continua.
  • No catch, o erro é um objeto com name, message e stack (e code nos erros do Node).
  • finally roda sempre, com ou sem erro, até depois de um return. Sem catch, o erro continua depois dele.
  • catch { }, sem parâmetro, quando o motivo não importa.
  • Use try no que só dá para saber tentando (JSON, arquivos, internet); o resto, evite com if e ?..
  • Trate só o erro esperado e jogue os outros de novo (throw erro). Nunca deixe um catch vazio.
  • O try não pega erro de sintaxe do arquivo nem erros que acontecem depois, num setTimeout. Variáveis criadas dentro do try não existem fora dele.
