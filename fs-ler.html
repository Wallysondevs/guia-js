JavaScript Lendo Arquivos (fs)

Tudo o que os seus programas guardaram até agora sumiu quando eles terminaram. Os dados de verdade moram em arquivos: a lista de compras num .txt, o estoque num .json, as notas da turma numa planilha .csv. No Node, quem abre arquivos é o módulo fs (de file system, "sistema de arquivos"), que já vem com ele: não precisa instalar nada. É um recurso só do Node: por segurança, o JavaScript de uma página não lê os arquivos do seu computador.

Você vai aprender
  • Como ler um arquivo de texto inteiro com readFileSync(nome, "utf8"), e o que é o Buffer que aparece sem o "utf8".
  • Como transformar o texto em linhas com split("\n"), e por que o trim() ajuda.
  • Como ler um JSON e uma planilha CSV simples.
  • As formas que não travam o programa: readFile com await e com callback.
  • Como saber se o arquivo existe e tratar o erro com try … catch.
  • Onde o Node procura o arquivo (a pasta atual), e os erros reais: ENOENT, EISDIR, EACCES e o JSON quebrado.

Todos os programas rodaram no Node.js v24.22.0 da máquina da Ana (usuária ana, computador notebook), na pasta /home/ana/ler.

A ideia: abrir a gaveta e copiar o caderno

A Ana guarda a lista de compras num caderno, na gaveta. Para usá-la, alguém precisa: saber qual caderno (o nome), abrir a gaveta certa (a pasta), e ler o que está escrito, na língua em que foi escrito. Se o caderno não estiver lá, não adianta fingir: é preciso avisar.

Ler um arquivo é isso: você dá o nome (e, se precisar, a pasta), diz a codificação do texto (quase sempre "utf8", a que guarda acentos), e o Node devolve o conteúdo como uma string. Se o arquivo não existir, vem um erro.

1. O primeiro arquivo: readFileSync

Na pasta da Ana há um arquivo de texto, compras.txt:

$ cat compras.txt
leite
pão francês
café
manteiga

O programa que o lê:

const fs = require("node:fs");

const texto = fs.readFileSync("compras.txt", "utf8");
console.log(texto);
console.log(typeof texto, texto.length);
const fs = require("node:fs");
Carrega o módulo fs, que vem dentro do Node (o node: na frente deixa claro que ele é do Node, e não um pacote do npm). Com import: import fs from "node:fs"; (veja Módulos).
fs.readFileSync(…)
"Ler o arquivo, sincronamente": lê o arquivo inteiro e só então passa para a próxima linha. O Sync (de synchronous) quer dizer "esperando terminar".
"compras.txt"
O nome do arquivo. Sem pasta na frente, o Node procura na pasta atual do terminal (veja a seção 6).
"utf8"
A codificação: diz como transformar os bytes do arquivo em letras. "utf8" é o padrão de hoje, e é o que faz o ã e o é saírem certos.
$ node ler.js
leite
pão francês
café
manteiga

string 32

O conteúdo inteiro veio numa string só, de 32 caracteres, com as quebras de linha dentro. Repare na linha em branco antes de string 32: o arquivo termina com uma quebra de linha (quase todo arquivo de texto termina), e o console.log acrescentou outra.

Sem o "utf8": o Buffer

Se você esquecer a codificação, o Node não sabe que é texto e devolve os bytes crus, num objeto chamado Buffer:

const fs = require("node:fs");

const dados = fs.readFileSync("compras.txt");
console.log(dados);
console.log(dados.toString());

$ node sem.js
<Buffer 6c 65 69 74 65 0a 70 c3 a3 6f 20 66 72 61 6e 63 c3 aa 73 0a 63 61 66 c3 a9 0a 6d 61 6e 74 65 69 67 61 0a>
leite
pão francês
café
manteiga

Cada par é um byte, em hexadecimal: 6c é o l, 0a é a quebra de linha, e o ã ocupa dois bytes (c3 a3). O Buffer serve para arquivos que não são texto (imagens, áudio); para texto, passe o "utf8" (ou converta com .toString(), como na segunda linha).

2. De texto para linhas: split("\n")

Uma string inteira é difícil de usar. O normal é quebrá-la em linhas com o split (veja split e join), usando "\n", a quebra de linha:

const { readFileSync } = require("node:fs");

const texto = readFileSync("compras.txt", "utf8");
const linhas = texto.split("\n");
console.log(linhas);

$ node linhas.js
[ 'leite', 'pão francês', 'café', 'manteiga', '' ]

Veio um item a mais, vazio (''), no fim: é o "pedaço" depois da última quebra de linha. Para não contar esse item fantasma, tire os espaços e quebras das pontas com trim() antes de dividir (veja Métodos de String):

const { readFileSync } = require("node:fs");

const itens = readFileSync("compras.txt", "utf8").trim().split("\n");
console.log(`A lista tem ${itens.length} itens:`);
itens.forEach((item, i) => console.log(`${i + 1}. ${item}`));

$ node linhas2.js
A lista tem 4 itens:
1. leite
2. pão francês
3. café
4. manteiga

Repare também no const { readFileSync } = require("node:fs");: a desestruturação pega só a função que interessa, e aí se escreve readFileSync(…) sem o fs. na frente. Os dois jeitos são comuns.

Missão: a aba compras.txt é um arquivo na pasta do programa. Hoje o programa só mostra o texto. Faça-o mostrar A lista tem 5 itens., contando as linhas com trim(), split("\n") e length. Depois, acrescente um item na aba e rode de novo.

3. Lendo JSON e CSV

JSON: readFileSync + JSON.parse

Um arquivo .json é texto; o JSON.parse o transforma em objetos e arrays de verdade (veja JSON):

{
  "loja": "Padaria da Ana",
  "produtos": [
    { "nome": "sonho", "preco": 3.5, "qtd": 12 },
    { "nome": "broa", "preco": 2, "qtd": 7 },
    { "nome": "rosca", "preco": 6, "qtd": 3 }
  ]
}

const { readFileSync } = require("node:fs");

const estoque = JSON.parse(readFileSync("estoque.json", "utf8"));
console.log(estoque.loja);
for (const p of estoque.produtos) {
  console.log(`${p.nome}: ${p.qtd} unidades a R$ ${p.preco.toFixed(2)}`);
}

$ node json.js
Padaria da Ana
sonho: 12 unidades a R$ 3.50
broa: 7 unidades a R$ 2.00
rosca: 3 unidades a R$ 6.00

CSV: uma linha por registro, campos separados

Um CSV (comma-separated values, "valores separados por vírgula") é uma planilha em texto: cada linha é um registro, e os campos são separados por um sinal. Nas planilhas brasileiras, o separador costuma ser o ponto e vírgula, porque a vírgula já é o separador decimal. A primeira linha, o cabeçalho, dá o nome das colunas:

$ cat precos.csv
produto;preco
sonho;3.50
broa;2.00
rosca;6.00

const { readFileSync } = require("node:fs");

const linhas = readFileSync("precos.csv", "utf8").trim().split("\n");
const dados = linhas.slice(1);
let total = 0;
for (const linha of dados) {
  const [produto, preco] = linha.split(";");
  console.log(`${produto.padEnd(8)} R$ ${preco}`);
  total += Number(preco);
}
console.log(`Total: R$ ${total.toFixed(2)}`);
linhas.slice(1)
Pula o cabeçalho (a linha 0) e fica com os dados (veja splice e slice).
const [produto, preco] = linha.split(";");
Divide a linha nos campos e dá um nome a cada um.
produto.padEnd(8)
Completa o nome com espaços até 8 caracteres, para os preços ficarem alinhados.
Number(preco)
O que vem do arquivo é texto: converta antes de somar (veja Conversão).
$ node csv.js
sonho    R$ 3.50
broa     R$ 2.00
rosca    R$ 6.00
Total: R$ 11.50

Este jeito serve para CSVs simples, como os que você mesmo escreve. Planilhas exportadas de programas podem ter campos com o separador dentro, entre aspas; para essas, existem pacotes prontos no npm.

4. Sem travar o programa: readFile

O readFileSync espera o arquivo chegar, e nesse meio-tempo o programa não faz mais nada. Para um programa pequeno, que lê um arquivo e termina, isso é ótimo: é o mais simples. Mas um servidor que atende muita gente não pode parar a cada arquivo. Para isso existem as versões assíncronas, que pedem o arquivo e seguem em frente (o assunto tem um grupo inteiro de aulas, a partir de O que é Código Assíncrono).

Com await (o jeito moderno)

O módulo node:fs/promises tem um readFile que devolve uma Promise; com await, o código fica quase igual ao síncrono. Num arquivo de módulo (.mjs), o await pode ficar solto no arquivo:

import { readFile } from "node:fs/promises";

console.log("Pedindo o arquivo...");
const texto = await readFile("compras.txt", "utf8");
console.log(texto.trim().split("\n"));

$ node assinc.mjs
Pedindo o arquivo...
[ 'leite', 'pão francês', 'café', 'manteiga' ]

Num arquivo CommonJS (require), o await precisa ficar dentro de uma função async (veja async e await). Repare na ordem da saída:

const { readFile } = require("node:fs/promises");

async function main() {
  const texto = await readFile("compras.txt", "utf8");
  console.log(`Primeiro item: ${texto.split("\n")[0]}`);
}

main();
console.log("Enquanto isso, o programa segue...");

$ node assinc.js
Enquanto isso, o programa segue...
Primeiro item: leite

O console.log de baixo apareceu primeiro: enquanto o arquivo era lido, o programa seguiu em frente. Quando o arquivo chegou, a função main continuou de onde parou.

Com callback (o jeito antigo)

Em código mais antigo, você vai ver o readFile do node:fs com uma função de callback, chamada quando o arquivo chega, com o erro (se houver) como primeiro parâmetro:

const fs = require("node:fs");

fs.readFile("compras.txt", "utf8", (erro, texto) => {
  if (erro) {
    console.error("Não deu para ler:", erro.message);
    return;
  }
  console.log(`Li ${texto.length} caracteres.`);
});
console.log("Pedi o arquivo.");

$ node callback.js
Pedi o arquivo.
Li 32 caracteres.

5. E se o arquivo não existir?

Ler um arquivo que não existe dá erro e derruba o programa (veja o ENOENT em Quando dá errado). Há duas formas de se precaver.

Perguntar antes: existsSync

const fs = require("node:fs");

for (const nome of ["compras.txt", "receitas.txt"]) {
  console.log(nome, fs.existsSync(nome));
}

$ node existe.js
compras.txt true
receitas.txt false

existsSync ("existe?") devolve true ou false. Serve para decidir o que fazer (if (fs.existsSync(nome)) …), mas não protege de tudo: o arquivo pode existir e estar trancado, ou ser uma pasta.

Tentar e tratar: try … catch

O jeito mais seguro é tentar ler e tratar o erro (veja try … catch … finally). O erro tem um code que diz o que aconteceu:

const fs = require("node:fs");

function lerLista(nome) {
  try {
    return fs.readFileSync(nome, "utf8").trim().split("\n");
  } catch (erro) {
    if (erro.code === "ENOENT") {
      console.error(`O arquivo ${nome} não existe. Começando com a lista vazia.`);
      return [];
    }
    throw erro;
  }
}

console.log(lerLista("compras.txt"));
console.log(lerLista("receitas.txt"));
try { return … }
Tenta ler e devolver as linhas.
catch (erro)
Se a leitura falhar, o erro cai aqui, em vez de derrubar o programa.
erro.code === "ENOENT"
"O arquivo não existe": aí faz sentido começar com uma lista vazia.
throw erro;
Qualquer outro problema (sem permissão, é uma pasta…) é relançado (veja throw): esconder um erro que você não esperava só atrasa a descoberta.
$ node seguro.js
[ 'leite', 'pão francês', 'café', 'manteiga' ]
O arquivo receitas.txt não existe. Começando com a lista vazia.
[]

5. Um item fantasma no fim

texto.split("\n") sem trim() deixou um '' no fim do array (seção 2), e a lista de 4 itens virou de 5. Arquivos feitos no Windows trazem ainda um \r invisível no fim de cada linha ('leite\r'). Conserto: texto.trim().split("\n") e, se o arquivo puder vir do Windows, split(/\r?\n/) (uma expressão regular que aceita os dois finais de linha).

Missão final: a média da turma

Missão: a aba notas.txt tem uma linha por aluno, no formato Nome;nota. Leia o arquivo, some as notas (convertidas com Number) e mostre Média da turma: 7.6, com uma casa decimal (toFixed(1)).

const { readFileSync } = require("node:fs");

// leia notas.txt, some as notas e mostre a média


Ana;9
Bia;7
Caio;8
Davi;6.5

const { readFileSync } = require("node:fs");

const linhas = readFileSync("notas.txt", "utf8").trim().split("\n");
let soma = 0;
for (const linha of linhas) {
  const [aluno, nota] = linha.split(";");
  soma += Number(nota);
}
console.log(`Média da turma: ${(soma / linhas.length).toFixed(1)}`);

No lab, a solução mostrou Média da turma: 7.6 (a soma é 30.5; dividida por 4 dá 7.625, arredondado para 7.6).

Resumo

  • O módulo node:fs lê arquivos (só no Node). fs.readFileSync(nome, "utf8") devolve o conteúdo inteiro como string; sem o "utf8", vem um Buffer de bytes.
  • Para trabalhar linha a linha: texto.trim().split("\n"). JSON: JSON.parse. CSV simples: split(";") em cada linha, pulando o cabeçalho, e Number() nos números.
  • readFile de node:fs/promises com await lê sem travar o programa; o readFile com callback é o jeito antigo.
  • Um nome sem pasta é procurado na pasta atual do terminal, não na pasta do programa (aula path).
  • Erros comuns: ENOENT (não existe), EISDIR (é pasta), EACCES (sem permissão), e o SyntaxError do JSON.parse num arquivo estragado. Trate com try … catch olhando o erro.code.
