JavaScript Comparação

A pessoa tem idade para dirigir? A senha está certa? O aluno passou? Antes de decidir qualquer coisa, o programa precisa comparar: um número com outro, um texto com outro. Os operadores de comparação fazem essas perguntas, e a resposta é sempre um booleano: true ou false. Esta aula mostra os oito operadores, e por que o guia usa o === (três sinais de igual) e nunca o == (dois).

Você vai aprender
  • Os operadores de "maior" e "menor": >, <, >= e <=.
  • Os de igualdade: === ("é igual") e !== ("é diferente").
  • O que o == e o != fazem de diferente, e por que evitá-los.
  • Como o JavaScript compara textos: maiúsculas, espaços e a ordem do dicionário.
  • As pegadinhas: o NaN, o 0 <= nota <= 10 e os arrays que nunca são iguais.
  • Os erros reais: => no lugar de >=, o =< e o = no lugar do ===.

A ideia: a placa da montanha-russa

Na entrada da montanha-russa há uma placa com uma régua: "altura mínima: 1,40 m". O funcionário encosta a criança na régua e faz uma pergunta: a altura dela é maior ou igual a 1,40? A resposta é sim ou não, e é ela que decide se a criança entra.

Uma comparação é isso: uma pergunta de sim ou não sobre dois valores. altura >= 1.40 é a placa da montanha-russa escrita em JavaScript. Ela não muda nada, não guarda nada: só responde.

1. Maior e menor: >, <, >=, <=

const idade = 16;
console.log(idade > 18);
console.log(idade < 18);
console.log(idade >= 16);
console.log(idade <= 15);

Dois detalhes para gravar:

  • "Ou igual" faz diferença na fronteira. Com 16 anos, idade > 16 é false, mas idade >= 16 é true. Pergunte-se sempre: o próprio limite entra ou não? ("A partir de 18" é >= 18; "mais de 18" é > 18.)
  • O = vem sempre por último: >= e <=, como se lê: "maior ou igual". A seção Quando dá errado mostra o que o => faz (e não é um erro: é pior).

Guardando a resposta

Como a resposta é um booleano, dá para guardar numa variável com um nome que soa como pergunta (veja Booleanos):

const media = 7.5;
const aprovado = media >= 6;
console.log(`Aprovado? ${aprovado}`);

2. Igual e diferente: === e !==

Para perguntar se dois valores são iguais, use três sinais de igual: ===. Para perguntar se são diferentes, !== (o ! é o "não": "não é igual").

const senha = "abc123";
console.log(senha === "abc123");
console.log(senha === "ABC123");
console.log(senha !== "abc123");
console.log(10 === 10.0);
console.log(0.1 + 0.2 === 0.3);

Mesmo texto, letra por letra: iguais.

Para o computador, a e A são letras diferentes.

Para o JavaScript, 10 e 10.0 são o mesmo número.

A pegadinha da precisão: 0.1 + 0.2 dá 0.30000000000000004, que não é exatamente 0.3 (veja NaN, Infinity e a Precisão). Com números com casas decimais, desconfie do ===.
=, == e === são três coisas diferentes

= (um sinal) guarda um valor: é a atribuição (aula Atribuição). === (três) pergunta se é igual. E o == (dois) também pergunta, mas de um jeito que o guia não recomenda: é a próxima seção.

3. O == e o !=: a igualdade "frouxa"

O JavaScript tem uma segunda dupla de igualdade, mais antiga: == e !=. A diferença é que, quando os dois valores são de tipos diferentes (um número e um texto, por exemplo), o == converte um deles antes de comparar. O === não converte nada: tipos diferentes já são diferentes.

console.log(5 == "5");
console.log(5 === "5");
console.log(5 != "5");
console.log(5 !== "5");
console.log(0 == false);
console.log(0 === false);
console.log("" == 0);
console.log(null == undefined);
console.log(null === undefined);

As conversões do == seguem regras que nem programadores experientes lembram de cor, e produzem coisas como "" == 0 ser true (a lista completa de pegadinhas está em Conversão Automática). Com o ===, não há nada para lembrar.

A regra do guia: sempre === e !==

Se os valores podem ser de tipos diferentes (a idade que chegou como texto do teclado e o número 18), converta antes, de propósito, e compare com ===: Number(idadeTexto) === 18 (veja Conversão). Assim o código diz exatamente o que faz. O == e o != aparecem no guia só para você reconhecer em código antigo.

Missão: o jogo sorteou o número 7, e a pessoa digitou "7" (como texto, que é como o teclado entrega). O programa usa == e "funciona" por acaso. Faça do jeito do guia: converta o palpite com Number() e compare com ===. O programa deve continuar mostrando Acertou!.

const sorteado = 7;
const palpite = "7";
if (palpite == sorteado) {
  console.log("Acertou!");
}

const sorteado = 7;
const palpite = "7";
if (Number(palpite) === sorteado) {
  console.log("Acertou!");
}

4. Comparando textos

Com textos, o === compara letra por letra, e o < e o > comparam na ordem do dicionário, com algumas surpresas:

console.log("Ana" === "Ana");
console.log("Ana" === "ana");
console.log("Ana " === "Ana");
console.log("abacaxi" < "banana");
console.log("Banana" < "abacaxi");
console.log("10" < "9");
console.log("ana".toLowerCase() === "ANA".toLowerCase());

const resposta = "Sim";
if (resposta === "sim") {
  console.log("Confirmado!");
}
console.log("Fim.");

const resposta = "Sim";
if (resposta.toLowerCase() === "sim") {
  console.log("Confirmado!");
}
console.log("Fim.");

5. Três pegadinhas

O NaN não é igual a nada, nem a ele mesmo

const valor = Number("abc");
console.log(valor === NaN);
console.log(NaN === NaN);
console.log(Number.isNaN(valor));
console.log(valor > 0, valor < 0);

$ node nan.js
false
false
true
false false

O NaN ("não é um número", o resultado de uma conversão que falhou) dá false em qualquer comparação, até com ele mesmo, e não é nem maior nem menor que zero. Para saber se um valor é NaN, a única forma confiável é Number.isNaN(valor) (veja Conversão).

0 <= nota <= 10 não faz o que parece

Na matemática, "0 ≤ nota ≤ 10" quer dizer "a nota está entre 0 e 10". No JavaScript, isso não funciona:

const nota = 15;
console.log(0 <= nota <= 10);
console.log(3 > 2 > 1);
console.log(0 <= nota && nota <= 10);

$ node encadeada.js
true
false
false
0 <= nota <= 10 → true (com nota 15!)
O JavaScript faz uma comparação de cada vez, da esquerda para a direita. Primeiro 0 <= 15, que dá true. Depois, true <= 10: o true vira 1 (veja Conversão Automática), e 1 <= 10 é true. Uma nota 15 passou como válida.
3 > 2 > 1 → false
Pelo mesmo motivo: 3 > 2 é true, e true > 1 é 1 > 1, que é false.
0 <= nota && nota <= 10 → false
O jeito certo: duas comparações separadas, ligadas pelo && ("e"). "A nota é maior ou igual a 0 e menor ou igual a 10". O && é da aula Operadores Lógicos.

Dois arrays iguais não são iguais

console.log([1, 2] === [1, 2]);
const a = [1, 2];
const b = a;
console.log(a === b);
console.log({ nome: "Ana" } === { nome: "Ana" });

$ node listas.js
false
true
false

Com arrays e objetos, o === não compara o conteúdo: ele pergunta "é a mesma lista?". Duas listas com os mesmos itens são como duas cadernetas de compras iguais: o conteúdo é o mesmo, mas são duas cadernetas. Já b = a não cria uma lista nova, só dá um segundo nome para a mesma, e aí o === dá true. Isso é explicado em detalhes em Objetos são Referências.

Formas diferentes de fazer a mesma coisa

Muitas perguntas podem ser escritas de mais de um jeito. Escolha o que se lê mais parecido com a frase em português:

PerguntaFormas equivalentesPrefira
"Tem 18 anos ou mais?"idade >= 18 · idade > 17 · 18 <= idadeidade >= 18: o número da regra aparece como está na regra
"Não é a senha certa?"senha !== certa · !(senha === certa)senha !== certa
"Está entre 0 e 10?"nota >= 0 && nota <= 10 · 0 <= nota && nota <= 10Qualquer uma das duas; nunca 0 <= nota <= 10
"É igual a 5, mesmo vindo como texto?"Number(x) === 5 · x == 5Number(x) === 5
"É NaN?"Number.isNaN(x) · Object.is(x, NaN)Number.isNaN(x) (o Object.is funciona, mas é mais raro)

Quando dá errado

Escreveu => no lugar de >= 
const idade = 12;
if (idade => 18) {
  console.log("Maior de idade");
}

$ node seta.js
Maior de idade

Uma criança de 12 anos foi considerada maior de idade, e o Node não reclamou de nada. O => não é "maior ou igual": é a seta de uma arrow function (aula Arrow Functions). O JavaScript leu idade => 18 como "uma função que recebe idade e devolve 18", e uma função, numa condição, conta como verdadeira. Resultado: o if entra sempre, qualquer que seja a idade. Como consertar: o = vem por último: idade >= 18.

A comparação de texto que "não bate"

Sintoma: o if (resposta === "sim") não entra, mas a pessoa digitou "sim". Causas prováveis: uma letra maiúscula ("Sim") ou um espaço sobrando ("sim "), que não aparecem a olho nu. Para investigar, mostre o valor entre colchetes: console.log(`[${resposta}]`) deixa os espaços visíveis. Como consertar: resposta.trim().toLowerCase() === "sim".

Missão: a nota 15 deveria ser recusada, mas o programa diz que ela é válida, por causa do 0 <= nota <= 10. Reescreva a condição com duas comparações ligadas por && para o programa mostrar Nota inválida.

const nota = 15;
const valida = 0 <= nota <= 10;
if (valida) {
  console.log("Nota válida");
}
if (!valida) {
  console.log("Nota inválida");
}

const nota = 15;
const valida = nota >= 0 && nota <= 10;
if (valida) {
  console.log("Nota válida");
}
if (!valida) {
  console.log("Nota inválida");
}

Missão final: o cinema

Missão: a Ana tem 14 anos e quer ir ao cinema. Complete as duas comparações para responder se ela pode assistir a cada filme: o primeiro é para maiores de 14 anos (14 ou mais), o segundo para maiores de 16 (16 ou mais). O programa deve mostrar true para o primeiro e false para o segundo.

const podeFilme16 = false; // troque pela comparação
console.log(`Filme 14 anos: pode assistir? ${podeFilme14}`);
console.log(`Filme 16 anos: pode assistir? ${podeFilme16}`);

const idade = 14;
const podeFilme14 = idade >= 14;

console.log(`Filme 14 anos: pode assistir? ${podeFilme14}`);
console.log(`Filme 16 anos: pode assistir? ${podeFilme16}`);

Resumo

  • Toda comparação responde true ou false. >, <, >= e <= perguntam "maior" e "menor"; o "ou igual" decide se o próprio limite entra.
  • === pergunta "é igual?" e !== "é diferente?", comparando valor e tipo. O == e o != convertem os tipos antes e dão resultados como "" == 0 ser true: evite.
  • Textos se comparam letra por letra: maiúsculas, espaços e a ordem do dicionário contam ("10" < "9" é true).
  • NaN nunca é igual a nada (use Number.isNaN); 0 <= x <= 10 não funciona (use &&); arrays e objetos só são === se forem o mesmo.
  • O = vem por último: >= e <=. O => é uma arrow function e faz o if entrar sempre, sem erro.
