JavaScript no Mundo

O JavaScript nasceu em 1995, criado em poucos dias por Brendan Eich, na empresa Netscape, para deixar as páginas da web um pouco mais vivas: conferir um formulário, trocar uma imagem. Trinta anos depois, ele está em quase todo lugar: em todas as páginas que você abre, em servidores de grandes empresas, em aplicativos de celular e de computador, nas ferramentas que os próprios programadores usam. Esta aula é um passeio por esses lugares, com um exemplo de cada um que deu para rodar, e um mapa do que estudar depois deste guia.

Você vai aprender
  • Os grandes lugares onde o JavaScript roda: o navegador, o servidor, a linha de comando, o celular e o computador.
  • O que são frameworks e bibliotecas (React, Vue, Angular, Express) e por que tanta gente usa.
  • Como é um servidor de verdade em Node.js, rodando e respondendo a um pedido.
  • Os outros "Nodes": Deno e Bun.
  • Um mapa de próximos passos, de acordo com o que você quer construir.

Os comandos desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook). Os números de versão dos pacotes do npm foram consultados no dia em que a aula foi escrita, em outubro de 2026, e mudam com o tempo.

A ideia: uma língua, muitos países

O português é falado no Brasil, em Portugal, em Angola, em Moçambique. A gramática é praticamente a mesma; o que muda é o lugar, o vocabulário de cada um e o que as pessoas fazem com a língua. O JavaScript é assim: a linguagem que você aprendeu (variáveis, funções, arrays, objetos, async) é a mesma em todo lugar. O que muda é o ambiente, com as "palavras locais" de cada um:

  • no navegador, o document (a página), o window, o alert;
  • no Node, o fs (arquivos), o process, o http (servidores);
  • num aplicativo de celular, a câmera, o GPS, as notificações.

Você já viu essa diferença na aula Onde o JavaScript Roda. Agora vamos ver até onde ela vai.

2. No servidor: o Node.js

Em 2009, Ryan Dahl pegou o motor V8 do Chrome e o colocou para rodar fora do navegador: nasceu o Node.js, que você usou o guia inteiro. Com ele, o JavaScript passou a rodar nos servidores, os computadores que recebem os pedidos dos navegadores e dos aplicativos e devolvem as respostas. Este é um servidor de verdade, com o módulo node:http que vem com o Node:

import { createServer } from "node:http";

const cardapio = [
  { nome: "Pão francês", preco: 0.75 },
  { nome: "Sonho", preco: 4.5 },
];

const servidor = createServer((pedido, resposta) => {
  console.log(`Pedido recebido: ${pedido.method} ${pedido.url}`);
  resposta.setHeader("Content-Type", "application/json; charset=utf-8");
  resposta.end(JSON.stringify(cardapio));
});

servidor.listen(3000, () => {
  console.log("Padaria no ar em http://localhost:3000");
});
createServer((pedido, resposta) => { … })
Cria o servidor. A função é chamada a cada pedido que chega (um callback): pedido diz o que foi pedido; resposta é o que vai ser devolvido.
pedido.method e pedido.url
O tipo do pedido (GET = "me dê") e o endereço pedido (/cardapio).
resposta.setHeader(…)
Avisa que a resposta é JSON.
resposta.end(JSON.stringify(cardapio))
Manda o cardápio, como texto JSON, e encerra a resposta.
servidor.listen(3000, …)
"Escute" na porta 3000: o servidor fica no ar, esperando pedidos, até alguém pará-lo. O endereço localhost quer dizer "este mesmo computador".

A Ana deixou o servidor rodando num terminal e, em outro, fez um pedido com o curl (um programa que faz pedidos à web pela linha de comando, como um navegador sem tela):

$ node servidor.js
Padaria no ar em http://localhost:3000
Pedido recebido: GET /cardapio

$ curl -s http://localhost:3000/cardapio
[{"nome":"Pão francês","preco":0.75},{"nome":"Sonho","preco":4.5}]

No primeiro terminal, o servidor anunciou que estava no ar e, quando o pedido chegou, registrou GET /cardapio. No segundo, o curl recebeu o cardápio em JSON. Um aplicativo de celular ou uma página faria o mesmo pedido com o fetch e mostraria o cardápio bonito na tela. O servidor só para com Ctrl+C (a Ana o parou com kill).

Esse exemplo não roda no editor do guia (o editor imita o Node, mas não tem o módulo http: um navegador não pode virar servidor). Na vida real, quase ninguém escreve o servidor "na mão" assim: usa-se um framework de servidor como o Express (versão 5.3.0 no npm, consultada com npm view express version) ou o Fastify, que cuidam de rotas, formulários e segurança.

4. No celular e no computador

  • Aplicativos de celular: com o React Native (da Meta), o mesmo JavaScript vira um aplicativo de Android e de iPhone, com botões e telas nativos de cada sistema. Outras opções: Ionic, Capacitor, NativeScript.
  • Programas de computador: o Electron junta um navegador (o Chromium) e o Node num programa só. Com ele foram feitos programas que você talvez use: o editor VS Code, o Discord, o Slack. Por dentro, cada janela é uma página web com JavaScript, que também pode ler arquivos como o Node.
  • Extensões de navegador (bloqueadores de anúncio, tradutores) são feitas de HTML, CSS e JavaScript.
  • Jogos no navegador, com bibliotecas como Phaser e Three.js (3D).
  • Automação e planilhas: o Google Apps Script, que automatiza Planilhas e Documentos do Google, usa JavaScript.

5. Os outros "Nodes": Deno e Bun

O Node não é o único programa que roda JavaScript fora do navegador. Dois mais novos disputam espaço:

AmbienteMotorO que tem de diferente
Node.js (2009)V8O mais usado, com o maior conjunto de pacotes (o npm). É o deste guia.
Deno (2018)V8Criado pelo mesmo Ryan Dahl do Node, para corrigir o que ele considerava erros de projeto: mais segurança por padrão e TypeScript sem configuração.
Bun (2022)JavaScriptCore (o do Safari)Foco em velocidade; junta num programa só o que no Node são várias ferramentas (instalar pacotes, testar, empacotar).

A linguagem é a mesma nos três: um programa que só usa JavaScript puro (sem fs nem process) roda em qualquer um. O que você aprendeu aqui vale para todos.

Quando dá errado

"JavaScript é a mesma coisa que Java?"

Não. São linguagens diferentes, de empresas diferentes, para usos diferentes. O nome "JavaScript" foi escolhido em 1995 por marketing, aproveitando a fama do Java naquela época. Como se diz por aí: Java está para JavaScript como carro está para carpete.

O código de um tutorial de framework "não funciona" no Node

Um tutorial de React usa document, ou um tutorial do Node usa fs numa página. Cada ambiente tem as suas "palavras locais": rodando no lugar errado, sai ReferenceError: document is not defined (no Node) ou require is not defined (no navegador). Como evitar: antes de copiar um exemplo, descubra onde ele foi feito para rodar (veja Onde o JavaScript Roda).

O servidor não responde no editor do guia

O editor imita o Node, mas roda dentro do navegador, e um navegador não pode abrir uma porta para receber pedidos. Por isso, no editor, o import { createServer } from "node:http" para com um erro: o editor não tem esse módulo. Como fazer: rode o servidor.js no Node do seu computador (veja Instalar o Node.js).

// mostre cada produto e o total aqui

const cardapio = [
  { nome: "Pão francês", preco: 0.75 },
  { nome: "Sonho", preco: 4.5 },
];

function linhaDoCardapio(produto) {
  return `${produto.nome}: R$ ${produto.preco.toFixed(2)}`;
}

for (const produto of cardapio) {
  console.log(linhaDoCardapio(produto));
}
const total = cardapio.reduce((soma, p) => soma + p.preco, 0);
console.log(`Total do cardápio: R$ ${total.toFixed(2)}`);

No lab, a solução mostrou Pão francês: R$ 0.75, Sonho: R$ 4.50 e Total do cardápio: R$ 5.25.

Resumo

  • O JavaScript é a única linguagem que todos os navegadores rodam, e desde o Node.js (2009) roda também em servidores e na linha de comando.
  • A linguagem é a mesma em todo lugar; o que muda é o ambiente (document no navegador, fs e http no Node).
  • Frameworks e bibliotecas (React, Vue, Angular, Express) são código JavaScript pronto que organiza projetos grandes.
  • Com o Node, poucas linhas fazem um servidor que responde JSON; com React Native e Electron, o JavaScript vira aplicativo de celular e de computador.
  • Deno e Bun são alternativas ao Node; o JavaScript puro roda em todos.
  • Próximo passo: domine a linguagem com os projetos do guia, e escolha a trilha (front-end, back-end, celular) pelo que você quer construir.
