JavaScript Modo Interativo do Node (>)

Para testar uma conta ou uma linha de código, não é preciso criar um arquivo. Digite só node no terminal, sem nome de arquivo, e o Node.js abre o modo interativo: aparece um >, você digita uma linha de JavaScript, aperta Enter e ele responde na hora. É o melhor lugar para tirar uma dúvida rápida ("quanto dá isso?", "como sai aquilo?"), e você vai usá-lo o guia inteiro.

Você vai aprender
  • A abrir o modo interativo com node e a sair com .exit ou Ctrl+D.
  • Que ele mostra sozinho o valor de cada linha, e por que aparece undefined depois de const e de console.log.
  • Por que os textos aparecem com aspas simples ('Ana'), e o atalho _ (o último resultado).
  • A escrever várias linhas (o prompt de continuação |) e o modo .editor.
  • Os comandos com ponto: .help, .save, .load, .exit.
  • A parar um programa travado com Ctrl+C.
  • Os erros reais: Uncaught ReferenceError, has already been declared, Assignment to constant variable, comando do terminal digitado no >.

Todas as sessões desta aula foram digitadas no Node.js 24 LTS, num terminal de verdade, na máquina fictícia da Ana (ana@notebook). O que aparece aqui é exatamente o que ficou na tela.

A ideia: a calculadora e a carta

Um programa em arquivo é como uma carta: você escreve tudo, revisa, envia, e só depois vê o resultado. O modo interativo é como uma calculadora: você digita uma conta, aperta "=", e a resposta aparece na hora; digita outra, outra resposta. Ninguém escreve uma carta numa calculadora, nem faz uma conta rápida mandando carta.

O nome técnico do modo interativo é REPL, de Read, Eval, Print, Loop: "ler" o que você digitou, "avaliar" (executar), "mostrar" o resultado e "repetir", voltando ao >.

2. A calculadora que responde sozinha

No >, o Node.js mostra o valor de qualquer coisa que você digitar, sem precisar de console.log:

$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> 2 + 3
5
> 10 / 4
2.5
> "Olá, " + "Ana"
'Olá, Ana'
> "pão".toUpperCase()
'PÃO'
> Math.max(3, 9, 4)
9
> .exit
10 / 4 → 2.5
A divisão. Decimais saem com ponto, nunca com vírgula.
"Olá, " + "Ana" → 'Olá, Ana'
O + entre dois textos junta os textos. E repare: a resposta veio entre aspas simples. O modo interativo mostra os textos assim para você saber que é um texto (e não um número ou um nome). É só o jeito de mostrar: o texto em si não tem aspas.
"pão".toUpperCase() → 'PÃO'
Um método de texto: "passar para maiúsculas". Os métodos de texto têm aula própria: Métodos de String.
Math.max(3, 9, 4) → 9
O maior dos números. O Math é a caixa de ferramentas de matemática do JavaScript.

Variáveis e o undefined que aparece sozinho

Você pode criar uma variável (um nome que guarda um valor; aula Variáveis) e usar nas linhas seguintes. Ela vale até você sair:

$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> const nome = "Ana";
undefined
> nome
'Ana'
> nome.length
3
> console.log("Bom dia, " + nome);
Bom dia, Ana
undefined
> .exit

Dois undefined ("indefinido") apareceram, e eles assustam todo mundo no começo. Não são erros:

const nome = "Ana"; → undefined
Criar uma variável é uma ação, não uma conta; ela não tem um "resultado" para mostrar. O modo interativo sempre mostra alguma coisa, então mostra undefined: "não há valor aqui". A variável foi criada, sim: na linha seguinte, nome respondeu 'Ana'.
nome.length → 3
O tamanho do texto: Ana tem 3 letras.
Bom dia, Ana
Isto é o que o console.log escreveu. Repare que saiu sem aspas: o console.log escreve o texto puro, como num programa.
undefined (depois do Bom dia)
E isto é o valor da linha console.log(...). O console.log escreve na tela, mas não "devolve" nada; o modo interativo mostra esse "nada" como undefined.

Experimente: esta caixa imita o modo interativo. Digite as linhas acima, uma de cada vez, e invente outras contas. Repare nos undefined.

O atalho _: o último resultado

O nome _ (sublinhado), só no modo interativo, guarda o resultado da linha anterior. Útil para continuar uma conta:

$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> 7 * 6
42
> _ + 1
43
> .exit

Num arquivo, um valor solto não aparece

Esse "mostrar sozinho" só existe no modo interativo. Num arquivo, uma linha com 2 + 3; é calculada e jogada fora, sem aparecer nada. Num programa, quem mostra é sempre o console.log:

3. Várias linhas: o prompt |

Quando você abre uma chave { e aperta Enter, o Node.js percebe que a instrução ainda não acabou e, em vez do >, mostra o |: o prompt de continuação, "pode continuar". Quando a chave fecha, ele executa tudo junto:

$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> for (let i = 1; i <= 3; i++) {
| console.log("volta " + i);
| }
volta 1
volta 2
volta 3
undefined
> function dobro(x) {
| return x * 2;
| }
undefined
> dobro(21)
42
> .exit
for (…) {
Uma repetição (aula for) que abriu a chave e ainda não fechou.
| console.log(…);
O | diz "continuo esperando o resto". Você digita a linha de dentro.
| }
A chave fechou: o Node.js executa as três linhas juntas, e o laço mostra três voltas. O undefined do fim é o valor do for, que não tem nenhum.
function dobro(x) { … }
Uma função (aula Funções). Criá-la não mostra nada além de undefined; usá-la, dobro(21), mostra 42.

Repare que o modo interativo não acrescenta os espaços da indentação: as linhas de dentro ficaram encostadas na margem. Para trechos maiores, bem arrumados, use o .editor (a seguir) ou um arquivo.

O modo .editor

O comando .editor abre um "mini editor": você digita quantas linhas quiser, Enter só pula de linha, e nada roda até você apertar Ctrl+D. (Para desistir, Ctrl+C.)

$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> .editor
// Entering editor mode (Ctrl+D to finish, Ctrl+C to cancel)
const itens = ["pão", "leite"];
for (const item of itens) {
  console.log("- " + item);
}
                                         « aqui a Ana apertou Ctrl+D
- pão
- leite
undefined
> .exit

"Entrando no modo editor (Ctrl+D para terminar, Ctrl+C para cancelar)". Depois do Ctrl+D, as linhas rodaram de uma vez e o > voltou.

Experimente: digite o for e a função dobro acima, linha por linha, e repare no prompt de continuação. Depois experimente dobro(100).

4. Parando o que travou: Ctrl+C

O Ctrl+C é o "freio de mão". Ele serve para duas coisas no modo interativo.

Desistir de uma linha pela metade. Aqui a Ana esqueceu de fechar o parêntese, o Node.js ficou no | esperando o resto, e ela apertou Ctrl+C: o pedaço foi descartado e o > voltou.

$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> console.log("tchau"
|                                        « Ctrl+C aqui
>
> 2 + 2
4
> .exit

Parar uma conta que não termina. O while (true) {} é uma repetição que nunca acaba (aula while): o modo interativo trava, sem voltar ao >. O Ctrl+C interrompe:

$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> while (true) {}
^C
Uncaught Error: Script execution was interrupted by `SIGINT`
    at ContextifyScript.runInThisContext (node:vm:137:12)
    «  mais 7 linhas "at …" cortadas: são do próprio Node
    at [_line] [as _line] (node:internal/readline/interface:969:18) {
  code: 'ERR_SCRIPT_EXECUTION_INTERRUPTED'
}
>
> 3 + 3
6
> .exit

O ^C é o jeito de o terminal mostrar o Ctrl+C. A mensagem diz "a execução foi interrompida pelo SIGINT" (SIGINT é o nome do sinal que o Ctrl+C manda: "interromper"). O importante: o modo interativo continua aberto e o 3 + 3 funcionou normalmente. Num > vazio, um Ctrl+C mostra o aviso (To exit, press Ctrl+C again or Ctrl+D or type .exit), "para sair, aperte Ctrl+C de novo, ou Ctrl+D, ou digite .exit".

E o .break?

O .help (seção 5) lista um comando .break para "sair" de uma linha pela metade. No Node.js 24 da Ana, digitado no meio de um trecho de várias linhas, ele foi lido como parte do código e deu erro de sintaxe. Use o Ctrl+C, que funcionou sempre.

Quando dá errado

No modo interativo, um erro não fecha nada: aparece a mensagem, começando com Uncaught ("não capturado": ninguém tratou o erro), e o > volta. Por isso ele é ótimo para errar à vontade.

Um nome que não existe 
$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> idade
Uncaught ReferenceError: idade is not defined
> Console.log("oi")
Uncaught ReferenceError: Console is not defined
> .exit

"idade não está definido": ninguém criou essa variável. "Console não está definido": com C maiúsculo, o nome não existe (é console). Repare que, aqui, a mensagem é bem mais curta que num arquivo: sem caminho, sem linhas at …, sem Node.js v24…. Como consertar: crie a variável antes (const idade = 30;) ou corrija o nome.

Criar de novo uma variável que já existe 
$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> let preco = 7.5;
undefined
> let preco = 8;
Uncaught SyntaxError: Identifier 'preco' has already been declared
> preco = 8;
8
> preco
8
> const loja = "Padaria";
undefined
> loja = "Mercado";
Uncaught TypeError: Assignment to constant variable.
> .exit

No modo interativo, as variáveis ficam vivas até você sair, e isso pega muita gente que está testando e redigita uma linha:

Identifier 'preco' has already been declared
"O identificador preco já foi declarado". Não dá para criar com let um nome que já existe. Para mudar o valor, escreva sem o let: preco = 8;.
Assignment to constant variable.
"Atribuição a uma variável constante". O const não deixa trocar o valor (aula Constantes). É um TypeError ("erro de tipo").

Como consertar: para mudar um valor, use o nome sem let; se quiser recomeçar do zero, saia (.exit) e abra o node de novo: tudo é esquecido.

Comando do terminal digitado no > 
$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> ls
Uncaught ReferenceError: ls is not defined
> .exit

O ls é um comando do terminal (o $), não JavaScript. No >, o Node.js achou que ls era o nome de uma variável. O mesmo acontece com node ola.js digitado aqui dentro (veja Rodando um Programa). Como consertar: saia com .exit e digite o comando no $.

Esqueceu os parênteses 
$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> "pão".toUpperCase
[Function: toUpperCase]
> "pão".toUpperCase()
'PÃO'
> .exit

Sem os parênteses, você não chamou o método: só perguntou "o que é toUpperCase?", e o Node.js respondeu "é uma função" ([Function: toUpperCase]). Não é erro, mas também não é o que você queria. Como consertar: ponha os parênteses: toUpperCase().

Um comando com ponto que não existe 
$ node
Welcome to Node.js v24.22.0.
Type ".help" for more information.
> .sair
Invalid REPL keyword

"Palavra-chave do REPL inválida". Os comandos com ponto são em inglês e são só os do .help. Como consertar: .exit.

Missão final: do > para o arquivo

Missão: no modo interativo, dobro(21) mostrava 42 sozinho. Neste arquivo, a última linha não mostra nada. Troque-a para que o programa mostre dobro de 21: 42 (dica: console.log("dobro de 21: " + dobro(21));).

function dobro(x) {
  return x * 2;
}

dobro(21);

function dobro(x) {
  return x * 2;
}

console.log("dobro de 21: " + dobro(21));

Resumo

  • node sozinho abre o modo interativo (o REPL). O > espera JavaScript; o $ é o terminal.
  • Ele mostra sozinho o valor de cada linha; textos aparecem com aspas simples ('Ana'). _ é o último resultado.
  • undefined depois de const, console.log, for ou function é normal: a linha não tem valor.
  • Abrindo uma chave, o prompt vira | até a instrução terminar; .editor + Ctrl+D roda um trecho maior.
  • Ctrl+C desiste de uma linha ou para algo travado; .exit ou Ctrl+D sai. Ao sair, tudo some, a não ser o que você guardou com .save.
  • Um erro no modo interativo começa com Uncaught e não fecha nada. Variáveis vivem até sair: let de novo dá has already been declared.
  • Num arquivo, nada aparece sozinho: use console.log.
