JavaScript no Node.js: console, process e fs

Esta é a página de consulta rápida das ferramentas que o Node.js dá aos seus programas: o console (escrever no terminal), o process (o programa em execução: argumentos, variáveis de ambiente, código de saída), o fs (file system, "sistema de arquivos": ler e escrever arquivos) e o path (montar e desmontar caminhos de pasta).

Só no Node

O process, o fs, o path e o require são do Node. No navegador eles não existem (lá, o console existe, mas escreve no Console do F12). As caixas "Experimente" deste guia imitam o Node, com uma pasta só da caixa para os arquivos (veja O Editor do Guia).

Como ler as tabelas
  • Aqui os exemplos são programas (arquivos .js) rodados com node arquivo.js na pasta da Ana, /home/ana, com o Node.js v24.22.0. Cada tabela vem com o programa completo e a saída real logo abaixo.
  • O fs e o path precisam ser importados: const fs = require("node:fs"); (CommonJS, o padrão de um arquivo .js) ou import fs from "node:fs"; (módulos). O node: na frente avisa que é um módulo que já vem com o Node. Veja Módulos e require e module.exports.

fs: arquivos

As funções terminadas em Sync ("síncrono") esperam o arquivo ficar pronto antes de ir para a próxima linha: são as mais simples para scripts. As da node:fs/promises são usadas com await. Os caminhos sem barra no começo ("compras.txt") são procurados na pasta do process.cwd().

const fs = require("node:fs");

fs.writeFileSync("compras.txt", "pão\nleite\n");
fs.appendFileSync("compras.txt", "café\n");
console.log(fs.readFileSync("compras.txt", "utf8"));
console.log(fs.readFileSync("compras.txt", "utf8").trim().split("\n"));
console.log(fs.readFileSync("compras.txt"));
console.log(fs.existsSync("compras.txt"), fs.existsSync("nada.txt"));
fs.mkdirSync("notas", { recursive: true });
fs.writeFileSync("notas/turma.json", JSON.stringify({ ana: 9 }, null, 2));
console.log(JSON.parse(fs.readFileSync("notas/turma.json", "utf8")));
console.log(fs.readdirSync("notas"));
fs.renameSync("notas/turma.json", "notas/turma-a.json");
console.log(fs.readdirSync("notas"));
console.log(fs.statSync("compras.txt").size, fs.statSync("notas").isDirectory());
fs.unlinkSync("notas/turma-a.json");
fs.rmSync("notas", { recursive: true });
console.log(fs.existsSync("notas"));

Quando dá errado

Ler um arquivo que não existe é o erro mais comum com fs:

const fs = require("node:fs");
const texto = fs.readFileSync("lista.txt", "utf8");
console.log(texto);

Desta vez, o começo da mensagem mostra uma linha de dentro do Node (o arquivo fs dele), e não do seu programa: foi lá que o erro foi lançado. Pule essas três linhas.
Error: ENOENT: no such file or directory, open 'lista.txt'
A mensagem: "não existe esse arquivo ou pasta", ao tentar abrir (open) lista.txt. ENOENT é o código do sistema para "não encontrado" (Error NO ENTry).
at Object.<anonymous> (/home/ana/fs-erro.js:2:18)
A primeira linha at com o seu arquivo: linha 2, coluna 18. É aqui que você vai olhar.
{ errno, code, syscall, path }
Os detalhes do erro, num objeto: o code ('ENOENT') é o que você testa num catch (if (erro.code === "ENOENT")), e o path é o arquivo procurado.
CódigoSignificaComo resolver
ENOENTo arquivo ou pasta não existeConfira o nome e a pasta: o caminho é relativo ao process.cwd(), não à pasta do programa. Use path.join(__dirname, "lista.txt") ou teste com existsSync.
EISDIRera para ser um arquivo, mas é uma pastaUse readdirSync para pastas.
EEXISTjá existe (ao criar uma pasta)mkdirSync(pasta, { recursive: true }).
EACCESsem permissãoGrave numa pasta sua (a pasta pessoal).

As mensagens completas de EISDIR e EEXIST, e as de require/import, estão em Mensagens de Erro Comuns. Para tratar o erro sem derrubar o programa, use try … catch.

Resumo

  • console.log escreve na saída padrão; console.error/warn, na saída de erros. console.table, group, count e dir ajudam a ver dados.
  • process.argv.slice(2) são os argumentos; process.env.NOME, as variáveis de ambiente; process.exit(n) termina na hora com o código n.
  • fs: readFileSync(arq, "utf8") lê, writeFileSync grava (substituindo), appendFileSync acrescenta, existsSync confere, mkdirSync/readdirSync/rmSync cuidam de pastas.
  • path.join monta caminhos; basename, extname e dirname desmontam; __dirname é a pasta do programa.
  • ENOENT = arquivo não encontrado: confira o nome e a pasta atual.
