JavaScript sort e toSorted

Pôr as coisas em ordem é uma das tarefas mais comuns de um programa: a lista de chamada em ordem alfabética, os produtos do mais barato ao mais caro, o ranking das notas da turma. Os arrays do JavaScript têm dois métodos para isso: o sort (em inglês, "ordenar"), que arruma o próprio array, e o toSorted ("para ordenado"), que devolve uma cópia arrumada e deixa o original como estava. Os dois escondem uma pegadinha famosa com números, que você vai ver logo no começo.

Você vai aprender
  • Como ordenar textos com sort(), e por que ele muda o array original.
  • A pegadinha: por que [10, 9, 100, 1, 25].sort() dá [ 1, 10, 100, 25, 9 ].
  • A função de comparação: (a, b) => a - b para crescente, b - a para decrescente.
  • O toSorted ES2023, que ordena sem estragar o original.
  • Acentos e maiúsculas: localeCompare.
  • Como ordenar objetos (por preço, por nome) e o que acontece com os empates.
  • reverse e toReversed: inverter a ordem.
  • Os erros reais: a função que devolve true/false, o a - b em textos, o localeCompare em números.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js. Você pode rodar cada um no editor do guia.

A ideia: arrumar a fila comparando de dois em dois

A professora da Ana quer os alunos em fila, em ordem alfabética. Ela não precisa saber nenhum método mágico: basta olhar dois alunos de cada vez e decidir "quem fica na frente?". Repetindo essa pergunta várias vezes, a fila inteira fica em ordem.

O sort trabalha assim. Ele escolhe pares de itens, pergunta "quem vem antes?" e vai trocando de lugar. O jeito exato de escolher os pares é assunto dele (você não precisa saber); a sua parte é só dizer como comparar dois itens. Se você não disser nada, ele usa uma regra própria, e é aí que mora a pegadinha.

1. Ordenando textos com sort()

const chamada = ["Caio", "Ana", "Davi", "Bia"];
chamada.sort();
console.log(chamada);

$ node nomes.js
[ 'Ana', 'Bia', 'Caio', 'Davi' ]
chamada.sort()
Ordena o array chamada. Sem nada entre os parênteses, a regra é a de "dicionário": compara os textos letra por letra.
console.log(chamada)
Repare que mostramos chamada, o mesmo array. O sort não criou uma lista nova: ele arrumou a lista que já existia, mudando os itens de lugar.

O sort também devolve o array, mas é o mesmo array, e não uma cópia:

const chamada = ["Caio", "Ana", "Davi", "Bia"];
const ordenada = chamada.sort();
console.log("ordenada:", ordenada);
console.log("chamada: ", chamada);
console.log(ordenada === chamada);

$ node devolve.js
ordenada: [ 'Ana', 'Bia', 'Caio', 'Davi' ]
chamada:  [ 'Ana', 'Bia', 'Caio', 'Davi' ]
true

O true no fim confirma: ordenada e chamada são o mesmo array com dois nomes (aula Objetos são Referências). A ordem original, com o Caio na frente, se perdeu. Na seção 4 você vê como ordenar sem perder o original.

Mas o array não era const?

Era, e mesmo assim o sort funcionou. O const só proíbe pôr outro array na variável (chamada = […]); ele não impede de mudar os itens de dentro (aula Constantes).

2. A pegadinha dos números

A Ana anotou as idades das pessoas da família e pediu para ordenar:

const idades = [10, 9, 100, 1, 25];
idades.sort();
console.log(idades);

$ node numeros.js
[ 1, 10, 100, 25, 9 ]

O 9 ficou no fim, depois do 100! Não é um defeito do Node: é a regra. Sem uma função de comparação, o sort transforma cada item em texto e compara os textos como no dicionário, letra por letra (aqui, algarismo por algarismo):

Como textoPrimeiro caracterePor que ficou nesse lugar
"1"1Começa com 1 e é o mais curto
"10"1Também começa com 1, mas é mais comprido que "1" (como "mar" vem antes de "mares")
"100"1Começa com "10" e é mais comprido que ele
"25"22 vem depois de 1
"9"99 vem depois de 2: no dicionário, "9" é "maior" que "25"

É a mesma coisa que pôr "zebra" depois de "abacaxi", mesmo sendo uma palavra mais curta. Para os números ficarem na ordem de valor, você precisa dizer ao sort como comparar.

3. A função de comparação

const idades = [10, 9, 100, 1, 25];
idades.sort((a, b) => a - b);
console.log("crescente:  ", idades);
idades.sort((a, b) => b - a);
console.log("decrescente:", idades);

$ node comparar.js
crescente:   [ 1, 9, 10, 25, 100 ]
decrescente: [ 100, 25, 10, 9, 1 ]
(a, b) => a - b
A função de comparação (em inglês, compare function). O sort a chama várias vezes, cada vez com dois itens do array, a e b, e pergunta: "quem vem antes?".
a - b
A resposta é um número, e só o sinal dele importa (veja a tabela abaixo). Se a for menor, a - b é negativo, e o a fica na frente: ordem crescente.
b - a
A conta ao contrário: o maior fica na frente, ordem decrescente.
A função devolve…O sort entendeExemplo com a - b
Um número negativoa vem antes de ba = 9, b = 25 → -16: o 9 fica antes
Um número positivob vem antes de aa = 100, b = 25 → 75: o 25 fica antes
ZeroTanto faz: os dois são "iguais"; ficam na ordem em que estavama = 10, b = 10 → 0
Para decorar

a - b: do menor para o maior (como uma escada subindo). b - a: do maior para o menor. Funciona para números, para preços, para notas e para qualquer valor numérico de um objeto (seção 6).

Missão: rode e veja a pegadinha: o 9 vai para o fim. Depois passe ao sort uma função de comparação para as idades saírem em ordem crescente: [ 1, 9, 10, 25, 100 ]. Para terminar, experimente a ordem decrescente.

const idades = [10, 9, 100, 1, 25];
idades.sort();
console.log(idades);

const idades = [10, 9, 100, 1, 25];
idades.sort((a, b) => a - b);
console.log(idades);

4. toSorted: ordenar sem mudar o original ES2023

Muitas vezes você quer as duas coisas: a lista na ordem em que foi digitada e uma versão ordenada. O toSorted aceita a mesma função de comparação do sort, mas devolve um array novo e não toca no original:

const notas = [7, 4.5, 9, 6, 8.5];
const ordenadas = notas.toSorted((a, b) => a - b);
console.log("ordenadas:", ordenadas);
console.log("original: ", notas);

$ node tosorted.js
ordenadas: [ 4.5, 6, 7, 8.5, 9 ]
original:  [ 7, 4.5, 9, 6, 8.5 ]

O toSorted entrou no JavaScript em 2023 (ECMAScript 2023) e existe no Node.js desde a versão 20. Em código mais antigo, você vai encontrar o mesmo efeito escrito com uma cópia antes do sort:

const notas = [7, 4.5, 9];
const a = notas.toSorted((x, y) => x - y);
const b = [...notas].sort((x, y) => x - y);
const c = notas.slice().sort((x, y) => x - y);
console.log(a, b, c, notas);

$ node copias.js
[ 4.5, 7, 9 ] [ 4.5, 7, 9 ] [ 4.5, 7, 9 ] [ 7, 4.5, 9 ]

As três formas dão o mesmo resultado e as três deixam notas intacto. O [...notas] e o notas.slice() fazem uma cópia (aula Copiando Arrays), e o sort arruma a cópia. Em código novo, prefira o toSorted: diz o que faz numa palavra só.

5. Acentos e maiúsculas: localeCompare

A regra de "dicionário" do sort() não é o dicionário do português: ela compara os códigos dos caracteres (o Unicode). Nesses códigos, todas as maiúsculas vêm antes de todas as minúsculas, e as letras com acento vêm depois do z:

const frutas = ["banana", "Abacaxi", "maçã", "abacate", "Uva", "ameixa"];
console.log(frutas.toSorted());
console.log(frutas.toSorted((a, b) => a.localeCompare(b)));

$ node acentos.js
[ 'Abacaxi', 'Uva', 'abacate', 'ameixa', 'banana', 'maçã' ]
[ 'abacate', 'Abacaxi', 'ameixa', 'banana', 'maçã', 'Uva' ]

Na primeira linha, 'Uva' ficou antes de 'abacate' só porque começa com maiúscula. Na segunda, com o localeCompare, a ordem é a que uma pessoa esperaria. Com acentos, a diferença é ainda maior:

const palavras = ["ovo", "óculos", "água", "zebra", "abelha"];
console.log(palavras.toSorted());
console.log(palavras.toSorted((a, b) => a.localeCompare(b, "pt-BR")));
console.log("a".localeCompare("b"), "b".localeCompare("a"), "a".localeCompare("a"));

$ node acentos2.js
[ 'abelha', 'ovo', 'zebra', 'água', 'óculos' ]
[ 'abelha', 'água', 'óculos', 'ovo', 'zebra' ]
-1 1 0
a.localeCompare(b)
Um método dos textos: "compare de acordo com o idioma" (locale = "local", a região e a língua). Ele devolve -1 se a vem antes, 1 se vem depois e 0 se são iguais, exatamente o que a função de comparação precisa devolver. Por isso dá para usá-lo direto.
"pt-BR"
Opcional: o idioma das regras. Sem ele, vale o idioma do sistema. Escrever "pt-BR" garante a ordem do português do Brasil em qualquer computador.

Regra prática: para ordenar textos que uma pessoa vai ler (nomes, produtos, cidades), use (a, b) => a.localeCompare(b). O sort() sem nada só serve para textos simples, sem acentos e todos com a mesma caixa (maiúsculas ou minúsculas).

6. Ordenando objetos

Com uma lista de produtos, a função de comparação escolhe qual informação comparar. Os objetos têm aula própria (Objetos); aqui basta saber que a.preco é o preço do produto a:

const produtos = [
  { nome: "caderno", preco: 18 },
  { nome: "mochila", preco: 129 },
  { nome: "caneta", preco: 3 },
  { nome: "estojo", preco: 25 },
];
const porPreco = produtos.toSorted((a, b) => a.preco - b.preco);
console.log(porPreco);
const porNome = produtos.toSorted((a, b) => a.nome.localeCompare(b.nome));
console.log(porNome.map((p) => p.nome).join(", "));

$ node objetos.js
[
  { nome: 'caneta', preco: 3 },
  { nome: 'caderno', preco: 18 },
  { nome: 'estojo', preco: 25 },
  { nome: 'mochila', preco: 129 }
]
caderno, caneta, estojo, mochila

Para preços (números), a mesma conta a.preco - b.preco. Para nomes (textos), o localeCompare. A última linha usa o map para pegar só os nomes e o join para juntá-los.

E os empates?

No ranking da turma, a Bia e o Caio tiraram 8; a Ana e o Davi tiraram 9:

const alunos = [
  { nome: "Bia", nota: 8 },
  { nome: "Ana", nota: 9 },
  { nome: "Caio", nota: 8 },
  { nome: "Davi", nota: 9 },
];
const ranking = alunos.toSorted((a, b) => b.nota - a.nota);
for (const aluno of ranking) {
  console.log(`${aluno.nota} - ${aluno.nome}`);
}

$ node estavel.js
9 - Ana
9 - Davi
8 - Bia
8 - Caio

Quando a função devolve 0 (empate), os dois itens ficam na ordem em que já estavam: a Bia vinha antes do Caio na lista original, e continua antes. Os programadores chamam isso de ordenação estável, e o JavaScript garante esse comportamento desde 2019 (ECMAScript 2019).

7. Invertendo: reverse e toReversed

Às vezes você não quer ordenar, só virar a lista de trás para a frente. A dupla é parecida com sort/toSorted: reverse ("inverter") muda o original; toReversed ES2023 devolve uma cópia invertida.

const fila = ["Ana", "Bia", "Caio"];
console.log(fila.toReversed());
console.log(fila);
fila.reverse();
console.log(fila);

$ node reverse.js
[ 'Caio', 'Bia', 'Ana' ]
[ 'Ana', 'Bia', 'Caio' ]
[ 'Caio', 'Bia', 'Ana' ]

Depois do toReversed(), a fila continuou igual; depois do reverse(), ela mudou de verdade. Atenção: reverse não ordena nada. Para "do maior para o menor", use b - a na comparação.

Quando dá errado

Números sem função de comparação

O erro mais comum de todos, e o Node não avisa nada. Você já viu na seção 2: [10, 9, 100, 1, 25].sort() dá [ 1, 10, 100, 25, 9 ]. Como consertar: sort((a, b) => a - b). Para números, nunca use o sort() vazio.

A função devolve true/false em vez de um número

Parece lógico escrever "a é maior que b?":

const numeros = [5, 1, 4, 2, 3, 9, 7, 8, 6, 0, 11, 10];
numeros.sort((a, b) => a > b);
console.log(numeros);

$ node booleano.js
[
   5,  1, 4, 2, 3,
   9,  7, 8, 6, 0,
  11, 10
]

Nada mudou de lugar. (O Node mostrou o array em colunas porque ele tem muitos números; é só a forma de exibir.) O a > b devolve true ou false, que o sort entende como 1 ou 0: ele nunca recebe um número negativo, então nunca sabe quando um item deve ir para a frente. Com listas pequenas às vezes "parece" funcionar, o que torna o erro ainda mais traiçoeiro. Como consertar: devolva um número: (a, b) => a - b.

a - b com textos 
const nomes = ["Caio", "Ana", "Bia"];
nomes.sort((a, b) => a - b);
console.log(nomes);

$ node textomenos.js
[ 'Caio', 'Ana', 'Bia' ]

De novo, nada mudou. "Caio" - "Ana" dá NaN ("não é um número", aula NaN e Infinity), e o sort trata o NaN como empate. Como consertar: para textos, (a, b) => a.localeCompare(b).

O original mudou sem querer

Sem erro nenhum na tela: você escreveu const ordenada = lista.sort() achando que tinha feito uma cópia, e mais adiante descobre que a lista também está ordenada (a seção 1 mostrou o true de ordenada === chamada). Como consertar: use toSorted quando a ordem original ainda for necessária.

Resumo

  • sort() ordena o próprio array (e devolve o mesmo array). toSorted() ES2023 devolve uma cópia ordenada e deixa o original intacto.
  • Sem função de comparação, tudo é comparado como texto: [10, 9, 100, 1, 25].sort() dá [ 1, 10, 100, 25, 9 ].
  • A função de comparação recebe dois itens e devolve um número: negativo = a antes; positivo = b antes; 0 = mantém a ordem. Números: a - b (crescente) e b - a (decrescente).
  • Textos para pessoas: (a, b) => a.localeCompare(b), que acerta acentos e maiúsculas.
  • Objetos: compare o campo que interessa (a.preco - b.preco). Nos empates, a ordem original é mantida (ordenação estável).
  • reverse() inverte o próprio array; toReversed() devolve uma cópia invertida. Nenhum dos dois ordena.
