JavaScript: Lendo uma Mensagem de Erro

Todo mundo que programa erra, todo dia: quem começou ontem e quem programa há 20 anos. A diferença é que quem tem experiência lê a mensagem de erro e, quase sempre, descobre o problema em segundos. Aquele bloco de texto que o Node mostra quando algo dá errado parece assustador, mas ele não é uma bronca: é um bilhete com o endereço do problema. Nesta aula você aprende a ler esse bilhete, linha por linha.

Você vai aprender
  • As partes de uma mensagem de erro do Node: o arquivo e a linha, a linha do código, o ^, o tipo e a mensagem, as linhas at … e a versão do Node.
  • O que acontece com o programa quando dá erro: o que já rodou, o que não roda mais, e o código de saída 1.
  • Como ler a pilha de chamadas (as linhas at …) quando o erro acontece dentro de uma função, e quais linhas ignorar.
  • Os erros de sintaxe, que impedem o programa de começar, e por que às vezes eles apontam a linha "errada".
  • As mensagens mais comuns, traduzidas.
  • Uma receita para ler qualquer erro.

Todas as mensagens desta aula saíram do Node.js 24 da máquina da Ana (usuária ana, computador notebook), com os programas salvos na pasta pessoal dela, /home/ana. As mensagens do Node são sempre em inglês; aqui cada uma ganha a tradução.

A ideia: o bilhete da professora

Quando a professora devolve uma redação corrigida, ela não escreve só "está errado". Ela marca onde (a página e a linha), sublinha a palavra e escreve na margem o que está errado ("concordância", "falta vírgula"). Com essas três informações, você conserta rápido.

A mensagem de erro do Node é esse bilhete:

  • onde: o arquivo e o número da linha;
  • o sublinhado: a linha do código copiada, com um ^ embaixo do ponto exato;
  • o quê: o tipo do erro e uma frase curta explicando.

Tem mais algumas linhas, que explicam o caminho até lá. Vamos a elas.

E o Tchau! da linha 4? Não apareceu. Quando acontece um erro que ninguém trata, o Node para o programa ali mesmo: o que vem depois não roda. (Na aula try … catch você aprende a tratar erros para o programa continuar.)

Leia de baixo para cima? Não: leia nesta ordem

1) a linha TipoDeErro: mensagem (o quê); 2) a primeira linha, com o arquivo e o número (onde); 3) a linha do código com o ^ (o ponto exato). Só depois, se precisar, as linhas at.

Missão: rode o programa, leia a mensagem de erro (repare em qual linha ela aponta) e conserte, até aparecer Olá, Ana! e Tchau!.

const nome = "Ana";
console.log("Bom dia!");

A caixa "Experimente" imita o Node: um erro não tratado aparece no mesmo formato, com o tipo e a mensagem. Os detalhes de como ela mostra o caminho e as linhas at estão em O Editor do Guia.

2. O programa termina "com erro": o código de saída

Todo programa, ao terminar, entrega ao terminal um número chamado código de saída: 0 quer dizer "terminei bem"; qualquer outro número quer dizer "deu problema". O terminal guarda o último código em $?, e o comando echo $? mostra:

$ node saudacao.js
Bom dia!
/home/ana/saudacao.js:3
console.log(`Olá, ${nomee}!`);
                    ^

ReferenceError: nomee is not defined
    at Object.<anonymous> (/home/ana/saudacao.js:3:21)
«                                  (mais 7 linhas "at" internas, cortadas aqui)

Node.js v24.22.0
$ echo $?
1

Com um erro não tratado, o Node termina com o código 1. Para você, que está olhando a tela, tanto faz; mas outros programas (um script que roda vários programas em sequência, um robô que testa o seu código) usam esse número para saber se deu certo. A aula process.env e process.exit mostra como escolher o código de saída.

3. Erro dentro de uma função: a pilha de chamadas

Quando o erro acontece dentro de uma função, as linhas at ficam mais interessantes. A Ana escreveu uma função que calcula a média, usando outra que soma:

function somar(notas) {
  let total = 0;
  for (const nota of notas) {
    total += nota;
  }
  return total;
}

function media(notas) {
  return somar(notas) / notas.length;
}

console.log(media([8, 9, 10]));
console.log(media());

Essa lista se chama pilha de chamadas (em inglês, stack trace, "rastro da pilha"): como uma pilha de pratos, a função chamada por último fica no topo. 4. Erros de sintaxe: o programa nem começa

Até aqui, os erros aconteceram no meio do programa: as primeiras linhas rodaram. Um erro de sintaxe é diferente. Sintaxe é a "gramática" da linguagem (veja Instruções, Ponto e Vírgula e Blocos). Antes de rodar a primeira linha, o Node lê o arquivo inteiro para entender o que está escrito. Se encontra um erro de gramática, ele desiste antes de começar:

console.log("Começou");
const preco = 4.5;
console.log("Preço:", preco;
console.log("Fim");

$ node parenteses.js
/home/ana/parenteses.js:3
console.log("Preço:", preco;
                      ^^^^^

SyntaxError: missing ) after argument list
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)
    at Module._compile (node:internal/modules/cjs/loader:1903:20)
«                                  (mais 6 linhas "at" internas, cortadas aqui)

Node.js v24.22.0

Repare nas diferenças:

  • O Começou da linha 1 não apareceu, mesmo estando certo: com erro de sintaxe, nenhuma linha roda.
  • O tipo é SyntaxError, "erro de sintaxe". A mensagem: "falta ) depois da lista de argumentos". Faltou fechar o parêntese do console.log.
  • Em vez de um ^, vieram vários: ^^^^^ sublinha a palavra preco inteira, onde o Node esperava encontrar o ) logo depois.
  • As linhas at são todas do Node (wrapSafe é ele "lendo" o arquivo). Nenhuma aponta para o seu arquivo, porque o seu código nem começou a rodar. O número que importa está na primeira linha: parenteses.js:3.

Quando o erro aponta a linha "errada"

O Node aponta onde ele percebeu o problema, e isso às vezes fica depois de onde você errou. A Ana esqueceu de fechar a chave do if:

const idade = 20;
if (idade >= 18) {
  console.log("Pode votar");

$ node chave.js
/home/ana/chave.js:4



SyntaxError: Unexpected end of input
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)
«                                  (mais 7 linhas "at" internas, cortadas aqui)

Node.js v24.22.0

"Fim inesperado da entrada": o arquivo acabou enquanto o Node ainda esperava o }. Ele aponta a linha 4, que nem tem nada escrito (por isso a linha do código e a do ^ saíram em branco). O erro de verdade é a chave que faltou, que deveria fechar o bloco da linha 2. Regra prática: se a linha apontada parece certa, olhe as linhas de cima.

Outro exemplo, as aspas que não fecham:

const cidade = "São Paulo;
console.log(cidade);

$ node aspas.js

               ^^^^^^^^^^^

"Token inválido ou inesperado". Token é cada "pedaço" do código: um nome, um número, um texto, um sinal. O ^^^^^^^^^^^ sublinha o texto que abriu aspas e nunca fechou. Como consertar: "São Paulo";.

7. A mensagem vai para a "saída de erros"

Um programa tem duas saídas para o terminal: a saída padrão (o console.log) e a saída de erros (o console.error e as mensagens de erro; veja console.error, warn e table). Na tela, as duas aparecem misturadas. Mas o terminal consegue separá-las: o 2> manda a saída de erros para um arquivo.

console.log("Linha 1 rodou");
console.log("Linha 2 rodou");
console.log(semNome);
console.log("Linha 4 rodou?");

$ node cedo.js 2> erro.txt

$ cat erro.txt

            ^

    at Object.<anonymous> (/home/ana/cedo.js:3:13)
«                                  (mais 7 linhas "at" internas, cortadas aqui)

Na tela ficou só a saída normal; a mensagem de erro inteira foi para o arquivo erro.txt (o cat mostra o que tem nele). Isso é útil para guardar o erro e mandar para alguém, e mostra que a mensagem de erro é uma coisa à parte, que não se mistura com os resultados do programa.

Receita: como ler qualquer erro

  1. Não entre em pânico com o tamanho. Das 10 ou 15 linhas, só 3 ou 4 importam.
  2. Leia a linha Tipo: mensagem e traduza. A tabela da seção 5 cobre a maioria dos casos.
  3. Olhe a primeira linha: o arquivo e o número da linha. Abra o arquivo nessa linha.
  4. Olhe o ^: ele está embaixo do ponto exato.
  5. Se a linha parece certa, olhe as linhas de cima (erro de sintaxe) ou desça na pilha de chamadas (as linhas at com o seu arquivo) até achar onde o valor errado entrou.
  6. Conserte uma coisa e rode de novo. O Node mostra um erro por vez; depois de consertar o primeiro, pode aparecer o próximo. Isso é progresso, não fracasso.
  7. Ainda não entendeu? Copie a linha Tipo: mensagem (sem os nomes que são só seus, como nomee) e pesquise na internet. Milhões de pessoas já viram a mesma mensagem.

Quando dá errado (lendo o erro)

Consertou a linha apontada, mas o erro estava antes

No chave.js (seção 4), o Node apontou a linha 4, que não existe no seu código. Quem tenta "consertar a linha 4" não acha nada para consertar. Lembre: num SyntaxError, o número é onde o Node percebeu, não onde você errou. Com Unexpected end of input, procure o {, ( ou [ que ficou aberto mais acima.

Leu só as linhas at internas

Quem lê at Module._compile (node:internal/modules/cjs/loader:1929:14) acha que o problema é no Node. Quase nunca é: essas linhas aparecem em todo erro, mesmo no mais simples. A linha que interessa tem o caminho do seu arquivo.

Nenhuma mensagem, mas o resultado está errado

Às vezes o programa roda até o fim, sem erro nenhum, e mostra NaN, undefined ou um número que não faz sentido. Isso é um erro de lógica: para o Node, está tudo certo, então ele não tem o que avisar. Para esses, a ferramenta é a depuração: espalhar console.log para ver os valores no meio do caminho, ou usar o depurador. É o assunto da aula Depurando.

Resumo

  • A mensagem de erro é um bilhete: onde (arquivo:linha), o trecho (a linha do código com ^) e o quê (Tipo: mensagem).
  • Comece pela linha Tipo: mensagem, depois o número da linha, depois o ^.
  • Um erro não tratado para o programa ali: as linhas anteriores rodaram, as seguintes não. O código de saída é 1.
  • As linhas at são a pilha de chamadas, da função onde estourou até o programa principal. Procure as que têm o seu arquivo; ignore node:internal.
  • Um SyntaxError impede o programa de começar, e às vezes aponta uma linha depois do erro de verdade: olhe para cima.
  • A mensagem vai para a saída de erros (2> separa). A última linha diz a versão do Node.
  • Programa que roda sem erro mas dá resultado errado é erro de lógica: veja Depurando.
