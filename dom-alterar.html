JavaScript Mudando Textos e Atributos

Você já sabe encontrar um elemento na página. Agora vem a parte que faz a página "ganhar vida": mudar o que ele mostra. Nesta aula, a Ana atualiza a página da padaria pelo JavaScript: troca o horário, a foto, o link do WhatsApp, lê o que o cliente digitou. São duas famílias de mudança: o texto de dentro do elemento e os atributos da tag (src, href, alt, value…).

Você vai aprender
  • Ler e trocar o texto de um elemento com textContent.
  • A diferença entre textContent, innerText e innerHTML, e por que o innerHTML é perigoso com texto digitado pelo usuário.
  • Os quatro métodos de atributo: getAttribute, setAttribute, removeAttribute e hasAttribute.
  • O atalho das propriedades: img.src, a.href, input.value, checkbox.checked, botao.disabled.
  • Os atributos data- e o dataset.
  • Os erros reais: o texto com tags que aparece cru, o src que vira endereço completo, o value que não muda no atributo.

As respostas do Console desta aula foram colhidas no Chromium da máquina da Ana, com a página abaixo aberta (com dois cliques, de /home/ana/placa/index.html). As classes e o estilo ficam para a próxima aula, Mudando o Estilo.

A ideia: a placa da padaria

A fachada da padaria tem uma placa de letras móveis, daquelas em que se trocam as letras do horário. Mudar o texto é trocar as letras da placa. Mas a placa também tem características: o tamanho, a foto pendurada ao lado, o número de telefone. No HTML, essas características são os atributos: o que vem dentro da tag de abertura, como src="pao.jpg" ou href="…". O JavaScript pode trocar as duas coisas.

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="utf-8">
  <title>Padaria da Ana</title>
</head>
<body>
  <h1 id="titulo">Padaria da Ana</h1>
  <p id="horario">Aberto das <strong>6h</strong> às 20h</p>
  <img id="foto" src="pao.jpg" alt="Pão francês">
  <a id="whats" href="https://wa.me/5511999999999">Fale conosco</a>
  <p id="produto" data-preco="4.50" data-estoque="12">Pão de queijo</p>
  <input id="nome" value="Ana">
  <input type="checkbox" id="entrega">
  <button id="enviar">Enviar</button>
</body>
</html>

1. textContent: o texto de dentro

O textContent ("conteúdo de texto") você já viu: lê todo o texto de dentro do elemento, inclusive o das tags filhas, sem as tags. E aceita um valor novo:

> document.querySelector("#horario").textContent
'Aberto das 6h às 20h'
> document.querySelector("#titulo").textContent = "Padaria e Confeitaria da Ana"
'Padaria e Confeitaria da Ana'

A primeira linha leu o horário: o <strong> sumiu, ficou só o texto. A segunda trocou o título, e a página mudou na hora. Num arquivo script.js, o normal é guardar o elemento numa constante e depois mexer nele:

const titulo = document.querySelector("#titulo");
titulo.textContent = "Padaria e Confeitaria da Ana";
const titulo = document.querySelector("#titulo");
Seleciona o elemento uma vez só e guarda. A constante guarda o elemento (o pedaço da árvore), não o texto: por isso dá para mudar o texto dele depois.
titulo.textContent = "…";
Apaga tudo o que havia dentro do elemento (textos e tags filhas) e põe o texto novo no lugar.

2. innerHTML: o HTML de dentro

E se a Ana quiser o novo horário com o 7h em negrito? Com textContent, não dá:

> document.querySelector("#horario").textContent = "Aberto das <strong>7h</strong> às 19h"
'Aberto das <strong>7h</strong> às 19h'

Na tela apareceu, ao pé da letra, Aberto das <strong>7h</strong> às 19h, com os sinais de menor e maior. O textContent trata tudo como texto: no DOM, o parágrafo ficou com Aberto das &lt;strong&gt;7h… (o &lt; é o jeito do HTML escrever um < que não abre tag). Para o navegador interpretar as tags, use innerHTML ("HTML de dentro"):

> document.querySelector("#horario").innerHTML = "Aberto das <strong>7h</strong> às 19h"
'Aberto das <strong>7h</strong> às 19h'

Agora o 7h aparece em negrito: o parágrafo ganhou um elemento <strong> de verdade. E, para ler, o innerHTML devolve o HTML com as tags (com a página recém-aberta):

> document.querySelector("#horario").innerHTML
'Aberto das <strong>6h</strong> às 20h'
Nunca ponha no innerHTML um texto que o usuário digitou

A Ana fez um mural de recados: o cliente digita num campo, clica em Publicar, e o script faz mural.innerHTML = texto. Um cliente mal-intencionado digitou isto no campo:

<img src=x onerror="alert(1)">

Ao publicar, o navegador interpretou o texto como HTML: criou uma imagem com endereço x (que não existe), e o onerror ("quando der erro") rodou o JavaScript que o cliente escreveu. No Chromium da Ana, apareceu a janela alert com 1. Aqui foi só um aviso, mas poderia ser um código que rouba os dados de quem está logado. Esse ataque se chama XSS (cross-site scripting, "script entre sites"), e é um dos mais comuns da internet.

Regra: texto que veio de fora (digitado, de um fetch, do endereço da página) vai no textContent, que nunca interpreta tags. Use innerHTML só com HTML que você escreveu.

E o innerText?

Existe um terceiro: o innerText ("texto de dentro"). Ele devolve o texto como aparece na tela, levando o CSS em conta. Com estes dois parágrafos:

<p id="misto">Pão <span style="display: none">(esgotado)</span>francês</p>
<p id="caixa" style="text-transform: uppercase">promoção</p>

> document.querySelector("#misto").textContent
'Pão (esgotado)francês'
> document.querySelector("#misto").innerText
'Pão francês'
> document.querySelector("#caixa").textContent
'promoção'
> document.querySelector("#caixa").innerText
'PROMOÇÃO'

O textContent lê o que está no HTML, inclusive o (esgotado) escondido pelo display: none. O innerText pula o que está escondido e devolve as maiúsculas que o CSS desenhou. Para o navegador calcular isso, o innerText precisa olhar o estilo da página, o que o torna mais lento. No dia a dia, use textContent; o innerText serve quando você quer exatamente o texto que a pessoa está vendo.

PropriedadeLendo, devolveRecebendo um valorQuando usar
textContentTodo o texto do HTML, sem as tagsPõe como texto (as tags aparecem cruas)Quase sempre
innerTextO texto como aparece na tela (sem o escondido, com o CSS)Põe como textoQuando precisa do texto visível
innerHTMLO HTML de dentro, com as tagsInterpreta as tagsHTML escrito por você, nunca texto do usuário

3. Atributos: getAttribute e setAttribute

Os atributos se leem e se mudam com quatro métodos, que funcionam com qualquer atributo:

> document.querySelector("#foto").getAttribute("src")
'pao.jpg'
> document.querySelector("#foto").setAttribute("src", "bolo.jpg")
undefined
> document.querySelector("#whats").hasAttribute("target")
false
> document.querySelector("#whats").setAttribute("target", "_blank")
undefined
> document.querySelector("#whats").removeAttribute("target")
undefined
> document.querySelector("#whats").hasAttribute("target")
false
getAttribute("src")
"Pegar atributo": devolve o valor exatamente como está escrito no HTML: 'pao.jpg'. Se o atributo não existe, devolve null.
setAttribute("src", "bolo.jpg")
"Definir atributo": recebe dois valores, o nome e o valor novo. Se o atributo não existir, ele é criado. A foto passou a ser bolo.jpg, e o navegador tentou carregá-la na hora. (O undefined embaixo é só o que o método devolve: nada.)
hasAttribute("target")
"Tem atributo?": true ou false.
setAttribute("target", "_blank")
Criou o atributo target="_blank", que faz o link abrir numa aba nova. O link ficou assim: <a id="whats" href="https://wa.me/5511999999999" target="_blank">Fale conosco</a>.
removeAttribute("target")
"Remover atributo": apagou o target; o hasAttribute voltou a dar false.

4. O atalho: atributos como propriedades

Os atributos mais comuns também existem como propriedades do elemento, com o mesmo nome. É o jeito mais usado, porque é mais curto:

> document.querySelector("#foto").alt
'Pão francês'
> document.querySelector("#foto").alt = "Bolo de cenoura"
'Bolo de cenoura'
> document.querySelector("#titulo").id
'titulo'

Depois dessas linhas (e do setAttribute da seção 3), a imagem ficou <img id="foto" src="bolo.jpg" alt="Bolo de cenoura">: mudar a propriedade alt mudou o atributo também.

A diferença que pega: src e href

> document.querySelector("#foto").getAttribute("src")
'pao.jpg'
> document.querySelector("#foto").src
'file:///home/ana/placa/pao.jpg'

O getAttribute devolve o que está escrito; a propriedade .src devolve o endereço completo, já resolvido a partir do endereço da página. Com o href dos links acontece o mesmo. Para comparar com o que está no HTML, use getAttribute; para saber o endereço de verdade, use a propriedade.

Atributos de formulário: value, checked, disabled

Aqui está a diferença mais importante entre atributo e propriedade. A Ana leu o campo, clicou nele, digitou Souza no fim, e leu de novo:

> document.querySelector("#nome").value
'Ana'
> document.querySelector("#nome").value
'Ana Souza'
> document.querySelector("#nome").getAttribute("value")
'Ana'

A propriedade value é o que está no campo agora: 'Ana Souza'. O atributo value é só o valor inicial, escrito no HTML, e não muda quando a pessoa digita: continua 'Ana'. Para ler o que o usuário digitou, use sempre .value (a aula Formulários usa isso o tempo todo).

Caixinhas de marcar e botões têm propriedades booleanas (true/false):

> document.querySelector("#entrega").checked
false
> document.querySelector("#entrega").checked
true
> document.querySelector("#enviar").disabled = true
true
> document.querySelector("#enviar").disabled = false
false
.checked
"Marcado": false antes; true depois que a Ana clicou na caixinha. Também dá para marcar pelo código: caixa.checked = true.
.disabled = true
"Desativado": o botão fica cinza e não aceita cliques. No HTML, apareceu o atributo: <button id="enviar" disabled="">Enviar</button>.
.disabled = false
Reativa: o atributo some, e o botão volta a ser <button id="enviar">Enviar</button>.

5. Atributos data- e o dataset

Às vezes você quer guardar uma informação sua num elemento: o preço de um produto, quantos ainda há no estoque. Para isso existem os atributos que começam com data- ("dados"): o HTML deixa você inventar o nome. O JavaScript os lê pelo dataset:

> document.querySelector("#produto").dataset
DOMStringMap {preco: '4.50', estoque: '12'}
> document.querySelector("#produto").dataset.preco
'4.50'
> Number(document.querySelector("#produto").dataset.estoque) - 1
11
> document.querySelector("#produto").dataset.estoque = 11
11
dataset
Um objeto com todos os atributos data- do elemento, sem o data- na frente: data-preco vira dataset.preco. (O DOMStringMap é o nome do tipo desse objeto.)
'4.50' e '12'
Repare nas aspas: os valores são sempre texto. Para fazer conta, converta com Number(…) (veja Conversão).
dataset.estoque = 11
Muda o atributo no HTML: o elemento ficou <p id="produto" data-preco="4.50" data-estoque="11">. O número virou texto de novo.

Um nome com hífen vira camelCase no dataset: data-preco-antigo se lê com dataset.precoAntigo.

Formas diferentes de fazer a mesma coisa

Você quer…Jeito curto (propriedade)Jeito geral (método)
Ler o endereço de uma imagemimg.src (completo)img.getAttribute("src") (como está escrito)
Trocar a imagemimg.src = "bolo.jpg"img.setAttribute("src", "bolo.jpg")
Ler o que foi digitadocampo.value(não use getAttribute("value"): é só o valor inicial)
Desativar um botãobotao.disabled = truebotao.setAttribute("disabled", "")

Um atributo inventado ou raro (aria-label…)—el.setAttribute("aria-label", "…")

Regra prática: para os atributos comuns (id, src, href, alt, value, checked, disabled), use a propriedade. Para os outros, e quando precisa saber o que está escrito no HTML, use os métodos.

Quando dá errado

As tags apareceram cruas na página

Você pôs "Aberto das <strong>7h</strong>" no textContent, e a página mostra os sinais <strong>. O textContent não interpreta tags (seção 2). Como consertar: se o HTML foi escrito por você, use innerHTML; se veio do usuário, deixe no textContent mesmo (é ele que protege a página).

Esqueceu o segundo valor do setAttribute 
> document.querySelector("#foto").setAttribute("src")
Uncaught TypeError: Failed to execute 'setAttribute' on 'Element': 2 arguments required, but only 1 present.
    at <anonymous>:1:33

"Falha ao executar o setAttribute no elemento: 2 argumentos necessários, mas só 1 presente." Como consertar: setAttribute("src", "bolo.jpg"): o nome e o valor.

O atributo que não existe: null × '' 
> document.querySelector("#foto").getAttribute("title")
null
> document.querySelector("#foto").title
''

A imagem não tem title. O getAttribute diz isso com null; a propriedade devolve um texto vazio. Para saber se um atributo existe, use hasAttribute ou compare o getAttribute com null; não confie na propriedade.

.value num elemento que não é de formulário 
> document.querySelector("#titulo").value
undefined

Só campos de formulário (input, textarea, select…) têm value. Num <h1>, dá undefined, e dar um valor a ele não muda nada na tela. Como consertar: para o texto de um elemento comum, use textContent.

O texto do campo "não muda"

A pessoa digitou, mas campo.getAttribute("value") continua dando o valor antigo. Não é defeito: o atributo é o valor inicial (seção 4). Como consertar: leia campo.value.

Mudou um elemento que não foi achado

Uncaught TypeError: Cannot set properties of null (setting 'textContent'): o querySelector devolveu null. Confira o seletor (#, ponto) e a posição do <script> (veja Selecionando Elementos e JavaScript na Página).

Resumo

  • textContent lê e troca o texto de um elemento, sem interpretar tags. É o padrão.
  • innerHTML lê e troca o HTML de dentro, interpretando as tags. Nunca o use com texto que veio do usuário (XSS).
  • innerText é o texto como aparece na tela (sem o que está escondido, com o CSS aplicado).
  • Atributos: getAttribute, setAttribute(nome, valor), removeAttribute, hasAttribute; os comuns também são propriedades (src, href, alt, id).
  • Em formulários, a propriedade é o estado atual: value (o que foi digitado), checked, disabled. O atributo value é só o valor inicial.
  • Atributos data- guardam dados seus e se leem com el.dataset, sempre como texto.
