JavaScript return

Com parâmetros, você manda informações para dentro da função. Com return (em inglês, "devolver"), a função manda um resultado de volta para fora, para quem a chamou. É isso que permite guardar o resultado numa variável, usar numa conta, comparar num if ou mandar para outra função.

Você vai aprender
  • Como uma função devolve um valor com return, e como usar esse valor.
  • A diferença entre mostrar (console.log) e devolver (return).
  • Que o return encerra a função na hora, e como usar vários return.
  • Funções que devolvem true ou false.
  • Por que uma função sem return devolve undefined.
  • As armadilhas reais: o return sozinho na linha, o NaN e o return fora de função.

Todos os programas desta aula rodaram no Node.js 24 (v24.22.0) da máquina da Ana, com node arquivo.js. Você pode rodar cada um no editor do guia.

A ideia: perguntar o preço no caixa

A Ana pergunta à moça do caixa: "quanto dão 10 pães a R$ 0,50?". A moça faz a conta e responde: "5 reais". A Ana guarda a resposta na cabeça e decide o que fazer com ela: pagar, somar com o café, desistir.

Agora imagine que a moça, em vez de responder, escrevesse "5 reais" num papel e o pendurasse na parede. A Ana pode ler, mas a resposta não chegou a ela: não dá para somar com o café de cabeça. É a diferença entre:

  • console.log: mostra na tela, para uma pessoa ler;
  • return: devolve o valor para o programa, que pode continuar usando.

1. O primeiro return

function calcularTotal(quantidade, preco) {
  return quantidade * preco;
}

const total = calcularTotal(10, 0.5);
console.log(`10 pães custam R$ ${total}`);

$ node total.js
10 pães custam R$ 5
return quantidade * preco;
"Devolva o resultado de quantidade * preco". O JavaScript calcula a conta (10 × 0,5 = 5) e manda o 5 de volta para o lugar da chamada.
calcularTotal(10, 0.5)
A chamada. Depois que a função devolve, é como se a chamada inteira virasse o valor devolvido: aqui, 5.
const total = …
Guarda o valor devolvido numa variável, para usar depois. A função não mostrou nada: quem mostra é o console.log da última linha.

Mostrar × devolver

Compare duas funções que parecem fazer a mesma coisa:

function mostrarDobro(numero) {
  console.log(numero * 2);
}

function calcularDobro(numero) {
  return numero * 2;
}

const a = mostrarDobro(5);
const b = calcularDobro(5);
console.log(`a vale ${a}`);
console.log(`b vale ${b}`);
console.log(`a + 1 = ${a + 1}`);
console.log(`b + 1 = ${b + 1}`);

$ node mostra.js
10
a vale undefined
b vale 10
a + 1 = NaN
b + 1 = 11
  • mostrarDobro(5) mostrou 10 na tela (a primeira linha da saída), mas não devolveu nada. Por isso a ficou undefined, e undefined + 1 dá NaN ("não é um número"; veja NaN e Infinity).
  • calcularDobro(5) não mostrou nada, mas devolveu 10: b vale 10, e b + 1 dá 11.

No modo interativo do Node (O Modo Interativo) dá para ver isso direto, porque o > mostra o valor que cada linha produz:

Em dobro(21), o 42 é o valor devolvido. Em mostrarDobro(21), o 42 é o que o console.log escreveu, e o undefined logo abaixo é o valor devolvido: nenhum. (É por isso que o console.log("oi") no > também mostra um undefined: o próprio console.log não devolve nada.)

Regra de bolso

Uma função que calcula algo deve devolver (return), e quem chamou decide se mostra, soma ou guarda. Deixe o console.log para as funções cujo trabalho é justamente mostrar.

Missão: o programa mostra Troco: R$ undefined, porque a função mostra o troco em vez de devolver. Troque o console.log de dentro da função por um return, para a última linha mostrar Troco: R$ 7.5.

function calcularTroco(pago, total) {
  console.log(pago - total);
}

const troco = calcularTroco(20, 12.5);
console.log(`Troco: R$ ${troco}`);

function calcularTroco(pago, total) {
  return pago - total;
}

const troco = calcularTroco(20, 12.5);
console.log(`Troco: R$ ${troco}`);

2. O valor devolvido serve em qualquer lugar

Como a chamada "vira" o valor, ela pode ir onde um valor iria: dentro do console.log, numa conta, num template, num if:

function calcularTotal(quantidade, preco) {
  return quantidade * preco;
}

console.log(calcularTotal(2, 4.5));
const compra = calcularTotal(10, 0.5) + calcularTotal(2, 4.5);
console.log(`Compra toda: R$ ${compra}`);
console.log(`Com desconto: R$ ${calcularTotal(10, 0.5) - 1}`);
if (calcularTotal(3, 18) > 50) {
  console.log("Três bolos passam de R$ 50!");
}

$ node usos.js
9
Compra toda: R$ 14
Com desconto: R$ 4
Três bolos passam de R$ 50!

Na linha do compra, a função foi chamada duas vezes: a primeira virou 5, a segunda virou 9, e 5 + 9 = 14.

Uma função recebendo o resultado de outra

O valor devolvido por uma função pode ser o argumento de outra. O JavaScript resolve de dentro para fora:

function calcularTotal(quantidade, preco) {
  return quantidade * preco;
}

function aplicarDesconto(valor) {
  return valor * 0.9;
}

const final = aplicarDesconto(calcularTotal(10, 2));
console.log(`Com 10% de desconto: R$ ${final}`);

$ node encadeia.js
Com 10% de desconto: R$ 18

Primeiro calcularTotal(10, 2) virou 20; depois aplicarDesconto(20) virou 18.

3. O return encerra a função

Quando o JavaScript chega num return, ele sai da função na hora, levando o valor. O que estiver depois, dentro da função, não roda:

function calcularTotal(quantidade, preco) {
  return quantidade * preco;
  console.log("Esta linha nunca aparece");
}

console.log(calcularTotal(4, 2));

$ node depois.js
8

Vários return: um para cada caso

Isso permite ter vários return, cada um dentro de um if. O primeiro que for alcançado decide a resposta:

function classificar(nota) {
  if (nota >= 7) {
    return "Aprovada";
  }
  if (nota >= 5) {
    return "Recuperação";
  }
  return "Reprovada";
}

console.log(`Nota 8.5: ${classificar(8.5)}`);
console.log(`Nota 6: ${classificar(6)}`);
console.log(`Nota 3: ${classificar(3)}`);

$ node nota.js
Nota 8.5: Aprovada
Nota 6: Recuperação
Nota 3: Reprovada

Com a nota 8.5, o primeiro if devolve "Aprovada" e a função acaba ali: o segundo if nem é olhado. Por isso não precisou de else: se o programa passou do primeiro if, é porque a nota é menor que 7. O último return, sem if, é o "em todos os outros casos".

O return também sai do laço

Um return dentro de um laço encerra o laço e a função. É o jeito mais comum de "procurar e parar quando achar" (lembra do rótulo para sair de dois laços? Dentro de uma função, um return resolve):

function posicaoDe(lista, procurado) {
  for (let i = 0; i < lista.length; i++) {
    if (lista[i] === procurado) {
      return i;
    }
  }
  return -1;
}

const compras = ["pão", "leite", "café"];
console.log(posicaoDe(compras, "leite"));
console.log(posicaoDe(compras, "ovos"));

$ node procura.js
1
-1

Achou o "leite" na posição 1: return 1, e o laço nem chega ao café. Os "ovos" não estão na lista: o laço termina sem achar, e o return -1 do fim avisa "não achei" (−1 é uma posição que não existe; o próprio JavaScript usa essa convenção, como você vai ver em Procurando em Arrays).

Missão: acrescente um caso novo na função: nota 9 ou mais devolve "Excelente". Cuidado com a ordem dos if: o primeiro return alcançado ganha.

4. Funções que respondem sim ou não

Uma comparação já produz true ou false (veja Booleanos), e uma função pode devolver esse resultado direto. Funções assim costumam ter nomes que soam como pergunta: ehPar, estaVazio, podeEntrar.

function ehPar(numero) {
  return numero % 2 === 0;
}

console.log(ehPar(4));
console.log(ehPar(7));
if (ehPar(10)) {
  console.log("10 é par");
}

$ node par.js
true
false
10 é par

O if (ehPar(10)) se lê quase em português: "se é par 10…". Não precisa escrever if (ehPar(10) === true).

5. Sem return, a função devolve undefined

Toda chamada de função produz um valor. Se a função termina sem passar por um return, ou passa por um return; sem nada, esse valor é undefined. O return; sozinho é útil para sair mais cedo de uma função que não precisa devolver nada:

function avisar(estoque) {
  if (estoque === 0) {
    console.log("Sem estoque!");
    return;
  }
  console.log(`Ainda temos ${estoque}.`);
}

avisar(0);
avisar(12);
console.log(avisar(5));

$ node vazio.js
Sem estoque!
Ainda temos 12.
Ainda temos 5.
undefined

Com estoque 0, o return; encerrou a função antes do segundo console.log. E a última linha mostra o que avisar(5) devolveu: undefined, porque ela não tem return com valor.

Formas diferentes de fazer a mesma coisa

A classificação da nota pode ser escrita de outros jeitos. Com if … else if … else e uma variável, e um return só no fim:

function classificar(nota) {
  let resultado;
  if (nota >= 7) {
    resultado = "Aprovada";
  } else if (nota >= 5) {
    resultado = "Recuperação";
  } else {
    resultado = "Reprovada";
  }
  return resultado;
}

Com o operador ternário (? :), quando os casos são poucos:

function classificar(nota) {
  return nota >= 7 ? "Aprovada" : "Recuperação";
}

E com uma arrow function de uma linha, em que o return fica implícito: const dobro = (n) => n * 2; devolve n * 2 sem escrever return (aula Arrow Functions).

Quando dá errado

O return sozinho na linha 
function calcularTotal(quantidade, preco) {
  return
    quantidade * preco;
}

console.log(calcularTotal(10, 0.5));

$ node quebra.js
undefined

Esta é uma das pegadinhas mais famosas do JavaScript. Quando a linha acaba logo depois do return, o JavaScript entende que ela acabou ali e põe um ponto e vírgula sozinho: return;. A função devolve undefined, e a conta da linha seguinte nunca roda. Não aparece erro nenhum. Como consertar: o valor (ou pelo menos o começo dele) tem de estar na mesma linha do return: return quantidade * preco;. Se a conta for comprida, abra um parêntese na mesma linha: return ( … );.

Esqueceu o return: undefined e NaN 
function calcularTotal(quantidade, preco) {
  quantidade * preco;
}

const total = calcularTotal(10, 0.5);
console.log(`Total: ${total}`);
console.log(`Total + taxa: ${total + 2}`);

$ node semreturn.js
Total: undefined
Total + taxa: NaN

A função faz a conta e joga o resultado fora. Sem return, a chamada vale undefined, e qualquer conta com undefined dá NaN. Se você vir undefined ou NaN onde esperava um resultado, a primeira suspeita é um return esquecido (ou um console.log no lugar dele). Como consertar: return quantidade * preco;.

Código depois do return

É o depois.js da seção 3: a linha depois do return nunca roda, sem erro nenhum. Se você quer mostrar algo e devolver, mostre antes do return.

Esqueceu os parênteses na chamada 
function calcularTotal(quantidade, preco) {
  return quantidade * preco;
}

const total = calcularTotal;
console.log(total);

$ node semparen.js
[Function: calcularTotal]

Sem os parênteses, a função não foi chamada: total recebeu a própria função, e não o resultado dela. Como consertar: calcularTotal(10, 0.5).

return fora de uma função

O return é para sair de uma função. Fora de uma, o resultado depende de como o arquivo é lido. Num módulo (arquivo .mjs, ou com import/export; veja Módulos), e também no navegador, é erro de sintaxe:

console.log("Antes");
return;
console.log("Depois");

$ node topo.mjs
file:///home/ana/topo.mjs:2
return;
^^^^^^

SyntaxError: Illegal return statement
    at compileSourceTextModule (node:internal/modules/esm/utils:319:16)   « mais 9 linhas "at … node:internal" cortadas

Node.js v24.22.0

"Instrução return ilegal". Repare que, num módulo, o caminho aparece como endereço (file:///home/ana/…). Já num arquivo .js comum, o Node não reclama: ele embrulha o arquivo inteiro numa função por baixo dos panos, e o return simplesmente encerra o programa. A Ana salvou as mesmas três linhas como topo.js:

$ node topo.js
Antes

Como consertar: não use return fora de função. Para encerrar o programa de propósito, existe o process.exit() (veja process.env e process.exit).

Missão: complete a função calcularMedia para devolver a média das três notas (some as três e divida por 3; use parênteses na soma). O resto do programa já usa o resultado.

function calcularMedia(n1, n2, n3) {
  // devolva a média aqui
}

const media = calcularMedia(7, 8, 9);
console.log(`Média: ${media}`);
if (media >= 7) {
  console.log("Aprovada!");
}

function calcularMedia(n1, n2, n3) {
  return (n1 + n2 + n3) / 3;
}

const media = calcularMedia(7, 8, 9);
console.log(`Média: ${media}`);
if (media >= 7) {
  console.log("Aprovada!");
}

No lab, a solução mostrou Média: 8 e Aprovada!. Sem os parênteses, n1 + n2 + n3 / 3 daria 18 (só o 9 seria dividido; veja Precedência).

Resumo

  • return valor; encerra a função e devolve o valor; a chamada "vira" esse valor.
  • console.log mostra para a pessoa; return devolve para o programa. Funções que calculam devem devolver.
  • O valor devolvido pode ir para uma variável, uma conta, um if ou outra função.
  • O primeiro return alcançado encerra tudo, inclusive laços: dá para ter vários, um por caso.
  • Sem return (ou com return;), a função devolve undefined, e contas com ele dão NaN.
  • Nunca deixe o return sozinho na linha: o valor tem de começar na mesma linha.
