JavaScript O Modo Estrito

O JavaScript nasceu em 1995, feito às pressas, e com o tempo ficou claro que algumas coisas dele eram tolerantes demais: um erro de digitação num nome de variável não dava erro nenhum, apenas criava uma variável nova, em silêncio. Para não quebrar os sites antigos, essas regras não podiam simplesmente mudar. A solução, de 2009, foi um interruptor: uma linha, "use strict", que liga o modo estrito, uma versão mais exigente da linguagem, que transforma vários desses silêncios em erros de verdade.

Você vai aprender
  • Como ligar o modo estrito: "use strict"; no começo do arquivo ou de uma função.
  • O que muda: a variável não declarada, a propriedade que não pode ser alterada, o this das funções e mais algumas regras.
  • Por que o modo estrito ajuda: ele mostra o erro na hora, em vez de deixar o programa dar um resultado errado.
  • Onde ele já vem ligado sozinho: módulos (import/export) e classes.
  • Os erros reais que só aparecem no modo estrito.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana, com node arquivo.js. O modo estrito funciona igual no navegador.

A ideia: o professor que corrige a lápis e o que corrige a caneta

A Ana teve dois professores de matemática. O primeiro era bonzinho: quando ela escrevia uma conta errada, ele fingia que não via, e ela só descobria na nota final, sem saber onde tinha errado. O segundo marcava em vermelho, na hora, a linha exata do erro. Na época, o segundo parecia chato. Mas era com ele que ela aprendia, porque cada erro aparecia logo, no lugar certo.

O JavaScript "normal" (os programadores chamam de modo desleixado, sloppy mode) é o professor bonzinho. O modo estrito é o da caneta vermelha.

1. O erro de digitação que vira variável

A Ana soma as compras da padaria. Ela digitou totl no lugar de total dentro do laço. Sem modo estrito:

let total = 0;
const precos = [4.5, 12.9, 3.25];
for (const preco of precos) {
  totl = total + preco;
}
console.log(`Total: ${total}`);
console.log(`E o totl? ${totl}`);

$ node sem-strict.js
Total: 0
E o totl? 3.25

Nenhum erro. O programa rodou até o fim e disse que a compra deu zero. O que aconteceu: no modo desleixado, atribuir um valor a um nome que não existe (totl = …) cria uma variável global nova com esse nome. A cada volta, o totl recebeu 0 + preco, e o total de verdade nunca mudou. Num programa grande, um erro desses pode levar horas para ser achado. Agora com "use strict" na primeira linha:

let total = 0;
const precos = [4.5, 12.9, 3.25];
for (const preco of precos) {
  totl = total + preco;
}
console.log(`Total: ${total}`);

2. Onde pôr o "use strict"

Ele só funciona como a primeira instrução do arquivo (comentários e linhas em branco antes podem) ou como a primeira instrução dentro de uma função, e aí vale só para aquela função:

function contar() {
  "use strict";
  contador = 1;
}
valor = 5;
console.log("fora da função, sem strict:", valor);
contar();

$ node funcao.js
fora da função, sem strict: 5
/home/ana/funcao.js:3
  contador = 1;
           ^

ReferenceError: contador is not defined
    at contar (/home/ana/funcao.js:3:12)
    at Object.<anonymous> (/home/ana/funcao.js:7:1)  « mais linhas cortadas

Node.js v24.22.0

Fora da função, o valor = 5 passou (modo desleixado). Dentro da contar, o contador = 1 deu erro (modo estrito). O at contar mostra que o erro foi dentro da função contar, chamada da linha 7.

Fora do lugar, ele é ignorado

Se o "use strict" vier depois de qualquer outra instrução, ele vira só uma string sem efeito, e o JavaScript não avisa nada:

console.log("começando");
"use strict";
nome = "Ana";
console.log(nome);

$ node tarde.js
começando
Ana

O nome = "Ana" passou sem erro: o modo estrito não foi ligado. Também não funciona com crase nem com letra diferente (`use strict`, "Use Strict"); aspas duplas ou simples, sim.

3. O que mais muda no modo estrito

Alterar o que não pode ser alterado dá erro

Um objeto congelado com Object.freeze (veja Imutabilidade) não aceita mudanças. No modo desleixado, a tentativa é ignorada em silêncio:

const loja = Object.freeze({ nome: "Padaria da Ana" });
loja.nome = "Outra padaria";
console.log(loja.nome);

$ node congelado.js
Padaria da Ana

A linha 2 "rodou", mas não fez nada, e ninguém ficou sabendo. Com "use strict" no começo do mesmo arquivo:

$ node congelado2.js
/home/ana/congelado2.js:3
loja.nome = "Outra padaria";
          ^

TypeError: Cannot assign to read only property 'nome' of object '#<Object>'
    at Object.<anonymous> (/home/ana/congelado2.js:3:11)  « mais linhas cortadas

Node.js v24.22.0

"Não dá para atribuir à propriedade somente-leitura 'nome' do objeto". O '#<Object>' é o jeito do motor dizer "um objeto comum". Agora a tentativa de mudar o que não pode é um erro visível.

O this de uma função comum vira undefined

Numa função chamada sozinha (sem objeto. na frente), o this do modo desleixado é o objeto global inteiro (o globalThis); no estrito, é undefined (veja this, call, apply e bind):

function semStrict() {
  return typeof this;
}
function comStrict() {
  "use strict";
  return typeof this;
}
console.log(semStrict());
console.log(comStrict());

$ node this.js
object
undefined

Parece pior, mas é melhor: com this igual ao objeto global, um this.nome = "Ana" esquecido numa função criaria uma variável global sem ninguém perceber. Com undefined, dá erro na hora.

4. Onde o modo estrito já vem ligado

No JavaScript moderno, você raramente precisa escrever "use strict", porque ele já vem ligado em dois lugares:

  • Dentro de classes. Todo o corpo de uma class é estrito.
  • Em módulos (import e export): arquivos .mjs, arquivos de um projeto com "type": "module" no package.json, e o <script type="module"> do navegador.
nome = "Ana";
console.log(nome);

$ node modulo.mjs
file:///home/ana/modulo.mjs:1
nome = "Ana";
     ^

ReferenceError: nome is not defined
    at file:///home/ana/modulo.mjs:1:6
    at ModuleJob.run (node:internal/modules/esm/module_job:561:25)  « mais linhas cortadas

Node.js v24.22.0

Sem "use strict" nenhum, o erro apareceu: o arquivo .mjs é um módulo. Repare que, em módulos, o Node mostra o caminho como endereço (file:///home/ana/…). E tem um detalhe do Node 24: um arquivo .js comum que use import ou export também é tratado como módulo, e portanto também é estrito. A Ana confirmou com um detecta.js que começava com import { sep } from "node:path";: o mesmo nome = "Ana" deu ReferenceError: nome is not defined.

Já um .js comum, sem import/export (o formato "CommonJS", da aula require e module.exports), e o <script> comum do navegador continuam no modo desleixado, a não ser que você escreva "use strict".

Formas diferentes de fazer a mesma coisa

Há três jeitos de ter o modo estrito no seu código:

  1. "use strict"; na primeira linha do arquivo: vale para tudo nele.
  2. "use strict"; na primeira linha de uma função: vale só para ela (útil para ir arrumando um código antigo aos poucos).
  3. Escrever o código como módulo (import/export, .mjs, "type": "module") ou dentro de classes: o modo estrito vem junto, sem escrever nada.
SituaçãoQual usar
Projeto novo no NodeMódulos ("type": "module" ou .mjs): estrito automático
Arquivo .js comum, com require"use strict"; na primeira linha
Página web<script type="module">, ou "use strict"; no topo do script
Código antigo grande, que ainda não aguenta o modo estrito"use strict"; função por função
Na dúvida, ligue

Todo código bem escrito (com let/const, sem with, sem octais) funciona igual nos dois modos. O modo estrito só reclama do que já era um erro escondido. Por isso, ligar o modo estrito num código novo não tem custo nenhum, e pega muitos erros de digitação.

Quando dá errado

Um código antigo parou de funcionar depois do "use strict"

Você acrescentou "use strict" e apareceu um ReferenceError: x is not defined numa linha que "sempre funcionou". Ela nunca funcionou direito: criava uma variável global sem querer. Como consertar: declare a variável com let ou const no lugar certo (ou corrija o nome, se for erro de digitação).

Parâmetro repetido 
$ node duplicado.js

    at wrapSafe (node:internal/modules/cjs/loader:1861:18)  « mais linhas cortadas

"Nome de parâmetro repetido não é permitido neste contexto". No modo desleixado, soma(1, 2) daria 4 (os dois a valeriam o último argumento). Como consertar: dê nomes diferentes: function soma(a, b).

Uma variável com nome de palavra reservada 
$ node reservada.js
/home/ana/reservada.js:2

^^^

SyntaxError: Unexpected strict mode reserved word
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)  « mais linhas cortadas

"Palavra reservada do modo estrito inesperada". As palavras implements, interface, let, package, private, protected, public, static e yield não podem ser nomes de variável no modo estrito (veja Palavras Reservadas). Como consertar: escolha outro nome, de preferência em português: publico.

Escreveu "use strict" e nada mudou

Ele não está na primeira linha (seção 2): alguma instrução veio antes, até um console.log. Ou foi escrito com crase, ou com letras diferentes. Como consertar: mova para o topo do arquivo, exatamente "use strict";.

Resumo

  • O modo estrito é uma versão mais exigente do JavaScript, ligada com "use strict"; na primeira linha do arquivo ou de uma função.
  • Ele transforma erros silenciosos em erros visíveis: variável não declarada (ReferenceError), mudança em objeto congelado (TypeError), e recusa escritas confusas (octal 010, parâmetros repetidos, palavras reservadas, with).
  • Numa função chamada sozinha, o this é undefined, e não o objeto global.
  • Fora da primeira linha, o "use strict" é ignorado sem aviso.
  • Módulos (import/export, .mjs, <script type="module">) e classes já são estritos sozinhos.
  • Código bem escrito funciona igual nos dois modos: ligue sempre.
