JavaScript Formulários

Login, cadastro, busca, pedido de pizza, comentário: quase tudo o que uma pessoa escreve numa página passa por um formulário. O HTML desenha os campos; o JavaScript lê o que foi digitado, confere se está certo e faz alguma coisa com isso. Nesta aula, a Ana monta o formulário de pedidos da pizzaria do bairro.

Você vai aprender
  • Como ler o que foi digitado num campo com .value, e quando ler (na hora do clique, não quando a página abre).
  • Por que o value é sempre texto, e como transformar em número.
  • Como ler checkbox, radio, select e textarea.
  • O evento submit e o preventDefault(), que impede a página de recarregar.
  • Como pegar o formulário inteiro de uma vez com FormData.
  • A validação que o navegador já faz sozinho (required, type="email", min, max) e a validação feita por você.
  • Os erros reais mais comuns: o valor lido cedo demais, o "2" + 1, o value() com parênteses e o null.

Esta aula é do navegador e continua as aulas Eventos e O Objeto do Evento. As respostas do Console foram colhidas no Chromium da máquina da Ana, com a digitação e os cliques feitos de verdade.

A ideia: a comanda da pizzaria

Na pizzaria do bairro, o atendente anota o pedido numa comanda de papel: nome do cliente, tamanho, sabor, "borda recheada? sim/não". Quando o cliente diz "pode fechar", o atendente confere a comanda (faltou o sabor?) e só então a entrega na cozinha.

  • Os campos do formulário (<input>, <select>…) são as linhas da comanda.
  • O valor de cada campo (.value) é o que está escrito naquela linha agora.
  • O botão de enviar é o "pode fechar": dispara o evento submit ("enviar").
  • O seu código é o atendente: confere e decide o que fazer com o pedido.

O form.elements ("os elementos do formulário") é outro jeito de achar um campo: pelo name dele. (No Console, o \" é só uma aspa dentro de outra; no seu código, use aspas simples por fora, como na tabela.)

4. O evento submit e o preventDefault()

Até aqui o botão era um botão solto, com um ouvinte de click. Com um <form> de verdade, o jeito certo é ouvir o formulário, no evento submit. Ele acontece quando a pessoa clica no botão e também quando ela aperta Enter num campo: o atendente fecha a comanda de qualquer jeito que o cliente pedir.

Mas o submit tem um comportamento padrão antigo: enviar os dados para outro endereço e carregar a página de novo. Veja o que acontece com um ouvinte simples, sem nada para impedir:

const form = document.querySelector("#pedido");
console.log("A página carregou.");
form.addEventListener("submit", () => {
  console.log("Pedido enviado!");
});

A Ana preencheu o nome, clicou em "Fazer pedido" e, depois, olhou o endereço da página:

A página carregou.
Pedido enviado!
A página carregou.
> location.href
'file:///home/ana/pizzaria/index.html?nome=Ana&telefone=&tamanho=M&sabor=calabresa&obs='

O ouvinte rodou (Pedido enviado!), mas logo em seguida a página recarregou: o script rodou de novo (o segundo A página carregou.), os campos voltaram vazios e o endereço ganhou os dados no fim, depois do ?. Num Console comum, as mensagens antigas até somem na recarga. Para o JavaScript cuidar do pedido sozinho, cancele o envio com o preventDefault() que você conheceu em O Objeto do Evento:

const form = document.querySelector("#pedido");
const saida = document.querySelector("#saida");

form.addEventListener("submit", (evento) => {
  evento.preventDefault();
  const nome = document.querySelector("#nome").value;
  const sabor = form.elements.sabor.value;
  saida.textContent = `Pedido de ${nome}: ${sabor}.`;
});
form.addEventListener("submit", …)
O ouvinte vai no <form>, e não no botão. Assim o Enter também funciona.
(evento) =>
Recebe o objeto do evento, porque vai precisar dele na linha seguinte.
evento.preventDefault()
"Não envie, não recarregue: deixe comigo." Fica na primeira linha do ouvinte; se alguma linha depois dela der erro, pelo menos a página não recarrega e você consegue ler a mensagem.
Por que o formulário recarrega?

Os formulários são mais velhos que o JavaScript. O jeito original era mandar os dados para um servidor (o computador do site), que respondia com uma página nova. Isso ainda existe e funciona (o atributo action do <form> diz para onde mandar). Mas quando é o seu JavaScript que vai cuidar dos dados, na própria página, o preventDefault() é obrigatório.

No editor do guia

Nas caixas "Experimente", um formulário enviado sem preventDefault() não recarrega o quadro Resultado: o editor segura o envio e escreve no Console uma linha [editor] o formulário foi enviado…. Num site de verdade (e no seu computador), a página recarrega como mostrado acima.

5. O formulário inteiro de uma vez: FormData

Com muitos campos, ler um por um cansa. O FormData ("dados do formulário") pega todos os campos que têm name de uma vez, e o Object.fromEntries transforma tudo num objeto comum (veja Percorrendo Objetos):

const form = document.querySelector("#pedido");
const saida = document.querySelector("#saida");

form.addEventListener("submit", (evento) => {
  evento.preventDefault();
  const dados = new FormData(form);
  const pedido = Object.fromEntries(dados);
  console.log(pedido);
  saida.textContent = `Pedido de ${pedido.nome}: pizza ${pedido.tamanho} de ${pedido.sabor}.`;
});

A Ana digitou o nome e a observação "Sem cebola", escolheu Grande e Marguerita e enviou. Depois marcou a borda e enviou de novo:

{nome: 'Ana', telefone: '', tamanho: 'G', sabor: 'margherita', obs: 'Sem cebola'}
{nome: 'Ana', telefone: '', tamanho: 'G', sabor: 'margherita', borda: 'on', …}

E o parágrafo mostrou Pedido de Ana: pizza G de margherita. Três detalhes:

  • As chaves do objeto são os name dos campos. Campo sem name não entra no FormData.
  • Na primeira vez não há borda: checkbox desmarcado não é enviado. Marcado, ele entra com o valor 'on' ("ligado"). Por isso, para checkbox, o form.elements.borda.checked (true/false) costuma ser mais claro.
  • O … no fim da segunda linha é o Chrome encurtando a prévia de um objeto grande; clicando nele, aparece o obs. Os valores continuam todos strings.

A validação do navegador ajuda, mas não basta

Ela evita erros de digitação de quem está usando o site de boa-fé. Mas qualquer pessoa pode desligá-la (é só apagar o required pelo F12). Por isso, um site de verdade confere os dados de novo no servidor. Na página, use as duas coisas: os atributos do HTML para o básico e o seu JavaScript para as regras do seu negócio.

A sua validação

Para regras que o HTML não conhece ("nota de 0 a 10, aceitando vírgula"; "a senha e a confirmação têm de ser iguais"), confira no ouvinte do submit e mostre a mensagem na página. Se estiver errado, return sai do ouvinte antes de fazer o resto (veja return):

form.addEventListener("submit", (evento) => {
  evento.preventDefault();
  const nota = Number(form.elements.nota.value.replace(",", "."));

  if (form.elements.nota.value === "" || nota < 0 || nota > 10) {
    erro.textContent = "A nota tem de ser de 0 a 10.";
    return;
  }

  erro.textContent = "";
  console.log(`Nota aceita: ${nota}`);
  form.reset();
});

O form.reset() ("reiniciar") devolve todos os campos ao valor inicial do HTML: o jeito de limpar a comanda para o próximo pedido.

Formas diferentes de fazer a mesma coisa

Para ler o campo <input name="nome" id="nome"> de dentro do ouvinte do submit, há três caminhos, todos com o mesmo resultado:

const a = document.querySelector("#nome").value;     // pelo id
const b = form.elements.nome.value;                  // pelo name, dentro do form
const c = new FormData(form).get("nome");            // pelo name, com FormData

E para reagir, também há escolhas: submit no formulário (quando a pessoa termina), input no campo (a cada letra, como o contador de caracteres de Eventos) ou change (quando o campo muda e a pessoa sai dele, ou escolhe outra opção num select).

Somou e deu um número "colado"

Escreveu value(), com parênteses 
const nome = document.querySelector("#nome");

  console.log(nome.value());

Uncaught TypeError: nome.value is not a function

"nome.value não é uma função". O value é uma propriedade (um valor guardado), e não um método: não se chama com (). O erro só aparece no clique, quando o ouvinte roda. Como consertar: nome.value, sem parênteses.

O seletor não achou o campo

  console.log(nome.value);
});

Uncaught TypeError: Cannot read properties of null (reading 'value')
    at script.js:3:20

O campo é #nome, e o código procurou #name (em inglês). O querySelector devolveu null, e o erro estourou no clique, ao ler o value desse null. Como consertar: confira o id no HTML.

A página "pisca" e tudo some

Você preenche, clica em enviar, a página pisca, os campos voltam vazios e a mensagem que o seu código escreveu não aparece (ou aparece por um instante). É o submit sem preventDefault() (seção 4): a página recarregou. Outra pista é o endereço com ?nome=… no fim. Como consertar: receba o evento e chame evento.preventDefault() na primeira linha do ouvinte do submit.

Um campo não aparece no FormData

O objeto do Object.fromEntries(new FormData(form)) veio sem o telefone? Confira se o <input> tem o atributo name: o id não basta. E checkbox desmarcado também não aparece (seção 5).

  // 2. leia o nome e a nota (converta a nota para número)
  // 3. nota vazia ou fora de 0 a 10? mostre o erro e return
  // 4. crie o li "NOME: NOTA", anexe na lista e dê form.reset()
});

const form = document.querySelector("#notas");
const erro = document.querySelector("#erro");
const lista = document.querySelector("#lista");

form.addEventListener("submit", (evento) => {
  evento.preventDefault();
  const nome = form.elements.nome.value;
  const texto = form.elements.nota.value;
  const nota = Number(texto);

  if (texto === "" || nota < 0 || nota > 10) {
    erro.textContent = "A nota tem de ser de 0 a 10.";
    return;
  }

  const item = document.createElement("li");
  item.textContent = `${nome}: ${nota}`;
  lista.append(item);
  form.reset();
});

Para ir além: na solução, se a professora errar uma nota e depois lançar uma certa, a mensagem de erro continua lá. Limpe o #erro (erro.textContent = "") quando a nota estiver certa; e aceite vírgula com texto.replace(",", ".").

Resumo

  • campo.value é o texto do campo agora: leia dentro do ouvinte, nunca quando a página abre.
  • O value é sempre string: converta com Number(…) (ou valueAsNumber) antes de fazer contas.
  • Checkbox: .checked. Radio: querySelector('input[name="x"]:checked').value. Select e textarea: .value.
  • Ouça o submit do <form> e chame evento.preventDefault() primeiro; sem isso, a página recarrega.
  • Object.fromEntries(new FormData(form)) junta todos os campos com name num objeto.
  • required, minlength, type="email", min/max: o navegador barra o envio sozinho. Regras próprias, você confere no submit e mostra a mensagem na página.
