JavaScript Acessando e Alterando Itens

Na aula Arrays, você criou listas e viu que cada item mora numa posição numerada, o índice, a partir do 0. Agora é hora de usar essas posições: ler um item específico ("qual é o terceiro aluno da chamada?"), pegar o último ("qual foi a venda de ontem?") e trocar um item por outro ("a Ana errou a nota da Bia; corrija para 9").

Você vai aprender
  • A ler um item com lista[índice], com o número escrito direto ou guardado numa variável.
  • A pegar o último item de dois jeitos: lista[lista.length - 1] e lista.at(-1).
  • O que acontece quando o índice não existe: undefined, sem erro nenhum.
  • A trocar um item: lista[1] = "novo valor".
  • O que acontece quando você escreve numa posição longe demais (os "buracos").
  • O with(), que devolve uma cópia com um item trocado e deixa o original como estava.
  • Os erros reais mais comuns: ler um item de algo que é undefined, usar parênteses no lugar dos colchetes e tentar trocar um item com at().

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Você pode rodar cada um no editor do guia.

A ideia: os armários numerados da escola

No corredor da escola da Ana, os armários dos alunos ficam enfileirados e numerados. A diferença é que, no JavaScript, o primeiro armário é o número 0:

Armário (índice)0123
Dono (item)"Ana""Bia""Caio""Duda"

Para saber quem usa um armário, você vai até ele pelo número. Para dar o armário a outra pessoa, você troca o conteúdo daquele número, e os outros armários continuam iguais. É exatamente o que esta aula faz com os itens de um array.

1. Ler um item: lista[índice]

const alunos = ["Ana", "Bia", "Caio", "Duda"];
console.log(alunos[0]);
console.log(alunos[2]);
console.log(`O segundo da chamada é ${alunos[1]}.`);
alunos
O nome do array.
[0]
Os colchetes, colados no nome, com o índice dentro: "o item da posição 0". Repare que os colchetes têm dois papéis no JavaScript: em ["Ana", "Bia"] eles criam um array; colados depois de um nome, como em alunos[0], eles pegam um item.
alunos[2]
O terceiro item (posição 2): Caio.
${alunos[1]}
Um item pode ir para qualquer lugar onde caberia um valor, como dentro de uma template string.
$ node chamada.js
Ana
Caio
O segundo da chamada é Bia.

O resultado de alunos[0] é um valor comum, uma string. Dá para guardar numa variável, comparar, juntar com outros textos:

const alunos = ["Ana", "Bia", "Caio", "Duda"];
const primeiro = alunos[0];
console.log(primeiro.toUpperCase());
console.log(alunos[0] === "Ana");
console.log(alunos[3].length);

$ node primeiro.js
ANA
true
4

alunos[0] é a string "Ana", então tudo o que funciona numa string funciona nele: o toUpperCase() (veja Métodos de String), a comparação com ===, o length, que aqui conta as letras de "Duda".

O índice numa variável

O que vai entre os colchetes não precisa ser um número escrito: pode ser uma variável, ou uma conta. É isso que vai permitir percorrer uma lista inteira com um laço (veja for e Percorrendo com for … of).

const alunos = ["Ana", "Bia", "Caio", "Duda"];
const vez = 2;
console.log(`Hoje quem apaga o quadro é ${alunos[vez]}.`);
console.log(`Amanhã é ${alunos[vez + 1]}.`);

$ node sorteio.js
Hoje quem apaga o quadro é Caio.
Amanhã é Duda.

O JavaScript primeiro calcula o que está dentro dos colchetes (vez + 1 dá 3) e depois busca o item dessa posição.

Missão: mude só o valor de vez para que a escolhida de hoje seja a Duda. Lembre que a contagem começa no 0.

const alunos = ["Ana", "Bia", "Caio", "Duda"];
const vez = 0;
console.log(`Hoje quem apaga o quadro é ${alunos[vez]}.`);

const alunos = ["Ana", "Bia", "Caio", "Duda"];
const vez = 3;
console.log(`Hoje quem apaga o quadro é ${alunos[vez]}.`);

2. O índice que não existe: undefined

O que acontece se você pedir o armário 10 num corredor de 4 armários? Em muitas linguagens, isso é um erro. No JavaScript, não: a resposta é undefined ("indefinido"; veja null e undefined), e o programa segue em frente.

const alunos = ["Ana", "Bia", "Caio", "Duda"];
console.log(alunos[4]);
console.log(alunos[10]);
console.log(alunos[-1]);
console.log("O programa continuou.");

$ node fora.js
undefined
undefined
undefined
O programa continuou.
alunos[4]
O array tem 4 itens, nas posições 0, 1, 2 e 3. A posição 4 já está fora: undefined. É o erro de um a mais da aula anterior: o tamanho é 4, mas o último índice é 3.
alunos[10]
Muito longe do fim: undefined também.
alunos[-1]
Quem vem do Python espera o último item. No JavaScript, com colchetes, índice negativo não conta de trás para a frente: dá undefined. (Para contar de trás para a frente existe o at(), na seção 3.)
Silencioso não quer dizer certo

O undefined não para o programa, e é aí que mora o perigo: ele segue adiante e o problema aparece mais tarde, em outro lugar, como um Olá, undefined! na tela ou um erro Cannot read properties of undefined algumas linhas depois (veja Quando dá errado). Se aparecer undefined onde devia haver um item, confira o índice.

3. O último item

O primeiro item é fácil: lista[0]. E o último? O número da última posição muda conforme o tamanho da lista. Existem dois jeitos de pegá-lo sem precisar contar.

O jeito clássico: lista[lista.length - 1]

const vendas = [120, 98, 143, 110, 87];
const ultimoIndice = vendas.length - 1;
console.log(ultimoIndice);
console.log(vendas[ultimoIndice]);
console.log(vendas[vendas.length - 1]);

$ node ultimo.js
4
87
87

São 5 vendas; o último índice é 5 - 1, ou seja, 4; e vendas[4] é 87. A terceira linha faz a mesma coisa sem a variável do meio: primeiro o JavaScript calcula vendas.length - 1, depois busca o item. Você vai ver esse jeito em muito código.

O jeito moderno: lista.at(-1) ES2022

O método at() (em inglês, "em", "na posição") faz o mesmo que os colchetes, com um superpoder: aceita índice negativo, que conta a partir do fim. -1 é o último, -2 o penúltimo, e assim por diante:

const vendas = [120, 98, 143, 110, 87];
console.log(vendas.at(0));
console.log(vendas.at(-1));
console.log(vendas.at(-2));
console.log(vendas.at(9));

$ node at.js
120
87
110
undefined
vendas.at(0)
Com número positivo, igual aos colchetes: o primeiro item.
vendas.at(-1)
O último item. É o mesmo que vendas[vendas.length - 1], só que mais curto e fácil de ler.
vendas.at(-2)
O penúltimo.
vendas.at(9)
Fora da lista: undefined, como os colchetes.

Repare que o at usa parênteses, não colchetes: ele é um método, uma ação do array (como o toUpperCase() das strings). E ele só lê: para trocar um item, só os colchetes servem (veja Quando dá errado). O at() chegou ao JavaScript em 2022 e funciona no Node 24 e em todos os navegadores atuais; em código mais antigo, você vai ver sempre o length - 1. As strings também têm o at() (veja Pedaços de String).

Missão: complete as duas linhas usando o at() com índice negativo, para mostrar a última e a penúltima venda.

const vendas = [120, 98, 143, 110, 87];
console.log(`Última venda: ${vendas[0]}`);
console.log(`Penúltima venda: ${vendas[0]}`);

const vendas = [120, 98, 143, 110, 87];
console.log(`Última venda: ${vendas.at(-1)}`);
console.log(`Penúltima venda: ${vendas.at(-2)}`);

4. Trocar um item: lista[índice] = valor

A professora lançou a nota da Bia (posição 1) errada: era 9, não 6. Para corrigir, use os colchetes do lado esquerdo do =:

const notas = [7.5, 6, 8, 10];
console.log("Antes: ", notas);
notas[1] = 9;
console.log("Depois:", notas);

$ node corrigir.js
Antes:  [ 7.5, 6, 8, 10 ]
Depois: [ 7.5, 9, 8, 10 ]
notas[1] = 9;
"O item da posição 1 passa a valer 9". É uma atribuição, igual a x = 9, só que o alvo é um item do array. O valor antigo (6) some; os outros itens não mudam, e o tamanho continua 4.
const notas
Funciona mesmo com const: a variável continua apontando para o mesmo array; só o conteúdo dele mudou (a aula Arrays explica isso com a folha de papel colada na geladeira).

Os operadores de atribuição que você já conhece também funcionam num item: notas[0] += 1 soma 1 à primeira nota, estoque[2]-- tira 1 do terceiro produto (veja Incremento e Decremento).

const estoque = [12, 5, 8];
estoque[0] += 10;
estoque[2]--;
console.log(estoque);

$ node estoque.js
[ 22, 5, 7 ]

5. Escrever longe demais: os buracos

E se você escrever numa posição que ainda não existe? O JavaScript aumenta o array até ela. Se ficar espaço entre o fim antigo e a posição nova, o espaço vira buracos vazios:

const compras = ["arroz", "feijão", "café"];
compras[3] = "leite";
console.log(compras);
compras[6] = "pão";
console.log(compras);
console.log(compras.length);
console.log(compras[4]);

$ node buracos.js
[ 'arroz', 'feijão', 'café', 'leite' ]
[ 'arroz', 'feijão', 'café', 'leite', <2 empty items>, 'pão' ]
7
undefined

Escrever na posição 3, logo depois do último item (posição 2), funcionou como acrescentar no fim. Já a posição 6 criou dois buracos (as posições 4 e 5), que o Node mostra como <2 empty items>, "2 itens vazios". O length pulou para 7, e ler um buraco dá undefined. Buracos quase sempre são um engano. Para acrescentar no fim, o certo é o push, da próxima aula: push, pop, shift e unshift.

6. Trocar sem estragar o original: with() ES2023

Às vezes você quer uma versão da lista com um item diferente, mas sem perder a original. O método with(índice, valor) (em inglês, "com") devolve uma cópia do array com aquele item trocado:

const notas = [7.5, 6, 8, 10];
const corrigidas = notas.with(1, 9);
console.log("Original:  ", notas);
console.log("Corrigidas:", corrigidas);
console.log(notas.with(-1, 9.5));

$ node with.js
Original:   [ 7.5, 6, 8, 10 ]
Corrigidas: [ 7.5, 9, 8, 10 ]
[ 7.5, 6, 8, 9.5 ]

O notas não mudou: o with fez uma lista nova. Como o at(), ele aceita índice negativo (-1 é o último). O with chegou ao JavaScript em 2023 e funciona no Node 24 e nos navegadores atuais. Quando usar cada um está na tabela da seção Formas diferentes.

"Erro de tipo: alunos não é uma função". Parênteses colados num nome querem dizer "chame esta função" (veja Funções), e um array não é uma função. Como consertar: para pegar um item, colchetes: alunos[0]. (Com o at são parênteses, porque o at é uma função do array: alunos.at(0).)

"Erro de referência: lado esquerdo inválido numa atribuição". Do lado esquerdo do = tem de estar um lugar onde guardar o valor (uma variável, um lista[i]). notas.at(-1) é o resultado de uma chamada, o número 10, e não dá para guardar nada dentro de um número. Curiosidade: o tipo é ReferenceError (e não SyntaxError), e o Node só reclama quando a execução chega nessa linha; as linhas de cima rodam normalmente. Como consertar: notas[notas.length - 1] = 9.5; (ou, se você quer uma cópia, notas.with(-1, 9.5)).

Resumo

  • lista[i] lê o item da posição i; o índice pode ser um número, uma variável ou uma conta. A primeira posição é a 0.
  • O último item é lista[lista.length - 1] ou, no jeito moderno, lista.at(-1). O at aceita índices negativos; os colchetes, não.
  • Uma posição que não existe devolve undefined, sem erro. O erro aparece depois, quando o item é usado: Cannot read properties of undefined.
  • lista[i] = valor troca o item (funciona com const). Escrever além do fim cria buracos.
  • lista.with(i, valor) devolve uma cópia com o item trocado e deixa o original intacto.
  • Item se pega com colchetes; parênteses chamam funções (is not a function); e não dá para atribuir a at().
