JavaScript async e await

Na aula Promises, você viu que uma tarefa demorada (esperar um tempo, ler um arquivo, buscar dados na internet) devolve uma Promise, a "promessa" de um resultado que vai chegar depois, e que o resultado se pega com .then(). Funciona, mas com vários passos seguidos o código vira uma escadinha de .then(() => …). As palavras async ("assíncrono") e await ("aguardar") deixam você escrever o mesmo programa de cima para baixo, como se cada linha esperasse a anterior terminar.

Você vai aprender
  • O que a palavra async faz com uma função: ela passa a devolver sempre uma Promise.
  • O que o await faz: pausa a função até a Promise se resolver e entrega o valor.
  • Como escrever vários passos demorados em sequência, e como o mesmo programa fica com .then().
  • Como tratar erros com try … catch … finally em volta do await.
  • O await no topo do arquivo, as arrow functions async e os métodos async.
  • Os erros reais mais comuns: await numa função sem async, o await esquecido (Promise { <pending> }), a rejeição sem catch e o await dentro do forEach.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: a senha da padaria

Na padaria do bairro, a Ana pede um bolo que ainda está no forno. A atendente entrega uma senha: "quando ficar pronto, a gente chama". A senha é a Promise: não é o bolo, é a promessa do bolo.

Com a senha na mão, a Ana tem dois jeitos de se organizar:

  1. Jeito .then(): ela escreve num papel "quando chamarem a senha, pegue o bolo; depois, pague; depois, vá para casa", entrega o papel a alguém e vai fazer outra coisa.
  2. Jeito await: ela mesma aguarda no balcão. Quando chamam, pega o bolo e segue a lista na ordem: paga, vai para casa. A lista dela fica escrita de cima para baixo, do jeito que a gente pensa.

O detalhe importante: enquanto a Ana aguarda o bolo, a padaria não para. Os outros clientes continuam sendo atendidos. No JavaScript é igual: o await pausa só a função que está esperando; o resto do programa continua rodando (você vai ver isso acontecer na seção 2).

1. A palavra async: a função passa a devolver uma Promise

Escreva async antes de function e a função vira uma função assíncrona. A primeira consequência é surpreendente:

async function saudar() {
  return "Olá, Ana!";
}

const resultado = saudar();
console.log(resultado);
resultado.then((texto) => console.log(texto));

$ node saudar.js
Promise { 'Olá, Ana!' }
Olá, Ana!
async function saudar()
Uma função comum com a palavra async na frente. Por dentro, ela pode ter tudo o que uma função normal tem, e ainda pode usar await.
return "Olá, Ana!";
Parece que devolve um texto, mas o async embrulha o valor numa Promise já resolvida.
console.log(resultado)
Mostra Promise { 'Olá, Ana!' }: uma Promise com o texto dentro. É assim que o Node mostra uma Promise que já tem o valor.
resultado.then(…)
Como é uma Promise, o valor se tira com .then(), igual na aula Promises. A seguir você vai ver o jeito mais curto: o await.
No editor do guia

Se você rodar este programa numa caixa do guia, a primeira linha sai Promise { <pending> }, e não Promise { 'Olá, Ana!' }. O editor roda no navegador, que não deixa espiar o valor guardado numa Promise de função async; o Node deixa. A segunda linha, a do .then, sai igual nos dois.

Regra de ouro

Uma função async sempre devolve uma Promise. Se ela fizer return 10, quem chamou recebe uma Promise que se resolve com 10. Se ela lançar um erro com throw, quem chamou recebe uma Promise rejeitada (a seção 4 mostra isso).

2. A palavra await: esperar o resultado

Dentro de uma função async, você pode escrever await antes de uma Promise. O await faz duas coisas:

  • pausa a função naquela linha até a Promise se resolver;
  • entrega o valor que estava dentro dela, que você guarda numa variável.

A Ana abre a padaria e precisa esperar os pães assarem. Para imitar o forno, a função assarPaes devolve uma Promise que só se resolve depois de 2 segundos (com o setTimeout da aula setTimeout e setInterval):

function assarPaes(quantidade) {
  return new Promise((resolve) => {
    setTimeout(() => resolve(`${quantidade} pães prontos`), 2000);
  });
}

async function abrirPadaria() {
  console.log("Ligando o forno...");
  const paes = await assarPaes(12);
  console.log(paes);
  console.log("Padaria aberta!");
}

abrirPadaria();
console.log("(enquanto isso, a Ana varre a calçada)");

3. Vários passos em sequência

O await brilha quando há vários passos demorados, um depois do outro. Para não repetir o new Promise toda vez, a Ana escreveu uma função auxiliar, esperar(ms), que devolve uma Promise resolvida depois de ms milissegundos (1000 ms = 1 segundo). Você vai ver essa função de 2 linhas em muitos programas de verdade:

function esperar(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function fazerCafe() {
  console.log("1. Fervendo a água...");
  await esperar(1000);
  console.log("2. Passando o café...");
  await esperar(1000);
  console.log("3. Servindo na xícara.");
  return "café pronto";
}

const resposta = await fazerCafe();
console.log(`Resultado: ${resposta}`);

$ node cafe.js
1. Fervendo a água...
2. Passando o café...      « 1 segundo depois
3. Servindo na xícara.     « mais 1 segundo
Resultado: café pronto

Leia o corpo de fazerCafe em voz alta: "ferve a água, espera 1 segundo, passa o café, espera 1 segundo, serve". É uma receita, na ordem. E o return "café pronto" vira o valor da Promise que fazerCafe() devolve; quem chama pega esse valor com outro await.

O await no topo do arquivo

Repare na penúltima linha: const resposta = await fazerCafe(); está fora de qualquer função. Isso se chama top-level await ("await no nível de cima"). Ele só é permitido em módulos (o formato de arquivo com import/export, da aula Módulos). O Node 24 percebe sozinho o await solto e roda o arquivo como módulo: por isso node cafe.js funcionou, sem configuração nenhuma.

Dentro de uma função, o await continua exigindo o async na função (a seção Quando dá errado mostra a mensagem). Nos programas desta aula, as funções que esperam têm async, e as últimas linhas do arquivo usam o await do topo.

Em código antigo: a função main

Antes do top-level await, era comum embrulhar o programa inteiro numa função e chamá-la no fim: async function main() { … } e depois main();. Ainda funciona e você vai encontrar isso em muitos projetos.

O mesmo programa com .then()

Para comparar, este é o café escrito só com Promises e .then(), do jeito da aula anterior. A saída é idêntica:

function esperar(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

function fazerCafe() {
  console.log("1. Fervendo a água...");
  return esperar(1000)
    .then(() => {
      console.log("2. Passando o café...");
      return esperar(1000);
    })
    .then(() => {
      console.log("3. Servindo na xícara.");
      return "café pronto";
    });
}

fazerCafe().then((resposta) => console.log(`Resultado: ${resposta}`));

$ node cafe-then.js
1. Fervendo a água...
2. Passando o café...
3. Servindo na xícara.
Resultado: café pronto

As duas versões fazem exatamente a mesma coisa: o async/await é outra forma de escrever Promises, não uma coisa diferente. A versão com await tem menos parênteses, menos return no meio do caminho e se lê como uma receita.

4. Quando a Promise falha: try … catch

Uma Promise pode ser rejeitada (o pedido não existe, o arquivo sumiu, a internet caiu). Com .then(), o erro se pega com .catch(). Com await, uma Promise rejeitada vira um erro comum, lançado na linha do await, e se pega com o mesmo try … catch … finally da aula try … catch … finally.

A Ana consulta encomendas no sistema da padaria. Só o pedido 7 existe:

function buscarPedido(numero) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (numero === 7) {
        resolve({ numero: 7, item: "bolo de cenoura" });
      } else {
        reject(new Error(`Pedido ${numero} não encontrado`));
      }
    }, 500);
  });
}

async function mostrarPedido(numero) {
  try {
    const pedido = await buscarPedido(numero);
    console.log(`Pedido ${pedido.numero}: ${pedido.item}`);
  } catch (erro) {
    console.log(`Problema: ${erro.message}`);
  } finally {
    console.log("Consulta encerrada.");
  }
}

await mostrarPedido(7);
await mostrarPedido(9);

$ node pedido.js
Pedido 7: bolo de cenoura
Consulta encerrada.
Problema: Pedido 9 não encontrado
Consulta encerrada.
reject(new Error(…))
Dentro de buscarPedido, o pedido que não existe rejeita a Promise com um objeto de erro.
try { const pedido = await … }
"Tente". Se a Promise se resolver, pedido recebe o objeto e a linha seguinte mostra o item.
catch (erro)
Se a Promise for rejeitada, o await lança o erro e o JavaScript pula direto para cá. A linha console.log(`Pedido …`) nem roda. O erro.message é o texto do Error.
finally
"Finalmente". Roda nos dois casos, com ou sem erro: bom para avisar que a consulta acabou.
await mostrarPedido(7); await mostrarPedido(9);
Os dois await no topo garantem a ordem: a consulta do 9 só começa depois que a do 7 terminou.

O throw dentro de uma função async

Do outro lado, um throw dentro de uma função async não derruba o programa na hora: vira uma Promise rejeitada, e o return vira uma Promise resolvida:

async function dobrar(n) {
  return n * 2;
}
async function falhar() {
  throw new Error("deu ruim");
}
console.log(dobrar(5));
console.log(await dobrar(5));
falhar().catch((erro) => console.log("Pegou:", erro.message));

$ node retorno.js
Promise { 10 }
10
Pegou: deu ruim

Os dois jeitos de pegar o erro se misturam sem problema: await dentro de try … catch, ou .catch() direto na Promise que a função devolveu.

5. Outras formas de escrever uma função async

O async vai na frente de qualquer jeito de criar função: arrow functions (aula Arrow Functions) e métodos de objeto (aula Métodos e this) também:

function esperar(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

const regar = async (planta) => {
  await esperar(500);
  return `${planta} regada`;
};

const jardim = {
  async podar(planta) {
    await esperar(500);
    return `${planta} podada`;
  },
};

console.log(await regar("samambaia"));
console.log(await jardim.podar("roseira"));

$ node arrow.js

E o await aceita qualquer valor, não só Promises: await 42 simplesmente dá 42 (no lab, const numero = await 42; console.log(numero); mostrou 42). Não é útil no dia a dia, mas explica por que um await a mais não quebra nada.

6. Repetindo com await: use for … of

A Ana tem uma lista de tarefas de casa, e cada uma leva meio segundo. Com for … of (aula for … of), o await dentro do laço espera cada tarefa terminar antes de começar a próxima:

function esperar(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

const tarefas = ["varrer", "lavar a louça", "regar as plantas"];

for (const tarefa of tarefas) {
  await esperar(500);
  console.log(`Feito: ${tarefa}`);
}
console.log("Terminei tudo!");

$ node forof.js
Feito: varrer
Feito: lavar a louça
Feito: regar as plantas
Terminei tudo!

O laço leva 1,5 segundo (3 × 0,5), e o Terminei tudo! só aparece no fim, como deve ser. Se as tarefas fossem independentes e pudessem andar ao mesmo tempo, daria para terminar em meio segundo: é o assunto da próxima aula, Várias Promises. Com o forEach, a ordem sai errada; veja em Quando dá errado.

Missão: a função dobrarDepois demora um pouco e devolve o valor dobrado (numa Promise). Escreva o while no lugar do comentário: enquanto valor for menor ou igual a 1000, guarde em valor o resultado de await dobrarDepois(valor) e some 1 em dias. function esperar(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

async function dobrarDepois(valor) {
  await esperar(200);
  return valor * 2;
}

let valor = 1;
let dias = 0;
while (valor <= 1000) {
  valor = await dobrarDepois(valor);
  dias++;
}
console.log(`Passou de R$ 1000 em ${dias} dias: R$ ${valor}`);

No lab, a solução mostrou Passou de R$ 1000 em 10 dias: R$ 1024, uns 2 segundos depois (10 voltas de 0,2 s).

Resumo

  • async antes de uma função faz ela sempre devolver uma Promise: o return a resolve, o throw a rejeita.
  • await promessa pausa a função até a Promise se resolver e entrega o valor. Só a função pausa; o resto do programa continua.
  • Vários await seguidos escrevem passos demorados em sequência, de cima para baixo, no lugar da escadinha de .then().
  • Uma Promise rejeitada vira um erro na linha do await: pegue com try … catch … finally.
  • O await exige async na função em volta; fora de funções, só vale em módulos (o Node 24 detecta sozinho).
  • Para repetir com await, use for … of, nunca forEach. E Promise { <pending> } na tela quase sempre é um await esquecido.
