JavaScript Constantes (const)

Na aula Variáveis (let), você guardou valores em caixas com etiqueta e trocou o conteúdo delas várias vezes. Mas muitos valores de um programa não deveriam mudar nunca: o preço do pão na tabela do dia, a taxa de entrega, o nome da padaria. Para esses existe a constante, criada com a palavra const (de constant, "constante", que não muda). Ela é a forma preferida de criar variáveis no JavaScript moderno.

Você vai aprender
  • Como criar uma constante com const nome = valor; e o que acontece se você tentar mudar o valor dela.
  • Por que o valor é obrigatório na hora de criar.
  • Por que a regra dos programadores é "const por padrão, let quando muda".
  • A pegadinha: uma lista ou um objeto guardado num const pode ter o conteúdo alterado.
  • O costume dos nomes em MAIÚSCULAS para valores fixos de configuração.
  • Os erros reais: Assignment to constant variable e Missing initializer in const declaration.

Todos os programas desta aula rodaram no Node.js v24.22.0 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js.

A ideia: a placa gravada na parede

Na padaria há duas formas de mostrar informação. O quadro-negro do "pão do dia" é apagado e reescrito toda manhã: é uma variável let. Já a placa de metal na porta, com "Padaria Bom Grão — desde 1987", foi gravada: ninguém apaga, ninguém reescreve. Se alguém tentar, vai perceber na hora que não dá.

A constante é a placa gravada: uma caixa com etiqueta, como a variável, mas que recebe o valor uma vez, na hora em que é criada, e fica com ele até o fim.

1. Criando uma constante

const precoPao = 0.75;
const quantidade = 6;
const total = precoPao * quantidade;
console.log("Total:", total);
const
A palavra que cria a constante. Fica no mesmo lugar do let.
precoPao
O nome (a etiqueta). Duas palavras juntas, a segunda com maiúscula: é o camelCase, o costume do JavaScript (veja Nomes de Variáveis).
= 0.75
O valor, que aqui é obrigatório. Uma constante sem valor não teria como recebê-lo depois.
const total = precoPao * quantidade;
Uma constante pode guardar o resultado de uma conta com outras constantes. O resultado (4.5) é calculado uma vez e fica guardado.
$ node preco.js
Total: 4.5

Para usar uma constante, nada muda: você escreve o nome e o JavaScript põe o valor no lugar. A diferença só aparece quando alguém tenta trocar o valor.

3. O valor é obrigatório

Com let, dá para criar a caixa vazia e encher depois. Com const, não:

const troco;
troco = 2.5;

$ node semvalor.js
/home/ana/semvalor.js:1
const troco;
      ^^^^^

SyntaxError: Missing initializer in const declaration
    «  … linhas "at" de dentro do Node (cortadas aqui)

Node.js v24.22.0

"Erro de sintaxe: falta o inicializador na declaração const". Inicializador é o = valor. Faz sentido: se a constante nascesse vazia, ela ficaria vazia para sempre. É um erro de sintaxe, então o Node o encontra antes de rodar qualquer linha. Como consertar: dê o valor na mesma linha (const troco = 2.5;), ou use let se o valor só vai ser conhecido depois.

4. const por padrão, let quando muda

Esta é a regra que os programadores de JavaScript seguem, e que este guia segue em todos os exemplos:

  1. Comece criando tudo com const.
  2. Se o valor precisar mudar (um contador, um total que vai somando, o saldo), troque aquela variável para let.
  3. Nunca use var (o motivo está na próxima aula, var: o Jeito Antigo).

Na prática, a maior parte das variáveis de um programa acaba sendo const. Veja um programa com as duas: o preço não muda, a quantidade vai somando, e o total é calculado uma vez, no fim:

const preco = 0.75;
let quantidade = 0;
quantidade = quantidade + 6;
quantidade = quantidade + 4;
const total = preco * quantidade;
console.log(quantidade, "pães custam", total);

$ node mistura.js
10 pães custam 7.5

Quem lê esse código entende muito só de olhar as palavras: let quantidade avisa "atenção, esta muda mais adiante"; const avisa "esta fica como está".

5. A pegadinha: listas e objetos num const

Até aqui, as constantes guardaram números. Com uma lista (um array, entre [ ], assunto de Arrays) acontece uma coisa que surpreende:

const compras = ["pão", "leite"];
compras.push("café");
console.log(compras);
compras[0] = "pão integral";
console.log(compras);

$ node lista.js
[ 'pão', 'leite', 'café' ]
[ 'pão integral', 'leite', 'café' ]

A lista era const e, mesmo assim, ganhou um item (o push acrescenta no fim) e teve o primeiro item trocado. Nenhum erro. Por quê?

Porque o const proíbe trocar o que está na caixa, e o que está na caixa compras é a lista, a mesma lista do começo ao fim. Escrever dentro da lista não troca a lista por outra. É como uma prancheta presa à parede com parafuso: você não consegue trocar a prancheta (o const), mas pode escrever e apagar na folha dela à vontade.

Trocar a prancheta inteira, isso o const não deixa:

const compras = ["pão", "leite"];
compras = ["banana"];

Com um objeto (pares "nome: valor" entre { }, assunto de Objetos) é igual: os campos podem mudar.

const cliente = { nome: "Ana", pontos: 10 };
cliente.pontos = cliente.pontos + 5;
console.log(cliente);

$ node cliente.js
{ nome: 'Ana', pontos: 15 }
E se eu quiser travar o conteúdo também?

Existe o Object.freeze ("congelar"). Um objeto congelado não aceita mudanças nos campos:

const cliente = Object.freeze({ nome: "Ana", pontos: 10 });
cliente.pontos = 99;
console.log(cliente);

$ node congelado.js
{ nome: 'Ana', pontos: 10 }

Os pontos continuaram 10. Repare que não apareceu erro: a mudança foi ignorada em silêncio. (No modo estrito, com "use strict"; no começo do arquivo, ela vira erro: no lab saiu TypeError: Cannot assign to read only property 'pontos' of object '#<Object>', "não é possível atribuir à propriedade somente-leitura pontos".) O assunto completo está em Imutabilidade.

6. Nomes em MAIÚSCULAS para valores fixos

Muitos programadores escrevem em MAIÚSCULAS, com as palavras separadas por _, as constantes que são configurações fixas do programa, conhecidas antes de ele rodar: a taxa de entrega, o pedido mínimo, o número máximo de tentativas.

const TAXA_ENTREGA = 5;
const PEDIDO_MINIMO = 20;
const valorPedido = 32.5;
const totalComEntrega = valorPedido + TAXA_ENTREGA;
console.log("Pedido mínimo:", PEDIDO_MINIMO);
console.log("Total com entrega:", totalComEntrega);

$ node taxa.js
Pedido mínimo: 20
Total com entrega: 37.5

Repare: valorPedido e totalComEntrega também são const, mas ficam em camelCase, porque são dados do programa (num programa de verdade, viriam do pedido do cliente). As MAIÚSCULAS ficam para os números "da tabela" que a padaria decidiu. Isso é só um costume; o JavaScript trata os dois do mesmo jeito.

7. Cada bloco, as suas constantes

Como o let, uma const criada dentro de um bloco { } só existe ali dentro. Por isso, uma constante de mesmo nome dentro de um bloco é outra caixa, que não mexe na de fora:

const cor = "azul";
{
  const cor = "verde";
  console.log("Dentro:", cor);
}
console.log("Fora:", cor);

$ node bloco.js
Dentro: verde
Fora: azul

Isso vai ser importante nos laços: em for…of, por exemplo, cada volta cria a sua própria const com o item da vez. Mas evite repetir nomes assim de propósito: fica confuso de ler.

Formas diferentes de fazer a mesma coisa

Resumo

  • const nome = valor; cria uma constante: ela recebe o valor uma vez e não aceita outro (TypeError: Assignment to constant variable.).
  • O valor é obrigatório na criação (SyntaxError: Missing initializer in const declaration).
  • A regra: const por padrão, let quando o valor muda, var nunca. A constante dá uma garantia a quem lê o código.
  • Uma lista ou objeto num const pode ter o conteúdo alterado (push, trocar um campo); o que não pode é pôr outra lista no lugar. Object.freeze trava o conteúdo.
  • Valores fixos de configuração costumam ter nome em MAIÚSCULAS: TAXA_ENTREGA.
  • Como o let, a const só existe dentro do seu bloco { } e não pode ser criada duas vezes com o mesmo nome.
