JavaScript require e module.exports

Na aula Módulos (import e export), você dividiu um programa em arquivos com import e export, o padrão oficial da linguagem. Só que o Node nasceu em 2009, seis anos antes de esse padrão existir. Para não esperar, ele criou o seu próprio sistema de módulos, o CommonJS, com duas palavras: require ("exigir", "requisitar") para trazer um módulo, e module.exports ("exportações do módulo") para oferecer. Milhões de pacotes e tutoriais usam esse jeito até hoje, e o npm init ainda cria projetos CommonJS. Por isso você precisa saber ler e escrever os dois.

Você vai aprender
  • Como oferecer coisas com module.exports e trazê-las com require("./arquivo").
  • O atalho exports.nome, a exportação de uma coisa só e a desestruturação no require.
  • Quando o Node usa CommonJS: .cjs, "type": "commonjs" e os .js sem "type".
  • O que o require faz a mais: dispensa a extensão, lê pastas e arquivos .json.
  • __dirname e __filename, e o cache (cada módulo roda uma vez só).
  • Como misturar CommonJS e módulos ES no Node 24.
  • Os erros reais: Cannot find module, o exports = { } que não funciona e o module.exports esquecido.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), numa pasta papelaria com um package.json igual ao que o npm init cria ("type": "commonjs"). O require e o module.exports são só do Node: o navegador não os conhece.

A ideia: a mesma cozinha, outro balcão

Lembra da cozinha do restaurante da aula anterior? Cada bancada é um módulo, e o que vai para o balcão os outros podem usar. No CommonJS, a ideia é a mesma; muda o jeito de usar o balcão:

  • cada bancada tem uma bandeja só, chamada module.exports. Tudo o que ela quer oferecer, coloca nessa bandeja;
  • quem precisa vai até a bancada e diz require("./molhos"): "me dá a bandeja dos molhos". E recebe a bandeja inteira.

2. Outras formas de exportar e de receber

Desestruturar no require

Se você só quer algumas coisas da bandeja, pegue-as direto, com a desestruturação. É o jeito mais parecido com o import { … }:

const { somar, TAXA_ENTREGA } = require("./contas");
console.log(somar(1, 2), TAXA_ENTREGA);

$ node desestruturar.js
3 7.5

Repare que aqui o caminho foi "./contas", sem o .js, e funcionou: o require tenta a extensão sozinho (seção 4).

O atalho exports.nome

Em vez de montar a bandeja no fim, dá para ir colocando uma coisa de cada vez com exports.nome = …:

exports.saudar = function (nome) {
  return `Olá, ${nome}!`;
};
exports.despedir = (nome) => `Tchau, ${nome}!`;

const mensagens = require("./exports");
console.log(mensagens);
console.log(mensagens.saudar("Ana"));

$ node usa-exports.js
{ saudar: [Function (anonymous)], despedir: [Function (anonymous)] }
Olá, Ana!

O exports é um apelido para a mesma bandeja (module.exports). Colocar coisas nela com ponto funciona; trocar a bandeja inteira com exports = … não funciona (veja Quando dá errado). O (anonymous) ("anônima") aparece porque essas funções foram criadas sem nome próprio.

Exportar uma coisa só

Quando o módulo oferece uma única função (ou classe), ela pode ser a bandeja:

module.exports = function saudar(nome) {
  return `Olá, ${nome}!`;
};

const saudar = require("./saudar");
console.log(saudar("Bia"));

$ node usa-saudar.js
Olá, Bia!

Agora o require devolve a própria função, que você chama direto. É o equivalente do export default.

3. Quando o Node usa CommonJS?

São as mesmas regras da aula anterior, olhando do outro lado:

ArquivoO Node trata como
arquivo.cjsCommonJS, sempre
arquivo.js com "type": "commonjs" no package.json (o que o npm init cria)CommonJS
arquivo.js sem "type" e sem import/exportCommonJS
arquivo.js com "type": "module", ou .mjsMódulo ES (lá, require não existe)

Num projeto "type": "module", se um arquivo precisar ser CommonJS, dê a ele a extensão .cjs.

4. O que o require faz a mais

Adivinha a extensão e lê pastas

Com require("./contas"), o Node procura contas, depois contas.js, contas.json… E se ./utils for uma pasta, ele procura o arquivo index.js dentro dela:

module.exports = { versao: "1.0" };

const utils = require("./utils");
console.log(utils);

$ node pasta.js
{ versao: '1.0' }

Os módulos ES não fazem nenhuma dessas adivinhações: lá, o caminho tem de ser o do arquivo, com extensão ("./utils/index.js").

Lê arquivos JSON

{ "pão": 0.75, "leite": 5.49 }

const precos = require("./precos.json");
console.log(precos);
console.log(precos["leite"]);

$ node json.js
{ 'pão': 0.75, leite: 5.49 }
5.49

O require de um .json lê o arquivo e já entrega o objeto pronto, sem JSON.parse (veja JSON). Prático para arquivos de configuração que não mudam enquanto o programa roda.

Os módulos do Node, __dirname e __filename

const fs = require("node:fs");

console.log(__filename);
console.log(__dirname);
console.log(path.join(__dirname, "precos.json"));
console.log(fs.existsSync(path.join(__dirname, "precos.json")));

Os módulos do Node vêm do mesmo jeito, pelo nome (aulas Lendo Arquivos e Caminhos de Arquivo).
__filename · __dirname
O caminho completo do arquivo que está rodando, e o da pasta dele. Existem em todo arquivo CommonJS, sem importar nada. (Nos módulos ES, são import.meta.filename e import.meta.dirname.)
path.join(__dirname, "precos.json")
Monta o caminho de um arquivo que está ao lado do programa, não importa de qual pasta você rodou o node.

Cada módulo roda uma vez só

console.log("contador.js rodou");
let visitas = 0;
module.exports = {
  visitar() {
    visitas++;
    return visitas;
  },
};

const a = require("./contador");
const b = require("./contador");
console.log(a.visitar(), b.visitar());
console.log(a === b);

$ node umavez.js
contador.js rodou
1 2
true

Igual aos módulos ES: o segundo require não roda o arquivo de novo, entrega a mesma bandeja (a === b é true). Por isso o contador chegou a 2. O Node guarda os módulos já carregados num cache ("depósito").

5. Misturando CommonJS e módulos ES

Num projeto de verdade, é comum um lado precisar usar o outro. No Node 24, as duas direções funcionam:

export function triplicar(n) {
  return n * 3;
}

const { triplicar } = require("./modulo-esm.mjs");
console.log(triplicar(4));

import contas from "./contas.js";
import { somar } from "./contas.js";
console.log(contas.TAXA_ENTREGA, somar(2, 2));

$ node require-esm.js
12
$ node importa-cjs.mjs
7.5 4
  • CommonJS usando módulo ES: o require de um módulo ES funciona sem nenhuma opção desde o Node 22.12 e foi declarado estável no Node 24.15. (A exceção: módulos ES que usam await no topo não podem ser carregados com require.) Em tutoriais antigos, você vai ler que isso "não funciona": era verdade até 2024.
  • Módulo ES usando CommonJS: o import padrao from recebe a bandeja inteira (o module.exports); o import { somar } from também funciona na maioria dos casos, porque o Node lê o arquivo e descobre os nomes que ele exporta.

Resumo

  • CommonJS é o sistema de módulos original do Node: module.exports oferece, require traz. Só existe no Node.
  • module.exports = { a, b } (ou exports.a = …, nunca exports = …); module.exports = f para uma coisa só.
  • const m = require("./arquivo") ou const { a } = require(…). O que não está na bandeja é privado, e o erro só aparece quando você tenta usar.
  • O require dispensa a extensão, carrega pasta/index.js e lê .json. __dirname e __filename dão o caminho do arquivo.
  • CommonJS: .cjs, "type": "commonjs" (o padrão do npm init) ou .js sem import/export.
  • No Node 24, CommonJS e módulos ES se usam um ao outro; mas cada arquivo é de um sistema só. Para projetos novos, prefira módulos ES.
