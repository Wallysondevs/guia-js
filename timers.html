JavaScript setTimeout e setInterval

Na aula O que é Código Assíncrono, você viu o setTimeout de relance. Agora ele e o irmão dele, o setInterval, ganham uma aula inteira. São os timers ("temporizadores") do JavaScript: o setTimeout é o despertador que toca uma vez; o setInterval é o relógio que faz "tic" sem parar, de tempos em tempos. Com eles você faz alarmes, lembretes, contagens regressivas, relógios na tela e jogos.

Você vai aprender
  • Agendar uma função com setTimeout(funcao, ms), e o que acontece com vários timers ao mesmo tempo.
  • Passar argumentos para a função agendada.
  • Cancelar um timer com clearTimeout.
  • Repetir com setInterval e parar com clearInterval: a contagem regressiva.
  • Outras formas: o setTimeout que se reagenda, e o await com node:timers/promises.
  • Os erros reais: chamar a função em vez de passá-la, o var no laço, o intervalo que nunca para.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. setTimeout e setInterval existem do mesmo jeito no navegador. No editor do guia, as esperas acontecem de verdade: um timer de 3 segundos demora 3 segundos.

A ideia: o despertador e o metrônomo

Na cozinha da Ana tem dois aparelhos:

  • o timer do forno: ela gira para 3 minutos e vai fazer outra coisa; quando o tempo acaba, ele toca uma vez. Se ela tirar o pão antes, pode desligar o timer, e ele não toca. Esse é o setTimeout, e o "desligar" é o clearTimeout;
  • o metrônomo do piano do irmão: faz "tic" a cada segundo, para sempre, até alguém desligar. Esse é o setInterval, e o "desligar" é o clearInterval.

Nos dois casos, o aparelho não fica "segurando" a Ana: ela liga e continua a vida. É o código assíncrono.

1. setTimeout: fazer uma coisa daqui a pouco

function tocarAlarme() {
  console.log("TRIIIM! Tire o pão de queijo do forno!");
}

console.log("Pão de queijo no forno.");
setTimeout(tocarAlarme, 3000);
console.log("Alarme agendado para daqui a 3 segundos.");
function tocarAlarme() { … }
A função que vai rodar quando o tempo acabar: o callback.
setTimeout(tocarAlarme, 3000)
"Daqui a 3000 milissegundos, chame tocarAlarme." Repare: tocarAlarme sem parênteses. Você entrega a função para o timer chamar depois; com parênteses, você a chamaria agora (é o primeiro erro da seção Quando dá errado).
3000
O tempo, em milissegundos: 1000 ms = 1 segundo, então 3000 = 3 segundos; meio segundo é 500; um minuto, 60000.
$ node alarme.js
Pão de queijo no forno.
Alarme agendado para daqui a 3 segundos.
TRIIIM! Tire o pão de queijo do forno!

As duas primeiras linhas aparecem na hora; a terceira, 3 segundos depois. Aí o programa termina sozinho: o Node espera os timers pendentes e, quando não sobra nenhum, encerra.

Vários timers ao mesmo tempo

Cada setTimeout é um timer independente. Eles tocam na ordem do tempo, não na ordem em que foram escritos:

setTimeout(() => console.log("3 segundos: bolo"), 3000);
setTimeout(() => console.log("1 segundo: café"), 1000);
setTimeout(() => console.log("2 segundos: pão"), 2000);
console.log("Tudo agendado!");

$ node varios.js
Tudo agendado!
1 segundo: café
2 segundos: pão
3 segundos: bolo

Aqui o callback foi escrito direto, como arrow function: () => console.log(…). É o jeito mais comum. E o programa todo levou 3 segundos, não 1 + 2 + 3 = 6: os três timers correram ao mesmo tempo.

O tempo é um mínimo, não uma promessa

setTimeout(f, 1000) quer dizer "chame f daqui a pelo menos 1 segundo". Se o JavaScript estiver ocupado com outra coisa nessa hora (um laço pesado, por exemplo), o callback espera a vez: você viu um timer de 0 ms atrasar quase 3 segundos em O que é Código Assíncrono. Para coisas do dia a dia, a diferença é de poucos milésimos.

Passando argumentos

Se a função agendada precisa de valores, há dois jeitos:

function lembrar(nome, remedio) {
  console.log(`${nome}, hora do ${remedio}!`);
}

setTimeout(lembrar, 1000, "Vó Lurdes", "remédio da pressão");
setTimeout(() => lembrar("Caio", "xarope"), 1500);

$ node argumentos.js
Vó Lurdes, hora do remédio da pressão!
Caio, hora do xarope!
  • Depois do tempo: tudo o que vem depois do 1000 é entregue à função quando ela for chamada.
  • Arrow function em volta: () => lembrar("Caio", "xarope") é uma função nova, sem parâmetros, que chama lembrar com os valores certos. É o jeito mais usado, porque fica claro de ler.

2. Cancelando: clearTimeout

Todo setTimeout devolve uma "identificação" do timer. Guarde-a numa variável, e você pode cancelá-lo antes de ele tocar com clearTimeout ("limpar o timer"):

console.log("Alarme agendado.");
const alarme = setTimeout(() => {
  console.log("TRIIIM!");
}, 2000);

console.log("A Ana tirou o bolo antes da hora.");
clearTimeout(alarme);
console.log("Alarme cancelado.");

$ node cancelar.js
Alarme agendado.
A Ana tirou o bolo antes da hora.
Alarme cancelado.
const alarme = setTimeout(…)
Guarda a identificação do timer. No Node ela é um objeto (typeof dá object, da classe Timeout); no navegador, é um número. Você não precisa olhar dentro dela: só guardar e entregar ao clearTimeout.
clearTimeout(alarme)
Desliga o timer. O TRIIIM! nunca aparece, e o programa termina na hora, sem esperar os 2 segundos: não sobrou nada pendente.

No navegador, isso é muito usado em campos de busca: a cada tecla, cancela a busca anterior e agenda uma nova para daqui a meio segundo; só quando a pessoa para de digitar a busca acontece.

Missão: o programa diz que cancelou o alarme, mas ele toca mesmo assim depois de 2 segundos. Guarde o timer numa constante alarme e cancele com clearTimeout(alarme) antes da mensagem de cancelado. A saída deve ter só Alarme agendado. e Alarme cancelado., sem TRIIIM!.

console.log("Alarme agendado.");
setTimeout(() => {
  console.log("TRIIIM!");
}, 2000);

console.log("Alarme cancelado.");

console.log("Alarme agendado.");
const alarme = setTimeout(() => {
  console.log("TRIIIM!");
}, 2000);

clearTimeout(alarme);
console.log("Alarme cancelado.");

3. setInterval: repetir de tempos em tempos

O setInterval recebe as mesmas duas coisas (a função e o tempo), mas chama a função de novo e de novo, a cada intervalo. Para parar, guarde a identificação e use clearInterval. A contagem regressiva para o lançamento do bolo novo da padaria:

let segundos = 3;

const relogio = setInterval(() => {
  console.log(segundos);
  segundos = segundos - 1;
  if (segundos === 0) {
    clearInterval(relogio);
    console.log("Já!");
  }
}, 1000);

console.log("Contagem começando...");

$ node regressiva.js
Contagem começando...
3
2
1
Já!
let segundos = 3;
Uma variável fora do callback, que guarda o estado entre um "tic" e outro. Se ela fosse criada dentro do callback, nasceria valendo 3 a cada volta.
const relogio = setInterval(() => { … }, 1000)
"A cada 1000 ms, rode esta função." A primeira chamada acontece depois de 1 segundo (não na hora).
segundos = segundos - 1;
Cada "tic" diminui o contador.
if (segundos === 0) { clearInterval(relogio); … }
A condição de parada: quando chega a zero, desliga o intervalo. Sem ela, o relógio contaria 0, -1, -2… para sempre.
"Contagem começando..." primeiro
Como sempre com timers: o programa agendou e seguiu. A contagem vem depois.

Repare que o setInterval parece um while, mas com uma pausa entre as voltas e sem travar o programa: entre um "tic" e outro, o JavaScript fica livre para fazer outras coisas.

O intervalo que nunca para

Um setInterval sem clearInterval não termina nunca, e o programa também não: sempre há um próximo "tic" pendente. A Ana rodou este com o comando timeout 3.5, que mata o programa depois de 3,5 segundos:

let voltas = 0;
setInterval(() => {
  voltas = voltas + 1;
  console.log(`tic ${voltas}`);
}, 1000);

$ timeout 3.5 node sem-fim.js
tic 1
tic 2
tic 3
$ echo $?
124

Três "tics" e o timeout interrompeu (o código de saída 124 é o jeito do timeout dizer "eu matei o programa"). Sem o timeout, você pararia com Ctrl+C no terminal. No editor do guia, use o botão ■ Parar (ou espere: o editor para sozinho qualquer programa que passe de 10 segundos). Num relógio na tela de uma página, rodar para sempre é exatamente o que se quer (veja o Projeto: Relógio e Cronômetro).

Formas diferentes de fazer a mesma coisa

Um setTimeout que se reagenda

Dá para repetir sem setInterval: a função, no fim, agenda a si mesma de novo. A mesma contagem:

let segundos = 3;

function contar() {
  console.log(segundos);
  segundos = segundos - 1;
  if (segundos > 0) {
    setTimeout(contar, 1000);
  } else {
    setTimeout(() => console.log("Já!"), 1000);
  }
}

setTimeout(contar, 1000);

$ node recursivo.js
3
2
1
Já!

Aqui não há nada para cancelar: quando a condição falha, a função simplesmente não se reagenda, e acabou. (Repare que o Já! agora vem 1 segundo depois do 1, porque ganhou um timer próprio.) A vantagem desse jeito: a próxima volta só é agendada depois que a anterior terminou, o que importa quando cada volta demora (como buscar dados na internet a cada 10 segundos).

Esperar com await (só no Node)

O Node tem uma versão do setTimeout que devolve uma Promise, no módulo node:timers/promises. Com ela, dá para "esperar" no meio do código com await (assunto das aulas Promises e async e await). Este arquivo termina em .mjs para poder usar import e await direto no topo (aula Módulos):

import { setTimeout as esperar } from "node:timers/promises";

console.log("Pão no forno...");
await esperar(2000);
console.log("Pão pronto!");

$ node promessa.mjs
Pão no forno...
Pão pronto!

A segunda linha veio 2 segundos depois, e o código ficou em ordem, de cima para baixo. No navegador esse módulo não existe; lá se escreve await new Promise((r) => setTimeout(r, 2000)), que você vai entender na aula Promises.

Em tutoriais muito antigos você vai ver o código entre aspas. O navegador ainda aceita isso (por compatibilidade), mas o Node não: "recebi o tipo string". Mesmo no navegador, é um jeito inseguro e lento. Como consertar: setTimeout(() => console.log("oi"), 1000).

Timers dentro de um laço com var 
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(`Var: forno ${i}`), 100);
}
for (let j = 1; j <= 3; j++) {
  setTimeout(() => console.log(`Let: forno ${j}`), 200);
}

$ node var-laco.js
Var: forno 4
Var: forno 4
Var: forno 4
Let: forno 1
Let: forno 2
Let: forno 3

Um clássico. Os callbacks só rodam depois que o laço inteiro terminou. Com var, existe uma variável i só, para o laço todo, e quando os timers tocam ela já vale 4 (o valor que fez o laço parar). Com let, cada volta tem a sua j, e cada callback lembra a da sua volta (aulas var e Closures). Como consertar: use let no laço, sempre.

A contagem não para, ou para cedo demais

Se a contagem passa do zero (0, -1, -2…), a condição de parada nunca ficou verdadeira: confira se o if testa o valor certo (segundos === 0 depois de diminuir) e se o clearInterval está dentro dele. Se a variável do contador foi criada dentro do callback, ela nasce de novo a cada "tic" e a contagem fica presa no mesmo número: crie-a fora. No editor, o botão ■ Parar interrompe um intervalo que não para.

Missão: este programa usa setTimeout e por isso só mostra o 3. Troque por setInterval, para ele repetir a cada segundo, e, dentro do if, pare o relógio com clearInterval(relogio). A saída deve ser 3, 2, 1 e Já!, um por segundo, e o programa deve terminar sozinho.

const relogio = setTimeout(() => {
  console.log(contador);
  contador = contador - 1;
  if (contador === 0) {
    console.log("Já!");
  }
}, 1000);

const relogio = setInterval(() => {
  console.log(contador);
  contador = contador - 1;
  if (contador === 0) {

    console.log("Já!");
  }
}, 1000);

No lab, a solução mostrou 3, 2, 1 e Já!, e terminou em uns 3 segundos.

Resumo

  • setTimeout(funcao, ms) chama a função uma vez, daqui a pelo menos ms milissegundos (1000 ms = 1 s). O programa não espera: agenda e segue.
  • Entregue a função sem parênteses (setTimeout(f, 1000)), ou uma arrow em volta (() => f(a)) para passar argumentos.
  • setInterval(funcao, ms) repete até alguém chamar clearInterval(id). Sem isso, o programa não termina.
  • Guarde a identificação do timer numa variável para poder cancelar: clearTimeout(id) e clearInterval(id).
  • Vários timers correm ao mesmo tempo e tocam na ordem do tempo. Dentro de laços, use let, nunca var.
  • Outras formas: um setTimeout que se reagenda, e o await com node:timers/promises.
