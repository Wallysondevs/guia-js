JavaScript NaN, Infinity e a Precisão

Na calculadora, dividir por zero mostra "Erro". No JavaScript, não: nenhuma conta com number dá erro. Quando a conta não tem resposta, o resultado é um valor especial: NaN ("não é um número") ou Infinity ("infinito"). E, para completar, algumas contas com decimais saem levemente tortas: 0.1 + 0.2 dá 0.30000000000000004. Esta aula explica os três casos e, principalmente, como se proteger deles, porque os três aparecem sem nenhuma mensagem de erro.

Você vai aprender
  • O que é o NaN, de onde ele vem e por que ele "contagia" as contas seguintes.
  • Por que NaN === NaN é false, e como testar com Number.isNaN.
  • O que é o Infinity, por que 1 / 0 não dá erro e como testar com Number.isFinite.
  • Por que 0.1 + 0.2 não dá exatamente 0.3.
  • Três jeitos de lidar com dinheiro: mostrar com toFixed(2), contar em centavos e comparar com tolerância.

Todos os programas desta aula rodaram no Node.js v24.22.0 da máquina da Ana (ana@notebook), com node arquivo.js.

A ideia: o caixa que nunca trava

Imagine um caixa de padaria que nunca mostra "Erro". Se alguém digita letras no lugar do preço, ele escreve no visor "não é um número" e continua. Se alguém divide a conta por zero pessoas, ele escreve "infinito". Parece prático, mas é perigoso: o caixa continua somando, e no fim do dia o fechamento sai "não é um número" sem ninguém saber onde começou o problema.

O number do JavaScript é esse caixa. Seu trabalho, como programador, é conferir os valores especiais antes que eles se espalhem.

1. NaN: "não é um número"

NaN vem do inglês Not a Number, "não é um número". É o resultado de uma conta que não tem resposta numérica:

console.log("abc" * 2);
console.log(Number("doze"));
console.log(0 / 0);
console.log(Math.sqrt(-1));
console.log(typeof NaN);

$ node nan.js

Multiplicar um texto que não é número. O JavaScript tentou transformar "abc" em número, não conseguiu, e o resultado é NaN.
Number("doze")
O Number(…) converte um texto em número (aula Conversão). "doze", por extenso, ele não entende.

Sim: o "não é um número" é do tipo number. Ele é o valor que o tipo number usa para dizer "resultado inválido".

A causa mais comum, na vida real, é a segunda: um texto que veio do usuário (do teclado, de um formulário) e não pôde ser convertido. Repare que, em nenhuma das linhas, apareceu uma mensagem de erro.

O NaN contagia

Qualquer conta com um NaN dá NaN. Ele se espalha de variável em variável:

const preco = Number("quatro e cinquenta");
const quantidade = 2;
const total = preco * quantidade;
const comEntrega = total + 5;
console.log("Preço:", preco);
console.log("Total:", total);
console.log("Com entrega:", comEntrega);

$ node contagia.js
Preço: NaN
Total: NaN
Com entrega: NaN

O problema nasceu na linha 1, mas só foi visto na hora de mostrar. Num programa grande, a linha que mostra o NaN pode estar muito longe da linha que o criou. Por isso, confira o valor logo depois de converter (seção 2).

Missão: o programa mostra Total: NaN. Descubra qual valor não pôde ser convertido e escreva-o com algarismos, para aparecer Total: 9.

const preco = Number("4.5");
const quantidade = Number("dois");
const total = preco * quantidade;
console.log("Total:", total);

const preco = Number("4.5");
const quantidade = Number("2");
const total = preco * quantidade;
console.log("Total:", total);

2. Testando o NaN: Number.isNaN

O jeito óbvio de perguntar "deu NaN?" não funciona:

const resultado = "abc" * 2;
console.log(resultado === NaN);
console.log(NaN === NaN);
console.log(Number.isNaN(resultado));
console.log(Number.isNaN(42));

$ node igual.js
false
false
true
false
resultado === NaN → false
Mesmo o resultado sendo NaN, a comparação deu false.
NaN === NaN → false
O NaN não é igual nem a ele mesmo. É uma regra do padrão de números que o JavaScript segue (o mesmo de quase todas as linguagens): dois "resultados inválidos" não são considerados iguais, porque podem ter vindo de contas completamente diferentes.
Number.isNaN(resultado) → true
O jeito certo: Number.isNaN(valor) ("é NaN?") responde true só para o NaN.
isNaN × Number.isNaN

Existe também um isNaN sozinho, mais antigo. Ele primeiro tenta converter o valor em número, e por isso responde diferente para textos:

console.log(isNaN("abc"));
console.log(Number.isNaN("abc"));
console.log(isNaN(NaN), Number.isNaN(NaN));

$ node isnan.js
true
false
true true

isNaN("abc") pergunta "isto, convertido em número, daria NaN?" (sim). Number.isNaN("abc") pergunta "isto é o valor NaN?" (não: é um texto). Prefira o Number.isNaN, que não faz conversões escondidas.

3. Infinity: o infinito

Dividir um número por zero, no JavaScript, não é erro: dá Infinity (ou -Infinity, se o número for negativo). O mesmo acontece quando o resultado passa do maior número que o number consegue guardar (veja Números):

console.log(1 / 0);
console.log(-1 / 0);
console.log(10 ** 1000);
console.log(Number.MAX_VALUE * 2);
console.log(Infinity + 1);
console.log(Infinity - Infinity);
console.log(typeof Infinity);

Testando: Number.isFinite

A Ana dividiu a conta do lanche entre os amigos, mas a variável pessoas ficou com 0:

const pessoas = 0;
const conta = 120;
const porPessoa = conta / pessoas;
console.log("Cada um paga:", porPessoa);
console.log(Number.isFinite(porPessoa));
console.log(Number.isFinite(40));
console.log(Number.isFinite(NaN));

$ node finito.js
Cada um paga: Infinity
false
true
false

Number.isFinite(valor) ("é finito?") responde true só para um número "normal": nem Infinity, nem -Infinity, nem NaN. É o teste mais completo para conferir se uma conta deu um resultado utilizável. Com o if, você vai poder avisar "ninguém para dividir a conta" antes de fazer a divisão.

Curiosidade: o -0

O number tem até um "zero negativo": 0 * -1 mostra -0 no Node. Na prática ele se comporta como zero (-0 === 0 dá true), e você quase nunca vai precisar se preocupar com ele.

4. A precisão: 0.1 + 0.2

Agora, o caso mais famoso do JavaScript:

console.log(0.1 + 0.2);
console.log(0.1 + 0.2 === 0.3);
console.log(0.3 - 0.1);
console.log(0.1 * 3);
console.log(1.1 * 3);
console.log(19.9 * 3);
console.log(0.5 + 0.25);

$ node precisao.js
0.30000000000000004
false
0.19999999999999998
0.30000000000000004
3.3000000000000003
59.699999999999996
0.75

Não é um defeito do Node, nem do JavaScript: o Python, o Java, o C e quase todas as linguagens dão o mesmo resultado, porque todas guardam decimais do mesmo jeito (um padrão chamado IEEE 754).

Por que isso acontece?

Tente escrever um terço em decimal: 0,3333333… Os 3 nunca acabam. Se você tiver espaço para só 16 algarismos, vai guardar 0,3333333333333333, que é quase um terço, mas não exatamente. E 1/3 + 1/3 + 1/3 com esses valores dá 0,9999999999999999, e não 1.

O computador guarda os números em binário (base 2), e na base 2 o 0,1 é como o 1/3 na base 10: uma dízima que não acaba. O computador guarda um valor muito próximo de 0,1, mas não exato. Somando dois valores "quase certos", o erro, que é minúsculo, às vezes aparece no 17º algarismo.

Repare na última linha: 0.5 + 0.25 deu exatamente 0.75. Metades, quartos e oitavos são "redondos" em binário, como 0,5 é redondo em decimal. Só alguns decimais têm o problema.

O problema na vida real: dinheiro

const chiclete = 1.1;
const bala = 2.2;
const total = chiclete + bala;
console.log("Total:", total);
console.log("Total:", total.toFixed(2));
console.log(total === 3.3);

$ node carrinho.js
Total: 3.3000000000000003
Total: 3.30
false

Um cliente nenhum gostaria de ver R$ 3.3000000000000003 na nota. E pior: o programa acha que o total não é 3,30 (a comparação deu false). Há três jeitos de lidar com isso.

Formas diferentes de lidar com a precisão

1) Arredondar na hora de mostrar: toFixed(2)

O valor.toFixed(2) devolve o número como texto, com exatamente 2 casas decimais (a linha do meio do carrinho.js: 3.30). É o suficiente quando o problema é só a aparência. Os detalhes estão em Formatando Números.

const total = 0.1 + 0.2;
console.log(total);
console.log(total.toFixed(2));
console.log(Math.round(total * 100) / 100);
console.log(Number(total.toFixed(2)));

$ node arredondar.js
0.30000000000000004
0.30
0.3
0.3

As duas últimas linhas arredondam e continuam com um número (não texto): Math.round arredonda para o inteiro mais próximo, então "multiplicar por 100, arredondar, dividir por 100" deixa 2 casas.

Missão: o programa mostra Total: 3.3000000000000003. Use o toFixed(2) na hora de mostrar o total, para aparecer Total: 3.30.

const chiclete = 1.1;
const bala = 2.2;
const total = chiclete + bala;
console.log("Total:", total);

const chiclete = 1.1;
const bala = 2.2;
const total = chiclete + bala;
console.log("Total:", total.toFixed(2));

2) Fazer as contas em centavos

Inteiros não têm o problema (até o limite de 9 quatrilhões, visto em Números). Então os programas de loja e de banco costumam guardar o dinheiro em centavos e só dividir por 100 na hora de mostrar:

const chiclete = 110;
const bala = 220;
const totalCentavos = chiclete + bala;
console.log("Total em centavos:", totalCentavos);
console.log("Total em reais:", totalCentavos / 100);
console.log(totalCentavos === 330);

$ node centavos.js
Total em centavos: 330
Total em reais: 3.3
true

Todas as contas foram com inteiros, então são exatas, e a comparação deu true. É o jeito mais seguro para dinheiro.

3) Comparar com tolerância: Number.EPSILON

Quando precisa comparar dois decimais, em vez de "são iguais?", pergunte "a diferença entre eles é minúscula?". O Number.EPSILON é a menor diferença que o number enxerga perto do 1:

const a = 0.1 + 0.2;
const b = 0.3;
console.log(Number.EPSILON);
console.log(Math.abs(a - b) < Number.EPSILON);

$ node epsilon.js
2.220446049250313e-16
true

Math.abs tira o sinal da diferença (o "valor absoluto"), e o < pergunta se ela é menor que o epsilon (cerca de 0,0000000000000002). Deu true: para todos os efeitos, são iguais. (Esse truque serve para números perto de 1; para números grandes, a tolerância precisa ser maior.)

SituaçãoUse
Só mostrar um valor bonito na telatotal.toFixed(2) (vira texto)
Arredondar e continuar fazendo contasMath.round(total * 100) / 100
Dinheiro: somar, multiplicar, compararCentavos (inteiros), divididos por 100 só para mostrar
Comparar dois decimais calculadosMath.abs(a - b) < Number.EPSILON
Saber se uma conta deu um número utilizávelNumber.isFinite(valor)

Quando dá errado

Nenhum dos problemas desta aula dá mensagem de erro. Os sintomas são valores estranhos na tela.

Apareceu NaN no resultado 
console.log(Number("4,50"));
console.log(Number("4.50"));

$ node virgula.js
NaN
4.5

Causa provável: um texto que não pôde virar número. O caso campeão no Brasil é a vírgula decimal que o usuário digitou: Number("4,50") dá NaN; Number("4.50") dá 4.5. Outros: "R$ 4.50", espaço no meio, texto vazio de propósito. Como consertar: confira com Number.isNaN logo depois de converter e, se for o caso, troque a vírgula por ponto antes (aula Substituindo).

O toFixed mostrou NaN 
const preco = Number("R$ 4,50");
console.log(preco.toFixed(2));

$ node fixednan.js
NaN

O toFixed não "conserta" um NaN: só formata. O problema está antes, na conversão. Como consertar: o mesmo do cenário anterior.

Testou === NaN e nunca deu true

Sintoma: valor === NaN é sempre false, mesmo quando o valor é NaN (seção 2). Como consertar: Number.isNaN(valor).

Apareceu Infinity

Causa provável: divisão por zero, quase sempre uma variável que ficou com 0 sem você esperar (zero pessoas, zero itens, zero dias). Como consertar: confira o divisor antes de dividir, ou o resultado com Number.isFinite.

Um valor com muitas casas (3.3000000000000003) ou uma comparação que devia dar true

Causa: a precisão dos decimais (seção 4). Como consertar: toFixed(2) para mostrar; centavos para dinheiro; tolerância para comparar.

O toFixed arredondou "errado" 
console.log((1.005).toFixed(2));
console.log((1.005).toFixed(20));
console.log((2.345).toFixed(2));

$ node fixed.js
1.00
1.00499999999999989342
2.35

Pela regra da escola, 1,005 arredondado para 2 casas daria 1,01. Saiu 1.00, porque o número guardado não é 1,005: é 1,00499999999999989342… (a segunda linha mostra com 20 casas), e esse número arredonda para baixo. Já o 2.345 arredondou para cima. É a mesma causa do 0.1 + 0.2. Para valores em que cada centavo importa, conte em centavos desde o começo.

Resumo

  • Contas com number nunca dão erro: quando não há resposta, o resultado é NaN ou Infinity, os dois do tipo number.
  • NaN ("não é um número") vem de conversões que falham e de contas impossíveis. Ele contagia todas as contas seguintes e não é igual nem a si mesmo: teste com Number.isNaN.
  • Infinity vem da divisão por zero e de números grandes demais. Number.isFinite confere se um valor é um número comum.
  • Decimais são guardados em binário e alguns (como 0,1) não são exatos: 0.1 + 0.2 dá 0.30000000000000004, em quase todas as linguagens.
  • Para mostrar: toFixed(2). Para dinheiro: conte em centavos. Para comparar decimais: Math.abs(a - b) < Number.EPSILON.
