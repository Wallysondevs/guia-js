JavaScript switch

Quando uma decisão depende de um único valor que pode ser uma entre várias opções exatas (o dia da semana, a opção do menu, a forma de pagamento), uma cadeia de else if fica repetitiva: if (dia === "sábado") … else if (dia === "domingo") … else if (dia === "segunda") …. O switch (em inglês, "chave seletora", como a de um painel) organiza isso: você diz qual valor olhar, e lista os casos.

Você vai aprender
  • As partes do switch: case ("caso"), break ("interromper") e default ("padrão").
  • Que o switch compara com ===: o texto "1" não casa com o número 1.
  • O que acontece quando você esquece o break, e como usar isso a seu favor para juntar casos.
  • Quando usar switch, else if ou um objeto como tabela.
  • Os erros reais: const repetida em dois case, dois default e o case com ||.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), salvos na pasta pessoal dela e executados com node arquivo.js (veja Rodando um Programa). Você pode rodar cada um no editor do guia.

A ideia: o atendimento por telefone

A Ana liga para a operadora do celular e ouve: "Digite 1 para segunda via da conta. Digite 2 para falar sobre a internet. Digite 3 para cancelar. Para outros assuntos, aguarde."

  • Tudo depende de um valor só: a tecla que ela apertou.
  • Cada tecla leva a um caso diferente.
  • Se ela apertar uma tecla que não está no menu (o 7, por exemplo), cai no atendimento padrão.

O switch é esse menu.

1. O primeiro switch

const opcao = 2;

switch (opcao) {
  case 1:
    console.log("Segunda via da conta.");
    break;
  case 2:
    console.log("Falar sobre a internet.");
    break;
  case 3:
    console.log("Cancelamento.");
    break;
  default:
    console.log("Aguarde um atendente.");
}

console.log("Obrigado por ligar.");
switch (opcao)
O valor que vai ser olhado, entre parênteses. Pode ser uma variável ou uma expressão qualquer.
{ … }
Todos os casos ficam dentro de um par de chaves.
case 1:
"Caso seja 1". Repare nos dois-pontos no fim. As linhas depois dele, até o break, são o que acontece nesse caso.
break;
"Interromper": sai do switch e continua depois da }. Sem ele, acontece uma surpresa (seção 3).
default:
"Padrão": o caso de quem não casou com nenhum case. É opcional e costuma ir no fim, onde não precisa de break.
$ node menu.js
Falar sobre a internet.
Obrigado por ligar.

O que o Node fez: comparou opcao com o 1 (não é), com o 2 (é!), rodou as linhas desse caso, encontrou o break e saiu. O case 3 e o default nem foram olhados. Com opcao valendo 7, nenhum case casaria, e apareceria Aguarde um atendente..

A mesma coisa com else if, para comparar:

const opcao = 2;

if (opcao === 1) {
  console.log("Segunda via da conta.");
} else if (opcao === 2) {
  console.log("Falar sobre a internet.");
} else if (opcao === 3) {
  console.log("Cancelamento.");
} else {
  console.log("Aguarde um atendente.");
}

$ node menu-if.js
Falar sobre a internet.

Mesma saída. O switch evita repetir opcao === em cada linha, e deixa claro, logo no começo, que tudo depende de opcao.

2. O switch compara com ===

A comparação de cada case é a estrita, o === (veja Comparação): o valor e o tipo têm de ser iguais. Isso pega quem recebe a opção como texto (do teclado, de um formulário) e escreve os casos com números:

const opcao = "2";

switch (opcao) {
  case 1:
    console.log("Segunda via da conta.");
    break;
  case 2:
    console.log("Falar sobre a internet.");
    break;
  default:
    console.log("Aguarde um atendente.");
}

$ node texto.js
Aguarde um atendente.

O texto "2" não é === ao número 2, então caiu no default. Como consertar: deixe os dois do mesmo tipo. Ou converta antes, com switch (Number(opcao)) (veja Conversão), ou escreva os casos como texto: case "2":.

Com textos, valem as mesmas regras do ===: maiúsculas importam, e um espaço a mais faz diferença. Um truque comum é padronizar o valor antes: switch (resposta.trim().toLowerCase()) (veja Métodos de String).

3. O break esquecido: o código "escorrega"

Quando um case casa, o Node começa a rodar dali para baixo e só para no break (ou no fim do switch). Ele não para no próximo case! Veja o que acontece sem os break:

const opcao = 1;

switch (opcao) {
  case 1:
    console.log("Segunda via da conta.");
  case 2:
    console.log("Falar sobre a internet.");
  case 3:
    console.log("Cancelamento.");
  default:
    console.log("Aguarde um atendente.");
}

$ node sembreak.js
Segunda via da conta.
Falar sobre a internet.
Cancelamento.
Aguarde um atendente.

A Ana pediu a segunda via e, de quebra, recebeu o cancelamento! Uma vez dentro do case 1, o Node continuou descendo pelos outros casos sem testar mais nada, até o fim. Em inglês, isso se chama fall-through ("cair através"). Não há mensagem de erro: o JavaScript acha que você fez de propósito.

Regra prática

Todo case termina com break, a não ser que você queira juntar casos, como na próxima seção. Quando o Node chega ao default no fim, o switch acaba de qualquer jeito; muita gente põe break nele também, por costume, e não faz mal.

4. Vários casos, uma resposta

O "escorregão" vira recurso quando vários valores têm a mesma resposta. A padaria abre em horários diferentes no fim de semana:

const dia = "domingo";

switch (dia) {
  case "sábado":
  case "domingo":
    console.log("Abrimos das 7h às 13h.");
    break;
  case "segunda":
    console.log("Fechado para descanso.");
    break;
  default:
    console.log("Abrimos das 6h às 20h.");
}

$ node horario.js
Abrimos das 7h às 13h.

O case "sábado": não tem nada embaixo dele. Se o dia fosse sábado, o Node entraria ali, escorregaria para o case "domingo":, mostraria o horário e pararia no break. Os dois casos empilhados se leem como "sábado ou domingo".

5. Faixas de valores: o switch (true)

O case compara com ===, então não serve diretamente para faixas como "nota de 7 a 8,9". Existe um truque que você vai encontrar em código dos outros: switch (true), com uma comparação em cada case:

const nota = 7.5;

switch (true) {
  case nota >= 9:
    console.log("Conceito A");
    break;
  case nota >= 7:
    console.log("Conceito B");
    break;
  default:
    console.log("Conceito C ou D");
}

$ node switchtrue.js
Conceito B

Funciona porque nota >= 7 vale true, e true === true. Mas é um truque: quem lê precisa parar para entender. Para faixas, a cadeia de else if da aula else e else if é mais clara.

Formas diferentes de fazer a mesma coisa

Quando cada caso só escolhe um valor (e não faz ações diferentes), existe uma terceira forma: um objeto usado como tabela (objetos têm aula própria: Objetos; aqui, só olhe a ideia):

const frete = {
  norte: 35,
  nordeste: 30,
  sudeste: 15,
  sul: 20,
};

const regiao = "sul";
console.log(`Frete: R$ ${frete[regiao] ?? 25}`);

$ node tabela.js
Frete: R$ 20

O frete[regiao] procura a região na tabela; se ela não estiver lá, o ?? 25 faz o papel do default (veja ?. e ??).

SituaçãoQual usar
Um valor, várias opções exatas, cada uma com ações diferentesswitch
Faixas (>=, <) ou condições que olham coisas diferentesif … else if
Cada opção só escolhe um valor (preço, texto, cor)Objeto como tabela
Só duas opçõesif … else ou o ternário (aula O Operador Ternário)

case com ||

Este não dá erro. A Ana tentou escrever "sábado ou domingo" num case só:

const dia = "domingo";

switch (dia) {
  case "sábado" || "domingo":
    console.log("Fim de semana!");
    break;
  default:
    console.log("Dia útil.");
}

$ node caseou.js
Dia útil.

Domingo virou dia útil! O "sábado" || "domingo" é calculado antes da comparação, e vale "sábado" (o primeiro valor truthy; veja Truthy e Falsy). Então esse case é só case "sábado":. Como consertar: empilhe os casos, como na seção 4: case "sábado": numa linha e case "domingo": na outra.

Resumo

  • switch (valor) compara um único valor com vários case, de cima para baixo, usando === (valor e tipo iguais).
  • Quando um case casa, o Node roda dali para baixo até o break; sem break, ele escorrega para os casos seguintes.
  • default pega o que não casou com nenhum case; é opcional e só pode haver um.
  • Casos empilhados (case "sábado": case "domingo":) dividem a mesma resposta. case a || b não funciona.
  • Os case dividem o mesmo bloco: para criar const dentro de um caso, use chaves.
  • Para faixas, prefira else if; para só escolher valores, um objeto como tabela.
