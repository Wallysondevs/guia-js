JavaScript BigInt

Na aula NaN, Infinity e a Precisão você viu que o tipo number do JavaScript tem limites. Um deles pega quem trabalha com números inteiros muito grandes: depois de 9007199254740991 (uns 9 quatrilhões), o JavaScript começa a errar contas de somar 1. Para esses casos existe um segundo tipo de número, o bigint (de big integer, "inteiro grande"): ele guarda inteiros de qualquer tamanho, sem perder nenhum dígito.

Você vai aprender
  • Por que o number comum erra com inteiros gigantes, e qual é o maior inteiro "seguro".
  • Como criar um BigInt: o n no fim do número (123n) e a função BigInt().
  • As contas com BigInt, e a pegadinha da divisão (que joga fora as casas decimais).
  • Comparar BigInt com number, e converter de um tipo para o outro.
  • Os erros reais mais comuns: misturar BigInt com number numa conta, usar o Math e o JSON.stringify com BigInt.
  • Quando usar (e quando não usar) o BigInt.

A ideia: o hodômetro que tem dígitos de menos

Pense no hodômetro de um carro antigo, aquele marcador de quilômetros com rodinhas de números. Ele tem, digamos, 6 rodinhas. Enquanto o carro rodou menos de 999999 km, a conta está certa. Depois disso, não há rodinha para o próximo dígito, e o marcador começa a mostrar coisas erradas.

O number do JavaScript é parecido: ele guarda cada número num espaço de tamanho fixo (64 bits, o mesmo para qualquer número). Nesse espaço cabem os inteiros exatos até 9007199254740991. Daí para cima, ele ainda guarda números enormes, mas aproximados: os últimos dígitos viram "chute".

O bigint é um hodômetro que ganha rodinhas novas sempre que precisa. Ele cresce quanto for necessário e nunca arredonda. O preço disso: ele só guarda inteiros (nada de 2.5) e não se mistura com o number comum, como você vai ver.

1. O problema: o number perde a conta

console.log(Number.MAX_SAFE_INTEGER);
console.log(9007199254740991 + 1);
console.log(9007199254740991 + 2);
console.log(2 ** 64);

Uma constante pronta do JavaScript: o maior inteiro seguro ("max safe integer"). Até ele, todo inteiro é guardado exatamente.
9007199254740991 + 1
O primeiro número depois do limite.
9007199254740991 + 2
O segundo. A conta de cabeça dá 9007199254740993.
2 ** 64
2 elevado a 64 (o ** é a potência; veja Operadores Aritméticos). De cabeça, ninguém sabe; a resposta exata é 18446744073709551616.
$ node limite.js
9007199254740991
9007199254740992
9007199254740992
18446744073709552000

Duas surpresas:

  • + 1 e + 2 deram o mesmo resultado. O 9007199254740993 simplesmente não existe para o number: não há "rodinha" para ele, então o JavaScript arredonda para o vizinho que ele consegue guardar.
  • 2 ** 64 terminou em ...552000, com três zeros que não deviam estar ali. O número certo termina em ...551616.

Nenhum erro, nenhum aviso: o resultado só sai errado em silêncio. Para preço de pão e nota de prova isso nunca acontece, porque são números pequenos. Mas acontece com números de identificação muito longos (como os de alguns sistemas e redes sociais), com contas de matemática que crescem rápido (fatorial, potências) e com criptografia.

2. Criando um BigInt: o n no fim

Para dizer ao JavaScript "este número é um BigInt", escreva um n colado no fim dele, sem espaço:

const grande = 9007199254740991n;
console.log(grande + 1n);
console.log(grande + 2n);
console.log(2n ** 64n);
console.log(typeof grande);
9007199254740991n
O n no fim transforma o número num BigInt. Ele aparece também na saída, para você saber que o valor é um BigInt.
grande + 1n
Numa conta com BigInt, os dois lados têm de ser BigInt: por isso o 1n, e não 1.
2n ** 64n
A mesma potência de antes, agora com BigInt.
typeof grande
O typeof (veja Descobrindo o Tipo) responde "bigint": é um tipo próprio, diferente de "number".
$ node criar.js
9007199254740992n
9007199254740993n
18446744073709551616n
bigint

Agora o + 2n deu 9007199254740993n, exato, e a potência deu todos os dígitos certos. O console.log do Node mostra o n no fim de cada BigInt.

Separador de milhares também vale

Como nos números comuns (veja Números), você pode usar o _ para separar os grupos de dígitos e facilitar a leitura: 1_000_000n é o mesmo que 1000000n. No lab, console.log(1_000_000n) mostrou 1000000n.

Missão: este programa calcula 2 elevado a 64 com number e mostra o resultado arredondado. Transforme a conta em BigInt (ponha o n nos dois números) para ver todos os dígitos certos.

const resultado = 2 ** 64;
console.log(resultado);

const resultado = 2n ** 64n;
console.log(resultado);

3. Criando um BigInt com a função BigInt()

Quando o valor já está numa variável, ou chega como texto, não dá para "colar um n". Para isso existe a função BigInt(), que converte:

const quantidade = 500;
console.log(BigInt(quantidade));
console.log(BigInt("123456789012345678901234567890"));
console.log(BigInt(9007199254740993));
console.log(BigInt("9007199254740993"));

$ node funcao.js
500n
123456789012345678901234567890n
9007199254740992n
9007199254740993n

Repare nas duas últimas linhas, que parecem iguais mas não são:

  • BigInt(9007199254740993) recebe um number. Esse número já foi arredondado para 9007199254740992 antes de chegar à função (lembre da seção 1), e o BigInt() só pode converter o que recebeu: o erro veio junto.
  • BigInt("9007199254740993") recebe um texto. Texto guarda todos os dígitos, então a conversão sai exata.

Regra prática: para números grandes, crie o BigInt com o n no fim ou a partir de um texto, nunca de um number grande.

Sem new

Escreva BigInt(500), e não new BigInt(500). Com new, o JavaScript recusa: TypeError: BigInt is not a constructor ("BigInt não é um construtor").

4. As contas com BigInt

As operações de sempre funcionam (veja Operadores Aritméticos): +, -, *, ** e o resto %. A divisão é diferente: como o BigInt só guarda inteiros, ela joga fora a parte depois da vírgula.

console.log(10n * 3n + 1n);
console.log(7n / 2n);
console.log(-7n / 2n);
console.log(7n % 2n);
console.log(7 / 2);

$ node contas.js
31n
3n
-3n
1n
3.5
7n / 2n → 3n
7 dividido por 2 dá 3,5; o BigInt corta o ,5 e fica com 3n. Ele não arredonda para cima: só descarta o que sobra.
-7n / 2n → -3n
Com número negativo também corta em direção ao zero: -3,5 vira -3n (e não -4n).
7n % 2n → 1n
O resto da divisão funciona normalmente.
7 / 2 → 3.5
Com number comum, a divisão mantém a parte decimal.

Um exemplo de verdade: fatorial

O fatorial de um número é a multiplicação de 1 até ele: o fatorial de 5 é 1 × 2 × 3 × 4 × 5 = 120. Ele cresce muito rápido. Veja o fatorial de 25 calculado dos dois jeitos (o laço for, que repete a multiplicação, tem aula própria: for; aqui, repare só no resultado):

let comNumber = 1;
let comBigInt = 1n;
for (let i = 1; i <= 25; i++) {
  comNumber = comNumber * i;
  comBigInt = comBigInt * BigInt(i);
}
console.log(comNumber);
console.log(comBigInt);

$ node fatorial.js
1.5511210043330986e+25
15511210043330985984000000n

O number desistiu de mostrar os dígitos e passou para a notação científica: 1.5511210043330986e+25 quer dizer "1,5511… vezes 10 elevado a 25", um valor aproximado. O BigInt mostrou o número inteiro, com todos os 26 dígitos. Repare no BigInt(i): o contador i é um number, e para multiplicar com um BigInt ele precisa ser convertido.

Experimente: o programa calcula o fatorial de 20 com BigInt, mas dá erro. Leia a mensagem no terminal da caixa e conserte a linha da multiplicação (dica: o i é um number).

let fatorial = 1n;
for (let i = 1; i <= 20; i++) {
  fatorial = fatorial * i;
}
console.log(fatorial);

let fatorial = 1n;
for (let i = 1; i <= 20; i++) {
  fatorial = fatorial * BigInt(i);
}
console.log(fatorial);

5. Comparando BigInt com number

Para fazer conta, BigInt e number não se misturam. Para comparar, misturam sim (os sinais de comparação têm aula própria: Comparação):

console.log(2n > 1);
console.log(1n == 1);
console.log(1n === 1);
console.log(0n ? "sim" : "não");

$ node comparar.js
true
true
false
não
2n > 1 → true
>, <, >= e <= comparam o valor, mesmo entre tipos diferentes.
1n == 1 → true
O == (igualdade "frouxa") acha que são iguais: o valor é o mesmo.
1n === 1 → false
O === (igualdade estrita, a que o guia recomenda) olha também o tipo: bigint não é number, então dá false. Para comparar com ===, deixe os dois do mesmo tipo: 1n === 1n dá true.
0n ? … : …
Numa condição, 0n conta como "falso", igual ao 0 (veja Truthy e Falsy). O ? : é o operador ternário (aula própria).

6. Convertendo de volta para number e para texto

const pequeno = 10n;
console.log(Number(pequeno));
console.log(String(pequeno));
console.log(`Total: ${pequeno}`);
console.log(Number(2n ** 64n));

$ node voltar.js
10
10
Total: 10
18446744073709552000
  • Number(…) transforma o BigInt em number. Para valores pequenos, perfeito. Para valores gigantes, a precisão se perde de novo (última linha): o number continua sem "rodinhas" para tantos dígitos.
  • String(…) e a template string (veja Template Strings) viram texto sem o n. O n só aparece quando o console.log mostra o BigInt sozinho.

Missão final: o grão de arroz no tabuleiro

Missão: conta a lenda que um sábio pediu ao rei 1 grão de arroz na primeira casa do tabuleiro de xadrez, 2 na segunda, 4 na terceira, dobrando até a casa 64. O total de grãos é 2 ** 64 - 1. O programa abaixo calcula com number e mostra um valor arredondado (e errado). Reescreva a conta com BigInt para mostrar o número exato.

const graos = 2 ** 64 - 1;
console.log("Total de grãos:");
console.log(graos);

const graos = 2n ** 64n - 1n;
console.log("Total de grãos:");
console.log(graos);

No lab, a versão com number mostrou 18446744073709552000 (o - 1 nem fez diferença, de tão aproximado que é o valor), e a versão com BigInt mostrou 18446744073709551615n: mais de 18 quintilhões de grãos.

Resumo

  • O number guarda inteiros exatos só até Number.MAX_SAFE_INTEGER (9007199254740991). Depois disso, os resultados saem arredondados, sem erro nenhum.
  • O bigint guarda inteiros de qualquer tamanho. Crie com o n no fim (123n) ou com BigInt(valor); para números grandes, use o n ou um texto.
  • As contas funcionam com + - * ** %; a divisão / descarta as casas decimais (7n / 2n é 3n).
  • BigInt e number não se misturam em contas (TypeError): converta com BigInt() ou Number(). Para comparar, misturam (2n > 1), mas 1n === 1 é false.
  • O Math e o JSON.stringify não aceitam BigInt. Para o dia a dia (preços, notas, contagens), continue com number.
