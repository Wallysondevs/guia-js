JavaScript Formatando Números

Para o computador, o salário da Ana é 3518.5. Para a Ana, é R$ 3.518,50. O número é o mesmo; o que muda é o jeito de mostrar. O JavaScript escreve os números no formato americano (ponto nas casas decimais, sem separar os milhares), e quase nunca é assim que a gente quer exibir um preço, uma nota ou uma porcentagem. Esta aula mostra as ferramentas para transformar um número num texto bem apresentado: o toFixed, o toLocaleString e o Intl.NumberFormat.

Você vai aprender
  • Como fixar o número de casas decimais com toFixed, e por que o resultado é texto.
  • Como escrever no jeito brasileiro (1.234,5) com toLocaleString("pt-BR").
  • Como mostrar dinheiro (R$ 3.518,50, US$, €) com style: "currency".
  • Como controlar as casas decimais, mostrar porcentagem, números curtos (2,3 mi) e unidades (42,195 km).
  • Como pôr zeros à esquerda (0007) e alinhar colunas com padStart e padEnd.
  • Os erros reais: toFixed is not a function, o código de moeda inválido, o 5.toFixed e as contas com texto.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook, sistema em português do Brasil), com node arquivo.js. O toLocaleString e o Intl são da linguagem: funcionam no Node e no navegador.

A ideia: o número é o mesmo, a etiqueta muda

Na prateleira da padaria, o queijo custa cinquenta e quatro reais e oitenta centavos. O dono escreve na etiqueta R$ 54,80. Um turista americano escreveria $54.80; um alemão, 54,80 €. O valor não mudou: mudou só a etiqueta.

No programa é a mesma coisa:

  • o número (54.8) é o que você usa nas contas. Ele é escrito sempre do jeito do JavaScript, com ponto;
  • a etiqueta ("R$ 54,80") é um texto, feito na hora de mostrar. Ela não serve mais para contas.

A regra de ouro desta aula: faça as contas com números e formate só no fim, na hora do console.log (ou de pôr na página).

1. Casas decimais: toFixed

Fixed quer dizer "fixo": o toFixed(n) devolve o número com exatamente n casas depois do ponto, arredondando se precisar.

const preco = 13.8915;

console.log(preco.toFixed(2));
console.log(preco.toFixed(1));
console.log(preco.toFixed(0));
console.log((5).toFixed(2));
console.log(typeof preco.toFixed(2));

Como o toFixed usa ponto, para o jeito brasileiro dá para trocar o ponto por vírgula (veja replace). Funciona, mas a seção seguinte tem um jeito melhor, que também separa os milhares:

const preco = 19.9;
const texto = `R$ ${preco.toFixed(2).replace(".", ",")}`;
console.log(texto);

2. O jeito brasileiro: toLocaleString("pt-BR")

Locale é a "localidade": o conjunto de costumes de um país e língua para escrever números, datas e moedas. O código "pt-BR" quer dizer "português do Brasil". O toLocaleString ("para texto da localidade") escreve o número do jeito daquele lugar:

const salario = 3518.5;

console.log(salario.toLocaleString("pt-BR"));
console.log(salario.toLocaleString("en-US"));
console.log(salario.toLocaleString("de-DE"));
console.log((1234567.891).toLocaleString("pt-BR"));

$ node locale.js
3.518,5
3,518.5
3.518,5
1.234.567,891

No Brasil (pt-BR) e na Alemanha (de-DE), ponto separa os milhares e vírgula separa as decimais; nos Estados Unidos (en-US), é o contrário. Repare que o salário saiu 3.518,5, com uma casa só: para dinheiro, falta dizer que é dinheiro.

Sempre diga a localidade

Sem nada entre os parênteses, salario.toLocaleString() usa a localidade do computador (ou do navegador) de quem roda o programa. No computador da Ana sai do jeito brasileiro; no de um amigo nos EUA, do jeito americano. Escrevendo "pt-BR", o resultado é o mesmo em qualquer lugar.

3. Dinheiro: style: "currency"

Depois da localidade, o toLocaleString aceita um objeto de opções. Para dinheiro, são duas: style: "currency" ("estilo: moeda") e currency, o código da moeda, com 3 letras maiúsculas ("BRL" é o real; "USD", o dólar americano; "EUR", o euro):

const salario = 3518.5;

console.log(salario.toLocaleString("pt-BR", { style: "currency", currency: "BRL" }));
console.log(salario.toLocaleString("en-US", { style: "currency", currency: "USD" }));
console.log(salario.toLocaleString("pt-BR", { style: "currency", currency: "USD" }));
console.log(salario.toLocaleString("de-DE", { style: "currency", currency: "EUR" }));

Formatando muitos números: Intl.NumberFormat

Repetir as opções em cada linha cansa. O Intl.NumberFormat (Intl de "internacionalização") cria um formatador uma vez só; depois, você usa o .format(numero) dele quantas vezes quiser. Por dentro, o toLocaleString faz exatamente isso.

const real = new Intl.NumberFormat("pt-BR", { style: "currency", currency: "BRL" });

const precos = [4.5, 12, 1299.9, 0.99];
for (const preco of precos) {
  console.log(real.format(preco));
}

O espaço depois do R$ não é um espaço comum

Entre o R$ e o número, o Intl põe um espaço inquebrável (o caractere 160, chamado em inglês no-break space): ele impede que o R$ fique no fim de uma linha e o número na linha de baixo. Na tela parece igual, mas numa comparação não é:

const texto = (3518.5).toLocaleString("pt-BR", { style: "currency", currency: "BRL" });

console.log(texto === "R$ 3.518,50");
console.log(texto.charCodeAt(2));
console.log(texto.replace(/\s/g, " ") === "R$ 3.518,50");

$ node espaco.js
false
160
true

A comparação com um espaço comum dá false; o caractere da posição 2 é o 160 (o espaço comum é o 32). Se precisar comparar, troque os espaços especiais com replace(/\s/g, " ") (o \s quer dizer "qualquer espaço"; veja Expressões Regulares). Para mostrar, não precisa fazer nada.

4. Controlando as casas decimais

Fora do dinheiro, o toLocaleString mostra até 3 casas e corta os zeros do fim. Duas opções mudam isso: minimumFractionDigits ("mínimo de casas decimais") e maximumFractionDigits ("máximo de casas decimais"):

const opcoes = { minimumFractionDigits: 2, maximumFractionDigits: 2 };

console.log((7).toLocaleString("pt-BR", opcoes));
console.log((7.456).toLocaleString("pt-BR", opcoes));
console.log((1500).toLocaleString("pt-BR", opcoes));
console.log((7.456).toLocaleString("pt-BR", { maximumFractionDigits: 1 }));

$ node casas.js
7,00
7,46
1.500,00
7,5

Com mínimo e máximo iguais a 2, é o toFixed(2) do jeito brasileiro, com milhares separados. Só o máximo, como na última linha, serve para notas (7,5) sem completar com zeros.

6. Zeros à esquerda e colunas alinhadas

O número do pedido aparece como 0007 na comanda; a senha da fila, como 042. Para isso, transforme o número em texto e complete à esquerda com o padStart ("preencher no começo", veja Métodos de String):

const pedido = 7;
const senha = 42;

console.log(String(pedido).padStart(4, "0"));
console.log(`Senha ${String(senha).padStart(3, "0")}`);
console.log((5).toLocaleString("pt-BR", { minimumIntegerDigits: 2 }));

$ node zeros.js
0007
Senha 042
05

padStart(4, "0") quer dizer: "complete com "0" no começo até o texto ter 4 caracteres". A última linha mostra o mesmo efeito pelo Intl, com minimumIntegerDigits ("mínimo de dígitos inteiros"). Juntando padEnd (preencher no fim) e padStart, dá para montar um cupom com as colunas alinhadas:

const itens = [
  ["Pão francês", 4.5],
  ["Leite", 6.25],
  ["Café 500 g", 21.9],
  ["Queijo", 54.8]
];
const real = new Intl.NumberFormat("pt-BR", { style: "currency", currency: "BRL" });

let total = 0;
for (const [nome, preco] of itens) {
  console.log(`${nome.padEnd(12, ".")} ${real.format(preco).padStart(10)}`);
  total += preco;
}
console.log(`${"TOTAL".padEnd(12, ".")} ${real.format(total).padStart(10)}`);

$ node tabela.js
Pão francês.    R$ 4,50
Leite.......    R$ 6,25
Café 500 g..   R$ 21,90
Queijo......   R$ 54,80
TOTAL.......   R$ 87,45

Repare: a soma (total += preco) é feita com os números; o real.format só entra na hora de mostrar. O padStart(10) sem o segundo valor completa com espaços.

"Erro de sintaxe: símbolo inválido ou inesperado". Logo depois de um número, o JavaScript lê o ponto como o ponto decimal (5. é o número 5,0) e não entende o toFixed que vem depois. É um erro de sintaxe, então o programa nem começa a rodar. Como consertar: (5).toFixed(2), ou guarde o número numa variável antes. Com números quebrados não há problema: (2.5).toFixed(1) e 2.5.toFixed(1) funcionam.

O toFixed arredondou "errado" 
console.log((1.005).toFixed(2));
console.log((2.345).toFixed(2));
console.log((2.5).toFixed(0), (3.5).toFixed(0));

$ node arred.js
1.00
2.35
3 4

Pela regra da escola, 1.005 com 2 casas seria 1.01, mas saiu 1.00. O computador guarda 1.005 como um número binário um tiquinho menor (algo como 1,00499999…), e o toFixed arredonda esse número de verdade. É a mesma causa do 0.1 + 0.2 (veja A Precisão). Para mostrar preços, isso quase nunca importa. Para contas de dinheiro que precisam ser exatas, trabalhe em centavos inteiros (1005 centavos) e divida por 100 só na hora de mostrar.

Tentou converter o texto formatado de volta 
console.log(Number("3.518,50"));
console.log(Number("3518.50"));

$ node fmt-pt.js
NaN
3518.5

O Number só entende o formato do JavaScript. Mais um motivo para guardar o número e formatar só na saída. Se o texto veio de uma pessoa ("3.518,50"), tire os pontos e troque a vírgula antes: Number(texto.replaceAll(".", "").replace(",", ".")).

Resumo

  • Faça as contas com números e formate só na hora de mostrar: toda formatação devolve texto.
  • x.toFixed(n): exatamente n casas, com ponto. Bom para arquivos e para o "jeito do computador".
  • x.toLocaleString("pt-BR"): o jeito brasileiro (3.518,5). Com { style: "currency", currency: "BRL" }: R$ 3.518,50.
  • Para formatar muitos números, crie um new Intl.NumberFormat("pt-BR", opções) e use o .format(x).
  • Outras opções: minimumFractionDigits/maximumFractionDigits, style: "percent", notation: "compact", style: "unit". Zeros à esquerda: padStart.
  • O espaço depois do R$ é inquebrável (caractere 160); o currency leva o código ("BRL"), não o símbolo.
