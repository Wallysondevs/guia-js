JavaScript null e undefined

Nem toda caixa tem alguma coisa dentro. Às vezes a variável ainda não recebeu valor, às vezes o dado procurado não existe, às vezes você quer dizer de propósito "aqui não tem nada". O JavaScript tem dois valores para representar o "nada": undefined ("indefinido") e null ("nulo"). Eles se parecem, mas não são a mesma coisa, e confundir os dois (ou esquecer que eles existem) causa o erro mais famoso do JavaScript: Cannot read properties of undefined.

Você vai aprender
  • O que é undefined e onde ele aparece sozinho: variável sem valor, propriedade que não existe, posição vazia de uma lista.
  • O que é null: o "vazio" que você coloca de propósito.
  • A diferença entre "undefined" e "is not defined".
  • Como comparar: null === undefined × null == undefined, e a esquisitice do typeof null.
  • Como dar um valor padrão com ??.
  • Os erros reais: Cannot read properties of null e of undefined.

A ideia: a ficha de cadastro

Imagine a ficha de cadastro da academia, em papel. Ela tem um campo "Segundo nome". Há duas situações em que esse campo fica sem nada escrito:

  • Ninguém preencheu ainda. A ficha acabou de ser impressa; o campo está em branco porque ninguém chegou nele. Isso é o undefined: "ainda não tem valor", "não sei".
  • A pessoa respondeu "não tenho". A Ana não tem segundo nome, e a atendente marcou um traço no campo: "—". Isso é o null: "a resposta é: nenhum". Foi alguém que decidiu.

Na prática: o JavaScript põe undefined sozinho quando falta alguma coisa; você põe null quando quer dizer "vazio, de propósito".

Não houve erro. undefined é um valor de verdade, que o programa pode mostrar, guardar e comparar. Ele só diz: "esta caixa existe, mas ninguém pôs nada nela".

Com const não dá

Uma constante precisa nascer com valor, porque depois ela não pode mudar. const apelido; dá SyntaxError: Missing initializer in const declaration ("falta o valor inicial na declaração const"; veja Constantes).

2. Outros lugares onde o undefined aparece

Sempre que você pede ao JavaScript uma coisa que não existe, ele responde undefined em vez de dar erro. Três casos comuns (objetos, arrays e funções têm aulas próprias; aqui, olhe só o undefined):

const aluna = { nome: "Ana", idade: 30 };
console.log(aluna.telefone);
const frutas = ["maçã", "banana"];
console.log(frutas[5]);
function cumprimentar() {
  console.log("Oi!");
}
const resposta = cumprimentar();
console.log(resposta);
aluna.telefone
O objeto aluna (aula Objetos) tem nome e idade, mas não tem telefone. Pedir uma propriedade que não existe dá undefined.
frutas[5]
A lista frutas (aula Arrays) tem só 2 itens. A posição 5 está vazia: undefined.
const resposta = cumprimentar();
A função cumprimentar (aula Funções) mostra Oi!, mas não devolve nenhum valor (não tem return). Então o que chega em resposta é undefined.
$ node ondeaparece.js
undefined
undefined
Oi!
undefined
Viu um undefined inesperado na tela?

Ele é uma pista: alguma coisa que o programa procurou não estava lá. Os suspeitos de sempre são um nome escrito errado (aluna.Nome em vez de aluna.nome), uma posição que não existe na lista, ou uma função que esqueceu o return.

3. null: o vazio de propósito

O null nunca aparece sozinho: é sempre o programador que o escreve. Ele quer dizer "aqui não tem nada, e eu sei disso". Na gincana da escola, ainda não há vencedor:

let vencedor = null;
console.log(vencedor);
console.log(typeof vencedor);
vencedor = "Bia";
console.log(vencedor);

$ node nulo.js
null
object
Bia
let vencedor = null;
A variável nasce com null: "ainda não tem vencedor", dito com todas as letras. Quem ler o código entende que o vazio foi intencional.
typeof vencedor → object
Uma esquisitice famosa: o typeof null diz "object", embora o null não seja um objeto. É um erro da primeira versão do JavaScript, de 1995, que nunca foi consertado para não quebrar os sites antigos. Não use o typeof para reconhecer um null; use valor === null (seção 5).
vencedor = "Bia";
Quando a gincana termina, a variável recebe o valor de verdade.

Num objeto, os dois aparecem lado a lado, e o Node mostra cada um com o seu nome:

const cadastro = { nome: "Ana", segundoNome: null, apelido: undefined };
console.log(cadastro);
console.log(cadastro.segundoNome);
console.log(cadastro.apelido);
console.log(cadastro.cidade);

$ node objeto.js
{ nome: 'Ana', segundoNome: null, apelido: undefined }
null
undefined
undefined

Repare nas duas últimas linhas: apelido existe no objeto com o valor undefined, e cidade nem existe, mas as duas leituras dão o mesmo undefined. Por isso a regra prática do guia: não escreva undefined à mão. Quando quiser dizer "vazio", escreva null; deixe o undefined para o JavaScript.

Experimente: a variável vencedor foi criada sem valor e mostra undefined. Deixe claro que o vazio é de propósito: faça ela nascer com null. Depois, se quiser, dê a ela o nome de um vencedor e rode de novo.

let vencedor;
console.log(vencedor);

let vencedor = null;
console.log(vencedor);

5. Comparando: === e ==

console.log(null === undefined);
console.log(null == undefined);
console.log(null === null);
let x;
console.log(x === undefined);
console.log(null == 0);
console.log(undefined == false);

$ node comparar.js

true
true
true
false

null === undefined → false
O === (igualdade estrita) compara valor e tipo: são dois valores diferentes, de tipos diferentes.
null == undefined → true
O == (igualdade "frouxa") tem uma regra especial: null e undefined são iguais entre si.
null === null e x === undefined → true
É assim que se pergunta "este valor é null?" e "este valor é undefined?".
null == 0 e undefined == false → false
Mesmo com ==, eles não são iguais a zero nem a false. Só um ao outro.

O guia recomenda sempre o === (a aula Comparação explica por quê). Para perguntar "tem valor ou não?", compare com os dois: valor === null || valor === undefined. Ou use o atalho da próxima seção.

6. Valor padrão com ??

O operador ?? (dois pontos de interrogação, chamado de nullish coalescing, algo como "junção do nulo") quer dizer: "use o valor da esquerda; se ele for null ou undefined, use o da direita".

let apelido;
console.log(apelido ?? "sem apelido");
apelido = "Aninha";
console.log(apelido ?? "sem apelido");
const desconto = 0;
console.log(desconto ?? 10);
console.log(desconto || 10);

$ node padrao.js
sem apelido
Aninha
0
10
apelido ?? "sem apelido"
Na primeira vez, apelido é undefined, então vale o da direita: sem apelido. Na segunda, ele tem valor, e o valor é usado: Aninha.
desconto ?? 10 → 0
O 0 é um valor de verdade (desconto zero), não é null nem undefined: o ?? mantém o 0.
desconto || 10 → 10
O || ("ou", da aula Operadores Lógicos) é parecido, mas troca qualquer valor que conte como falso, inclusive o 0 e o texto vazio. Aqui, o desconto zero sumiu e virou 10: um erro de conta.

O ?? e o seu primo ?. (que lê uma propriedade sem dar erro quando o valor é null/undefined) têm aula própria: ?. e ??.

Missão: quando ninguém fez login, usuario é null e o programa mostra Olá, null!. Use o ?? na segunda linha para mostrar Olá, visitante! nesse caso.

const usuario = null;
const nomeNaTela = usuario;
console.log(`Olá, ${nomeNaTela}!`);

const usuario = null;
const nomeNaTela = usuario ?? "visitante";
console.log(`Olá, ${nomeNaTela}!`);

  • Numa conta, null vira 0 (por isso null + 1 dá 1) e undefined vira NaN, o "não é um número" (veja NaN, Infinity e a Precisão). Um NaN no resultado de uma conta muitas vezes é um undefined escondido.
  • Num texto, eles aparecem escritos: Nome: null, Nome: undefined. Se isso aparecer para o usuário, faltou um valor padrão (seção 6).

Resumo

  • undefined é o "ainda não tem valor" que o JavaScript põe sozinho: variável sem =, propriedade ou posição que não existe, função sem return.
  • null é o "vazio de propósito" que você escreve. Prefira null e não escreva undefined à mão.
  • typeof null dá "object" (erro histórico). Para reconhecer, use === null e === undefined; null === undefined é false.
  • valor ?? "padrão" troca só null e undefined pelo padrão (o 0 e o "" ficam).
  • Ler uma propriedade de null ou undefined dá TypeError: Cannot read properties of …: o culpado é o que vem antes do ponto. Já "is not defined" quer dizer que a variável nem existe.
