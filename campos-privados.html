JavaScript Campos Privados (#)

Até agora, qualquer parte do programa podia mexer em qualquer propriedade de um objeto: ler, trocar, apagar. Para a maioria das coisas, tudo bem. Mas pense no saldo de um cofrinho: ele só deveria mudar por um depósito ou um saque, que conferem se o valor faz sentido. Se qualquer linha puder escrever cofre.saldo = 1000000, as conferências não servem para nada. Os campos privados, escritos com # na frente do nome, são propriedades que só o código de dentro da classe consegue ver e mudar.

Você vai aprender
  • Por que esconder dados de um objeto (e o problema de deixar tudo aberto).
  • Como criar e usar um campo privado: #saldo = 0; e this.#saldo.
  • Como deixar o mundo ler sem poder mudar, com get.
  • Métodos privados (#validar()), o teste #campo in obj, e o que acontece na herança.
  • O jeito antigo (_saldo, com sublinhado) e a alternativa com closure.
  • O erro que você mais vai ver: Private field '#saldo' must be declared in an enclosing class.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Os campos privados chegaram ao JavaScript no ES2022; qualquer Node atual e qualquer navegador atual os entendem.

A ideia: o cofrinho com cadeado

Um cofrinho de porquinho tem uma fenda: você coloca moedas por ela, mas não consegue enfiar a mão e tirar (nem trocar as moedas por pedrinhas). O dinheiro está lá dentro, guardado; o único jeito de mexer é pelas aberturas que o fabricante fez. Um objeto com campos privados é igual:

  • o campo privado é o dinheiro lá dentro: existe, ocupa espaço, mas ninguém de fora encosta nele;
  • os métodos (depositar, sacar) são as aberturas: fazem as conferências e só então mexem no dinheiro.

Os programadores chamam isso de encapsulamento ("pôr numa cápsula"): esconder os detalhes e mostrar só o que é seguro usar.

1. O problema: tudo aberto

Primeiro, o cofrinho do jeito que você já sabe escrever, com o saldo numa propriedade comum:

class Cofrinho {
  constructor() {
    this.saldo = 0;
  }

  depositar(valor) {
    if (valor <= 0) {
      console.log("Depósito inválido!");
      return;
    }
    this.saldo = this.saldo + valor;
  }
}

const cofre = new Cofrinho();
cofre.depositar(50);
cofre.depositar(-20);
cofre.saldo = 1000000;
console.log(cofre.saldo);

$ node publico.js
Depósito inválido!
1000000

O depositar fez o trabalho dele direitinho: recusou o depósito de -20. Mas a linha cofre.saldo = 1000000 passou por cima de tudo: o saldo virou um milhão sem depósito nenhum. Num programa pequeno, é você mesmo quem escreveria essa linha sem querer (um erro de digitação, um = no lugar de ===); num programa grande, é outra pessoa da equipe que nem sabia que não podia.

2. O campo privado: #saldo

class Cofrinho {
  #saldo = 0;

  depositar(valor) {
    if (valor <= 0) {
      console.log("Depósito inválido!");
      return;
    }
    this.#saldo = this.#saldo + valor;
  }

  verSaldo() {
    return this.#saldo;
  }
}

const cofre = new Cofrinho();
cofre.depositar(50);
cofre.depositar(-20);
cofre.saldo = 1000000;
console.log(cofre.verSaldo());
console.log(cofre.saldo);
console.log(cofre);
console.log(Object.keys(cofre));
console.log(JSON.stringify(cofre));
console.log(cofre["#saldo"]);
#saldo = 0;
A declaração do campo privado, no corpo da classe, fora de qualquer método. O # (cerquilha, "jogo da velha") faz parte do nome: o campo se chama #saldo. Cada cofrinho criado ganha o seu, começando em 0. Declarar é obrigatório: sem esta linha, nenhum this.#saldo funciona.
this.#saldo = this.#saldo + valor;
Dentro da classe, o campo se usa como qualquer outro, só que sempre com o #.
verSaldo()
Uma "abertura" só para olhar: devolve o valor, mas não deixa trocar.
cofre.saldo = 1000000;
Não deu erro, mas também não mexeu no #saldo: criou uma propriedade pública nova, chamada saldo (sem #), que não tem nada a ver com o dinheiro do cofre.
$ node privado.js
Depósito inválido!
50
1000000
Cofrinho { saldo: 1000000 }
[ 'saldo' ]
{"saldo":1000000}
undefined

Leia a saída de cima para baixo:

  • 50: o saldo de verdade, pelo verSaldo(). O "um milhão" não chegou nele.
  • 1000000: a propriedade pública que a linha cofre.saldo = … criou. É uma etiqueta colada do lado de fora do cofre; o dinheiro de dentro continua 50.
  • Cofrinho { saldo: 1000000 }: o console.log do Node não mostra o #saldo, só o que é público.
  • [ 'saldo' ] e {"saldo":1000000}: o Object.keys e o JSON.stringify (aula JSON) também não enxergam campos privados.
  • undefined: cofre["#saldo"], com o nome entre aspas, procura uma propriedade comum que se chamaria "#saldo", e ela não existe. Não há truque com colchetes para chegar no privado.
O # faz parte do nome

this.#saldo e this.saldo são duas coisas diferentes, que podem existir ao mesmo tempo no mesmo objeto (como na saída acima). Esquecer o # numa linha dentro da classe não dá erro: só cria uma propriedade pública por engano.

Missão: rode e veja o saldo virar um milhão pela linha "malandra" do fim. Depois proteja o cofrinho: declare #saldo = 0; no corpo da classe, apague o constructor e troque todo this.saldo por this.#saldo. Não apague a linha malandra: com o campo privado, ela deixa de fazer efeito e a saída vira Saldo: R$ 50.

3. E se alguém tentar ler de fora?

Do lado de fora da classe, escrever cofre.#saldo (com o #) não é nem permitido:

class Cofrinho {
  #saldo = 0;

  depositar(valor) {
    this.#saldo = this.#saldo + valor;
  }
}

const cofre = new Cofrinho();
cofre.depositar(50);
console.log(cofre.#saldo);

A linha 11, a do console.log(cofre.#saldo).
SyntaxError
Um erro de escrita, não de execução. O Node recusou o arquivo inteiro antes de rodar a primeira linha: nem o depositar(50) chegou a acontecer.
Private field '#saldo' must be declared in an enclosing class
"O campo privado #saldo precisa estar declarado numa classe em volta (daqui)". A linha 11 não está dentro de classe nenhuma, então para ela não existe #saldo.

A pilha mostra só o Node lendo o arquivo (wrapSafe é a parte que confere a escrita): nada do seu código chegou a rodar.

É a proteção mais forte possível: o JavaScript nem deixa escrever um programa que lê o campo de fora. Com um método privado (seção 5), a mensagem é a mesma: cofre.#registrar("oi") fora da classe dá Private field '#registrar' must be declared in an enclosing class.

4. Ler sem poder mudar: get

O verSaldo() funciona, mas na aula get e set você viu um jeito mais elegante: um getter. Com um get saldo() e nenhum set, quem está de fora lê cofre.saldo como uma propriedade comum, mas não consegue trocar:

class Cofrinho {
  #saldo = 0;
  #historico = [];

  constructor(dono) {
    this.dono = dono;
  }

  get saldo() {
    return this.#saldo;
  }

  depositar(valor) {
    if (!this.#valorValido(valor)) {
      console.log(`Depósito de ${valor} recusado`);
      return;
    }
    this.#saldo = this.#saldo + valor;
    this.#registrar(`+${valor}`);
  }

  sacar(valor) {
    if (!this.#valorValido(valor) || valor > this.#saldo) {
      console.log(`Saque de ${valor} recusado`);
      return;
    }
    this.#saldo = this.#saldo - valor;
    this.#registrar(`-${valor}`);
  }

  extrato() {
    return `${this.dono}: ${this.#historico.join(" ")} = ${this.#saldo}`;
  }

  #valorValido(valor) {
    return typeof valor === "number" && valor > 0;
  }

  #registrar(texto) {
    this.#historico.push(texto);
  }
}

const cofre = new Cofrinho("Ana");
cofre.depositar(50);
cofre.depositar(30);
cofre.sacar(100);
cofre.sacar(20);
cofre.depositar("10");
console.log(cofre.saldo);
console.log(cofre.extrato());
cofre.saldo = 999;
console.log(cofre.saldo);
console.log(cofre);

$ node getter.js
Saque de 100 recusado
Depósito de 10 recusado
60
Ana: +50 +30 -20 = 60
60
Cofrinho { dono: 'Ana' }
  • O saque de 100 foi recusado (só havia 80), e o depósito de "10" também: entre aspas, é um texto, não um número (o typeof é da aula typeof).
  • cofre.saldo, sem parênteses, chamou o get saldo() e mostrou 60.
  • cofre.saldo = 999 foi ignorado em silêncio: o saldo continuou 60. Não existe set saldo, então não há como trocar. (No modo estrito, que é o padrão dentro de módulos import/export, essa linha dá erro: no lab, com "use strict"; no topo do arquivo, saiu TypeError: Cannot set property saldo of #<Cofrinho> which has only a getter, "não dá para mudar a propriedade saldo, que só tem um getter".)
  • O console.log(cofre) só mostra o dono, a única propriedade pública. Os dois campos privados e os dois métodos privados ficam escondidos.

5. Métodos privados

No cofrinho acima, repare em #valorValido(valor) e #registrar(texto): são métodos privados. Eles se escrevem como os normais, com # no nome, e se chamam com this.#valorValido(…). Servem para os ajudantes internos: pedaços de código que os métodos públicos usam, mas que não fazem sentido para quem está de fora. Ninguém precisa chamar cofre.#registrar("+1000") para inventar uma linha no extrato; deixar privado garante que ninguém consegue.

Membro do CofrinhoQuem pode usarPor quê
donoTodo mundoNão tem perigo: é só um nome
saldo (o get)Todo mundo, só para lerMostra o saldo sem deixar mudar
depositar, sacar, extratoTodo mundoSão as "aberturas" do cofre, com as conferências
#saldo, #historicoSó a classeSó mudam por depósito ou saque
#valorValido, #registrarSó a classeAjudantes internos

6. Privado é da classe, não da família: a herança

Um campo privado é privado até para as classes filhas (aula Herança). A Ana tentou criar um cofrinho que rende juros mexendo direto no #saldo da mãe:

class Cofrinho {
  #saldo = 0;

  depositar(valor) {
    this.#saldo = this.#saldo + valor;
  }
}

class CofrinhoComJuros extends Cofrinho {
  renderJuros() {
    this.#saldo = this.#saldo * 1.01;
  }
}

$ node filha.js
/home/ana/filha.js:11
    this.#saldo = this.#saldo * 1.01;
        ^

SyntaxError: Private field '#saldo' must be declared in an enclosing class
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)   « (mais 7 linhas at node:internal… cortadas)

Node.js v24.22.0

A mesma mensagem: o #saldo foi declarado na classe Cofrinho, e a CofrinhoComJuros é outra classe. A filha herda os métodos públicos, e é por eles que ela deve passar, como todo mundo:

class Cofrinho {
  #saldo = 0;

  get saldo() {
    return this.#saldo;
  }

  depositar(valor) {
    this.#saldo = this.#saldo + valor;
  }
}

class CofrinhoComJuros extends Cofrinho {
  renderJuros() {
    this.depositar(this.saldo * 0.01);
  }
}

const cofre = new CofrinhoComJuros();
cofre.depositar(200);
cofre.renderJuros();
console.log(cofre.saldo);

$ node filha-ok.js
202

Os juros de 1% sobre 200 entraram como um depósito de 2, pelo método público. Assim, se um dia o depositar ganhar uma conferência nova, os juros também passam por ela.

"Este objeto tem o campo privado?" — #campo in obj

Dentro da classe, dá para perguntar se um objeto qualquer tem o campo privado dela, com #saldo in obj. É um jeito seguro de saber se ele é mesmo um Cofrinho criado por esta classe:

class Cofrinho {
  #saldo = 0;

  static ehCofrinho(obj) {
    return #saldo in obj;
  }
}

console.log(Cofrinho.ehCofrinho(new Cofrinho()));
console.log(Cofrinho.ehCofrinho({ saldo: 0 }));

$ node in.js
true
false

O objeto { saldo: 0 } tem um saldo comum, mas não o #saldo da classe: false. (O static é o da aula Membros static; campos e métodos static também podem ser privados: static #contador = 0;.)

Formas diferentes de fazer a mesma coisa

O jeito antigo: o sublinhado _saldo

Antes de 2022, o JavaScript não tinha campos privados de verdade. Os programadores combinaram um aviso: um nome começando com sublinhado (_saldo) quer dizer "isto é interno, não mexa". Mas é só um combinado:

class Cofrinho {
  constructor() {
    this._saldo = 0;
  }

  depositar(valor) {
    this._saldo = this._saldo + valor;
  }
}

const cofre = new Cofrinho();
cofre.depositar(50);
cofre._saldo = 1000000;
console.log(cofre);

$ node sublinhado.js
Cofrinho { _saldo: 1000000 }

O JavaScript deixou mudar sem reclamar: o _ é uma letra como outra qualquer. Você vai ver muito _algo em código antigo e em bibliotecas. Em código novo, use #.

Sem classe: a variável presa numa closure

Também dá para esconder um valor sem classe nenhuma, com uma função que cria o objeto e uma variável que só as funções de dentro enxergam (aula Closures):

function criarCofrinho() {
  let saldo = 0;
  return {
    depositar(valor) {
      saldo = saldo + valor;
    },
    verSaldo() {
      return saldo;
    },
  };
}

const cofre = criarCofrinho();
cofre.depositar(50);
console.log(cofre.verSaldo());
console.log(cofre.saldo);

$ node closure.js
50
undefined

O saldo é uma variável da função criarCofrinho, não uma propriedade do objeto: de fora, cofre.saldo não existe. Era o jeito "privado de verdade" antes do #.

FormaProtege de verdade?Quando usar
#saldo numa classeSim: de fora nem se consegue escrever o nomeCódigo novo com classes (o padrão)
_saldoNão: é só um aviso para os humanosReconhecer em código antigo; não escreva assim
Variável numa closureSimQuando o resto do código já usa funções em vez de classes
Propriedade comum (this.saldo)NãoDados que podem mudar livremente (nome, cor, apelido)

Quando dá errado

Usou o campo sem declarar no corpo da classe

Quem está acostumado a criar propriedades no construtor tenta fazer o mesmo com o privado:

class Cofrinho {
  constructor() {
    this.#saldo = 0;
  }
}

const cofre = new Cofrinho();

$ node sem-declarar.js
/home/ana/sem-declarar.js:3
    this.#saldo = 0;
        ^

SyntaxError: Private field '#saldo' must be declared in an enclosing class
    at wrapSafe (node:internal/modules/cjs/loader:1861:18)   « (mais 7 linhas at node:internal… cortadas)

Node.js v24.22.0

Desta vez a linha está dentro da classe, e mesmo assim deu erro. Uma propriedade comum nasce na hora em que você escreve this.saldo = 0; um campo privado, não: ele precisa ser declarado antes, no corpo da classe. Como consertar: acrescente #saldo; (ou #saldo = 0;) logo depois do class Cofrinho {. Se o valor inicial vem do construtor, declare sem valor e dê o valor lá, como na missão final.

Tentou ler ou chamar o privado de fora

É o caso da seção 3: cofre.#saldo ou cofre.#registrar() fora da classe dão o mesmo SyntaxError: Private field '…' must be declared in an enclosing class, e o programa inteiro não roda. Como consertar: crie um método público ou um get que devolva o que o resto do programa precisa saber.

Esqueceu o # numa linha

Este não dá erro, e por isso é o pior:

class Cofrinho {
  #saldo = 0;

  depositar(valor) {
    this.saldo = this.saldo + valor;
  }

  verSaldo() {
    return this.#saldo;
  }
}

const cofre = new Cofrinho();
cofre.depositar(50);
console.log(cofre);
console.log(cofre.verSaldo());

$ node esqueceu.js
Cofrinho { saldo: NaN }
0

No depositar, faltou o #. O JavaScript entendeu que era uma propriedade pública chamada saldo, diferente do #saldo: ela não existia (valia undefined), undefined + 50 deu NaN (aula NaN, Infinity…), e o saldo privado continuou 0. Como consertar: procure no código as linhas com o nome do campo e confira se todas têm o #. Se o console.log(objeto) mostrar uma propriedade que você queria privada, faltou um # em algum lugar.

A classe filha tentou usar o privado da mãe

Também é o mesmo SyntaxError, apontando a linha da filha (seção 6). Como consertar: use os métodos públicos (ou um get) que a mãe oferece.

Missão final: a senha do armário

Missão: o armário da padaria tem uma senha. Do jeito que está, qualquer um lê a senha com senha.valor. Troque o campo comum por um campo privado #valor: declare #valor; no corpo da classe e use this.#valor no construtor e no confere. A última linha deve passar a mostrar Dá para ler? undefined, e o confere deve continuar funcionando (true para "1234", false para "0000").

class Senha {
  constructor(valor) {
    this.valor = valor;
  }

  confere(tentativa) {
    return tentativa === this.valor;
  }
}

const senha = new Senha("1234");
console.log(`Confere 1234? ${senha.confere("1234")}`);
console.log(`Confere 0000? ${senha.confere("0000")}`);
console.log(`Dá para ler? ${senha.valor}`);

class Senha {
  #valor;

  constructor(valor) {
    this.#valor = valor;
  }

  confere(tentativa) {
    return tentativa === this.#valor;
  }
}

const senha = new Senha("1234");
console.log(`Confere 1234? ${senha.confere("1234")}`);
console.log(`Confere 0000? ${senha.confere("0000")}`);
console.log(`Dá para ler? ${senha.valor}`);

No lab, a solução mostrou Confere 1234? true, Confere 0000? false e Dá para ler? undefined.

Resumo

  • Um campo com # no nome (#saldo) é privado: só o código dentro da classe consegue ler e mudar. É o encapsulamento: mostrar só as "aberturas" seguras.
  • O campo privado precisa ser declarado no corpo da classe (#saldo = 0;) e se usa sempre com o #: this.#saldo.
  • Tentar usar o privado fora da classe (ou numa filha, ou sem declarar) dá SyntaxError: Private field '#…' must be declared in an enclosing class, e o programa nem começa.
  • Para deixar ler sem deixar mudar, use um get sem set. Métodos também podem ser privados: #registrar().
  • console.log, Object.keys e JSON.stringify não mostram campos privados.
  • _saldo é só um combinado antigo, sem proteção. Em código novo, use #.
