JavaScript Nomes de Variáveis

Toda variável precisa de um nome, a etiqueta da caixa. O JavaScript tem algumas regras para esse nome (se você não seguir, o programa nem começa) e os programadores têm alguns costumes (se você não seguir, o programa roda, mas fica difícil de ler). Nesta aula você vai ver as duas coisas, e por que quantidadePaes é um nome muito melhor que x.

Você vai aprender
  • As regras obrigatórias: que caracteres podem entrar num nome e quais não podem.
  • Que nome, Nome e NOME são três variáveis diferentes.
  • As palavras reservadas, que não podem ser nomes (let, new, class…).
  • O que acontece com acentos, e por que este guia não os usa em nomes.
  • Os costumes: camelCase, MAIÚSCULAS_COM_SUBLINHADO e como escolher um nome que explica a si mesmo.
  • Os erros reais de cada regra quebrada.

Todos os programas desta aula rodaram no Node.js v24.22.0 da máquina da Ana (ana@notebook), com node arquivo.js.

A ideia: etiquetas que qualquer um entende

Imagine a despensa da padaria com as caixas etiquetadas assim: "x", "coisa2", "aaa". O padeiro novo, no primeiro dia, não acharia nada. Agora imagine as etiquetas "farinha de trigo", "açúcar refinado", "fermento". Ninguém precisa perguntar nada.

Nomes de variáveis são lidos muito mais vezes do que são escritos: por você, daqui a uma semana, e por outras pessoas. Um bom nome é a forma mais barata de explicar o que um programa faz.

1. As regras obrigatórias

Um nome de variável (o nome técnico é identificador) segue estas regras:

RegraPodeNão pode
Usar letras, números, _ (sublinhado) e $ (cifrão)total2, _codigo, $saldopreco-pao, preco.pao, total%
Não começar com númerolugar11lugar
Ser uma palavra só, sem espaçosprecoDoPaopreco do pao
Não ser uma palavra reservadanova, classenew, class, let

Todos estes nomes são válidos:

const nome = "Ana";
const precoPao = 0.75;
const total2 = 15;
const _codigo = 42;
const $saldo = 100;
const TAXA_ENTREGA = 5;
console.log(nome, precoPao, total2, _codigo, $saldo, TAXA_ENTREGA);

$ node validos.js
Ana 0.75 15 42 100 5
precoPao
Duas palavras juntas, sem espaço, a segunda começando com maiúscula. É o estilo mais comum (seção 4).
total2
Números podem aparecer no meio ou no fim, nunca no começo.
_codigo
O sublinhado é permitido em qualquer posição, inclusive no começo.
$saldo
O cifrão também. Ele não tem nada a ver com dinheiro: para o JavaScript, é só mais um caractere permitido. Você vai vê-lo em bibliotecas antigas, como o jQuery.
TAXA_ENTREGA
Tudo em maiúsculas, com _ entre as palavras: o costume para constantes de configuração (veja Constantes).

2. Maiúsculas e minúsculas fazem diferença

O JavaScript é sensível a maiúsculas e minúsculas (em inglês, case-sensitive). Para ele, uma letra maiúscula é um caractere diferente da minúscula:

const nome = "Ana";
const Nome = "Bia";
const NOME = "Caio";
console.log(nome, Nome, NOME);

$ node maiuscula.js
Ana Bia Caio

Três variáveis diferentes, com três valores diferentes. Isso é permitido, mas é uma péssima ideia num programa de verdade: ninguém vai lembrar qual é qual. O lado prático dessa regra é o erro mais comum de quem começa: criar precoPao e escrever precopao depois.

const precoPao = 0.75;
console.log(precopao);

$ node maiusc2.js

"precopao não está definido". O Node não diz "você quis dizer precoPao?": para ele, são etiquetas sem nenhuma relação. Quando aparecer um is not defined de uma variável que você tem certeza de que criou, compare letra por letra, maiúsculas incluídas.

3. Acentos: funcionam, mas evite

O JavaScript aceita letras de qualquer idioma em nomes, incluindo as acentuadas:

const preço = 0.75;
const açúcar = "1 kg";
console.log(preço, açúcar);

$ node acento.js
0.75 1 kg

Funciona. Mesmo assim, este guia escreve os nomes em português sem acento (preco, acucar, quantidade), e você deve fazer o mesmo. Por quê?

  • Ninguém lembra onde estava o acento. Você escreve preço numa linha e preco em outra, e o resultado é este:
const preço = 0.75;
console.log(preco);

$ node acento2.js
/home/ana/acento2.js:2
console.log(preco);
            ^

ReferenceError: preco is not defined
    at Object.<anonymous> (/home/ana/acento2.js:2:13)
    «  … mais 7 linhas "at" de dentro do Node (cortadas aqui)

Node.js v24.22.0
  • Teclados e equipes. Num teclado sem ç e sem acentos (comum fora do Brasil), digitar preço é um sofrimento; uma equipe com pessoas de outros países vai reclamar.
  • Costume. Praticamente todo código JavaScript que você vai ler usa só as letras de a a z nos nomes.

Os textos entre aspas, esses sim, podem e devem ter acento: const produto = "pão de açúcar"; está perfeito. A regra vale só para os nomes.

E emoji?

Não: const 🍞 = 6; dá SyntaxError: Invalid or unexpected token no lab. Emoji não é letra, então não pode fazer parte de um nome (dentro de um texto entre aspas, pode).

4. Os costumes: camelCase e MAIÚSCULAS

Como não pode haver espaço no nome, os programadores precisam de um jeito de juntar várias palavras. Cada linguagem tem o seu costume; no JavaScript são estes:

EstiloComo éPara quêExemplo
camelCasea primeira palavra em minúsculas, as outras começando com maiúsculaquase tudo: variáveis, constantes comuns, funçõesprecoPao, totalDaCompra, nomeCliente
MAIÚSCULAS_COM_SUBLINHADOtudo maiúsculo, _ entre as palavrasconstantes de configuração, fixas antes de o programa rodarTAXA_ENTREGA, MAXIMO_TENTATIVAS
PascalCasetodas as palavras começando com maiúsculaclasses (aula Classes)Cliente, CarrinhoDeCompras

O nome camelCase vem de camel, "camelo": as maiúsculas no meio do nome parecem as corcovas (precoPaoFances). Em outras linguagens, como Python, se usa preco_pao (com sublinhado); no JavaScript isso funciona, mas foge do costume.

Missão: os nomes deste programa quebram as regras, e ele não roda. Conserte os dois nomes (nas três linhas onde aparecem), usando camelCase: por exemplo, precoPao e quantidadePaes.

const 1preco = 0.75;
const quantidade-paes = 6;
const total = 1preco * quantidade-paes;
console.log("Total:", total);

const precoPao = 0.75;
const quantidadePaes = 6;
const total = precoPao * quantidadePaes;
console.log("Total:", total);

5. Palavras reservadas

Algumas palavras já têm um significado para o JavaScript (const, if, for, new, class, return…). Elas são reservadas: não podem ser nomes de variáveis, porque o JavaScript não saberia se você está falando da variável ou do comando.

const new = "pão quentinho";

$ node reservada.js
/home/ana/reservada.js:1

6. Escolhendo bons nomes

As regras dizem o que o JavaScript aceita. Mas um nome aceito pode ser ruim. Compare dois programas que fazem exatamente a mesma conta:

const x = 6;
const y = 0.75;
const z = x * y;
console.log(z);

const quantidadePaes = 6;
const precoPao = 0.75;
const totalCompra = quantidadePaes * precoPao;
console.log(totalCompra);

$ node bons.js
4.5
4.5

O resultado é o mesmo, mas só o segundo trecho explica a si mesmo. No primeiro, você precisa adivinhar o que é x. Algumas dicas:

DicaEvitePrefira
Diga o que a variável guardax, valor, dados, coisaprecoPao, nomeCliente
Não abrevie demaisqtdPs, vlTtquantidadePaes, valorTotal
Para sim/não (true/false), comece com esta, tem, podeaberta, descontoestaAberta, temDesconto

Um idioma só no programatotalPrice e precoTotal juntostudo em português (ou tudo em inglês)
Sem acento nos nomespreçopreco

O prefixo esta/tem deixa a leitura quase uma frase em português:

const estaAberta = true;
const temDesconto = false;
console.log("A padaria está aberta?", estaAberta);
console.log("Tem desconto hoje?", temDesconto);

$ node booleano.js
A padaria está aberta? true
Tem desconto hoje? false
E o i dos laços?

Existe uma exceção famosa à regra "nada de uma letra só": o contador de um laço for curto costuma se chamar i (de "índice"), e todo programador entende. Fora disso, prefira nomes inteiros.

Quando dá errado

Hífen no nome 
let preco-pao = 0.75;

$ node hifen2.js
/home/ana/hifen2.js:1
let preco-pao = 0.75;
         ^

SyntaxError: Unexpected token '-'
    «  … linhas "at" de dentro do Node (cortadas aqui)

Node.js v24.22.0

Linha por linha: o erro está na linha 1 de hifen2.js; a setinha aponta o -; e a mensagem diz "símbolo inesperado -". Para o JavaScript, o - é sempre o sinal de menos: ele leu let preco e depois "menos pao", o que não faz sentido numa criação de variável. Como é erro de sintaxe, nada roda.

Com const, a mensagem engana mais:

$ node hifen.js
/home/ana/hifen.js:1
const preco-pao = 0.75;
      ^^^^^

SyntaxError: Missing initializer in const declaration
    «  … linhas "at" de dentro do Node (cortadas aqui)

Node.js v24.22.0

"Falta o valor na declaração const": o JavaScript entendeu const preco sem valor, seguido de um "menos" perdido. A mesma mensagem aparece com espaço (const preco do pao = 0.75;) ou ponto (const preco.pao = 0.75;) no nome. Como consertar: precoPao.

Nome começando com número 
const 1lugar = "Ana";

$ node numero.js
/home/ana/numero.js:1
const 1lugar = "Ana";
      ^

SyntaxError: Invalid or unexpected token
    «  … linhas "at" de dentro do Node (cortadas aqui)

Node.js v24.22.0

"Símbolo inválido ou inesperado". Um 1 no começo faz o JavaScript achar que vem um número, e 1lugar não é um número. Como consertar: ponha o número no fim (lugar1) ou escreva por extenso (primeiroLugar).

Palavra reservada como nome

Sintoma: SyntaxError: Unexpected token 'new' (ou 'class', 'return'…) apontando o nome, ou let is disallowed as a lexically bound name. Como consertar: use outra palavra; em português, nunca há conflito (nova, classe, retorno).

Maiúscula, minúscula ou acento diferentes

Sintoma: ReferenceError: precopao is not defined, mesmo você tendo criado a variável. Causa: o nome foi criado como precoPao (ou preço) e usado como precopao (ou preco). Como consertar: copie o nome exatamente como foi criado. Escrever todos os nomes sem acento e em camelCase evita a maior parte desses enganos.

Missão final: dê nomes de verdade

Missão: o programa funciona, mas os nomes não dizem nada. Renomeie a para nomeCliente, b para quantidadePaes, c para precoPao e d para totalCompra, em todos os lugares onde aparecem. Depois, troque a cliente para "Bia", que levou 10 pães de 0.8. Tem de aparecer Bia pagou 8.

const a = "Ana";
const b = 6;
const c = 0.75;
const d = b * c;
console.log(a, "pagou", d);

const nomeCliente = "Bia";
const quantidadePaes = 10;
const precoPao = 0.8;
const totalCompra = quantidadePaes * precoPao;
console.log(nomeCliente, "pagou", totalCompra);

No lab, o código inicial mostra Ana pagou 4.5, e a solução, Bia pagou 8.

Resumo

  • Nomes podem ter letras, números, _ e $; não podem começar com número, ter espaço, hífen ou ponto, nem ser uma palavra reservada.
  • Maiúsculas e minúsculas contam: precoPao e precopao são variáveis diferentes.
  • Acentos funcionam em nomes, mas este guia (e quase todo código JavaScript) não os usa: preco, não preço. Nos textos entre aspas, acento à vontade.
  • O costume é camelCase (precoPao) para quase tudo e MAIUSCULAS_COM_SUBLINHADO para constantes de configuração.
  • Um bom nome diz o que a variável guarda: quantidadePaes, não x; temDesconto para sim/não; plural para listas.
