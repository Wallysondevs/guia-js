JavaScript Testes (node:test)

Até agora, para saber se um programa estava certo, você rodava e olhava a saída. Funciona para programas pequenos. Mas, quando o programa cresce, ninguém consegue olhar tudo de novo a cada mudança, e um conserto aqui quebra uma coisa lá sem ninguém perceber. Um teste automático é um pedacinho de código que confere outro pedaço de código: "a função de desconto, com R$ 50 e 10%, tem de dar R$ 45". Você escreve uma vez e o computador confere sempre que você pedir, em menos de um segundo. O Node já vem com tudo o que é preciso para isso: o node:assert e o node:test.

Você vai aprender
  • O que é um teste e por que vale a pena escrever um.
  • Como conferir um valor com o node:assert: assert.equal, assert.deepEqual, assert.throws.
  • Como escrever testes com o node:test (test, describe, it) e rodá-los com node --test e npm test.
  • Como ler a saída de um teste que falhou e achar o defeito.
  • As armadilhas reais: comparar arrays com equal, o 0.1 + 0.2 e o "type": "commonjs" do package.json.

Todos os comandos desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), numa pasta loja. Os testes usam módulos (import e export).

A ideia: o peso-padrão da balança

Toda manhã, antes de abrir, o dono da padaria põe um peso de 1 kg na balança. Se ela marcar 1,000 kg, está tudo certo e o dia começa. Se marcar 1,050, alguma coisa estragou, e ele descobre antes de cobrar errado de um cliente. Ele não pesa todos os pães do dia para conferir; ele usa um caso em que já sabe a resposta.

Um teste é exatamente isso: você chama a sua função com valores para os quais já sabe o resultado certo e manda o computador comparar. Três palavras que você vai ver:

  • valor obtido (em inglês, actual): o que a função devolveu de verdade;
  • valor esperado (expected): o que ela deveria devolver;
  • asserção (assertion, "afirmação"): a linha que afirma "o obtido tem de ser igual ao esperado".

1. A primeira conferência: node:assert

O módulo node:assert vem com o Node. A versão node:assert/strict ("estrita") compara com ===, como este guia recomenda:

import assert from "node:assert/strict";

function dobro(n) {
  return n * 2;
}

assert.equal(dobro(4), 8);
assert.equal(dobro(0), 0);
console.log("Conferências feitas.");

Missão: a função de desconto está errada: ela subtrai a porcentagem como se fosse dinheiro. Rode, leia o AssertionError (o obtido e o esperado) e conserte a função (não as conferências!) para calcular a porcentagem do preço: preco - (preco * porcentagem) / 100.

import assert from "node:assert/strict";

function precoComDesconto(preco, porcentagem) {
  return preco - porcentagem;
}

assert.equal(precoComDesconto(50, 10), 45);
assert.equal(precoComDesconto(50, 0), 50);
assert.equal(precoComDesconto(20, 50), 10);
console.log("Conferências feitas.");

import assert from "node:assert/strict";

function precoComDesconto(preco, porcentagem) {
  return preco - (preco * porcentagem) / 100;
}

assert.equal(precoComDesconto(50, 10), 45);
assert.equal(precoComDesconto(50, 0), 50);
assert.equal(precoComDesconto(20, 50), 10);
console.log("Conferências feitas.");

2. O executor de testes: node:test

Na vida real, os testes ficam num arquivo separado do código que eles conferem. A Ana pôs a função no precos.js (ainda com o defeito da missão acima, para ver o que acontece):

export function precoComDesconto(preco, porcentagem) {
  return preco - porcentagem;
}

E os testes no precos.test.js. O .test.js no fim do nome é um combinado: é assim que o Node sabe que o arquivo tem testes.

import { test } from "node:test";
import assert from "node:assert/strict";
import { precoComDesconto } from "./precos.js";

test("10% de desconto em R$ 50 dá R$ 45", () => {
  assert.equal(precoComDesconto(50, 10), 45);
});

test("sem desconto, o preço não muda", () => {
  assert.equal(precoComDesconto(50, 0), 50);
});

test("50% de desconto em R$ 20 dá R$ 10", () => {
  assert.equal(precoComDesconto(20, 50), 10);
});
import { test } from "node:test";
Traz a função test do executor de testes do Node (estável desde o Node 20).
import { precoComDesconto } from "./precos.js";
Traz a função que vai ser conferida, do outro arquivo.
test("descrição", () => { … })
Um teste: um nome que diz, em português, o que está sendo conferido, e uma arrow function com as asserções. Se nada lançar erro dentro dela, o teste passa; se alguma asserção falhar, o teste falha, e o executor continua para o próximo.

3. Outras conferências

O assert.equal compara com ===. Isso serve para números, textos e booleanos, mas não para arrays e objetos: dois arrays com o mesmo conteúdo são caixas diferentes (veja Objetos são Referências). Para eles existe o deepEqual ("igual em profundidade"), que compara o conteúdo, item por item. E para conferir que uma função dá erro quando deve, existe o throws ("lança").

Asserção (de node:assert/strict)Passa quando…
assert.equal(obtido, esperado)obtido === esperado (números, textos, booleanos)
assert.notEqual(obtido, outro)são diferentes
assert.deepEqual(obtido, esperado)arrays/objetos com o mesmo conteúdo
assert.ok(valor)o valor é truthy (por exemplo, true)
assert.throws(() => …, /mensagem/)a função lança um erro cuja mensagem casa com a regex
assert.match(texto, /regex/)o texto casa com a regex

4. Organizando: describe e it

Quando há muitos testes, eles se agrupam por assunto. O describe ("descreva") cria um grupo (o Node chama de suite); dentro dele, cada teste se escreve com it ("ele"), que é o mesmo que test com outro nome: lido em inglês, it("põe o item no fim") soa como uma frase sobre a função. A Ana escreveu o carrinho da lojinha:

export function adicionarItem(carrinho, item) {
  return [...carrinho, item];
}

export function totalDoCarrinho(carrinho) {
  let total = 0;
  for (const item of carrinho) {
    if (item.preco < 0) {
      throw new Error(`Preço negativo: ${item.nome}`);
    }
    total += item.preco * item.quantidade;
  }
  return total;
}

E os testes, no carrinho.test.js:

import { describe, it } from "node:test";
import assert from "node:assert/strict";
import { adicionarItem, totalDoCarrinho } from "./carrinho.js";

describe("adicionarItem", () => {
  it("põe o item no fim", () => {
    const carrinho = adicionarItem([], { nome: "pão", preco: 0.75, quantidade: 10 });
    assert.deepEqual(carrinho, [{ nome: "pão", preco: 0.75, quantidade: 10 }]);
  });

  it("não muda o carrinho original", () => {
    const original = [];
    adicionarItem(original, { nome: "leite", preco: 5, quantidade: 1 });
    assert.equal(original.length, 0);
  });
});

describe("totalDoCarrinho", () => {
  it("soma preço vezes quantidade", () => {
    const carrinho = [
      { nome: "pão", preco: 0.75, quantidade: 10 },
      { nome: "leite", preco: 5, quantidade: 2 },
    ];
    assert.equal(totalDoCarrinho(carrinho), 17.5);
  });

  it("carrinho vazio dá zero", () => {
    assert.equal(totalDoCarrinho([]), 0);
  });

  it("recusa preço negativo", () => {
    assert.throws(
      () => totalDoCarrinho([{ nome: "bolo", preco: -1, quantidade: 1 }]),
      /Preço negativo: bolo/,
    );
  });

  it.todo("aplicar cupom de desconto");
});

Um grupo com os testes de uma função.
assert.deepEqual(carrinho, [ … ])
Compara o array devolvido com o esperado, item por item, propriedade por propriedade.
"não muda o carrinho original"
Teste de uma regra importante: a função devolve um carrinho novo (veja Imutabilidade).
"carrinho vazio dá zero"
Teste de um caso de borda: o vazio, o zero, o negativo. É nas bordas que os defeitos se escondem.

Passa se a chamada lançar um erro com essa mensagem (veja throw). A chamada vai dentro de uma arrow function para o assert poder rodá-la e "pegar" o erro.

Mais opções do node --test

node --test --watch fica de olho nos arquivos e roda os testes de novo a cada vez que você salva (Ctrl+C para sair). node --test --experimental-test-coverage mostra quanto do seu código os testes alcançaram. A documentação do Node 24 marca as duas como experimentais (podem mudar em versões futuras). E as bibliotecas de teste famosas, como o Jest e o Vitest, seguem as mesmas ideias: describe, it, "esperado × obtido".

Desta vez o Node mostrou uma diferença (diff): a linha com + é o obtido (actual), a com - é o esperado (expected), e o ^ aponta onde elas começam a diferir. Em dinheiro, muita gente trabalha em centavos inteiros.

O teste passa, mas a função está errada

Um teste sem asserção nenhuma, ou com o valor esperado errado, sempre "passa". Foi o que aconteceu com o teste "sem desconto" da seção 2: ele passou com a função errada, porque 0 reais e 0% dão o mesmo resultado. Como evitar: escreva testes com valores que diferenciam o certo do errado, e, de vez em quando, estrague a função de propósito para ver o teste ficar vermelho.

import assert from "node:assert/strict";

  }

No lab, a solução mostrou Conferências feitas.. Com a função estragada (nota > 9), a primeira conferência falhou, mostrando a diferença: + 'recuperação' (o obtido) e - 'aprovada' (o esperado).

Resumo

  • Um teste chama o seu código com valores de resposta conhecida e compara o obtido com o esperado.
  • node:assert/strict: equal (números e textos), deepEqual (arrays e objetos), throws (a função tem de lançar erro), ok. Uma asserção que falha lança AssertionError.
  • node:test: cada test("nome", () => { … }) é um teste; describe/it agrupam; todo e skip marcam o que falta ou está desligado.
  • node --test roda todos os arquivos *.test.js (e outros nomes combinados); a saída mostra ✔/✖, o placar e o detalhe de cada falha. Código de saída 1 = algum teste falhou.
  • Com package.json: "scripts": { "test": "node --test" }, "type": "module" para usar import, e npm test.
