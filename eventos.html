JavaScript Eventos

Um programa no terminal roda de cima para baixo e termina. Uma página é diferente: ela abre e fica esperando. Esperando a pessoa clicar num botão, digitar num campo, apertar uma tecla, passar o mouse em cima de uma foto. Cada uma dessas coisas é um evento (em inglês, event: "acontecimento"). Nesta aula você vai ensinar a página a reagir: "quando acontecer isto, faça aquilo".

Você vai aprender
  • Como pedir para o navegador rodar uma função quando um evento acontece: addEventListener.
  • A diferença entre entregar a função (mostrar) e chamar a função (mostrar()), o erro número 1 com eventos.
  • Os eventos mais usados: click, dblclick, mouseenter/mouseleave, input, change, keydown, submit e DOMContentLoaded.
  • Como pôr o mesmo ouvinte em vários elementos, e como tirar um ouvinte (removeEventListener e once).
  • Os jeitos antigos (onclick) e por que preferir o addEventListener.
  • Os erros reais mais comuns: o null do seletor errado, o nome do método errado e o evento com nome errado (que falha em silêncio).

Eventos de página são do navegador. (O Node.js também tem eventos, de outro tipo, que não são assunto desta aula.) As respostas do Console mostradas aqui vieram do Chromium da máquina da Ana. Antes, veja Selecionando Elementos e Mudando Textos e Atributos.

A ideia: a campainha

A Ana instalou uma campainha na porta e deixou um combinado com o filho: "Quando a campainha tocar, vá ver quem é."

  • O combinado é feito uma vez, de manhã. Nada acontece na hora: o filho só fica sabendo o que fazer.
  • O filho não fica parado na porta olhando. Ele vive a vida dele; quando a campainha toca, ele vai.
  • Se a campainha tocar cinco vezes no dia, ele vai cinco vezes. Se não tocar nenhuma, ele não vai nenhuma.

Num evento é igual. O addEventListener ("adicionar ouvinte de evento") é o combinado: você diz qual elemento (a porta), qual evento (a campainha tocar) e o que fazer (uma função). O navegador fica "ouvindo" e, a cada vez que o evento acontece, roda a sua função.

1. O primeiro evento: um clique

<button id="botao">Clique aqui</button>
<p id="saida">Ninguém clicou ainda.</p>
<script src="script.js"></script>

const botao = document.querySelector("#botao");
const saida = document.querySelector("#saida");

botao.addEventListener("click", () => {
  saida.textContent = "Você clicou!";
});
botao
O elemento que vai ser "ouvido". O evento é sempre ligado a um elemento: este botão, e não outro.
.addEventListener(
"Adicionar um ouvinte de evento": o combinado. Recebe duas coisas entre os parênteses, separadas por vírgula.
"click"
O nome do evento, num texto, em minúsculas e sem o "on" na frente: "click", e não "onclick" nem "Click".
() => { … }
A função que vai rodar a cada clique (uma arrow function). Ela é chamada de ouvinte (listener) ou tratador do evento (handler). Repare que ninguém a chama no código: quem chama é o navegador, na hora do clique.
saida.textContent = "Você clicou!"
O que acontece no clique: troca o texto do parágrafo.

Quando a página abre, o script roda inteiro, de cima para baixo, como sempre. Só que a linha do addEventListener não troca o texto: ela só registra o combinado. O parágrafo continua "Ninguém clicou ainda." até a Ana clicar. Aí o navegador roda a função, e o texto vira "Você clicou!".

Contando os cliques

A função roda a cada clique. Com uma variável do lado de fora, dá para contar:

const botao = document.querySelector("#botao");
const saida = document.querySelector("#saida");
let cliques = 0;

console.log("O script terminou de rodar.");

botao.addEventListener("click", () => {
  cliques += 1;
  saida.textContent = `Cliques: ${cliques}`;
  console.log(`clique número ${cliques}`);
});

console.log("O ouvinte foi registrado.");

A Ana abriu a página e clicou três vezes. O Console mostrou:

O script terminou de rodar.
O ouvinte foi registrado.
clique número 1
clique número 2
clique número 3

Repare na ordem: as duas mensagens de fora apareceram logo, quando a página abriu, antes de qualquer clique. As de dentro só vieram depois, uma por clique. O cliques fica fora da função com let porque precisa lembrar o valor de um clique para o outro; se ele fosse criado dentro da função, voltaria a 0 a cada clique (a função recomeça do zero toda vez que roda).

2. Entregar a função, não chamar

A função do ouvinte também pode ser uma função com nome, escrita antes. Aí você passa o nome dela, sem parênteses:

const botao = document.querySelector("#botao");
const saida = document.querySelector("#saida");

function cumprimentar() {
  saida.textContent = "Bom dia, Ana!";
}

botao.addEventListener("click", cumprimentar);

cumprimentar sem parênteses é a função em si, como um bilhete entregue na mão do navegador: "rode isto quando clicarem". Com parênteses, cumprimentar(), você mesmo a chamaria, na hora, e entregaria ao navegador o resultado dela. É a diferença entre dar a receita do bolo para alguém fazer depois e entregar um bolo já pronto (aqui, nem bolo: a função não tem return, então o resultado é undefined). Veja o que acontece no erro clássico:

botao.addEventListener("click", cumprimentar());

O parágrafo mostra "Bom dia, Ana!" assim que a página abre, sem clique nenhum, e clicar no botão não faz mais nada. Não aparece erro no Console: o navegador recebeu undefined como ouvinte e simplesmente não tem o que rodar. Quem já leu Funções como Valores reconhece a ideia: funções podem ser passadas de um lado para o outro como qualquer valor.

Arrow function ou função com nome?

As duas servem. A arrow function no próprio addEventListener é prática para ações curtas, usadas num lugar só. A função com nome é melhor quando a ação é grande, quando vários elementos usam a mesma ação, ou quando você vai precisar tirar o ouvinte depois (seção 5).

3. Os eventos mais usados

O clique é só um dos eventos. Os nomes são em inglês; estes são os que você vai usar quase sempre:

dblclickdão um clique duploeditar um item com dois cliques

Passar o mouse: mouseenter e mouseleave

Um par de eventos para ligar e desligar um destaque (veja Mudando o Estilo):

const foto = document.querySelector("#foto");

foto.addEventListener("mouseenter", () => {
  foto.classList.add("destaque");
});

foto.addEventListener("mouseleave", () => {
  foto.classList.remove("destaque");
});

Repare: um elemento pode ter vários ouvintes, um para cada evento (e até vários para o mesmo evento; todos rodam, na ordem em que foram registrados).

Digitar: input

O evento input acontece a cada mudança no campo. O que está escrito fica em campo.value ("valor"; os campos são o assunto de Formulários). Um contador de caracteres para um recado de no máximo 40 letras:

<input id="recado" maxlength="40" placeholder="Deixe um recado">
<p id="conta">0/40</p>
<script src="script.js"></script>

const recado = document.querySelector("#recado");
const conta = document.querySelector("#conta");

recado.addEventListener("input", () => {
  conta.textContent = `${recado.value.length}/40`;
});

Digitando Oi, mãe, o parágrafo passa por 1/40, 2/40… e para em 7/40. Apagando uma letra, volta para 6/40: apagar também muda o campo, então também dispara o input.

Missão: faça o parágrafo #eco repetir, enquanto a pessoa digita, o que está escrito no campo: use o evento "input" e o nome.value. Rode e digite o seu nome no campo do Resultado.

<label>Seu nome: <input id="nome"></label>
<p>Olá, <strong id="eco"></strong>!</p>
<script src="script.js"></script>

const nome = document.querySelector("#nome");
const eco = document.querySelector("#eco");

// quando o campo mudar, copie nome.value para o eco

const nome = document.querySelector("#nome");
const eco = document.querySelector("#eco");

nome.addEventListener("input", () => {
  eco.textContent = nome.value;
});

Teclas: keydown

O keydown acontece quando uma tecla desce. Para saber qual tecla foi, a função precisa receber o objeto do evento, um pacote de informações que o navegador entrega a todo ouvinte. Ele é o assunto da próxima aula, O Objeto do Evento; aqui vai só um gostinho, o Enter num campo de busca:

const busca = document.querySelector("#busca");

busca.addEventListener("keydown", (evento) => {
  if (evento.key === "Enter") {
    console.log(`Buscando: ${busca.value}`);
  }
});

Digitando pão de queijo e apertando Enter, o Console mostra Buscando: pão de queijo. As outras teclas também disparam o evento, mas o if ignora todas que não sejam o Enter.

Esperar a página: DOMContentLoaded

Se o <script> estiver no <head>, ele roda antes de o resto do HTML existir, e o querySelector devolve null. Um jeito de resolver é ouvir o evento DOMContentLoaded ("o conteúdo do DOM foi carregado") no document:

document.addEventListener("DOMContentLoaded", () => {
  const botao = document.querySelector("#botao");
  botao.addEventListener("click", () => {
    console.log("clicou");
  });
});

Hoje o mais comum é pôr o <script> no fim do <body> ou usar <script defer>, e aí esse evento não é necessário (veja JavaScript na Página). Mas você vai encontrá-lo muito em código pronto.

4. O mesmo ouvinte em vários elementos

O addEventListener liga um elemento. Para vários, pegue todos com querySelectorAll e ligue um por um com forEach (ou for … of). A Ana tem três botões de tamanho de pizza:

<button class="tamanho">Pequena</button>
<button class="tamanho">Média</button>
<button class="tamanho">Grande</button>
<p id="escolha">Escolha o tamanho.</p>
<script src="script.js"></script>

const botoes = document.querySelectorAll(".tamanho");
const escolha = document.querySelector("#escolha");

botoes.forEach((botao) => {
  botao.addEventListener("click", () => {
    escolha.textContent = `Pizza ${botao.textContent}`;
  });
});

Cada botão ganha o seu próprio ouvinte, e cada ouvinte "lembra" do seu botao (é um closure). Clicando em Média, aparece Pizza Média.

A lista não tem addEventListener

document.querySelectorAll(".tamanho").addEventListener(…) dá erro: a lista de elementos não é um elemento. A mensagem está em Quando dá errado.

5. Tirando um ouvinte

Para desfazer o combinado, use removeEventListener ("remover ouvinte"), com o mesmo evento e a mesma função. Por isso a função precisa ter nome: uma arrow function escrita de novo é outra função, mesmo com o texto igual, e o navegador não a reconhece.

const botao = document.querySelector("#votar");
const saida = document.querySelector("#saida");

function votar() {
  saida.textContent = "Voto registrado. Obrigado!";
  botao.removeEventListener("click", votar);
}

botao.addEventListener("click", votar);

No primeiro clique, o voto é registrado e o ouvinte se desliga: os próximos cliques não fazem nada. Como "só uma vez" é muito comum, existe um atalho, a opção once ("uma vez"):

botao.addEventListener("click", () => {
  saida.textContent = "Voto registrado. Obrigado!";
}, { once: true });

O terceiro item entre os parênteses é um objeto de opções. Com { once: true }, o navegador tira o ouvinte sozinho depois da primeira vez.

Formas diferentes de fazer a mesma coisa

Há três jeitos de ligar uma função ao clique. Você vai encontrar os três em código por aí:

<!-- 1. o atributo no HTML (antigo) -->
<button onclick="cumprimentar()">Um</button>

<!-- 2 e 3: no script -->
<button id="dois">Dois</button>
<button id="tres">Três</button>

function cumprimentar() {
  console.log("Bom dia!");
}

// 2. a propriedade onclick
document.querySelector("#dois").onclick = cumprimentar;

// 3. addEventListener (o recomendado)
document.querySelector("#tres").addEventListener("click", cumprimentar);

Os três mostram Bom dia! no clique. As diferenças:

  • Atributo onclick="…" no HTML: mistura JavaScript dentro do HTML, o código fica espalhado e difícil de achar, e a função tem de ser global. Muitos sites até bloqueiam esse tipo de código por segurança. Reconheça, mas não use.
  • Propriedade elemento.onclick = função: cada elemento tem um onclick só. Se outra parte do código fizer elemento.onclick = outraFuncao, a primeira é apagada sem aviso. Aqui o nome leva o "on": onclick, oninput.
  • addEventListener: aceita vários ouvintes no mesmo evento, tem opções (once) e pode ser desfeito com removeEventListener. É o padrão moderno.
SituaçãoQual usar
Qualquer código novoaddEventListener("click", função)
Ação que só pode acontecer uma vezaddEventListener(…, { once: true })
Ligar e desligar o ouvinte várias vezesFunção com nome + addEventListener / removeEventListener
Ler código antigoReconheça onclick="…" no HTML e el.onclick = …: fazem a mesma coisa

Quando dá errado

O seletor não achou o botão 
const botao = document.querySelector("#btn");
botao.addEventListener("click", () => {
  console.log("clicou");
});

Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
    at script.js:2:7
Uncaught TypeError
Um erro de tipo que ninguém tratou. O script para aqui: nenhuma linha depois desta roda.
Cannot read properties of null (reading 'addEventListener')
"Não dá para ler propriedades de null (lendo addEventListener)". A variável botao vale null: o querySelector não achou nenhum elemento com id="btn".
at script.js:2:7
Arquivo script.js, linha 2, coluna 7.

É o erro mais comum com eventos. As causas: o seletor está diferente do HTML (aqui o botão é #botao, não #btn), ou o <script> rodou antes do botão existir. Como consertar: confira o seletor; ponha o <script> no fim do <body>.

Escreveu o nome do método errado 
const botao = document.querySelector("#botao");
botao.addEventListner("click", () => {
  console.log("clicou");
});

Uncaught TypeError: botao.addEventListner is not a function
    at script.js:2:7

"botao.addEventListner não é uma função". Faltou o e de Listener. O nome é comprido e fácil de errar: add·Event·Listener, com as maiúsculas no lugar. Como consertar: corrija o nome. (O mesmo erro sai com addeventlistener, tudo minúsculo: o JavaScript diferencia maiúsculas de minúsculas.)

Ligou o evento na lista inteira 
const botoes = document.querySelectorAll(".tamanho");
botoes.addEventListener("click", () => {
  console.log("clicou");
});

Uncaught TypeError: botoes.addEventListener is not a function
    at script.js:2:8

O querySelectorAll devolve uma lista (NodeList), e uma lista não tem addEventListener. Como consertar: percorra a lista e ligue cada um: botoes.forEach((b) => b.addEventListener(…)) (seção 4).

Nome do evento errado: nada acontece, e não há erro 
botao.addEventListener("onclick", () => {
  console.log("clicou");
});

O Console fica limpo, e clicar não faz nada. O navegador aceita qualquer texto como nome de evento (dá para inventar eventos próprios); ele só fica esperando um evento chamado "onclick", que nunca acontece. O mesmo vale para "Click" com maiúscula ou "clik". Como consertar: o nome é "click", minúsculo e sem "on".

A função rodou sozinha quando a página abriu 
botao.addEventListener("click", cumprimentar());

Também sem erro. Os parênteses chamaram a função na hora (seção 2), e o navegador recebeu o resultado dela, undefined, que não é uma função para rodar no clique. Como consertar: tire os parênteses: addEventListener("click", cumprimentar). Se precisar passar um valor para a função, embrulhe numa arrow function: addEventListener("click", () => cumprimentar("Ana")).

Resumo

  • Um evento é algo que acontece na página: clique, tecla, digitação, mouse. A página fica esperando por eles.
  • elemento.addEventListener("evento", função) registra o combinado: a função roda a cada vez que o evento acontece, chamada pelo navegador.
  • Entregue a função sem parênteses (cumprimentar); com parênteses ela roda na hora, e o clique fica sem ação.
  • Os mais usados: click, input, change, keydown, mouseenter/mouseleave, submit, DOMContentLoaded. O nome vai sem "on".
  • Variáveis que precisam lembrar valores entre um evento e outro ficam fora da função.
  • Para vários elementos, querySelectorAll + forEach. Para tirar, removeEventListener com a mesma função, ou { once: true }.
