JavaScript Promises

Na aula Callbacks Assíncronos, você viu o problema: cada passo que depende do anterior vai dentro do callback anterior, o código vira uma pirâmide e o tratamento de erro se repete em cada nível. A Promise ("promessa") resolve isso com uma ideia simples: em vez de entregar um callback e esperar a ligação, a função assíncrona te devolve, na hora, um objeto que representa o resultado que ainda vai chegar. Com esse objeto na mão, você diz o que fazer quando der certo (.then) e quando der errado (.catch), e encadeia os passos um embaixo do outro.

Você vai aprender
  • O que é uma Promise e os seus três estados: pendente, cumprida e rejeitada.
  • Como usar uma Promise com .then, .catch e .finally.
  • Como criar a sua própria Promise com new Promise((resolve, reject) => { … }).
  • Como encadear passos: a pirâmide da aula passada vira uma lista reta.
  • Como os valores e os erros andam pela corrente de .then.
  • Os erros reais: a Promise rejeitada sem catch, o .then sem return, o new esquecido.

Todos os programas desta aula rodaram no Node.js 24 da máquina da Ana (usuária ana, computador notebook), com node arquivo.js. Os arquivos cardapio.txt e pedido.txt são os mesmos da aula Callbacks Assíncronos, e de novo não existe nenhum estoque.txt. Promises são ES2015 e existem igualzinhas no navegador.

A ideia: a senha da lanchonete

Na lanchonete, a Ana pede um sanduíche e o caixa entrega, na hora, um papelzinho com a senha 42. Ela ainda não tem o sanduíche, mas tem uma promessa de sanduíche. Com a senha na mão, ela pode ir sentar, conversar, pegar um guardanapo. A senha sempre está num destes três estados:

Estado da senhaNome em inglês (o que o Node mostra)Quer dizer
PendentependingO sanduíche ainda está sendo feito
CumpridafulfilledChamaram o 42: o sanduíche (o valor) está pronto
RejeitadarejectedChamaram o 42 para avisar que acabou o pão: veio um erro

Duas regras: a senha começa pendente e muda uma vez só (para cumprida ou rejeitada) e, depois que mudou, nunca mais muda. Quando ela já não está pendente, diz-se que foi resolvida (em inglês, settled).

A diferença para o callback: lá, a Ana deixava o telefone dela com a lanchonete. Aqui, a lanchonete dá a senha para a Ana, e é ela quem decide o que fazer quando chamarem.

3. Criando a sua Promise: new Promise

As funções do Node já devolvem Promises prontas. Para transformar uma tarefa sua em Promise, use new Promise. A máquina de café da aula passada, agora sem callback:

function prepararCafe(tamanho) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      const tamanhos = ["pequeno", "médio", "grande"];
      if (!tamanhos.includes(tamanho)) {
        reject(new Error(`tamanho desconhecido: ${tamanho}`));
        return;
      }
      resolve(`Café ${tamanho} pronto`);
    }, 1000);
  });
}

const pedido = prepararCafe("médio");
console.log(pedido);

pedido.then((cafe) => {
  console.log(cafe);
  console.log(pedido);
});

prepararCafe("gigante").catch((erro) => {
  console.log("Erro:", erro.message);
});

4. Encadeando: adeus, pirâmide

A grande vantagem: todo .then devolve uma Promise nova. Então dá para pendurar outro .then nele, e outro, e outro. E se um .then devolve (return) uma Promise, o próximo espera ela terminar. A pirâmide do recibo, da aula passada, vira uma lista reta:

const fsp = require("node:fs/promises");

fsp.readFile("pedido.txt", "utf8")
  .then((texto) => {
    const linhas = texto.trim().split("\n");
    let total = 0;
    for (const linha of linhas) {
      const [, quantidade, preco] = linha.split(";");
      total = total + Number(quantidade) * Number(preco);
    }
    const recibo = `Itens: ${linhas.length}\nTotal: R$ ${total.toFixed(2)}\n`;
    return fsp.writeFile("recibo.txt", recibo);
  })
  .then(() => {
    return fsp.readFile("recibo.txt", "utf8");
  })
  .then((conferido) => {
    console.log("Recibo salvo:");
    console.log(conferido);
  })
  .catch((erro) => {
    console.log("Algo deu errado:", erro.message);
  });

$ node corrente.js
Recibo salvo:
Itens: 3
Total: R$ 40.00

Os mesmos três passos e o mesmo resultado, mas agora:

  • os passos ficam um embaixo do outro, na ordem em que acontecem, sem empurrar o código para a direita;
  • return fsp.writeFile(…): o próximo .then só roda quando a gravação terminar;
  • um único .catch, no fim, pega o erro de qualquer passo. Na versão com callbacks eram três if (erro).

Como os valores e os erros andam pela corrente

Promise.resolve(10)
  .then((valor) => {
    console.log("1º then recebeu", valor);
    return valor * 2;
  })
  .then((valor) => {
    console.log("2º then recebeu", valor);
    throw new Error("o forno desligou");
  })
  .then((valor) => {
    console.log("3º then recebeu", valor);
  })
  .catch((erro) => {
    console.log("catch recebeu:", erro.message);
    return "pão de ontem";
  })
  .then((valor) => {
    console.log("depois do catch:", valor);
  });

$ node passa-valor.js
1º then recebeu 10
2º then recebeu 20
catch recebeu: o forno desligou
depois do catch: pão de ontem
  1. Promise.resolve(10) cria uma Promise já cumprida com 10 (um atalho; existe também Promise.reject(erro)).
  2. O que um .then devolve com return é o que o próximo recebe: 10 virou 20.
  3. Um throw dentro de um .then rejeita a corrente: o 3º .then foi pulado e o erro foi direto para o .catch.
  4. O .catch tratou o erro e devolveu um valor: a corrente voltou ao normal, e o .then seguinte recebeu pão de ontem.
O .then nunca roda na hora

Mesmo com uma Promise já cumprida, o .then espera o código "de agora" terminar:

const pronta = Promise.resolve("já estava pronta");
pronta.then((valor) => console.log("then:", valor));
console.log("Esta linha vem primeiro");

$ node ordem.js
Esta linha vem primeiro
then: já estava pronta

É a mesma regra do setTimeout de 0 ms: um callback nunca interrompe o código que está rodando. Quem organiza essa fila é o Event Loop.

Formas diferentes de fazer a mesma coisa

A mesma leitura, nos três estilos do grupo "Assíncrono" (são trechos para comparar: os require de fs e fsp ficaram de fora):

// 1. callback "erro primeiro" (aula Callbacks Assíncronos)
fs.readFile("cardapio.txt", "utf8", (erro, texto) => {
  if (erro) { console.log(erro.message); return; }
  console.log(texto);
});

// 2. Promise com then/catch (esta aula)
fsp.readFile("cardapio.txt", "utf8")
  .then((texto) => console.log(texto))
  .catch((erro) => console.log(erro.message));

// 3. async/await (próxima aula): a mesma Promise, esperada com await
async function ler() {
  try {
    const texto = await fsp.readFile("cardapio.txt", "utf8");
    console.log(texto);
  } catch (erro) {
    console.log(erro.message);
  }
}

O async/await não substitui as Promises: ele é um jeito mais confortável de esperar por elas. Tudo o que você aprendeu aqui (estados, resolve/reject, rejeição sem tratamento) continua valendo lá.

SituaçãoQual usar
Código novo, passos em sequênciaasync/await (aula async e await)
Uma operação só, ou uma corrente curta.then/.catch fica bem
Transformar uma tarefa sua (timer, callback antigo) em Promisenew Promise((resolve, reject) => …)
Esperar várias Promises ao mesmo tempoPromise.all e companhia (aula Várias Promises)
Eventos que se repetem (cliques, "tics")Callback: uma Promise só se resolve uma vez

No Node 24, uma Promise rejeitada que ninguém trata derruba o programa (com código de saída 1), como um throw sem catch. Como consertar: toda corrente de Promises termina com um .catch (a missão da seção 2).

Esqueceu o return dentro do .then 
const fsp = require("node:fs/promises");

fsp.readFile("cardapio.txt", "utf8")

O primeiro .then calculou a lista de itens e… jogou fora. Uma função com chaves { } que não tem return devolve undefined (aula return), e é isso que o próximo .then recebe. Com uma Promise, é pior: sem o return fsp.writeFile(…), o próximo passo não esperaria a gravação terminar. Como consertar: return texto.trim().split("\n");, ou a arrow sem chaves, que devolve sozinha: .then((texto) => texto.trim().split("\n")).

Chamou a função dentro do .then em vez de entregá-la

"Chegou!" apareceu antes do pedido, e o cardápio não apareceu. O console.log("Chegou!") rodou na hora, e o .then recebeu o resultado dele (undefined); o JavaScript não reclama, só ignora um .then que não recebe função. É o mesmo engano do setTimeout(f(), 1000). Chamou resolve ou reject mais de uma vez

  resolve("café pronto");

Só a primeira chamada vale: depois de resolvida, a Promise não muda mais, e as outras são ignoradas em silêncio.   .catch((erro) => console.log(`Erro: ${erro.message}`));

function prepararCafe(tamanho) {
  const tamanhos = ["pequeno", "médio", "grande"];
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (!tamanhos.includes(tamanho)) {
        reject(new Error(`tamanho desconhecido: ${tamanho}`));
        return;
      }
      resolve(`Café ${tamanho} pronto`);
    }, 1000);
  });
}

prepararCafe("grande")
  .then((cafe) => console.log(cafe))
  .catch((erro) => console.log(`Erro: ${erro.message}`));

prepararCafe("gigante")
  .then((cafe) => console.log(cafe))
  .catch((erro) => console.log(`Erro: ${erro.message}`));

Rode o programa inicial antes de mexer: como a função ainda não devolve nada, aparece TypeError: Cannot read properties of undefined (reading 'then'), porque não dá para pendurar um .then em undefined. É o erro que você vai ver sempre que esquecer o return da Promise.

Resumo

  • Uma Promise é um objeto que representa um resultado que ainda vai chegar (a "senha" da lanchonete). Ela está pendente, cumprida (com um valor) ou rejeitada (com um erro), e só muda de estado uma vez.
  • .then(valor => …) trata o resultado, .catch(erro => …) trata o erro, .finally(() => …) roda no fim de qualquer jeito. Toda corrente termina com .catch: no Node 24, uma rejeição sem tratamento derruba o programa.
  • new Promise((resolve, reject) => { … }) transforma uma tarefa sua em Promise: resolve(valor) cumpre, reject(new Error(…)) rejeita.
  • Todo .then devolve uma Promise nova. O que você der return vai para o próximo passo (e, se for uma Promise, ele espera). Um throw pula direto para o .catch. Assim, a pirâmide de callbacks vira uma lista reta, com um só tratamento de erro.
  • Próxima aula: async e await, o jeito mais confortável de esperar uma Promise.
