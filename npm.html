JavaScript npm

Você não precisa escrever tudo do zero. Milhões de programadores já resolveram problemas comuns (formatar datas, embaralhar listas, colorir o terminal, criar um servidor) e publicaram a solução como um pacote: um conjunto de arquivos JavaScript prontos para outros usarem. O npm é o programa que busca esses pacotes na internet e os coloca no seu projeto. Ele vem junto com o Node.js. Esta aula é só do Node: o npm roda no terminal, não no navegador.

Você vai aprender
  • O que são pacote, registro e npm, e onde eles entram no seu programa.
  • Como preparar uma pasta de projeto com npm init -y e instalar um pacote com npm install.
  • O que aparece na pasta depois: node_modules, package-lock.json e a lista de dependências.
  • Como usar o pacote no código, com require e com import.
  • Por que a pasta node_modules não se copia, e como o npm install a refaz.
  • Versões e segurança: npm ls, npm outdated, npm audit e npm update.
  • Como remover um pacote (npm uninstall) e rodar um programa sem instalar (npx).
  • Os erros reais: Cannot find module, E404 e ENOVERSIONS.

Tudo nesta aula rodou no Node.js v24.22.0 com o npm 11.19.1 da máquina da Ana (usuária ana, computador notebook), ligada à internet. Os comandos são digitados no terminal (veja Rodando um Programa).

A ideia: a padaria não fabrica o próprio fermento

A padaria do bairro faz pão, sonho e broa. Mas ela não planta o trigo, não fabrica o fermento nem monta o forno: compra tudo isso pronto, de fornecedores. Assim ela gasta o tempo no que interessa, que é o pão.

Com programas é igual:

Na padariaNo JavaScript
O fermento comprado prontoUm pacote (em inglês, package): código pronto, escrito por outra pessoa
O catálogo do atacadista, com milhões de produtosO registro do npm (registry.npmjs.org), onde os pacotes ficam publicados
O entregador que traz o pedidoO programa npm, que baixa o pacote para a sua pasta
A despensa da padariaA pasta node_modules, onde os pacotes baixados ficam
A lista de compras pregada na paredeO arquivo package.json, que anota quais pacotes o projeto usa

Um pacote que o seu projeto usa se chama dependência (o seu projeto "depende" dele para funcionar). O nome npm vem de Node Package Manager, "gerenciador de pacotes do Node".

1. O npm já veio com o Node

Quem instalou o Node.js (veja Instalar o Node.js) já tem o npm. Confira as duas versões com -v (de version, "versão"):

$ node -v
v24.22.0
$ npm -v
11.19.1

São dois programas diferentes, com números diferentes: o node roda o seu JavaScript; o npm cuida dos pacotes. Na sua máquina os números podem ser outros; tudo bem, desde que o Node seja 24 ou mais novo.

3. Instalando um pacote: npm install

A Ana vai usar o lodash, um dos pacotes mais usados do mundo: uma caixa de ferramentas com centenas de funções para listas, textos e objetos. Dentro da pasta do projeto:

$ npm install lodash

added 1 package, and audited 2 packages in 521ms

found 0 vulnerabilities
npm install lodash
"npm, instale o lodash". O npm procura o nome lodash no registro, baixa a versão mais nova e guarda no projeto. Dá para abreviar: npm i lodash.
added 1 package
"Adicionei 1 pacote". O lodash não depende de nenhum outro pacote, então veio só ele. Um pacote que usa outros traz todos juntos, e aí aparece added 25 packages, por exemplo.
audited 2 packages in 521ms
"Conferi 2 pacotes em 521 milissegundos": o npm consultou uma lista de falhas de segurança conhecidas. O tempo muda a cada vez (depende da internet); na segunda vez, no lab, deu 427ms.
found 0 vulnerabilities
"Encontrei 0 vulnerabilidades": nenhuma falha de segurança conhecida nessas versões. Na seção 6 você vê o que aparece quando há uma.

A pasta node_modules: a despensa

É ali que ficam os arquivos dos pacotes (node modules, "módulos do Node"). O lodash é uma pasta cheia de arquivos .js, como qualquer programa seu:

$ ls node_modules/lodash | head -5

README.md

_Hash.js
_LazyWrapper.js
$ ls node_modules/lodash | wc -l

$ du -sh node_modules

São 637 arquivos e quase 5 MB, só para um pacote. Projetos grandes chegam a centenas de megabytes de node_modules. Você nunca edita nada lá dentro: é o npm que cuida dessa pasta.

O package.json ganhou uma linha

$ cat package.json

  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"

O campo "dependencies" ("dependências") é a lista de compras: o projeto precisa do lodash, versão 4.18.1 ou mais nova dentro da 4 (é isso que o ^ quer dizer; os detalhes estão em O package.json). Quando você ler esta aula, a versão mais nova do lodash pode ser outra.

4. Usando o pacote no seu código

Com o pacote na despensa, o programa pede por ele pelo nome. O projeto da Ana é do tipo "commonjs" (está no package.json), então o jeito padrão é o require (veja require e module.exports):

const _ = require("lodash");

const paes = ["pão francês", "sonho", "broa", "pão de queijo", "rosca"];
console.log(_.capitalize("pão de queijo"));
console.log(_.chunk(paes, 2));
console.log(_.sum([4.5, 12.9, 3.25]));
console.log(_.shuffle([1, 2, 3, 4, 5]));
const _ = require("lodash");
"Requerer o lodash": o Node procura uma pasta lodash dentro de node_modules e entrega o que o pacote exporta. Repare: só o nome, sem ./ nem .js. O _ (sublinhado) é só o nome da variável; é a tradição para o lodash (o nome vem de "low dash", "traço baixo"). Poderia ser const lodash = require("lodash");.
_.capitalize(texto)
Primeira letra maiúscula, o resto minúsculo.
_.chunk(lista, 2)
"Pedaço": corta a lista em grupos de 2 (as prateleiras da vitrine).
_.sum(lista)
Soma os números da lista.
_.shuffle(lista)
"Embaralhar": devolve uma cópia da lista em ordem aleatória.
$ node vitrine.js
Pão de queijo
[
  [ 'pão francês', 'sonho' ],
  [ 'broa', 'pão de queijo' ],
  [ 'rosca' ]
]
20.65
[ 2, 5, 3, 4, 1 ]

A última linha muda a cada execução, porque é sorteada. Rodando de novo, no lab saiu [ 3, 4, 2, 5, 1 ].

Com import

Num arquivo de módulo (.mjs, ou num projeto com "type": "module"; veja Módulos), o mesmo pacote entra com import, também só pelo nome:

import _ from "lodash";

const estoque = [
  { nome: "sonho", tipo: "doce", qtd: 12 },
  { nome: "broa", tipo: "salgado", qtd: 7 },
  { nome: "rosca", tipo: "doce", qtd: 3 },
];
console.log(_.groupBy(estoque, "tipo"));
console.log(_.sumBy(estoque, "qtd"));

$ node estoque.mjs
{
  doce: [
    { nome: 'sonho', tipo: 'doce', qtd: 12 },
    { nome: 'rosca', tipo: 'doce', qtd: 3 }
  ],
  salgado: [ { nome: 'broa', tipo: 'salgado', qtd: 7 } ]
}
22

_.groupBy separou o estoque por tipo e _.sumBy somou as quantidades (12 + 7 + 3 = 22).

const { capitalizar } = require("utilidades");

function capitalizar(texto) {
  return texto[0].toUpperCase() + texto.slice(1).toLowerCase();
}

module.exports = { capitalizar };

const { capitalizar } = require("./utilidades.js");

console.log(capitalizar("pão de queijo"));

6. Versões e segurança: ls, outdated, audit, update

Pacotes mudam: os autores corrigem defeitos e falhas de segurança e publicam versões novas. Para escolher uma versão, ponha @ e o número depois do nome. A Ana instalou de propósito uma versão antiga do lodash, a 4.17.21:

$ npm install lodash@4.17.21

added 1 package, and audited 2 packages in 506ms

1 high severity vulnerability

To address all issues, run:
  npm audit fix --force

Run `npm audit` for details.

O resumo mudou: 1 high severity vulnerability, "1 vulnerabilidade de gravidade alta". O npm sugere rodar npm audit ("auditoria") para ver os detalhes. Antes, ela confere o que está instalado e o que está atrasado:

$ npm ls
padaria@1.0.0 /home/ana/padaria
└── lodash@4.17.21

$ npm outdated
Package  Current  Wanted  Latest  Location             Depended by
lodash   4.17.21  4.18.1  4.18.1  node_modules/lodash  padaria
npm ls
De list, "listar": mostra a árvore de pacotes do projeto, com a versão de cada um.
npm outdated
"Desatualizado": a tabela dos pacotes que têm versão mais nova. Current é a que está instalada; Wanted, a mais nova que o package.json aceita; Latest, a mais nova que existe. Se tudo estiver em dia, o comando não mostra nada.
$ npm audit

1 high severity vulnerability

  npm audit fix

O relatório diz que as versões do lodash até a 4.17.23 (<=, "menor ou igual") têm falhas conhecidas, cada uma com um link para a explicação, e que existe correção. A lista de falhas muda com o tempo: o que hoje dá "0 vulnerabilities" pode ganhar um aviso amanhã, quando alguém descobrir um problema. Para atualizar dentro do que o package.json permite:

$ npm update

changed 1 package, and audited 2 packages in 483ms

found 0 vulnerabilities
$ npm ls
padaria@1.0.0 /home/ana/padaria
└── lodash@4.18.1

changed 1 package, "troquei 1 pacote": o lodash foi para a 4.18.1, e as vulnerabilidades sumiram. (O npm audit fix, sugerido pelo próprio npm, faria a mesma correção.)

Cuidado com o --force

npm audit fix --force ("forçar") pode pular para uma versão principal nova do pacote (de 4 para 5, por exemplo), e versões principais novas costumam mudar o jeito de usar o pacote. Prefira npm update ou npm audit fix, sem o --force, e rode o seu programa depois para conferir.

Se o projeto não precisa mais de um pacote, não apague a pasta dele à mão: peça ao npm, que tira o pacote da node_modules e da lista do package.json:

E o npm install -g?

O -g (de global) instala um pacote para o computador inteiro, em vez de na pasta do projeto. Ele costuma precisar de permissão de administrador, depende de como o Node foi instalado, e mistura os pacotes de todos os projetos. Para quem está começando, a regra é simples: pacote para usar no código → npm install na pasta do projeto; programa para rodar de vez em quando → npx.

E, antes de instalar, uma pergunta vale ouro: preciso mesmo de um pacote? Cada pacote é código de outra pessoa entrando no seu projeto. Muita coisa que o lodash faz o próprio JavaScript já faz: a soma _.sum([4.5, 12.9, 3.25]), por exemplo, sai com um for … of ou com o reduce, e o agrupamento _.groupBy tem um primo pronto na linguagem, o Object.groupBy ES2024. A missão final é exatamente isso.

"Um registro completo desta execução está em…": um arquivo com todos os detalhes. O nome tem a data e a hora, então muda a cada vez.

Conserto: confira o nome do pacote no site npmjs.com, na página dele, onde aparece o comando certo de instalação.

3. ENOVERSIONS: um erro de digitação que caiu num nome abandonado

A Ana digitou lodsh em vez de lodash:

$ npm install lodsh
npm error code ENOVERSIONS
npm error No versions available for lodsh
npm error A complete log of this run can be found in: /home/ana/.npm/_logs/2026-10-19T14_05_26_445Z-debug-0.log

"Nenhuma versão disponível para lodsh": o nome existe no registro, mas sem nenhuma versão para instalar (o pacote foi retirado). Desta vez a Ana teve sorte. Erros de digitação são perigosos no npm: há gente mal-intencionada que publica pacotes com nomes parecidos com os famosos, esperando alguém errar uma letra. Copie o nome da página oficial do pacote e confira o que o npm install respondeu.

4. Rodou o npm install fora da pasta do projeto

O npm instala na pasta em que você está (ou na primeira pasta acima dela que tenha um package.json). Se você esquecer o cd padaria, a node_modules vai parar em outro lugar, e o programa do projeto continua sem achar o pacote. Antes de instalar, confira onde está com pwd ("mostrar a pasta atual") e se o ls mostra o package.json certo.

Missão: este programa usa o lodash só para somar três preços. O editor não tem pacotes, então ele dá erro. Tire a linha do require e troque o _.sum(precos) por uma soma feita com um for … of (ou com o reduce), até aparecer Total: R$ 20.65.

const precos = [4.5, 12.9, 3.25];
const total = _.sum(precos);
console.log(`Total: R$ ${total}`);

const precos = [4.5, 12.9, 3.25];
let total = 0;
for (const preco of precos) {
  total += preco;
}
console.log(`Total: R$ ${total}`);

No lab, a soma com for … of deu 20.65, o mesmo número do _.sum. Um pacote a menos para baixar, atualizar e auditar.

Resumo

  • Um pacote é código pronto publicado no registro do npm. O npm vem com o Node e roda no terminal; é só do Node.
  • npm init -y cria o package.json; npm install nome baixa o pacote para a node_modules, anota em "dependencies" e grava as versões exatas no package-lock.json.
  • No código, o pacote entra pelo nome: require("lodash") ou import _ from "lodash". Arquivos seus levam ./.
  • A node_modules não se copia nem se edita: npm install, sem nome, refaz tudo a partir do package.json e do package-lock.json.
  • npm ls, npm outdated, npm audit e npm update cuidam das versões e da segurança; npm uninstall remove; npx roda sem instalar.
  • Cannot find module 'x' = o pacote não está na node_modules (ou faltou o ./); E404 = o nome não existe no registro. Confira sempre o nome antes de instalar.
  • O editor do guia não instala pacotes: tudo do npm se faz no terminal.
